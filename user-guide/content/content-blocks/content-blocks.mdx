Content blocks allow you to reuse the same content across multiple campaigns. For example, a block might be a frequently used header, footer, or call-to-action button.

With content blocks, you can:

- **Maintain consistency**: Use the same headers, footers, or brand assets across all campaigns.
- **Reuse assets**: Create predefined assets for use across any channel or campaign type.
- **Update at scale**: Edit multiple campaigns simultaneously by updating the source content block.

# Create a Content Block

<Note>
  Content Block creation is gated by more than the **Content** permission set alone. To let a custom role create Content Blocks, also grant **Campaigns, Inform, Flows & Personalize > Create, Manage & Publish** — Content permissions by themselves are not sufficient.
</Note>

To create a new content block:

1. On the sidebar menu in MoEngage, hover over the **Content** menu item <img alt="content icon.png"  src="/images/moengage_24b340.png"  /> . The **Content** menu appears.
2. Click **Content Blocks**.   
    <img  src="/images/moengage_4cced1.png"  />   
   The Content blocks page appears.
3. Click **Create content block** in the upper right corner. The content blocks page is displayed.
4. Enter the following details: <img alt="create content block_new UI.png" src="/images/moengage_2b8d6a.png" />   
     

   | Field | Description |
   | --- | --- |
   | **Teams** | If your organization has teams enabled, select a Team from the dropdown. |
   | **Name** | Enter a unique name. This name identifies the block in campaigns, templates, or alerts. Use alphanumeric characters and underscores. |
   | **Description** | Provide context on what the block contains and where it should be used. |
   | **Tags** | Add tags to categorize the block. You can use existing [campaign tags.](/user-guide/campaigns-and-channels/getting-started/introduction/campaign-tags) |
   | **Communication Type** | Type of Communication. Supported values are:<ul><li>Engage</li><li>Inform</li></ul> |
   | **Content block type** | Type of content block. Supported values are:<ul><li>**Plain text**: Text-based content blocks are supported in all campaign channels.</li><li>**HTML**: HTML content blocks are supported in Email, In-App, and Personalize.</li></ul>Select the type depending on your use cases. For example, for a simple coupon code (without styling), you can use a Plain text type; for an email header/footer, use an HTML type. |
   | **Content** | Enter the content of the content block.<ul><li>For campaigns: Type @ to personalize the content for campaigns.</li><li>For alerts: Click the **Text personalization** button to personalize the content for alerts.</li></ul> |
5. Click **Publish**.   
   You can also personalize content blocks. For more information, refer to [Personalize Content Using Content Blocks](/user-guide/campaigns-and-channels/getting-started/message-personalization/personalize-content-using-content-blocks).

# Best Practices for HTML Content Blocks

<Warning>
  When adding custom HTML to a content block, include only body-level content — tags such as `div`, `section`, headings, paragraphs, and lists. Do not add an `<html>` tag or global `<style>` blocks.

  Every content block is inserted into a template that already has its own parent `<html>` tag. If your HTML content block includes another `<html>` tag or a global `<style>` block, those styles are not scoped to the block — they override the entire parent template. This can affect the rendering of other rows in the template and, in some cases, even the appearance of the editor UI itself.
</Warning>

To style the HTML in a content block, use **inline CSS** applied directly to the specific elements that need it. This keeps the styling scoped to your content block instead of leaking into the rest of the template.

# Manage Content Blocks

You can find content blocks using the following options:

- **Search by name or label**: Locate blocks by name or label.
- **Select updated by**: Narrow results by the user who last updated the block.
- **Content type**: Narrow results by content type.
- **Filter**: Narrow results by Type, Teams, Status, Tags, or the user who last updated the block.

You can switch between List view and Grid view using the icons on the page depending on your preference.

The following fields are available on the Content blocks page:

| Field | Description |
| --- | --- |
| **Name** | Displays the unique name given to the content block. |
| **Content type** | Indicates if the block is Plain text or HTML. |
| **Status** | Shows the current state of the block (e.g., Published or Draft). |
| **Teams** | Identifies the specific team it belongs to. |
| **Updated by** | Displays the the user who most recently modified the block. |
| **Usage** | Shows how many active campaigns, alerts, or templates are currently using this block. |

## View a Content Block

To view a content block,

- Click the three dots at the end of the row in the Content block listing and select **View**.
- Alternatively, click anywhere on the row to open the preview.

The preview window provides a comprehensive look at the block's configuration and how it appears to customers. It includes the following tabs and options:

- Toggle between **Web** and **Mobile** views to see how the content renders on different devices.
- Access the **Edit** and **Duplicate** options directly from the preview screen.
- **Details Tab** displays the block’s metadata, including:  
  - **Block label**
  - **Communication type**
  - **Content type**
  - **Updated by**
  - **Teams**
  - **Description**
- **Content blocks** tab shows the nested block name and type if this block is part of a larger content structure. <img alt="view content block_new UI.png" src="/images/moengage_94033e.png" />

## Edit a Content Block

To edit a content block,

- Click the three dots at the end of the row in the Content block listing and select **Edit**. Alternatively, click anywhere on the row to open the preview and click the **Edit** option in the preview page.
- In the Edit page, you can modify the **Teams**, **Name**, **Description**, **Tags**, and **Content** fields.

<Info>
  - You cannot change the **Communication type** or **Content block type** after a block is created.
  - Campaigns that use the content block pick up your changes automatically, but not instantly. For details, refer to [When Content Block Updates Appear in Campaigns](#when-content-block-updates-appear-in-campaigns).
</Info>

## Duplicate Content Blocks

To duplicate content blocks,

- Click the three dots at the end of the row in the Content block listing and select **Duplicate**.
- In the Duplicate page, click **Publish**.

The new block will be prefixed with **Duplicate**.

## Delete a Content Block

To delete content blocks,

- Click the three dots at the end of the row in the Content block listing and select **Delete**.
- In the confirmation message that appears, click **Delete**.

You can only delete a block if it is not currently used in any active campaigns.

# When Content Block Updates Appear in Campaigns

When you edit a published content block, every active campaign that uses the block picks up the change automatically. You don't need to edit or republish the campaign. However, the update doesn't appear instantly. How long it takes depends on the following:

- **Channel and campaign type**: Each channel processes content block updates differently.
- **Direct or nested edit**:
  - **Direct edit**: You edit a content block that is added directly to the campaign.
  - **Nested edit**: You edit a content block that is used inside another content block, and the campaign uses the outer block.
- **Content block link tracking (Email only)**: When this is enabled for your account, MoEngage tracks clicks on links inside content blocks in your emails. Emails with link tracking enabled take longer to show content block updates.

The following table shows how long it takes for content block updates to appear in active campaigns.

| Channel | Delivery type | Direct edit | Nested edit |
| :--- | :--- | :--- | :--- |
| **Email** (link tracking enabled or disabled) | Periodic | Up to 5 minutes. Not applied to an instance that is already running. Applied from the next instance onward. | Up to 65 minutes. Not applied to an instance that is already running. Applied from the next instance onward. |
| **Email** (link tracking disabled) | One-time, Event-triggered, and Flows | Up to 5 minutes | Up to 65 minutes |
| **Email** (link tracking enabled) | One-time | Up to 5 minutes, if you edit the block before the campaign starts sending. Not applied to a campaign that is already in the sending state. | Up to 65 minutes, if you edit the block before the campaign starts sending. Not applied to a campaign that is already in the sending state. |
| **Email** (link tracking enabled) | Event-triggered and Flows | Up to 70 minutes | Up to 2 hours |
| **Push**, **SMS**, **RCS**, **WhatsApp**, and **Connectors** | All delivery types | Up to 5 minutes | Up to 65 minutes |
| **In-App**, **On-site Messaging**, and **Web Personalization** | All delivery types | Up to 5 minutes | Up to 65 minutes |
| **Cards** | One-time, Event-triggered, and Flows | Not applied automatically. To apply the update, edit and save the campaign. | Not applied automatically. To apply the update, edit and save the campaign. |
| **Cards** | Periodic | Up to 5 minutes, from the next scheduled occurrence. Cards already delivered are not updated. | Up to 65 minutes, from the next scheduled occurrence. Cards already delivered are not updated. |
| **Inform** (all channels) | Transactional alerts | Up to 5 minutes | Up to 65 minutes |

<Note>
  - Content block updates apply only to messages that haven't been sent yet. Messages that were already sent are not changed.
  - In emails, content blocks used in the **Subject**, **Sender name**, and **Preheader** fields are updated within 5 minutes (65 minutes for nested edits), even when link tracking is enabled.
  - The time values are approximate. Message processing can add a few more minutes.
</Note>
