## Overview

[BigQuery](https://cloud.google.com/bigquery) is a fully managed, serverless data warehouse available on the Google Cloud Platform (GCP). It allows you to perform complex analytics on terabytes of data in real time without managing infrastructure.

## How Does MoEngage Work with BigQuery?

The MoEngage and BigQuery integration directly transfers user and event data to Google BigQuery for advanced analytics.

<Note>
  This is a direct integration and does not require Google Cloud Storage (GCS) to export your data.
</Note>

## Integration

<Tip>
  - Ensure you have a BigQuery account with the required permissions to create/edit BigQuery instances, roles, and policies.
  - It is optional to create a new user. However, you must have access to create a new user in your BigQuery database.
  - If your system requires IP whitelisting, you must allowlist MoEngage IPs. For more information, refer [here](/user-guide/settings/account/security/ip-whitelisting-in-moengage).
  - Ensure you have a BigQuery connection in the App Marketplace.
  - Exports to BigQuery are part of the Streams add-on. Contact your MoEngage customer success manager (CSM) to enable this feature for your account.
</Tip>

To create a BigQuery connection, refer to [Google BigQuery](/partner-guide/data-and-analytics/data-warehouses/google-bigquery).

### Export Events from MoEngage to BigQuery

#### Step 1: Ensure Your User's Assigned Role Has Required Permissions

To successfully set up and execute a BigQuery export, your service account or user must have the following permissions based on the action being performed:

- **To Create a Connection**: To establish a new BigQuery connection within the MoEngage App Marketplace, the user must have the _BigQuery Data Viewer_ and _BigQuery Job User_ roles. This allows MoEngage to validate the project and dataset details. For more information, refer [here](/user-guide/data/imports/setting-up-a-data-warehouse-import).
- **To Perform Exports**: To execute the actual data transfer, your service account must be assigned the _BigQuery Data Editor_ role. This grants MoEngage the necessary permissions to read and write data to your specific BigQuery tables.

#### Step 2: Add a New BigQuery Export in the MoEngage App Marketplace

<Info>
  - For a full list of events and attributes, refer to the [Data Exports Glossary](/user-guide/data/exports/events/data-export-glossary).
  - The `event_time` of exported events is always in UTC.
  - MoEngage does not currently support exporting historical data.
</Info>

To add a new BigQuery export, perform the following steps:

1. On the left navigation menu in the MoEngage UI, click **App marketplace**.
2. On the App Marketplace page, search for **BigQuery**. <img src="/images/moengage_ef1a2d.png" />
3. Click the **Google BigQuery** tile.
4. On the Google BigQuery page, go to the **Integrate** tab and click **\+Add Export**.
5. Enter the following details:
   | Field | Required | Description |
   | --- | --- | --- |
   | **Export name** | Yes | Type a name for the BigQuery export. Ensure your export name contains at least three characters. |
   | **BigQuery connection** | Yes | Select your BigQuery connection. |
   | **Dataset ID** | Yes | Select the specific dataset in BigQuery where your data will be exported. |
   | **Table name** | Optional | Enter the name for the export table. If left blank, MoEngage creates a name for you with the prefix _moe\_events_.  <br />**Note:** To avoid errors, allow MoEngage to automatically create this table. |
   | **User Properties** | Optional | Select the specific user properties you want to include in the export. |
   | **Select events** | Yes | Select the events to export to BigQuery. You can choose to export all events, including existing and new events coming into MoEngage, or manually select specific events to export. |
   | <img src="/images/moengage_3e3a7b.png" /> |  |  |
6. Click **Save export**.

Now, MoEngage populates the newly created table with events every hour.

#### Export Process and Frequency

After you save the export, MoEngage creates a destination table in your dataset. New event data is then appended to this same table at hourly intervals:

**Initial action**: MoEngage creates the table when the first export is triggered.

**Recurring action**: MoEngage adds (appends) data to the same table every hour.

#### Sample Table Structure

If you do not specify a table name in the export configuration, MoEngage creates a single table in your dataset using the following format:\
`moe_events_<table_creation_timestamp>`

<Note>
  This table is created once per connection. All hourly exports and different event types configured under this connection are consolidated and appended to this specific table.
</Note>

The overall structure of the table remains fixed for all event types. ## Export Failure Policy

MoEngage pauses an export that keeps failing. While it is paused, MoEngage collects the events the export would have delivered, and you replay them after you fix the problem.

### When MoEngage Pauses an Export

Exports to BigQuery run hourly. MoEngage will retry an export multiple times before marking it as failed. The export will be paused after 3 consecutive scheduled export failures.

When MoEngage pauses an export, it alerts you and shows the export as **Paused** on the App Marketplace.

### What Happens While an Export Is Paused

![A paused BigQuery export on the Integrate tab, with Export status turned off and the Paused label beside it](/images/export-paused-card.png)

MoEngage collects the events the export would have delivered and keeps only the most recent 7 days. If the export stays paused for longer than a week, MoEngage drops the oldest days as newer ones come in.

If an export pauses more than once before you replay, MoEngage combines the data from all those pauses, provided it falls within the 7-day window.

### Resume an Export

#### Find the Failure Reason

On the App Marketplace, click the **Integrate** tab, and then hover over the **Paused** label on the export. MoEngage names the reason for the failure, such as a missing write permission on the destination table, and tells you how to fix it.

![The Paused label hover on the Integrate tab, showing the failure reason and what you need to do](/images/bigquery-export-paused-failure-reason.png)

#### Enable the Export

Fix the cause at your end, and then turn on **Export status** for the export. Do this as soon as you can, because the 7-day window keeps moving while the export stays paused.

When you enable the export, MoEngage stops collecting and sets aside what it has: the last 7 days of paused data, or all of it if the pause was shorter. This is the data you can replay. It stays fixed from then on, and does not reduce further even if you wait to replay it.

### Replay Paused Data

#### Request a Replay

MoEngage saves the data it collected while the export was paused. An export with data waiting shows a **Replay available** label on the **Integrate** tab.

To replay, perform the following steps:

1. Hover over the **Replay available** label, or open the kebab menu on the export.
2. Click **Replay paused data**.

   ![BigQuery export with a Replay available label on the Integrate tab and the Replay paused data option](/images/bigquery-export-replay-paused-data.png)
3. In the **Replay paused data** dialog box, click **Confirm**.

   ![Replay paused data dialog box asking you to confirm, with the Confirm button](/images/export-replay-confirm.png)

A replay sends everything MoEngage collected while the export was paused. MoEngage appends the data to the destination table.

You can replay at any time until 30 days from the date the oldest paused data was collected. After that, the data is no longer available.

<Note>
  Replay before the export pauses again. If it pauses a second time before you replay, MoEngage adds the new paused data to the data still waiting from the first pause. The combined data is then trimmed back to the most recent 7 days, so if the two pauses are more than 7 days apart, the older data is lost.

  For example, your export pauses on day 1. You enable it but do not replay. It pauses again on day 20. Since that is 19 days later, the day 1 data falls outside the 7 day window and is gone, even though its 30 day replay window had not expired. If the second pause had happened within 7 days of the first, the day 1 data would still be included.
</Note>

#### Replay Results

When the replay finishes, MoEngage emails the user who requested it with one of the following results:

| Result | What it means |
| --- | --- |
| Successful | MoEngage delivered all the collected data. The replay option is no longer available. |
| Partially Successful | MoEngage delivered some of the collected data, and then hit an error. The replay stops and MoEngage pauses the export again. The email states why the replay did not finish. Fix the cause, enable the export, and then replay again. For the data you can replay, refer to [What Happens While an Export Is Paused](#what-happens-while-an-export-is-paused). |
| Failed | MoEngage delivered none of the collected data, because of an error. The replay stops and MoEngage pauses the export again. The email states why the replay did not finish. Fix the cause, enable the export, and then replay again. For the data you can replay, refer to [What Happens While an Export Is Paused](#what-happens-while-an-export-is-paused). |

You can run only one replay per export at a time.

#### Avoid Duplicate Data

Every replay sends the whole collection again, because MoEngage does not deduplicate. If you replay more than once, deduplicate at your end on the `event_uuid` field, which is unique for each event. For the fields in the export, refer to the [Data Export Glossary](/user-guide/data/exports/events/data-export-glossary).

### Export Paused Alerts

MoEngage alerts you when it pauses an export, so you can fix the issue and replay the data collected while the export was paused.

MoEngage subscribes workspace admins to the Data Exports system alert by default, and adds the user who creates or updates an export. To subscribe or unsubscribe anyone else, go to the Alert Management page. Subscribing or unsubscribing changes notifications only for that person, and does not affect anyone else's subscription.
