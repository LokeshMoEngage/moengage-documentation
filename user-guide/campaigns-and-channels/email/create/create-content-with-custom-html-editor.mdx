## Edit/Paste HTML Template

You can craft email content using the HTML editor. The side-by-side view of the editor helps you visualize the impact of any changes made to the HTML code, regardless of its complexity.

With HTML editor, you can perform the following actions:

### Add HTML Code

<Info>
  If you have turned on the **Auto-format HTML code** toggle in the [Email settings](/user-guide/campaigns-and-channels/email/getting-started-with-email/configure-email-channel#general-settings-tab), Custom HTML editor of MoEngage performs some actions in the HTML templates. This offers a significant advantage through automatic HTML cleanup, ensuring semantic correctness and reliable rendering across browsers. For more information on these actions, refer to [How MoEngage Formats Your HTML](#how-moengage-formats-your-html).
</Info>

You can add an HTML code that you have prepared previously or create it with the editor. The editor supports the following editor tools to create HTML code:

- _Text editor and formatting_. This basic text editor tool allows you to type or modify the HTML code directly.
- _Table editor._ This editor allows you to easily create and customize HTML tables by specifying the number of rows and columns.
- _Hyperlink insertion._ The editor typically includes a tool for inserting hyperlinks. You can specify the URL, link text, and target window option.
- _Image editor._ This editor allows you to insert and manage images in your HTML code.
- _Undo/Redo._ Undo and redo buttons are available to easily revert or reapply changes to your HTML code. <img src="/images/moengage_614ea2.png" alt="side by side.png" />

<Warning>
Do not embed base64-encoded image data in your HTML (for example, `<img src="data:image/png;base64,...">`) or paste it into a link or URL field. Reference images with a hosted URL or upload them instead. A large base64 image can exceed the message-size limit during sending and cause the campaign to fail silently, with a Sent count of 0.
</Warning>

### How MoEngage Formats Your HTML

MoEngage applies some edits to every HTML template in the Custom HTML Editor, and applies more edits when the **Auto-format HTML code** toggle is turned on in the **General Settings** of Email.

#### Edits MoEngage Always Applies

MoEngage applies the following edits regardless of the **Auto-format HTML code** toggle:

- **Head and meta tags**: If your HTML contains a `<head>` tag, MoEngage adds meta tags inside it. If there is no `<head>` tag, MoEngage adds one with the following meta tags:

  ```html Inserted Head and Meta Tags wrap
  <head><meta charset="utf-8" content="text/html" http-equiv="Content-Type"/><meta content="noindex, nofollow, noarchive" name="robots"/><meta content="noindex, nofollow, noarchive" name="googlebot"/></head>
  ```

- **View in browser (VIB) link**: MoEngage adds the VIB link with the required styling:

  ```html View in Browser Link wrap
  <p style="text-align:center;"><a href="https://example-tracking-domain.com/v1/emailview?q=ENCODED_TRACKING_TOKEN&amp;event_date=2025-07-11&amp;event_time=1752206312" id="moe_internal_email_vib">View in browser</a></p>
  ```

- **Open tracking pixel**: MoEngage inserts an open tracking pixel with the required styling:

  ```html Open Tracking Pixel wrap
  <img src="https://example-tracking-domain.com/v1/emailopen?q=ENCODED_TRACKING_TOKEN" alt="" style="display:none;width:1px;height:1px;" height="1" width="1">
  ```

- **HTML tag correction**: MoEngage uses a backend library (BeautifulSoup) to correct incomplete or malformed HTML tags:
  - If an opening tag has no matching closing tag, MoEngage adds the closing tag. For example, MoEngage changes this HTML:

    ```html Original HTML wrap
    <!DOCTYPE html> <html> <body> <h1>My First Heading</h1> <strong>test 123 <p>My first paragraph
    ```

    to this HTML:

    ```html Corrected HTML wrap
    <!DOCTYPE html> <html> <body> <h1>My First Heading</h1> <strong>test 123 </strong><p>My first paragraph</p></body></html>
    ```

  - An empty `<b />` tag, which is not valid HTML, becomes a `<b></b>` tag pair. For example, `<a><b /></a>` becomes `<a><b></b></a>`.
  - A closing tag without a matching opening tag is ignored entirely, or corrected if possible. For example, `<a></p>` becomes `<a></a>`.

#### Edits That Depend on the Auto-Format HTML Code Toggle

MoEngage applies the following edits only if you turn on the **Auto-format HTML code** toggle in the **General Settings** of Email. For more information, refer to [Configure Email Channel](/user-guide/campaigns-and-channels/email/getting-started-with-email/configure-email-channel).

- Removes empty tags, unless they are listed in _htmlAllowedEmptyTags_.
- Normalizes whitespace and removes unnecessary or trailing spaces.
- Inserts `<br>` where it is structurally required for visual breaks.
- Sanitizes lists and tables, for example, by inserting `<tbody>` inside `<table>`.
- Cleans up redundant `<br>` or `<div>` tags.
- Converts deprecated or invalid tags and attributes to HTML5 standards.
- Removes invalid or unknown attributes based on the editor configuration.
- Fixes nested structures that do not comply with HTML rules.

### Known Editor Behavior: HTML Attribute Casing and Inline SVG

The rich-text editor (Froala) parses your code as standard HTML DOM. Standard HTML attributes are not case-sensitive, so the editor normalizes attribute casing — for example, `viewBox` is automatically converted to lowercase `viewbox`.

<Warning>
If you're using inline SVG, this normalization breaks it. SVG is XML-based and case-sensitive, so `viewbox` is not recognized and the SVG renders blank.
</Warning>

**Workaround:** To preserve attribute casing exactly as written, use the **HTML editor** or the **Drag and Drop editor** instead of the default rich-text (Froala) editor. The HTML editor passes your code through unprocessed, without DOM normalization.

<Note>
Even with casing preserved, inline SVG is not recommended for email. Gmail strips inline `<svg>` tags entirely for security reasons, regardless of which editor was used to create the content. If your email needs to render correctly on Gmail, use a PNG or other raster image format instead of inline SVG.
</Note>

## Upload an HTML Template in ZIP Format

You can craft your email content by uploading a ZIP file (containing an HTML file and images). MoEngage converts this ZIP file and displays your design in the Custom HTML Editor. You can then make further changes or [personalize the message](/user-guide/campaigns-and-channels/email/create/personalize-email-content).

### ZIP File Format

To upload a ZIP file, make sure to follow the specifications below:

- Limit your file size to 5 MB.
- The file name should not contain any of the following characters: `*`, `/`, `&`, `~`, or `"`.
- The ZIP file should contain only one HTML file with inlined CSS. If you see an error regarding the file name, ensure that there is only one HTML file.
- Make sure the images are in the JPG, JPEG, PNG, or GIF formats.
- All images should be located on the relative path mentioned in HTML (with case sensitivity). If you encounter an error regarding the image location, ensure that all images are placed in the correct folders inside the ZIP.
- Make sure the HTML is error-free. Every opening tag needs a closing tag, for example `<div><p>contents</p></div>`, and every CSS class needs its closing brace.
- If the upload fails with the error _Oh snap! Zip upload failed. Please contact our support team._, check the ZIP file against each of these specifications.

  <img alt="Upload Zip Template dialog with the Zip upload failed error message highlighted" src="/images/moengage_26821b.png" />

## Known Limitations

### Gmail-Specific CSS Behavior

- Gmail ignores `@media` hide/show queries on both mobile and desktop clients — build responsive layout with fluid-hybrid tables (percentage- or max-width-based) instead of relying on media-query toggles alone.
- Gmail does not honor `prefers-color-scheme` dark-mode CSS — it applies its own automatic color inversion instead, and it strips inline SVG. For attribute-casing and inline SVG details, refer to [Known Editor Behavior: HTML Attribute Casing and Inline SVG](#known-editor-behavior-html-attribute-casing-and-inline-svg). For dark-mode design guidance, refer to [Rendering Issues in HTML Templates](/user-guide/campaigns-and-channels/email/faqs-email/rendering-issues-in-html-templates).

### Personalization (Jinja) Syntax

- Never place Jinja loop/templating syntax as a direct child of a `<tr>` element — HTML parsers will hoist it out of the table structure and scramble the logic, causing "item is not defined" failures at send time even though the personalized preview looks correct. Unroll loops into fixed `<td>` cells with index-based access and fallbacks, or use Display Conditions for list-length-based variants.

### Fonts

- Custom or branded web fonts (Google Fonts, `@import`, etc.) will not render in most inbox clients — this is an email-client limitation, not a MoEngage gap. Custom fonts only display in "View in Browser," and the font `<link>`/`@import` must be added manually for View in Browser to pick it up. Design with web-safe fonts and a solid fallback stack for the inbox itself.
- If a font is not supported in the recipient's inbox, the email client uses its own fallback fonts, so the font in the sent email can differ from the font you used while composing it. To control the fallback sequence, set the `font-family` property with your preferred web-safe fonts. In the following example, _Noto Sans_ is the primary font. If the recipient's email client does not support _Noto Sans_, it falls back to _Arial_, and then to _sans-serif_:

  ```html Font Fallback Sequence wrap
  <p style="font-family: 'Noto Sans', Arial, sans-serif;">This is sample text.</p>
  ```

  To upload your own fonts and configure fallback fonts from the dashboard instead of editing HTML, refer to [Custom Fonts](/user-guide/campaigns-and-channels/email/getting-started-with-email/custom-fonts).

### Editor Behavior Quirks

- The rich-text editor can silently append trailing newline characters to a pasted link URL, breaking the click-through with nothing visibly wrong in the UI. If links start failing silently after editing, check the raw href in code view; switching to the HTML editor avoids the mangling since it passes HTML through untouched.
- The rich-text editor restructures imported HTML — head-level markup (like Gmail annotation schema) can get relocated into the body and broken, and `<script>` tags are rejected outright as a security measure. For head-level structured data, author it once and load it through the HTML editor (plain HTML passthrough, no DOM restructuring).
- Keep the entire `<html>`/`<body>` structure inside one place — never split opening tags in the template from closing tags inside a separately managed content block referenced via a merge tag. The editor can't resolve unresolved merge tags at edit time and may wipe out body content.
- Pasting raw HTML into the rich-text (WYSIWYG) view instead of the code view gets escaped as literal text and can shift formatting elsewhere in the email. Add HTML only through the code view, or paste plain text in the rich-text view and apply links via the toolbar's "Insert Link."
- If a link-edit popup won't open, suspect a browser extension (DLP/"safe-link" tooling) before assuming a template or platform problem — test in incognito or a clean browser profile before escalating.
