MoEngage provides various analysis types suited for different scenarios to evaluate product performance and user interactions with your platform. By utilizing these analysis options, you can implement data-driven customer engagement strategies. The available analysis options include:

- [Users](/user-guide/analyze/analytics/users)
- [Behavior](/user-guide/analyze/analytics/behavior)
- [Funnel](/user-guide/analyze/analytics/funnels)
- [Retention](/user-guide/analyze/analytics/retention)
- [Session and source](/user-guide/analyze/analytics/session-and-source)
- [User paths](/user-guide/analyze/analytics/user-paths)
- [Acquisition](/user-guide/analyze/analytics/acquisition)
- [Uninstalls](/user-guide/analyze/analytics/uninstall)

These tools will help you gather and analyze demographics, preferences, user interactions across various channels, conversion rates, and retention patterns. They will allow you to identify key trends and gain deeper insights into your customer and product needs.

# Getting Started

At a high level, you will follow these standard steps to perform these analyses. While the specifics may vary based on the case and needs, this provides a general overview of the process to be followed.

## Choose Events

Select the events or properties for the analysis, either single or multiple. Choose those that will provide the most value for your analysis. These should generally be relevant to your users and app/website.

![Screenshot 2025-04-08 at 11.48.21 AM.png](/images/moengage_da291d.png)

## Define Attributes

Select relevant attributes for your event. Attributes provide context for the events you choose, allowing you to filter specific actions or events further.

![Screenshot 2025-04-08 at 11.51.20 AM.png](/images/moengage_02efd2.png)

## Choose Users

Identify the users on whom you want to perform this analysis. These are the individuals who have completed the set of events that you have selected. For more information, refer to [Segmentation](/user-guide/segment/create-segments/rule-based-filter-segments).

![Screenshot 2025-04-08 at 11.52.27 AM.png](/images/moengage_cd0ff6.png)

## Analysis Options and Duration

MoEngage offers options for count-level and aggregated analysis. These options vary depending on the type of analysis. You will learn more about these options in the analysis types.

After selecting the analysis option, you will specify the duration for which you wish to run the analysis.

## Charts

Charts are the results obtained at the end of an analysis. They visually represent data, making it easier to understand large quantities and their relationships with different data. Each analysis type offers different ways to visualize your query. To give you a general overview, the types of visualization options available are:

- Line
- Bar
- Column
- Area
- Pie
- Choropleth

You can visualize the results in Numerical and Percentage views.

![2025-01-23_14-25-34 (1).gif](/images/moengage_d8d196.png)

## Tables

With charts, the data is also presented in tabular form, arranged in rows and columns. Tables are useful for locating specific information and identifying patterns.

You can adjust how each table looks and what it shows—resize and reorder columns, sort and filter values, pin the columns you care about, and download the current view—without rerunning your query. These table controls are available across Behavior, Funnels, Retention, Session & Source, User Analysis, and Custom Dashboards.

<Note>
Sorting, filtering, and other column actions only change how the table is displayed. They do not change the underlying query or the chart above the table.
</Note>

### Transpose Table

You can transpose the table. This allows you to view and download the table in your preferred format by shifting its vertical and horizontal orientation.

![Behavior table being transposed, switching the rows and columns, and then transposed back to the original orientation.](/images/analytics-table-transpose.gif)

### Sorting and Calculation

You can organize the data in the table without external tools. Click the header of any column to sort the table data. Sorting is available on every column.

- The first click sorts in ascending order, the second click sorts in descending order, and the third click resets the column to its default order.
- To sort by more than one column, hold **Shift** and click additional column headers. The table applies the sorts in the order you click them.
- You can also open the column menu (the three-dot icon in the column header) and select **Sort Ascending** or **Sort Descending**.

Along with sorting, you can choose the calculation type from the list in the column.

- Sum
- Median
- Average
- Min
- Max

For tables with multiple events, you can sort the calculation by clicking the header of the calculation type. This will sort the data in ascending or descending order. In the transpose view, the calculation type row remains fixed while the columns are sortable.

![Sorting a table column and selecting a calculation type such as Sum or Average from the column header.](/images/analytics-table-sorting-calculation.gif)

### Resize Columns

Drag the divider between two column headers to make a column wider or narrower. Each column has a minimum and maximum width, so content stays readable. To fit a column to its content automatically, open the column menu (the three-dot icon in the column header) and select **Autosize This Column** or **Autosize All Columns**. When you resize the browser window, the table adjusts to fit the available space.

![Dragging to resize a column and to reorder columns in the Behavior table.](/images/analytics-table-resize-reorder.gif)

### Filter

You can narrow the rows shown in a table without changing your query.

- **Column filters:** Click the filter (funnel) icon in a column header to keep only the rows that match a condition. For text columns, the available operators are **Contains**, **Does not contain**, **Equals**, **Does not equal**, **Begins with**, **Ends with**, **Blank**, and **Not blank**. You can combine two conditions with **AND** or **OR**, and apply filters on more than one column at the same time.
- **Quick search:** Use the **Search across all columns** box above the table to find a value across all rows and columns at once. The table updates as you type to show only matching rows.
- **Advanced filters:** For more complex conditions, open the **Filters** tab on the right sidebar to assemble multiple conditions into a single filter expression.

![Behavior table with a column filter open, showing operators such as Contains, Does not contain, Equals, and Begins with, alongside the Search across all columns box above the table.](/images/analytics-table-column-filter.png)

### Pin, Reorder, and Choose Columns

- **Pin:** To keep a column visible while you scroll horizontally, open the column menu (the three-dot icon in the column header), select **Pin Column**, and choose **Pin Left** or **Pin Right**. Select **No Pin** to unpin. You can also drag a column into or out of a pinned section.
- **Reorder:** Drag a column header left or right to change the order of columns.
- **Choose columns:** Open the column menu and select **Choose Columns** to show or hide columns, or use the **Columns** tab on the right sidebar. Select **Reset Columns** to restore the default layout.

![Column menu open on a table column, showing Sort Ascending, Sort Descending, Pin Column with Pin Left and Pin Right options, Autosize This Column, Autosize All Columns, Choose Columns, and Reset Columns.](/images/analytics-table-column-menu.png)

### Download the Table

To share or analyze the table elsewhere, click **Download Table** at the top of the table and choose **Download as CSV** or **Download as Excel**. The download reflects the table's current state, including any filters you applied and the sort order you set, and includes all columns.

![Download Table button at the top of the Behavior table, expanded to show the Download as CSV and Download as Excel options.](/images/analytics-table-download.png)

### Tooltips and Copy

When a cell value or column header is too long to fit, the full text appears in a tooltip when you hover over it. Values that already fit do not show a tooltip. You can also select one or more cells and copy them to your clipboard—the copied text keeps the order in which you selected the cells.

### Pagination and Infinite Scroll

How a table loads rows depends on where you view it. On the analysis pages (Behavior, Funnels, Retention, Session & Source, and User Analysis), tables are paginated: a **Page Size** selector controls how many rows appear per page, a row count shows the current range (for example, 1 to 38 of 38), and page controls let you move between pages. On Custom Dashboards, tables use infinite scroll, loading more rows as you scroll down.

### Pivot Tables

<Info>
This feature is only available in the Product Analytics package of MoEngage Analytics. To enable it for your account, contact your MoEngage Customer Success Manager (CSM) or the Support team.
</Info>

See your events and attributes side by side in MoEngage, without exporting the table to Excel. In pivot mode, you drag the table's columns into rows, columns, and values, and choose how the numbers add up. Your pivot always reflects the data you were already looking at: the same events, filters, and date range.

Pivot mode helps most when your analysis has several events or split-by attributes. The standard table shows one row for every combination of event and attribute value, which gets hard to compare as the combinations grow. In pivot mode, you decide what goes in the rows and what sits side by side in the columns.

<Tip>
  **Before You Start**

  - Open a [Behavior](/user-guide/analyze/analytics/behavior/behavior-analysis) or [Session and Source](/user-guide/analyze/analytics/session-and-source/session-and-source-analysis) analysis.
  - Split or group your data by at least one attribute, such as **Platform** or **City**. In Behavior, use **Split by** or **Group by user property**. In Session and Source, select a source property.

  If the **Pivot mode** toggle is disabled, check that the table isn't transposed and that your analysis type supports pivot. For more information, see [Where Pivot Is Available](#where-pivot-is-available).
</Tip>

#### Turn On Pivot Mode

<Steps>
  <Step title="Run the Analysis">
    Set up your Behavior or Session and Source analysis with at least one attribute to split or group by, and click **Apply**.
  </Step>
  <Step title="Turn On Pivot Mode">
    In the table header, next to **Transpose** and **Download Table**, turn on the **Pivot mode** toggle. The table opens empty, with the message *Drag fields into Row Groups and Column Labels to build your Pivot*, and the **Columns** sidebar opens on the right.
  </Step>
  <Step title="Build the Layout">
    Drag columns into **Row Groups**, **Values**, and **Column Labels**. For more information, see [Build a Pivot Table](#build-a-pivot-table).
  </Step>
</Steps>

<Tip>
Pivot rearranges the data you're already seeing. It doesn't fetch any new data, so you can try different layouts without rerunning the analysis.
</Tip>

To return to the standard table, turn off the **Pivot mode** toggle. If you change the analysis and click **Apply** again, pivot mode turns off and your layout is cleared, so you need to build it again.

#### Build a Pivot Table

A pivot has three parts:

- **Rows** are what you're comparing, such as platforms.
- **Columns** are what you want side by side, such as events.
- **Values** are the numbers you're comparing, such as daily counts.

The **Columns** sidebar lists the columns of the standard table that you can use:

- **Events**, which holds the event names. This column appears in Behavior only.
- One column for each split-by attribute, group-by user property, or source property in the analysis.
- One column for each date in the analysis duration, at the analysis granularity. For example, a daily analysis from 17 Sep 2026 to 24 Sep 2026 lists one column for each of those eight days. A weekly analysis lists one column per week.

Drag each column into the zone where you want it. To place a column faster, select its checkbox instead: attributes go to **Row Groups** and dates go to **Values**. To remove a column, click its **X**.

![Dragging Platform from the Columns sidebar into Row Groups, selecting the 4 Oct 2026 and 5 Oct 2026 checkboxes so they move to Values, and clicking X to remove sum(4 Oct 2026) from Values.](/images/analytics-table-pivot-build.gif)

| Zone | What it does | Example |
| :--- | :--- | :--- |
| **Row Groups** | Groups rows by the values of the column. Add more than one column to nest groups, in the order shown in the bar above the table. | Add **Platform** to get one row each for Android, iOS, and Web. |
| **Values** | Sets the numbers shown in the table. Each date column you add becomes a column in the pivot. Add only the dates you want to compare. | Add the three most recent dates to compare the last three days. |
| **Column Labels** | Adds a column group for each value of the column. Each group holds the date columns from **Values** and a **Total** column. Use an attribute with a short list of values, such as a text or true or false attribute. | Add **Events** to get one column group per event. |

<Note>
Integer, float, array, and object attributes can't be used as column labels, because each unique value would become its own column. You can still add them to **Row Groups**.
</Note>

**Tips**

- Pivot tables start collapsed, so you see only totals at first. To see the numbers by day, click the arrow next to a group name in the table header. Click it again to collapse the group.
- When you nest row groups, click the arrow next to a row group to show or hide the rows under it.
- The **Total** row at the bottom of the table aggregates each column across all rows.

![Behavior table in pivot mode with Platform in Row Groups, Events in Column Labels, and three dates in Values. The App/Site Opened column group is expanded to show a column for each date and a Total column, and a Total row appears at the bottom.](/images/analytics-table-pivot-mode.png)

##### Change the Pivot Aggregation

Each column in **Values** shows its aggregation function and name, for example **sum(17 Sep 2026)**. Values use **sum** by default. To change it, click the column in **Values** and select one of these functions:

| Function | What each group shows |
| :--- | :--- |
| **sum** | The total of the values in the group. |
| **avg** | The average of the values in the group. |
| **min** | The smallest value in the group. |
| **max** | The largest value in the group. |
| **count** | The number of rows in the group. |
| **first** | The value of the first row in the group. |
| **last** | The value of the last row in the group. |

![Aggregation menu open on a Values column, listing avg, count, first, last, max, and min.](/images/analytics-table-pivot-aggregation.png)

The column headers in the table show only the column name, such as the date, and don't include the function name.

#### Example: Compare Carts and Orders by Platform

An ecommerce team wants to know whether shoppers on each platform turn their carts into orders at the same rate.

In Behavior, the team adds two events, **Add to Cart** and **Order Placed**, splits each by **Platform**, chooses **Total events**, and runs the analysis daily from 22 Sep 2026 to 24 Sep 2026. The standard table has one row for every event and platform combination, so comparing carts to orders on the same platform means jumping between rows:

| Events | Platform | Average | 22 Sep 2026 | 23 Sep 2026 | 24 Sep 2026 |
| :--- | :--- | ---: | ---: | ---: | ---: |
| Add to Cart | Android | 1,350 | 1,200 | 1,350 | 1,500 |
| Add to Cart | iOS | 840 | 800 | 820 | 900 |
| Add to Cart | Web | 600 | 600 | 550 | 650 |
| Order Placed | Android | 340 | 310 | 320 | 390 |
| Order Placed | iOS | 255 | 240 | 255 | 270 |
| Order Placed | Web | 90 | 90 | 80 | 100 |

To put carts and orders side by side, the team turns on **Pivot mode** and builds this layout:

1. Drag **Platform** into **Row Groups**.
2. Drag **Events** into **Column Labels**.
3. Drag **22 Sep 2026**, **23 Sep 2026**, and **24 Sep 2026** into **Values**, and keep the function as **sum**.

The pivot now has one row per platform and one column group per event. With both groups expanded, the table looks like this:

| Group | Add to Cart: 22 Sep | Add to Cart: 23 Sep | Add to Cart: 24 Sep | Add to Cart: Total | Order Placed: 22 Sep | Order Placed: 23 Sep | Order Placed: 24 Sep | Order Placed: Total |
| :--- | ---: | ---: | ---: | ---: | ---: | ---: | ---: | ---: |
| Android | 1,200 | 1,350 | 1,500 | 4,050 | 310 | 320 | 390 | 1,020 |
| iOS | 800 | 820 | 900 | 2,520 | 240 | 255 | 270 | 765 |
| Web | 600 | 550 | 650 | 1,800 | 90 | 80 | 100 | 270 |
| **Total** | 2,600 | 2,720 | 3,050 | 8,370 | 640 | 655 | 760 | 2,055 |

The gap is now easy to read. On 22 Sep 2026, web shoppers placed about one order for every seven carts, compared with about one in four on Android and nearly one in three on iOS. The same pattern holds on every date, which points to a web checkout problem rather than a one-day dip. With both groups collapsed, the two **Total** columns give the same comparison for the whole period: 270 orders from 1,800 carts on web, against 1,020 from 4,050 on Android. The **Total** row gives the carts and orders across all platforms.

The team can reshape the pivot to answer follow-up questions:

- **Compare platforms for each event:** Move **Events** to **Row Groups** and **Platform** to **Column Labels**. Each event becomes a row, and the platforms sit side by side under each date.
- **Find where the gap comes from:** Add **City** as a **Group by user property** and click **Apply**. Turn on **Pivot mode** again, rebuild the layout, and drag **City** into **Row Groups** below **Platform**. Expand **Web** to see which cities have the lowest orders for their carts, and collapse it to return to the platform view.

For more examples across industries, see [How to Use Pivot Tables to Answer Common Business Questions](/use-cases/analytics/how-to-use-pivot-tables-to-answer-common-business-questions).

#### Download and Pin a Pivot Table

To share your pivot, download it or pin it to a dashboard:

- **Download:** Click **Download Table** and choose **Download as CSV** or **Download as Excel** to export the table in its pivoted shape. In the Excel file, grouped column headers are kept as merged header rows. For more information, see [Download the Table](#download-the-table).
- **Pin to a dashboard:** Pin the table to a [custom dashboard](/user-guide/analyze/dashboards/custom-dashboards). The dashboard widget shows the pivot layout as it was when you pinned it. You can't edit the layout from the dashboard, and the widget doesn't show the **Pivot mode** toggle. To change the layout, edit the pivot in the source analysis and pin it again.

#### Where Pivot Is Available

You can use pivot mode in Behavior and Session and Source analyses. It isn't available in Funnels, Retention, User Paths, or User Analysis.

Pivot works best for counts and totals. It isn't available for medians, percentiles, or ratio metrics such as bounce rate, because combining those numbers again gives misleading results. For these analysis types, the toggle is disabled, and its tooltip explains why. For example, a median shows *Pivot is not available for median or percentile aggregation*, and a ratio report shows *Pivot is not available for a derived ratio metric like this report type*.

<Tabs>
  <Tab title="Behavior">
    | Analysis type | Pivot available |
    | :--- | :--- |
    | Total events | Yes, when a split-by attribute or group-by user property is set. |
    | Unique users | Yes, when a split-by attribute or group-by user property is set. |
    | Unique sessions | Yes, when a split-by attribute or group-by user property is set. |
    | Aggregation with sum, minimum, maximum, average, or distinct count | Yes, when a split-by attribute or group-by user property is set. |
    | Aggregation with median or percentile | No. |
    | Total events per user with sum, average, minimum, maximum, or count | Yes, when a split-by attribute or group-by user property is set. |
    | Total events per user with median or percentile | No. |
    | Aggregation distribution | No. |
    | Attribute aggregation per user | No. |
  </Tab>
  <Tab title="Session and Source">
    | Report type | Pivot available |
    | :--- | :--- |
    | Session count | Yes, when a source property is selected. |
    | Conversion Count | Yes, when a source property is selected. |
    | Revenue | Yes, when a source property is selected. |
    | Avg. Session Duration | No. |
    | Avg. Sessions / User | No. |
    | Avg. Conversions/Session | No. |
    | Bounce Rate | No. |
  </Tab>
</Tabs>

#### Pivot Limitations

- You can't add custom calculated fields to a pivot.
- You can't edit a pivot from a dashboard widget. To change it, edit the pivot in the source analysis and pin it again.
