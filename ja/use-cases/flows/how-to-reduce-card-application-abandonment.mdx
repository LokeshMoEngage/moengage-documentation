title: "カード申し込みの放棄を減らす方法"

# はじめに

カードの申し込みは長くなることが多く、ユーザーがすぐには用意できない詳細情報の提出が必要になる場合があります。特にデジタルユーザーの集中力が持続しにくい現在において、これはマーケターにとって最も一般的でありながら対処が難しい状況の 1 つです。顧客をサイトに呼び戻し、申し込みを完了するよう促すことを目的とした Flows を設定できます。これによりコンバージョン率を高め、新規ユーザーや収益の損失を防ぐことができます。

この記事では、次の手順でカードの申し込みを完了するようユーザーに促す Flow キャンペーンを作成します。

- 顧客の離脱意図を検知し、離脱しないよう促す、またはリードを獲得するためのメッセージをウェブサイトに表示します。
- 申し込みプロセスから離脱した 1 時間後に、SMS でフォローアップメッセージを送信します。
- この Flow を通じてフォームを正常に送信したユーザー数を分析します。

# ステップ 1: 全般設定

1. **Engage** \> **Flows** に移動して **\+ Create Flow** をクリックするか、サイドバーに移動して **\+ Create new** をクリックしてから **Flow** をクリックします。
2. **\+ Start with a blank canvas** をクリックして、最初のステップ「Details and goals」に移動します。
3. 次の詳細を入力します。
   - **Flow name**: 「CreditCard Application Abandonment」と入力します。
   - **Flow tags**: Flow のタグを選択します。
4. **Conversion goal セクションで、****Event name** ドロップダウンリストから「BFSI-applicationFormSubmitted」を選択します。これは主要なコンバージョン目標であり、ユーザーが申し込みフォームを送信したときにトリガーされます。
   ![UC43-1.png](/images/moengage_d9830c.png)
5. **Exit on conversion** トグルをオンにして、「BFSI-applicationFormSubmitted」イベントを実行してコンバージョンしたユーザーを Flow から退出させます。
6. **Next** をクリックして 2 番目のステップ「When will users enter the flow」に進みます。このステップでは、トリガー条件を指定して、ユーザーをいつ Flow に参加させるかを定義します。
7. **Users enter the flow** セクションで **On event trigger** を選択します。
8. **IF user** セクションのドロップダウンリストから、ユーザーがクレジットカードの申し込みプロセスを開始したときにトリガーされる「BFSI-applicationFormStarted」イベントを選択します。
9. **THEN enter the user** セクションで、**Immediately** オプションを選択します。
   ![UC43-2.png](/images/moengage_9541c4.png)
10. **Flow Schedule** セクションでは、デフォルト値のままにします。デフォルトでは、Flow は「As soon as possible」に開始され、終了しません。必要に応じて Flow の開始時刻と終了時刻を定義します。
11. **Limit user entry into this flow** トグルをオンにして、ユーザーが Flow に参加できる最大回数を定義します。この例では、制限を 2 に設定できます。
    <Info>
      ユーザーはカード申し込み放棄 Flow の参加ルールに頻繁に一致する可能性が高く、Flow に何度も参加してしまうことがあります。このような制限を定義すると、ユーザーが繰り返し Flow に再参加するのを制御でき、過剰なメッセージ送信を避けられるため、より良いユーザーエクスペリエンスを提供できます。
    </Info>
    ![UC43-3.png](/images/moengage_b8ff6c.png)
12. **Next** をクリックして 3 番目のステップ「Who will enter the flow」に進みます。ここでは、Flow のターゲットオーディエンスとコントロールグループを選択します。
13. カードの申し込みを開始したものの送信していないすべてのユーザーにコミュニケーションを送信したいため、**Audience** セクションで **All users** を選択します。
    ![UC43-4.png](/images/moengage_77d9c1.png)
14. **Next** をクリックしてキャンバスセクションに移動します。

全般設定が完了したので、ユーザーが進む Flow の構造を定義しましょう。

# ステップ 2: 離脱意図 Flow

このステップでは、カードの必要な特典を得るためにフォームの申し込みを続けるよう促すポップアップをユーザーに表示します。また、申し込みを放棄する場合は電話番号を残すよう促します。次の画像は、離脱意図 Flow を通じて顧客に表示される働きかけのサンプルです。

![UC43-7.png](/images/moengage_558ca1.png)

このユースケースを実現するために、次の手順を実行します。

1. **\+** アイコンをクリックします。ドロワーが表示され、**Actions** の Push、Email、SMS、WhatsApp などのさまざまなオプションから、メッセージを送信するアクションキャンペーンを選択できます。On-site または In-app チャネルでバナーを表示したり、Facebook や Google のリマーケティングを使用したりすることもできます。
2. このシナリオでは、ユーザーの離脱意図を予測してほぼリアルタイムでポップアップを表示できるため、まず **On-site** オプションを選択します。詳細については、[Exit Intent Technology](/ja/user-guide/campaigns-and-channels/on-site-message/create/exit-intent-technology) を参照してください。
   ![UC43-5.png](/images/moengage_19e860.png)
3. On-site アクションにマウスポインターを合わせ、編集アイコンをクリックしてステージの定義を開始します。
   1. **Trigger criteria** セクションで **On Exit Intent** を選択します。
      ![UC43-6.png](/images/moengage_7276e3.png)
   2. カードの申し込みを放棄しようとしているすべてのユーザーに申し込みを完了するよう促したいため、**Target audience** セクションで **All users** を選択します。
   3. 次のステップでテンプレートを選択し、提供内容に基づいて詳細を入力します。ユーザーが離脱しないよう興味を引き、申し込みプロセスを続けてもらえるようにしてください。
4. ユーザーはまだ連絡先情報を提供していないため、このステップを適切に実行することが重要です。ユーザーがその後離脱した場合でも、営業チームを通じてリードとして活用できるよう、電話番号などの連絡先情報を必ず収集してください。\
   OSM を通じてユーザーから値を保存する方法の詳細については、[Lead Generation](/ja/user-guide/campaigns-and-channels/on-site-message/create/osm-templates#lead-generation) を参照してください。

離脱意図 Flow を定義したので、Flow に SMS ステージを追加してユーザーにフォローアップしましょう。

# ステップ 3: フォローアップメッセージを送信する

このステップでは、カードの申し込みを完了せず、離脱意図キャンペーンで電話番号を残したユーザーにフォローアップメッセージを送信します。申し込みプロセスから離脱した 1 時間後に、SMS でフォローアップメッセージを送信します。

1. **Has Done Event** ステージを追加し、ユーザーが「MOE\_RESPONSE\_SUBMITTED」イベントを通じてリード獲得フォームを送信し、かつカードの申し込みを完了していないかどうかを確認します。
2. **Keep Evaluating for the next** トグルをオンにして、ユーザーがイベントを実行するのを待つ最大時間を定義します。この例では、待機時間を 1 時間にします。
   ![Screenshot 2024-02-07 at 5.06.00 PM.png](/images/moengage_e146a7.png)
3. 連絡先情報を送信していないユーザーはリターゲティングできないため、「No」ブランチを編集する必要はありません。
4. 「Yes」ブランチで **\+** アイコンをクリックし、SMS ステージを追加します。
   <Info>
     ユーザーに SMS を送信するための同意の取得方法に関するルールは国によって異なります。電話番号は、お住まいの国の規制に準拠した方法で収集してください。
   </Info>
5. SMS メッセージを設定します。
   1. Campaign name: 「Card application abandonment SMS」と入力します。
   2. SMS Sender: SMS 送信者を選択します。
   3. Message: 申し込みを完了するようユーザーに促すメッセージを入力します。
      ![Screenshot 2024-02-07 at 5.39.27 PM.png](/images/moengage_c14982.png)
   4. **Done** をクリックします。
6. この時点で、Flow は次の画像のようになります。
   ![Screenshot 2024-02-07 at 5.25.13 PM.png](/images/moengage_096a61.png)
7. **Publish** をクリックします。

# まとめ

このユースケースでは、ユーザーがカードの申し込みを途中で放棄しないよう促し、送信せずに離脱したユーザーに SMS を送信する Flow を作成しました。

- Flow を公開したので、キャンペーンのパフォーマンスを[分析](/ja/user-guide/flows-cross-channel-messaging/analyze-flows/analyze-a-flow)できます。
- キャンペーンによってカードの申し込みに戻ってきたユーザー数を把握できます。「Flow ID」を指定して「User Entered Flow」イベントでセグメンテーションを作成します。詳細については、[Users who have entered/exited the Flow](/ja/user-guide/flows-cross-channel-messaging/analyze-flows/tracking-users-in-flows) を参照してください。
- キャンペーンによって実際にコンバージョンしたユーザー数も把握できます。「Flow ID」を指定して「Flow Trip Conversion」イベントでセグメンテーションを作成します。詳細については、[Conversion Tracking and Attribution in Flows](/ja/user-guide/flows-cross-channel-messaging/analyze-flows/conversion-attribution-in-flows) を参照してください。
