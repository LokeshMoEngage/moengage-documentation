# はじめに

Web サイトのホームページにカルーセルバナーを配置することは、アプリユーザーとのエンゲージメントを高め、特定のオファーをプロモーションするための優れた方法です。

この記事では、MoEngage Self-Handled Cards を使用して Android および iOS ネイティブアプリにバナーカルーセルを構築し、Card キャンペーンを作成して、これらのバナーカルーセルを通じてアプリ訪問者にターゲットを絞った Card を配信する方法を説明します。

# 期待される結果

ユーザーには、Web サイトのホームページにカルーセルバナーが表示されます。

![Announcement Carousels.gif](/images/moengage_0c0c91.png)

# 統合の手順

MoEngage の self-handled Cards を使用すると、Card コンテンツの生のペイロードにアクセスできます。これらのペイロードを利用するコンポーネントをアプリ内に作成し、アプリに統合されたコンポーネントとして機能するデザインとレイアウトで Card コンテンツを表示できます。

次の手順では、以下の内容について説明します。

1. [Cards の統合](/ja/use-cases/cards/how-to-add-carousel-banners-on-app-home-page#step-1-cards-integration)
2. [各カテゴリの Cards UI の作成](/ja/use-cases/cards/how-to-add-carousel-banners-on-app-home-page#step-2-guide-for-cards-ui-creation)
3. [MoEngage Cards ペイロードの解析とカルーセル UI へのフィード](/ja/use-cases/cards/how-to-add-carousel-banners-on-app-home-page#step-3-parsing-moengage-cards-payload-and-feed-into-the-carousel-ui)
4. [アナリティクスのトラッキング](/ja/use-cases/cards/how-to-add-carousel-banners-on-app-home-page#step-4-track-analytics)

## ステップ 1: Cards の統合

### Android の場合

#### **Catalog を使用したインストール**

Version Catalog を使用した統合が推奨される統合方法です。まだカタログを設定していない場合は、[Configure Version Catalog](https://developers.moengage.com/hc/en-us/articles/4407395989268) ドキュメントを参照して設定してください。カタログを設定したら、次に示すように _app/build.gradle_ ファイルに依存関係を追加します。

build.gradle

```json
dependencies {
    ...
    implementation(moengage.cardsCore)
}
```

または、[Artifact ID を使用したインストール](/ja/developer-guide/android-sdk/sdk-integration/advanced-or-optional/installing-sdk-using-artifact-id#core)で説明されているように、Artifact ID を使用して依存関係を追加することもできます。ただし、Artifact ID を使用したインストールでは、マッピングが正しくないとバージョンの不一致が発生する可能性があるため、Catalog ID を使用したインストールが推奨されます。

詳細については、[Android ネイティブの Self Handled Cards](/ja/developer-guide/android-sdk/cards/self-handled-cards) を参照してください。

### iOS の場合

#### **CocoaPod を使用したインストール**

次に示すように、podfile に依存関係を追加して MoEngageCards フレームワークを統合します。

Ruby

```ruby
pod 'MoEngageCards','~> 4.0.0'
```

次に、` pod install` を実行してフレームワークをインストールします。

詳細については、[iOS ネイティブの Self Handled Cards](/ja/developer-guide/ios-sdk/cards/self-handled-cards) を参照してください。

## ステップ 2: Cards UI 作成ガイド

self-handled cards を統合したので、次に Card ペイロードを利用してカードを表示する UI を構築します。例えば、このユースケースの構築では、Android には **SliderView**、iOS には **ImageSlider** を使用しました。これらは、ホームページ上で 3～4 秒ごと (設定可能) にスライドするカルーセル形式で表示されます。

<Info>
  **SliderView** と **ImageSlider** は、このユースケースで例としてのみ使用している外部ライブラリであり、MoEngage によってメンテナンスされているものではありません。信頼でき、ユースケースに最適なライブラリを使用することを強くお勧めします。
</Info>

**データを UI にレンダリングする際の注意点**:

- UI のキャンペーン駆動のコンポーネントは、cards ペイロードに存在するコンポーネント (タイトル、メッセージ、アクション、画像など) と一致している必要があります。
- ユーザーがどのカードの対象にもならない場合があります。そのような場合は、カルーセルウィジェットを削除するか、バックアップコンテンツを用意するよう対応してください。
- ペイロード内のすべての要素について、null 値、キャンペーンからの構文エラー、画像アセットが時間内に取得されないなどの例外シナリオを確認してください。
- 読み込みに時間がかかる可能性のあるアセットがある場合は、シームレスなユーザー体験のために暫定 UI の追加を検討してください。
- キャンペーンで使用する画像のサイズが画像コンテナに収まるようにするか、UI で画像のスケーリングを処理するようにしてください。
- テキスト (ヘッダーとメッセージ) は絵文字と HTML 形式 (書式設定、色など) をサポートしているため、Html.format() メソッドを使用して処理してください。
- 最上部に固定する機能は "display\_control" に含まれており、UI へのレンダリング時に個別に処理する必要があります (構造についてはサンプルペイロードを参照してください)。
- Illustration テンプレートと Basic テンプレートでは、ペイロードの構造が若干異なります。Basic テンプレートでは、image キーの null 値を考慮してください。

上記の関数から Cards データを取得した後、次のコードスニペットに示すように、データを解析して詳細を抽出し、UI へのレンダリングに使用する Model クラスに格納する必要があります。

```swift wrap
func parseData(cardData: MoEngageCardCampaign) -> NewCardModel {
      let newCardModel = NewCardModel()
      newCardModel.card = cardData
      let container : MoEngageCardContainer = (cardData.templateData?.containers.first)!
      newCardModel.container = container
      newCardModel.ctaAction = container.actions
      if(cardData.templateData?.type == MoEngageCardTemplateType.basic) {
          newCardModel.itemViewType = "Basic"
      } else {
            newCardModel.itemViewType = "Illustration"
        }
      newCardModel.templateType = cardData.templateData?.type;
      for widgetData in container.widgets {
          newCardModel.widget = widgetData
              if(widgetData.id == 0 && widgetData.type == MoEngageCardWidgetType.image) {
                  newCardModel.imageFromUrl = widgetData.content
              } else if(widgetData.id == 1 && widgetData.type == MoEngageCardWidgetType.text) {
                    newCardModel.cardTitle = widgetData.content
                } else if(widgetData.id == 2 && widgetData.type == MoEngageCardWidgetType.text) {
                      if(widgetData.content.isEmpty) {
                          print("Widget text missing will not show widget.")
                          continue
                      }
                  newCardModel.cardDescription = widgetData.content
                  } else if(widgetData.id == 3 && widgetData.type == MoEngageCardWidgetType.button) {
                        if(!widgetData.content.isEmpty) {
                            newCardModel.ctaAction = widgetData.actions
                        }
                    }
          }
      return newCardModel
      }
}
```

# アプリ内のさまざまなウィジェットの配置

上記の例では、Announcement Card カテゴリを使用して、ホームページのカルーセルウィジェットに追加するカードをフィルタリングしました。

アプリの複数のセクション (同じページ内の複数のセクションを含む) に self-handled cards を実装する場合は、Card Categories を使用してセクションを区別することをお勧めします。これにより、[カテゴリのカードを取得する](/ja/developer-guide/android-sdk/cards/self-handled-cards#fetch-cards-for-categories)関数を使用して、そのセクションに関連するカードのみを取得できます。

カードカテゴリを設定するには、[サポートチケットを作成](/ja/user-guide/contact-support/raise-a-support-ticket-through-moengage-dashboard)してください。

# まとめ

このユースケースでは、MoEngage Self-Handled Cards を使用して Android および iOS ネイティブアプリにバナーカルーセルを構築し、Card キャンペーンを作成して、これらのバナーカルーセルを通じてアプリ訪問者にターゲットを絞った Card を配信する方法を学びました。
