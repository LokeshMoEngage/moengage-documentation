以下の例を参考に、一般的なビジネス上の疑問に答えるピボットテーブルを作成してください。各例には、実行する分析と、ピボット内で各列を配置する場所が記載されています。イベント名とプロパティ名は例示のためのものなので、ワークスペースでトラッキングしている名前に置き換えてください。

ピボットモードの仕組みについては、[ピボットテーブル](/ja/user-guide/analyze/analytics/getting-started-with-analytics/overview#pivot-tables)を参照してください。

## 前提条件

- 各例に記載されているイベントとプロパティ、またはそれに相当するものがワークスペースでトラッキングされていること。
- **Split by** や **Group by user property** を含め、[Behavior 分析](/ja/user-guide/analyze/analytics/behavior/behavior-analysis)に精通していること。

## E コマース: どのカテゴリがどのプラットフォームで売れているかを把握する

マーチャンダイジングチームは、一部の商品カテゴリがウェブサイトよりもアプリでよく売れているかどうかを把握し、各カテゴリをどこでプロモーションするかを決めたいと考えています。

**分析:** Behavior で **Order Placed** イベントを選択し、**Category** と **Platform** で分割して、**Total events** を選択し、期間を過去 7 日間に設定します。

| ゾーン | 配置 |
| :--- | :--- |
| **Row Groups** | **Category** |
| **Column Labels** | **Platform** |
| **Values** | 週の各日付(**sum**) |

**結果の読み方:** 各行がカテゴリを表し、各日付はプラットフォームごとに 1 列ずつ分割されます。**Total** 行には、すべてのカテゴリにわたる各プラットフォームの日別の注文数が表示されます。ウェブでの注文が多くアプリでの注文が少ないカテゴリは、アプリ限定キャンペーンの候補になります。

注文数ではなく注文金額を比較するには、分析オプションを **Aggregation** に変更し、**Order Value** プロパティの **Sum** を選択して、同じレイアウトを維持します。

## 銀行・融資: 商品と顧客ティア別に申し込みを追跡する

融資チームは、ローン商品と顧客ティアごとに、ローン申し込みの週ごとの推移を確認したいと考えています。

**分析:** Behavior で **Loan Application Submitted** イベントを選択し、**Loan Type** で分割して、**Customer Tier** を **Group by user property** として追加します。**Total events** を選択し、粒度を週単位に、期間を過去 12 週間に設定します。

| ゾーン | 配置 |
| :--- | :--- |
| **Row Groups** | **Loan Type**、次に **Customer Tier** |
| **Values** | 週単位の日付列(**sum**) |

**結果の読み方:** 各ローンタイプを折りたたんで週ごとの申し込み数を確認し、展開してどの顧客ティアが傾向を牽引しているかを確認します。他のティアが安定している中で 1 つのティアだけが減少している場合は、季節的な落ち込みではなく、ターゲティングや適格性の問題を示しています。

## 保険: プランと獲得チャネル別に保険契約の購入を比較する

グロースチームは、各保険プランの購入者をどの獲得チャネルが呼び込んでいるかを把握したいと考えています。

**分析:** Behavior で **Policy Purchased** イベントを選択し、**Plan Type** と **UTM Source** で分割して、**Unique users** を選択し、粒度を月単位に、期間を前四半期に設定します。

| ゾーン | 配置 |
| :--- | :--- |
| **Row Groups** | **UTM Source** |
| **Column Labels** | **Plan Type** |
| **Values** | 月単位の日付列(**sum**) |

**結果の読み方:** 各行には、チャネルが毎月呼び込むプランの構成が表示されます。低価格プランの購入者は多いもののプレミアムプランの購入者が少ないチャネルでは、プレミアムセグメント向けに別のクリエイティブやランディングページが必要な場合があります。

## 投資・フィンテック: 資産とプラットフォーム別に取引規模を比較する

投資アプリのプロダクトチームは、各プラットフォームにおける資産ごとの平均取引規模を比較したいと考えています。

**分析:** Behavior で **Trade Executed** イベントを選択し、**Asset** と **Platform** で分割して、**Trade Amount** プロパティの **Average** を使用する **Aggregation** を選択し、期間を過去 7 日間に設定します。

| ゾーン | 配置 |
| :--- | :--- |
| **Row Groups** | **Asset** |
| **Column Labels** | **Platform** |
| **Values** | 週の各日付(**avg**) |

**結果の読み方:** 各セルには、その日のプラットフォームにおける資産の平均取引規模が表示されます。プラットフォーム間で大きな差がある場合は、高額取引を行うトレーダーが特定のプラットフォームを好んでいる可能性があり、新しい取引機能を最初にどこでリリースするかを決める際に役立ちます。

<Note>
分析の集計方法が中央値またはパーセンタイルの場合、ピボットは利用できません。これらの値を行全体で再度集計すると、誤解を招く数値になるためです。代わりに、合計、最小値、最大値、平均、またはユニーク数を使用してください。
</Note>

## メディア・エンターテインメント: ジャンルとサブスクリプションプラン別に視聴を比較する

コンテンツチームは、各サブスクリプションプランのユーザーがどのジャンルを最もよく視聴しているか、またそれが日ごとにどのように変化するかを確認したいと考えています。

**分析:** Behavior で **Video Played** イベントを選択し、**Genre** で分割して、**Subscription Plan** を **Group by user property** として追加します。**Total events** を選択し、期間を過去 14 日間に設定します。

| ゾーン | 配置 |
| :--- | :--- |
| **Row Groups** | **Subscription Plan**、次に **Genre** |
| **Values** | 比較したい日付(**sum**) |

**結果の読み方:** 各プランを折りたたんでプラン間の総視聴数を比較し、プランを展開してそのジャンル構成を確認します。無料プランのユーザーが特定のジャンルを多く視聴している場合、そのジャンルはアップグレードキャンペーンの良いフックになります。

## マーケティング: ソースとメディア別にトラフィックを比較する

マーケティングチームは、トラフィックのソースとメディアごとにセッション数を比較したいと考えています。

**分析:** Session and Source で **Session count** を選択し、ソースプロパティとして **Source** と **Medium** を選択して、期間を過去 7 日間に設定します。

| ゾーン | 配置 |
| :--- | :--- |
| **Row Groups** | **Source** |
| **Column Labels** | **Medium** |
| **Values** | 週の各日付(**sum**) |

**結果の読み方:** 各行には、ソースの日別セッションが email、cpc、social などのメディアにどのように分かれているかが表示されます。同じレイアウトで **Conversion count** を実行すると、どのソースとメディアの組み合わせがコンバージョンにつながっているかを確認できます。

<Note>
Avg. Session Duration、Avg. Sessions / User、Avg. Conversions/Session、Bounce Rate は比率であるため、ピボットできません。これらの指標を比較するには、標準のテーブルを使用してください。
</Note>

## 結果を共有する

ピボットを作成したら、次の 2 つの方法で共有できます。

- **ダウンロードする:** **Download Table** をクリックして、CSV または Excel としてエクスポートします。ファイルにはピボットされたレイアウトが維持されます。
- **ダッシュボードにピン留めする:** テーブルをカスタムダッシュボードにピン留めすると、関係者が同じレイアウトを確認できます。後でレイアウトを変更するには、元の分析で編集します。
