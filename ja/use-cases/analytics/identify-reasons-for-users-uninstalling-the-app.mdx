# はじめに

ユーザーがアプリをアンインストールする理由はさまざまです。たとえば、ユーザーエクスペリエンス (UX) の低さ、価値の欠如、過剰な広告、プライバシーへの懸念、パフォーマンスの問題、わかりにくいオンボーディングプロセス、バッテリーの消耗、ストレージの問題、アップデートの不足、関連性の低いキャンペーン、期待を満たしていないことなどが挙げられます。ユーザーがアプリをアンインストールした場合、ビジネスやブランドにとってアンインストールの理由を把握することが重要になります。

#### ユーザーがアプリをアンインストールする理由を特定するメリット

- **ユーザー行動の理解**: これらの理由と、ユーザーがアプリをアンインストールするタッチポイントを理解することで、ブランドはユーザーの行動に関するインサイトを得ることができます。
- **関連性の高いコミュニケーションの作成**: これらの理由を理解することで、その理由に対してより関連性の高いコミュニケーションを作成することもできます。詳細については、[Uninstalls](/ja/user-guide/analyze/analytics/uninstall) を参照してください。
- **ユーザーエクスペリエンスの向上**: アンインストールの理由を特定することで、具体的な問題に対処でき、全体的なユーザーエクスペリエンスの向上につながります。
- **今後のアンインストールの防止**: アンインストールの理由を理解することで、潜在的な問題に先回りして対処し、そもそもユーザーがアプリをアンインストールしないようにすることができます。
- **リテンションの向上**: アンインストールの理由に対処することで、ユーザーリテンションを向上させ、解約を減らすことができ、最終的にエンゲージメントが高くロイヤルなユーザーベースにつながります。

このユースケースは、次の 3 つのステップで実現します。

1. [アンインストール数を把握する](/ja/use-cases/analytics/identify-reasons-for-users-uninstalling-the-app#step-1-understand-the-number-of-uninstalls)
2. [ユーザーパスを把握する](/ja/use-cases/analytics/identify-reasons-for-users-uninstalling-the-app#step-2-understand-the-user-paths)
3. [アンインストールのファネル分析を実行する](/ja/use-cases/analytics/identify-reasons-for-users-uninstalling-the-app#step-3-perform-the-funnel-analysis-of-uninstalls)

# 期待される結果

_uninstall_ イベントが記録される前にユーザーが通過するタッチポイントと実行するイベントについて、全体的な理解を得ることができます。アンインストールイベントのレポートと、アンインストールからイベントをさかのぼる可視化を得られます。また、キャンペーン受信後のアンインストールに関するファネルチャートを成果として得られます。

<Tip>
  - 設定で Uninstall Tracking が有効になっている必要があります。詳細については、[Uninstall Tracking](/ja/user-guide/settings/analytics/uninstall-tracking) を参照してください。
  - 通知を受信するユーザーアクションを追跡するためのイベントが MoEngage で利用可能である必要があります。この例では、_Notification Received Android_ または _Notification Received iOS_ イベントを使用します。イベントの追跡方法については、[Developer Guide](/ja/developer-guide/introduction) を参照してください。
  - アプリをインストールするユーザーのアクションを追跡するためのイベントが MoEngage で利用可能である必要があります。この例では、_Uninstalled from device_ イベントを使用します。
</Tip>

# ステップ 1: アンインストール数を把握する

このセクションでは、**Analyze** セクションからアンインストール数を把握します。

1. MoEngage ダッシュボードの左側のナビゲーションメニューで **Analyze** をクリックし、**Uninstalls** をクリックします。特定の期間に発生したアンインストール数の傾向を確認できます。ここでの分析は、ユーザーレベルとイベントレベルで行われます。**Users** タブでは、アンインストールのユニーク数が表示されます。一方、**Events** タブでは、アンインストールがユニークか重複かに関係なく、アンインストールイベントの数が表示されます。詳細については、[Uninstall](/ja/user-guide/analyze/analytics/uninstall) を参照してください。
2. **Uninstalls By Time** セクションには、指標を表示するための粒度のオプションがあります。期間とプラットフォームごとに、日次、週次、または月次のアンインストール数を表示できます。\
   得られたチャートには、設定した期間の合計アンインストール数が表示されます。
3. **Uninstall By Attribute** セクションでは、特定の属性でアンインストールをフィルタリングできます。たとえば、ユーザーの **Last Known City** 属性でアンインストールを設定します。得られたチャートには、その特定の属性に関連付けられたアンインストール数が表示されます。

# ステップ 2: ユーザーパスを把握する

このセクションでは、アンインストールに至るユーザーパスを把握します。これにより、アンインストールの前に発生するイベントをマッピングできます。

1. MoEngage ダッシュボードの左側のナビゲーションメニューで **Analyze** をクリックし、**User Paths** をクリックします。アンインストールまでのパスを可視化するため、**Show user paths analysis** で、ユーザーパス _Ending With_ と属性 **Uninstalled from device** を選択します。
2. デフォルトのセグメントオプションを使用し、**All users** を対象に分析を実行します。
3. **User path window** を 4 時間に設定します。これは、アンインストールの前に発生するイベントを追跡する時間数です。
4. **User path steps** を 5 に設定します。これは、ユーザーがアンインストールを実行する前に追跡するレベルの数です。詳細については、[User Paths](/ja/user-guide/analyze/analytics/user-paths/user-paths-overview) を参照してください。
   ![Screenshot 2024-12-30 at 1.19.12 PM.png](/images/moengage_b1bd86.png)
5. **Chart for user paths** セクションでは、選択した特定の期間において、アプリのアンインストールにつながった重要なイベントとタッチポイントを把握できます。ユーザーパスチャートの読み方の詳細については、[Understanding Chart](/ja/user-guide/analyze/analytics/user-paths/user-paths-overview) を参照してください。

# ステップ 3: アンインストールのファネル分析を実行する

このセクションでは、ユーザーが Push キャンペーンを受信した後に発生したアンインストールのファネル分析を実行します。

1. MoEngage ダッシュボードの左側のナビゲーションメニューで **Analyze** をクリックし、**Funnels** をクリックします。
2. Push キャンペーン受信後のアンインストールを分析するため、**Steps** で最初のイベントを _Notification Received Android_ **OR** _Notification Received iOS_ として定義します。2 番目のイベントとして _Uninstalled from device_ を選択します。
3. セグメンテーションフィルターで **All users** を選択します。
4. **Funnel Options** セクションで、次の操作を行います。
   1. **Funnel Type** リストで _Funnel - Unique Users_ を選択します。ファネルタイプの詳細については、[Funnels](/ja/user-guide/analyze/analytics/funnels/funnels-overview) を参照してください。
   2. **Duration** フィールドで、期間を _Last 7 Days_ に設定します。
   3. **Funnel split** リストで _Step 1_ を選択し、次に _Campaign Name_ または _Readable Campaign_ を選択して、アンインストールの主な要因を把握します。
   4. **Funnel window** を 15 分に設定します。アンインストールをその特定のキャンペーンに帰属させるために、十分に短い時間にする必要があります。

# まとめ

このユースケースでは、Analytics からアンインストール数を把握し、アンインストールに至るユーザーパスを把握したうえで、アンインストールのファネル分析を実行しました。

アンインストールイベントとユーザーを詳細に分析するには、多大な労力が必要です。しかし、このレポートを取得すれば、全体的な戦略を計画し、さまざまなコホートに合わせたメッセージングを行うための十分なインサイトが得られます。
