# はじめに

プッシュの到達可能性は、すべてのキャンペーンのインプレッション数とエンゲージメント数に影響する要素です。優れたプッシュ通知をユーザーに届けるには、ユーザーがアプリでの受信を許可している必要があります。プッシュチャネルをオプトアウトしたユーザーがアプリに戻ってきたときに、オプトインを促すことができます。

この記事では、プッシュチャネルをオプトアウトしたユーザーがアプリに戻ってきたときにオプトインを促すIn-Appキャンペーンを作成します。プッシュのオプトインをリクエストするこれらのキャンペーンは、他のキャンペーンよりも自動的に優先されます。

# 期待される結果

ユーザーがアプリに戻ってくると、スマートフォンにIn-App通知が表示されます。

# In-Appキャンペーンを作成する

このセクションでは、プッシュチャネルをオプトアウトしたユーザーがアプリに戻ってきたときにオプトインを促すIn-Appキャンペーンを作成します。

## ステップ1: ターゲットユーザー

1. 左側のサイドバーに移動して **Engage** \> **Campaigns** をクリックし、**\+ Create campaign** をクリックするか、**\+ Create new**\> **Campaign** をクリックします。
2. **Inbound** で **In-app** をクリックします。
   ![In-app.png](/images/moengage_b1939a.png)
   キャンペーン定義の最初のステップである「Target users」に移動します。
3. 次の詳細を入力します。
   - **Campaign name**: キャンペーンの名前を入力します。例: 「Reminder for Returning Users」
   - **Campaign tags**: 関連するキャンペーンタグを選択します。
4. **Target Platforms** セクションで **iOS** を選択します。
   <img
     alt="3.png"
     src="/images/moengage_5c97e9.png"
     style={{ width:"61%" }}
   />
5. **Trigger Criteria** セクションで **On app open** を選択します。
   ![image-20240121-050504.png](/images/moengage_5b66b2.png)
   トリガー条件として **On custom event** を選択することもできます。このオプションを使用すると、ユーザーがアプリに高いエンゲージメントを示しているときにアプローチできます。たとえば、ユーザーが「Order Confirmed」を実行したときにポップアップを表示します。
6. **Select trigger time** セクションで **Immediately** を選択し、メッセージをすぐに送信します。
7. **Target audience** セクションで **Filter users by** を選択し、「Reachability Push iOS is 202」を選択して、iOSデバイスでプッシュ通知をオプトアウトしたユーザーのみを対象にします。
   ![image-20240615-165721.png](/images/moengage_8e2c63.png)
8. **Next** をクリックして、キャンペーンに含めるコンテンツを定義する2番目のステップ「Content」に進みます。

## ステップ2: コンテンツ

MoEngageのIn-Appキャンペーンでは、あらゆるユースケースに対応するさまざまなテンプレートが用意されています。また、ゼロから作成するオプションもあります。

1. ユーザーに表示するテンプレートを選択します。**Popup - Image, text, and 2 button** テンプレートの使用をお勧めします。Template Settingsページでカスタマイズできます。
2. **Buttons** セクションで、**Actions** タブを使用してユーザーの遷移先を選択します。次の2つのオプションがあります。
   - **Request notification permission** - ユーザーが対象となる場合、このアクションはiOSネイティブの通知許可をトリガーします。ユーザーがすでにプロンプトを拒否している場合は、アプリの通知設定画面に誘導され、そこで手動で通知許可を管理できます。
   - **Navigate to Notification Settings** - このアクションはユーザーをアプリの通知設定画面に移動させ、そこでユーザーが通知許可を管理できます。
3. **Next** をクリックして、キャンペーンのスケジュールと目標を定義する3番目のステップ「Schedule and goals」に進みます。

## ステップ3: スケジュールと目標

ここでは、キャンペーンのスケジュールの選択、コンバージョン目標の追加、キャンペーンの優先度の選択、カスタム配信コントロールの定義を行います。

1. **Send campaign** セクションで、In-Appアンケートの開始と終了のタイミングを定義します。 <img alt="image-20240121-054649.png" src="/images/moengage_d1e586.png" />
2. **Conversion goals** セクションで、トラッキングしたいコンバージョン目標を追加します。
3. **Campaign priority** セクションで、このキャンペーンに優先度を割り当てます。優先度を割り当てることで、特定の時点でユーザーが複数のメッセージの対象となる場合に、どのIn-Appメッセージを表示するかを決定できます。たとえば、**Critical** を選択すると、ユーザーが対象となる他のキャンペーンがある場合でも、このキャンペーンが必ず表示されます。
4. **Delivery controls** セクションで、要件に応じてコントロールを定義します。詳細については、[In-Appキャンペーンの作成](/ja/user-guide/campaigns-and-channels/in-app-message/create/create-in-app-campaign)を参照してください。  <img alt="image-20240121-054810.png" src="/images/moengage_01a11f.png" />
5. **Publish** をクリックします。

# まとめ

このユースケースでは、プッシュチャネルをオプトアウトしたユーザーがアプリに戻ってきたときにオプトインを促すIn-Appキャンペーンを作成しました。プッシュのオプトインをリクエストするこれらのキャンペーンは、他のキャンペーンよりも自動的に優先されます。

この自動化されたキャンペーンは、プッシュのオプトイン数を増やし、魅力的なコミュニケーションを受信できるユーザー数の増加につながります。ユーザーが再び通知許可をオフにしないよう、ユーザー行動を理解したうえで最適な方法でアプローチしてください。

キャンペーンを公開したら、CTRとコンバージョン(定義されている場合)をトラッキングして、キャンペーンのパフォーマンスを把握できます。詳細については、[In-Appキャンペーンのアナリティクス](/ja/user-guide/campaigns-and-channels/in-app-message/analyze/analyze-in-app-campaigns)を参照してください。
