# はじめに

マーケターとして、アンケートを実施し、その回答に基づいてユーザーをプロファイリングしたい場合があります。アンケートによるユーザーのプロファイリングは、ターゲットオーディエンスを理解し、ニーズや好みを特定し、製品、サービス、マーケティング施策を最適化してより良い成果を上げるのに役立ちます。

#### アンケートによるユーザープロファイリングのメリット

- **ユーザーニーズの理解**: アンケートを使用すると、企業はユーザーの属性、行動、好み、興味、オンライン行動、購入履歴に関する情報を直接収集できます。これはユーザーのニーズと期待を理解するうえで不可欠です。
- **改善すべき領域の特定**: アンケートにより、ユーザーが困難や不満を感じている領域が明らかになり、企業はこれらの問題を特定して対処できます。
- **体験のパーソナライズ**: ユーザープロファイリングにより、ターゲットを絞ったメッセージング、パーソナライズされた広告、リマーケティング戦略が可能になり、各ユーザーにとってより魅力的で関連性の高い体験を提供できます。
- **意思決定の支援**: ユーザーアンケートを通じて収集したデータは、マーケティング戦略についてデータに基づいた意思決定を行うための貴重なインサイトを提供します。
- **リテンションの向上**: ユーザーがキャンペーンの購読を解除したりエンゲージしなくなったりする理由を理解することで、顧客リテンションの向上、チャーンの軽減、長期的な関係の構築に役立ちます。

このユースケースは、[In-app Messaging キャンペーンを作成する](/ja/use-cases/in-app-message/profile-users-through-in-app-surveys#create-an-in-app-campaign)ことで実現します。ニュースレターの購読を解除したユーザーを対象にアンケートを実施し、アンケートの回答をユーザープロパティとして保存します。

# 期待される結果

ユーザーがアプリを開くと、アンケートが表示されます。

ユーザーが送信した回答は、ユーザープロパティとして保存されます。たとえば、ユーザーが回答を送信すると、その回答に関連付けられた属性がプロパティ _survey\_response_ に保存されます。この情報は、ユーザープロファイル内の _MOE\_RESPONSE\_SUBMITTED_ イベントで確認できます。

<Tip>
  - アプリが MoEngage Android SDK または iOS SDK と統合されている必要があります。統合の詳細については、[Android SDK](/ja/developer-guide/android-sdk) または [iOS SDK](/ja/developer-guide/ios-sdk) を参照してください。
  - ユーザーがニュースレターの購読を解除するアクションと、プラットフォーム、アプリバージョン、プランなどの関連情報を追跡するイベントが MoEngage で利用可能である必要があります。この例では、イベント _Newsletter Unsubscribed_ を使用します。イベントの追跡方法については、[Developer Guide](/ja/developer-guide/introduction) を参照してください。
</Tip>

# In-app キャンペーンを作成する

このセクションでは、ニュースレターの購読を解除したユーザーを対象にアンケートを実施する In-app キャンペーンを作成します。

## ステップ 1: ユーザーをターゲットにする

1. MoEngage ダッシュボードの左側のナビゲーションメニューで **Engage** をクリックし、**Campaigns** をクリックします。
2. All campaigns ページで **\+ Create new** をクリックします。
3. **Inbound** で **In-app** をクリックします。 <img src="/images/moengage_c4c6dd.png" alt="Screenshot 2025-05-12 at 10.27.15 AM.png" />
4. キャンペーンの名前とタグを定義します。
5. **Target platforms** セクションで、両方のプラットフォームのユーザーをターゲットにするために **Android** と **iOS** の両方を選択します。 <img src="/images/moengage_74878e.png" alt="image-20240121-050519.png" />
6. **Trigger criteria** セクションで、アンケートの条件として **On app open** を使用します。この条件を選択すると、ターゲットオーディエンスがアプリを開いたときにアンケートのポップアップが表示されます。 <img src="/images/moengage_128033.png" alt="image-20240121-050504.png" />
7. **Target audience** セクションでは、ニュースレターの購読を解除したユーザーをターゲットにします。これを行うには、**User behavior** タブをクリックし、セグメントを _Has Executed Newsletter Unsubscribed at least once in the last 30 days_ と定義します。 <img alt="image-20240121-050811.png" src="/images/moengage_b3d579.png" />
8. **Next** をクリックして 2 番目のステップ **Content** に進みます。

次のステップでは、キャンペーンのコンテンツを定義します。

## ステップ 2: コンテンツ

1. **Prebuilt and saved templates** タブで、左側の **Filter By Use Case** セクションにある **Survey** を選択します。検索ボックスを使用してテンプレートを検索することもできます。 <img alt="1.2.png" src="/images/moengage_b52602.png" />
2. **Survey Popup - Radio Buttons with Emoji** テンプレートを選択します。テンプレートのコードビューが表示されます。左側のセクションにある HTML コードスニペットで、コンテンツとデザインを編集できます。  <img alt="image-20240121-051423.png" src="/images/moengage_82fc35.png" />
3. **Android** タブと **iOS** タブの両方で、要件に基づいてコードを編集します。**Mirror platforms** トグルをオンにすると、変更が両方のプラットフォームに反映されます。HTML テンプレートの編集の詳細については、[HTML In-App Templates](/ja/user-guide/campaigns-and-channels/in-app-message/templates/html-in-app-templates) を参照してください。  <img alt="1.3.png" src="/images/moengage_6812a5.png" /> このコードは、選択された回答を属性として _MOE\_RESPONSE\_SUBMITTED_ イベントを自動的にトリガーするように定義されています。また、送信された回答を含む _survey\_response_ という名前のユーザープロパティも作成します。詳細については、[Survey](/ja/user-guide/campaigns-and-channels/in-app-message/templates/sample-html-in-app-templates#survey-template) を参照してください。 <img alt="image-20240121-054240.png" src="/images/moengage_1601e5.png" />
4. ユースケースに応じて、コード内のプロパティ名を編集できます。HTML
   ```html wrap
   <button
   class="btn btn-cstm-light submit"data-dismiss="modal"aria-label="Close"onclick="moengage.trackClick(1); moengage.trackEvent('MOE_RESPONSE_SUBMITTED',{survey_response: document.querySelector('input[name=customRadio]:checked').value},{},{},false,true); moengage.setUserAttribute('survey_response', document.querySelector('input[name=customRadio]:checked').value)">Submit</button>          
   ```
5. **Next** をクリックして 3 番目のステップ **Schedule and goals** に進みます。

次のステップでは、キャンペーンのスケジュールと目標を定義します。

## ステップ 3: スケジュールと目標

1. **Send campaign** セクションで、In-app アンケートの開始日時と終了日時を定義します。 <img alt="image-20240121-054649.png" src="/images/moengage_c586fe.png" />
2. **Conversion goals** セクションで、追跡したいコンバージョン目標を追加します。詳細については、[Schedule and goals](/ja/user-guide/campaigns-and-channels/in-app-message/create/create-in-app-campaign#step-3-schedule-and-goals) を参照してください。
3. **Campaign priority** セクションで、このキャンペーンに優先度を割り当てます。たとえば、**Critical** を選択すると、ユーザーが対象となる他のキャンペーンがある場合でも、このキャンペーンが常に表示されます。
4. **Delivery controls** セクションで、要件に基づいてコントロールを定義します。詳細については、[Create In-app Campaign](/ja/user-guide/campaigns-and-channels/in-app-message/create/create-in-app-campaign) を参照してください。  <img alt="image-20240121-054810.png" src="/images/moengage_d73ac6.png" />
5. **Publish** をクリックします。

これでキャンペーンが公開されました。ユーザーがアンケートを送信すると、そのデータが追跡され、MoEngage のユーザープロファイルに保存されます。

# まとめ

このユースケースでは、In-app アンケートを使用してユーザーをプロファイリングする方法を学びました。収集した回答を使用してユーザーをプロファイリングできます。

キャンペーンを公開したら、クリックスルー率（CTR）とコンバージョン（定義されている場合）を追跡して、キャンペーンのパフォーマンスを把握できます。詳細については、[In-app Campaign Analytics](/ja/user-guide/campaigns-and-channels/in-app-message/analyze/analyze-in-app-campaigns) を参照してください。
