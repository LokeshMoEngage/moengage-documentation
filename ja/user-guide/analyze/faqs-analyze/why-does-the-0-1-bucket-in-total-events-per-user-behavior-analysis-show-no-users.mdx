## 問題

カスタム分布を使用して **Total Events per User** の行動分析を実行すると、アクティビティの低いユーザーが含まれることを期待しているにもかかわらず、0-1 バケットには常に 0 ユーザーと表示されます。

## この現象が発生する理由

次の 2 つの要因が組み合わさることで、このバケットは常に空になります。

1. **Total Events per User は、選択したイベントを少なくとも 1 回実行したユーザーのみをカウントします。** この分析では、各ユーザーがすでに実行したイベントを何回実行したかを測定するため、結果セットにカウント 0 が現れることはありません。
2. **カスタム分布のバケットには上限値が含まれません。** 0-1 バケットは 0 以上 1 未満の値、つまりカウントがちょうど 0 の場合のみを対象とします。イベントがちょうど 1 回のユーザーは、0-1 ではなく次のバケットである 1-2 に分類されます。

この分析ではカウントが 0 のユーザーは存在し得ないため、データにかかわらず 0-1 バケットは常に空になります。

<Tip>
  実際の利用頻度の分布をわかりやすく表示するには、**Distribution bucketing** を **Custom** に設定し、**From** を 0 ではなく 1 に設定します。バケットは **From**、**to**、**interval** の値から生成されるため、0 から開始すると最初のバケットは常に空になります。
</Tip>

## イベントがゼロのユーザーを見つける方法

行動分析はイベントを実行したユーザーのみを分析するため、イベントを一度も実行していないユーザーを抽出することはできません。イベントがゼロのコホートを見つけて対応するには、代わりにセグメンテーションを使用します。

1. **Segment** \> **Create segment** に移動し、**Filter users by** を選択します。
2. **User behavior** タブで **Has Not Executed** を選択し、イベント(たとえば **App/Site Opened**)を選択します。
3. 目的の期間(たとえば **in the last** 7 **days**)を設定します。  
    <img
      alt="User behavior フィルターが過去 7 日間に App/Site Opened を Has Not Executed に設定されている Create segment ページ"
      src="/images/segment-has-not-executed-condition.png"
    />
4. **Show count** をクリックしてコホートのサイズを確認し、セグメントを保存します。

このセグメントを分析に直接使用したり、イベントを実行していないユーザーをターゲットにした再エンゲージメントキャンペーンの作成に使用したりできます。
