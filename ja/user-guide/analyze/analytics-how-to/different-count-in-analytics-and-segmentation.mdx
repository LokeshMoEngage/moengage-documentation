MoEngage では、ユーザー数を 2 つの異なるページ（Analytics ページと Segmentation ページ）で分析できます。

Segmentation ページではセグメントのユーザー数とサンプルユーザーが提供され、Analytics ページ（Behavior、Funnel など）ではユニークユーザー数に加えて、イベント数、イベント頻度、収益、リテンション、ファネルの情報が提供されます。

## Behavior と Segmentation のユーザー

Behavior ページでユーザーを分析するには、Plot For として Total Users を選択します。このオプションでは、折れ線グラフ/面グラフでは選択した粒度ごとのユニークユーザー、棒グラフでは全体のユニークユーザーが表示されます。

一方、Segmentation ページでは全体のユニークユーザー数が表示されます。

## ユーザーのマージ

Segmentation ページと Behavior ページの 2 つのユーザー数が一致しない場合があります。これはユーザーのマージが原因で発生することがあります。MoEngage のエンゲージメントモジュールでは、異なるデバイスから来たユーザーは、ログイン時にマージされます。[ユーザーのマージについては、こちらで詳しく説明しています。](/ja/user-guide/data/user-data/user-profile)

ユーザーのマージは MoEngage Analytics モジュールでも利用できます。ただし、デフォルトでは有効になっていません。そのため、システム内に残存する匿名ユーザーが存在します。

通常、1 人の人物が、匿名だったときとログインしていたときの 2 種類のイベントを Analytics 内で持つことがあり、その結果 2 人の異なるユーザーとして識別されます。

このシナリオに対処するには、ユーザーのマージを有効にします。これにより、匿名ユーザー ID を登録済みユーザー ID とマージし、それらのユーザーを 1 人として表示できます。

ユーザーのマージを有効にするには、次のパスに従います。

*Settings -\> General Settings -\> Analytics Settings -\> Enable User Merging*

## Funnel と Segmentation のユーザー

ファネルのユーザー数とセグメンテーションのユーザー数には違いが生じることがあります。これは主に、ファネルとセグメンテーションの動作の違いによるものです。

ファネルはイベントの順序を考慮します。イベント E1 と E2 のユーザーファネルの場合、最終的な数はイベント E1 を実行し、その後に E2 を実行したユーザーです。E1 の前に E2 を実行したユーザーは考慮されません。

セグメンテーションはイベントの順序を考慮しません。イベント E1 と E2 のユーザーセグメントの場合、最終的な数は E1 と E2 の両方のイベントを実行したユーザーです。どちらが最初のイベントで、どちらが 2 番目のイベントかは関係ありません。
