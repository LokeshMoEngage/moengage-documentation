# セッション

Session Analysis は、ユーザーが Web アプリやモバイルアプリとどのようにやり取りしているかを理解するのに役立ち、プロダクトやデザインの改善につなげることができます。セッションを分析することで、アプリや Web サイトにおけるユーザー体験の質を把握できます。

## セッションとは

セッションとは、特定の時間枠内における Web サイトまたはアプリ上でのユーザーの一連のインタラクションを表します。セッションは主に、ユーザーがデバイス上で実行したイベントやアクティビティを記録することでトラッキングされます。

セッションは個々のデバイスに固有のものです。サーバー側で発生したユーザーアクティビティやイベントは、セッションに含まれません。

## 計算方法

セッションは、ユーザーがデバイス上で実行した最初のイベントまたはアクティビティから始まります。この最初のアクションのタイムスタンプが、セッションの開始時刻となります。

セッションは次の場合に終了します。

- **ログアウト**: ユーザーがアプリケーションからログアウトした場合。
- **ソースの変更**: 現在のセッションがアクティブな間に、ユーザーが別のトラフィックソースからセッションに入った場合。すべてのセッションにはソース情報が関連付けられています。このソースデータは UTM パラメーターから取得され、トラフィックソース、メディア、キャンペーンなどのプロパティが含まれます。ソースはオーガニックの場合も有料の場合もあります。ソースのプロパティのうち 1 つ以上が既存セッションのソースプロパティと一致しない場合にのみ、ソースが異なるとみなされます。
- **非アクティブ**: ユーザーが指定された非アクティブ期間(デフォルト: 30 分)を超えて操作を行わなかった場合。

各セッションには、定義された開始時刻と終了時刻があります。これらの時刻の間に実行されたすべてのイベントとアクティビティは、そのセッションの一部とみなされます。セッションの長さは、セッションの開始時刻と終了時刻の差として計算されます。

### インタラクションイベントと非インタラクションイベント

セッション内のユーザーイベントは、次の場合にインタラクティブとみなされます。

- アプリや Web サイトがバックグラウンドにある場合でも、新しいセッションを開始する。
- アプリや Web サイトがバックグラウンドにある場合でも、現在のセッションを延長する。
- ソース情報とセッション情報を含む。

内部用途や技術的な目的で必要なイベント、またはユーザーのアクションによって直接生成されないイベントは、非インタラクションイベントとみなされます。これらのイベントはセッションの計算に影響せず、次のような特性があります。

- アプリ/サイトがフォアグラウンドにある場合でも、新しいセッションを開始しない。
- セッションを延長しない。
- ソース情報とセッション情報を含まない。

たとえば、_Notification Received_ イベントは非インタラクションイベントです。このイベントはセッション時間を増加させず、セッションイベントとしてカウントされません。

非インタラクティブイベントの指定方法の詳細については、MoEngage 開発者ドキュメントの [Android SDK](/ja/developer-guide/android-sdk/data-tracking/basic/track-events)、[iOS SDK、](/ja/developer-guide/ios-sdk/data-tracking/advanced/session-and-source-tracking)および [Web SDK](/ja/developer-guide/web-sdk/data-tracking/web-sdk-events-tracking) を参照してください。

セッション分析には UTM パラメーターが必須です。詳細については、[Source Analysis](/ja/user-guide/analyze/analytics/session-and-source/session-and-source-overview#utm-parameters) を参照してください。

# ソース

ユーザーのソースは、マーケティング施策の ROI を測定するうえで重要な要素です。ソースを分析することで、トラフィックの質とエンゲージメントを評価し、最も効果的なソース、メディア、キャンペーンを特定できます。

## ソースのプロパティ

### UTM パラメーター

UTM パラメーターは、さまざまなトラフィックソースのパフォーマンスを分析するために使用されます。デフォルトでは、MoEngage SDK は Web トラフィックの場合は URL から、モバイルアプリの場合はディープリンクから UTM パラメーターを自動的に取得します。

MoEngage は次の UTM パラメーターをサポートしています。

- **utm_source**: 特定の Web サイト、アプリ、リンクなど、トラフィックのソースを識別します。(例: YouTube、Instagram、Google)
- **utm_medium**: 使用されたチャネルの種類を識別します。(例: プッシュ通知、バナー広告、メール)
- **utm_campaign**: 特定のマーケティングキャンペーンの名前を識別します。(例: Newyear、Bigbillionday)
- **utm_term**: 有料広告トラフィックで使用された検索語句を識別します。(例: Mobile+sale)
- **utm_content**: 広告またはキャンペーン内で使用された特定のコンテンツを識別します。(例: バナー、動画、商品画像)

次の URL では、_utm_source_ と _utm_medium_ がパラメーター名で、_MoEngage_ と _email_ がそれぞれの値です。

[_https://www.testdomain.com/?utm_source=MoEngage&utm_medium=email&utm_campaign=Newyear &utm_term=mobile+sale&utm_content=image_](https://www.testdomain.com/?utm_source=MoEngage&utm_medium=email&utm_campaign=Newyear)

### ユーザー定義パラメーター

<Tip>
  Source Analysis を効果的に活用するには、UTM パラメーターまたはカスタムのユーザー定義パラメーターが必要です。これらがない場合、ソース、キャンペーン、メディア、コンテンツ、ターム、およびカスタムのユーザー定義パラメーターに関する情報は利用できません。すべてのマーケティングリンク、紹介リンク、キーと値のペアに UTM またはカスタムパラメーターの情報が含まれていることを確認してください。ユーザー定義パラメーターを有効にするには、MoEngage サポートチームにお問い合わせください。
</Tip>

多くのマーケターは、自社のビジネスニーズに特化したカスタムソースパラメーターを使用しています。MoEngage はこれらのカスタムパラメーターにも対応しています。標準の UTM パラメーターに加えて、アプリや Web サイト用に最大 5 つのカスタムパラメーターを定義できます。MoEngage SDK は、URL 内のこれらの新しいパラメーターをソースプロパティとして認識し、すべてのイベントに自動的に含めます。

プッシュ通知では、ディープリンクが存在しない場合やディープリンクにソース情報が含まれていない場合、SDK はキーと値のペアの中からソースプロパティを検索します。

### アトリビューション

MoEngage はラストクリックアトリビューションモデルを採用しています。つまり、すべてのユーザーアクティビティとイベントは、ユーザーが最後にクリックしたソースに帰属します。アトリビューションウィンドウはセッションの長さによって定義されます。

たとえば、ユーザーが Google Ads 経由で訪れ、5 分間のセッション中アクティブで、15 個のイベントをトリガーした場合、15 個すべてのイベントのソースプロパティ値は _Google Ads_ になります。次のセッションでユーザーがオーガニックに訪れた場合、そのセッションのイベントにはソース情報が帰属されません。

# ユースケース

マーケターやプロダクトオーナーは、Session and Source Analysis を使用して次のような質問に答えることができます。

- 総セッション数とユーザーあたりのセッション数は、時間の経過とともにどのように推移しているか?
- 総イベント数とトリガーされた固有のイベントタイプ数から見た、ユーザーセッションの一般的な深さはどの程度か?
- 特定のコンバージョンイベント(購入やサインアップなど)を含むセッションはいくつあるか
- 特定のユーザーの連続するセッション間の平均経過時間はどのくらいか?
- ユーザーが訪れたソース、キャンペーン、メディアによって、ユーザーアクティビティや主要イベントの発生にどのような違いがあるか?
- トラフィックソースのパフォーマンスはどうか?
- どの MoEngage キャンペーンタイプが最良の成果、エンゲージメント、リテンションをもたらしているか?
- トラフィックソースからどの程度のコンバージョンと収益が生まれているか?
- 特定のチャネルのパフォーマンスはどの程度か?
