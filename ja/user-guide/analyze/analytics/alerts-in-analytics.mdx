# 概要

アラートを使用すると、ダッシュボードを手動で確認しなくても分析データを監視できます。保存済みの分析に条件を定義すると、その条件が満たされたときにMoEngageからメールが届くため、異常、減少、急増が発生した時点ですぐに対応できます。

アラートは、次の分析タイプで作成できます。

- [Behavior](/ja/user-guide/analyze/analytics/behavior/behavior-analysis)
- [Retention](/ja/user-guide/analyze/analytics/retention/retention-analysis)
- [Funnels](/ja/user-guide/analyze/analytics/funnels/funnel-analysis)
- [Session and source](/ja/user-guide/analyze/analytics/session-and-source/session-and-source-analysis)

# 活用例

アラートを使用すると、次のことができます。

- **行動トレンドの追跡** — トラッキングしているイベントのTotal Events、Unique Users、Unique Sessionsが大きく変化したときに通知を受け取ります。
- **リテンションの監視** — D7などの特定のリテンション日を監視し、リテンションが上昇または低下したときに通知を受け取ります。
- **ファネルの離脱の検出** — ファネルの任意の2ステップ間でコンバージョンしたユーザー数にアラートを設定し、カスタマージャーニーにおける悪化を発見します。
- **セッションと獲得の健全性の監視** — ソースごとのセッション数、直帰率、収益を追跡し、主要な指標が変化したときに通知を受け取ります。

# アラートを作成できるユーザー

**Admin**、**Manager**、**Marketer**、**Analyst**のロールを持つユーザーは、アラートを作成および管理できます。**Developers**はアラートを作成または管理できません。

各ロールのアラートへのアクセスは、**Settings > Account > Team Management > Roles > OOB Alerts Management**で設定できます。

# アラートの作成

アラートの作成は、2つのステップで行います。

**Step 1**: [分析の作成](/ja/user-guide/analyze/analytics/alerts-in-analytics#create-analysis)

**Step 2**: [新しいアラートの作成](/ja/user-guide/analyze/analytics/alerts-in-analytics#create-a-new-alert)

## Create Analysis

保存済みの任意のBehavior、Retention、Funnel、Session and source分析にアラートを設定できます。大まかな流れは、どの分析タイプでも同じです。

<Steps>
  <Step title="分析を作成する">
    左側のサイドバーから**Analyze**に移動し、アラートを設定する分析タイプ([Behavior](/ja/user-guide/analyze/analytics/behavior/behavior-analysis)、[Retention](/ja/user-guide/analyze/analytics/retention/retention-analysis)、[Funnels](/ja/user-guide/analyze/analytics/funnels/funnel-analysis)、または[Session and source](/ja/user-guide/analyze/analytics/session-and-source/session-and-source-analysis))を選択します。イベント、フィルター、オプションを設定し、**Apply**をクリックしてチャートを表示します。
  </Step>
  <Step title="My Studioに保存する">
    **Save**ドロップダウンをクリックし、**Save to My Studio**を選択します。

    <Info>
      分析にアラートを設定する前に、分析をMy Studioに保存する必要があります。
    </Info>
  </Step>
</Steps>

### 例: Behavior分析

この手順では、*App/Site Opened*イベントに対するBehavior分析を作成し、アプリまたはサイトが50回を超えて開かれたときにアラートを受け取れるようにします。

1. MoEngageダッシュボードの左側のサイドバーで、**Analyze \> Behavior**に移動します。
2. **Events & Filters**セクションでドロップダウンをクリックし、**App/Site Opened**を選択します。

   ![Events and Filtersドロップダウンで App/Site Opened イベントを選択する](/images/moengage_e9fb32.png)

   <Accordion title="任意">
     イベントには次のフィルターを追加できます。
     - 複数の属性の追加 — **AND**または**OR**の論理演算子を使用して、イベントの属性を組み合わせます。分析ではすべての属性が適用され、結果が表示されます。

       ![AND または OR 演算子でイベントに複数の属性を追加する](/images/moengage_8afaf4.png)
     - イベントの分割 — **Split by**オプションを使用して、選択した属性をドロップダウンの別の属性と比較します。詳細については、[Comparing Properties](/ja/user-guide/analyze/analytics/compare-mode-in-analytics)を参照してください。

       ![Split by を使用して選択した属性を別の属性と比較する](/images/moengage_b6f8fb.png)
     - 複数のイベントの追加 — **\+ Add Event**ボタンを使用して、最大10個のイベントを追加します。分析ではすべてのイベントが実行され、結果が表示されます。

       ![Add Event ボタンで Behavior 分析に複数のイベントを追加する](/images/moengage_336524.png)
   </Accordion>
3. この分析を適用するユーザーを選択します。デフォルトでは、分析はワークスペース内のすべてのユーザーに対して実行されます。対象を絞り込むには、**Filter by users**オプションを使用します。\
   詳細については、[Filter Users](/ja/user-guide/analyze/analytics/behavior/behavior-analysis)を参照してください。

   ![Behavior 分析の Filter by users オプション](/images/moengage_ef1920.png)
4. **Behavior Options**セクションで、計算する分析タイプを選択します。次の分析タイプでアラートを作成できます。
   - Total Events
   - Unique Users
   - Unique Sessions
   - Aggregation
   - Total Events Per User

     ![Behavior Options セクションで分析タイプを選択する](/images/moengage_291a8a.png)
5. **Apply**をクリックします。
6. **Behavior Chart**が表示されたら、**Save**ドロップダウンをクリックし、**Save to My Studio**を選択します。

   ![Behavior 分析を My Studio に保存する](/images/moengage_d9bcbb.png)

## Create a New Alert

分析を作成したら、My Studioからその分析にアラートを設定します。

アラートを作成するには、

1. MoEngageダッシュボードの左側のサイドバーで、**Analyze \> My Studio**に移動します。
2. **Saved analysis**のリストから分析を選択します。

   ![My Studio のリストから保存済みの分析を選択する](/images/moengage_16e02b.png)
3. **Apply**をクリックして分析チャートを表示し、チャートタイプと粒度を選択します。サポートされているチャートと粒度の組み合わせについては、[Alert Subscription Details](/ja/user-guide/analyze/analytics/alerts-in-analytics#alert-subscription-details)を参照してください。

     <Info>
       - 時間単位のチャート粒度ではアラートはサポートされていません。
       - 時系列比較またはセグメント比較が適用されている場合、アラートはサポートされていません。
       - タイムゾーンはデフォルトでアプリのタイムゾーンになります。
     </Info>
4. **Set alert**をクリックして、選択した分析に新しいアラートを作成します。

   ![Set alert をクリックして選択した分析に新しいアラートを作成する](/images/moengage_240bb4.png)
5. **Create alert**ポップアップで、次の詳細を入力します。
   - **Alert Name** — アラートの一意の名前。
   - **Alert Criteria** — トリガー条件。利用できる条件は分析タイプによって異なります。[分析タイプ別のアラート条件](/ja/user-guide/analyze/analytics/alerts-in-analytics#alert-criteria-by-analysis-type)を参照してください。
   - **Alert Recipients** — アラートを受信するサブスクライバーのメールアドレス。受信者はワークスペースへのアクセス権を持っている必要があります。
   - **Alert evaluation time** — アラートが評価され、メールが送信されるタイミング。
6. **Create**をクリックします。

# Alert Criteria by Analysis Type

アラートに設定できる条件は、分析タイプによって異なります。

## Behavior

イベント数または集計値に基づいてアラートをトリガーします。利用できる条件:

- **Above** — 選択した分析のカウントがしきい値を上回ったときにトリガーされます。
- **Below** — カウントがしきい値を下回ったときにトリガーされます。
- **Increased by percentage (%) or value (#)** — カウントが前の期間と比較して、パーセンテージまたは固定値だけ増加したときにトリガーされます。
- **Decreased by percentage (%) or value (#)** — カウントが前の期間と比較して、パーセンテージまたは固定値だけ減少したときにトリガーされます。

次の項目を使用して条件を絞り込むこともできます。

- **Select event** — 分析の作成時に選択したイベント。
- **Select Split by** — イベント属性とその値。たとえば、*App/Site Opened*イベントで、Platformが*Android*である*Platform*で分割します。
- **Select Group by user property** — ユーザープロパティとその値。たとえば、*App/Site Opened*イベントで、countryが*USA*である*last known country*でグループ化します。

## Retention

**D7**など、コホート内の特定の日のリテンションに対してアラートをトリガーします。

- パーセンテージ(%)または値(#)による**Increased by**または**Decreased by**をサポートしています。
- **Above**および**Below**のしきい値はRetentionには適用されません。

Retentionアラートは、最近のデータのローリングウィンドウ(月次リテンションの場合は最大365日)をクエリします。ウィンドウより古いデータは、ワークスペースに保存されていてもアラートの評価対象になりません。

## Funnel

ファネルの任意の2ステップ間でコンバージョンしたユーザー数に対してアラートをトリガーします。

- 最初のステップは固定の開始点です。2番目のステップを選択すると、アラートはその2つのステップ間のコンバージョンを追跡します。
- Funnelアラートは、2つのステップ間の**コンバージョンしたユーザー数**を評価します。コンバージョン率ではありません。設定した条件は、最初のステップに入ったユーザー数に関係なく、2番目のステップを完了したユーザー数と比較されます。
- **Split by**属性がサポートされています。

利用できる条件:

- **Above** — コンバージョンしたユーザー数がしきい値を上回ったときにトリガーされます。たとえば、しきい値が60の場合、61人のユーザーがコンバージョンするとアラートが発生します。
- **Below** — コンバージョンしたユーザー数がしきい値を下回ったときにトリガーされます。たとえば、しきい値が50の場合、コンバージョンしたユーザーが50人未満になるとアラートが発生します。
- **Increased by percentage (%) or value (#)** — コンバージョンしたユーザー数が前の期間と比較して、パーセンテージまたは固定のユーザー数だけ増加したときにトリガーされます。
- **Decreased by percentage (%) or value (#)** — コンバージョンしたユーザー数が前の期間と比較して、パーセンテージまたは固定のユーザー数だけ減少したときにトリガーされます。

<Note>
  Funnelアラートは、コンバージョン率ではなくコンバージョンしたユーザー数を測定します。2つのステップ間のコンバージョン率が変わっていなくても、トラフィック量の変化によってアラートがトリガーされたり、抑制されたりする場合があります。
</Note>

## Session and Source

セッション数、直帰率、収益など、ソースごとのセッションレベルの指標に対してアラートをトリガーします。

- ほとんどの指標は、**Above**、**Below**、**Increased by**、**Decreased by**をサポートしています。これらは固定値として設定することも、ベースラインと比較したパーセンテージ(%)または値(#)として設定することもできます。
- **Bounce rate**は、パーセンテージ(%)による**Increased by**または**Decreased by**のみをサポートしています。

## Comparison Periods

**Increased by**および**Decreased by**の条件では、選択できる比較期間はチャートの粒度によって異なります。

| チャートの粒度 | 利用できる比較期間                |
| ----------------- | ------------------------------------------- |
| Daily             | Previous Day, Previous Week, Previous Month |
| Weekly            | Previous Week, Previous Month               |
| Monthly           | Previous Month                              |

Previous QuarterおよびCustom Rangeはサポートされていません。

# メールアラートの表示

アラートを設定すると、指定した条件が満たされたときにメールが届きます。メールには、可視化されたグラフと、指標の変化、変化率、データが評価されたタイムスタンプなどのアラートの詳細が含まれます。

![指標の変化、変化率、評価タイムスタンプを示すアラートメールの例](/images/moengage_40d756.png)

<Info>
  アラートの作成とスケジュール設定の間には、少なくとも10分間の非アクティブ時間を確保してください。そうしないと、アラートは翌日にスケジュールされます。
</Info>

# アラートの登録解除、登録、削除

MoEngageダッシュボードでアラートを表示および管理するには、次の手順に従います。

1. MoEngageダッシュボードの左側のサイドバーにあるSettingsアイコン<Icon icon="gear" size={32} />をクリックします。
2. **Reports and Alerts**までスクロールし、ドロップダウンから**Alert management**を選択します。

   <img
     src="/images/moengage_7ffde7.png"
     alt="ダッシュボード設定の Reports and Alerts オプション"
     style={{ width:"39%" }}
   />
3. **Analytics alerts**タブを選択し、表示または管理するアラートを検索します。\
   次のオプションを使用して検索を絞り込みます。
   - 検索バーを使用してアラートを探します。
   - **Created by**ドロップダウンを使用して、作成者でアラートをフィルタリングします。
   - **Subscribed by**ドロップダウンを使用して、受信者でアラートをフィルタリングします。

     ![検索とフィルターオプションを備えた Alert management の Analytics alerts タブ](/images/moengage_ff18d6.png)
4. アラートが見つかったら、テーブルの右端にある**Actions**列の縦三点アイコン<Icon icon="ellipsis-vertical" size={32} />をクリックします。
5. 次のアクションを実行できます。
   - **Unsubscribe**: ユーザーをアラートから削除し、選択した分析のアラートを受信しないようにします。
   - **Subscribe Others**: ドロップダウンからメールアドレスを選択して、他のユーザーをアラートに追加します。
   - **Delete**: アラートを完全に削除します。

     <img
       src="/images/moengage_fddee1.png"
       alt="Unsubscribe、Subscribe Others、Delete を表示するアラートのアクションメニュー"
       style={{ width:"35%" }}
     />

# 制限事項

- 1つのワークスペースで作成できるアラートは最大**10件**です。この上限を引き上げるには、CSMまたはアカウントマネージャーにお問い合わせください。
- アラートは**メールのみ**で配信されます。
