MoEngageは、標準的なコホートチャートを超えてユーザーリテンションをより深く理解するための高度な分析を提供しています。これにより、時間の経過に伴うユーザーの再訪行動やエンゲージメントパターンの微妙な違いを調べることができます。

# First Occurrence

First Occurrenceは、特定の日に(最初のイベントの後で)初めてリターンイベントを実行したユーザーの割合を示します。これは、選択した日までリターンイベントを実行していなかったユーザーの割合です。First Occurrenceは、ユーザーがリターンイベントを実行するまでにかかる時間を表します。より詳細な粒度にするには、日の代わりに時間、週、または月を選択します。\
たとえば、ユーザーがDay 0にアプリをインストール(最初のイベント)したとします。ユーザーはDay 1とDay 2に購入(リターンイベント)を実行しなかったため、それらの日は非アクティブとしてカウントされます。Day 3にユーザーが初めて購入すると、そのユーザーはリターンしたユーザーとしてカウントされます。この分析は、ユーザーが戻ってきてリターンイベントを実行するまでにどれくらいアプリから離れていたかのみを示すため、Day 3以降に起こることは考慮しません。

# First Occurrenceを使用するタイミング

標準的なリテンション分析では、通常、最初のイベントの後の特定の日、週、または月に戻ってきてアクションを実行したユーザーの割合が示されます。**First Occurrence**を使用すると、最初の再エンゲージメントのタイミングに焦点を当てた、より具体的な分析が可能になります。

分析で次のことを理解する必要がある場合に、この高度な機能を使用します。

- **最初の再エンゲージメントまでの時間:** ユーザーが最初のインタラクションの後、特定のリターンアクションを初めて実行するまでにかかる時間を知る必要がある場合。
- **アクティベーションのタイムライン:** 最初のイベント(インストールや登録など)と、主要なフォローアップアクション(購入やコア機能の使用など)の最初のインスタンスとの間の時間差を測定したい場合。

First Occurrenceオプションが特定の分析上の課題の解決にどのように役立つかを以下に示します。

- **機能:** _最初のイベント_を実行した後の特定の日、週、月、さらには時間に、特定の_リターンイベント_を初めて実行したユーザーの割合を測定して表示します。ユーザーがそのリターンイベントを1回実行するまでにかかる時間を具体的に追跡し、それ以降のリターンイベントの実行は無視します。
- **使用するタイミング:**
  - 一般的な繰り返し行動だけでなく、最初のアクティベーションや主要なアクションまでのタイムラグを理解することが重要なインサイトである場合。
  - ユーザーがジャーニーを開始してから特定のマイルストーンに初めて到達するまでの速さを測定する場合。
  - 特定の最初のアクションを促進するうえでの、オンボーディングや初期エンゲージメントキャンペーンの効果を分析する場合。

### ユースケースの例

このオプションを使用して解決できるユースケースの例:

- **初回購入までの時間:** _App Install_(最初のイベント)の後、日次/週次/月次のコホートを追跡して、ユーザーが初めて_Purchase_(リターンイベント)を行うタイミングを確認します。これにより、新規ユーザーを購入者に転換するまでにかかる時間を把握できます。
- **コア機能の導入の遅れ:** _Account Signup_(最初のイベント)の後、ユーザーが最初に_Used Core Feature X_(リターンイベント)を実行するまでに何日/何週間かかるかを算出します。これは、ユーザーが主要な機能をどれくらいの速さで発見し、利用しているかを示します。
- **オンボーディングの完了時間:** _Started Onboarding Flow_(最初のイベント)の後、ユーザーが初めて_Completed Onboarding Step 5_(リターンイベント)をトリガーするまでにかかる時間を分析します。

First Occurrenceオプションを活用することで、最初のイベントの後にユーザーが主要なアクションを初めて実行するまでにかかる重要な時間について正確なインサイトを得ることができ、オンボーディングフロー、アクティベーション戦略、初期エンゲージメントキャンペーンの最適化に役立ちます。
