MoEngage は送信されたデータをいくらでも取り込むことができますが、データの追跡方法には一定の制限を設けています。これは、データ統合に加えた変更が MoEngage 内のデータの健全性を損なわないようにし、このデータを使用してキャンペーンやユーザートレンドを作成・分析する際にシームレスな体験を提供するためです。

## MoEngage で追跡されるイベントと属性の制限

MoEngage でデータを追跡する際には、以下の制限が適用されます。

| **タイプ** | **制限** | **超過時の処理** |
| --- | --- | --- |
| ユニークイベント | 512 | 直近 60 日間に追跡されていないイベントが最初に削除され、それでも制限を超えている場合は新しいイベントがブラックリストに登録されます。 |
| ユニークユーザー属性 | 256 | 制限を超えると、新しいユーザー属性は拒否されます |
| ユニークイベント属性 | イベントあたり 100 | 最初の 100 個のイベント属性のみが取り込まれます。 |

これらの制限は、イベントやユーザー属性の量の制限を表すものではなく、フェアユースポリシーの観点から追跡可能なカスタムイベントや属性のユニーク数のみを表しています。上記の制限を超える必要がある場合は、カスタマーサクセスマネージャーまたは MoEngage サポートチームにお問い合わせください[。](mailto:support@moengage.com) すでにこれらの制限を超えている場合でも、既存のイベントや属性が自動的にブラックリストに登録されることはありません。ただし、新しいイベントや属性を送信すると、上記の表に記載のロジックに基づいてブラックリストに登録されます。問題がある場合はお問い合わせください。

## イベントと属性の名前および値の制限

以下の表は、イベントと属性名の制限値を示しています。

| キー | 文字数制限 | 制限超過時の処理 |
| --- | --- | --- |
| イベント名の長さ | 200 | 最初の 200 文字のみを保存します。 |
| ユーザー属性名の長さ | 200 | 最初の 200 文字のみを保存します。 |
| ユーザー属性値の長さ | 512 | 最初の 512 文字のみを保存します |
| イベント属性名の長さ | 200 | 最初の 200 文字のみを保存します。 |
| イベント属性値の長さ | 512 | 最初の 512 文字のみを保存します。 |

## サポートされるデータ型

MoEngage は、属性に対して以下のデータ型を受け付けます。

| キー | 許可されるデータ型 | その他のデータ型 |
| --- | --- | --- |
| ユーザー属性値 | Integer, Float, Double, Long, Boolean, String, Datetime, Array``<Long>``, Array``<Int>``, Array``<Double>``, Array``<Short>``, Array``<Float>``, Array``<String>``, Object, Array of Objects | 無視 |
| イベント属性値 | Integer, Float, Double, Long, Boolean, String, Datetime, Array``<Long>``, Array``<Int>``, Array``<Double>``, Array``<Short>``, Array``<Float>``, Array``<String>``, Objects, Array of Objects | 無視 |

MoEngage でのデータ追跡に関する追加情報：

1. リストの場合、各要素は最大 512 文字、リストあたり最大 50 要素です。
2. datetime データ型の属性を送信する場合、Data API からデータを送信する際は ISO 8601 日付形式（例：2020-05-31T16:33:35Z）を使用し、SDK から直接データを送信する際は SDK の日付関数を使用してください。SDK は値からデータ型を推測しないため、SDK からプレーンな文字列として送信された日付は、有効な ISO 8601 形式であっても文字列として保存されます。その場合、Segmentation ではその属性に対して日付演算子ではなく文字列演算子が提供されます。特定の ISO 8601 対応形式を送信できない場合は、カスタマーサクセスチームにご確認ください。最も一般的に受け付けられる形式は %Y-%m-%dT%H:%M:%S.%fZ および %Y-%m-%dT%H:%M:%SZ です。Datetime 値は GMT（UTC）で指定する必要があります。GMT のタイムスタンプのみが受け付けられ、その他のオフセットが渡された場合は日付として処理されません。
3. 属性値が URL で、許可された文字数制限の 512 文字を超える場合、その値は完全に拒否されます。これは、画像や URL のパーソナライゼーションが壊れないようにするためです。
4. 配列の場合、配列のデータ型は同種である必要があり（配列内のすべての値が同じデータ型であること）、データの型変換は配列レベルでサポートされています。型変換の詳細については、[データの型変換](/ja/user-guide/settings/data-management/overview-data-management#array-typecasting)を参照してください。
