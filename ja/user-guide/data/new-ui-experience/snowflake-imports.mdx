# 概要

MoEngage では、Snowflake データベースに保存されたテーブルを使用してユーザーとイベントをインポートできます。

# インポートの種類

MoEngage は Snowflake データウェアハウスから以下をインポートできます。

1. **登録ユーザー**: MoEngage にすでに登録されているユーザーです。
2. **匿名ユーザー**: MoEngage にまだ登録されていないユーザーです。
3. **イベント**（標準およびユーザー定義）: MoEngage は、Campaign Interaction Events などの標準イベントに加えて、独自のユーザー定義イベントもインポートできます。

# データの準備

MoEngage では、インポートのために特定のテーブルスキーマを用意する必要はありません。テーブル内のすべての列は、MoEngage ダッシュボードでスキップするか、個別にマッピングできます。ただし、インポートを設定する前に注意すべき点がいくつかあります。

ユーザーインポート イベントインポート

MoEngage で定期的なユーザーインポートを設定すると、前回の同期以降に変更されたデータのみが同期されます。MoEngage は、`updated_at` というタイムスタンプ（日付 + 時刻）列を使用して、前回の同期以降に変更された行を識別します。行のデータが最後に変更された時点のタイムスタンプが含まれていれば、この列には任意の名前を付けることができます。テーブル内でこの列に別の名前を付けている場合は、MoEngage ダッシュボードでこのマッピングを個別に構成できます。

MoEngage でイベントインポートを設定する場合は、イベントのタイムスタンプ（日付 + 時刻）を含む列を必ずマッピングする必要があります。この列は、前回の同期以降の新しいイベントのみを同期するために使用されます。この列に別の名前を付けている場合も、MoEngage ダッシュボードでこのマッピングを構成できます。

さらに、MoEngage の標準イベントをインポートする場合は、テーブル内のイベント名が MoEngage の標準イベント名と一致していることを確認してください。

## Datetype 属性のインポート

Datetype 属性のインポートには追加の手順が必要です。詳細については、[専用ガイド](/ja/user-guide/data/imports/setting-up-a-data-warehouse-import)を参照してください。

# 必要なアクセス権限

MoEngage がデータを取り込めるように、データベースへの `READ` アクセス権が必要です。これらの権限を既存のデータベースユーザーに付与するか、MoEngage 専用の新しいデータベースユーザーを作成できます。

```
-- Grant SELECT permission on all tables in the schema
GRANT SELECT ON SCHEMA `catalog_name`.`schema_name` TO `user@example.com`;
-- Grant USE SCHEMA permission to access the schema
GRANT USE SCHEMA ON SCHEMA `catalog_name`.`schema_name` TO `user@example.com`;
-- Grant USE CATALOG permission (recommended for complete access)
GRANT USE CATALOG ON CATALOG `catalog_name` TO `user@example.com`;
```

以下の値を必ず変更してください。

1. `` - MoEngage がクエリを実行する際に使用するウェアハウスの名前です。
2. `` - データをインポートするデータベースの名前です。
3. `` - 新しく作成したデータベースユーザーに強力なパスワードを設定します。

## ステップ 2: 列を MoEngage 属性にマッピングする

このステップでは、テーブルの列を MoEngage に存在する属性にマッピングする必要があります。すべての列が縦に並んで表示されます。

__PROTECTED_16__

1. **Column name** - マッピングする列名です。列名の下には、参考としてサンプル値（前のステップで取得したテーブルの最初の行から取得されます）も表示されます。
2. **Map attribute** - テーブルの列をマッピングする MoEngage 属性を選択します。新しい属性を作成することもできます。一部の属性は複数のデータ型からの取り込みをサポートしているため、列のデータ型も選択する必要があります。「DateTime」列の場合は、__PROTECTED_32__ も選択する必要があります。
3. **More actions** - 必要に応じて列をスキップできます。スキップした列はインポートされません。

### マニフェストファイル

必要に応じて、[マニフェストファイル](/ja/user-guide/data/imports/overview-imports)をアップロードしてこれらの列を自動マッピングできます。

マニフェストファイルをアップロードするには、マッピングテーブルの右上にある「Upload mapping file」オプションをクリックします。

|  |  |
| --- | --- |
| <img src="/images/moengage_aa417b.png" /> | <img alt="UploadMapping.png" src="/images/moengage_d06a96.png" /> |

マニフェストファイルをアップロードし、Done をクリックします。マッピングはそれに応じて自動構成されます。MoEngage 以外の属性を持つ列は空白のままになり、列を手動でマッピングするか、新しい属性を作成できます。マニフェストファイルが記載どおりの[想定される規則](#manifest-files)に従っていることを確認してください。

マニフェストファイルに存在するもののテーブルに存在しない追加の列は無視されます。また、既存のテーブル列のマッピングがマニフェストファイルに存在しない場合、MoEngage はマッピングを空白のままにし、手動で構成できるようにします。

マニフェストファイル内の列が存在しない MoEngage 属性にマッピングされている場合、マッピングは空白になるため、まず UI から新しい属性を手動で作成してからマッピングする必要があることに注意してください。

#### Snowflake に互換性のある JSON データを保存する

Snowflake 内に有効な JSON を保存するには、列のデータ型を *VARIANT* 型に変更する必要があります。詳細については、[こちら](https://docs.snowflake.com/en/user-guide/tutorials/json-basics-tutorial)を参照してください。Snowflake 内に保存する JSON は有効な JSON である必要があります。そうでない場合、値は JSON として書き込まれません。JSON 列の例を次に示します。

### セグメントとして保存

ユーザーをインポートする場合は、MoEngage 内のカスタムセグメントにユーザーを追加することもできます。同期が実行されるたびに、インポートされたユーザーがこのカスタムセグメントに引き続き追加されます。このセグメントからユーザーが削除されることはありません。その後、このセグメントにターゲットを絞ったキャンペーンを送信できます。インポートしたユーザーをカスタムセグメントに保存するには、「Save as a custom segment」オプションを有効にします。

セグメントに名前を付け、テーブル内の識別子列を選択します。

## ステップ 3: インポート頻度を選択する

<img alt="frequency import.png" src="/images/moengage_092268.png" />

このステップでは、テーブルと同期するタイミングを定義する必要があります。以下の種類のインポートがサポートされています。

1. 1 回限りのインポート: できるだけ早くインポートを実行するか、後の日時に実行する（スケジュール）かを選択できます。インポート条件に一致する既存のすべての行がインポートされます。
2. 定期インポート: インポートを数分ごと、毎時、毎日、毎週、毎月、または間隔や詳細設定を指定して実行するように選択できます。

必要に応じて、指定した回数の実行後または特定の日付にインポートを終了するかどうかを指定できます。準備ができたら **Done** をクリックします。

<Warning>
インポートの初回実行時には、テーブルから一致するすべての行がインポートされることに注意してください。以降のインポートでは、変更された行のみが取り込まれます。
</Warning>

## 重複インポート

一度に構成できる一意のインポートは 1 つだけです。以下が**すべて**同じである場合、そのインポートは重複インポートと見なされます。

1. **インポートの種類** - Users / Events
2. **インポートのサブタイプ** - Event Name / Registered / Anonymous / All users - イベント名が同じ場合、または同じ Snowflake 接続を持つ登録ユーザー/匿名ユーザー/すべてのユーザーのインポートがすでに存在する場合
3. **Snowflake 接続**
4. **インポートのスキーマとテーブル**

上記のいずれか 1 つでも異なれば、そのインポートは一意と見なされます。

# よくある質問

<Accordion title="複数のテーブルにまたがるデータからインポートできますか？">

いいえ。現在、手動クエリの記述（結合の実行など）はサポートされていません。MoEngage にインポートするすべての列を含む専用のテーブルまたはビューを作成することをお勧めします。

</Accordion>
<Accordion title="Snowflake からのビューのインポートはサポートされていますか？">

はい。Snowflake のビューからのデータのインポートもサポートしています。MoEngage にビューの読み取りアクセス権を付与すると、ビューは Table/View 選択ドロップダウンに自動的に一覧表示されます。

</Accordion>
<Accordion title="履歴データのインポートはできますか？">

はい。最初の同期ですべての行が取り込まれるため、1 回限りのインポートを作成することは、実質的に履歴データのインポートと同じです。

</Accordion>
