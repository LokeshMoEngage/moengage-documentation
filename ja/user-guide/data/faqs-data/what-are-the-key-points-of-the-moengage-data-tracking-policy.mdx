---

この記事では、MoEngage のデータトラッキングポリシーの要点について説明します。これらのポリシーは、初期実装の段階で必要な調整を行う際に役立ちます。

## 手順

1. MoEngage では、属性に次のデータ型を使用できます。
   - Integer、Float、Double、Long、Boolean、String、Datetime、Array``<Long>``、Array``<Int>``、Array``<Double>``、Array``<Short>``、Array``<Float>``、Array``<String>``、Object、Array of Objects。
2. 各配列要素は最大 512 文字で、各配列には最大 50 個の要素を含めることができます。
3. 辞書データ型として送信された属性値は拒否されます。
4. datetime データ型の属性の場合:
   - MoEngage Data API を通じてデータを送信する場合は、ISO 8601 の日付形式（例: 2020-05-31T16:33:35Z）を使用します。
   - SDK を通じてデータを送信する場合は、SDK の日付関数を使用します。
5. 属性値が URL で 512 文字の上限を超える場合、画像や URL のパーソナライズで問題が発生しないように拒否されます。
6. 配列は同種である必要があります（配列内のすべての値が同じデータ型である必要があります）。データの型キャストは配列レベルでサポートされています。
7. ピリオドを含むイベント名を使用すると、余分なスペースが追加されます。たとえば、*event.name* は *event. Name*（スペース付き）として取り込まれます。「.」（ピリオド）の代わりに「\_」（ハイフン）を使用することをお勧めします。
8. 1 つのイベントに対して、最大 100 個の一意のイベント属性を作成できます。
9. 次の表に、イベント名と属性名の上限値を示します。  

   | キー | 文字数の上限 | 上限超過時の処理 |
   | --- | --- | --- |
   | イベント名の長さ | 200 | 最初の 200 文字のみを保存します。 |
   | ユーザー属性名の長さ | 200 | 最初の 200 文字のみを保存します。 |
   | ユーザー属性値の長さ | 512 | 最初の 512 文字のみを保存します。 |
   | イベント属性名の長さ | 200 | 最初の 200 文字のみを保存します。 |
   | イベント属性値の長さ | 512 | 最初の 512 文字のみを保存します。 |

詳細については、[データトラッキングポリシー](/ja/user-guide/data/key-concepts/data-tracking-policies)を参照してください。
