## 問題

MoEngage ダッシュボードで、特定の少数のユーザーのイベントが表示されませんが、それ以外のユーザーベースには影響がありません。

## 説明

少数のユーザーのみでイベントが欠落している場合、それらのユーザーが [Fair Usage Policy（FUP）](/ja/user-guide/data/key-concepts/fair-usage-policy-fup)の制限を超過した可能性があります。

FUP の制限はユーザーごとに適用されます。単一のユーザー ID が短時間に大量のデータリクエストを送信し、MoEngage の安全しきい値を超えると、MoEngage はプラットフォームの安定性を保護するために、そのユーザー ID のデータトラッキングを一時的にブロックします。他のすべてのユーザーのデータは通常どおりトラッキングされるため、影響は特定のユーザーに限定されます。

特定のユーザーが次のいずれかのしきい値を超えた場合、そのユーザーのトラッキングは一時的にブロックされます。制限は、データが SDK ソースから送信されるか、SDK 以外のソースから送信されるかによって異なります。

**SDK ソース**

| 時間間隔 | 許可されるデータリクエストの最大数 | 制限を超えた場合の措置 |
| --- | --- | --- |
| 1 分 | 500 | そのユーザーのトラッキングデータを以後 1 時間ブロックします。 |
| 5 分 | 1,000 | そのユーザーのトラッキングデータを以後 1 時間ブロックします。 |
| 1 時間 | 5,000 | そのユーザーのトラッキングデータを以後 24 時間ブロックします。 |
| 1 日 | 10,000 | そのユーザーのトラッキングデータを以後 24 時間ブロックします。 |

**SDK 以外のソース**

ファイルインポート、パートナー連携、および Data API に適用されます。制限は SDK 以外のすべてのソースで累積されます。

| 時間間隔 | 許可されるデータリクエストの最大数 | 制限を超えた場合の措置 |
| --- | --- | --- |
| 1 分 | 5,000 | そのユーザーのトラッキングデータを以後 1 時間ブロックします。 |
| 5 分 | 10,000 | そのユーザーのトラッキングデータを以後 1 時間ブロックします。 |
| 1 時間 | 50,000 | そのユーザーのトラッキングデータを以後 24 時間ブロックします。 |
| 1 日 | 100,000 | そのユーザーのトラッキングデータを以後 24 時間ブロックします。 |

<Warning>
上記のいずれの時間間隔においても、制限超過が連続して最大 3 回発生すると、MoEngage は 7 日間のブロックを課します。ブロックが課されると、その特定のユーザーのすべてのデータトラッキングが 7 日間停止されます。
</Warning>

ユーザープロファイルのアクティビティ情報やユーザーあたりのデバイス数に関する制限を含むポリシーの全容については、[Fair Usage Policy の制限と措置](/ja/user-guide/data/key-concepts/fair-usage-policy-fup#fair-usage-policy-limits-and-actions)を参照してください。

<Note>
イベントの欠落は、Data Management でイベントがグローバルにブロックまたは非表示にされていることが原因の場合もあります。この場合は、特定のユーザーではなくユーザーベース全体に影響します。この可能性を除外するには、[新しいイベントまたはユーザー属性がダッシュボードに反映されないのはなぜですか？](/ja/user-guide/data/faqs-data/why-are-new-events-or-user-attributes-not-reflected-on-the-dashboard)を参照してください。
</Note>

## 解決策

Behavior 分析を使用して、特定のユーザーが FUP の制限を超過したかどうかを確認します。

<Info>
**前提条件:**

- **Analyze** > **Behavior** および **Settings** > **Data Management** へのアクセス権。
- 影響を受けているユーザー ID。
</Info>

次の手順を実行します。

1. イベントがアクティブで、グローバルにブロックされていないことを確認します。**Settings** > **Data Management** に移動し、イベントの **Status** が **Allowed** になっていることを確認します。Data Management へのアクセス権がない場合は、ワークスペース管理者にお問い合わせください。詳細については、[概要 - Data Management](/ja/user-guide/settings/data-management/overview-data-management)を参照してください。

![イベントのステータスが Allowed に設定されている MoEngage の Data Management ページ。](/images/fup-data-management-page.png)

2. **Analyze** > **Behavior** に移動します。**Events & filters** セクションで、ユーザーについて欠落しているように見えるイベントを選択します。
3. **Filter Users** セクションで、**Filter users by** を選択します。**Filter users by** リストで **ID** をクリックし、影響を受けているユーザー ID を入力します。

![イベントが選択され、ID でユーザーが絞り込まれている MoEngage の Behavior 分析。](/images/fup-behavior-filter-by-id.png)

4. **Behavior Options** セクションの **Analysis type** リストで、**Total events** をクリックします。
5. **Duration** で、イベントが欠落した期間を選択し、**Apply** をクリックします。
6. **Behavior chart** を確認します。スパイクにカーソルを合わせると、イベントの 1 時間ごとまたは 1 分ごとの内訳が表示されます。

![1 時間に合計 535 件のイベントのスパイクが表示されている MoEngage の Behavior チャート。](/images/fup-behavior-chart-spike.png)

スパイクが短時間にリクエストが集中していることを示している場合（例: 1 分間に 535 件のイベント）、そのユーザーは SDK の制限（500 件/分）を超えていますが、SDK 以外の制限（5,000 件/分）は大きく下回っています。これにより、そのユーザーのその後のイベントが FUP 違反によってブロックされたことが確認できます。
