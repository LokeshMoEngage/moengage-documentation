# はじめに

MoEngage は、すべての時刻データを UTC 時刻で保存します(イベントを除く)。MoEngage は、アプリのタイムゾーンのオフセットを使用して、UTC 時刻に基づいてアクション分析とユーザー分析のクエリを実行します。MoEngage はイベント時刻(Event Time)とサーバー時刻(Server Time)を収集します。

# イベント時刻

イベント時刻とは、イベントが実行されたときのデバイス上の時刻です。イベント時刻はユーザープロファイルに表示されます。詳細については、[ユーザープロファイル](/ja/user-guide/data/user-data/user-profile)を参照してください。  
  
デバイスで生成されないイベント([MoEngage が生成するイベント](/ja/user-guide/data/event-data/derived-events-and-attributes))やデバイス時刻を持たないイベント([Data API イベント](https://www.moengage.com/docs/api/event/track-event))の場合、イベント時刻はユーザーのタイムゾーンで記録されます。ユーザーのタイムゾーンが利用できない場合は、アプリのタイムゾーンが表示されます。どちらも利用できない場合は、UTC 時刻がイベント時刻として使用されます。

# 受信時刻(サーバー時刻)

デバイスから MoEngage サーバーでイベントが受信されるたびに、その時刻がイベント受信時刻(またはサーバー時刻)として設定されます。

デバイスで生成されないイベント([MoEngage が生成するイベント](/ja/user-guide/data/event-data/derived-events-and-attributes)および [Data API イベント](https://www.moengage.com/docs/api/event/track-event))の場合、受信時刻はユーザープロファイル内のアプリのタイムゾーンになります。

すべてのセグメンテーションおよび分析クエリでは、イベントの時間範囲の選択に受信時刻が使用されます。

[ユーザープロファイル](/ja/user-guide/data/user-data/user-profile)では、すべてのイベントについて、イベント時刻(イベントが実行された時刻)とイベント受信時刻(MoEngage でイベントが受信された時刻)が表示されます。

# イベント時刻と受信時刻の違い

イベント時刻とイベント受信時刻(サーバー時刻)は、通常は同じか、数秒程度の差がある程度です。しかし、イベント時刻とサーバー時刻が一致せず、時間差が大きくなる場合があります。その理由は次のとおりです:

- データが遅れて MoEngage サーバーに到達する - インターネットの問題、アプリのクラッシュ、メモリからのアプリの削除(特に中国の OEM の場合)などにより、イベントが時間どおりに MoEngage サーバーに到達しません。
- イベント時刻が正確でない - デバイスの時刻が正確でないため、イベント時刻が不正確になります。

イベント時刻とサーバー時刻の時間差が大きい場合、ごく一部のユーザーについて分析結果がわずかにずれることがあります。これらのユーザーについては、セグメンテーション、分析、ユーザープロファイルの結果がわずかにずれる可能性があります。影響はユーザーイベントの 0.5% 未満です。

キャンペーン詳細ページおよびキャンペーン統計ダッシュボードでのキャンペーン分析には影響はありません。
