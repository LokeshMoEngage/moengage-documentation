# はじめに

<Info>
  Outbound Segment Sync は有料のアドオン機能です。アカウントで有効にするには、MoEngage のカスタマーサクセスマネージャー（CSM）またはサポートチームにお問い合わせください。
</Info>

_Outbound Segment Sync_ を使用すると、MoEngage で作成した価値の高い顧客セグメントを、テックスタック内の他のプラットフォームに同期して送信できます。これらのセグメントは、広告ネットワーク、ロイヤルティプラットフォーム、レコメンデーションエンジン、実験ツールなど、さまざまなプラットフォーム間で同期できます。これにより、ターゲットを絞ったエンゲージメントやデータドリブンな意思決定など、さまざまなビジネスユースケースを推進できます。

![Outbound](/images/moengage_09fa5a.png)

## ユースケース

ブランドは Outbound Segment Sync を使用して効果の高いセグメントをツール間で同期し、ターゲットを絞ったエンゲージメントやその他のビジネス戦略を実現できます。

- **セグメントをデータウェアハウスに同期:** セグメントをデータウェアハウスにシームレスに同期して詳細な分析を行うことで、より深いインサイトを得て、データドリブンな意思決定を強化できます。
- **セグメントをロイヤルティプラットフォームに同期:** セグメントを同期することで、個々の好みに合わせたパーソナライズされた特典やプロモーションを提供し、顧客ロイヤルティプログラムを強化できます。
- **セグメントを In-App パーソナライゼーションプラットフォームに同期:** セグメントを同期することで、各ユーザーが好みに合ったコンテンツや機能を受け取れるようにし、高度にパーソナライズされたユーザー体験を実現できます。
- **セグメントを広告ネットワークに同期:** 精度の高いターゲティング広告キャンペーンのためにセグメントを同期し、広告が最も関連性の高いオーディエンスに届くようにします。
- **顧客セグメントを実験プラットフォームに同期:** セグメントを同期して異なる顧客グループの反応や行動を比較し、A/B/n テストを精度高く実施できます。
- **セグメントを CRM プラットフォームに同期:** セグメントを同期することで顧客とのやり取りの追跡を改善し、顧客の行動や好みについてより良いインサイトを得られます。
- **セグメントをカスタマーサービスプラットフォームに同期:** セグメントを同期することで、カスタマーサービスチームが個々の顧客をより深く理解し支援できるようになり、パーソナライズされたサポートを提供できます。
- **ある MoEngage アプリから別のアプリにセグメントを同期:** Outbound Segment Sync と Cohort Sync API を組み合わせることで、複数の MoEngage アプリ間でセグメントを簡単に同期できます。詳細については、[ある MoEngage アプリから別のアプリにセグメントを同期する](/ja/user-guide/data/exports/segments/outbound-segment-sync#sync-segments-from-one-moengage-app-to-another)を参照してください。

## API リクエスト形式

MoEngage が API エンドポイントにセグメントを送信する際のリクエスト形式は次のとおりです。

#### リクエストボディ:

JSON

```json wrap
{
"type": "segment_sync",
"pagination": {
"total_pages": 14,
"page_count": 12
},
"data": {
"moengage_sync_id": "{{sync_id}}",
"moengage_sync_name": "{{sync_name}}",
"moengage_execution_id": "{{execution_id}}",
"moengage_integration_id": "{{integration_id}}",
"add_users": [
{
"moengage_distinct_id": ,
"partner_user_id": "{{uid99}}"
},
{
"moengage_distinct_id": ,
"partner_user_id": "{{uid00}}"
}
],
"remove_users": [
{
"moengage_distinct_id": ,
"partner_user_id": "{{uid98}}"
},
{
"moengage_distinct_id": ,
"partner_user_id": "{{uid01}}"
}
]
}
}
```

<Info>
  - 接続のテスト中、エンドポイントは成功を示す 2xx コードを返す必要があります。
  - 宛先からのレスポンスヘッダーの content-type は application/json である必要があります。
  - SDK の完全な API リファレンスについては、こちらの[リンク](https://moengage.github.io/ios-api-reference/)のドキュメントを参照してください。
  - Total pages: 以前に同期されたすべてのセグメントで構成される「Synced Segment」ページのページ数を定義します。
  - Page count: ペイロードに現在表示されているデータがどのページのものかを示します。
</Info>

## ペイロード内の ID の定義

1. `moengage_sync_id`: 特定のセグメントに対して開始された同期に付与される一意の ID で、他の同期済みセグメントと区別するためのものです。
2. `moengage_sync_name`: 同期されているセグメントの名前です。
3. `moengage_execution_id`: 同期の実行に割り当てられる一意の ID で、特定のセグメントで発生しうる複数の同期の中からその同期を区別するためのものです。
4. `moengage_integration_id`: セグメントが特定の連携宛先にマッピングされたときに生成される ID です。つまり、セグメントと連携宛先のマッピングを `moengage_integration_id` で表します。
5. `moengage_distinct_id`: MoEngage システムによってユーザーに割り当てられる一意の ID です。これは、顧客/パートナーがユーザーに割り当てた ID とは異なります。
6. `partner_user_id`: 顧客/パートナーが独自の規則に従ってユーザーを識別できるように、自社システムを通じて MoEngage に送信する一意の ID です。

## ステップ 3: セグメント同期を設定する

宛先プラットフォームを設定したら、セグメント同期の設定を開始できます。

![Trigger](/images/moengage_4ccac3.png)

新しい同期セグメントを設定するには:

**1. 同期するカスタムセグメントを選択する**

**Segment** \> [Manage Segments ページ](/ja/user-guide/segment/create-segments/manage-segments)で、カスタムセグメントを選択し、アクションのドロップダウンリストで **Sync Segment** をクリックします。

**2. 宛先を選択する**

App Marketplace の Custom Destinations で設定した宛先がドロップダウンリストに表示されます。利用可能なオプションから宛先を選択するか、同期用の新しい宛先を追加します。

**3. 同期のスケジュールを選択し、通知設定を行う**

同期は、セグメント内のユーザーを宛先に 1 回だけ転送するか、セグメントの最新の状態を継続的に定期更新するかのいずれかを選択できます。

定期同期の場合、セグメントは毎日、毎週、毎月のいずれかで同期できます。毎時の同期は個別に有効化できます。アカウントで毎時の同期を有効にするには、アカウントマネージャーにお問い合わせください。

以下の通知を受け取るメール ID を設定することもできます。

- 同期設定の更新
- 同期の実行成功
- 同期の失敗

<Info>
  1. アウトバウンド同期プロセスにはクールオフ期間が設定されています。クールオフ期間は、すでに実行中のセグメント同期が中断されないように定義されています。例: セグメント同期の途中で属性の値が変更されると、進行中の同期に影響する可能性があります。また、同期の処理中に属性の値に加えられた変更はすぐには反映されません。変更が行われてから 30 分後に反映されます。
  2. Outbound Segment Sync のデフォルトの上限は次のとおりです。

  - 「アクティブ」なセグメント同期の上限は 10 です。アウトバウンドセグメント同期のステータスには、アクティブ、一時停止、非アクティブ、失敗があります。
  - 1 日あたり 10 件のセグメント同期を作成できます。アクティブなセグメント同期の上限に達すると、それ以上セグメント同期を作成できません。
  - 1 日あたりのセグメント同期の再同期の上限は 20 です。
  - これらの上限は変更可能です。上限を変更するには、MoEngage サポートチームにお問い合わせください。
</Info>

## 定期的なアウトバウンドセグメント同期

定期的なアウトバウンドセグメント同期では、MoEngage はセグメント内の全ユーザーを初回の同期でのみ送信します。以降の同期では、MoEngage は変更データキャプチャ（change data capture）プロセスに従い、前回の同期とセグメントの現在の状態を比較して、ユーザーの差分のみを送信します。

この差分は 2 つのリストで送信されます。`add_users`（セグメントに追加されるユーザーのリスト）と `remove_users`（セグメントから削除されるユーザーのリスト）です。この差分は、最後の差分のみを宛先に同期する **Resync Last Difference** アクションのためにも MoEngage によって保持されます。このオプションは、宛先でのデータの不一致に対処するために提供されています。

## 同期ステータス

各同期セグメントは、次の 5 つのステータスのいずれかになります。

| ステータス | 説明 |
| --- | --- |
| Active | 同期の最新の実行が成功し、同期がまだ期限切れになっていない状態です。つまり、同期の終了日にまだ達していません。 |
| Paused | **Pause** アクションをクリックして同期が手動で一時停止された状態です。**Run Adhoc Sync** をクリックすると、そのセグメントの今後のすべての同期が再開されます。 |
| Failed | 同期の最後の実行で失敗が発生した状態です。同期が失敗状態の場合、今後のすべての同期は一時停止されます。同期を手動で実行（**Run Adhoc Sync**）してスケジュールを再開できます。 |
| Inactive | 1. 指定された同期の終了時刻に達した状態です。 <br />2. 非アクティブな同期は 30 日後に自動的にアーカイブされます。 |
| Archived | ダッシュボードから同期がアーカイブされた状態です。 |

<Info>
  - Segment Sync のステータスが Inactive の場合、同じカスタムセグメントから同じ頻度の新しい Segment Sync を作成することはできません。
  - Segment Sync のステータスが Inactive の場合、同じカスタムセグメントから異なる頻度/宛先の新しい Segment Sync を作成できます。
  - 同じカスタムセグメントから同じ頻度の新しいセグメント同期を作成するには、Inactive の Segment Sync をアーカイブする必要があります。
</Info>

# ある MoEngage アプリから別のアプリにセグメントを同期する

![](/images/moengage_d2416c.png)

Outbound Segment Sync と [Cohort Sync API](https://www.moengage.com/docs/api/cohort-sync/sync-cohort-members) を使用すると、ある MoEngage アプリから別のアプリにセグメントを同期できます。これにより、地域をまたぐチームが同期して業務を行い、より適切なターゲティングを実現できます。

## ステップ 1: 送信元アプリにログインする

まず、セグメントの送信元となるアプリ（ソース）にログインします。このアプリで Outbound Segment Sync がすでに有効になっていることを確認してください。

## ステップ 2: 新しいカスタム宛先を作成する

新しいカスタム宛先を設定するには、**App Marketplace** に移動し、**Custom Destinations** セクションに移動します。「MoEngage」という名前の新しいカスタム宛先を追加します。

## ステップ 3: 新しいエンドポイントを作成する

新しく作成したカスタム宛先で、**\+ Add integration** をクリックして新しいエンドポイントを設定します。エンドポイントには、宛先アプリ名などの名前を付けます。その他のフィールドは次のように設定します。

| フィールド | 値 | 説明 |
| --- | --- | --- |
| Request Method | POST |  |
| URL endpoint | `https://api-0X.moengage.com/v1/integrations/cohortsync` | API エンドポイント URL の「X」は、MoEngage のデータセンター（DC）を指します。MoEngage は顧客ごとに異なる DC でホストしています。DC と API エンドポイントのマッピングを[こちら](/ja/user-guide/data/key-concepts/data-centers-in-moengage)で参照して DC 番号（X の値）を確認し、URL の「X」の値を置き換えてください。 |
| Parameters | 空欄のままにします。 |  |
| Authentication | Basic Auth | **Username**: 宛先の MoEngage Workspace ID です。 **Password**: 宛先の MoEngage アプリの Data API Key です。 |
| Headers | 1. `MOE-APPKEY` - 宛先の MoEngage Workspace ID です。 <br />2. `MOE-DESTINATION-PARTNER` - `moengage` | これら 2 つのヘッダーは必須です。 |
| User identifier |  | ユーザー識別子を選択します。これは送信元アプリと宛先アプリの両方で同じである必要があります。 |
| Destination identifier | `uid` | 別の MoEngage アプリにセグメントを送信するには、宛先識別子として「uid」を選択します。 |

上記のフィールドを設定したら、接続をテストできます。すべての詳細が正しければ、テストは成功します。連携を保存します。

## ステップ 4: 宛先アプリにセグメントを同期する

[上記](#step-3-set-up-a-segment-sync)の詳細に従って、宛先アプリにセグメントを同期します。

<Info>
  - ある MoEngage アプリから別のアプリにセグメントを同期する場合、ユーザーが送信元アプリと宛先アプリの両方に存在することを確認する必要があります。
  - ユーザーの識別子が両方のアプリで同じであることを確認してください。
  - 現在、この方法では匿名ユーザーを同期できません。
  - リージョンをまたいでセグメントを同期することも可能です。
</Info>

# アウトバウンド同期セグメントの詳細を表示する

同期セグメント名または **View** アクションをクリックすると、その同期セグメントの詳細ページに移動します。

詳細ページでは、宛先、スケジュール、最新の同期ステータス、同期の更新者、更新日時、同期スケジュール、最終同期時刻、次回同期時刻、親カスタムセグメントへのリンクなどの同期の詳細を確認できます。

同期されたユーザー属性、同期スケジュール、通知設定などの同期設定も詳細ページで確認できます。

このページから、同期に関連するすべてのアクション（**Edit**、**Run Adhoc Sync**、**Pause Sync**、**Resync All Users**、**Resync Last Difference**、**Archive Sync**）を実行できます。

同期セグメントの詳細ページでは、このセグメントに対して実行されたすべての同期の同期履歴も確認できます。

## ![Screenshot\_2023-03-07\_at\_10.50.18\_AM.png](/images/moengage_0c89c8.png)

## 同期履歴

同期履歴には、スケジュールされた頻度でセグメントが宛先に同期されるたびの詳細が表示されます。

- **Run time** - 同期が実行された時刻です。
- **Status of execution** - 各同期の実行は、次のいずれかのステータスになります。
  - Complete - 同期が正常に実行され、すべての行が必要な宛先に送信されました。
  - Processing - 必要な宛先への同期が現在実行中です。
  - Failed - 同期の実行中に失敗が発生しました。
- **No. of users added** - 前回同期が処理されてからカスタムセグメントに追加された、`<synced user attribute>` を持つユーザーの数です。このユーザーのリストは、リクエストボディの 'add\_users' として宛先に同期されます。
- **No. of users removed** - 前回同期が処理されてからカスタムセグメントから削除された、`<synced user attribute>` を持つユーザーの数です。このユーザーのリストは、リクエストボディの 'remove\_users' として宛先に同期されます。
- **Total no. of users** - 親カスタムセグメントに存在する、`<synced user attribute>` を持つユーザーの数です。

<Info>
  - カスタムセグメントから宛先に同期できるユーザー属性は 1 つです。また、1 日に最大 5 件の同期を作成し、DB で最大 5 件のアクティブな同期を維持できます。さらに、1 日に最大 5 件の同期を実行できます（アドホックでの同期実行または再同期の実行）。上記の上限はカスタマイズ可能です。要件に応じてカスタマイズするには、アカウントマネージャーにお問い合わせください。
  - アーカイブされた同期が **Archived Syncs** ページに表示されるまで、約 1 時間かかります。
  - 1 つ以上の同期が存在するカスタムセグメントを編集、名前変更、アーカイブする際は注意してください。親カスタムセグメントの名前を変更しても、同期名には親カスタムセグメントの新しい名前が反映されません。
  - カスタムセグメント内のユーザー数は、カスタムセグメントから宛先に同期されたユーザー数と常に一致するとは限りません。たとえば、カスタムセグメント内のユーザー数が 100 で、選択した同期属性がメール ID であるとします。カスタムセグメント内の 100 人のうち 90 人にメール ID が存在する場合、この 90 人のユーザーが宛先に同期されます。
</Info>

# よくある質問

<Accordion title="30 分のクールオフ期間を解除できますか？">
  いいえ、30 分のクールオフ期間は解除できません。進行中の同期の中断を防ぎ、誤ったデータが同期される可能性を回避するための予防措置として、クールオフ期間はデフォルトで設定されています。
</Accordion>

<Accordion title="'API already failed' とはどういう意味ですか？">
  このエラーは、API 呼び出しが失敗した後に再試行が行われた場合に表示されます。「API already failed」エラーの考えられる原因は次のとおりです。

  - **ネットワーク接続の問題:** 信号が弱い、サーバーがダウンしているなど、ネットワーク接続に問題があったために API 呼び出しが失敗した可能性があります。
  - **認可または認証の不足:** API 呼び出しにはクライアント側で何らかの認可または認証が必要であり、それが欠落しているか無効になっている可能性があります。
  - **サーバーの過負荷:** サーバーが処理しているリクエストが多すぎるため過負荷になり、それ以上のリクエストを処理できなくなっています。
</Accordion>

<Accordion title="同期名を任意の名前に変更できますか？">
  いいえ、現在、同期名を編集または変更する機能はありません。
</Accordion>

<Accordion title="途中でセグメント名を編集するとどうなりますか？">
  同期が進行中にセグメントに対して何らかのアクションを実行すると中断につながる可能性があるため、推奨されません。同期の途中でセグメントに加えられた変更はすぐには反映されず、30 分のクールオフ期間の後に反映されます。1 つ以上の同期が存在するセグメントを編集、名前変更、アーカイブする際は注意してください。親カスタムセグメントの名前を変更しても、同期名には新しい名前が反映されません。
</Accordion>

<Accordion title="セグメント同期で複数の属性を渡すことはできますか？">
  いいえ、現在の MoEngage システムでは、セグメント同期で複数の属性を渡すことはできません。
</Accordion>

<Accordion title="KV ペアをパーソナライズしたり、動的なタイムスタンプを使用したりできますか？">
  顧客は KV（キーと値）ペアを特定のニーズに合わせてパーソナライズできます。ただし、現時点では動的なキー値はサポートされていません（例: 動的なタイムスタンプはサポートされていません）。キーと値のペアは静的である必要があります。
</Accordion>

<Accordion title="再試行の仕組みとタイムアウト期間はどのようになっていますか？">
  再試行の仕組みにより、顧客またはパートナーのシステムは MoEngage API を複数回試行して呼び出すことができます。ただし、再試行の仕組みには上限が設定されています。合計 3 回の再試行が可能で、最大頻度またはタイムアウトは 3 秒に 1 回の再試行です。
</Accordion>
