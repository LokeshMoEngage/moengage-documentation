# はじめに

MoEngage Event Exports を使用すると、さまざまなサードパーティツールにイベントを転送できます。次の機能を提供しています。

1. **MoEngage Streams** - Streams を使用すると、MoEngage で利用可能なユーザーアクションやキャンペーンインタラクションイベントなどのイベントを、事前に定義した API エンドポイントにほぼリアルタイムで転送できます。
2. **Data Warehouses** - MoEngage は、イベントをテーブルに直接転送する宛先として、複数のデータウェアハウスをサポートしています。サポート対象は次のとおりです。
   1. [Amazon Redshift](/ja/user-guide/data/exports/events/data-warehouse/redshift-exports)
   2. [Google BigQuery](/ja/user-guide/data/exports/events/data-warehouse/bigquery-exports) (GCS 経由)
   3. [Snowflake](/ja/user-guide/data/exports/events/data-warehouse/snowflake-exports)
3. **Cloud Storages** - MoEngage は、イベントを JSON ファイルとしてバケットに転送する宛先として、複数のクラウドストレージもサポートしています。
   1. [Amazon S3](/ja/user-guide/data/exports/events/data-warehouse/s3-exports)
   2. [Google Cloud Storages](/ja/user-guide/data/exports/events/data-warehouse/google-cloud-storage-gcs-exports)
   3. [SFTP](https://partners.moengage.com/hc/en-us/articles/26763225201172-SFTP)

# エクスポートスキーマ

エクスポートスキーマは宛先のタイプによって異なります。各カテゴリ (Data Warehouse、Cloud Storages、API) には、さまざまな MoEngage イベントとユーザー定義イベントに対応する一貫したスキーマがあります。

## Streams (API)

MoEngage は、指定された API エンドポイントに Bulk API 呼び出しを行います。一般的な構造は次のとおりです。

JSON

```json wrap
{
  "app_name": "The name of your app.",
  "source": "MOENGAGE",
  "moe_request_id": "MoEngage unique request id for each request.",
  "events": [
    {
      "event_name": "Name of your event",
      "event_code": "Event code",
      "event_uuid": "Unique code of this event. This helps in determining each unique event being captured by MoEngage.",
      "event_time": "EPOCH_TIMESTAMP_OF_EVENT_TRIGGERED_TIME_IN_UTC",
      "event_type": "CAMPAIGN_EVENT",
      "event_source": "MOENGAGE",
      "push_id": "Recipient device’s push token",
      "email_id": "Recipient's email ID",
      "mobile_number": "Recipient's mobile number",
      "uid": "MoEngage Customer ID",
      "event_attributes": {
        "campaign_id": "ID of the campaign",
        "campaign_name": "Name of the campaign",
        "campaign_type": "Type of the campaign",
        "campaign_channel": "Channel of the campaign"
      },
      "user_attributes": {
        "moengage_user_id": "MoEngage Internal User ID"
      },
      "device_attributes": {
        "moengage_device_id": "MoEngage Device ID"
      }
    }
  ]
}
```

## データウェアハウスの宛先

MoEngage はデータウェアハウスに単一のテーブルを作成し、選択したすべてのイベントをそのテーブルにエクスポートします。

### Amazon Redshift

`moengage_events` という名前のテーブルを作成します。

### Snowflake

`moe_events_<table_creation_timestamp>` という名前のテーブルを作成します。

### テーブル構造

テーブルの全体的な構造は、すべてのイベントタイプで固定されています。エクスポートされる新しいユーザープロパティまたはイベント属性は、それぞれ `user_attributes` 列または `event_attributes` 列の一部になります。すべてのイベントは、分析しやすいように、イベント名やイベント時刻などの必要な情報をすべて含む単一のテーブルに格納されます。

次の一般的なスキーマに従います。

- _event\_attributes\__ で始まる列にはイベント属性が含まれます。その後に _event\_attributes\_campaign\_name_ のようにイベント属性名が続きます。
- _user\_attributes\__ で始まる列にはユーザー属性が含まれます。その後に _user\_attributes\_moengage\_user\_id_ のようにユーザー属性名が続きます。
- device\_attributes で始まる列にはデバイス属性が含まれます。その後に _device\_attributes\_moengage\_device\_id_ のようにデバイス属性名が続きます。
- また、_event\_attributes_、_user\_attributes_、_device\_attributes_ という 3 つの JSON (または同等の) フィールドがあります。これらの各フィールドには、辞書形式の生の JSON フィールドが含まれます。

### Google BigQuery (汎用)

MoEngage は、BigQuery Transfer File サービスを使用して、GCS バケット経由で BigQuery テーブルにイベントをエクスポートします。BigQuery でイベント用のテーブルを作成するには、次の 2 つの方法があります。

1. エクスポートされたファイルのスキーマを使用して、エクスポートされたイベント専用のテーブルを作成する。
2. 汎用スキーマを持つテーブルを作成する。

汎用スキーマを作成したいが、イベントがわからない場合は、次のスキーマを使用できます。

JSON

```json wrap
[
    {

        "type": "STRING"
    },
    {
        "mode": "NULLABLE",
        "name": "export_hour",
        "type": "INTEGER"
    },
    {
        "mode": "NULLABLE",
        "name": "export_day",
        "type": "DATE"
    },
    {
        "mode": "NULLABLE",
        "name": "event",
        "type": "JSON"
    },
    {
        "mode": "NULLABLE",
        "name": "app_name",
        "type": "STRING"
    },

        "mode": "NULLABLE",

```

## クラウドストレージの宛先

MoEngage は圧縮ファイルをクラウドストレージにエクスポートします。

### 汎用エクスポートスキーマ

- **ファイル形式:** .json.gz
- 解凍された各ファイルには、JSON 形式の改行区切りのイベントが含まれます (各行が 1 つのイベントです)。
- 各ファイルには複数のタイプのイベントが含まれる場合があります。イベントのタイプごとに 1 つのファイルを作成するわけではありません。
- イベントの JSON 形式は次のとおりです。

JSON

### Amazon S3

MoEngage は、S3 Exports の設定時に指定したフォルダ内に、事前に定義されたファイルパスを作成します。

ファイルは次の場所に格納されます。

_s3://\<your\_bucket\_name\>/\[\<folder\_path\>\_\]\<connection\_name\>/export\_day=`<DD-MM-YYYY>`/event\_exports\_\<export\_timestamp\>.json.gz_

### Google Cloud Storage

MoEngage は、GCS バケット内に事前に定義されたファイルパスを作成します。ファイルは次の場所に格納されます。

_gs://\<your\_bucket\_name\>/event-exports/\<your\_app\_name\>/\<connection\_id\>/export\_day=YYYY-MM-DD/export\_hour=HH/`<file-name>`.json.gz_

### SFTP

MoEngage は、SFTP サーバー上に事前に定義されたファイルパスを作成します。ファイルは次の場所に格納されます。

_sftp://\<your\_host\_name\>/\[\<folder\_path\>/\]\<connection\_name\>/export\_day=`<DD-MM-YYYY>`/event\_exports\_\<export\_timestamp\>.json.gz_

### 共通イベント属性

これらの属性は、カスタム/ユーザー定義イベントを追跡するときに自動的に追跡されます。

|  |  |  |
| --- | --- | --- |
| キー名 | 属性キー | 説明 |
| App Version | appVersion | このイベントが追跡されたアプリのバージョン。 |
| SDK Version | sdkVersion | このイベントが追跡された MoEngage SDK のバージョン。 |
| MOE Event Category | moe\_event\_category | イベントカテゴリを表します   <br />- 例: Tracked User Events |
