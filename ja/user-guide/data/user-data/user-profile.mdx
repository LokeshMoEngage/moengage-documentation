User Profile は、MoEngage に保存されているユーザーのデータ (名、メールアドレス、サブスクリプションステータス、ウェブサイトで訪問したページなど) の 360° ビューを提供します。

<Info>
  このドキュメントでは、User Profile の新しい UI と古い UI の両方について説明します。User Profile の新しい UI は段階的にリリースされます。ワークスペースで早期に有効化したい場合は、MoEngage サポートチームにお問い合わせください。 
</Info>

User Profile は、ユーザーが MoEngage SDK を導入したアプリまたはウェブサイトを開いたとき、または UI や API を通じてユーザー情報をアップロードしたときに作成および更新されます。

<Info>
  - MoEngage はあらゆる量のデータを取り込むことができますが、不正使用を防ぐため、データの [トラッキング](/ja/user-guide/data/key-concepts/data-tracking-policies) と [アーカイブ](/ja/user-guide/data/key-concepts/data-archival-retention-policy) についてフェアユースポリシーに従います。
  - ワークスペースで [Portfolio](/ja/user-guide/settings/account/portfolio/portfolio) が有効になっている場合、User Profile にも関連する変更が加わります。詳細については、[Portfolio: データの取り込みと管理](/ja/user-guide/data/key-concepts/portfolio-data-ingestion-and-management) を参照してください。
</Info>

<Callout icon="bars-progress" color="#FFC107" iconType="regular">
 **前提条件**

 ユーザーアカウントを管理するには、**User Profile Management** 権限が必要です。この権限により、ユーザーの削除や権限の編集が可能になります。デフォルトでは、この権限は **Admin** ロールと **Manager** ロールに自動的に付与されます。詳細については、[アクセスロール](/ja/user-guide/settings/account/team-management/access-roles) を参照してください。
</Callout>

### Lifecycle

このセクションには、ユーザーの最近のアクティビティの概要が表示されます。次の情報が表示されます。

- **Last Active**: ユーザーがプラットフォーム上で最後にアクティブだった日付。
- **No of sessions**: ユーザーが行ったセッション数。これは、ユーザーが App/Site Open イベントを実行した回数です。

### Conversion

このセクションには、プラットフォームにおけるユーザーの価値とエンゲージメントを示すコンバージョン指標の詳細が表示されます。次の情報が表示されます。

- **No of conversions**: ユーザーが行ったコンバージョンイベントの数。
- **Life Time value**: ユーザーのライフタイムバリュー。これは、ユーザーが実行した _Conversion goal_ イベントに含まれる収益属性の合計です。LTV は、ユーザーがコンバージョンゴールイベントを実行するたびに更新されます。詳細については、[ライフタイムバリュー (LTV) の設定](/ja/user-guide/data/user-data/derived-user-attributes#configure-lifetime-value-ltv) を参照してください。

### Acquisition

このセクションには、ユーザーが最初にどのように獲得されたかに関する情報が表示されます。次の情報が表示されます。

- **First Seen**: ユーザーが MoEngage プラットフォームで最初に確認された、または登録された日付。
- **Publisher / Campaign**: ユーザーがアプリをインストールした経路となった Publisher/Campaign の名前。

### Location

このセクションには、ユーザーの地理的な位置が表示されます。次の情報が表示されます。

- **City / State**: ユーザーの市区町村と州/都道府県。
- **Country**: ユーザーの国。

### Reachability

Reachability は、プッシュ、メール、SMS などのさまざまなチャネルを通じてユーザーにリーチ/接続できるかどうかを示します。Push カードの緑色のチェックマークは、このユーザーにリーチ可能なプラットフォームまたはデバイスが少なくとも 1 つあることを示します。赤色の感嘆符は、該当するプラットフォームまたはチャネルでユーザーにリーチできないことを表します。詳細については、[ユーザーのリーチ可能性](/ja/user-guide/segment/reachability/user-reachability) を参照してください。Reachability のテスト: **Test Push、Test Email、** および **Test SMS** ボタンを使用して、ユーザーにテスト通知をすばやく送信できます。Test Push と Test Email は、それぞれ事前設定されたプッシュとメールを送信します。一部の国 (インドなど) の法律では SMS の送信にホワイトリスト登録されたテキストが必要なため、Test SMS ではユーザーがテキストメッセージを入力する必要があります。

### Subscription Statuses

<Info>
  **Subscription Statuses** セクションは新しい UI でのみ利用できます。
</Info>

このセクションでは、Email チャネルと SMS チャネルのサブスクリプションステータスを確認し、手動で編集できます。

<Frame>
  ![Screenshot 2026 05 14 At 1 46 03 PM](/images/Screenshot-2026-05-14-at-1.46.03-PM.png)
</Frame>

- **サブスクリプションステータスの編集**: 編集アイコンをクリックして、サブスクリプションステータスを変更します。現在、手動での上書きは Email と SMS でのみサポートされています。WhatsApp と Push は読み取り専用です。
- **Email のサブスクリプションステータス**: Email のサブスクリプションステータスには **Subscribed** と **Unsubscribed** があります。ワークスペースで [Double-optin ](/ja/user-guide/campaigns-and-channels/email/getting-started-with-email/opt-in-management)が設定されている場合、サブスクリプションステータスには **Optin pending**、**Double-opted in**、**Opted out** が含まれます。\
  **注**: メールコネクタとして SendGrid を使用している場合、MoEngage でステータスを更新すると、ステータスの同期を保つために SendGrid へのダウンストリーム更新が自動的にトリガーされます。この変更により、内部トラッキングイベントと Audit Logs のエントリも生成されます。生成されるイベントは次のとおりです。
  - _Email Resubscribed_
  - _Email Opt-in Status Updated_
  - _Email Unsubscribed_
- **SMS のサブスクリプションステータス**: SMS のステータスを更新すると、対応するサブスクリプション属性の値が直接変更されます。

### User Properties

このセクションには、ユーザーに関するすべてのユーザー属性が表示されます。

![usersearch.png](/images/moengage_2f586e.png)

これらは、ユーザーセグメンテーション時に **User Properties** ドロップダウンからアクセスでき、カテゴリ別に整理されています。プロパティの横にある「mo」記号は、そのプロパティが MoEngage によって派生または生成されたものであることを示します。

 - 特定の値を使用してユーザーを検索するには、プロパティにカーソルを合わせて **COPY** をクリックします。 
 - リスト全体を CSV ファイルにエクスポートするには、右上隅の **Download** をクリックします。 
 - プロパティの完全なリストとその関連情報を確認するには、[こちら](/ja/user-guide/data/event-data/derived-events-and-attributes) を参照してください。

<Info>
  PII (個人を特定できる情報) としてマークされたプロパティは、User Profile では **Private** と表示されます。詳細については、[PII マスキング](/ja/user-guide/data/privacy/personal-data-or-personally-identifiable-information-pii/pii-masking) を参照してください。
</Info>

<Note>
  **User Profile で日付属性が 1 日ずれて表示される場合があります**

  User Profile は、保存されている値が想定される末尾の形式と一致する場合にのみ、日付属性を UTC からワークスペースのタイムゾーンに変換します。`.xxxZ` で終わる値は変換されますが、`.xxZ` で終わる値は変換されないため、UTC のまま表示され、1 日ずれて見えることがあります。

  これは User Profile での値の表示にのみ影響します。セグメントのカウントとキャンペーンのターゲティングはどちらもワークスペースのタイムゾーンで属性を評価するため、影響を受けません。User Profile の日付が 1 日ずれているように見える場合は、同じ属性のセグメントカウントを確認して、基になる値が正しいことを確認してください。
</Note>

**イベントフィルター**

<Info>
  **Event Filter** は、新しい UI では **Filter Events** と表示されます。

ユーザーアクティビティは最大 5 つのイベントでフィルタリングできます。アカウントに存在する任意のイベントとその属性を使用して、顧客アクティビティをフィルタリングできます。これは、セグメンテーションにおけるユーザーアクティビティのフィルタリングと同様です。**キャンペーンフィルター** キャンペーンフィルターを使用すると、ユーザーのキャンペーンアクティビティをフィルタリングできます。これらのフィルターにより、ユーザーが実行したキャンペーンイベントに基づいて、すべてのキャンペーンまたは個々のキャンペーンを取得できます。アクティビティページには、以下の追加機能が含まれています。

- アクティビティタイムラインは、LATEST FIRST (新しい順) または Oldest First (古い順) で並べ替えることができます。設定はデバイスに保存されます。

### 30 日を超えるユーザーアクティビティ

Activity Info (Event Activity) では、アカウントのデータ保持期間全体にわたるユーザーのイベントとイベント属性を表示することもできます。30 日を超えるユーザーのイベントにアクセスするには、以下の手順に従ってください。

1. **Activity Info (Event Activity)** ページ上部の **Filter Events (Event Filter)** セクションに移動します。
2. 過去 30 日より前の、最大 7 日間の日付範囲を選択します。日付範囲は、アカウントの最大データ保持期間まで選択できます。 <img alt="custom_range.png" src="/images/custom_range.png" />
3. ユーザーについて表示したいイベントと属性を選択します。最大 10 個のイベントと、イベントごとに最大 5 個の属性を選択できます。 <img alt="event_flilter.png" src="/images/event_flilter.png" width="50%" />
4. **Apply** をクリックすると、指定した日付範囲内のユーザーについて、選択したイベントとイベント属性が表示されます。

## アクション

新しい UI を使用している場合は、**Actions** ボタンを使用して次の操作を実行できます。

- **Delete User:** ユーザープロファイルを完全に削除できます。削除をクリックすると、警告が表示されます。削除がシステム全体に反映されるまでに最大 24 時間かかる場合があり、完全に削除されるまではユーザープロファイルを引き続き利用できることに注意してください。この操作は [Audit Logs](/ja/user-guide/settings/account/audit-logs/audit-logs) に記録されます。
