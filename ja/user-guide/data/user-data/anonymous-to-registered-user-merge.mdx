すべてのユーザーは、メール、携帯電話番号、カスタムIDなどの一意の属性を使用して識別されます。これらの識別子は、ユーザーがメールID、携帯電話番号、ユーザー名でログインするときなど、ユーザーが自身の情報を提供したときに生成されます。さらに、ユーザーは複数のデバイスを使用してアプリやWebサイトにアクセスすることがあり、ユーザーがログインするまで、そのユーザーが新規ユーザーか既存ユーザーかはわかりません。

MoEngageはユーザーを以下のように分類します。

- **匿名ユーザー** - Webサイトまたはアプリによってまだ識別されていないユーザーです。アプリ/Webサイトを使用しているがログインしていないユーザー、またはまだサインアップしていない完全な新規ユーザーが該当します。
- **登録ユーザー** - Webサイトまたはアプリにサインアップまたはログインしたユーザーです。

# 知っておくべき用語

- **MoEngage ID** - MoEngageは、ユーザーを認識するために、ユーザーがWebサイトまたはアプリにアクセスするとすぐに一意の識別子を作成します。これは変更できない値です。
- **ID** - ユーザーがアプリまたはWebサイトに（メール、電話番号、ユーザーIDのいずれかを提供して）登録した際には、そのプロファイルに対して一意の識別子を生成し、IDとしてMoEngageに渡すことをお勧めします。このIDにより、複数のデバイスやプラットフォームにわたってユーザーを認識でき、360°ビューを実現できます。これにより、ユーザーがアプリをアンインストールして再インストールした場合でも、ユーザーに関する情報が正しく取得されます。

# MoEngage IDとIDの関係

- **新規ユーザー** - ユーザーが初めてアプリを開くかアクセスしたとき、ブランドもMoEngageもそのユーザーに関する情報を持っていません。MoEngageはこのユーザーにMoEngageIDを割り当て、匿名プロファイルを作成します。MoEngageは、ユーザーが実行したすべてのアクションを記録します。
- **サインアップ** - ユーザーがサインアップに進むと、登録ユーザーまたは識別済みユーザーになります。アプリは各ユーザーに一意の識別子を割り当てます（SDKのIdentifyUser()関数を使用）。この情報がMoEngageに渡され、このユーザーはMoEngageシステムで登録ユーザーと見なされます。
- **最初にサインインしていない登録ユーザー** - ユーザーがアカウントを持っている（MoEngage IDとIDを持っている）ものの、一連のイベントを実行した後にサインインした場合、最初にサインインしていなかったため、新しいMoEngage IDが作成されています。サインインすると、新しいMoEngage IDで作成されたユーザープロファイルは既存のMoEngage IDとマージされます。

# ユーザーマージのシナリオ

MoEngageでは、ユーザーが異なるデバイスを使用している場合でも、すべてのユーザーに単一のユーザーIDを持たせることができます。MoEngageでユーザーをマージするための唯一の条件は、ユーザーがデバイスでサインインしていることです。ユーザーがWebサイトまたはアプリにアクセスすると、MoEngageはユーザーがシステムにログインした時点で、匿名ユーザープロファイルを登録ユーザープロファイルとマージします。ユーザーマージの有効化の詳細については、[Enable User Merging](/ja/user-guide/settings/analytics/enable-user-merging)を参照してください。

**シナリオ1：** ユーザーがデバイス（デバイス1）で初めてWebサイトまたはアプリにアクセスすると、そのユーザーは匿名ユーザーと呼ばれ、MoEngageIDとしてMoEID-1が設定されます。  
ユーザーがログインすると、このユーザーは識別済みユーザーとなり、U-1というIDが設定されます。ユーザーがログアウトまたはアンインストールするまで、このデバイス上のすべてのイベントはMoEID-1に帰属します。

<img alt="UserMerge_Scenario1.png" src="/images/moengage_4a0ad7.png" />

**シナリオ2：** 同じユーザーが別のデバイス（デバイス2）からWebサイト/アプリにアクセスした場合、MoEngageはこのユーザーの身元を把握していないため、このユーザーは引き続き匿名ユーザーであり、新しいMoEngageID MoEID2が作成されます。ユーザーがログインすると、Webサイトまたはアプリは、ユーザーIDがU-1であることをMoEngageに通知します。これにより、匿名ユーザーは既存の登録ユーザーとマージされます。

# マージがユーザー属性に与える影響

<Info>
匿名ユーザーの追跡と、その後の登録ユーザーへのマージは、MoEngage SDKの統合を通じてのみ可能です。他のデータソースを通じて匿名ユーザーを登録ユーザーにマージすることはできません。
</Info>

## デフォルトのマージ動作

デフォルトでは、ユーザーマージが発生すると、MoEngageは受信した匿名ユーザーのデータよりも、登録ユーザープロファイルにすでに存在するデータを優先します。つまり、既存の登録ユーザーの属性値が保持され、匿名ユーザーの値は通常破棄されます。

匿名ユーザープロファイルを保持対象のユーザープロファイルにマージすると、以下のシステムアクションと属性の変更が行われます。

- 保持対象のユーザープロファイルの**First Seen**属性は、マージされるすべてのプロファイルの中で最も古い**First Seen**値に設定され、**Last Seen**属性は、マージされるすべてのプロファイルの中で最新の**Last Seen**値に設定されます。
- **LTV**、**No. of Conversion**、**No. of Sessions**属性の値は、既存プロファイルと保持対象プロファイルの両方から合算され、その結果が保持対象プロファイルに保存されます。保持対象ユーザーのその他の既存属性は変更されません。
- 匿名ユーザーのみが持つ属性は、保持対象ユーザーがその属性を持っていない場合、保持対象ユーザーに転送されます。
- プッシュの到達可能性は、全体のデバイスに基づいて計算されます。
- **Email (Standard)**属性が保持対象ユーザーにコピーされた場合、関連するメール抑制属性（**Hard Bounce**、**Spam**、**Unsubscribed**）もコピーされます。

## 登録済みのカスタムユーザー属性を最新の匿名ユーザーデータで上書きする

<Info>
- アカウントでこの機能を有効にするには、MoEngageのカスタマーサクセスマネージャー（CSM）またはサポートチームにお問い合わせください。
- この機能はカスタムユーザー属性にのみ適用されます。
</Info>

ユーザーデータを柔軟に管理できるように、MoEngageでは、選択した既存のカスタムユーザー属性を、匿名ユーザーセッションから取得した最新のデータで上書きできます。この機能は、ログイン前に取得した最新の情報がパーソナライゼーションやキャンペーンのターゲティングにより関連性が高い場合に特に役立ちます。

**シナリオ**：頻繁に旅行する登録ユーザーが、旅行アプリケーションでパリ行きのフライトを匿名で閲覧しています。**Last Searched Location**カスタム属性を上書きしたいとします。

- **上書きなし**：ユーザーの登録プロファイルの**Last Searched Location**カスタム属性が当初*New York*であった場合、最近の検索にかかわらず、ユーザーマージ時にもこの値（*New York*）が維持されます。
- **上書きあり**：上書き機能が有効な場合、ユーザーマージ時に、匿名プロファイルの値が登録プロファイルの**Last Searched Location**属性を上書きします。そのため、**Last Searched Location**は*New York*から*Paris*に変わります。

これにより、旅行アプリケーションはユーザーの最新の場所への関心をターゲットオファーやパーソナライズされたコンテンツに活用でき、より関連性が高く効果的なキャンペーンにつながります。

# マージがイベントに与える影響

ユーザーマージ後に発生するすべてのイベントは、識別済み/登録ユーザーに帰属します。それ以前に実行されたすべてのイベントも、識別済み/登録ユーザーに帰属します。
