## 概要

<Info>
**Early Access**

これは Early Access 機能です。アカウントで有効にするには、MoEngage のカスタマーサクセスマネージャー (CSM) またはサポートチームにお問い合わせください。
</Info>

Unset User Property 機能を使用すると、特定のユーザープロパティから値を削除し、実質的に「null」または「存在しない」状態に戻すことができます。この機能が導入される以前は、ユーザープロパティの値をクリアしたい場合、値を 0、N/A、または空文字列に設定することがありました。しかし、MoEngage はこれらも「値」として扱います。設定解除 (Unset) を行うと、ユーザープロパティの値が完全に削除されるため、より正確なセグメンテーションとデータの健全性を実現できます。

<Info>
**情報**

- この機能は標準およびカスタムのユーザープロパティにのみ適用され、派生ユーザープロパティおよび ID (customer_id) には適用されません。
- この機能はイベント属性やデバイス属性ではサポートされていません。
- 属性の設定解除機能は、データ API、具体的には Track User API と Bulk Import API (ユーザープロパティのみ。イベント属性やデバイス属性は対象外) を通じてのみサポートされています。
- 属性の設定解除機能は、SDK、Warehouse Imports、およびファイルベースのインポートではサポートされていません。
- PII として暗号化およびマスクされたユーザープロパティも設定解除できます。
</Info>

## ユースケース

**セグメンテーション精度の向上:** 古くなったステータスフラグ (例: 有効期限切れの Loyalty Tier) をユーザープロファイルから削除することで、正確なターゲティングが可能になります。これにより、ユーザーが「存在しない (Does Not Exist)」セグメントに正しく該当するようになり、残存する空の値や null 値によるデータノイズを排除できます。

**正確なデータ削除:** 値を 0 や null に設定する場合 (属性キーはプロファイル上に残ります) とは異なり、属性の設定を解除すると属性値が削除されます。これにより、個々の属性 (PII や古い連絡先情報など) を正確に削除でき、ユーザープロファイル全体に影響を与えることなくデータの健全性を維持できます。

**データコンプライアンスと GDPR:** 部分的なデータ削除リクエスト (例: ユーザーからのリクエストや GDPR 準拠のために電話番号や特定の PII を削除する場合) に対応するため、ユーザーのプロファイルの残りの部分と履歴データを保持したまま、特定のユーザープロパティを消去できます。

## サポートされているデータ型

次のデータ型の属性を設定解除できます。

- String (テキスト)
- Numeric (整数、小数)
- DateTime
- Boolean (True/False)
- すべての Array 型
  デフォルトでは、配列を設定解除すると、配列内のすべての属性要素が設定解除されます。配列から特定の要素のみを部分的に削除したい場合は、removeValueFromArrayField 機能を使用してください。詳細については、[Track User](/ja/api/user/track-user) API の ``User Property as Array`` cURL を参照してください。

## ユーザープロパティの設定解除

属性の設定を解除するには、サポートされているデータ API の JSON ペイロードの `unset_attributes` キーで属性を渡します。設定解除する各属性の名前を、文字列として配列に追加します。各名前は、ワークスペース内の属性名と完全に一致する必要があります。

### サンプル cURL

以下は [Track User API](/ja/api/user/track-user) のサンプル JSON ペイロードです。[Bulk Import API](/ja/api/bulk/bulk-import-users-and-events) の場合も属性を設定解除するロジックは同じですが、Customer ペイロード (`type: customer`) にのみ適用されます。

```bash
curl --location --request POST 'https://api-0X.moengage.com/v1/customer/{{appId}}?app_id={{appId}}' \
--header 'Content-Type: application/json' \
--header 'Authorization: Basic Base64_ENCODED_APPKEY_APIKEY' \
--data '{
    "type": "customer",
    "customer_id": "Customer01",
    "attributes": {
    },
    "unset_attributes": ["custom_userattribute_1"]
}'
```

<Info>
**情報**

- Data Management ダッシュボードで Blocked になっている属性の設定解除リクエストは無視されます。
- Data Management ダッシュボードで Hidden になっている属性の設定解除リクエストは正常に処理されます。
- 同じ API ペイロード内で、ある属性が `attributes` オブジェクトと `unset_attributes` オブジェクトの両方に定義されている場合、設定解除操作が優先され、属性値は削除されます。
- 設定解除操作は、ワークスペース内にすでに登録または存在する属性に対してのみ実行できます。`unset_attributes` 内の属性名が見つからない場合、MoEngage はエラーを返さずにその属性をスキップします。
</Info>
