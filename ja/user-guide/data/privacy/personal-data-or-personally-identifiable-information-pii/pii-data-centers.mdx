MoEngage は、データプライバシーとコンプライアンスのための堅牢なソリューションの提供に取り組んでいます。データレジデンシーおよびデータローカライゼーションのニーズをサポートするため、MoEngage はプライマリデータセンターがない地域向けに、個人を特定できる情報（PII）データセンター（DC）を提供しています。

## PII データセンターとは

PII DC は、特定の地理的リージョン内で個人を特定できる情報（PII）を保存および処理するために設計された、物理的に分離された専用の DC です。これにより、顧客の機密データが確実にその国の国境内に留まり、現地のデータレジデンシーおよびプライバシー規制への準拠に役立ちます。PII DC は、お客様のリージョンにメイン DC がまだ存在しない場合にのみ使用されます。メイン DC の一覧については、こちらの[記事](/ja/user-guide/data/key-concepts/data-centers-in-moengage)を参照してください。

PII DC は、お客様のシステムと MoEngage のメイン DC の間の仲介役として機能します。メイン DC が非 PII データを保存および処理する一方で、指定された PII DC がすべての PII を安全に処理します。

## 主な機能

| 機能 | 説明 |
| --- | --- |
| データレジデンシー | すべての PII データが指定された国の国境内で保存および処理されることを保証し、現地の規制への準拠を確保します。 |
| 安全な PII の取り扱い | 保存時および転送時の暗号化を含む堅牢なセキュリティ対策を実装し、すべての PII データを保護します。 |
| シームレスな統合 | MoEngage のメイン DC と最小限の影響で統合され、スムーズなキャンペーンのオーケストレーションと実行を可能にします。 |
| リアルタイム処理 | 低レイテンシーとリアルタイム処理機能を維持し、タイムリーで効率的な顧客エンゲージメントを実現します。 |
| スケーラビリティ | 他のリージョンへの拡張が容易な設計で、成長するビジネスニーズに柔軟に対応するソリューションを提供します。 |

## データの取り込み

PII データは PII DC に、非 PII データは MoEngage のメイン DC に送信できます。PII データを送信するには顧客番号が必須です。顧客番号は、特定の顧客のメールアドレスまたは電話番号を検索するために使用されます。

## メッセージの送信

すべてのコミュニケーションは MoEngage のメイン DC から開始されます。メイン DC では、まずセグメンテーションが実行され、コミュニケーションを送信する必要があるユーザーが特定されます。コミュニケーションの対象ユーザーが特定されると、コミュニケーションメッセージが作成され、PII DC に送信されます。これは、メイン DC にはメールアドレス、携帯電話番号、その他の PII が存在しないためです。コミュニケーションメッセージと顧客番号が PII DC に送信されます。

PII DC は顧客番号を使用して実際のメールアドレスまたは携帯電話番号を特定し、コミュニケーションメッセージとともにプロバイダーにメッセージの送信をリクエストできます。

## 統合と設定

MoEngage の PII DC の使用を開始するには、データ取り込みプロセスを正しいリージョンのエンドポイントに向けるように設定する必要があります。

### データ取り込みエンドポイント

PII DC へのデータ取り込み用の URL は次のとおりです。

メソッド: **POST**


```json API Endpoint
https://pii-dc0X.moengage.com/v1/transition/
```

**注:**

- pii-dc0X の X を、指定された PII DC の番号に置き換えてください（例: AWS UAE の場合は 1）。
- `<Workspace_ID>` を、お客様の MoEngage Workspace ID に置き換えてください。

Bulk Import API の使用方法の詳細については、[Bulk Import](https://www.moengage.com/docs/api/bulk/bulk-import-users-and-events) API ドキュメントを参照してください。

## よくある質問（FAQ）

このセクションでは、スムーズな統合を実現するために、よくある質問と発生する可能性のある問題について説明します。

### 一般とセキュリティ

<Accordion title="PII DC ではデータはどのように保護されますか？">

MoEngage の PII DC は、ISO 認証を取得し SOC2 Type 2 に準拠しているメイン DC と同じ高いセキュリティ基準に準拠しています。PII は保存時に暗号化され、内部通信の転送時にも暗号化されます。

</Accordion>
<Accordion title="アカウントで PII DC をリクエストするにはどうすればよいですか？">

MoEngage へのオンボーディング中に、MoEngage のソリューションアーキテクトから PII DC のセットアップについてご連絡します。PII DC は、お客様のリージョンにメイン DC がまだ存在しない場合にのみ適しています。

</Accordion>
<Accordion title="PII DC の使用には追加料金がかかりますか？">

PII DC の料金および商取引条件の詳細については、MoEngage の担当アカウントマネージャーまたは営業チームにお問い合わせください。

</Accordion>

### 統合とデータ管理
<Accordion title="ファイルアップロードで PII を送信できますか？">

いいえ。MoEngage は、データ API を通じてのみ PII DC への PII を受け付けます。

</Accordion>
<Accordion title="送信できる PII 属性の数に制限はありますか？">

はい。MoEngage PII DC には最大 20 個の PII 属性を送信できます。

</Accordion>
<Accordion title="携帯電話番号にはどの形式を使用すればよいですか？">

データ API を通じて送信する携帯電話番号は E.164 形式である必要があります。

</Accordion>
<Accordion title="PII DC でコンテンツのパーソナライゼーションは可能ですか？">

いいえ。PII DC リリースの第 1 フェーズでは、パーソナライゼーションはサポートされていません。

</Accordion>
<Accordion title="誤って PII を標準の MoEngage エンドポイントに送信した場合はどうなりますか？">

データは PII DC ではなく、MoEngage のメイン DC で処理されます。データレジデンシー要件を満たすため、すべての PII が正しい PII DC エンドポイントのみを経由するようにすることが非常に重要です。

</Accordion>
<Accordion title="統合時によく発生するエラーは何ですか？">

よくあるエラーには、誤った Workspace ID の使用、不正な形式の API エンドポイント URL、認証の問題などがあります。HTTP 4xx エラーコードは通常、リクエストのクライアント側の問題を示しています。

</Accordion>
<Accordion title="データ取り込みの RPM はどれくらいですか？">

PII DC はデータ取り込みで 1K RPM をサポートしています。

</Accordion>
