# はじめに

他のプラットフォームからMoEngageへ移行するブランドマーケターは、遅延なくプラットフォームの機能を最大限に活用し始めるために、過去のユーザーデバイスデータをMoEngageプラットフォームに移行したいと考えています。移行プロセスの一環として、ブランドのエンドユーザーはMoEngage SDKが統合された新しいバージョンのブランドアプリにアップグレードする必要があります。ブランドのユーザーベース全体が徐々に新しいバージョンへ移行するため、通常はこれに時間がかかります。

この記事では、サーバー間APIを使用して、ユーザーとそのデバイスの過去データをMoEngageへシームレスに移行するのに役立つさまざまな方法について説明します。これらの方法により、移行作業が簡素化され、より便利になります。

# ユースケース

大規模なユーザーベースを持つブランド/ビジネスの場合、すべてのユーザーがアップグレードされたアプリバージョンに移行するまでに時間がかかり、プラットフォームのメリットを享受するのが遅れます。ただし、MoEngage SDKを含む更新済みのアプリバージョンをすでにインストールしているユーザーについては、すぐにデータのトラッキングが開始されます。  
これにより、以下のようなシナリオが発生します。この記事では、各シナリオの解決策を説明します。

## シナリオ1:

MoEngage SDKが統合された最新のアプリバージョンにアップグレードしていないユーザーは、MoEngageプラットフォームからトリガーされたプッシュ通知を受信できません。

## 解決策: Track Device APIを使用したプッシュトークンの移行

多くのユーザーがまだ最新のアプリバージョンにアップグレードしていないため、MoEngage SDKはそれらのユーザーのデバイスプロパティやイベントをまだトラッキングできません。ユーザーベース全体がMoEngage SDK統合済みのバージョンにアプリを更新するのを待つ代わりに、Track Device APIを使用して、すでに保有しているプッシュトークンをMoEngageにインポートできます。Track Device APIまたはBulk Import APIを使用すると、既存ユーザーのデバイスを作成/更新できます。

[Track device API](https://www.moengage.com/docs/api/device/track-device)を使用すると、プッシュトークン、GAID/IDFV、プラットフォーム情報など、すでに保有しているデバイス情報をMoEngageにシームレスに移行できます。MoEngageは、ユーザーに紐づくすべてのデバイスのプッシュトークン、GAID/IDFV、プラットフォームの一意の値を検証して受け入れます。

上記のデバイス情報がMoEngageに正常に取り込まれると、MoEngageプラットフォームからプッシュキャンペーンをトリガーできます。

<Info>
  **iOSデバイスの動作**:
    - Device APIを使用してデバイス属性を移行し、MoEngageプラットフォームからプッシュキャンペーンを送信するこのプッシュ通知配信方法は、iOSデバイスにのみ適用されます。新しいバージョンのAndroidOSを搭載したAndroidデバイスでは、プッシュ通知を表示するために引き続きMoEngage SDKが必要です。また、このような通知はアプリを起動しますが、アプリ内の特定のページにリダイレクトすることはできないため、プッシュ通知のタイトル、サブタイトル、メッセージ内容はそれに応じて作成してください。
    - iOSデバイスにはプッシュ通知が配信されますが、_Push notification clicked_ などの対応するキャンペーン統計はトラッキングされません。これらのイベントはMoEngage SDKによってトラッキングされますが、移行期間中にエンドユーザーが使用しているアプリバージョンにはMoEngage SDKが統合されていない可能性があるためです。

  **Track Device APIのリーチャビリティの動作**: 

    - Track Device APIを使用してプッシュトークンを渡した場合、リーチャビリティが更新されるのは、デバイスが現在 _Installed_ としてマークされている場合のみです。デバイスが _Uninstalled_ としてマークされている場合、Track Device APIを使用して `push_id` または `moe_push_opted` を更新しても、リーチャビリティには影響しません（Unreachableのままです）。デバイスのステータスを _Installed_ に戻すには、MoEngage SDKがデバイスをアクティブにトラッキングする必要があります。
</Info>

## シナリオ2:

効果的にターゲティングして、MoEngage SDKが統合された最新のアプリバージョンへのアップグレードをユーザーに促します。

## 解決策: Bulk Import APIを使用したユーザーデバイス情報の移行

マーケターは、MoEngageの[Bulk Import API](https://www.moengage.com/docs/api/bulk/bulk-import-users-and-events)を使用してユーザーとそのデバイスを作成できます。その後、アプリバージョンのアップグレードについて通知すべきユーザーを示すために、対応する値を持つカスタムユーザー属性を割り当てることができます。   
たとえば、最新のアプリバージョンにアップグレードしていないユーザーに対して、カスタムユーザー属性 *bulk\_migration* の値を *true* に設定するとします。このカスタムユーザー属性を使用して、以下の手順でセグメントを作成できます。

### セグメントを作成する

アプリのアップグレードを行っていないユーザーを含むセグメントを作成するには、次の手順を実行します。

1. MoEngageダッシュボードの左側のナビゲーションメニューで、**Segment** \> **Create segment** をクリックします。
2. **Filter users by** をクリックし、**User property** タブをクリックします。
3. **Select attribute** リストで、移行したユーザーをマークするために作成したカスタムユーザー属性を選択します。このユースケースでは、カスタムユーザー属性は *true* に設定された *bulk\_migration* です。  
    <img alt="Screenshot 2025-01-03 at 11.37.05 AM.png" src="/images/moengage_1cd4e7.png" />
4. 残りの手順を実行してセグメントを作成します。詳細については、[セグメントの作成](/ja/user-guide/segment/create-segments/rule-based-filter-segments)を参照してください。

セグメントを作成した後、このセグメント内のユーザーをターゲットにキャンペーンを送信し、MoEngage SDKが統合された最新のアプリバージョンへのアップグレードを促すことができます。
