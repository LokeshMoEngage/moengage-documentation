この記事では、InApp 通知連携を手動で検証する方法を段階的に説明します。

# 何を検証するのか

アプリ内キャンペーンがアプリに表示され、CTA ボタンが想定どおりに動作するかを確認します。

# 検証方法

- 自分の ID と画面起動時を対象にアプリ内キャンペーンを作成します。
- テストキャンペーンをデバイスに送信し、アプリ内通知が表示されるか確認します(テストを送信するとデバイスでプッシュ通知を受信し、それをクリックするとアプリのランダムなページが開いてアプリ内通知が表示されます)。失敗した場合は、失敗の理由を確認してください。
- キャンペーンの作成を完了し、配信制御をオフにします。15～30 分ほどでアプリ内通知がアプリに反映され始めます。
- アプリ内通知の作成時に、アクションの追加でナビゲーションを選択してリダイレクトを追加します。
- 画面に移動するオプションを選択し、ドロップダウンから画面を選択します。通知を受信したらクリックし、ドロップダウンで選択した画面がアプリで開くことを確認します。KV ペアがある場合は追加してください(iOS の場合は画面名を貼り付けることができます)。
- ディープリンクオプションを選択し、URL を追加します。通知をクリックすると、ユーザーはアプリ内の意図した箇所に正確にリダイレクトされる必要があります(KV ペアがある場合は追加してください)。
- リッチランディングオプションを選択し、URL を追加します。通知をクリックすると、ユーザーは Web にリダイレクトされる必要があります。
- キャンペーンが送信されると、キャンペーンの統計情報にインプレッションとクリックが表示されます。

# 成功基準

- アプリ内通知がデバイスに表示される必要があります
- 意図したリダイレクトが実現される必要があります
- キャンペーンがライブになったら、通知のインプレッションとクリックが記録される必要があります。

# 考えられる問題と解決策

InApp が動作しない場合、プッシュチャネル以外でユーザーをターゲティングできなくなります。InApp に関するこの問題を修正するには、[Android](/ja/developer-guide/android-sdk/in-app-messages/in-app-nativ) および [iOS](/ja/developer-guide/ios-sdk/in-app-messages/in-app-nativ) のドキュメントを確認してください。
