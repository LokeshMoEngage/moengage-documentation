title: "知っておくべき用語"
description: "使い始める前に、MoEngageの主要な用語と概念を理解しましょう。Merlin AIなどの定義や、プラットフォームの基本用語を取り上げています。"
---

以下の用語は、MoEngageを使い始める際に役立ちます。

| 用語 | 定義 |
| --- | --- |
| A/B & Multivariate Testing | 多変量テストまたはスプリットテストは、マーケターが1つ以上の変数を変更してキャンペーンへの影響を判断するために実施する実験です。A/Bテストは、メッセージの2つのバージョンを、ランダムに選ばれた同数のユーザーグループに送信して比較し、どちらのパフォーマンスが高いかを確認するもので、1つの変数のみをテストする場合に使用されます。多変量テストは、コミュニケーションの3つ以上のバリエーションを、ランダムに選ばれた異なるユーザーに送信してパフォーマンスを比較します。詳細については、[概要](/ja/user-guide/ai-and-intelligence/ab-testing/what-is-ab-or-multivariate-testing/overview)を参照してください。 |
| A/B Split in Flows | A/B Splitを使用すると、最大5つのフローパスのバリエーションをテストして、最もパフォーマンスの高いオプションを判断できます。これらのフローパス間で、異なるチャネル、同じチャネルでの異なるメッセージ、異なるメッセージ頻度を試すことができます。各ブランチのパフォーマンスを分析した後、勝者のブランチが有利になるようにユーザー配分を変更できます。詳細については、[FlowsのA/B Split](/ja/user-guide/flows-cross-channel-messaging/create/experimentation/ab-split-in-flows)を参照してください。 |
| Affinity Segments | アフィニティセグメントは、アプリ内で示されるユーザーの性格、ライフスタイル、信念、選択に基づいてユーザーをグループ化し、ターゲティングします。特定のアーティストを最もよく聴くユーザーや、特定の時間帯にタクシーを予約するユーザーを見つけるなど、性格特性を分析してユーザーをより深く理解できます。これらのセグメントを使用して、各グループの好みや習慣に合わせてキャンペーンを調整できます。詳細については、[アフィニティセグメント](/ja/user-guide/segment/create-segments/affinity-segments)を参照してください。 |
| AIRA (Support Bot) | AIRA（Artificial Intelligence Resolution Agent）は、MoEngageの生成AIサポートボットです。豊富なナレッジベースとカスタムワークフローを参照して問い合わせに対応し、複雑な問題についてはサポートチケットを作成してエスカレーションできます。AIRAは24時間365日利用できます。詳細については、[AIRAの概要](/ja/user-guide/contact-support/aira-support-bot/aira-overview)を参照してください。 |
| Analytics | MoEngage Analyticsは、ユーザーがWebアプリやモバイルアプリをどのように操作しているかを理解するのに役立ちます。イベントをトラッキングし、トレンドを分析して、アプリやキャンペーンのパフォーマンスを測定できます。 |
| Anonymous vs. Registered User | 匿名ユーザーとは、ログインしていない訪問者やサインアップしていない新規ユーザーなど、Webサイトやアプリでまだ識別されていないユーザーです。登録ユーザーとは、Webサイトやアプリにサインアップまたはログインしたユーザーです。MoEngageは、ユーザーが訪問するとすぐに変更不可のMoEngage IDを割り当ててユーザーを認識し、ユーザーがサインアップすると一意のIDを渡すことで、デバイスやプラットフォームをまたいでユーザーを認識できるようにします。詳細については、[匿名ユーザーから登録ユーザーへのマージ](/ja/user-guide/data/user-data/anonymous-to-registered-user-merge)を参照してください。 |
| API | MoEngage APIは、モバイルSDKやWeb SDKを経由せずに、ユーザーが行ったアクションをHTTPSで直接送信できるWebサービスを提供します。これにより、アプリやWebサイト内でトラッキングされていないユーザーデータをMoEngageに渡すことができます。詳細については、[API](https://www.moengage.com/docs/api/introduction)を参照してください。 |
| Auxiliary Data | Auxiliary Dataを使用すると、キャンペーンのパーソナライゼーションのために補足的なユーザー情報を既存のデータベースにインポートできます。期間限定のオファー、割引、プロモーションなど、永続的な保存が不要な短期的なデータに使用します。データはファイルインポートで取り込み、関連性がある期間中にキャンペーン作成時に使用します。詳細については、[Auxiliary Data](/ja/user-guide/data/imports/auxiliary-data)を参照してください。 |
| Behavior Analysis | Behavior Analysisは、Webアプリケーションやモバイルアプリケーションでのユーザーのインタラクションに関するインサイトを提供します。特定のイベントをトラッキングし、新たなトレンドを評価して、製品やマーケティングキャンペーンの効果を評価できます。可視化のためのグラフと、詳細な分析のための表形式のレポートを生成します。詳細については、[Behavior - 概要](/ja/user-guide/analyze/analytics/behavior/behavior-overview)を参照してください。 |
| Best Time Analysis | Best Time Analysisは、チャネルごとに過去24時間の1時間単位の詳細なユーザーアクティビティを表示するダッシュボードです。グラフを使用すると、全員に決まった時間にコミュニケーションを送信するのではなく、ユーザーにキャンペーンを送信するのに最適な時間帯を特定できます。チャネルごとに、インタラクションや反応の可能性を高める最適な時間帯を見つけることができます。詳細については、[Best Time Analysis](/ja/user-guide/analyze/dashboards/best-time-analysis)を参照してください。 |
| Best Time to Send (BTS) | Best Time to Send（BTS）は、Send Time Optimizationとも呼ばれ、インタラクションや反応の可能性を高めるために、ユーザーにキャンペーンを送信する推奨時間帯を提示します。BTSはユーザーレベルで定義され、Push、Email、SMS、MMSごとに、キャンペーンやチャネルに対する過去のユーザーインタラクションを個別に分析します。これにより、すべてのユーザーに決まった時間にコミュニケーションを送信するのではなく、各ユーザーの最適な時間帯にターゲティングできます。詳細については、[Best Time to Send](/ja/user-guide/ai-and-intelligence/timing/best-time-to-send)を参照してください。 |
| Business Events | ビジネスイベントを使用すると、ユーザーのアクションではなくビジネス上のアクションに基づいてイベントを作成し、それらのイベントが発生したときにキャンペーンを実行できます。ユーザーのアクション（Webページの閲覧など）から開始されるイベントトリガーキャンペーンとは異なり、ビジネスイベントキャンペーンはビジネス側で行われたアクション（ブランドによる商品の再入荷など）から開始されます。これにより、社内のビジネスアクションに合わせてキャンペーンの配信を自動化できます。詳細については、[概要 - ビジネスイベント](/ja/user-guide/campaigns-and-channels/getting-started/triggers/business-event/overview-business-events)を参照してください。 |
| BYOK (Bring Your Own Key) | デフォルトでは、MoEngageがPIIの保護に使用する暗号化キーを生成・管理します。Bring Your Own Key（BYOK）を使用すると、マスター暗号化キーを直接管理できるため、MoEngageを含め誰もお客様のキーを使わずにユーザーのPIIにアクセスすることはできません。これはPII Data Encryptionのアドオンであり、MoEngageチームによる手動での有効化が必要です。詳細については、[PIIデータ暗号化のためのBring Your Own Key（BYOK）](/ja/user-guide/data/privacy/personal-data-or-personally-identifiable-information-pii/-bring-your-own-key-byok-for-PII-data-encryption)を参照してください。 |
| Campaign Approval Flow | キャンペーン承認を使用すると、マーケティングチームは作成者-承認者（メーカー-チェッカー）方式を導入して、公開されるキャンペーンを管理またはレビューできます。詳細については、[キャンペーン承認ワークフロー](/ja/user-guide/settings/account/team-management/campaign-approval-workflow)を参照してください。 |
| Campaign Decisioning | Campaign Decisioningは、キャンペーン配信を手動のルールベースのターゲティングから、個々のユーザーレベルでの自動化された成果ベースの意思決定へと転換します。Campaign Decisioning Agentは、「このセグメントに当てはまるのは誰か」を問うのではなく、特定のユーザーがメッセージを受け取った場合にコンバージョンする確率を評価します。このリアルタイムのインテリジェンスは、発生する前にあらゆる潜在的なインタラクションを評価し、大規模な確率ベースの最適化を可能にします。詳細については、[はじめに](/ja/user-guide/decisioning/campaign-decisioning/introduction)を参照してください。 |
| Cards | Cardsは、ユーザーのフローを妨げることなく、アプリの受信トレイやニュースフィードに表示される、パーソナライズされたキャンペーン、オファー、レコメンデーションを配信するためのカスタマイズ可能なエンゲージメントチャネルです。Cardキャンペーンの配信には、MoEngage Cards InboxまたはSelf-handled Cardsを使用できます。配信されたカードはユーザーのアプリ体験の一部として残り、他のチャネルとは異なりオプトインは不要です。詳細については、[Cardsの概要](/ja/user-guide/campaigns-and-channels/cards/getting-started-with-cards/cards-overview)を参照してください。 |
| Catalogs | アイテムカタログは、レコメンデーションを作成して使用するための前提条件です。製品、サービス、フライト、記事、レストラン、料理、ソーシャルメディアフィードなど、ビジネスで提供するすべてのものとその関連詳細の一覧です。Catalog機能を使用すると、アイテムカタログを作成・管理し、MoEngageに接続して、キャンペーンでアイテム情報を使用できます。詳細については、[Catalogs](/ja/user-guide/content/recommendations/getting-started/catalogs)を参照してください。 |
| Computed Traits | Computed Traitsは、MoEngageですでに収集しているイベントデータに計算や変換を適用して作成される動的なユーザー属性です。ユーザーの行動に基づいて自動的に更新されるため、手動でのアップロードや開発作業なしに、セグメンテーションやパーソナライゼーションのためのより充実したユーザープロファイルを構築できます。詳細については、[Computed Traits - 概要](/ja/user-guide/data/computed-traits/computed-traits-overview)を参照してください。 |
| Connected Apps | MoEngage Connected Appsは、さまざまなデータソースやチャネルを統合するためのローコードプラットフォームを提供します。このプラットフォームにより、マーケターやパートナーはマーケティングテクノロジースタックを接続し、リアルタイムでデータを交換し、ソースやプラットフォームをまたいでパーソナライズされた顧客とのインタラクションを作成できます。Connected Appsを使用すると、任意のアプリをMoEngageに接続し、MoEngageからユーザー、イベント、セグメントを自社のアプリに送信できます。詳細については、[概要](/ja/user-guide/campaigns-and-channels/connected-apps/getting-started-with-connected-apps/overview)を参照してください。 |
| Connectors | Connectorsを使用すると、MoEngageを外部システムに接続して、自社またはサードパーティの他のプラットフォームにリアルタイムデータをプッシュしたり、そこからデータを取得したりできます。Connectorキャンペーンは、MoEngageからリアルタイムデータを取得したり、他の分析システムにデータを渡したりできるため、すべてのコミュニケーションチャネルでユーザーをターゲティングするのに役立ちます。詳細については、[Connectorキャンペーンの作成](/ja/user-guide/campaigns-and-channels/connectors/create/create-a-connector-campaign)を参照してください。 |
| Content APIs | Content APIは、MoEngageキャンペーンで動的データを使用するために設定する外部APIです。Settings > Advanced SettingsでAPI名、HTTPメソッド、その他の詳細を追加して設定し、ユーザー属性を使用してパラメータをパーソナライズできます。詳細については、[Content APIの追加](/ja/user-guide/settings/advanced-settings/add-a-content-api)を参照してください。 |
| Content Blocks | Content Blocksは、ヘッダー、フッター、CTAボタンなど、複数のキャンペーンやチャネルで使用できる再利用可能なコンテンツです。Content Blockを編集すると、使用されているすべての場所に変更が適用されるため、一貫性を維持し、大規模に更新できます。詳細については、[Content Blocks](/ja/user-guide/content/content-blocks/content-blocks)を参照してください。 |
| Control Group | コントロールグループは、キャンペーンでターゲティングするユーザーのうち、キャンペーンのコミュニケーションを受け取らないサブセットであり、比較のためのベースラインとして機能します。このグループを、コミュニケーションを受け取るターゲットグループと合わせて測定することで、マーケティング施策の真の影響と効果を判断できます。詳細については、[コントロールグループ](/ja/user-guide/campaigns-and-channels/getting-started/introduction/control-groups)を参照してください。 |
| Conversion Goals / Conversion Attribution | FlowsのMultiple Conversion Goalsを使用すると、実行されたときにフローの成功を示すユーザーイベントを最大5つトラッキングでき、いずれかのゴールから得られた収益もトラッキングできます。「Purchase」に向けたステップとして「Add to cart」をトラッキングするなど、ユーザーが主要なコンバージョンゴールに向けて行う中間ステップをトラッキングするために使用できます。詳細については、[複数のコンバージョンゴールの追加](/ja/user-guide/flows-cross-channel-messaging/create/actions-in-flows/add-multiple-conversion-goals)を参照してください。 |
| Coupons | MoEngage Couponsを使用すると、対象ユーザーに使い切りクーポンを割り当てて配布できます。使い切りクーポンコードは個々の顧客に配布される一意のコードであり、2人のユーザーが同じクーポンを受け取ることはなく、各クーポンは1回のみ使用できます。アクティベーションのための新規ユーザー、再活性化のための非アクティブユーザー、購入を放棄したユーザーなど、特定のコホートにクーポンを送信できます。詳細については、[概要](/ja/user-guide/content/coupons/overview)を参照してください。 |
| Custom Dashboards | カスタムダッシュボードを使用すると、製品やマーケティングのニーズに合わせたカスタム分析グラフやレポートを追加できます。ダッシュボードに複数のグラフやレポートを追加し、同時にモニタリングできます。カスタムダッシュボードは、プライベートダッシュボードまたはワークスペースダッシュボードとして作成できます。詳細については、[カスタムダッシュボード](/ja/user-guide/analyze/dashboards/custom-dashboards)を参照してください。 |
| Custom Segments | カスタムセグメントを使用すると、キャンペーン、フロー、分析ごとに同じクエリを作り直す代わりに、ユーザーセグメントクエリに名前を付けて保存し、MoEngageダッシュボードの複数のページで再利用できます。詳細については、[カスタムセグメント](/ja/user-guide/segment/new-ui-experience/custom-segments)を参照してください。 |
| Data Archival (Retention) Policy | データアーカイブは、非アクティブまたは休眠状態のユーザーデータを体系的に削除するプロセスであり、ワークスペースが真のエンゲージメント機会とビジネス価値をもたらすユーザーのみに集中できるようにします。MoEngageはこれを利用して、プラットフォームのパフォーマンスとデータの健全性を、GDPRやCCPAなどの世界的なプライバシー基準と両立させています。MoEngageは14日ごとに、非アクティブで到達不能なユーザー、イベント、デバイスを削除するプロセスを実行し、各エンティティには独自のアーカイブポリシーがあります。アーカイブされると、データポイントは完全に削除されます。詳細については、[データアーカイブ（保持）ポリシー](/ja/user-guide/data/key-concepts/data-archival-retention-policy)を参照してください。 |
| Data Centers | MoEngageは世界中に複数のデータセンターを保有しており、サインアップ時にアカウントは特定のデータセンターに属します。データセンターによって、ダッシュボードのアクセスURL、SDKエンドポイント、REST APIエンドポイントが決まります。サインアップ後、ダッシュボードのURLからデータセンターを確認できます。詳細については、[MoEngageのデータセンター](/ja/user-guide/data/key-concepts/data-centers-in-moengage)を参照してください。 |
| Decision Policy | Decision Policyは、ユーザーまたはユーザーセグメントに表示する最も関連性の高いオファリングを選択してランク付けするルールベースのエンジンです。オファリングをグループ化し、定義されたランキング戦略を適用することで、ポリシーは大量のオファリングの中から少数の最適なものだけを提示します。返すオファリングの数、選択対象のオファリングプール、選択戦略、主要なオファリングの対象とならないユーザー向けのフォールバックオファリングを定義します。詳細については、[Decision Policyの作成](/ja/user-guide/decisioning/offer-decisioning/decision-policy)を参照してください。 |
| Derived Events | 派生イベントは、派生属性とともにMoEngageがデフォルトで生成するイベントです。セグメンテーションや分析でフィルターとして使用し、ユーザーをセグメント化できます。MoEngageは、ライフサイクル、獲得、アンインストール、リーチャビリティ、キャンペーンアクティビティなどのカテゴリに分類しています。詳細については、[派生イベントと属性](/ja/user-guide/data/event-data/derived-events-and-attributes)を参照してください。 |
| Derived User Attributes | 派生ユーザー属性は、ライフサイクルステージやライフタイムバリュー（LTV）など、MoEngageがデフォルトで生成するユーザー属性です。セグメンテーションや分析でフィルターとして使用し、ユーザーをセグメント化できます。ワークスペースでPortfolioが有効になっている場合、派生ユーザー属性の動作が変わります。詳細については、[派生ユーザー属性](/ja/user-guide/data/user-data/derived-user-attributes)を参照してください。 |
| Do Not Disturb (DND) | Do Not Disturb（DND）を使用すると、トリガー通知をユーザーに送信しないアイドル時間を設定できます。これにより、Push、Email、SMS、MMS、RCSのメッセージが不適切な時間帯にユーザーに届くのを防ぎます。詳細については、[Do Not Disturb](/ja/user-guide/settings/channels/delivery-controls/do-not-disturb)を参照してください。 |
| Dynamic Sender Routing | Dynamic Sender Routingは、APIリクエストごとに最適な送信者を自動的に選択するMoEngage Informのルーティングシステムです。ユーザー属性またはAPI属性に基づいてカスタムルーティングルールを定義し、到達率の向上、送信コストの管理、各地域のコンプライアンス要件への対応を実現します。SMSチャネルとEmailチャネルでサポートされています。詳細については、[Dynamic Sender Routing](/ja/user-guide/inform/advanced-concepts/dynamic-sender-routing)を参照してください。 |
| Dynamic Template Selector | Dynamic Template Selectorは、MoEngage InformのRule-Based Templatesを通じて利用でき、重複するアラートを複数作成する代わりに、1つのアラートで適切なメッセージバリアントを配信できます。テンプレートのバリエーションは、ランダムな割合による分割や最適化ルールではなく、ユーザー属性またはAPI属性に基づいてリアルタイムで選択されます。詳細については、[Dynamic Template Selector](/ja/user-guide/inform/advanced-concepts/dynamic-template-selector)を参照してください。 |
| Engagement Channels | チャネルとは、スマートフォンへのプッシュ通知や受信トレイへのメールなど、ユーザーにメッセージを配信するために使用する方法です。MoEngageはモバイル、Web、メッセージング、広告プラットフォームにわたるさまざまなチャネルをサポートしているため、さまざまなタッチポイントでオーディエンスとエンゲージできます。適切なチャネルを選択することで、関連性の高いコンテンツを配信し、キャンペーンの目標を達成できます。詳細については、[MoEngageのチャネル](/ja/user-guide/campaigns-and-channels/getting-started/introduction/moengage-channels)を参照してください。 |
