ここでは、静的および動的な多変量テストに関するよくある質問をまとめています。

**Q. 多変量テストとは何ですか?**

A. 多変量テストとは、メッセージバリエーションのパフォーマンスを比較するために、ランダムに選ばれた異なるユーザーに、コミュニケーションの 3 つ以上のバリエーションを送信することを指します。

**Q. ユーザーはバリエーション間でどのように配分されますか?**\
A. オーディエンスは複数に分割され、各オーディエンスはメールのいずれか 1 つのバリエーションを受け取ります。

- 手動 A/B テストでは、配分はユーザーが定義し、キャンペーン期間中は固定されたままです。この配分は、手動で編集しない限り変更されません。この方法では、分析はキャンペーンの終了時に提示され、今後のキャンペーンで使用する、よりパフォーマンスの高いバリエーションを決定するのに役立ちます。
- 動的 A/B テストでは、キャンペーンの開始時にユーザーがバリエーション間で均等に配分されます。この方法では、キャンペーンの実行中に各バリエーションのパフォーマンスに基づいて、配分と分析が継続的に行われます。

**Q. メッセージバリエーションは固定されますか? たとえば、ユーザーが 1 日目に定期キャンペーンのバリエーション 1 を受け取り、その後の任意の日に同じキャンペーンを再び受け取る資格がある場合、そのユーザーはバリエーション 1 のみを受け取りますか?**

A/B テスト機能では、バリエーションは固定されません。定期インスタンスの実行がスケジュールされるたびに、対象となるすべてのユーザーを取得し、メッセージバリエーション間でランダムに分割します。そのため、ユーザーがバリエーション 1 を受け取るとは限りません。

同様に、ユーザーがすでに受け取ったアクティブなキャンペーンを再び受け取る資格を得た場合も、同じシナリオが繰り返されます。

**Q. コントロールグループとは何ですか?**\
A. コントロールグループとは、特定のキャンペーンでターゲットにしている顧客の**サブセット**であり、**キャンペーンを受け取らない**ため、キャンペーンのパフォーマンスを比較するためのベースラインとして機能します。

**Q. キャンペーンのアップリフトはどのように測定しますか?**\
A. キャンペーンのアップリフトは、メッセージバリエーションがコンバージョン目標の達成に与える影響を測定します。コントロールグループのパフォーマンスが、アップリフトを計算するためのベースラインとして機能します。詳細は[こちら](/ja/user-guide/campaigns-and-channels/getting-started/introduction/control-groups#uplift)で確認できます。

**Q. 一般プッシュキャンペーンの特定のバリエーションを受け取ったユーザーを特定するにはどうすればよいですか?**

A. MoEngage Dashboard \> Segment \> Create Segment に移動してセグメンテーションクエリを作成することで、これらのユーザーを検索できます。クエリは次のようになります。

has executed _Notification Received Android_ where _campaign id_ contains  _`<cid>`\_F\_T\_GP\_AB\_`<  VariationSerialNumber>`_

例: cid:57f112bc2b8dbc480b457ffe の場合

バリエーション 1 は次のキーで識別できます: 57f112bc2b8dbc480b457ffe\_F\_T\_  GP\_AB\_1

バリエーション 2 は次のキーで識別できます: 57f112bc2b8dbc480b457ffe\_F\_T\_  GP\_AB\_2

バリエーション 3 は次のキーで識別できます: 57f112bc2b8dbc480b457ffe\_F\_T\_  GP\_AB\_3

バリエーション 1 の最終的なクエリは次のようになります: has executed;  _Notification Received Android where campaign id contains 57f112bc2b8dbc480b457ffe\_F\_T\_  GP\_AB\_1_

**注:** 現在、コントロールグループのメンバーを特定することはできません。

**Q. 一般プッシュキャンペーンの特定のバリエーションをクリックしたユーザーを特定するにはどうすればよいですか?**

A. MoEngage Dashboard \> Segment \> Create Segment に移動してセグメンテーションクエリを作成することで、これらのユーザーを検索できます。クエリは次のようになります。

_has executed Notification Clicked Android where campaign id contains `<cid>`\_F\_T\_GP\_AB\_`<  VariationSerialNumber>`_

_OR_

_has executed Notification Clicked iOS where campaign id contains `<cid>`\_F\_T\_GP\_AB\_`<  VariationSerialNumber>`_

例: cid:57f112bc2b8dbc480b457ffe の場合

バリエーション 1 は次のキーで識別できます: 57f112bc2b8dbc480b457ffe\_F\_T\_  GP\_AB\_1

バリエーション 2 は次のキーで識別できます: 57f112bc2b8dbc480b457ffe\_F\_T\_  GP\_AB\_2

バリエーション 3 は次のキーで識別できます: 57f112bc2b8dbc480b457ffe\_F\_T\_  GP\_AB\_3

バリエーション 1 の最終的なクエリは次のようになります: has executed;  _Notification Clicked Android where campaign id contains 57f112bc2b8dbc480b457ffe\_F\_T\_  GP\_AB\_1_

**Q. 統計的アプローチは頻度主義とベイズ主義のどちらですか?** A. ベイズ検定を使用しています。ベイズ検定の結果はマーケターにとって理解しやすく、さらに**事前**学習を取り込むことで、時間の経過とともに結果が洗練されるためです。[ベイズ検定の入門はこちら](/ja/user-guide/ai-and-intelligence/ab-testing/what-is-ab-or-multivariate-testing/manual-multivariate-experiment)でご覧いただけます。
