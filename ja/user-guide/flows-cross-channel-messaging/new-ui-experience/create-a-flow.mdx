# 概要

MoEngage Flows は、アプリやウェブサイトでの顧客のアクションまたは非アクションに基づいて顧客に送信される、一連のクロスチャネル（メール、プッシュ、SMS などのチャネルにまたがる）ライフサイクルキャンペーンです。

<Tip>
チャネル設定が構成されていることを確認してください。
</Tip>

Flow を作成するには、次の手順を実行します。

1. MoEngage のサイドバーメニューで、Engage メニュー項目 <img alt="Screenshot 2025-06-04 at 4.32.53 PM.png"  src="/images/moengage_b20f76.png"  /> にカーソルを合わせます。**Engage** メニューが表示されます。
2. **+ New Flow** をクリックします。  
    <img  src="/images/moengage_71c22d.png"  />   
   **Engage** メニューで **All Flows** をクリックし、Flows ページで **+ Create flow** をクリックすることもできます。Create new flow ページが表示されます。
3. **Create new flow** ダイアログボックスで、**+ Start with a blank canvas** をクリックします。  
    <img src="/images/moengage_e4922c.png" />   
   Create flow ページが表示されます。  
    <img src="/images/moengage_8f9896.png" />
4. 表示されるポップアップから、次のいずれかのオプションを使用して Flow を作成します。
   - [Flow テンプレートを使用する](/ja/user-guide/flows-cross-channel-messaging/create/create-flows/create-a-flow)または
   - [ゼロから作成する](/ja/user-guide/flows-cross-channel-messaging/create/create-flows/create-a-flow)

# オプション 1: Flow テンプレートを使用して Flow を作成する

Flow テンプレートは、オンボーディング、インセンティブ付与、エンゲージメントといった目標に基づいて Flow を作成するためのヒントを提供します。カート放棄のリマインダー送信、離脱リスクのある顧客へのアプローチ、アプリ/ウェブサイトのエンゲージメント向上のために、単一チャネルまたは複数チャネルの Flow を作成できます。各種 Flow テンプレートについて以下で説明します。

## テンプレートの種類

基本的なテンプレートの種類は 2 つあります。

- **Adoption**: Adoption テンプレートは新規顧客のオンボーディングに使用でき、単一チャネル用と複数チャネル用があります。
- **Engagement**: Engagement テンプレートは、単一チャネル、複数チャネル、またはウェブやアプリなどの特定のチャネル向けに用意されています。アプリやウェブサイトのエンゲージメント向上、特定のオファリングを閲覧した顧客や特定の商品をカートに追加して放棄した顧客へのエンゲージメント、離脱リスクのある顧客へのアプローチに使用できます。

Flow を作成する際に、次のいずれかのテンプレートを選択できます。

| テンプレートの種類 | テンプレート名 | 説明 |
| --- | --- | --- |
| Adoption | Onboard Customers - Single Channel | このテンプレートを使用して、新規顧客を歓迎し、製品やサービスでのジャーニーをガイドします。このテンプレートでは、オンボーディング段階の顧客とのコミュニケーションに単一のチャネルを使用し、オンボーディング後に最初の購入を促します。 |
| Adoption | Onboard Customers - Multi-Channel | このテンプレートを使用して、新規顧客を歓迎し、複数のチャネルで顧客とコミュニケーションを取ります。A/B テストを活用して新規ユーザーとのコミュニケーションに最適なチャネルを特定できます（この情報は他のオンボーディング Flow にも活用できます）。また、このテンプレートではロケールと条件分岐を使用してユーザーの現地言語を特定し、その言語でコミュニケーションを取ります。 |
| Engagement | Abandoned Cart Reminder - Single Channel | このテンプレートを使用して、カートに商品を追加したもののまだ購入していないユーザーにリマインダーを送信します。このテンプレートでは Wait For/Till Node 要素を使用して一定の遅延後に通知を送信し（ユーザーがカートに商品を追加してから一定の時間間隔が経過した後にのみ通知が送信されます）、コミュニケーションを送信する前に、設定した間隔の経過後にユーザーがカートを放棄したか購入したかを確認します。このテンプレートでは単一のチャネルでコミュニケーションを行います。 |
| Engagement | Abandoned Cart Reminder - Multi Channel | このテンプレートを使用して、カートを放棄したユーザーに複数のチャネルを活用して購入を促します。 |
| Engagement | Browse Abandonment - Multi-Channel | このテンプレートを使用して、商品を閲覧したり特定の商品カテゴリを検索したりしたものの、まだ購入していない顧客にエンゲージします。このテンプレートはコンテキストに応じたコミュニケーションの送信に役立ち、Intelligent Path Optimization（IPO）を活用して、Merlin AI によりユーザーを最もパフォーマンスの高いパスに自動的かつインテリジェントに振り分けることができます。 |
| Engagement | Customer Reactivation - Multi-channel | このテンプレートを使用して、長期間プラットフォームでアクティブでない顧客にエンゲージします。このテンプレートは、厳選したオファーの送信や休眠顧客とのコミュニケーションに役立ちます。このテンプレートでは Next Best Action（NBA）が使用されるため、各顧客が最もエンゲージする可能性の高いチャネルとタイミングでコミュニケーションが送信されます。 |
| Engagement | Periodic Customer Reactivation - Multi-channel | このテンプレートを使用して、休眠顧客に定期的に（10 日ごとに）エンゲージします。このテンプレートは NBA を活用して、各顧客の好みのチャネルで、そのチャネルで最もエンゲージする可能性の高いタイミングでコミュニケーションを取ります。 |
| Engagement | Engage customers on App | このテンプレートを使用して、数日間アプリを利用していない顧客に NBA を使用してエンゲージします。このテンプレートでは、顧客がアプリを開いた際にアプリ内キャンペーンとカードキャンペーンを使用して購入を促します。 |
| Engagement | Engage customers on Web | このテンプレートを使用して、数日間アプリを利用していない顧客に NBA を使用してエンゲージします。このテンプレートでは、顧客がアプリを開いた際に Web Push、On-site messaging、Cards、Google Ads を組み合わせて購入を促します。 |

テンプレートの種類がわかったら、それを使用して Flow を作成できます。

<Info>
- Flow テンプレートを編集して、必要に応じてイベントチェックを追加したり、キャンペーンのコンテンツを編集したりできます。
- 必要に応じて、テンプレートにステージを追加または削除できます。
</Info>

## テンプレートを使用する

1. Flow テンプレートを選択し、**Use template** をクリックします。
2. Flow のエントリー条件を追加し、ターゲットオーディエンスとコンバージョン目標（ある場合）を定義します。
3. テンプレート内のキャンペーンを確認し、必要に応じて変更します。
4. ビジネスのユースケースに応じて、必要であれば新しいステージやパスを追加します。
5. Flow の構造が完成したら、**Save** をクリックして下書きとして保存できます。Flow を公開するための次のアクションは、アカウントの設定によって異なります。
   - - Campaign Approval ワークフローが無効になっている場合は、Flow を直接公開できます。
     - Campaign Approval ワークフローが有効で、キャンペーンの作成、管理、公開の権限がある場合は、Flow を直接公開できます。
     - Campaign Approval ワークフローが有効で、**Create & Manage** 権限のみがある場合は、Flow を承認に提出する必要があります。詳細については、[こちら](/ja/user-guide/flows-cross-channel-messaging/create/create-flows/create-a-flow)を参照してください。

<img alt="Flow templates.gif" src="/images/moengage_d4a770.png" />

# オプション 2: ゼロから Flow を作成する

空白のキャンバスから始めて、任意の Flow を構築できます。ゼロから Flow を作成する手順は次のとおりです。

1. [詳細と目標](/ja/user-guide/flows-cross-channel-messaging/create/create-flows/create-a-flow): Flow の目標を定義し、必要な詳細を追加します。
2. [ユーザーが Flow に入るタイミング](/ja/user-guide/flows-cross-channel-messaging/create/create-flows/create-a-flow): ユーザーが Flow に入るタイミングを定義します。
3. [Flow に入るユーザー](/ja/user-guide/flows-cross-channel-messaging/create/create-flows/create-a-flow): Flow のオーディエンスを定義します。

<Info>
Flow 作成中はどのステップからでも直接キャンバスに移動できます。**Skip to Canvas** をクリックすると MoEngage キャンバスが開きます。
</Info>

## 詳細と目標

**+ Start with a blank canvas** をクリックすると、Create flow ページが表示されます。このセクションには次の内容が含まれます。

### Flow の詳細

Flow の詳細セクションには、次のフィールドがあります。

|  |  |
| --- | --- |
| - - **Team:** 組織で **Team** が有効になっている場合は、**Team** リストで Flow に関連付けるチームを選択します。詳細については、[MoEngage のチーム](/ja/user-guide/settings/account/team-management/teams-in-moengage)を参照してください。   - **Flow name**: Flow を管理および識別するための Flow 名を入力します。Flow 名は 5 文字以上で、上限は 256 文字です。Flow 名には特殊文字を使用できます。   - **Flow tags**: ドロップダウンリストから Flow タグを選択して、タグを明確にします。最大 5 つのタグを選択できます。詳細については、[MoEngage のタグ](/ja/user-guide/campaigns-and-channels/getting-started/introduction/campaign-tags)を参照してください。 | <img  src="/images/moengage_7e1d49.png"  /> |

### コンバージョン目標

Flow のコンバージョンを追跡するためのコンバージョンを定義します。Flow に設定されたコンバージョン目標は、Flow に含まれるすべてのキャンペーンのコンバージョン目標として扱われます。

<Info>
- 1 つの Flow に 5 つのコンバージョン目標を追加できます。詳細については、[Flow に複数の目標を追加する](/ja/user-guide/flows-cross-channel-messaging/create/actions-in-flows/add-multiple-conversion-goals)を参照してください。
- 目標を設定せずに Flow を公開することもできます。
</Info>

次の項目を選択して目標を定義します。

| フィールド | 説明 |
| --- | --- |
| Goal name | 目標を管理および識別するための目標名を入力します。 |
| Event name | 目標の追跡の基準となる定義済みのイベントをドロップダウンから選択します。  詳細については、[イベントと属性](/ja/user-guide/data/event-data/derived-events-and-attributes)を参照してください。 |
| Attribute | 追跡する目標をフィルタリングまたはドリルダウンするための定義済みの属性、条件、値をドロップダウンから選択します。  詳細については、[イベントと属性](/ja/user-guide/data/event-data/derived-events-and-attributes)を参照してください。 |
| Track above goal for | アトリビューションウィンドウを設定します。これは、アトリビューションタイプに基づいて、インプレッションまたはクリック後にコンバージョン目標が追跡される期間です。  <img alt="Attribution" src="/images/moengage_14477b.png" /> |
| Exit on conversion | このトグルをオンにすると、ユーザーがプライマリコンバージョン目標でコンバージョンした時点で、Flow から強制的に退出させます。  <img alt="ExitOnConversion.png" src="/images/moengage_e582a9.png" /> |

**+ New goal** をクリックして目標を追加します。

<Info>
Flow を公開する前であれば、**Settings** をクリックして、目標、タグ、コンバージョン時のユーザー退出の設定をいつでも変更できます。詳細については、[Flow の設定](/ja/user-guide/flows-cross-channel-messaging/create/configure-flows/flow-settings)を参照してください。

<img alt="Screenshot_2022-07-31_at_1.40.29_AM.png" src="/images/moengage_4006f4.png" />
</Info>

**Next** をクリックして、[ユーザーが Flow に入るタイミング](#when-will-users-enter-the-flow)のステップに移動します。

## ユーザーが Flow に入るタイミング

次のいずれかを選択して、ユーザーが Flow に入るタイミングを定義します。

On Event TriggerAt fixed time On flow exit On business event trigger

トリガー条件を定義するには、次の操作を行います。

- **If user** セクションで、  
  1. **Primary trigger event (s)** の **Has Executed** フィールドで、リストから **Select an event** を選択し、ユーザーが Flow に入るためのプライマリトリガーイベントを定義します。
  2. **+ Add alternate trigger event** をクリックして、**Primary trigger event(s)** に複数のイベントを追加します。これにより、ユーザーはプライマリトリガーイベントで定義されたいずれかのイベントを実行した場合に Flow に入ることができます。（任意）
  3. **+ Attributes** をクリックして、追加したプライマリトリガーに属性を追加します。（任意） <img alt="bau 1.png" src="/images/moengage_934489.png" />

セカンダリトリガー条件を定義するには、次の操作を行います。

- **AND** セクションで、
  1. **+ Add secondary trigger event** をクリックします。
  2. **Secondary trigger event(s)** で、要件に応じて **Has Executed** または **Has Not Executed** を選択し、**Select an event** リストからイベントを選択して、ユーザーが Flow に入るためのプライマリトリガーイベントとあわせてセカンダリトリガーイベントを定義します。
  3. **+ Add more trigger event** をクリックして、**Secondary** **trigger event(s)** に複数のイベントを追加します。（任意）
  4. **+ Attributes** をクリックして、追加したセカンダリトリガーに属性を追加します。（任意）  
     ユーザーの過去のアクションに基づいて、パーソナライズされた動的なチェックを追加できます。詳細については、[Linked Conditions](/ja/user-guide/flows-cross-channel-messaging/create/create-flows/linked-conditions)を参照してください。  
      <img alt="bau123.png" src="/images/moengage_56558b.png" />

- **THEN enter the user** セクションで、

1. 1. 1. **Immediately** を選択すると、ユーザーは直ちに Flow に入ります。  
         これは、Flow にプライマリトリガーが定義されている場合にのみ適用されます。
      2. **With Delay** を選択し、次の詳細を指定すると、ユーザーは遅延した時間間隔で Flow に入ります。
         1. 時間の値を入力し、分、時間、または日を選択します。入力できる値は 5 分から 30 日まで（両端を含む）です。
         2. **Before** または **After** を選択して、指定した時間間隔の前または後のどちらでユーザーが Flow に入るかを指定します。  
            <Info>
            複数のプライマリトリガーイベントを追加した場合、時間間隔の指定には **After** オプションのみ使用できます。ただし、プライマリトリガーイベントを 1 つだけ追加した場合は、**Before** と **After** の両方のオプションを使用して遅延をパーソナライズできます。
            </Info>
         3. この時間計算の基準となる属性を選択します。詳細については、[こちら](/ja/user-guide/campaigns-and-channels/getting-started/triggers/event/create-an-event-triggered-campaign)をクリックしてください。  
             <img alt="bau1234.png" src="/images/moengage_8f3058.png" />

**Flow のスケジュール設定**

**Start** で、Flow をトリガーするための次のいずれかのオプションを選択します。

| フィールド | アクション |
| --- | --- |
| **As soon as possible** | Flow を直ちにトリガーします。次の項目を選択できます。   - **Campaign time zone** - キャンペーンを送信するタイムゾーン。 - **Ends**: End オプションを選択して Flow の終了時刻を選択し、Flow への新規エントリーを停止するタイミングを制御できます。次のオプションを使用できます。   - **Never**: Flow は終了しません。   - **On**: **End date** フィールドと **End time** フィールドで指定した終了日に Flow が終了します。 |
| **At specific date and time** | 指定した時刻、タイムゾーン、または予測時刻に Flow をトリガーします。  このセクションでは、特定の日時にキャンペーンを送信できます。次のフィールドがあります。   - **Campaign time zone** - キャンペーンを送信するタイムゾーン。 - **Start date** - キャンペーンを送信する日付。 - **Send time** - キャンペーンを送信する時刻。キャンペーンを送信する時間帯に応じて am または pm を選択します。 - **Ends**: End オプションを選択して Flow の終了時刻を選択し、Flow への新規エントリーを停止するタイミングを制御できます。次のオプションを使用できます。   - **Never**: Flow は終了しません。   - **On**: **End date** フィールドと **End time** フィールドで指定した終了日に Flow が終了します。 |

Flow を固定時刻にスケジュールするには、次の操作を行います。

**User entry** で、Flow をトリガーするための次のいずれかのオプションを選択します。

| フィールド | アクション |
| --- | --- |
| **As soon as possible** | このオプションを選択すると、ユーザーはできるだけ早く 1 回限りで Flow に入ります。  <img alt="CreateFlows_OneTime_ASAP.png"  src="/images/moengage_49e127.png"  /> |
| **At specific date and time** | 次の手順に従って、ユーザーが指定した日時に 1 回限りで Flow に入るようにします。   1. タイムゾーンを選択します。 2. カレンダーから日付を選択します。 <img alt="CreateFlows_At_Specified_Date_and_Time.png" src="/images/moengage_ebebd5.png" /> 3. 時刻を入力するか、上下の矢印を使用して設定します。 4. am または pm をクリックします。 |
| **Daily** | 次の手順に従って、指定した日時から毎日の頻度でユーザーが Flow に入るようにします。  <img alt="Flow Daily.png" src="/images/moengage_ad8bcb.png" />   1. タイムゾーンを選択します。 2. カレンダーから開始日を選択します。 3. 開始時刻（時と分）を入力するか、上下の矢印を使用して設定します。 4. am または pm をクリックします。 5. **Repeat Every** を使用して、ユーザーが Flow に入ることができる日の頻度を選択します。 6. 次のいずれかを実行して、システムが Flow への新規エントリーを停止する終了日時を定義します。    1. **Never** をクリックすると、ユーザーは常に Flow に入ることができます。    2. **On** をクリックし、カレンダーから終了日を選択します。**注**: 終了日が開始日より後であることを確認してください。    3. **After** をクリックし、キャンペーンが終了するまでの発生回数を選択します。 |
| **Weekly** | 次の手順に従って、指定した日時から毎週の頻度でユーザーが Flow に入るようにします。  <img alt="Flow Weekly.png" src="/images/moengage_d6dd08.png" />   1. タイムゾーンを選択します。 2. カレンダーから開始日を選択します。 3. 開始時刻（時と分）を入力するか、上下の矢印を使用して設定します。 4. am または pm をクリックします。 5. **Repeat every** オプションと **Repeat on** オプションを使用して、ユーザーが Flow に入ることができる頻度を選択します。    1. **Repeat** **on** で、ユーザーが毎週 Flow に入ることができる曜日を選択し、    2. **Repeat every** で、Flow がユーザーのエントリーを許可する週単位の頻度を選択します。たとえば、'Repeat on' セクションで月曜日と金曜日を選択し、'Repeat every' セクションで 3 を選択すると、キャンペーンは 3 週間に 1 回、その週の月曜日と金曜日に送信されます。 6. 次のいずれかを実行して、システムが Flow への新規エントリーを停止する終了日時を定義します。    1. **Never** をクリックすると、ユーザーは常に Flow に入ることができます。    2. **On** をクリックし、カレンダーから終了日を選択します。**注**: 終了日が開始日より後であることを確認してください。    3. **After** をクリックし、キャンペーンが終了するまでの発生回数を選択します。 |

### グローバル退出条件

**Flow Exit** で **Exit based on conditions** トグルをオンにして、Flow の退出条件を定義します。ユーザーが定義された条件を満たすと、MoEngage はユーザーが Flow のどこにいるかにかかわらず、最後に確認された位置からユーザーを削除します。退出条件はすべての Flow タイプ（例: **On event trigger**、**At fixed time**、**On flow exit**、**On business event trigger**）に適用されます。

<img alt="Screenshot 2024-07-29 at 3.35.49 PM.png" src="/images/moengage_1254d9.png" />

MoEngage は、ユーザーが Flow に入った時点から、次のような理由で Flow から退出する時点まで、これらの条件でユーザーを評価します。

- Flow パス内の退出ステージを通過した
- 退出条件の条件を満たした
- Flow で定義されたコンバージョン目標を達成した

退出条件は、ユーザーがトリガーしたイベント、またはユーザーについて追跡しているユーザープロパティを使用して定義できます。

<img alt="Screenshot 2024-07-29 at 3.35.49 PM.png" src="/images/moengage_416bb8.png" />

- **User property**: **User property** タブでは、特定の属性の値を指定することで、ユーザープロパティを使用して退出条件を定義できます。例:
  - メンバーシップが Gold になったらユーザーを削除する（Flow の目的がユーザーを Gold メンバーシップにコンバージョンさせることに固定されている場合に使用できます）。
- **User behavior**: **User behavior** タブでは、MoEngage で追跡されているイベントのリストを使用して退出条件を定義できます。例:
  - Flow に入った後に何らかの商品を購入したらユーザーを削除する
  - Flow に入った後に、カートに追加したのと同じ商品を購入したらユーザーを削除する
    - このようなユースケースは、プライマリトリガーイベントと退出条件をリンクすることで実現できます。詳細については、[Linked Conditions](/ja/user-guide/flows-cross-channel-messaging/create/create-flows/linked-conditions)を参照してください。
  - 在庫が復活した同じ商品を購入したらユーザーを削除する。

#### サポートされているフィルター

退出条件は、文字列、整数、ブール値のデータ型の条件のみを使用して定義できます。

<Warning>
MoEngage は、次のフィルターで定義された条件をサポートしていません。

- カスタムセグメント
- アフィニティセグメント
- 配列型と GeoPoint
- 特殊な日付フィルター（Daily where the hour、Weekly where the day、Monthly where the day、Yearly where the month、Yearly where the date）
- 過去 n 週間、時間、か月
- n が 30 日以上の過去 n 日間
- Merlin AI ベースの属性

サポートされていないフィルターを使用すると、エラーメッセージが表示されます。問題を解決するには、サポートされているフィルターを選択する必要があります。

<img alt="Screenshot 2024-07-29 at 3.43.22 PM.png" src="/images/moengage_8eea4c.png" />
</Warning>

**+ Add exit condition** をクリックして条件を追加します。条件は最大 5 つまでです。各条件は他の条件と OR ロジックで評価されます。ユーザーがこれらの条件のいずれかを（順序を問わず）満たすと、Flow から退出します。たとえば、ユーザーが最初に Condition 3 を満たした場合、Condition 1 を満たしていなくても Flow から退出します。

<img alt="Screenshot 2024-07-29 at 3.41.39 PM.png" src="/images/moengage_370e41.png" />

各条件内にサブ条件を追加できます。**+ Filter** をクリックして条件を追加します。サブ条件は最大 5 つまで追加できます。各サブ条件は他のサブ条件と AND ロジックで評価されます。ユーザーがすべての条件を満たした場合にのみ、Flow から退出します。

<img alt="Screenshot 2024-07-29 at 3.43.16 PM.png" src="/images/moengage_898389.png" />

<Info>
1 つの条件で複数のサブ条件を使用している場合、退出条件を満たすには、ユーザーが 30 日間以内にすべてのサブ条件を順序を問わず満たす必要があります。たとえば、Condition 1 に次のサブ条件を定義したとします。

- Has Executed App/Site Opened at least 1 time
- Last Seen Date is on July 25, 2024
- Last Known City is New York

<img alt="7.png" src="/images/moengage_ee46f8.png" />

ユーザーが 2024 年 8 月 1 日に最初の 2 つの条件を満たしても、直ちに Flow から退出するわけではありません。MoEngage は、最後の条件が満たされるまで 8 月 1 日から 30 日間待機します。8 月 31 日より前に満たされた場合、ユーザーは Flow から退出します。9 月 2 日に満たされた場合、最初の 2 つの条件が 30 日間のウィンドウ外となるため、ユーザーは Flow から退出しません。
</Info>

退出条件は Flow の公開後でも編集できます。ただし、その場合 MoEngage は Flow の新しいバージョンを作成します。これは 1 回限りの Flow には適用されません。

## Flow に入るユーザー

Flow のターゲットオーディエンスまたはターゲットセグメントを選択します。複数のフィルターを使用してターゲットオーディエンスを作成できます。  
組織で Teams 2.0 を使用している場合、作成する新しいルールにはチームの元のターゲティング条件が自動的に追加されます。詳細については、[こちら](/ja/user-guide/settings/account/team-management/teams-20-in-moengage)を参照してください。  
 <img src="/images/moengage_162c15.png" />

次のオプションを使用できます。

All Users Filter by User Property Filter by User Behavior Filter by User Affinity Filter by Custom Segment

このフィルターオプションでは、すべてのアプリユーザーを選択できます。このオプションを使用する場合、複数のフィルターを追加することはできません。

<img alt="1.png"  src="/images/moengage_38de57.png"  />

このフィルターオプションでは、first seen、last seen、city などのユーザープロパティに基づいてユーザーを選択できます。**User property** タブをクリックし、次の操作を行います。

1. **Select attribute** リストで目的の属性を選択します。これにより、選択した属性に基づくフィルターが有効になります。
2. ドロップダウンリストで条件付きのフィルターを選択します。たとえば、文字列属性には 'is' や 'is not' などのフィルター条件があり、整数属性には異なるフィルターがあります。
3. デフォルトの **Constant value** を使用すると、特定の静的な値でフィルターを完成させることができます。以下に示すように、**User attribute**（すべてのタイプの Flow に適用可能）または **Business event attribute**（Business Event Triggered Flow のみ）オプションを使用すると、別のユーザー属性またはビジネスイベント属性を使用して条件を定義できます。  
   たとえば、新しい *Thriller* シリーズの開始を告知し、*Genre* として *Thriller* を好むユーザーをターゲットにする Flow を作成する場合は、次のスクリーンショットを参照してください。  
    <img alt="Screenshot 2024-12-19 at 3.53.15 PM.png" src="/images/moengage_da7d41.png" />

詳細については、[セグメントを作成する](/ja/user-guide/segment/create-segments/rule-based-filter-segments)を参照してください。

このフィルターオプションでは、'App/Site Opened'、'Viewed Product' などのユーザーの行動やイベントに基づいてユーザーを選択できます。**User Behavior** タブをクリックし、次の操作を行います。

1. ドロップダウンリストから **User Behaviour** を選択します。
2. **Select an event** リストでイベントを選択します。
3. イベントの頻度とイベント実行の期間を入力します。
4. **+ Attributes** をクリックし、**Select attribute** リストで目的の属性を選択します。これにより、選択した属性に基づくフィルターが有効になります。たとえば、文字列属性には 'is' や 'is not' などのフィルター条件があり、整数属性には異なるフィルターがあります。
5. デフォルトの **Constant value** を使用すると、特定の静的な値でフィルターを完成させることができます。以下に示すように、**User attribute**（すべてのタイプの Flow に適用可能）または **Business event attribute**（Business Event Triggered Flow のみ）オプションを使用すると、別のユーザー属性またはビジネスイベント属性を使用して条件を定義できます。たとえば、新しい *Thriller* シリーズの開始を告知し、過去 3 日間に *Genre* が *Thriller* のコンテンツを少なくとも 1 回視聴したユーザーをターゲットにする Flow を作成する場合は、次のスクリーンショットを参照してください。  
    <img alt="Screenshot 2024-12-19 at 5.09.21 PM (1).png" src="/images/moengage_228cbb.png" />   
   詳細については、[セグメントを作成する](/ja/user-guide/segment/create-segments/rule-based-filter-segments)を参照してください。

1. 目的のユーザーイベントまたは属性を選択します。
2. 次の中からユーザーアフィニティのパラメーターを選択します。
   - **Predominantly**: フィルター条件付きのアフィニティ属性を選択し、アフィニティの値を指定します。
   - **For a minimum of**: フィルター条件付きのアフィニティ属性を選択し、アフィニティの値を指定します。
   - **Most no. of times**: 値を入力するか矢印を使用して、上位のユーザーの割合を指定します。
   - **Least no. of times**: 値を入力するか矢印を使用して、下位のユーザーの割合を指定します。
3. 値を入力するか矢印を使用して、イベント実行の期間を指定します。
4. **+ Attributes** をクリックして、フィルターに属性を追加します。

詳細については、[セグメントを作成する](/ja/user-guide/segment/create-segments/rule-based-filter-segments)を参照してください。

詳細については、[カスタムセグメント](/ja/user-guide/segment/create-segments/manage-segments)を参照してください。

# Flow を設計して公開する

1. Flow の構造を設計するには、**+** をクリックして次の要素を Flow に追加します。  
   - [アクション](/ja/user-guide/flows-cross-channel-messaging/create/actions-in-flows/add-actions-to-flows)
   - [条件](/ja/user-guide/flows-cross-channel-messaging/create/conditions-and-controls-in-flows/branching-of-users-in-flows)
   - [コントロール](/ja/user-guide/flows-cross-channel-messaging/create/conditions-and-controls-in-flows/force-move-or-delay-users-in-flows)
2. Flow の構造が完成したら、**Save** をクリックして下書きとして保存します。Flow を公開するための次のアクションは、アカウントの設定によって異なります。  
   - - Campaign Approval ワークフローが無効になっている場合は、Flow を直接公開できます。
     - Campaign Approval ワークフローが有効で、キャンペーンの作成、管理、公開の権限がある場合は、Flow を直接公開できます。
     - Campaign Approval ワークフローが有効で、**Create & Manage** 権限のみがある場合は、Flow を承認に提出する必要があります。詳細については、[こちら](/ja/user-guide/flows-cross-channel-messaging/create/create-flows/create-a-flow)を参照してください。

## 承認フロー

Creator Reviewer

作成者として Flow を承認に送信するには、次の手順を実行します。

1. Flow キャンバスページで、右側にある **Actions** ボタンを選択します。
2. **Actions** リストで、**Send for Approval** を選択します。**Send for approval** ポップアップウィンドウが表示されます。  
   MoEngage は Flow 内の設定エラーを特定し、キャンバス右側の **Error** パネルに表示します。Flow を承認に送信する前に、表示されたすべてのエラーを解決する必要があります。  
    <img  src="/images/moengage_2cd4bf.png"  />
3. Flow をレビューして承認するユーザーを選択する必要があります。
   1. **Start typing to filter approvers** ボックスで、[詳細と目標](/ja/user-guide/flows-cross-channel-messaging/create/create-flows/create-a-flow)のステップで選択したチームのユーザー（Admin または Manager）を検索します。
   2. Flow をレビューしてもらいたい各ユーザーの名前の横にある **+ Add** をクリックします。選択したユーザーは右側の **Selected Approvers** セクションに表示されます。
4. **Add yours comment here (optional)** ボックスで、承認者向けのコンテキスト、指示、メモなどのコメントを追加できます。
5. **Send for approval** をクリックします。  
    <img  src="/images/moengage_be2a8f.png"  />
6. 選択した承認者には、Flow がレビュー待ちであることを知らせるメール通知が届きます。Flow が **Under Review** 状態の間、次のオプションを使用できます。  
   1. **Flow を編集する**: **Under Review** の Flow を編集できます。編集後、**Update and send for approval** をクリックして、Flow を再度レビューに送信する必要があります。その後、手順 3 ～ 5 を繰り返します。  
       <img  src="/images/moengage_9e9a7a.png"  />
   2. **承認者にフォローアップする**: フォローアップするには、**Remind Reviewers** をクリックします。承認者にリマインダー通知が届きます。  
        
       <img  src="/images/moengage_b9aa71.png"  />

Flow をレビューするには、次の手順を実行します。

1. MoEngage から受信したメールを開き、**Click to** **Review Flow** をクリックします。  
    <img  src="/images/moengage_1d3f68.png"  />   
   または  
   **All Flows** ページに移動します。**Select status** フィルターで **Under Review** チェックボックスを選択します。承認待ちの Flow のリストが表示されます。
2. 開く Flow をクリックします。  
    <img  src="/images/moengage_5c64b0.png"  />

すべてのステージの設定を確認して Flow をレビューする必要があります。レビューが完了し、Flow に修正が不要な場合は、次の手順を実行します。

1. 1. Flow キャンバスページで、右側にある **Approve and Publish** をクリックします。  
       <img  src="/images/moengage_cb7d26.png"  />   
      **Approve & publish** Flow ポップアップウィンドウが表示されます。
   2. **Add yours comment here** **(optional)** ボックスに、作成者向けのコメントを追加します。
   3. **Approve & publish** をクリックします。  
       <img  src="/images/moengage_7a3ef0.png"  />   
      公開後、Flow は Flow の種類（例: **On event trigger** または **At fixed time**）に応じて **Active** または **Scheduled** になります。作成者と他の承認者には、Flow が公開されたことを知らせるメール通知が届きます。

Flow に修正が必要な場合は、次の手順を実行する必要があります。

1. Flow キャンバスページで、右側にある **Actions** ボタンを選択します。
2. **Actions** リストで、**Reject** を選択します。  
    <img  src="/images/moengage_85c55e.png"  />   
   **Reject the flow** ポップアップウィンドウが表示されます。
3. **Add your comments here** ボックスに、作成者が編集を行う必要がある理由を説明するコメントを追加する必要があります。
4. **Reject flow** をクリックします。  
    <img  src="/images/moengage_1b00bd.png"  />   
   Flow を却下すると、作成者と他の承認者にあなたのコメントを含むメール通知が届きます。

<Info>
- Flow が却下された場合、作成者は承認者のコメントをメール通知と [Flow 監査ログ](/ja/user-guide/flows-cross-channel-messaging/create/create-flows/editing-a-flow)で確認できます。
- 要求された変更を行った後、承認プロセスに従って Flow を再提出できます。詳細については、[こちら](/ja/user-guide/flows-cross-channel-messaging/create/create-flows/create-a-flow)を参照してください。
</Info>
