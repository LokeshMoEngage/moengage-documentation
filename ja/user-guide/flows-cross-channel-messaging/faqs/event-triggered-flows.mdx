1. **ユーザーはどのように Event Trigger Flows にエントリーしますか？**

   MoEngage は、ユーザーが Trigger condition に記載された IF 条件に一致するたびに、そのユーザーがターゲットオーディエンスに属しているかどうかを確認します。ターゲットオーディエンスに含まれるユーザーは、Flow に記載されたその他の条件を満たす場合にのみ、それらの条件に基づく評価プロセスの次のステップに進みます。

   したがって、ユーザーはエントリー基準を満たす時点でターゲットオーディエンスのカテゴリに該当している必要があります。該当していない場合、フローにエントリーするには、ターゲットオーディエンスの一員になった後に同じ条件を満たす必要があります。

   さらに、ユーザーがフローに再エントリーできるのは、同じフローのアクティブなトリップに含まれておらず、フローに記載されたすべての条件を満たす場合のみです。エントリー回数の上限を設定して、ユーザーがフローにエントリーできる回数を制御することもできます。希望する上限は、Flow 作成プロセスの 2 番目のステップの **When users enter the flow** セクションで指定します。
2. **Event Triggered Flow では、ユーザーがターゲットオーディエンスに含まれているかどうかをいつ確認しますか？**

   MoEngage は、トリガーイベントが実行されたときに、ユーザーがターゲットオーディエンスに含まれているかどうかを確認します。したがって、ユーザーがフローにエントリーするには、トリガーイベントが実行される前にターゲットオーディエンスに含まれている必要があります。
3. **ユーザーがトリガーイベントを実行したのに、フローにエントリーしませんでした。なぜですか？**

   フローのターゲットオーディエンスがリアルタイムではない (定期) セグメントの場合、セグメントのメンバーシップはリアルタイムではなく、セグメントの最後にスケジュールされた更新時点で評価されます。更新と更新の間に条件を満たすようになったユーザーは、トリガーイベントが発生した時点ではまだターゲットオーディエンスに含まれていないため、その時点ではフローにエントリーしません。

   次回の更新でターゲットオーディエンスに含まれるようになっても、それだけではエントリーはトリガーされません。フローがエントリーをトリガーするには、更新後、ターゲットオーディエンスに含まれている間に、ユーザーがトリガーイベントを再度実行する必要があります。

   ユースケースで可能な場合は、ターゲットオーディエンスにリアルタイムセグメントを使用することで、この遅延を回避できます。ルールに定期的な評価が必要なセグメント (たとえば、過去 300 日間に基づく条件) はリアルタイムにできないため、そのような場合はこの遅延が想定されます。詳細については、[リアルタイムセグメント評価](/ja/user-guide/segment/advanced-concepts/real-time-segment-evaluation)を参照してください。
