# 概要

MoEngage Flows は、ユーザーのインタラクションを分析し、作成した Flow のパフォーマンスを把握するための直感的な方法を提供します。パフォーマンスはトリップ (Trip) を使用して表されます。トリップとは、基本的に一意のユーザージャーニーを表し、ユーザーが特定の条件を満たして Flow に入ったところから始まり、その過程でのキャンペーンとのインタラクションや発生しうるコンバージョンを含みます。

ユーザーのトリップデータの分析は、効果的なユーザーエンゲージメントと Flow のパフォーマンス最適化に不可欠です。Active Trips、Engaged Trips、Converted Trips、Drop-offs、Revenue などの指標により、ユーザーの行動とインタラクションに関する詳細なインサイトが得られます。また、Canvas ビューと Detailed Stats ビューを使用して、トリップデータを可視化してフィルタリングすることもできます。さらに、個々のチャネルやキャンペーンのパフォーマンス分析も可能になり、顧客エンゲージメント戦略の微調整に役立ちます。

<Note>
  - これは Early Access 機能です。アカウントで有効にするには、MoEngage の Customer Success Manager (CSM) またはサポートチームにお問い合わせください。
  - すべての指標は App Timezone で計算・表示されます。現在のアプリのタイムゾーンの値を確認するには、[Workspace Settings](/ja/user-guide/settings/account/general-settings/workspace-settings) を参照してください。
  - この機能は有効化後に作成された Flow にのみ適用されます。有効化前に作成された Flow では、引き続き GMT で統計が表示されます。
</Note>

# トリップを使用する理由

ユーザーの総エントリー数を追跡する方法もありますが、指標間の曖昧さを解消するには、ユニークユーザーエントリー数やユニークコンバージョン数などの補助的な指標を毎回追跡して報告する必要があります。

トリップは、ユーザーのライフタイム全体において、ユーザーが Flow に入る各インスタンスを一意に識別するため、Flow のパフォーマンスを分析するために追跡したいあらゆる指標に拡張できる、曖昧さのない概念を提供します。

## 指標の定義

すべての Flow で、次のトップレベルの指標を確認できます。

| 指標 | 説明 |
| --- | --- |
| **Trip Started** | 一定期間内に開始されたトリップの数。これは、ユーザーが Flow に入った回数です。 |
| **Active trips** | 全トリップのうち、まだ終了していないトリップの数、つまり現在 Flow 内にいるユーザーの数です。 |
| **Ended Trips** | すでに終了したトリップ。Trips Ended = Total Trips - Active Trips |
| **Engaged trips** | ユーザーがトリップ中にアクションキャンペーンを少なくとも 1 つ受信したトリップの数。Flow に帰属するコンバージョンにつながる可能性があるのは、エンゲージしたトリップのみです。トリップ中に、ユーザーが Flow から離脱する前に複数のキャンペーンを受信した場合でも、1 つのエンゲージしたトリップとしてカウントされます。<br />Flow のトリップにおいて、該当するチャネルについてユーザーから次のいずれかのイベントを受信すると、そのトリップはそのチャネルタイプに関してエンゲージしたトリップになります。<ul><li>Push: Notification Received Android または Notification Received iOS (iOS の配信トラッキングが利用できない場合は、notification sent iOS イベントを使用してエンゲージメントを追跡します)</li><li>Email: Email Opened</li><li>SMS: SMS Delivered (配信が追跡されない場合は SMS sent)</li><li>Connector: Connector Sent</li><li>In-App Messaging: Mobile In-App Shown</li><li>On-site Messaging: On-site Message Shown</li><li>Facebook: Facebook Audience Synced</li><li>WhatsApp: WhatApp Message Delivered</li><li>Cards: Card Campaign Viewed</li></ul> |
| **Converted trips** | トリップ期間中に少なくとも 1 回のコンバージョンにつながった、エンゲージしたトリップの数。<br />Flow の効果を測定するためにコントロールグループが設定されている場合は、コントロールグループのトリップのコンバージョンに対するアップリフトの割合が表示されます。<br />CVR の計算式は ((Converted Trips)/(Engaged Trips))\*100 です。 |
| **Total Conversions** | すべてのコンバージョンしたトリップから受信したコンバージョンの総数。<br />コンバージョンがどのように追跡され、Flow に帰属されるかの詳細については、[Flow におけるコンバージョンのトラッキングとアトリビューション](/ja/user-guide/flows-cross-channel-messaging/analyze-flows/conversion-attribution-in-flows)を参照してください。 |
| **Drop-offs** | 次の理由で終了したトリップの総数: <ul><li>フリークエンシーキャッピング (FC) の上限に達し、メッセージが送信されなかった場合にユーザーを Flow から削除する設定になっている場合。</li><li>Do Not Disturb (DND) によりメッセージが配信されず、メッセージが配信されなかった場合にユーザーを Flow から削除する設定になっている場合。</li><li>一時停止した Flow を再開した場合、またはユーザーが Wait For/till ステージに入った時点で、そのステージの待機期間がすでに終了していた場合。</li><li>User Merge の後、既知のユーザーがすでに同じ Flow に含まれている場合。</li><li>ユーザーを Flow の新しいバージョンに移動し、そのバージョンにユーザーに一致するステージが存在しなかった場合。</li><li>内部エラー。<br />**注**: これは、プライマリ以外のゴールを表示している場合、またはプライマリゴールで収益パフォーマンスが追跡されていない場合にのみ表示されます。</li></ul> |
| **Revenue** | エンゲージしたユーザーがゴールイベントを実行するたびに、定義された収益属性を累計した合計。<br />**Revenue Boost**<br />収益をもたらしたエンゲージしたテスト Flow ユーザーの、コントロールグループのユーザーと比較した増加率。<br />Revenue Boost の計算式は次のとおりです。<br />((テスト Flow トリップの平均収益 - コントロールグループトリップの平均収益)/コントロールグループトリップの平均収益) x 100<br />Flow にグローバルコントロールグループがある場合、Revenue Boost の計算式は次のとおりです。<br />((テスト Flow トリップの平均収益 - コントロールグループトリップおよびグローバルコントロールグループトリップの平均収益)/コントロールグループトリップおよびグローバルコントロールグループトリップの平均収益) x 100 |

## 例

アクションキャンペーン C1 と C2 を含む Flow で、ユーザー U1 が Flow に入り、両方のキャンペーンを受信して、設定されたコンバージョンゴールで 2 回コンバージョンしたとします。ユーザーが Flow から離脱した後の統計は次のようになります。

- Total Trips: 1
- Active Trips: 0
- Engaged Trips: 1 (ユーザーは両方のキャンペーンを受信しましたが、1 つのトリップとして扱われます)
- Converted Trips: 1
- Total Conversions:2

次に、ユーザー U2 が Flow に入りましたが、何らかの理由 (パーソナライゼーションの失敗やアクティブなデバイストークンがないなど) でどのキャンペーンも受信せず、コンバージョンイベントを 1 回実行したとします。ユーザーが Flow から離脱した後の統計は次のようになります。

- Total Trips: 2
- Active Trips: 0
- Engaged Trips: 1
- Converted Trips: 1
- Total Conversions:2

ユーザー U2 はどの Flow アクションキャンペーンからもエンゲージされていないため、エンゲージしたトリップ、コンバージョンしたトリップ、総コンバージョン数は変わりません。

# Canvas ビュー

上部の全体的な統計に加えて、Flow で設定された各ステージのパフォーマンスも確認できます。期間を指定してフィルタリングすることで、その期間内に Flow に入ったユーザーの行動や統計を把握できます。

![エントリールール、各ステージの entered、current、drops、exits のカウント、および条件分岐の下の分岐と離脱のカウントを示す Flow キャンバス](/images/flows-canvas-view-stage-stats.gif)

ステージレベルの統計を表示して、そのステージを通過したユーザー数、現在そのステージにいるユーザー数、そのステージから Flow を離脱したユーザー数を確認することもできます。

<Note>
  任意のステージについて、Entered = Current \+ Drop off \+ Exits となります。
</Note>

ユーザーが以前のバージョンから別のバージョンに移動すると、ユーザーが直接入った各ステージの右上隅にバッジが表示されます。バッジにポインターを合わせると、そこに到達したユーザー数と、ユーザーの移動元のバージョンが表示されます。

ステージの **Entered** カウントには、`0 + 2 (from V10, V6)` のような内訳を示す 2 行目も表示されます。最初の数値は上のステージからそのステージに到達したユーザー数を、2 番目の数値は以前のバージョンから到達したユーザー数を表します。これにより、エントリーステージでは説明できないステージの数値の増加を把握できます。

内訳に示されるバージョンはユーザーの移動元のバージョンであり、必ずしも現在のバージョンの直前のバージョンとは限りません。公開してアクティブユーザーを前に進めることを選択するたびに、その公開前のバージョンにいるユーザーも一緒に移動するため、ユーザーは複数回の公開を経て前に進むことがあります。そのため、上記の例のように、1 つのステージに複数の以前のバージョンからの到着が表示される場合があります。

![ステージのバッジにポインターを合わせて、以前のバージョンから直接そのステージに入ったユーザー数を確認する様子](/images/flows-versioning-canvas-cross-version-badge.gif)

次の画像は、2 人のユーザーが **Has done event** ステージから Flow を離脱したことを示しています。ステージにマウスポインターを合わせると、各離脱の理由を示すポップアップが表示されます。

![8.png](/images/moengage_c1096c.png)

<Note>
  ユーザーは、次のような理由で Flow の任意のステージから離脱する可能性があります。

  - Flow パス内の離脱ステージを通過した
  - 離脱条件の条件を満たした (離脱条件の追加の詳細については、[Global Exit Criteria](/ja/user-guide/flows-cross-channel-messaging/create/create-flows/create-a-flow) を参照してください)
  - Flow で定義されたコンバージョンゴールを達成した
  - 新しいバージョンを公開し、アクティブユーザーをそのバージョンに移動することを選択したときに、Flow の新しいバージョンに移動した
  - [指標の定義](#definition-of-metrics)セクションに記載されている理由によりドロップオフした
</Note>

すべてのユーザートリップについて Canvas ビューを分析するだけでなく、定義した期間内に Flow に入ったユーザーの統計や行動を分析・比較することもできます。前の画像に示すように、選択した日付範囲内に開始されたユーザートリップで Canvas ビューをフィルタリングできます。

<Note>
  Canvas ビューで期間を指定してフィルタリングすると、指定した期間内に Flow に入ったすべてのユーザーのデータが表示されます。詳細な統計では、ユーザーが Flow に入った時期に関係なく、その期間中に発生したことのデータが表示されます。詳細については、[こちら](/ja/user-guide/flows-cross-channel-messaging/faqs/analyzing-flows#why-are-the-stats-shown-in-canvas-view-and-detailed-stats-view-different-when-filtered-for-a-specific-date)を参照してください。
</Note>

アクティブなトリップの最新の統計を確認するには、日付範囲フィルターの横にある Refresh アイコンをクリックして、全体とステージレベルの両方の統計を更新します。

## コンバージョンアップリフト

アップリフトは、フィルタリングした期間中にコントロールグループが少なくとも 1 日有効になっていた場合にのみ、全体の統計に表示されます。アップリフトの計算方法の詳細については、[こちら](/ja/user-guide/flows-cross-channel-messaging/create/experimentation/control-group-in-flows)をクリックしてください。

# 詳細な統計

"Flows" タブの隣にある "Stats" タブをクリックすると、Flow の詳細な統計ページを開くことができます。

<Note>
  詳細な統計は、デフォルトでは過去 90 日間、または現在のバージョンの公開時刻以降のいずれか短い方の期間について表示されます。日付範囲フィルターを使用すると、Flow が公開された時点からの統計を確認できます。
</Note>

## Flow のパフォーマンス

このセクションには、現在アクティブなバージョンの Flow の統計が読み込まれます。次の画像に示すように、バージョンセレクターからバージョンを選択すると、特定のバージョンの統計を確認できます。バージョンセレクターでは、次のいずれかを選択できます。

- **Specific Version**: このセクションには、選択したバージョンについて、User trips、Engaged Trips、Converted trips の推移が表示されます。フィルタリングした期間中にコントロールグループが有効になっている場合は、コンバージョンアップリフトも表示されます。<img src="/images/moengage_09135e.png" alt="Flow Performance.png" />
- **All Versions**: _All Versions_ オプションでは、すべてのバージョンを合計した累積統計が読み込まれます。All Versions の Flow Performance には、User Trips、Engaged Trips、Converted Trips、Conversions の推移に関する情報が含まれます。フィルタリングした期間中にコントロールグループが有効になっている場合は、コンバージョンアップリフトも表示されます。バージョンごとに収益属性や通貨が異なる可能性があるため、All Versions オプションでは収益パフォーマンスは利用できません。チャートには、各バージョンが公開された時期も表示されます。<img src="/images/moengage_5c8420.png" alt="Flow Performance.gif" />

デフォルトのビューは、Flow の全期間と、Flow の公開時に定義されたプライマリゴールですが、次の条件で統計をフィルタリングできます。

- 日付に基づく特定の期間。
- コンバージョンゴールに基づく。

<Note>
  コントロールグループのトリップが定義した割合を超えている場合や、アップリフトがマイナスになっている場合は、詳細について [アップリフトの計算と CG の割り当て](/ja/user-guide/flows-cross-channel-messaging/create/experimentation/control-group-in-flows)を参照してください。
</Note>

### ドロップオフと離脱

このセクションには次のタブがあります。

- **Drops** - このタブには、すべてのドロップオフの理由、各ドロップオフ理由の説明、その理由によるドロップオフの総数、すべてのドロップオフに占める割合が一覧表示されます。ドロップオフ理由を展開すると、ユーザーがドロップオフしたステージのタイプとステージ名が表示されます。アクティブユーザーを新しいバージョンに移動すると、このタブには **Version migration failed** という理由も表示されます。これは、新しいバージョンにユーザーの定義済みパスが存在しなかった場合など、バージョン間の移行が完了しなかったためにドロップされたトリップをカウントします。![ユーザーがドロップしたステージまで Version migration failed の理由が展開された、Drops and Exits Breakdown の Drops タブ](/images/flows-versioning-drops-version-migration.png)
- **Exits** - このタブには、すべての離脱の理由、各離脱理由の説明、その理由による離脱の総数、すべての離脱に占める割合が一覧表示されます。離脱理由を展開すると、ユーザーが離脱したステージのタイプとステージ名が表示されます。\
  このタブには Exit on conversion も表示されます。Flow で定義されたコンバージョンゴールを達成して Flow を離脱したユーザーの統計を確認できます。アクティブユーザーを新しいバージョンに移動すると、このタブには **Version migration** という理由も表示されます。これは、バージョン間の移行によって離脱したトリップをカウントします。展開すると、各ユーザーが離れたステージのタイプとステージ名が表示されます。<img src="/images/moengage_83f95a.png" alt="9.png" />

![ユーザーが離れたステージまで Version migration の理由が展開された Exits タブ](/images/flows-versioning-exits-version-migration.png)

<Note>
  **Version migration** と **Version migration failed** は、他の場所で **User Exited Flow** の理由として表示されるイベントと同じです。**Version migration** は **Move to new version** として、**Version migration failed** は **Dropped off as the path was no longer defined** として表示されます。詳細については、[Flow をデバッグする](/ja/user-guide/flows-cross-channel-messaging/analyze-flows/debug-flows)を参照してください。
</Note>

### バージョン間の移動

特定のバージョンを選択すると、Flow のパフォーマンスチャートの下に **Cross-version movement** テーブルが表示されます。**Moved from** には各ユーザーグループの移動元のバージョンが表示され、**No. of users moved** にはその人数が表示されます。このテーブルには **Flow performance** とは別の独自の日付範囲があるため、そちらの日付を変更してもこのテーブルは変わりません。

## チャネルとキャンペーンのパフォーマンス

このセクションでは、Flow で使用されている各チャネルの集計パフォーマンスと、その中の各アクションキャンペーンのパフォーマンスを分析できます。MoEngage では以前、これを **Engagement Trends** と **Campaign Stats** の 2 つの別々のセクションとして表示していました。

### チャネルのパフォーマンス

タブからチャネルを選択するとそのチャネルのパフォーマンスが表示され、**All Channels** を選択すると Flow で使用されているすべてのチャネルを比較できます。データはテーブル、折れ線グラフ、棒グラフで表示でき、チャートを **CVR**、**CTR**、**Delivery rate** で切り替えることができます。**Date Range** と **Tracking Goal** を使用してビューの範囲を指定し、**Compare With** を使用して比較対象となる 2 つ目の期間を設定します。

単一のチャネルを選択すると、トラッキングゴールの **CVR** と **CTR** がチャートの上に表示され、チャートにはそのチャネル固有の指標 (試行数、正常に送信されたメッセージ数、コンバージョン数、コンバージョンイベント数など) がプロットされます。**All Channels** を選択すると、選択した指標について Flow 内のすべてのチャネルがチャートで比較されます。テーブルビューでは、各行が日付を表し、ユーザーエントリー数、送信成功数、配信数、開封数、調整後の開封数、クリック数、CTR、コンバージョン数の列があります。

![チャネルタブ、CVR、CTR、Delivery rate のオプションを備えた Channel Performance チャート、およびその下の Campaign Performance テーブルを示す Channel and Campaign Performance セクション](/images/flows-channel-campaign-performance.gif)

このセクションは **All Versions** を選択した場合にも利用でき、Flow のすべてのバージョンにわたって各指標が合計されます。各バージョンをエクスポートして自分で数値を合計しなくても、Flow の総コストと総リターンを判断するのに使用できます。All Versions ビューでは、チャネルごとに **Converted trips**、**Converted users**、**Conversions** の列が追加されます。

<Note>
  コンバージョンゴールの変更は新しいバージョンを作成する理由の 1 つですが、その場合でも MoEngage はバージョン間でコンバージョンと収益の数値を合計します。プライマリコンバージョンゴールのイベントがバージョン間で異なる場合、MoEngage は All Versions ビューにコールアウトを表示し、合計に複数の定義が含まれていることがわかるようにします。
</Note>

### キャンペーンのパフォーマンス

このセクションには、Flow で設定されたすべてのアクションキャンペーンのパフォーマンスが一覧表示されます。これにより、チャネルをまたいで個々のキャンペーンを比較できます。必要に応じて、特定のチャネルのアクションキャンペーンに絞り込み、類似したキャンペーンのパフォーマンスを把握・比較することもできます。

<Note>
  **Campaign Performance** テーブルは各キャンペーンのパフォーマンスを示しており、キャンペーン間でアトリビューションが重複するため、各行の指標を合計して Flow レベルの指標と比較することはできません。たとえば、ユニークコンバージョンの合計は、Flow 全体レベルのコンバージョンしたトリップ数やコンバージョン数と異なる場合があります。詳細については、[こちら](/ja/user-guide/flows-cross-channel-messaging/faqs/analyzing-flows)を参照してください。
</Note>

| 指標 | 説明 |
| --- | --- |
| **Campaign Name** | Flow 内のアクションキャンペーンの名前。 |
| **Channel** | キャンペーンの送信に使用されるチャネル。 |
| **Total User Entries** | キャンペーンがメッセージの配信を試みたユーザー数。トリップ中にキャンペーンを通過した可能性のあるコントロールグループのユーザーや、何らかの失敗理由によりキャンペーンが配信に失敗したすべてのユーザーが含まれます。 |
| **Total Sents** | 最終的に正常に送信されたメッセージの数。 |
