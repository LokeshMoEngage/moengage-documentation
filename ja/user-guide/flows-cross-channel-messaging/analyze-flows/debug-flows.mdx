# 概要

マーケターは、ユーザーが Flow 内で特定のパスを移動した理由、現在 Flow のどこにいるのか、または Flow に参加したかどうかについて知りたいことがよくあります。Debug Flows を使用すると、マーケターは公開済みの Flow がなぜそのように動作しているのかを理解できます。

Debug Flows は、特定のターゲットユーザーのジャーニーを追跡することで、公開済みの Flow でユーザーがたどっている正確なパスを把握するのに役立ちます。これにより、Flow 内の特定のキャンペーンのエンゲージメントが最適でなかった理由や、ユーザーが特定の行動をとった理由を理解できます。<br />Debug Flows は、マーケターが Flow 内のユーザーのパスをトレースするのに役立つ機能です。これにより、公開済みの Flow のパフォーマンスを検証し、エントリー条件、トリガー、スケジュールなどの Flow の設定とセットアップが正しく構成されているかどうかを確認できます。また、特定のユーザーまたはコホート内の離脱ポイントやコンバージョンを把握するのにも役立ちます。

Debug Flows を使用すると、次のことを把握できます。

- トリガーイベントを実行したにもかかわらず、ユーザーが Flow に参加しなかった理由。
- Flow に参加した後、ユーザーがキャンペーンを受信しなかった理由。
- ユーザーが Flow に参加した後にたどったパス、Flow とのエンゲージメントの状況、およびコンバージョンまたは離脱した場所。

<Info>
  Debug Flows は、すべての Enterprise クライアントでデフォルトで利用可能です。Enterprise プランをご利用で Debug Flows が有効になっていない場合は、MoEngage のカスタマーサクセスマネージャー (CSM) またはサポートチームにお問い合わせください。
</Info>

## Debug Flows の活用方法

- **Flow が期待どおりのパフォーマンスを発揮していない理由の把握** Flow を公開したものの、分析を確認すると、キャンペーンを受信しているオーディエンスが意図したオーディエンスではないことに気付いたとします。Debug Flows を使用すると、これらのオーディエンスが Flow に含まれた理由を把握し、それに応じて是正措置を講じることができます。
- **大規模なセグメント/オーディエンスに公開する前に Flow を自分でテスト** 大規模なオーディエンスを対象にマルチチャネルのカスタマージャーニーを実行しているとします。ただし、セグメント全体にキャンペーンを公開する前に、少数のユーザー (または社内チームメンバー) に公開してテストしたい場合があります。Debug Flows を使用すると、「ユーザーのシャドーイング」によって少数のオーディエンスに対する Flow のパフォーマンスを把握し、Flow を最適化してから、より大規模なオーディエンスに公開できます。
- **Flow を自分でデバッグ** Flow を公開したものの、ユーザーが期待どおりに Flow とエンゲージしていないとします。Debug Flows を使用して、Flow のセットアップにおけるギャップを把握し、適切な変更を加えることができます。

## Debug Flows の仕組み

<Info>
  Debug Flows は、固定時間の Flow、つまり One-time または Periodic の Flow では利用できません。
</Info>

ユーザートリップをデバッグするには:

1. All Flows ページに移動します。
2. 目的の Flow をクリックして選択します。
3. _Debug Flows_ タブに移動します。
4. _Search user entry_ 検索バーで、リストからユーザー識別子 (ID または MoEngageID) を選択します。詳細については、[ユーザー識別子](/ja/user-guide/data/user-data/anonymous-to-registered-user-merge)を参照してください。
5. ユーザートリップをデバッグするユーザーの ID または MoEngageID を指定します。
6. Enter キーを押します。これにより、Flow のさまざまなバージョンにおけるユーザーのすべての試行とエントリーが **User Entry** ドロップダウンに表示されます。
7. <img alt="Filter_Icon.png" src="/images/moengage_32350c.png" /> (フィルターアイコン) をクリックし、日付フィールドで日付範囲を指定することで、特定の期間内のユーザーの試行/エントリーを選択できます。利用可能なオプションは、_Yesterday_、_Last Week_、_Custom Range_ です。**注**: デバッグのために、現在の日付から 7 日を超える日付範囲をさかのぼることはできません。
8. **User Entry** ドロップダウンで確認したいエントリーまたは試行を選択し、**Debug** をクリックします。

![ユーザーエントリーをデバッグして Flow キャンバス上でユーザートリップを可視化する](/images/debug-flows-visualize-user-trip.gif)

## 用語集

| 用語 | 説明 |
| --- | --- |
| Entry | Entry は、ユーザーが Flow に設定されたエントリー条件を満たした後に Flow に参加したことを示します。 |
| Attempt | Attempt は、ユーザーが Flow の対象として検討されたものの、Flow のエントリー条件に設定されたすべてのパラメーターを満たさなかったために Flow に参加しなかったことを示します。また、_ユーザーエントリー上限_にすでに達している場合、すべてのエントリー条件を満たしていてもユーザーが Flow に参加できないことがあります。<br />**注**: ユーザーがイベントトリガー型 Flow の指定されたターゲットセグメントに属していても、トリガー条件に関連付けられたプライマリイベントを実行しない場合、そのユーザーは Flow の対象としてまったく検討されないため、試行は記録されません。 |
| Entry/Attempt Number | 各試行とエントリーには、ユーザーが Flow の対象となった回数に応じて、エントリー 'x' または試行 'x' というラベルが付けられます。たとえば、エントリー 1 はユーザーが初めて Flow に参加したことを表し、試行 5 はユーザーが Flow への参加に 5 回目に失敗したことを表します。 |
| Status | このフィールドは、ステージに関連付けられたアクションのステータス、または条件のステータスを示します。たとえば、ステージに関連付けられたキャンペーンの場合、キャンペーンがユーザーに正常に送信されたかどうかに応じて、ステータスは送信済みまたは未送信になります。 |
| Locale | このフィールドは、Flow の子キャンペーンに関連付けられたロケールを示します。 |
| Variant | このフィールドは、Flow 内でユーザーに割り当てられた子キャンペーンのバリアントを示します。 |
| Entry | このフィールドは、ユーザーがステージに参加した日時を示します。 |
| Exit | このフィールドは、ユーザーがステージから離脱した日時を示します。 |
| Selected Channel | このフィールドは、Next Best Action で選択されたチャネルを示します。 |
| Evaluation Start Time | このフィールドは、Flow 内の特定の条件についてユーザーの評価が行われた時刻を示します。 |
| Evaluation End Time | このフィールドは、Flow 内の特定の条件についてユーザーの評価が終了した時刻を示します。 |
| Defined Conditions | このフィールドは、Flow 内の条件ステージに指定された基準を示します。 |
| Traversed Branch | このフィールドは、Intelligent Path Optimizer (IPO) または A/B スプリットの Flow でユーザーがたどったブランチを示します。 |
| Time Zone | このフィールドは、Wait for/till コントロールを指定する際に選択されたタイムゾーンを示します。アプリまたはユーザーのタイムゾーンのいずれかになります。 |
| Time Slots | このフィールドは、Wait for/till コントロールで選択されたタイムスロットを示します。たとえば、毎週月曜日の午後 6 時にユーザーを次のステージに移動するように選択できます。この情報は Time Slots フィールドで確認できます。 |
| Duration | このフィールドは、Wait for/till コントロールで選択された期間を示します。たとえば、Wait for/till ステージに到着してから 'x' 時間後にユーザーを次のステージに移動するように選択できます。 |

# ステージ/アクションに関する情報の表示

ステージ、アクション、または条件に関する情報を表示するには、ステージをクリックすると、キャンバスの左側にその詳細が表示されます。たとえば、Flow にメールキャンペーンが関連付けられており、ユーザーがそのステージを通過した場合、キャンペーンをクリックすると、ステータス、ロケール、バリアントの情報に加えて、ユーザーがそのステージに参加した日時と離脱した日時を確認できます。

| ステージ | ユーザーがステージに参加した場合に利用可能な情報 | ユーザーがステージの対象とならなかった場合、またはステージに参加しなかった場合に利用可能な情報 |
| --- | --- | --- |
| キャンペーン | Flow 内のすべてのキャンペーンについて、ステータス、ロケール、バリアント、およびエントリー/離脱の情報を確認できます。 | ユーザーに配信されなかったキャンペーンについては、エントリー/離脱の情報と、キャンペーンがユーザーに配信されなかった理由が表示されます。 |
| 条件ステージ | 条件ステージについては、ステータス、評価開始時刻、評価終了時刻、定義された条件、およびエントリー/離脱の情報を確認できます。 | 条件ステージについては、ユーザーが満たさなかった条件 (イベント実行済み、ユーザー属性チェック、または条件分岐の基準) に関する情報と、エントリー/離脱の情報を確認できます。 |
| NBA | NBA ステージについては、ステータス、選択されたチャネル、ロケール、バリアント、およびエントリー/離脱の情報を確認できます。 | NBA ステージについては、エントリー/離脱の情報と、キャンペーンがユーザーに配信されなかった理由が表示されます。 |
| Wait Till/For | Wait Till/For ステージについては、タイムゾーン、タイムスロット/期間の情報、およびエントリー/離脱の情報を確認できます。 | Wait till/for ステージについては、エントリー/離脱の情報が表示されます。たとえば、定義されたタイムスロットが経過した後にユーザーが Wait for/till ステージに参加した場合、そのユーザーは Wait for/till ステージで離脱となります。定義されたタイムスロットが 2023 年 5 月 25 日午後 6 時で、ユーザーが 2023 年 5 月 28 日午後 4 時に Wait for/till ノードに参加して到着した場合、そのユーザーは離脱となり、この情報が表示されます。 |
| A/B Split/IPO | AB Split/IPO を含む Flow については、ユーザーがたどったブランチとエントリー/離脱の情報を確認できます。 | A/B スプリットまたは IPO コントロールノードについては、ユーザーが離脱したブランチと、その特定のブランチのエントリー/離脱の情報が表示されます。 |
| GoTo | GoTo 条件については、ソースステージ、宛先ステージ、およびエントリー/離脱の情報を確認できます。 | GoTo コントロールノードについては、エントリー/離脱の情報が表示されます。 |

### **トリップサマリー**

トリップサマリーセクションでは、ユーザーがトリップを開始した日時と Flow から離脱した日時に関する情報を確認できます。次の詳細が表示されます。

- **Trip start**: ユーザーが Flow に参加した時刻。
- **Trip converted**: ユーザーがトリップ中にコンバージョンしたかどうか。
- **Trip end**: ユーザーが Flow から離脱した時刻。
- **Trip end reason**: ユーザーが Flow から離脱した理由。ユーザーは次のいずれかの理由で離脱した可能性があります。
  | トリップ終了理由 | 説明 |
  | --- | --- |
  | Dropped out due to DND/FC settings | フリークエンシーキャップの上限を超えたか、Flow の DND 時間帯に配信が試行され、Flow の設定でユーザーを除外するように定義されていたため、ユーザーが Flow から離脱しました。[詳細はこちら](/ja/user-guide/flows-cross-channel-messaging/create/configure-flows/frequency-capping-fc-and-do-not-disturb-dnd-for-flows)をクリックしてください。 |
  | Dropped out due to Technical Exception | 内部システムエラーが発生したため、ユーザーが Flow から離脱しました。 |
  | Dropped out as Flow was Inactive (Paused/Stopped/Retired) | Flow が一時停止、停止、または廃止されたため、ユーザーが Flow から離脱しました。 |
  | Exited as User converted | Flow に設定されたコンバージョン目標が達成されたため、ユーザーが離脱しました。 |
  | User entered post the Waiting period of the Wait Stage | Wait For/Till の時間が経過した後にユーザーが参加したため、Flow から離脱しました。 |
  | Exited via Exit Stage | ユーザーが離脱ステージに到達したため、Flow から離脱しました。 |
  | Dropped due to user merge | ユーザーが登録ユーザーのアカウントにマージされたため、Flow から離脱しました。詳細については、[ユーザーのマージ](/ja/user-guide/data/user-data/anonymous-to-registered-user-merge)を参照してください。 |
  | Move to new version | 新しいバージョンを公開し、アクティブユーザーをそのバージョンに移動することを選択したため、ユーザーがこのバージョンから離脱しました。 |
  | Dropped off as the path was no longer defined | 新しいバージョンにユーザーの移動先となる一致するステージがなかったため、ユーザーが離脱しました。 |
- **Trip end stage**: ユーザーが Flow から離脱したステージ。

トリップサマリーには、次のオプションもあります。

- **Locate user**: ユーザーが現在 Flow 内のどこにいるかを表示します。
- **Locate trip end stage**: ユーザーが Flow から離脱したステージを表示します。Flow には通常、多数のノード、複数のブランチ、スプリットがあるため、このオプションを使用すると、キャンバスを探さなくてもステージを見つけることができます。

### **バージョン間を移動したユーザーのデバッグ**

ユーザーがバージョン間を移動した場合、Debug Flows では、ユーザーが参加した各バージョンが個別のエントリーとして一覧表示され、発生順にエントリーに番号が付けられます。古いバージョンのエントリーを選択するとユーザーがそのバージョンから離脱した場所を確認でき、新しいバージョンのエントリーを選択するとユーザーが到着した場所を確認できます。新しいエントリーでは、トリップはエントリーステージではなくそのステージから開始されます。

キャンバス上では、そのステージの上にあるアイコンが、ユーザーがこのバージョンに参加した場所を示し、移動元のバージョン名を表示します。トリップサマリーには、同じ情報が注記として表示されます。注記をクリックするとキャンバスがそのステージに移動するため、自分で探す必要はありません。
