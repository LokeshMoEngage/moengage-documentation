## Flow に参加したユーザーの追跡

Flow に参加したユーザーを特定するには、"User Entered Flow" イベントを実行したユーザーをセグメント化します。このイベントは、ユーザーによる各エントリーごとに追跡されます。

<img alt="Screenshot_2022-07-30_at_11.19.24_PM.png" src="/images/moengage_748986.png" />

以下にいくつかの例を示します。

| 参加ユーザーのセグメント | 使用するイベント属性 | 説明 |
| --- | --- | --- |
| Flow 別 | Flow Id または Flow Name | **Flow Id** でフィルタリングすると、コンバージョンがこの Flow に帰属したユニークユーザーのリストを取得できます。 |
| 特定のバージョン別 | Version Name | **Version Name** でフィルタリングすると、コンバージョンがこのバージョンの Flow に帰属したユニークユーザーのリストを取得できます。 |
| ユーザータイプ別 | With control group | **With control group =** **True** でフィルタリングすると、コントロールグループ (Global と Flow の両方) として Flow に参加したユーザーのリストを取得できます。**With Control Group =** **False** でフィルタリングすると、ターゲットグループとして Flow に参加したユーザーのリストを取得できます。 |
| コントロールグループタイプ別 | Control Group Type | **Control Type Group = Flow** でフィルタリングすると、コントロールグループとして Flow に参加したユーザーのリストを取得できます。**Control Type Group = Global** でフィルタリングすると、グローバルコントロールグループとして Flow に参加したユーザーのリストを取得できます。 |
| トリガーイベントタイプ別 | Trigger Event Met | **Trigger Event met** が Flow のトリガーイベントのいずれかに等しいという条件でフィルタリングします。これにより、特定のトリガーイベントによって Flow に参加したユーザーを特定できます。これは、Flow に複数のプライマリイベントが含まれている場合に特に役立ちます。 |

<Info>
- User Entered Flow イベントのイベント時刻は、ユーザーのタイムゾーンで表示されます。利用できない場合は、アプリのタイムゾーンで表示されます。どちらも利用できない場合は、UTC 時刻がイベント時刻として使用されます。

  **注:** 表示されるイベント時刻は、現地の夏時間の変更に合わせて調整されません。
- キャンペーンの Flow Id は、Flow を新しいウィンドウで開き、URL の **/flows/** に続く文字列をコピーすることで確認できます。たとえば、次の画像では 6616a9259670a17eec8b7c65 が Flow ID です: <img alt="flow ID.png"  src="/images/moengage_bb0719.png"  />
</Info>

## コンバージョンしたユーザーの追跡

Flow Action キャンペーンのいずれかを受信した後にコンバージョン目標イベントを実行したユーザー (つまりコンバージョンしたユーザー) を特定するには、"Flow Trip conversion" を実行したユーザーをセグメント化します。

<img alt="Screenshot 2024-04-13 at 2.04.50 PM.png" src="/images/moengage_f56f27.png" />   
このイベントはコンバージョンごとに追跡されるため、ユーザーが Flow トリップ中にコンバージョンを複数回実行した場合、記録された各コンバージョンおよび定義された各目標に対してこのイベントが発生します。

特定の Flow または特定のアクションキャンペーンでコンバージョンしたユーザーを特定できます。

以下にいくつかの例を示します。

| コンバージョンユーザーのセグメント | 使用するイベント属性 | 説明 |
| --- | --- | --- |
| Flow 別 | Flow Id または Flow Name | **Flow Id** でフィルタリングすると、コンバージョンがこの Flow に帰属したユニークユーザーのリストを取得できます。 |
| 特定のバージョン別 | Version Name | **Version Name** でフィルタリングすると、コンバージョンがこのバージョンの Flow に帰属したユニークユーザーのリストを取得できます。 |
| 特定の Flow Action キャンペーン別 | Flow Action Campaign Id | **Campaign Id** でフィルタリングすると、コンバージョンがこの Flow のキャンペーンに帰属したユニークユーザーのリストを取得できます。 |
| 特定の Flow 目標イベント別 | Flow Conversion Event または Goal Name | **Goal Name** でフィルタリングすると、このイベントを実行してコンバージョンしたユニークユーザーのリストを取得できます。 |
| 特定のアトリビューションタイプ別 | Attribution Type | **Attribution Type** でフィルタリングすると、特定のアトリビューションロジックに従ってコンバージョンしたユニークユーザーのリストを取得できます。 |
| すべてのコントロールグループユーザー | User Type | **User Type = Control Group** でフィルタリングすると、コンバージョンしたユニークなコントロールグループユーザーのリストを取得できます。 |
| すべての非コントロールグループユーザー | User Type | **User Type = Targeted** でフィルタリングすると、コンバージョンしたユニークなコントロールグループユーザーのリストを取得できます。 |

## Flow から離脱したユーザーの追跡

Flow から離脱したユーザーを特定するには、"User Exited Flow" を実行したユーザーをセグメント化します。

<img alt="Screenshot_2022-09-07_at_2.22.22_PM.png" src="/images/moengage_d29da0.png" />

このイベントは、ユーザーによる各離脱ごとに追跡されます。コンバージョンによる離脱、特定の Flow の完了などの関連フィルターを使用して、Flow から離脱したユーザーを特定できます。

以下にいくつかの例を示します。

| 離脱ユーザーのセグメント | 使用するイベント属性 | 説明 |
| --- | --- | --- |
| Flow 別 | Flow Id または Flow Name | **Flow Id** でフィルタリングすると、コンバージョンがこの Flow に帰属したユニークユーザーのリストを取得できます。 |
| 特定のバージョン別 | Version Name | **Version Name** でフィルタリングすると、コンバージョンがこのバージョンの Flow に帰属したユニークユーザーのリストを取得できます。 |
| 特定のステージ別 | Stage Id または Stage Name | **Stage Id** でフィルタリングすると、そのステージを通じて Flow から離脱したユニークユーザーのリストを取得できます。 |
| 特定の離脱理由別 | Exit Reason | **Exit Reason** でフィルタリングすると、特定の理由で Flow から離脱したユニークユーザーのリストを取得できます。 |
| ユーザータイプ別 | With control group | **With control group =** **True** でフィルタリングすると、コントロールグループ (Global と Flow の両方) として Flow に参加したユーザーのリストを取得できます。**With control group =** **False** でフィルタリングすると、ターゲットグループとして Flow に参加したユーザーのリストを取得できます。 |

<Info>
- "User Exited Flow" イベントを使用すると、特定の期間中に特定の Flow から離脱したユーザーの数と対象ユーザーをセグメント化し、ユースケースに応じて任意のキャンペーン (Push/Email/SMS/Connector/Flows) で再ターゲティングできます。
- User Exited` Flow イベントのイベント時刻は、ユーザーのタイムゾーンで表示されます。利用できない場合は、アプリのタイムゾーンで表示されます。どちらも利用できない場合は、UTC 時刻がイベント時刻として使用されます。

  **注:** 表示されるイベント時刻は、現地の夏時間の変更に合わせて調整されません。
</Info>

## 実験ステージを通過したユーザーの追跡

AB Split または Intelligent Path Optimiser (IPO) ステージの特定のブランチに割り当てられたユーザーを特定するには、"User Flow Advancement" イベントを実行したユーザーをセグメント化します。このイベントは、ユーザーが実験ステージを通過してブランチに割り当てられるたびに発生します。

<Info>
User Flow Advancement は[課金対象の標準イベント](/ja/user-guide/data/event-data/derived-events-and-attributes#billable-standard-events)です。ご依頼に応じて追跡され、発生するたびに課金対象のイベント数にカウントされます。アカウントでこの機能を有効にするには、MoEngage のアカウントマネージャーに連絡するか、[サポートチケット](/ja/user-guide/contact-support/raise-a-support-ticket-through-moengage-dashboard)を作成してください。
</Info>

<img alt="セグメンテーションにおける User Flow Advancement イベント" src="/images/User_flow_adv.png" />

以下にいくつかの例を示します。

| 通過したユーザーのセグメント | 使用するイベント属性 | 説明 |
| --- | --- | --- |
| Flow 別 | Flow Id または Flow Name | **Flow Id** または **Flow Name** でフィルタリングすると、その Flow 内のブランチに割り当てられたユニークユーザーのリストを取得できます。 |
| 特定のバージョン別 | Version Name | **Version Name** でフィルタリングすると、特定のバージョンの Flow でブランチに割り当てられたユニークユーザーのリストを取得できます。 |
| 特定の実験ステージ別 | Stage Id または Stage Name | **Stage Id** または **Stage Name** でフィルタリングすると、特定の実験ステージを通過したユニークユーザーのリストを取得できます。 |
| 実験ステージタイプ別 | Stage Type | **Stage Type = AB Split** でフィルタリングすると、AB Split ステージを通過したユーザーを取得できます。**Stage Type = IPO** でフィルタリングすると、Intelligent Path Optimiser ステージを通過したユーザーを取得できます。 |
| 特定のブランチ別 | Branch Name | **Branch Name** でフィルタリングすると、その特定のブランチに割り当てられたユニークユーザーのリストを取得できます。 |
| Flow タイプ別 | Flow Type | **Flow Type** でフィルタリングすると、特定のタイプの Flow (Event Triggered、Time Based、または Business Event Triggered) 内で通過したユーザーを取得できます。 |
| ユーザータイプ別 | User Type | **User Type = Target Group** でフィルタリングすると、ターゲットグループのユーザーを取得できます。**User Type = Flow Control Group** または **User Type = Global Control Group** でフィルタリングすると、それぞれのコントロールグループのユーザーを取得できます。 |

<Info>
- "User Flow Advancement" イベントを使用すると、特定のブランチに参加したユーザーをセグメント化し、ユースケースに応じて任意のチャネル (Push / Email / SMS / WhatsApp / Flows) で再ターゲティングできます。
- このイベントは Flow のアトリビューションウィンドウとは独立して追跡されるため、Flow に組み込まれたレポートで利用できる範囲を超えて、コンバージョン、リテンション、その他の指標など、ユーザー行動の長期的な分析に使用できます。
- **Branch Name** でフィルタリングすると、実験の異なるブランチに参加したユーザーを MoEngage Analytics で比較したり、より詳細な分析のためにサードパーティツールにエクスポートしたりできます。
- **User Type** でフィルタリングすると、分析にコントロールグループのユーザーを含めたり除外したりして、各ブランチでターゲットユーザーがどのようなパフォーマンスを示したかを明確に把握できます。
</Info>
