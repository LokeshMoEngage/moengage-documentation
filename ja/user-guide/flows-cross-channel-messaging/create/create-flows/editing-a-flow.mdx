# 概要

フローの最適化は、多くの場合反復的なプロセスです。フローを繰り返し改善するには、公開済みのフローを編集する必要があります。新しいチャネルや、まったく新しい戦略を試してフローのパフォーマンスを向上させることができます。フローのバージョニングを使用すると、複数の個別フローを作成することなく、任意の公開済みフローで同じことを実現できます。これにより、フローのすべての分析データとコンテキストをそのまま維持できます。

バージョニングを使用すると、重複した独立フローを作成する代わりに、ログを使用して公開済みフローを効率的に管理し、リビジョン履歴を確認しながら編集できます。公開済みフローでは、要素の追加、削除、変更、ステージやパラメーターの追加、フローのパスや設定の変更が可能です。

これにより、カスタマージャーニーの実験や最適化における業務効率が向上し、混乱や煩雑さが軽減されます。また、バージョニングにより、フローの各バージョンのパフォーマンスに関する明確なレポートとインサイトが得られます。

## ユースケース

- ある小売ブランドは、毎月最終週に月次割引キャンペーンを実施しています。このキャンペーンは、入念に作成されたメール、SMS、プッシュ通知を組み合わせたマルチチャネルのアプローチで伝えられています。しかし、ここ数か月でこれらのキャンペーンのパフォーマンスが低下しています。このブランドは、フローを編集して実行中のキャンペーンの改良版を作成し、キャンペーンを最適化できます。
- 小売ブランドは、フローを編集して複数のバージョンを作成し、フロー全体を複製することなく、公開済みフロー内で異なるユーザーパスのメッセージングやクリエイティブ要素をテストできます。異なるチャネル、条件、ステージを持つ同じフローの複数バージョンを作成し、エンゲージメントやコンバージョンの向上につながるかどうかを評価できます。
- フローを編集してフローバージョンを繰り返し作成することで、フィンテックアプリは顧客からのフィードバックに基づいて公開済みフローに変更を加えることができます。たとえば、顧客がアプリ内の操作に苦労している場合、フィンテックアプリはバージョニングを使用してフローをすばやく変更し、ユーザーエクスペリエンスを改善できます。

## バージョニングの仕組み

公開済みフローを編集すると、新しいバージョンが作成されます。たとえば、ステージを追加または削除したり、Flows の設定（コンバージョントラッキングやコントロールグループなど）を変更したりすると、変更を保存したかどうかにかかわらず、フローの新しいバージョンが作成されます。

すべての変更が完了したら、新しく作成したバージョンを公開できます。公開すると、エントリー条件を満たす新規ユーザーは最新の公開バージョンに入ります。

以前のバージョンですでにアクティブなユーザーについては、公開時にどうするかを決定します。現在のバージョンを最後まで進めさせるか、新しいバージョンに移動させるかを選択できます。詳細については、[新しいバージョンの公開](/ja/user-guide/flows-cross-channel-messaging/create/create-flows/editing-a-flow#publishing-a-new-version)を参照してください。

フローの新しいバージョンが作成されると、次のようになります。

- バージョンは通常、フローに作成されたバージョン数に応じて「Version 'n'」という名前が付けられます。この例では、アクティブなフローは「Version 1」、編集中のバージョンは「Version 2」と表示されます。
- バージョンを追跡しやすくするため、フロー名の横にバージョンセレクター（ドロップダウン）が追加されます。ドロップダウンでは編集中のバージョンが選択されています。バージョンセレクターには次の情報が表示されます。<img src="/images/moengage_039a13.png" alt="Version_Dropdown.png" />
- Flows キャンバス上部のリボン（フロー詳細セクション）にある「View Changes」ハイパーリンクをクリックすると、変更内容を確認できます。このハイパーリンクをクリックするとバージョンログが開き、未保存および保存済みの変更を確認できます。詳細については、バージョンログを参照してください。<img src="/images/moengage_d8225c.png" alt="View_Changes.png" />
- 必要な変更を行ったら、Flows キャンバス上部のリボンにある _Save_ をクリックします。保存された変更は、バージョンログの _Saved_ セクションに表示されます。
- バージョンを保存すると、Flows キャンバス上部に次のオプションが表示されます。
  | アクション | 説明 |
  | --- | --- |
  | View changes | バージョンログを表示できます。 |
  | Delete | 保存済みのバージョンを削除できます。バージョンを削除すると、復元することはできません。 |
  | Publish | ドラフトバージョンを公開できます。MoEngage は、以前のバージョンを公開した瞬間ではなく、そのバージョンでまだアクティブなユーザーが退出した時点で[リタイア](/ja/user-guide/flows-cross-channel-messaging/create/create-flows/status-of-flows#retiring-a-flow)します。 <br />**注:** 以前のバージョンが[一時停止ステータス](/ja/user-guide/flows-cross-channel-messaging/create/create-flows/status-of-flows#pause%2Fresume)の場合、ドラフトバージョンを公開すると以前のバージョンは停止されます。 |
  | Save | フローの現在のバージョンへの変更を保存できます。 |
  | Duplicate | フローの現在のバージョンを複製できます。 <br />**注**: 現在のバージョンの複製フローが作成されます。ただし、複製されたフローには、複製元フローのすべてのバージョンは含まれません。複製されたフローには、複製対象の現在のフローバージョンに含まれる情報のみが含まれます。 |

### バージョン間でのユーザーエントリー制限の仕組み

User Entry Limit はフローのバージョン間で引き継がれます。新しいバージョンが公開されてもリセットされません。ユーザーの過去のエントリーは現在のバージョンで定義されている制限に対してカウントされるため、ユーザーはその制限に達するまでの回数だけ新しいバージョンに入ることができます。

たとえば、Version 1 でフローの User Entry Limit が年 2 回に設定されており、あるユーザーがすでに 2 回エントリーしているとします。

- Version 2 で制限を 2 回のまま維持した場合: ユーザーは Version 1 から引き継がれた制限をすでに使い切っているため、その年の残りの期間はエントリーできません。
- Version 2 で制限を 3 回に引き上げた場合: 3 回のうち 2 回しか使用していないため、ユーザーはもう 1 回エントリーできます。
- Version 2 で制限を 1 回に引き下げた場合: ユーザーのエントリー回数がすでに新しい制限を超えているため、まったくエントリーできません。

## 新しいバージョンが作成されるタイミング

次のアクションを行うと、新しいバージョンが作成されます。

| フロー要素/設定 | 新しいバージョンの作成につながるアクション |
| --- | --- |
| オーディエンス | <ul><li>フローのオーディエンスの変更</li></ul> |
| ユーザーエントリー条件と制限 | <ul><li>トリガー条件およびそれに関連する遅延の変更</li><li>User Entry Limit の変更</li></ul> |
| コンバージョンゴール | <ul><li>フローに追加されたコンバージョンゴールの追加、削除、編集</li><li>コンバージョンゴールに追加されたアトリビューションウィンドウの編集</li><li>フローの Exit on conversion トグルの有効化/無効化</li></ul> |
| その他のフロー設定 | <ul><li>コントロールグループ設定の変更</li></ul> |
| アクションステージ | <ul><li>ステージの追加または削除</li><li>バリエーション/ロケールの追加または削除</li><li>ユーザー配分設定の変更</li><li>フォールバックチャネル/デフォルト時間設定の変更、NBA チャネルの追加または削除、BTS の有効化または無効化</li></ul> |
| 条件（Check User Attribute/ Has done event/Conditional split） | <ul><li>ステージまたはブランチの条件の変更</li><li>評価ウィンドウの変更</li><li>ブランチの追加または削除</li><li>ブランチの順序の変更</li></ul> |
| コントロール（Wait for/till、Goto、Intelligent Path Optimizer (IPO)、A/B Split） | <ul><li>Wait Till/For ステージの設定の変更</li><li>Goto の遷移先の変更</li><li>A/B split から IPO への切り替え</li><li>AB Split ブランチ間のユーザー配分の変更</li><li>AB split/IPO のブランチの追加または削除</li><li>Merlin AI が最大化する指標の変更</li></ul> |

<Note>
      - バージョニングは、次のフローステータスには適用されません: Stopped、Retired、Completed、Draft。また、「One-time」の時間ベースのエントリーフローにも適用されません。アクティブなフローの以前のバージョンを戻すには、[以前のバージョンの復元](/ja/user-guide/flows-cross-channel-messaging/create/create-flows/editing-a-flow#restoring-a-previous-version)を参照してください。
      - 公開済みフローのエントリータイプは変更できません。
      - スケジュール済みフローでコントロールグループ設定または User Entry Limit 条件を変更しても、新しいバージョンは作成されません。
      - アクティブおよび一時停止中のフローでは、定期実行の「End Date」を除き、フローのスケジュール設定を編集できません。
      - フロー名、フローステータス、DND、FC 設定の変更や、既存のアクションキャンペーンのコンテンツの変更では、フローの新しいバージョンは作成されません。
</Note>

## 新しいバージョンの公開

新しいバージョンを公開すると、MoEngage は以前のバージョンでまだアクティブなユーザーをどう扱うかを確認します。

新しいバージョンを公開するには、次の手順を実行します。

1. フローキャンバスで **Actions** をクリックし、**Publish** をクリックします。

   ![Actions メニューが開き、Publish オプションが強調表示されたフローキャンバス](/images/flows-versioning-publish-action.png)

2. **Publish new version** ダイアログボックスで、次のいずれかのオプションを選択します。

   | オプション | 動作 |
   | --- | --- |
   | Let them continue on the previous version | すべてのアクティブユーザーが退出した後、MoEngage は以前のバージョンを **Retired** にします。 |
   | Move them to this version as soon as possible | アクティブユーザーは、すぐに、または現在のステージで保留中の遅延が終了した後にこのバージョンに移動します。一致するステージがないユーザーはフローから退出します。 |

3. **Publish** をクリックします。

   ![以前のバージョンのアクティブユーザーを処理するための 2 つのオプションを示す Publish new version ダイアログボックス](/images/flows-versioning-publish-dialog.png)

公開するバージョンが後で開始するようにスケジュールされている場合、スケジュールされたバージョンがアクティブになるまで現在のバージョンは実行され続けます。MoEngage は、公開した時点ではなく、新しいバージョンがアクティブになった時点で現在のバージョンをリタイアします。

<Note>
  デフォルトの選択はないため、公開する前に 2 つのオプションのいずれかを選択する必要があります。選択するまで **Publish** は使用できません。

  この選択は、今回の直前に公開されたバージョンにのみ影響します。Version 3 を公開する場合、この選択は Version 2 のアクティブなトリップに適用され、それ以前のバージョンには適用されません。
</Note>

### バージョン間でのユーザーの移動

**Move them to this version as soon as possible** を選択した場合、各ユーザーの移動先は行った変更によって異なります。待機ステージにいるユーザー、**Keep Evaluating For** がオンになっている条件ステージにいるユーザー、または DND が無視されないアクションステージにいるユーザーは、保留中の遅延が終了した後にのみ移動します。

| 行った変更 | アクティブユーザーの移動先 |
| --- | --- |
| ステージを追加した | 新しいステージにまだ到達していないユーザーは、そのステージを通過します。すでにその地点を過ぎているユーザーは、新しいバージョンで下流に進み続けます。 |
| ステージを削除した | 削除されたステージ、またはその直上にいるユーザーは、その上にある最も近い残存ステージに移動し、その次のステップから続行します。その地点を過ぎているユーザーは下流に進み続けます。ユーザーがドロップオフするのは、上位のパス全体も削除されている場合など、上に残存するステージがない場合のみです。 |
| ブランチを削除した | まだ存在するブランチに一致するユーザーは続行します。削除されたブランチに一致するユーザー、またはすでにそのブランチ内にいるユーザーはドロップオフします。 |
| ステージの設定を更新した | 編集されたステージにすでにいるユーザーは、エントリー時に適用されていた設定に従います。それ以外のユーザーは新しい設定に従います。 |

MoEngage は、以前のバージョンから退出する各ユーザーに対して、次のいずれかの退出理由とともに **User Exited Flow** イベントを発生させます。

- **Move to new version**: ユーザーが新しいバージョンに入った場合。
- **Dropped off as the path was no longer defined**: 新しいバージョンにユーザーに一致するステージが存在しない場合。

MoEngage は、ドロップオフをユーザーが退出したバージョンに帰属させます。これらのユーザーは、Behavior Analytics でフロー ID を条件として、退出理由を指定して **User Exited Flow** イベントをクエリすることで見つけることができます。

### 新しいバージョンを承認に送信する

ワークスペースでキャンペーン承認ワークフローを使用している場合、**Actions** には **Publish** の代わりに **Send for approval** が表示され、ダイアログボックスには **Manage users from previous version** と **Send for approval** の 2 つのステップがあります。

新しいバージョンを承認に送信するには、次の手順を実行します。

1. **Manage users from previous version** で 2 つのオプションのいずれかを選択し、**Next** をクリックします。

   ![2 つのオプションと Next ボタンを示す Manage users from previous version ステップ](/images/flows-versioning-approval-manage-users.png)

   <Note>
     デフォルトの選択はないため、続行する前に 2 つのオプションのいずれかを選択する必要があります。選択するまで **Next** は使用できません。

     MoEngage はバージョンがレビューに送られるたびにユーザー移動の選択を求めるため、すでにレビュー中のバージョンを編集する場合や、承認者に却下されたバージョンを再提出する場合にも、再度回答する必要があります。
   </Note>

2. **Select Approvers** で、**Start typing to filter approvers** ボックスに承認者の名前を入力し、承認者の横にある **\+ Add** をクリックします。

   ![Add オプションを含む承認者リストと空の Selected Approvers パネルを示す Send for approval ステップ](/images/flows-versioning-approval-select-approvers.png)

3. 必要に応じて、**Add your comment here** ボックスに承認者へのメモを入力します。
4. **Send for approval** をクリックします。

   ![承認者が追加され、Send for approval ボタンが使用可能な Send for approval ステップ](/images/flows-versioning-approval-send.png)

追加した承認者は **Selected Approvers** に表示され、少なくとも 1 人を追加するまで **Send for approval** は使用できません。承認者を削除するには、アバターのマイナスアイコンをクリックします。ユーザー移動の選択を変更するには、**Previous** をクリックします。

### 後から選択内容を確認する

Flow Settings には、バージョンの公開時に選択したオプションが表示されるため、後から決定内容を確認できます。

選択内容を確認するには、次の手順を実行します。

1. フローを開き、**Settings** をクリックします。

   ![Flow タブの右上に Settings オプションがあるフローキャンバス](/images/flows-versioning-settings-tab.png)

2. **Users movement from previous version to this version** までスクロールし、どのオプションが選択されているかを確認します。

   ![Users movement from previous version to this version オプションが読み取り専用状態で表示された Flow Settings パネル](/images/flows-versioning-settings-user-movement.png)

この画面では、2 つのオプションは **Let users in this version continue** および **Move users to this version as soon as possible** と異なる表現になっていますが、公開時に選択したものと同じ選択肢です。

どちらのオプションも読み取り専用のため、バージョンの公開後に選択を変更することはできません。このフィールドは、2 つ以上のバージョンを持つフローにのみ表示されます。承認者は、バージョンを承認する前にこのフィールドで決定内容を確認します。

## 以前のバージョンの復元

新しいバージョンが期待どおりに機能しない場合は、作り直す代わりに以前のバージョンを戻すことができます。復元すると、そのバージョンが新しいドラフトにコピーされ、他のバージョンと同様に編集して公開できます。

以前のバージョンを復元するには、次の手順を実行します。

1. フロー名の横にあるバージョンセレクターをクリックし、復元するバージョンを選択します。

   ![各バージョンとそのステータス、および選択したバージョンの詳細を一覧表示するバージョンセレクター](/images/flows-versioning-version-selector.png)

2. **Actions** をクリックし、**Restore as draft** をクリックします。

   ![Pause、Retire、Stop、Duplicate、Export の下に Restore as draft オプションを表示する Actions メニュー](/images/flows-versioning-restore-action.png)

3. **Restore as draft** ダイアログボックスで、**Restore as draft** をクリックします。

   ![復元によりドラフト状態の新しいバージョンが作成されることを確認する Restore as draft ダイアログボックス](/images/flows-versioning-restore-confirm.png)

ダイアログボックスには、作成されるバージョン番号が表示されます。MoEngage は選択したバージョンを **Draft** ステータスの新しいバージョンにコピーし、そのドラフトは公開するまで非アクティブのままです。

<Note>
  - このオプションは、最新バージョンがアクティブ、スケジュール済み、一時停止中、またはリタイア済みの場合に使用できます。
  - 最新バージョンが停止している場合、このオプションは使用できません。
</Note>

## アクティブな旧バージョンを持つフローの停止

最新バージョンを停止すると、フローのすべての旧バージョンも停止されるため、以前のバージョンでまだアクティブなユーザーがそのバージョンからメッセージを受信し続けることはありません。

MoEngage がこの確認を表示するのは、以前のバージョンにまだアクティブなトリップがある場合のみです。以前のバージョンにアクティブなトリップがない場合、フローを停止すると、[Stop](/ja/user-guide/flows-cross-channel-messaging/create/create-flows/status-of-flows#stop) で説明されている標準の確認が表示されます。

フローを停止するには、次の手順を実行します。

1. **Actions** をクリックし、**Stop** をクリックします。
2. **Stop all versions of this flow?** ダイアログボックスで、**Stop Flow** をクリックします。

   ![フローを停止したときに起こることを一覧表示する Stop all versions of this flow ダイアログボックス](/images/flows-versioning-stop-all-versions.png)

フローを停止すると、次のようになります。

- 新しいユーザーはフローに入りません。
- すべてのバージョンのアクティブユーザーは、現在のステージで停止します。
- 後からフローを再開または編集することはできません。

フローを停止した後でも、フローを複製することはできます。

## バージョンの切り替え

バージョンを切り替えると、次のようになります。

      - 現在のバージョンが保存されていない場合は、変更を保存するかどうかを確認されます。保存しないことを選択した場合、そのバージョンは保持されず、すべての変更が破棄されます。
      - 保存後に（保存したバージョンが公開されていない状態で）バージョンを切り替えると、バージョンセレクターの横に次のアラートが表示されて通知されます。<img src="/images/moengage_5f4070.png" alt="Save_Options.png" />

## ログ

公開済みフローを編集できるようになると、どのような変更が、誰によって、いつ行われたのかという疑問が生じます。次のログは、マーケターがバージョン単位およびフローの複数バージョンにわたって、これらの疑問に答えるのに役立ちます。

### バージョンログ

バージョンログは、ドラフト状態のフローのバージョンで使用でき、バージョンに関する上記 3 つの疑問に答えます。バージョンログにアクセスするには、Flows キャンバス上部のリボン（フロー詳細セクション）にある _View Changes_ ラベルをクリックします。バージョンログでは次の詳細を確認できます。

    - **Unsaved** - このセクションでは詳細と日付を確認できます。一覧表示されたバージョンに加えられた変更の詳細を確認できます。一覧の変更をクリックすると、下の画像に示すように、変更が行われたノード/ステージが表示されます。
    - **Saved** - 以下に示すように、このセクションではユーザー、詳細、日付を確認できます。また、バージョンに加えられた変更の詳細も確認できます。

![VersionLogs.gif](/images/moengage_d9156b.png)

### 監査ログ

監査ログは、フローのすべてのバージョンで使用できます。各バージョンについて次の情報が含まれます。

    - **Version** - このフィールドは、フローのバージョン名を示します。
    - **Status** - このフィールドは、バージョンのステータスを示します。
    - **Details** - このフィールドには、バージョンが公開されたかどうかと変更の一覧、保存済みの変更とその一覧などの情報が含まれます。
    - **User** - このフィールドには、フローのバージョンに最後に編集を加えたユーザーに関する情報が含まれます。
    - **Date** - このフィールドには、バージョンへの最新の編集が行われた日時に関する情報が含まれます。

![AuditLogs.gif](/images/moengage_b15615.png)

## フローバージョンに入ったユーザーの検索

新しいバージョンを作成した後、新しいバージョンに入ったユーザーを見つけて、同じフローの旧バージョンとパフォーマンスを比較したい場合があります。

_User entered flow_ イベントを実行したすべてのユーザーを含むセグメントを作成できます。その際、_Flow Id Attribute_ の値をフローの [flow-id](/ja/user-guide/flows-cross-channel-messaging/analyze-flows/tracking-users-in-flows) に、_Flow Version Name_ 属性を特定のバージョン名に設定します（詳細については、[フローのバージョン名の確認](/ja/user-guide/flows-cross-channel-messaging/create/create-flows/editing-a-flow)を参照してください）。
