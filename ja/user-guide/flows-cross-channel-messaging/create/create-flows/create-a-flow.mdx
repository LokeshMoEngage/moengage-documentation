MoEngage Flows は、アプリやウェブサイトでの顧客の行動 (または行動しなかったこと) に基づいて顧客に送信される、クロスチャネル (Email、Push、SMS などのチャネルにまたがる) のライフサイクルキャンペーンの一連の流れです。

<Tip>
  チャネル設定が構成されていることを確認してください。
</Tip>

Flow を作成するには:

1. MoEngage Dashboard に移動します。
2. 左側のナビゲーションから、次のいずれかのオプションを使用します。
   <Tabs>
     <Tab title="Create flow">
       1. **Flows** をクリックします。Flows ページが表示されます。<img src="/images/moengage_803067.png" alt="7.png" />
       2. 右上隅にある **\+ Create flow** をクリックします。<img src="/images/moengage_af660c.png" alt="8.png" />
     </Tab>
     <Tab title="Create new">
       1. **Create new** をクリックします。次のページが表示されます。<img src="/images/moengage_3eba7a.png" alt="9.png" />
       2. ![10.png](/images/moengage_614cc6.png)
     </Tab>
   </Tabs>
3. 表示されるポップアップで、次のいずれかのオプションを使用して Flow を作成します。
   - [Merlin AI Flows Assist を使用する](#option-1-using-merlin-ai-flows-assist)

# オプション 1: Merlin AI Flows Assist を使用する

Merlin AI Flows Assist は、自然言語で記述されたマーケティング戦略を技術的に正確な MoEngage Flow に変換する、AI 駆動のオーケストレーターです。マルチエージェントシステムを利用してユーザーの意図を解釈し、過去のパターンに基づいて最も効果的な戦略的パスを自動的に選択し、キャンバス上に完全なビジュアルジャーニーを直接構築します。このプロセスには、マーケティングのアイデアを正確な技術的指示に変換し、業界固有のコンテキストで最適化することが含まれ、すべてのジャーニーが適切でデプロイ可能な状態になるようにします。詳細については、[Create a Flow Using AI Assist](/ja/user-guide/flows-cross-channel-messaging/create/create-flows/create-a-flow-using-ai-assist) および [Merlin AI Flows Assist](/ja/user-guide/ai-and-intelligence/merlin-ai/merlin-ai-flows-assist) を参照してください。

# オプション 2: Flow テンプレートを使用して Flow を作成する

Flow テンプレートは、オンボーディング、インセンティブ、エンゲージメントといったゴールに基づいて Flow を作成する際のヒントを提供します。単一チャネルまたは複数チャネルの Flow を作成して、カート放棄のリマインダーを送信したり、離脱リスクのある顧客にアプローチしたり、アプリ/ウェブサイトのエンゲージメントを向上させたりできます。各種 Flow テンプレートについて以下で説明します。

## テンプレートの種類

基本的なテンプレートの種類は 2 つあります。

- **Adoption**: Adoption テンプレートは新規顧客のオンボーディングに使用でき、単一チャネルと複数チャネルで利用できます。
- **Engagement**: Engagement テンプレートは、単一、複数、またはウェブやアプリなどの特定のチャネルで利用できます。アプリやウェブサイトのエンゲージメント向上、特定の商品を閲覧したり特定の商品をカートに追加して放棄したりした顧客へのエンゲージメント、離脱リスクのある顧客へのアプローチに使用できます。

Flow の作成時に、次のいずれかのテンプレートを選択できます。

| テンプレートの種類 | テンプレート名 | 説明 |
| --- | --- | --- |
| Adoption | Onboard Customers - Single Channel | このテンプレートを使用して新規顧客を歓迎し、製品やサービスを利用するジャーニーをガイドします。このテンプレートでは、オンボーディング段階の顧客とのコミュニケーションや、オンボーディング後の初回購入への後押しに単一のチャネルを使用します。 |
| Adoption | Onboard Customers - Multi-Channel | このテンプレートを使用して新規顧客を歓迎し、複数のチャネルを使用して顧客とコミュニケーションを取ります。A/B テストを活用して、新規ユーザーとのコミュニケーションに最適なチャネルを特定できます (この情報は他のオンボーディング Flow にも活用できます)。このテンプレートでは、ロケールと条件分岐も使用してユーザーの現地語を特定し、その言語でコミュニケーションを取ります。 |
| Engagement | Abandoned Cart Reminder - Single Channel | このテンプレートを使用して、カートに商品を追加したもののまだ購入していないユーザーにリマインダーを送信します。このテンプレートでは Wait For/Till Node 要素を使用して時間をおいてから通知を送信し (ユーザーがカートに商品を追加してから一定の時間が経過した後にのみ通知が送信されます)、通知を送信する前に、設定した時間の経過後にユーザーがカートを放棄したか購入したかを確認します。このテンプレートでは単一のチャネルでコミュニケーションを行います。 |
| Engagement | Abandoned Cart Reminder - Multi Channel | このテンプレートを使用して、複数のチャネルを活用し、カートを放棄したユーザーに購入を促します。 |
| Engagement | Browse Abandonment - Multi-Channel | このテンプレートを使用して、商品を閲覧したり特定の商品カテゴリを検索したりしたものの、まだ購入していない顧客にエンゲージします。このテンプレートはコンテキストに応じたコミュニケーションの送信に役立ち、Intelligent Path Optimization (IPO) を活用して、Merlin AI によりユーザーを最もパフォーマンスの高いパスにインテリジェントかつ自動的に振り分けることができます。 |
| Engagement | Customer Reactivation - Multi-channel | このテンプレートを使用して、長期間プラットフォームでアクティブでない顧客にエンゲージします。このテンプレートは、厳選したオファーの送信や休眠顧客とのコミュニケーションに役立ちます。このテンプレートでは Next Best Action (NBA) が使用されるため、各顧客が最もエンゲージする可能性の高いチャネルで、最もエンゲージする可能性の高いタイミングにコミュニケーションが送信されます。 |
| Engagement | Periodic Customer Reactivation - Multi-channel | このテンプレートを使用して、休眠顧客に定期的に (10 日ごとに) エンゲージします。このテンプレートは NBA を活用し、各顧客の優先チャネルで、そのチャネルで最もエンゲージする可能性の高いタイミングにコミュニケーションを取ります。 |
| Engagement | Engage customers on App | このテンプレートを使用して、数日間アプリを利用していない顧客に NBA を使用してエンゲージします。このテンプレートでは、顧客がアプリを利用した際に、アプリ内キャンペーンとカードキャンペーンを使用して購入を促します。 |
| Engagement | Engage customers on Web | このテンプレートを使用して、数日間アプリを利用していない顧客に NBA を使用してエンゲージします。このテンプレートでは、顧客がアプリを利用した際に、Web Push、On-site messaging、Cards、Google Ads を組み合わせて購入を促します。 |

テンプレートの種類を理解したら、それらを使用して Flow を作成できます。

<Info>
  - Flow テンプレートを編集して、必要に応じてイベントチェックを追加したり、キャンペーンのコンテンツを編集したりできます。
  - 必要に応じて、テンプレートにステージを追加または削除できます。
</Info>

## テンプレートを使用する

1. Flow テンプレートを選択し、**Use template** をクリックします。
2. Flow のエントリー条件を追加し、ターゲットオーディエンスとコンバージョンゴール (ある場合) を定義します。
3. テンプレート内のキャンペーンを確認し、必要に応じて変更します。
4. ビジネスのユースケースに応じて、必要であれば新しいステージやパスを追加します。
5. Flow の構造が完成したら、**Save** をクリックして下書きとして保存できます。Flow を公開するための次のアクションは、アカウントの設定によって異なります。
   - Campaign Approval ワークフローが無効の場合は、Flow を直接公開できます。
   - Campaign Approval ワークフローが有効で、キャンペーンの作成、管理、公開の権限を持っている場合は、Flow を直接公開できます。
   - Campaign Approval ワークフローが有効で、**Create & Manage** 権限のみを持っている場合は、Flow を承認申請する必要があります。詳細については、[こちら](/ja/user-guide/settings/account/team-management/campaign-approval-workflow)を参照してください。

# オプション 3: Flow を一から作成する

空白のキャンバスから始めて、任意の Flow を構築できます。Flow を一から作成する手順は次のとおりです。

1. [Details and goals](#details-and-goals): Flow のゴールを定義し、必要な詳細を追加します。
2. [When will users enter the flow](#when-will-users-enter-the-flow): ユーザーが Flow に入るタイミングを定義します。
3. [Who will enter the flow](#who-will-enter-the-flow): Flow のオーディエンスを定義します。

<Info>
  Flow 作成中は、どのステップからでも直接キャンバスに移動できます。**Skip to Canvas** をクリックすると、MoEngage のキャンバスが開きます。
</Info>

## 詳細とゴール

**\+ Start with a blank canvas** をクリックすると、Create flow ページが表示されます。このセクションには次の内容が含まれます。

### Flow の詳細

Flow の詳細セクションには、次のフィールドがあります。

- **Team:** 組織で **Team** が有効になっている場合は、**Team** リストで Flow に関連付けるチームを選択します。詳細については、[Teams in MoEngage](/ja/user-guide/settings/account/team-management/teams-in-moengage) を参照してください。
- **Flow name**: Flow を管理・識別するための Flow 名を入力します。Flow 名は 5 文字以上、最大 256 文字である必要があります。Flow 名には特殊文字を使用できます。
- **Flow tags**: ドロップダウンリストから Flow タグを選択して、タグを明確にします。最大 5 つのタグを選択できます。詳細については、[Tags in MoEngage](/ja/user-guide/campaigns-and-channels/getting-started/introduction/campaign-tags) を参照してください。

![](/images/moengage_0bce0e.png)

### コンバージョンゴール

Flow のコンバージョンをトラッキングするためのコンバージョンを定義します。Flow に構成されたコンバージョンゴールは、その Flow に含まれるすべてのキャンペーンのコンバージョンゴールとして扱われます。

<Info>
  - 1 つの Flow に 5 つのコンバージョンゴールを追加できます。詳細については、[Add multiple goals to flows](/ja/user-guide/flows-cross-channel-messaging/create/actions-in-flows/add-multiple-conversion-goals) を参照してください。
  - ゴールを設定せずに Flow を公開することもできます。
</Info>

次の項目を選択してゴールを定義します。

| フィールド | 説明 |
| --- | --- |
| Goal name | ゴールを管理・識別するためのゴール名を入力します。 |
| Event name | ゴールのトラッキングに使用する定義済みイベントをドロップダウンから選択します。詳細については、[Events and Attributes](/ja/user-guide/data/event-data/derived-events-and-attributes) を参照してください。 |
| Attribute | トラッキング対象のゴールを絞り込むための定義済み属性、条件、値をドロップダウンから選択します。詳細については、[Events and Attributes](/ja/user-guide/data/event-data/derived-events-and-attributes) を参照してください。 |
| Track above goal for | アトリビューションウィンドウを設定します。これは、アトリビューションタイプに基づき、インプレッションまたはクリックの後にコンバージョンゴールをトラッキングする期間です。<br /><img alt="Attribution" src="/images/moengage_6259fd.png" /> |
| Exit on conversion | このトグルをオンにすると、ユーザーがプライマリコンバージョンゴールを達成した時点で、そのユーザーを Flow から強制的に離脱させます。<br /><img alt="ExitOnConversion.png" src="/images/moengage_630a4f.png" /> |

**\+ New goal** をクリックして、さらにゴールを追加します。

<Info>
  Flow を公開する前であれば、**Settings** をクリックして、ゴール、タグ、コンバージョン時のユーザー離脱設定をいつでも変更できます。詳細については、[Flow Settings](/ja/user-guide/flows-cross-channel-messaging/create/configure-flows/flow-settings) を参照してください。

  ![Screenshot\_2022-07-31\_at\_1.40.29\_AM.png](/images/moengage_4e0f6e.png)
</Info>

**Next** をクリックして、[When will users enter the flow](#when-will-users-enter-the-flow) ステップに進みます。

## ユーザーが Flow に入るタイミング

ユーザーが Flow に入るタイミングを定義するには、次のいずれかを選択します。

<Tabs>
  <Tab title="On Event Trigger">
    トリガー条件を定義するには、次の操作を行います。

    - **If user** セクションで、
      1. **Primary trigger event (s)** の **Has Executed** フィールドで、リストから **Select an event** を使用してイベントを選択し、ユーザーが Flow に入るためのプライマリトリガーイベントを定義します。
      2. **\+ Add alternate trigger event** をクリックして、**Primary trigger event(s)** に複数のイベントを追加します。これにより、ユーザーはプライマリトリガーイベントに定義されたいずれかのイベントを実行すると Flow に入ることができます。(任意)
      3. **\+ Attributes** をクリックして、追加したプライマリトリガーのいずれかに属性を追加します。(任意) <img alt="bau 1.png" src="/images/moengage_b55758.png" />

    セカンダリトリガー条件を定義するには、次の操作を行います。

    - **AND** セクションで、
      1. **\+ Add secondary trigger event** をクリックします。
      2. **Secondary trigger event(s)** で、要件に応じて **Has Executed** または **Has Not Executed** を選択し、**Select an event** リストからイベントを選択して、ユーザーが Flow に入るためのプライマリトリガーイベントとあわせてセカンダリトリガーイベントを定義します。
      3. **\+ Add more trigger event** をクリックして、**Secondary** **trigger event(s)** に複数のイベントを追加します。(任意)
      4. **\+ Attributes** をクリックして、追加したセカンダリトリガーのいずれかに属性を追加します。(任意)\
         ユーザーの過去の行動に基づいて、パーソナライズされた動的なチェックを追加できます。詳細については、[Linked Conditions](/ja/user-guide/flows-cross-channel-messaging/create/create-flows/linked-conditions) を参照してください。<img src="/images/moengage_3c7c93.png" alt="bau123.png" />
    - **THEN enter the user** セクションで、
      1. **Immediately** を選択すると、ユーザーはすぐに Flow に入ります。\
         これは、Flow にプライマリトリガーが定義されている場合にのみ適用されます。
      2. **With Delay** を選択し、次の詳細を指定すると、ユーザーは一定の時間をおいて Flow に入ります。
         1. 時間の値を入力し、分、時間、または日を選択します。入力できる値は 5 分から 30 日まで (両端を含む) です。
         2. **Before** または **After** を選択して、指定した時間間隔の前と後のどちらでユーザーを Flow に入れるかを指定します。
         <Info>
           複数のプライマリトリガーイベントを追加した場合、時間間隔の指定には **After** オプションのみ使用できます。ただし、プライマリトリガーイベントを 1 つだけ追加した場合は、**Before** と **After** の両方のオプションを使用して遅延をパーソナライズできます。
         </Info>
         3. この時間計算の基準となる属性を選択します。詳細については、[こちら](/ja/user-guide/campaigns-and-channels/getting-started/triggers/event/create-an-event-triggered-campaign)をクリックしてください。<img src="/images/moengage_9d2753.png" alt="bau1234.png" />

    <Note>
      トリガーイベントがユーザーのマージと重なる可能性がある場合は、**With Delay** (約 10 分) を使用してください。これは、ログイン、登録、確認のイベントでよく見られるもので、トリガーの発火直後に匿名ユーザーが既知のユーザーになることがよくあります。遅延を設けることで、ユーザーが Flow に入る前にマージが完了する時間を確保できるため、イベントのトリガー直後にマージされたユーザーがスキップされることはありません。
    </Note>

    **Flow Schedule Settings** **Start** で、次のいずれかのオプションを選択して Flow をトリガーします。

    | フィールド | アクション |
    | --- | --- |
    | **As soon as possible** | Flow をすぐにトリガーします。次の項目を選択できます。<ul><li>**Campaign time zone** - キャンペーンを送信するタイムゾーンです。</li><li>**Ends**: End オプションを選択して Flow の終了時刻を選択し、Flow への新規エントリーを停止するタイミングを制御できます。次のオプションを使用できます。<ul><li>**Never**: Flow は終了しません。</li><li>**On**: **End date** および **End time** フィールドで指定した終了日に Flow が終了します。</li></ul></li></ul> |
    | **At specific date and time** | 指定した時刻、タイムゾーン、または予測時刻に Flow をトリガーします。このセクションでは、特定の日時にキャンペーンを送信でき、次のフィールドがあります。<ul><li>**Campaign time zone** - キャンペーンを送信するタイムゾーンです。</li><li>**Start date** - キャンペーンを送信する日付です。</li><li>**Send time** - キャンペーンを送信する時刻です。キャンペーンを送信する時間帯に応じて am または pm を選択します。</li><li>**Ends**: End オプションを選択して Flow の終了時刻を選択し、Flow への新規エントリーを停止するタイミングを制御できます。次のオプションを使用できます。<ul><li>**Never**: Flow は終了しません。</li><li>**On**: **End date** および **End time** フィールドで指定した終了日に Flow が終了します。</li></ul></li></ul> |
  </Tab>
  <Tab title="At fixed time">
    Flow を固定時刻にスケジュールするには、次の操作を行います。**User entry** で、次のいずれかのオプションを選択して Flow をトリガーします。

    <Note>
      時間ベースの Flow では、ユーザーが一括で Flow に入ります。時間ベースの Flow の各インスタンスまたは各実行では、最大 1,000 万人のユーザーを Flow に入れることができます。
    </Note>

    <Info>
      **初回送信の計算方法**

      Daily、Weekly、Monthly の繰り返しでは、初回送信は、Start Date と Send Time 以降で、選択したパターンに該当する最も早い日時になります。そのサイクル内でパターンに一致する日が Start Date より前にすでに過ぎている場合、MoEngage はその日をスキップし、初回送信を次に一致するサイクルに移動します。さかのぼって送信されることはなく、Start Date がパターンに一致しない限り、Start Date 当日に送信されることもありません。

      スケジュールの構成が完了すると表示される確認メッセージで、計算された日付を確認してください。

      ![Monthly の Periodic Flow で計算された初回送信日を示す確認行](/images/periodic-flow-confirmation-send-date.png)

      公開前にこの行を確認してください。この行には常に現在の構成が反映されます。
    </Info>

    | フィールド | アクション |
    | --- | --- |

### グローバル離脱条件

**Flow Exit** で **Exit based on conditions** トグルをオンにして、Flow の離脱条件を定義します。ユーザーが定義された条件を満たすと、MoEngage はユーザーが Flow 内のどこにいるかにかかわらず、最後に確認された位置からそのユーザーを削除します。離脱条件はすべての Flow タイプ (例: **On event trigger**、**At fixed time**、**On flow exit**、**On business event trigger**) に適用されます。

![Screenshot 2024-07-29 at 3.35.49 PM.png](/images/moengage_4254d7.png)

MoEngage は、ユーザーが Flow に入った時点から、次のような理由で Flow から離脱するまで、これらの条件でユーザーを評価します。

- Flow パス内の離脱ステージを通過した
- 離脱条件を満たした
- Flow に定義されたコンバージョンゴールを達成した

離脱条件は、ユーザーがトリガーしたイベント、またはユーザーについてトラッキングしているユーザープロパティを使用して定義できます。

![Screenshot 2024-07-29 at 3.35.49 PM.png](/images/moengage_bcb619.png)

- **User property**: **User property** タブでは、特定の属性の値を指定することで、ユーザープロパティを使用して離脱条件を定義できます。例:
  - メンバーシップが Gold になったユーザーを削除する (Flow の目的がユーザーを Gold Membership に転換させることに固定されている場合に使用できます)。
- **User behavior**: **User behavior** タブでは、MoEngage でトラッキングされているイベントのリストを使用して離脱条件を定義できます。例:
  - Flow に入った後に何らかの商品を購入したユーザーを削除する
  - Flow に入った後に、カートに追加したものと同じ商品を購入したユーザーを削除する
    - このユースケースや類似のユースケースは、プライマリトリガーイベントと Exit Condition をリンクすることで実現できます。詳細については、[Linked Conditions](/ja/user-guide/flows-cross-channel-messaging/create/create-flows/linked-conditions) を参照してください。
  - 再入荷した商品と同じ商品を購入したユーザーを削除する。

#### サポートされているフィルター

離脱条件は、文字列型、整数型、Boolean 型の条件のみを使用して定義できます。

<Warning>
  MoEngage では、次のフィルターで定義された条件はサポートされていません。

  - Custom segments
  - Affinity segments
  - 配列型と GeoPoint
  - 特殊な日付フィルター (Daily where the hour、Weekly where the day、Monthly where the day、Yearly where the month、Yearly where the date)
  - last n weeks、hours、months
  - n が 30 日以上の last n days
  - Merlin AI ベースの属性

  サポートされていないフィルターを使用すると、エラーメッセージが表示されます。問題を解決するには、サポートされているフィルターを選択する必要があります。

  ![Screenshot 2024-07-29 at 3.43.22 PM.png](/images/moengage_dde3fe.png)
</Warning>

**\+ Add exit condition** をクリックすると、最大 5 つまで条件を追加できます。各条件は他の条件と OR ロジックで評価されます。ユーザーがこれらの条件のいずれかを (順序を問わず) 満たすと、Flow から離脱します。たとえば、ユーザーが最初に Condition 3 を満たした場合、Condition 1 を満たしていなくても Flow から離脱します。

![Screenshot 2024-07-29 at 3.41.39 PM.png](/images/moengage_86366d.png)

各条件内には、サブ条件を追加できます。**\+ Filter** をクリックして、さらに条件を追加します。サブ条件は最大 5 つまで追加できます。各サブ条件は他のサブ条件と AND ロジックで評価されます。ユーザーがすべての条件を満たした場合にのみ、Flow から離脱します。

![Screenshot 2024-07-29 at 3.43.16 PM.png](/images/moengage_f59012.png)

<Info>
  1 つの条件で複数のサブ条件を使用している場合、離脱条件を満たすには、ユーザーは 30 日以内にすべてのサブ条件を順序を問わず満たす必要があります。たとえば、Condition 1 で次のサブ条件を定義したとします。

  - Has Executed App/Site Opened at least 1 time
  - Last Seen Date is on July 25, 2024
  - Last Known City is New York

  ![7.png](/images/moengage_245213.png)

  ユーザーが 2024 年 8 月 1 日に最初の 2 つの条件を満たしても、すぐには Flow から離脱しません。MoEngage は、最後の条件が満たされるまで 8 月 1 日から 30 日間待機します。8 月 31 日より前に満たされた場合、ユーザーは Flow から離脱します。9 月 2 日に満たされた場合は、最初の 2 つの条件が 30 日間の期間外となるため、ユーザーは Flow から離脱しません。
</Info>

Flow を公開した後でも、離脱条件を編集できます。ただし、この場合、MoEngage は Flow の新しいバージョンを作成します。これは One-time Flow には適用されません。

または\
**Previous** をクリックして、[Details and Goals](#details-and-goals) ステップに戻ります。

    このフィルターオプションでは、初回表示日、最終表示日、都市などのユーザープロパティに基づいてユーザーを選択できます。**User property** タブをクリックし、次の操作を行います。

    1. **Select attribute** リストで目的の属性を選択します。これにより、選択した属性に基づくフィルターが有効になります。
    2. ドロップダウンリストで条件付きのフィルターを選択します。たとえば、文字列属性には「is」や「is not」などのフィルター条件があり、整数属性には異なるフィルターがあります。
    3. デフォルトの **Constant value** を使用すると、特定の静的な値でフィルターを完成できます。以下に示すように、**User attribute** (すべてのタイプの Flow に適用可能) または **Business event attribute** (Business Event Triggered Flow のみ) オプションを使用すると、別のユーザー属性またはビジネスイベント属性を使用して条件を定義できます。\
       たとえば、新しい _Thriller_ シリーズの公開を告知し、_Genre_ として _Thriller_ を好むユーザーをターゲットにする Flow を作成するには、次のスクリーンショットを参照してください。<img src="/images/moengage_64e7bc.png" alt="Screenshot 2024-12-19 at 3.53.15 PM.png" /> 詳細については、[Create Segments](/ja/user-guide/segment/create-segments/rule-based-filter-segments) を参照してください。
  </Tab>
  <Tab title="Filter by User Behavior">
    このフィルターオプションでは、「App/Site Opened」、「Viewed Product」などのユーザーの行動やイベントに基づいてユーザーを選択できます。**User Behavior** タブをクリックし、次の操作を行います。

    1. ドロップダウンリストから **User Behaviour** を選択します。
    2. **Select an event** リストでイベントを選択します。
    3. イベントの実行頻度と期間を入力します。
    4. **\+ Attributes** をクリックし、**Select attribute** リストで目的の属性を選択します。これにより、選択した属性に基づくフィルターが有効になります。たとえば、文字列属性には「is」や「is not」などのフィルター条件があり、整数属性には異なるフィルターがあります。
    5. デフォルトの **Constant value** を使用すると、特定の静的な値でフィルターを完成できます。以下に示すように、**User attribute** (すべてのタイプの Flow に適用可能) または **Business event attribute** (Business Event Triggered Flow のみ) オプションを使用すると、別のユーザー属性またはビジネスイベント属性を使用して条件を定義できます。たとえば、新しい _Thriller_ シリーズの公開を告知し、過去 3 日間に _Genre_ が _Thriller_ の作品を 1 回以上視聴したユーザーをターゲットにする Flow を作成するには、次のスクリーンショットを参照してください。<img src="/images/moengage_a52d07.png" alt="Screenshot 2024-12-19 at 5.09.21 PM (1).png" /> 詳細については、[Create Segments](/ja/user-guide/segment/create-segments/rule-based-filter-segments) を参照してください。
  </Tab>
  <Tab title="Filter by User Affinity">
    1. 目的のユーザーイベントまたは属性を選択します。
    2. 次のユーザーアフィニティパラメーターを選択します。
       - **Predominantly**: フィルター条件を指定してアフィニティ属性を選択し、アフィニティ値を指定します。
       - **For a minimum of**: フィルター条件を指定してアフィニティ属性を選択し、アフィニティ値を指定します。
       - **Most no. of times**: 値を入力するか矢印を使用して、上位何パーセントのユーザーかを指定します。
       - **Least no. of times**: 値を入力するか矢印を使用して、下位何パーセントのユーザーかを指定します。
    3. 値を入力するか矢印を使用して、イベント実行の期間を指定します。
    4. **\+ Attributes** をクリックして、フィルターに属性を追加します。詳細については、[Create Segments](/ja/user-guide/segment/create-segments/rule-based-filter-segments) を参照してください。<img src="/images/moengage_e55a72.png" alt="4.png" />
  </Tab>
  <Tab title="Filter by Custom Segment">
    このフィルターオプションでは、カスタムセグメントをターゲットオーディエンスとして選択できます。利用可能なカスタムセグメントのリストから、ターゲットオーディエンスとするカスタムセグメントを選択します。詳細については、[Custom Segments](/ja/user-guide/segment/create-segments/manage-segments) を参照してください。<img src="/images/moengage_8a16cb.png" alt="5.png" />
  </Tab>

### コントロールグループ

キャンペーンを送信するコントロールグループを有効にできます。コントロールグループの詳細については、[Control Group](/ja/user-guide/campaigns-and-channels/getting-started/introduction/control-groups) を参照してください。**Control groups** セクションで、次の操作を行います。

- **Global control group** トグルをオンにすると、Global control group に含まれるユーザーにはキャンペーンが送信されません。詳細については、[こちら](/ja/user-guide/settings/advanced-settings/global-control-group)を参照してください。
- **Flow control group** トグルをオンにすると、この Flow のキャンペーンがランダムに抽出された一部のユーザーに送信されなくなります。詳細については、[こちら](/ja/user-guide/campaigns-and-channels/getting-started/introduction/control-groups)を参照してください。
- Flow に入ったときに Control group としてマークするユーザーの割合を定義します。
- 「**Users part of control group should continue to be part of it for their subsequent entries**」チェックボックスを選択したままにすると、コントロールグループに含まれるユーザーは、以降のエントリーでもコントロールグループに含まれ続けます。\
  詳細については、[Control Group](https://moengage.com/docs/user-guide/campaigns-and-channels/getting-started/introduction/control-groups) を参照してください。

# Flow をデザインして公開する

<Warning>
  Flow のステージ数が 500 を超えると、キャンバスのパフォーマンスが低下します。
</Warning>

1. Flow の構造をデザインするには、**\+** をクリックして、次の要素を Flow に追加します。
   - [Actions](/ja/user-guide/flows-cross-channel-messaging/create/actions-in-flows/add-actions-to-flows)
   - [Conditions](/ja/user-guide/flows-cross-channel-messaging/create/conditions-and-controls-in-flows/branching-of-users-in-flows)
   - [Controls](/ja/user-guide/flows-cross-channel-messaging/create/conditions-and-controls-in-flows/force-move-or-delay-users-in-flows)
2. Flow の構造が完成したら、**Save** をクリックして下書きとして保存します。Flow を公開するための次のアクションは、アカウントの設定によって異なります。
   - Campaign Approval ワークフローが無効の場合は、Flow を直接公開できます。
   - Campaign Approval ワークフローが有効で、キャンペーンの作成、管理、公開の権限を持っている場合は、Flow を直接公開できます。
   - Campaign Approval ワークフローが有効で、**Create & Manage** 権限のみを持っている場合は、Flow を承認申請する必要があります。詳細については、[こちら](#when-will-users-enter-the-flow)を参照してください。

## 承認フロー

<Tabs>
  <Tab title="作成者">
    作成者として Flow を承認申請するには、次の手順を実行します。

    1. Flow のキャンバスページで、右側にある **Actions** ボタンを選択します。
    2. **Actions** リストで **Send for Approval** を選択します。**Send for approval** ポップアップウィンドウが表示されます。\
       MoEngage は Flow 内の構成エラーを特定し、キャンバスの右側にある **Error** パネルに表示します。Flow を承認申請する前に、リストに表示されたすべてのエラーを解決する必要があります。<img src="/images/moengage_fee281.png" />
    3. Flow をレビューして承認するユーザーを選択する必要があります。
       1. **Start typing to filter approvers** ボックスで、[Details and Goals](#details-and-goals) ステップで選択したチームのユーザー (Admin または Manager) を検索します。
       2. Flow をレビューしてもらう各ユーザーの名前の横にある **\+ Add** をクリックします。選択したユーザーは、右側の **Selected Approvers** セクションに表示されます。
    4. **Add yours comment here (optional)** ボックスに、承認者向けのコンテキスト、指示、メモなどのコメントを追加できます。
    5. **Send for approval** をクリックします。<img src="/images/moengage_eae0f5.png" />
    6. 選択した承認者には、Flow がレビュー待ちであることを知らせるメール通知が届きます。Flow が **Under Review** 状態の間は、次のオプションを使用できます。
       1. **Flow を編集する**: **Under Review** の Flow を編集できます。編集後、**Update and send for approval** をクリックして、Flow を再度レビューに送信する必要があります。その後、手順 3 から 5 を繰り返します。<img src="/images/moengage_e2bbe4.png" />
       2. **承認者にフォローアップする**: フォローアップするには、**Remind Reviewers** をクリックします。承認者にリマインダー通知が届きます。<img src="/images/moengage_d3ebfe.png" />
  </Tab>
  <Tab title="レビュー担当者">
    Flow をレビューするには、次の手順を実行します。

    1. MoEngage から届いたメールを開き、**Click to** **Review Flow** をクリックします。<img src="/images/moengage_bc4e65.png" /> または\
       **All Flows** ページに移動します。**Select status** フィルターで **Under Review** チェックボックスを選択します。承認待ちの Flow のリストが表示されます。
    2. 開きたい Flow をクリックします。<img src="/images/moengage_faf4b3.png" /> すべてのステージの構成を確認して、Flow をレビューする必要があります。レビューが完了し、Flow に修正が不要な場合は、次の手順を実行します。
       1. Flow のキャンバスページで、右側にある **Approve and Publish** をクリックします。<img src="/images/moengage_f03d38.png" /> **Approve & publish** Flow ポップアップウィンドウが表示されます。
       2. **Add yours comment here** **(optional)** ボックスに、作成者へのコメントを追加します。
       3. **Approve & publish** をクリックします。<img src="/images/moengage_95d106.png" /> 公開すると、Flow の種類 (例: **On event trigger** または **At fixed time**) に応じて、Flow は **Active** または **Scheduled** になります。作成者と他の承認者には、Flow が公開されたことを知らせるメール通知が届きます。Flow に修正が必要な場合は、次の手順を実行する必要があります。
          1. Flow のキャンバスページで、右側にある **Actions** ボタンを選択します。
          2. **Actions** リストで **Reject** を選択します。<img src="/images/moengage_f2de7a.png" /> **Reject the flow** ポップアップウィンドウが表示されます。
          3. **Add your comments here** ボックスに、作成者が編集を行う必要がある理由を説明するコメントを追加する必要があります。
          4. **Reject flow** をクリックします。<img src="/images/moengage_53a6a9.png" /> Flow を却下すると、作成者と他の承認者には、コメントを含むメール通知が届きます。

    <Info>
      - Flow が却下された場合、作成者は承認者のコメントをメール通知と [Flow Audit logs](/ja/user-guide/flows-cross-channel-messaging/create/create-flows/editing-a-flow) で確認できます。
      - 要求された変更を行った後、承認プロセスに従って Flow を再申請できます。詳細については、[こちら](#the-approval-flow)を参照してください。
    </Info>
  </Tab>
</Tabs>
