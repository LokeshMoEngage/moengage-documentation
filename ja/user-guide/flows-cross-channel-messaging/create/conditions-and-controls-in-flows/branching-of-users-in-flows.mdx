# 概要

フロー内で特定の条件に基づいてユーザーを分割してエクスペリエンスをパーソナライズしたり、実験のためにユーザーをランダムに分割したりしたい場合がよくあります。MoEngage では、ユーザーを分割する次の方法を提供しています。

| 分割方法 | 説明 |
| --- | --- |
| Check User Attribute | このステージでは、定義したユーザープロパティのチェックを満たすかどうかに基づいてユーザーを分割できます。 |
| Has Done Event | このステージでは、定義したアクションベースのチェックを満たすかどうかに基づいてユーザーを分割できます。 |
| Conditional Split | このステージでは、ユーザープロパティとアクションの組み合わせに基づいてユーザーを分割でき、最大 25 個の異なるパスを作成できます。 |
| Campaign-Based Conditions | フローに _Action_ ステージを追加した後に表示されるカスタムステージです。以前に追加したキャンペーンに関連する条件に基づいてユーザーを分割できます。 |
| A/B Split | このステージでは、定義した割り当て率に基づいてユーザーをランダムに分割し、実験を行うことができます。 |
| Intelligent Path Optimizer | このステージでは、MoEngage の Merlin AI インテリジェンスを使用してユーザーをランダムに分割し、実験を支援します。 |

# ユースケース

### 条件に基づいてユーザーを分割する

条件に基づいてユーザーを分割するユースケースは次のとおりです。

- 優先言語に基づいてユーザーを分割したい場合は、_Conditional Split_ を追加します。
- 特定のアクションを実行したユーザーをフローから退出させたい場合は、_Has Done Event_ ステージを追加します。
- ユーザープロパティが特定の値を満たすユーザーをフローから退出させたい場合は、_Check User Attribute_ ステージを追加します。
- 最後のメールがユーザーに送信されたかどうかに基づいてユーザーを分割したい場合は、_On Send Email Message_ ステージを追加します。

### ユーザーをランダムに分割する

ユーザーをランダムに分割するユースケースは次のとおりです。

- ユーザーベースに効果的なチャネルタイプを見つけるためにユーザーをランダムに分割したい場合は、_A/B split_ ステージを追加します。

<Info>
  Entry Criteria に基づいてユーザーを分割したい場合は、Conditional Split または Has Done Event ステージを追加し、**Flow Entry Events** カテゴリーのオプションを選択します。このオプションを選択すると、MoEngage はユーザーのパスを決定する際に、ユーザーがフローに入るきっかけとなったイベントを考慮します。
</Info>

# 条件ステージを追加する

条件ステージを追加するには、次の手順を実行します。

1. MoEngage Canvas で **\+** をクリックします。
2. Add stage ダイアログボックスで、次のいずれかを実行します。
   - 検索バーでステージを直接検索します。検索結果から、追加するオプションをクリックします。たとえば、「conditional」と検索すると、**Conditional Split** オプションが表示されます。<img src="/images/moengage_bdc71d.png" alt="検索による追加.gif" />
   - **All stages** タブで次の操作を行います。
     1. **Conditions & controls** で、カテゴリーをクリックして追加できる条件ステージを確認します。
        | カテゴリー | 利用可能なステージ |
        | --- | --- |
        | **AI TOOLS** | Intelligent path optimizer |
        | **USER CONDITIONS** | <ul><li>Check User Attribute</li><li>Has done event</li></ul> |
        | **SPLIT USER PATH** | <ul><li>Conditional Split</li><li>A/B Split</li></ul> |
        | Action conditions | <ul><li>Has received push notifications</li><li>Has dismissed push notifications およびその他のキャンペーンベースの条件</li></ul> |
     2. 追加するステージをクリックします。<img src="/images/moengage_c69347.png" alt="カテゴリーからの追加.gif" />
        <Info>
          よく使用される 5 つのステージは、**All stages** タブの **Frequently Used** セクションに表示されます。利用可能なステージの一覧はワークスペースに応じて動的に変わります。必要なステージをクリックしてフローに追加します。<img src="/images/moengage_5e19dd.png" alt="image.png" />
        </Info>
   - **Conditions & controls** タブで、追加するステージをクリックします。<img src="/images/moengage_1ce0e5.png" alt="タブからの追加.gif" /> 選択したステージがキャンバスに追加されます。

      - ブランチを削除することはできません。

## ユーザーをランダムに分割する

<Tabs>
  <Tab title="A/B Split">
    A/B Split を使用すると、最大 5 つのフローパスのバリエーションをテストして、最もパフォーマンスの高いオプションを特定できます。これらのフローパスで、異なるチャネル、同じチャネルでの異なるメッセージ、異なるメッセージ頻度を試すことができます。

    実験を設定し、フローを公開した後に各ブランチのパフォーマンスを分析して、勝者ブランチに有利になるようにユーザー配分を変更できます。これにより、フローに入るほとんどのユーザーが、最もパフォーマンスの高いブランチに進むようになります。

    <Info>
      **インテリジェンスを活用する**

      フローに入るユーザーが増えるにつれて、最もパフォーマンスの高いブランチに有利になるようにユーザー配分を自動的に調整するよう、MoEngage Flows を設定できます。

      詳細については、[Intelligent Flow Path optimizer](#overview) を参照してください。
    </Info>

    ### テストのセットアップ

    フローステージのコントロールカテゴリーから、フローの任意の場所に A/B Split を追加します。

    ![A.png](/images/moengage_400362.png)

    - 実験するブランチの数を追加します。1 つの A/B Split ステージに最大 5 つのブランチを追加できます。
    - 各ブランチのユーザー配分を設定します。各ブランチのバリエーション率は 0～100 の範囲で設定できます。
    - すべてのブランチのバリエーション率の合計が 100 になるようにしてください。

    <Tip>
      **あらゆるものをテストする**

      A/B Split はフロー内の任意のステージで使用でき、1 つのフローに最大 10 個の A/B Split を追加できます。
    </Tip>

    キャンバス上でブランチを区別できるように、各ブランチに異なる表示名を付けてください。

    ### パフォーマンスを把握する

    ユーザーがフローに入るにつれて、各ブランチのパフォーマンスがキャンバス上で更新されます。<img src="/images/moengage_ea3566.png" alt="Screenshot_2021-01-11_at_11.34.07_PM.png" />

    - **Email (50%)** は、ブランチの表示名と、そのブランチに設定されたユーザー配分 (この例では 50) を示します。
    - **4 Done** は、このブランチを通過したフロートリップの数です。
    - **Converted trips** は、少なくとも 1 回のコンバージョンにつながったブランチトリップの数です。上記の例では、ブランチのコンバージョン率は 75% です。
    - **Engagement Score** は、ブランチのエンゲージメントを反映する派生指標です。数値が高いほどエンゲージメントが良好です。エンゲージメントスコアの計算方法の詳細については、[こちら](/ja/user-guide/flows-cross-channel-messaging/create/intelligence-in-flows/intelligent-path-optimizer)を参照してください。

    <Info>
      **ブランチとは**

      - A/B Split ノードからフローの退出ステージまでのすべてのアクションステージが、ブランチのパフォーマンスのトラッキング対象に含まれます。
      - ブランチが複数のブランチに分岐する場合、分岐後のブランチは親ブランチの一部と見なされます。
      - ブランチがある時点で別のブランチに合流する場合、共通のフローパスは合流する両方のブランチの一部と見なされます。
    </Info>

    ### 勝者を見つける

    _split node_ のレポートで、ブランチのパフォーマンスを分析および比較できます。キャンバス上のステージにカーソルを合わせてレポートオプションをクリックするか、フローの詳細な統計ページの split node stats セクションに移動し、一覧から特定の split node でフィルタリングします。

    ![Screenshot\_2021-01-12\_at\_10.20.29\_AM.png](/images/moengage_b8addd.png)

    ブランチのパフォーマンスを分析した後、設定したユーザー配分を編集して、次にフローに入るほとんどのユーザーが最もパフォーマンスの高いブランチに進むようにできます。
  </Tab>
  <Tab title="Intelligent path optimizer">
    Intelligent Path optimizer を使用すると、最大 5 つのブランチで A/B テストを実施でき、Merlin AI が最もパフォーマンスの高いパスに向けてユーザー配分を自動的に調整し続けます。各ブランチでどのチャネルを使用するか、どのようなメッセージ頻度にするかの実験に集中し、ユーザー配分の最適化は Merlin AI に任せることができます。

    ユーザー配分の最適化を Merlin AI に任せる際は、フローで最大化したい指標も設定する必要があります。指標は Engagement、Conversion、またはその両方から選択できます。

    <Info>
      **有力な代替手段** ユーザー配分を手動で管理したい場合は、A/B Split を選択できます。詳細については、[こちら](/ja/user-guide/flows-cross-channel-messaging/create/experimentation/ab-split-in-flows)を参照してください。
    </Info>

    ### Intelligent Path Optimizer を設定する

    有力な代替オプションを試したいフローの任意の場所に、Intelligent Path Optimizer を追加できます。

    キャンバス上で識別できるように、各ブランチに固有の名前を付けてください。各ステージで最大 5 つのフローパスを試すことができ、各フローにはこのようなステージを最大 5 つ追加できます。

    ### 最大化する指標の選択

    MoEngage Flows はさまざまなユースケースに対応でき、それらは大きく次の 2 つのカテゴリーに分類できます。

    - ユーザーエンゲージメントの向上
    - ユーザーコンバージョンの向上

    そのため、フローを最適化する際、MoEngage は最大化する指標の選択に基づいて、最適化を _フローの目標_ に合わせます。

    ### 仕組み

    最初はユーザーが均等に配分され、MoEngage がより多くのパフォーマンス結果を取得するにつれて、Merlin AI は最もパフォーマンスの高いブランチに向けてユーザー配分を調整し続けます。最大化するように設定された指標に基づいて、MoEngage は実験に含まれる各ブランチのさまざまなパフォーマンス統計をトラッキングします。

    - **コンバージョンの最大化**\
      MoEngage は各ブランチについて、コンバージョンしたブランチトリップ数 / ブランチの総トリップ数の比率を最大化することを目指します。これは大まかに **Branch CVR** とも呼ばれます。\\
      <Warning>
        **注意点** MoEngage は、ブランチの総コンバージョン数を最大化する指標として使用していません。これは、ブランチ上で複数回コンバージョンするユーザーが優遇され、アクションキャンペーンの多いブランチも有利になるためです。どちらも、最終的に勝者となるブランチが最も最適化されたブランチであることを必ずしも意味しません。\
        MoEngage は、コンバージョンにつながる最も一般的なユーザー行動に基づいて、最適化されたブランチを見つけようとします。
      </Warning>
    - **エンゲージメントの最大化**\
      コンバージョンの計算と同様に、MoEngage は各ブランチの総エンゲージメントではなく、エンゲージしたトリップの総数を最適化することを目指します。そのため、MoEngage は各ブランチにエンゲージメントスコアを付与し、ブランチの総クリック数やメール開封数ではなく、そのスコアを最大化しようとします。\
      ブランチのエンゲージメントスコアは、少なくとも 1 つのアクションキャンペーンからクリックを獲得したブランチトリップ数 (BTC) \+ メール開封のみを獲得したブランチトリップ数 (BTO) の 10 分の 1 と、ブランチの総トリップ数との比率です。**Engagement Score** **= (BTC\+ 1/10(BTO))/Total Branch Trips**

    <Info>
      **ご協力のお願い** エンゲージメントスコアにより、MoEngage は最もパフォーマンスの高いブランチを最適化できます。このブランチは、必ずしもクリック数やメール開封数が最も多いブランチとは限りません。

      このアプローチがユースケースや期待に合わない場合は、[product@moengage.com](mailto:product@moengage.com) までお問い合わせください。
    </Info>

    - **エンゲージメントとコンバージョンの組み合わせの最大化**\
      MoEngage は各ブランチについて、Branch CVR と Engagement Score を組み合わせます。エンゲージメントの獲得よりもコンバージョンの獲得の方が重要であるため、Branch CVR に重点が置かれます。そのため、この場合の最大化指標は **Branch CVR \+ 1/10( Engagement Score)** になります。

    ユーザーがパスオプティマイザーステージに到達すると、Merlin AI は最もパフォーマンスの高いブランチに最大数のユーザーを配分します。

    <Tip>
      **実験を続ける**

      より多くのユーザーがフローを通過するにつれて、最もパフォーマンスの高いブランチは随時変わる可能性があるため、あるブランチのパフォーマンスが優れていると判断された場合でも、Merlin AI はパフォーマンスの低いブランチへのユーザー配分を停止しません。
    </Tip>

    ### パフォーマンスを分析する

    より多くのユーザーがフローを通過するにつれて、各フローブランチのパフォーマンスがフローキャンバス上で更新されます。

    ![Screenshot\_2021-01-11\_at\_11.27.51\_PM.png](/images/moengage_821e17.png)

    - ブランチに対してどの指標が最大化されているかに関係なく、各ブランチの **Engagement score** も表示されます。

    </Info>

    ![mceclip0.png](/images/moengage_a1004b.png)
  </Tab>
