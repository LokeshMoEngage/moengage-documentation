# 概要

この記事では、マーケターがタイムリーで関連性の高いメッセージをユーザーに届けられるように設計された、MoEngage の 2 つの永続メッセージ配信ソリューションの主な違いについて説明します。

- Cards
- Push Notification Center

どちらも重要なメッセージにいつでもアクセスできるようにしますが、目的が異なり、提供されるカスタマイズのレベルも異なります。

| Cards | Push Notification Center |
| --- | --- |
| <img alt="MoENgageCards.png" src="/images/moengage_b7862d.png" /> | <img alt="moengagepushnotificationcentre.jpg" src="/images/moengage_62c7b2.png" /> |
| アプリ内に永続的なリッチメディアの受信箱を提供し、魅力的なコンテンツフィード、カルーセル、ウィジェットの配信に最適です。最初のエンゲージメント後も重要な情報にアクセスできる状態を保ちます。 | プッシュ通知の履歴を提供し、デバイスの通知ドロワーから閉じた後も重要な通知を表示できるようにします。ユーザー固有のアラートを集約するリポジトリとして機能します。 |
| <ul><li>構造化されたパーソナライズ済みのメッセージをメッセージフィード内に表示します。</li><li>Card は一度配信されると、長期間にわたってユーザーのアプリ体験の一部として残ります。</li><li>2 つの形式で利用できます: <ul><li>**MoEngage Cards Inbox**: 基本的なカスタマイズが可能な構築済みのフィード。</li><li>**Self-Handled Cards Inbox**: MoEngage Cards のペイロードを使用してチームが開発するカスタムフィード。</li></ul></li></ul> | <ul><li>配信されたプッシュ通知の履歴をアプリケーション内に保存します。</li><li>デバイスの通知ドロワーから閉じた後も重要な通知を表示したままにします。</li><li>2 つの形式で利用できます: <ul><li>**MoEngage Push Notification Center**: 基本的なカスタマイズが可能な MoEngage の受信箱。</li><li>**Self-Handled Push Notification Center**: MoEngage のペイロードを使用して構築する完全カスタムの受信箱。</li></ul></li></ul> |
| Cards は以下の用途に使用できます: <ul><li>プロモーションキャンペーン</li><li>ロイヤルティプログラムの更新情報</li><li>パーソナライズされたレコメンデーション</li><li>ゲーミフィケーションとコンテスト</li><li>サービスのお知らせ</li><li>トランザクションメッセージ</li></ul> | Push Notification Center は以下の用途に使用できます: <ul><li>プッシュ通知の履歴を表示可能な状態で保持する</li><li>重要なアラートや更新情報を閉じた後もアクセス可能にする</li><li>サービス通知、リマインダー、コンテストへの参加登録、プロモーションアラートを配信する</li></ul> |

# 機能

以下の表は、Cards と Push Notification Center の機能を比較したものです。

|  | Cards | Push Notification Center |
| --- | --- | --- |
| コンテンツタイプ | テキスト、画像、アイコン、GIF、インタラクティブな Call-to-Action(CTA)をサポートするリッチメディア Card。視覚的で魅力的なコンテンツ体験を実現できます。 | 主にテキストベースのプッシュ通知。メディアコンテンツ(画像、GIF)は、Self-Handled Push Notification Center でペイロードを解析する場合にのみサポートされます。 |
| 配信メカニズム | <ul><li>SDK が MoEngage サーバーと同期したとき、または Public Fetch API を使用してバックエンドシステム経由で配信されます。</li><li>これにより、即時のプッシュ通知とは独立して、柔軟なコンテンツの更新と配信が可能になります。</li></ul> | <ul><li>以下を介して即座に配信されます <ul><li>iOS の場合は APNS(Apple Push Notification Service)</li><li>Android の場合は FCM(Firebase Cloud Messaging)</li></ul></li><li>APNS/FCM によるプライマリ配信が失敗した場合は、バックアップ配信メカニズムにより次回のアプリオープン時に配信されます。</li></ul> |
| 到達範囲 | アプリがインストールされ、Cards モジュールを含む MoEngage SDK が統合されたデバイスを持つすべてのユーザーがアクセスできます。コンテンツはすべてのアプリユーザーに表示されます。 | 対象であり、アプリからのプッシュ通知の受信にオプトインしており、Notification Center モジュールを含む MoEngage SDK が統合されたデバイスを持つすべてのユーザーがアクセスできます。ユーザーは通知の許可を付与する必要があります。 |
| 利用可能なトリガーオプション | <ul><li>一括(One-time)</li><li>トリガーベース <ul><li>Event-triggered</li><li>Flow triggered</li></ul></li><li>Periodic</li></ul> | <ul><li>一括(One-time)</li><li>トリガーベース <ul><li>Event-triggered</li><li>Device triggered</li><li>Location triggered</li><li>Business event triggered</li><li>Flow triggered</li></ul></li><li>Periodic</li><li>Inform </li></ul> **注**: Event Triggered Card では、最新のトリガーによる Card が、同じキャンペーンの以前のトリガーによる既存の Card(存在する場合)を上書きします。そのため、ユーザーにはそのキャンペーンの最新の Card のみが表示されます。|
| コンテンツの保持 | <ul><li>メッセージは複数のデバイス間、アンインストール後、ログアウト後も保持されます。</li><li>キャンペーンが更新された場合、コンテンツを更新したり非表示にしたりできます。</li></ul> | <ul><li>メッセージは受信したデバイスにローカルに保存されます。</li><li>メッセージはアンインストール、ログアウト、データ消去後は保持されません。</li><li>メッセージは配信後に更新できません。</li></ul> |
| UI のカスタマイズ | <ul><li>**MoEngage Cards Inbox**: 受信箱レイアウトの基本的なカスタマイズ。定義済みテンプレートと Card レベルの UI カスタマイズをサポートします。</li><li>**Self-Handled Cards Inbox**: Card のデザインと配置を完全に制御できます。</li></ul> | <ul><li>**MoEngage Push Notification Center**: 受信箱レイアウトの基本的なカスタマイズ。</li><li>**Self-Handled Push Notification Center**: プッシュ通知のデザインと配置を完全に制御できます。</li></ul> |
| メディアのサポート | 画像、アイコン、GIF、動画を含むすべてのリッチメディアタイプをサポートします。 | <ul><li>**MoEngage Push Notification Center**: サポートされていません</li><li>**Self-Handled Push Notification Center**: ペイロード経由でサポートされます。</li></ul> |
| インタラクションの追跡 | <ul><li>**MoEngage Cards Inbox**: 配信、インプレッション、クリック、削除を自動的に追跡します。</li><li>**SDK を使用した Self-handled Cards(クライアントサイド)**: インプレッション、クリック、削除を追跡するには SDK 関数が必要です。</li><li>**Fetch API を使用した Self-handled Cards(サーバーサイド)**: サポートされていません。</li></ul> | <ul><li>**MoEngage Push Notification Center**: 配信、インプレッション、クリック、削除を自動追跡します。</li><li>**Self-Handled Push Notification Center**: <ul><li>配信と削除は自動追跡されます。</li><li>クリックは SDK 関数による手動追跡が必要です。</li></ul></li></ul> |
| 配置 | <ul><li>**MoEngage Cards Inbox**: 全画面の Activity、または埋め込み Fragment(Android のみ)。</li><li>**Self-Handled Cards Inbox**: アプリ内のカスタム配置。</li></ul> | <ul><li>**MoEngage Push Notification Center**: 全画面の Activity、または埋め込み Fragment(Android のみ)。</li><li>**Self-Handled Push Notification Center**: アプリ内のカスタム配置。</li></ul> |
| 統合の工数 | <ul><li>**MoEngage Cards Inbox**: 基本的な統合と UI カスタマイズ値の設定が必要です。</li><li>**SDK を使用した Self-handled Cards(クライアントサイド)**: カスタム UI の構築と、UI に反映するための通知ペイロードの解析が必要です。</li><li>**Fetch API を使用した Self-handled Cards(サーバーサイド)**: カスタム UI の構築と、UI に反映するための通知ペイロードの解析が必要です。</li></ul> | <ul><li>**MoEngage Push Notification Center**: 基本的な統合と UI カスタマイズ値の設定が必要です。</li><li>**Self-Handled Push Notification Center**: カスタム UI の構築と、UI に反映するための通知ペイロードの解析が必要です。</li></ul> |
| 最適な対象 | リッチで永続的なアプリ内コンテンツ(フィード、カルーセル、ウィジェット)でユーザーのエンゲージメントを高めたいチーム。 | アプリ内に通知履歴の受信箱を必要とするチーム。 |
| サポートされるキャンペーン機能 | <ul><li>パーソナライズ: 属性ベース、イベントベース</li><li>Card の有効期限オプション <ul><li>インプレッション数ベース</li><li>配信からの日数</li><li>インプレッションからの日数</li></ul></li></ul> | <ul><li>パーソナライズ: 属性ベース、イベントベース、Recommendations、Content API</li><li>A/B テスト</li><li>ロケール</li><li>Notification Center の有効期限オプション - 配信からの日数</li></ul> |
| サポートされるプラットフォーム | <ul><li>**MoEngage Cards Inbox**: Android(Native)、iOS(Native)、Web(Native)</li><li>**SDK を使用した Self-handled Cards(クライアントサイド)**: Android(Native)、iOS(Native)、Web(Native)、React Native、Flutter。</li><li>**Fetch API を使用した Self-handled Cards(サーバーサイド)**: サーバーベースであり、SDK は不要です。</li></ul> | <ul><li>**MoEngage Push Notification Center**: Android(Native)、iOS(Native)。</li><li>**Self-Handled Push Notification Center**: Android(Native)、iOS(Native)、React Native、Flutter。</li></ul> |

MoEngage を使用すると、アプリの顧客体験を向上させる、タイムリーで関連性が高く永続的なメッセージを配信できます。以下を選択できます。

- アプリ内で配信されるリッチでインタラクティブなコンテンツでユーザーのエンゲージメントを高めるには、Cards を選択します。
- 重要なアラートを閉じた後もアクセス可能にしておくには、Push Notification Center を選択します。

メッセージング戦略とユーザーエンゲージメントの目標に最適なソリューションを選択してください。

# よくある質問

<Accordion title="アプリケーションを Web プラットフォームで開発しています。受信箱の構築にはどのチャネルが適していますか?">
  Web ブラウザは Notification Center をサポートしていないため、MoEngage では Web のメッセージ受信箱に Cards を使用することをお勧めします。Cards は Web アプリの受信箱機能に不可欠です。
</Accordion>

<Accordion title="オプトアウトしたユーザーや、プッシュトークンが登録されていないユーザーを含む、アプリケーションのすべてのユーザーに通知を送信したいと考えています。どのチャネルを使用すべきですか?">
  Cards を使用すると、オプトアウトしたユーザーやプッシュトークンを持たないユーザーを含む、すべてのアプリユーザーにリーチできます。Cards は、プッシュ通知の対象でオプトインしているユーザーにもリーチできます。
</Accordion>

<Accordion title="画像や背景色など、通知をカスタマイズする必要があります。これに Cards を使用できますか?">
  はい、MoEngage Cards の受信箱では、通知の画像や背景色をカスタマイズできます。さらに、タイトル、メッセージ、デフォルトアクションもカスタマイズできます。
</Accordion>

<Accordion title="ユーザーがアプリケーションをアンインストールまたはログアウトした後も通知を保持する必要があります。これをサポートするチャネルはありますか?">
  はい、Cards は複数のデバイス間、アンインストール後、ログアウト後もメッセージを保持します。ただし、Notification Center を使用する場合、メッセージはデバイス間、アンインストール後、ログアウト後には保持されません。
</Accordion>

<Accordion title="受信箱のメッセージをパーソナライズするにはどのチャネルを使用できますか?">
  要件に応じて、Cards または Notification Center のいずれかを使用できます。

  - Cards は、属性ベースおよびイベントベースのパーソナライズをサポートしています。
  - Notification Center は、属性ベース、イベントベース、Recommendations、Content API によるパーソナライズをサポートしています。
</Accordion>

<Accordion title="Web アプリケーションで Push Notification Center を使用できますか?">
  Push Notification Center は現在、Android および iOS のネイティブ、React Native、Flutter の各プラットフォームでサポートされています。Web アプリでは利用できません。Web アプリケーションの永続的なメッセージ受信箱には Cards を使用してください。
</Accordion>
