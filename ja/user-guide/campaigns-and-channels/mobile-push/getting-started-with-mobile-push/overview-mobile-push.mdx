# はじめに

プッシュキャンペーンは、アプリまたはウェブサイトの通知を通じてユーザーにアプローチします。MoEngage では、次のタイプのプッシュキャンペーンを提供しています。

<Tabs>
  <Tab title="ワンタイム">
    ワンタイムプッシュキャンペーンは、特定の時刻に単一のメッセージを送信してユーザーとのエンゲージメントを図ります。
  </Tab>
  <Tab title="定期">
    定期プッシュキャンペーンは、特定の時刻と期間に、設定された一連のメッセージを送信してユーザーとのエンゲージメントを図ります。
  </Tab>
  <Tab title="イベントトリガー">
    イベントトリガー型プッシュキャンペーンは、ユーザーが実行した一連のイベントに基づき、適切なタイミングで送信されるメッセージを通じてユーザーとのエンゲージメントを図ります。

    たとえば、ユーザーが特定の商品を閲覧した、またはカートに追加した（ユーザーアクティビティトリガー）にもかかわらず購入しなかった場合、ユーザーのアクションから数分以内にリマインダーメッセージや関連するオファーがトリガーされ、リターゲティングを行います。

    イベントトリガー型キャンペーンの最も一般的なユースケースは次のとおりです。

    - アプリをインストールしたユーザーに送信するウェルカムメッセージ
    - 初回購入の促進またはユーザーのアクティベーションの促進
    - カート放棄
    - 閲覧放棄
    - サブスクリプションの離脱
    - 支払いの離脱

    <Info>
      イベントトリガー型プッシュキャンペーンは、スケジュール型プッシュキャンペーンと比較して最大 4 倍のコンバージョンを促進できます。
    </Info>
  </Tab>
  <Tab title="デバイストリガー">
    デバイストリガー型プッシュキャンペーンは、ユーザーのアクションによってイベントがトリガーされるたびにデバイスに送信されるメッセージです。メッセージはイベントをトリガーしたデバイスにのみ、リアルタイムで配信されます。

    メッセージは SDK でトラッキングされたユーザーアクションに対してのみトリガーされ、サーバー間イベントや MoEngage バックエンドでトリガーされたイベントではトリガーできません。デバイストリガー型プッシュキャンペーンには次のタイプがあります。

    - オンラインユーザーによるイベントのトリガー
    - オフラインユーザーによるイベントのトリガー

    デバイストリガーは、ユーザーがアプリを離れようとしたタイミングでユーザーを呼び戻すために効果的に使用されます。

    キャンペーンの作成時には、次の配信制御方法を利用できます。

    - **Maximum times to show the message from the same campaign**：顧客のライフタイム中にメッセージが表示される回数を制限します。この値は、デバイスのキャッシュがクリアされたとき、またはアプリが再インストールされたときにリセットされます。0 に設定した場合この設定は適用されず、メッセージは（他の制御条件を満たすまで）無制限に表示されます。
    - **Minimum delay between two messages from the same campaign**：ユーザーエクスペリエンスを向上させるため、マーケターは同じキャンペーンからの 2 つのメッセージの間に最小の遅延時間を追加できます。遅延時間が経過する前に別のメッセージが生成された場合、そのメッセージは配信されません。
    - **Expiry time for sync data**：以前に同期されたキャンペーンを定期的に削除し、古いメッセージが長期間配信され続けないようにします。たとえば、同期されたキャンペーンは、再度同期が行われない限り、設定された 7 日間が経過すると配信されなくなります。
    - **Ignore Frequency Capping**：緊急性が高く、チャネルのキャッピングポリシーを無視して常に配信する必要があるメッセージに使用します。
    - **Ignore DND period**：緊急性が高く、アカウントレベルで設定されたおやすみモード（Do Not Disturb）期間中にトリガーが生成された場合でも常に配信する必要があるメッセージに使用します。
    - **Serve in offline mode**：選択すると、ユーザーがインターネットに接続されていない状態（オフラインモード）でイベントをトリガーした場合でもメッセージが配信されます。

    ### オンライントリガー

    オンライントリガーは、エンドユーザーがオンラインの状態でトリガーイベントを実行したときに配信されます。すべての条件がリアルタイムでチェックされ、対象となるユーザーに通知が表示されます。

    ### オフライントリガー

    デバイストリガーは、エンドユーザーがオフライン、つまりインターネットに接続されていない場合でも、トリガーイベントに対してメッセージを配信できます。

    オフライントリガーは、以前に同期されたメッセージを配信します。メッセージの同期は、インターネットに接続されたユーザーが MoEngage SDK を組み込んだアプリケーションを起動したときに行われます。

    オフライントリガーは、最後に同期されたデータに基づいて配信されます。オフライントリガーメッセージの配信には、次の制限があります。

    - **Segmentation**：オフライントリガーは、同期時にキャンペーンのセグメンテーション条件を満たしている、または満たしていないユーザーに基づいて判定されます。たとえば、キャンペーンの同期時にユーザーがキャンペーン C1 の対象だったとします。その後ユーザーがオフラインになってトリガーイベントを実行した場合、そのユーザーにメッセージが配信されます。
    - **Frequency capping**：配信されるメッセージ数に上限はありません。イベントがトリガーされるたびに、ユーザーにメッセージが配信されます。
    - **Personalization**：イベントのパーソナライゼーションはオフラインでは機能しません。その他のパーソナライゼーションは、以前に同期された値に基づいて機能します。
    - **Campaign Performance**：オフライントリガーメッセージのインプレッションやクリックなどの統計情報は、ユーザーがインターネットに接続した後に MoEngage サーバーに登録されます。
    - **Campaign Editing**：初回の同期後にキャンペーンが編集された場合、ユーザーが初回同期後にアプリを開かずにオフラインになると、オフライントリガーは以前の設定に従って配信されます。
 
  </Tab>
  <Tab title=" ロケーショントリガー">
    ユーザーの位置情報を活用して、関連性の高いコンテンツでエンゲージメントを図るターゲットキャンペーンを送信することもできます。たとえば、空港や駅に到着したユーザーに対しては、その都市のホテルやタクシーの予約アプリでエンゲージメントを図ることが重要です。
    
    ロケーショントリガー型プッシュキャンペーンは、すべてのユーザーが特定の場所（たとえば空港）の周囲に事前定義された範囲に入る、出る、または滞在したときにトリガーされます。現在、ロケーショントリガー型キャンペーンは Android および iOS プラットフォームで利用でき、ジオフェンスの条件を満たすすべてのユーザーがキャンペーンを受信します。
  </Tab>
</Tabs>
