# 概要 - プッシュ許可

プッシュ通知の許可は、アプリがユーザーのデバイス上で取得するアプリレベルの許可です。この許可は、ユーザーの通知トレイにプッシュ通知を表示するために必要です。この許可がオフになっている場合、送信した通知はユーザーに表示されず、バックグラウンドでアプリにサイレントに配信されます。

![PushPermissions.png](/images/moengage_4f133e.png)

# プッシュ許可の仕組み

Android 12 以前のバージョンではアプリに通知送信の許可が自動的に付与されますが、Android 13 以降の OS バージョンでは、アプリが通知を送信する前にユーザーに許可をリクエストする必要があります。

- **Android 12 以前の OS バージョンのデバイス**：アプリには通知を送信する許可が自動的に付与されます。つまり、ユーザーはアプリからの通知送信に明示的な許可を与える必要がなく、デフォルトでオプトインされています。
- **Android 13 以降の OS バージョンのデバイス** - プッシュ通知の許可は Android 13 の新機能で、アプリは通知を送信する前にユーザーに許可をリクエストする必要があります。ユーザーが Android 13 以降のデバイスにアプリをインストールした場合、ユーザーが許可を付与するまで、アプリは通知を送信できません。

さまざまな Android バージョンでのプッシュ許可の仕組みは次のとおりです。

<Tabs>
  <Tab title="Android 13 以降をターゲットとするアプリ">
    Android 13 以降をターゲットとするアプリでは、この許可の付与方法をより細かく制御できます。

    Android 13 互換モードでのプッシュ通知許可の仕組みは次のとおりです。

    - アプリは、許可を付与するためのプロンプトをユーザーに表示するタイミングと場所を制御できます。
    - ユーザーが許可を付与すると、アプリはユーザーに通知を送信できるようになります。
    - ユーザーが許可を拒否または無視すると、アプリはユーザーに通知を送信できません。
    - ユーザーが許可を明示的に 2 回拒否した場合、ユーザーがアプリを再インストールしない限り、アプリは再度ユーザーにプロンプトを表示できません

    Android 13 互換モードでのプッシュ通知許可の仕組みは次のとおりです。

    - アプリが初めて通知チャネルを作成すると、ユーザーに許可の付与を求めるプロンプトが表示されます。
    - ユーザーが許可を付与すると、アプリはユーザーに通知を送信できるようになります。
    - ユーザーが許可を拒否または無視すると、アプリはユーザーに通知を送信できません。その後、ユーザーがアプリを再インストールしない限り、再度プロンプトは表示されません。

この許可は、再インストールやデータの消去のたびにリセットされます。OS のアップグレード時には、1 つの例外を除いてこの許可は保持されます。ユーザーがデバイスを Android 12 から Android 13 にアップグレードした場合：

- Android 12 でアプリに許可がなかった場合、Android 13 にアップグレードした後、ユーザーが許可を付与するまでアプリは通知を送信できません。
- Android 12 でアプリに許可があった場合、Android 13 にアップグレードした後、アプリは一時的な許可によって通知を送信できます。この一時的な許可は、アップグレード後にユーザーが初めてアプリを開くまで有効です。ユーザーがアプリを開くと許可はリセットされ、ユーザーが許可を付与するまでアプリは通知を送信できません。

# プッシュ許可のトラッキング

Android のプッシュ通知のオプトイン/オプトアウトのトラッキングを有効にするには、MoEngage Core SDK バージョン 12.3.01 以降にアップグレードしてください。MoEngage SDK は、デフォルトでデバイスのオプトインステータスをトラッキングします。ユーザーのデバイスのオプトインステータスは、「Reachability Push Android」ユーザー属性でトラッキングできます。

## ユーザーレベルでのプッシュ許可ステータスのトラッキング

| Reachability Push Android 属性値 | リーチャビリティの説明 |
| --- | --- |
| 202 - Not reachable due to Opt-out | プッシュの対象となるすべての Android デバイスでプッシュ通知の受信をオプトアウトしたユーザーのリーチャビリティ値です。これらのユーザーはリーチ可能とは見なされなくなり、キャンペーンのターゲットになりません。 |
| 201 - Reachable and opted in | 少なくとも 1 つの Android デバイスでプッシュ通知の受信にオプトインしたユーザーのリーチャビリティ値です。 |
| 200 - Reachable and opt-in status unknown | 古い SDK バージョンを使用しているためにオプトイン/オプトアウトの設定がトラッキングされていないユーザーのリーチャビリティ値です。これらのユーザーはリーチ可能と見なされ、プッシュ通知の送信が試行されますが、一部のユーザーはオプトアウトしている可能性があり、通知を確認できない場合があります。_オプトイン/オプトアウトのトラッキングは、MoEngage Core SDK バージョン 12.3.01 以降でサポートされています。_ |

## ユーザーレベルでのプッシュ許可の変更のトラッキング

Android のプッシュ許可の変更に関するイベントは次のとおりです。

| 名前 | 説明 | プラットフォーム |
| --- | --- | --- |
| Subscribed to Push | ユーザーがプッシュ通知をサブスクライブしたときにトラッキングされます。 | Android |
| Unsubscribed to Push | ユーザーがデバイスのプッシュ許可を Subscribed から Unsubscribed に変更したときにトラッキングされます。注: _デフォルトで許可が拒否されているデバイスでは、このイベントは生成されません。_ | Android |

<Info>
  これらのイベントは、デバイスのオプトインステータスが変更された場合、またはユーザーが許可を明示的に確認した場合にのみ生成されます。デバイスのデフォルトの状態では、Subscribed/Unsubscribed to push イベントはトリガーされません。

  例 - Android 12 以前のデバイスは、デフォルトでオプトインされています。この場合、Subscribed to push イベントはトリガーされません。Android 13 では、ユーザーはデフォルトでオプトアウトされており、Unsubscribed to push イベントはトリガーされません。ただし、ネイティブプロンプトでユーザーにプッシュ許可をリクエストし、ユーザーが許可をブロックした場合は、Unsubscribed to push イベントが発生します。
</Info>

## Android 13 ユーザーのオプトイン率のトラッキング

ユーザーは複数のデバイスを持っているため、特定の OS バージョンのデータは利用できません。

過去 60 日間にアプリでアクティブだったユーザーのオプトイン率をトラッキングする手順を以下に説明します。

![Reachability](/images/moengage_ae4288.png)

1. MoEngage ダッシュボードで **Analytics** -\> **Behavior** に移動します。
2. **Events & filters** セクションで、_App/Site Opened_ イベントを実行し、_OS version_ が _33_ のユーザーを選択します。
3. **Filter Users** セクションで、Filter users by オプションを選択します。
4. _User property Reachability Push Android_ のフィルター条件として、_in the following \[201-Reachable and opted in, 202- Reachable but opted out\]_ を選択します。
5. **Behavior Options** で、Analysis type に _Unique users_、Group by user property に _Reachability Push Android_、Duration に _last 2 months_ を選択します。
6. **Behavior Chart** セクションで _Pie Chart visualization_ を選択します。選択したフィルター条件のサンプル画像を以下に示します。201 のユーザーの割合が、Android 13 ユーザーのみのオプトイン率になります。クエリを変更して、他の OS バージョンのユーザーのオプトイン率を取得することもできます。
   ![PieChart.png](/images/moengage_e05df4.png)

# オプトイン率の向上

この機能による追加の制御性と柔軟性を活用するため、できるだけ早く Android 13 以降をターゲットにすることを強く推奨します。12L（API レベル 32）以前をターゲットにし続けると、アプリの機能のコンテキストで許可をリクエストする際の柔軟性が一部失われます。

## オプトインの方法

ユーザーからオプトインを取得するさまざまな方法は次のとおりです。

<Tabs>
  <Tab title="2 ステップオプトイン ">
    ![Screenshot](/images/moengage_16e139.png)

    ダブルオプトインまたは 2 ステップオプトインでは、2 つのステップでユーザーの許可を求めます。最初のステップでコンテキストを示し、次にユーザーを通知設定に誘導して、アプリからのプッシュ通知を有効にしてもらいます。2 ステップオプトインの前提条件とキャンペーン設定について以下で説明します。

    #### 2 ステップオプトインの前提条件

    Moengage SDK 12.6.00 以降および InApp バージョン 6.5.0 以降でアプリ内通知を統合してください。Core SDK の互換バージョンについては、[リリースノート](https://developers.moengage.com/hc/en-us/articles/4403896795540-Changelog)を参照してください。

    #### 事前許可メッセージ

    アプリ内通知を使用すると、ユーザーがアプリのプッシュ通知を許可すべき理由を伝える事前許可メッセージを作成できます。ユーザーが許可を明示的に 2 回拒否すると Android ネイティブのプッシュプロンプトをトリガーできなくなるため、この方法は Android ネイティブのプッシュプロンプトを不必要に表示することを避けるのにも役立ち、ユーザーに再度アプローチできます。

    ### 2 ステップオプトインプロンプトを表示するためのキャンペーン設定

    #### アクション

    - 通知許可のリクエスト\
      ユーザーが対象の場合、このアクションは Android ネイティブの通知許可をトリガーします。ユーザーがすでにプロンプトを複数回拒否している、または古い OS バージョンを使用しているために対象外の場合は、ユーザーが通知許可を管理できるアプリの通知設定画面にリダイレクトされます
    - 通知設定への移動\
      このアクションは、ユーザーが通知許可を管理できるアプリの通知設定画面にユーザーを誘導します

    #### セグメンテーション

    特定のユーザーセグメントを除外する具体的なユースケースがない限り、セグメンテーション条件として「All users」を使用することを推奨します。Moegnage は次のケースを自動的に管理します。

    - 無関係なユーザー\
      上記のいずれかのアクションを含むアプリ内通知では、Moengage が無関係なユーザーを自動的に除外します。例：
      - すでにオプトインしているユーザー
      - オプトイン許可アクションがサポートされていない古い SDK バージョンを使用しているユーザー
    - Android 12 以前のユーザー\
      これらのアクションは、OS バージョンに基づいて、オプトアウトしたユーザーに適した動作を自動的に選択します。Android 12 以前のユーザーは、通知許可を管理できるアプリの通知設定画面に誘導されます

    #### 優先度

    上記のアクションを含むキャンペーンは自動的に Critical-functional 優先度に設定され、同じトリガー条件を持つ他のキャンペーンよりも優先されます

    #### 最小遅延

    セッションごとに許可を求める代わりに、数日おきにユーザーにナッジするよう最小遅延を追加することもできます
  </Tab>
  <Tab title="1 ステップオプトイン">
    **シングルステップ**または**1 ステップオプトイン**のプロセスでは、許可を付与するためのプロンプトを使用して、アプリがプッシュ通知を送信することへのユーザーの許可を直接求めます。これを使用して、ビジネスロジックに基づき、ユーザージャーニーの重要なタイミングで許可をトリガーできます。MoEngage SDK には、ユーザーに [Android の許可リクエストを表示するためのヘルパー API](/ja/developer-guide/flutter-sdk/push/basic/android-notification-runtime-permissions) や、ユーザーを通知設定に誘導するためのヘルパー API が用意されています。詳細については、[Notification-Runtime-Permissions](/ja/developer-guide/android-sdk/push/basic/notification-runtime-permissions) を参照してください。

    ![A13\_PushPermissionExample.png](/images/moengage_740e91.png)
  </Tab>
  <Tab title="セルフハンドルオプトイン">
    **セルフハンドルオプトイン**では、開発者は他のランタイム許可と同様に、[Android の通知許可](https://developer.android.com/develop/ui/views/notifications/notification-permission#declare)プロンプトを直接呼び出すことができます。このメソッドを呼び出すとユーザーに通知プロンプトがトリガーされますが、ユーザーが許可プロンプトを 2 回拒否している場合は表示されません。他の方法が正しく機能するように、必ず [SDK に通知回数を通知](/ja/developer-guide/android-sdk/push/basic/notification-runtime-permissions)してください。セルフハンドルオプトインの実装に自信がない場合は、代わりに 1 ステップオプトインを使用することを推奨します。1 ステップオプトインは、ユーザーに許可が表示された回数をトラッキングし、呼び出されたときに次のアクションを暗黙的に判断します。
