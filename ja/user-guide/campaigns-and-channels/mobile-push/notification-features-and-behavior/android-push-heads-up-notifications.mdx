# 概要

ヘッドアップ通知は、Android における優先度の高いプッシュ通知です。ヘッドアップ通知は、現在のアプリに重なる形で画面上部に一時的なバナーとして表示され、ユーザーの注意を引きます。ユーザーが操作しない限り、通知は数秒後に自動的に消えます。

ヘッドアップ通知は、[プッシュ通知チャネル](/ja/user-guide/campaigns-and-channels/mobile-push/notification-features-and-behavior/android-push-notification-channels)の優先度が *High* に設定されている場合にトリガーされます。Android の通知チャネルの詳細については、[こちら](https://developer.android.com/develop/ui/views/notifications#Heads-up)を参照してください。

<Info>
- 操作されない場合、ヘッドアップ通知は 5〜8 秒後に自動的に閉じられます。
- ユーザーが通知を操作した場合、通知は自動的に閉じられず、フローティングウィンドウに表示されたままになります。
</Info>

# ユースケース

この機能のユースケースには、次のようなものがあります。

- 期間限定オファーやフラッシュセールについてユーザーに通知し、すぐに目に留まるようにして迅速なアクションを促します。
- 限定割引を添えてカート放棄をユーザーにリマインドし、購入の完了を促します。
- 支払いの失敗やアカウントのセキュリティ問題についてユーザーに警告し、タイムリーな認識と対応を確保します。

# MoEngage のヘッドアップ通知

MoEngage では、次の 2 つの方法でヘッドアップ通知を設定できます。

- [再投稿方式（デフォルトの方式）](#reposting-method-default-method)
- [直接投稿方式](#direct-posting-method)

## 再投稿方式（デフォルトの方式）

再投稿方式は、MoEngage のデフォルトの方式です。この方式では、メッセージの信頼性を維持しながら、デバイス間で一貫した動作を確保します。次のように動作します。

1. まず、テキストコンテンツを含む通知が投稿されます。
2. 最初の投稿の後、アセット（画像やメディアなど）がダウンロードされます。
3. その後、テンプレートコンテンツ（背景色、タイマー、プログレスバーなど）とダウンロードされたアセットを含めて通知が再投稿されます。

<img alt="Reposting method-snaggit.gif"  src="/images/moengage_9fc8e2.png"  />

この方式では、次のようになります。

- アセットのダウンロードや通知の更新に失敗しても、コアとなるメッセージの配信には影響しません。エンドユーザーには、少なくともバックアップテキストが常に表示されます。
- 通常 5〜8 秒間表示されるヘッドアップ通知は、スムーズなアニメーションなしに突然閉じられます。そのため、ユーザーには基本コンテンツからテンプレートコンテンツへの切り替わりがぎこちなく見える場合があります。

## 直接投稿方式

<Info>
- 直接投稿方式は、Android 8（Oreo）以降のバージョンでのみ利用できます。
- 直接投稿方式を有効にするには、MoEngage Android SDK バージョン 13.06.00 以降を使用していることを確認してください。
</Info>

直接投稿方式では、まずアセットがダウンロードされ、その後それらのアセットを含めて通知が投稿されます。  
この方式では、ユーザーは意図したとおりにヘッドアップ通知を体験できます。テンプレートコンテンツが通知に直接表示され、ヘッドアップ領域に 5〜8 秒間表示されます。

<img alt="Direct posting-snaggit.gif"  src="/images/moengage_7a3ced.png"  />

この方式では、インターネット接続が不安定なためにメディアアセットのダウンロードが遅れた場合や、テンプレートコンテンツの構築に関連する内部エラーが発生した場合、通知はエンドユーザーに表示されません。ただし、MoEngage SDK は引き続き *Notification received Android* イベントを生成します。

この方式を設定するには、[こちら](/ja/developer-guide/android-sdk/push/optional/heads-up-notification#configuration)を参照してください。

<Info>
カルーセルテンプレートの場合、カルーセルを操作すると通知はヘッドアップ領域から削除されますが、通知ドロワーには残ります。
</Info>

### 通知の制限事項と想定される動作

このセクションでは、さまざまな Android デバイスおよび OS バージョンで確認されている通知の制限事項と想定される動作について説明します。

- Android 9、10、11 のデバイスでは、通知の展開ビューを利用できません。通知を展開するためのドロップダウンボタンはありません。
- ヘッドアップ通知の展開ビュー
  - **一般的な動作**：展開すると、ヘッドアップ通知はユーザーが操作するか、別の通知を受信するまでフローティングウィンドウに表示されたままになります。
  - **Samsung デバイス**：ヘッドアップ通知を展開ビューで表示するには、**Advanced Settings** の **Notification Pop-up Style** を調整します。
  - **OnePlus デバイス**：*Basic*、*Timer*、*Timer with Progress Bar* テンプレートのヘッドアップ通知にはドロップダウンボタンがないため、フローティングウィンドウで展開できません。
- アプリの終了時/バックグラウンド移行時のヘッドアップ通知の消去
  - **Mi デバイス**：ユーザーがアプリを終了するか、バックグラウンドに移行すると、ヘッドアップ通知は閉じられます。
  - **Samsung および Pixel デバイス**：通知はフローティングウィンドウに表示されたままになります。
- おやすみモード（DND）でのヘッドアップ通知
  - **Samsung デバイス**：通知はサウンド付きでフローティングウィンドウに表示されます。
  - **Mi デバイス**：通知はサウンド付きで通知ドロワーにのみ表示されます。

<Info>
デバイスが *Do Not Disturb* モードの場合、ヘッドアップ機能が動作しないことがあります。
</Info>

# ベストプラクティス

- MoEngage SDK は、通知ドロワーでの通知の視認性を最大化するため、デフォルトで再投稿方式を使用します。
- *High* 優先度のチャネルを設定しており、ヘッドアップ領域での視認性を高めたい場合は、直接投稿方式を使用してください。最適な視認性を得るため、メディアアセットがサイズのガイドラインに準拠していることを確認してください。詳細については、[こちら](/ja/user-guide/campaigns-and-channels/mobile-push/create/push-templates)を参照してください。
- MoEngage では、キャンペーン作成者がこれらの通知を識別し、メディアアセットを適切に使用できるよう、ダッシュボード上でチャネル名に *heads-up* とラベルを付けることを推奨しています。このチャネル名は内部参照専用であり、エンドユーザーには表示されません。
