## 問題

MoEngage から送信された通知が、一部のエンドユーザーに届きません。これらの通知は Google Cloud Messaging (GCM) または Apple Push Notification Service (APNS) には正常に配信されていますが、ユーザーのデバイスには届いていません。

## 説明

通知の配信に失敗する考えられる原因は、次のいずれかのカテゴリに分類されます。

- **ユーザーとデバイスの設定**:
  - **通知のブロック**: ユーザーは、オペレーティングシステム (OS) レベルで特定のアプリの通知を無効にできます。この場合、GCM や APNS はデバイストークンを無効化せず、ユーザーが通知をブロックしたことを MoEngage に通知することもありません。
  - **バッテリーとアプリの最適化**: 多くのデバイス、特に積極的なバッテリー節約機能や "doze mode" (Motorola 製スマートフォンなど) を備えたデバイスでは、バックグラウンドでのアプリのアクティビティが制限される場合があります。これにより、アプリがアクティブに使用されていないときに通知が配信されない可能性があります。同様に、一部のバッテリー節約アプリはバックグラウンドプロセスを強制停止することがあり、これも通知の配信に影響します。
- **ネットワークとサーバー側の問題:**
  - **ネットワーク接続:** プッシュ通知を受信するには、デバイスが Google または Apple のサーバーへの常時接続を維持している必要があります。ユーザーが長時間オフラインの場合、各プッシュサービスは通知を配信できません。ユーザーが再接続した場合でも大幅な遅延が発生することがあり、有効期間 (TTL) が期限切れになっている場合は通知がまったく配信されないこともあります。Google の推定では、常時最大 15% のユーザーが GCM に接続されていない可能性があります。
  - **有効期間 (TTL) の期限切れ:** GCM または APNS が指定された TTL 内にデバイスに接続できない場合、通知の配信は試行されず、通知は期限切れになります。
  - **トークンの無効化の遅延:** アプリがアンインストールされてから、GCM または APNS がデバイストークンを非アクティブとしてマークするまでには遅延があります。そのため、MoEngage がアンインストールされたアプリに通知を正常に送信しても、ユーザーには配信されないことがあります。
- **メーカー固有の問題:** 一部のデバイスメーカーは、通知の配信を妨げる可能性のある積極的な省電力機能やメモリ管理機能を実装しています。新しい OS アップデートで一部の問題が解決される場合もありますが、古いデバイスでは問題が残ることがあります。MoEngage では、Lenovo、Micromax、ASUS などのメーカーの特定のモデルでこの問題を確認しており、配信失敗率が 90～99% に達する場合もあります。これらの問題は MoEngage の管理外です。
- **企業のファイアウォール:** 一部の企業環境では、厳格なセキュリティ設定により、ネットワークの外部ファイアウォールが受信パケットを拒否する場合があります。これにより、ネットワーク上のデバイスにプッシュ通知が届かなくなることがあります。

  詳細と考えられる解決策については、このトピックに関する[こちら](https://forum.earlybird.club/threads/no-notifications-on-wifi.482601/)のブログ記事を参照してください。

## User Activity

GCM や APNS などのプッシュサービスに正常に受け付けられた後でも、多くの通知がエンドユーザーに配信されないことがあります。以下のグラフは、これらの未配信の通知の内訳を示しています。

<img alt="" src="https://help.moengage.com/hc/en-us/article_attachments/206454863/SentNotReceived.png" />

MoEngage は直接的な因果関係を確立することはできませんでしたが、ユーザーの非アクティブ状態と通知の配信性には強い相関関係があります。ユーザーの非アクティブ期間が長くなるほど、デバイスへの到達可能性は低下します。つまり、GCM や APNS などのプッシュサービスは、これらのユーザーへの到達と通知の配信が困難になる可能性があります。

通知を正常に受信したユーザーをさらに分析したところ、ユーザーのリーセンシー (最後にアプリを利用してからの期間の短さ) も到達可能性と正の相関関係があることがわかりました。

### デバイス固有の配信の問題

分析の結果、一貫した傾向が確認されました。一部の Android デバイスモデルでは、他のモデルと比べてプッシュ通知の配信率が大幅に低くなっています。この仮説は、複数のクライアントキャンペーンのデータを調査した結果、特定のデバイスで高い失敗率が明らかになったことから立てられました。

配信率が最も低いデバイスの一部は次のとおりです。

- Lenovo A6020 および A6000: 失敗率 98～99%。
- Micromax Canvas シリーズ: 失敗率 90～95%。
- ASUS デバイス (モデル Z00AD、Z010D、Z008D、Z00UD、Z00LD): 配信率 4% 未満。
- Vivo デバイス (モデル Y11、Y15S、Y27L、Y28、Y57L、V1): 配信率 2～3%。

このような低い配信率は、多くの場合、デバイスメーカーや Android OS 自体が実装している積極的なバッテリー最適化機能が原因です。たとえば、Motorola 製スマートフォンの Doze モードや App Standby 機能は、デバイスがアイドル状態のときにアプリをディープスリープ状態にするため、通知の配信がブロックされることがあります。同様の問題は、組み込みのバッテリー最適化設定により、多くの Android Marshmallow デバイスでよく見られます。
