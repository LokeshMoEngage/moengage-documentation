# 概要

プッシュテンプレートを使用すると、コーディングなしで数分のうちに魅力的な通知を作成できます。表現力豊かで、ワクワクする、エンゲージメントの高いリッチでパーソナライズされた通知により最適なプッシュ体験を提供し、混雑した通知トレイの中でも通知を目立たせることができます。

MoEngage では、以下で説明する事前構築済みテンプレートを提供しているほか、カスタムテンプレートをアップロードすることもできます。キャンペーン作成のステップ 2 で、[事前構築済みテンプレート](/ja/user-guide/campaigns-and-channels/mobile-push/create/push-templates#pre-built-templates)または[カスタムテンプレート](/ja/user-guide/campaigns-and-channels/mobile-push/create/push-templates#custom-templates)からテンプレートを選択できます。

# 事前構築済みテンプレート

以下の事前構築済みテンプレートに基づいて通知を作成できます。

- Basic notification
- Stylized basic notification
- Simple image carousel
- Image banner with text overlay
- Timer
- Timer with Progress bar
- Background Update

<Tip>
  1. 開始するには、まずこれらのテンプレートをサポートする最新の SDK と統合する必要があります。詳細については、[Android](/ja/developer-guide/android-sdk/push/optional/push-templates) および [iOS の統合ドキュメント](/ja/developer-guide/ios-sdk/push/optional/push-templates)を参照してください。
  2. 先に進む前に、[基本的なプッシュキャンペーンの作成](/ja/user-guide/campaigns-and-channels/mobile-push/create/create-push-campaigns)について理解しておいてください。
</Tip>

## ユースケース

1. 環境に配慮した取り組みを始めますか？緑色の背景色を使用したプッシュ通知で最新情報を送信しましょう。
2. ユーザーをアプリや Web サイトに呼び戻したいですか？ユーザーが最後に閲覧した商品、音楽、メディアの画像を使用したカルーセルプッシュ通知を送信しましょう。

## プッシュテンプレート通知の作成

<Info>
  - プッシュテンプレートは Web プラットフォームではサポートされていません。
  - プッシュテンプレートは、すべてのポイントプッシュキャンペーンタイプ（One Time、Periodic、Event Triggered、Location Triggered、Device Triggered、Flows）でサポートされています。
  - Android と iOS でそれぞれ異なるテンプレートを選択できます。
  - ロケールやバリエーションごとに異なるテンプレートを追加できます。
</Info>

テンプレートベースのプッシュキャンペーンを作成するには、プッシュキャンペーン作成のステップ 2 で任意のテンプレートを選択します。各テンプレートでサポートされているプラットフォームは、各テンプレートタイルの右下隅に表示されます。

<Accordion title="Stylized basic">
  背景色、テキストの色、テキストの書式を設定したプッシュ通知を作成し、通知トレイで通知を目立たせることができます。

  Stylized basic notification は、SDK のカスタムレイアウトを使用して作成されます。ホワイトリストに登録されていないデバイスでは、Stylized basic notification で作成された通知は 64dp の高さで表示されます。以下の手順に従います。

  **基本情報**

  1. Background color で、メッセージの背景色を選択します。
  2. App name color（Android のみ）で、アプリ名の色を選択します。
  3. Notification control color（Android のみ）で、Light または Dark をクリックして通知の色を制御します。
  4. **Apply background color in text editor** トグルをオンにすると、選択した背景色がテキストエディタのフィールド（Title、Message、Summary）に適用されます。明るい色のフォントを使用する場合の視認性向上に役立ちます。
  5. 共通のプッシュテンプレート要素で説明されている手順に従います。
  6. ライトモードとダークモードの両方でプレビューを確認し、どちらのモードでも通知の見た目がよく、読みやすいことを確認してください。
  7. iOS の場合、**Image** セクションで以下を行います。
     - **Image/GIF URL** を選択し、画像/GIF の URL を入力または貼り付けます。
     - **Upload Image/GIF** をクリックし、画像/GIF をドラッグアンドドロップするか、コンピューターから保存済みの画像/GIF をアップロードします。推奨サイズは 25 KB～200 KB で、GIF の場合は最大 500 KB です。詳細については、[こちら](/ja/user-guide/campaigns-and-channels/mobile-push/notification-features-and-behavior/gifs-in-push-notifications)を参照してください。

  **詳細設定**

  1. 共通のプッシュテンプレート要素で説明されている手順に従います。
  2. _Auto-dismiss notification_ トグルをオンにして、通知の自動削除を有効にします。プッシュ通知がユーザーに配信された後、ユーザーの通知トレイから通知が自動的に削除されるまでの時間を選択できます。時間は分、時間、日単位で選択できます。許可される最大値は 1 日です。これは Android デバイスにのみ適用されます。 \
     <Note>
       通知が配信される前に自動削除の時間がすでに経過している場合、_Notification Received_ イベントは追跡されません。このような場合、通知はユーザーに表示されません。
     </Note>

<Accordion title="Image banner with text overlay">
  Image Banner with Text Overlay テンプレートを使用すると、通知領域全体を覆う大きなバナー画像と、画像の上に重ねたテキストでプッシュ通知を作成できます。このようなテンプレートは、送信する通知にブランドのロゴや色を追加する場合に使用できます。

    MoEngage Android SDK が統合されていることを確認してください。詳細については、[Android SDK](/ja/developer-guide/android-sdk/sdk-integration/basic-integration/Install-Using-BOM) を参照してください。

  Text overlay on Image 通知を作成するには、以下の手順に従います。

  1. プッシュキャンペーン作成のステップ 2 で、テンプレートタイプとして Image banner with text overlay notification を選択します。
  2. 共通のプッシュテンプレート要素セクションで説明されている以下のフィールドに入力します。
          - Notification Channel
          - Message
          - Title Message
          - Default Click Action
  3. _Include App name and time_ トグルをオンにすると、通知にアプリ名と時刻が含まれます。
  4. _App name color_ を使用して、アプリ名の色を選択します。アプリ名の色として「system default」を選択することもできます。
  5. _Notification controls color_ トグルで「Light」または「Dark」モードを選択します。
  6. 通知にバナー画像を追加するには、以下を行います。
         1. 「Image URL」オプションをクリックし、画像の URL を入力または貼り付けます。
         2. フィールドに「@」と入力して、画像 URL をパーソナライズすることもできます。これにより、パーソナライズ UI が呼び出されます。
         3. 「Upload Image」オプションをクリックし、画像をドラッグアンドドロップするか、コンピューターから保存済みの画像をアップロードします。推奨される画像サイズは約 25 KB です。推奨されるアスペクト比（幅:高さ）は、通知にボタンが含まれる場合は 1.4:1、含まれない場合は 1.3:1 です。サポートされているファイル形式は PNG、JPEG、JPG です。

         -  _Keep same as template backup_: 折りたたみモードでは、テキストはテンプレートのバックアップのメッセージと同じになります。ここではテキストのみが表示され、画像は表示されません。
         - _Show collapsed image:_ このオプションを使用すると、通知が折りたたまれたときに表示する別の画像を追加できます。このオプションを選択すると、画像のスケーリングも行えます。
              - _Image Scaling Options_: Crop image を選択すると、デバイスとプレビューで中央がトリミングされた画像が表示されます。Fit to container を選択すると、画像がコンテナ内の中央に配置されます。注: 画像のスケーリングは Android 12 以降でのみ使用できます。

<Accordion title="Timer">
  タイマーとメッセージを含むプッシュ通知を作成します。このような通知は、フラッシュセールや期間限定のセール/オファーのカウントダウンを表示するために使用できます。マーケターは、顧客エンゲージメントを高めるためにこれらのオプションを活用しています。

  <Tip>
    1. MoEngage Android SDK が統合されていることを確認してください。
    2. Push templates SDK の `4.0.0` バージョンが統合されていることを確認してください。
    3. 詳細については、[Android SDK](/ja/developer-guide/android-sdk/sdk-integration/basic-integration/Install-Using-BOM) を参照してください。
  </Tip>

  Timer with message 通知を作成するには、以下の手順に従います。

  1. プッシュキャンペーン作成のステップ 2 で、テンプレートタイプとして Timer を選択します。
  2. 上記の[共通のプッシュテンプレート要素セクション](#common-push-template-elements)で説明されているとおりに、Basic details、Buttons、Advanced にあるフィールドに情報を追加します。
  3. Timer セクションでは、ユーザーのデバイスに通知を表示する時間を設定できます。たとえば、Timer セクションで期間を 4 時間に設定した場合、通知がユーザーのデバイスに正常に送信されてから 4 時間表示されます。4 時間が経過すると、通知は自動的に削除されます。
  4. 「Timer ends at」フィールドを使用して、タイマーの期間を選択します。

  <Tabs>
    <Tab title="期間">
      ### Duration

      ユーザーに通知を表示する時間を入力します。

      #### **パーソナライズ**

      以下に示すように、「Personalise value」トグルを選択してパーソナライズを有効にします。パーソナライズする値は分単位で入力する必要があります。

      たとえば、タイマーを 1 時間表示するには、60 と入力します。最大期間は 12 時間、最小期間は 15 分です。

      「@」と入力してパーソナライズ UI を呼び出し、任意の User Attribute、Content Block、Product Set、または Content API を選択することもできます。プッシュ通知のパーソナライズの詳細については、[こちら](/ja/user-guide/campaigns-and-channels/mobile-push/create/personalize-push-campaigns)をクリックしてください。
    </Tab>
    <Tab title="ユーザーのタイムゾーンでの特定の時刻">
      ### At a specific Time in User timezone

      タイマーが終了する特定の時刻を入力します。この時刻はユーザーのタイムゾーンに基づいて計算され、カウントダウンタイマーは通知の送信から 24 時間以内に指定した時刻が到来した時点で終了します。

      たとえば、ユーザーのタイムゾーンでこの値を午前 10:30 に設定し、通知が午前 10 時にユーザーに届いた場合、タイマーは午前 10:30 に終了し、ユーザーはその時刻以降に通知を見ることはありません。

      注: この通知はユーザーのタイムゾーンに依存するため、通知が本日の午前 11 時にスケジュールまたはトリガーされ、タイマーがユーザーのタイムゾーンで午前 10:30 に設定されている場合、通知は翌日の午前 10:30 に終了するようにスケジュールされます。ただし、これはタイマー通知の有効期限である 12 時間の上限を超えるため、この通知は配信されません。

      #### **パーソナライズ**

      以下に示すように、「Personalise value」トグルを選択してパーソナライズを有効にします。パーソナライズする値は、タイムゾーンなしの 12 時間形式である必要があります。例: 11:30 AM、4:00 PM

      「@」と入力してパーソナライズ UI を呼び出し、任意のユーザー属性、コンテンツブロック、プロダクトセット、またはコンテンツ API を選択することもできます。プッシュ通知のパーソナライズの詳細については、[こちら](/ja/user-guide/campaigns-and-channels/mobile-push/create/personalize-push-campaigns)をクリックしてください。
    </Tab>

  </Tip>

  ### Background Update 通知の作成

  プッシュキャンペーン作成のステップ 2 で、**Background Update** タイルを選択します。 <img alt="bg update create.png" src="/images/moengage_50c27b.png" />

  1. このテンプレートの主な入力は、**Key-Value** **(KV) Pair** インターフェイスです。これらのペアは、プッシュペイロードのルートレベルで送信されます。バックエンドでは、対象の OS に応じて値のシリアル化の処理が異なります。
     - **Android**: FCM Data Message の標準に準拠するため、バックエンドはすべての値（数値、ブール値、オブジェクト）を文字列化します。
     - **iOS**: 値フィールドに入力された有効な JSON 文字列は、適切な JSON オブジェクトとして送信されます。有効でない JSON は文字列として送信されます。
  2. 標準のプッシュ通知とは異なり、Background Update テンプレートはサイレントになるように設計されています。配信メカニズムは、各オペレーティングシステムのバックグラウンド処理の要件に適応します。
     - **Android の場合**: ペイロードは高優先度の Data Message として配信されます。MoEngage SDK がこれをインターセプトし、トレイに通知を表示することなく生データをアプリに渡します。
     - **iOS の場合**: MoEngage は content-available フラグを使用して、アプリをバックグラウンドで最大 30 秒間起動します。これにより、ユーザーに通知することなく、アプリでコンテンツの更新やデータの同期を行えます。\
       いずれの場合も、開発者は特定の SDK コールバックを実装して、これらのペイロードを「リッスン」し、目的のアプリロジックをトリガーする必要があります。

  <Info>
    - SDK の機能との競合を避けるため、MoEngage では MO、gcm、aps、apns で始まるキーが制限されており、これらをカスタムキーとして使用することはできません。
    - ほとんどの SDK テクノロジーでは、ブール値のキーワードを小文字（例: true）にする必要があります。標準の JSON ペイロードでは通常これが正しく処理されますが、これらの値は文字列として配信されるため、パーソナライズや条件ロジックを使用する場合に問題が発生することがあります。
      - リスク: パーソナライズされた属性が "True"（先頭が大文字）のような文字列を返した場合、アプリのロジックがブール値として認識せず、偽陰性につながる可能性があります。
      - 推奨される対応: 特定のキーがブール値であることが想定されている場合、開発者はビジネスロジックを実行する前に、文字列を小文字に変換する（例: "True" を "true" に変換する）コードレベルのチェックを追加してください。
  </Info>

  プッシュキャンペーン作成のステップ 3 では、**Advanced** セクションで新しいターゲティングオプションである **Background Update Targeting** を使用できます。このオプションは、すべてのプラットフォーム、ロケール、バリアントで Background Update テンプレートが選択されている場合にのみ表示されます。詳細については、[プッシュキャンペーンの作成](/ja/user-guide/campaigns-and-channels/mobile-push/create/create-push-campaigns)を参照してください。 <img alt="bg update delivery.png" src="/images/moengage_487d60.png" />

  ### 分析と情報

  **分析**

  - Sent や Delivered などの指標は通常どおり追跡されます。
  - システム UI がないため、Impressions と Clicks は自動的には記録されません。
  - バックグラウンド更新によってカスタムのローカル通知や UI の変更がトリガーされる場合、開発者はそれらのインタラクションをキャンペーンに関連付けるために、`trackPushClick` SDK メソッドを手動で呼び出す必要があります。

  **キャンペーン情報**

  キャンペーンを公開した後、**Campaign Info** タブで設定を確認できます。

  - 設定されたすべてのキーと値が読み取り専用の形式で表示されます。
  - 値が有効な JSON オブジェクトとして入力された場合は、読みやすいように整形された JSON ブロックとして表示されます。
  - プレビューパネルを使用して、システムによって挿入されたトラッキングキーを含め、デバイスに表示される最終的な JSON 構造を視覚的に確認できます。

  **サンプルペイロード**

  以下の例は、MoEngage のバックエンドが最終的な配信ペイロードをどのように構成するかを示しています。Background Update テンプレートで追加したカスタムキーは、ペイロードのルートレベルに追加され、標準の MoEngage メタデータと共存します。

  1. 文字列値
     ```ruby
     key1: User1
     ```
  2. 有効な JSON オブジェクト JSON
     ```ruby
     key2: {
     "k1": "v1"(string),
     "k2": true/false(boolean),
     "k3": 200(number)
     }
     ```
  3. 有効でない JSON JSON
     ```ruby
     key2: {
     "k1": User,
     "k2": True,
     "k3": 200
     ```
     - iOS の出力 JSON
       ```text
       {
       "Key1ios": 200,
       "k2ios": true,
       "k3ios": "Praxxxn",
       "k4ios": "{\\n\\"k1\\": User,\\n\\"k2\\": True,\\n\\"k3\\": 200"
       }
       ```
       <Info>
         - バックエンドは無効な JSON 入力を不正な形式の文字列として扱うため、入力が有効な JSON であることを確認してください。入力が有効な JSON でない場合は、構造化されていない文字列データを処理するロジックを統合に含める必要があります。
         - 上記の出力では、有効でない JSON は不正な形式の文字列として扱われています: `"k4ios": "{\\n\\"k1\\": User,\\n\\"k2\\": True,\\n\\"k3\\": 200"`
       </Info>
     - Android の出力 JSON
       ```text
       {
       "message": {
       "data": {
       "Key1Android": "200",
       "k2android": "true",
       "k3android": "Praxxxn",
       "k4android": "{\n\"k1\": User,\n\"k2\": True/False,\n\"k3\": 200"
       }
       }
       ```
</Accordion>

## 推奨事項

プッシュテンプレートを使用する際に従うべき**重要なガイドライン**は以下のとおりです。

- 背景色やテキストの色を適用する場合は、ライトモードとダークモードの両方でプレビューを確認してください。これにより、どちらのデバイスモードでも通知が適切に表示されることを確認できます。
- ダッシュボードのデバイスプレビューの左側にある <img alt="CollapseButton.png" src="/images/moengage_354e30.png" />  ボタンを使用して、折りたたみモードと展開モードの両方でプレビューを確認してください。
- カルーセルの場合は、デバイスの下部にある再生/一時停止ボタンを使用して、切り替えを確認してください。
- SDK メソッド _setNotificationColor()_ を使用して、プッシュ通知の左上にある小さいアイコンに色を追加します。ただし、同じ色が基本的なプッシュ通知のアイコンにも適用されます。
- コンテンツが中央揃えになるように画像を作成してください。これにより、余白の周囲で多少トリミングされても、メインのコンテンツが切り取られることはありません。

#### 注意事項

- Push Amp\+ はテンプレートではサポートされていません。つまり、Push Amp\+ でターゲットにされたデバイスは通知を受信しますが、その通知はテンプレートのデータではなく、バックアップデータを含むシンプルなプッシュになります。
- テンプレートのデータによってペイロードサイズが 4kB を超える場合は、バックアップペイロードのみが送信されるため、配信には影響しません。
- iOS では、システムの仕様により、折りたたみビューでカスタム書式を表示できません。そのため、折りたたみビューでは、通知はシンプルなテキストと画像を含む基本的な通知のように表示されます。ただし、展開モードで開くと、テキスト/色の書式が適用されたテンプレートのカスタムビューが表示されます。
- 取り消し線は Android 7 以前のバージョンではサポートされていません。
- テンプレートは、基本的なプッシュ通知と同じ方法でパーソナライズできます。
- システムの制限により、Android 11 以降では自動カルーセルはサポートされていません。自動カルーセルを設定した場合は、手動の切り替えで表示されます。
- Android OS および OEM によるバッテリー最適化のため、自動削除がトリガーされない場合や、遅れてトリガーされる場合があります。

プッシュテンプレートに関連する表示の問題の詳細については、[Android でのプッシュテンプレートに関連する表示の問題](/ja/user-guide/campaigns-and-channels/mobile-push/troubleshooting-and-faqs-mobile-push/why-do-push-templates-have-rendering-issues-in-android)を参照してください。

## カスタムテンプレート

カスタムテンプレートは、Push Custom Template API を使用して MoEngage にアップロードします。詳細については、[Push Template API](/ja/api/push-templates/push-templates-overview) を参照してください。このオプションを使用すると、MoEngage のエコシステム外で作成された事前定義済みのテンプレートセットを利用できます。これらのテンプレートを再利用したり、ダッシュボードでプレビューしたり、顧客へのキャンペーン送信に使用したりできます。

カスタムテンプレートセクションでは、以下を行えます。

1. **テンプレートの選択** - テンプレートをクリックして選択します。
2. **テンプレートの並べ替え** - <img alt="SortIcon.png" src="/images/moengage_7c15f9.png" /> アイコンをクリックすると、テンプレートの最終更新日時の昇順または降順でテンプレートを並べ替えます。
3. **テンプレートの検索** - カスタムテンプレートセクションの右上にある検索ボックスにテンプレート名を入力して、特定のテンプレートを検索します。
4. **テンプレートのプレビュー** - 以下に示すように、テンプレートにカーソルを合わせ、表示される <img alt="PreviewIcon__1_.png" src="/images/moengage_48f64b.png" />  アイコンをクリックすると、テンプレートをプレビューできます。

![CustomTemplatePreview.gif](/images/moengage_196470.png)

カスタムテンプレートを選択すると、テンプレート内のすべてのフィールドの詳細とともに UI に読み込まれます。フィールドは表示できますが、編集できるのは「Edit Templates」権限がある場合のみです。

<Info>
  - 以下のロールを持つユーザーは、テンプレートを編集できます: Default Admin、Manager、Marketer
  - 他のユーザーに編集アクセスを付与するには、そのユーザーに「Edit Templates」権限を付与する必要があります。
  - カスタムテンプレートは Background Update テンプレートには適用されません。
  - カスタムテンプレートはパーソナライズをサポートしています。カスタムテンプレートのペイロードを渡す際は、パーソナライズの構文を Campaigns で使用される Jinja 構文に合わせる必要があります。
</Info>

ユーザーにキャンペーンを送信した際にテンプレートがどのように表示されるかをプレビューできます。また、Test Campaign オプションを使用してキャンペーンをテストし、特定のデバイスでの表示をリアルタイムでプレビューすることもできます。

## よくある質問

<Accordion title="プッシュテンプレートに関する Android 14 固有の変更点は何ですか？">
  Android 14 では、プッシュテンプレートに影響する以下の変更が導入されました。

  - Timer with Progress Bar テンプレート\
    SDK は Alarm を使用して、プログレスバーの進捗を定期的に更新します。Android 14 以降、Alarm の権限はデフォルトでオフになっています。そのため、Timer 通知を表示する場合は、マニフェストファイルに行を追加するだけでなく、Alarm の権限を明示的にリクエストする必要があります。詳細については、[プッシュテンプレート](/ja/developer-guide/android-sdk/push/optional/push-templates)を参照してください。\
    アプリケーションに上記の権限がない場合、Timer with Progress Bar テンプレートはユーザーに表示されず、代わりにタイマーはあるもののプログレスバーのないバックアップテンプレートがユーザーに表示されます。
  - スティッキー通知\
    Android 14 以降のデバイスでは、ユーザーはスワイプ操作でスティッキー通知を閉じることができます。ユーザーが **Clear all** の通知操作を実行しても通知はトレイに残り（誤って閉じてしまうことを防ぐのに役立ちます）、スマートフォンがロックされている場合でも通知を閉じることができます。Android 14 のドキュメントは[こちら](https://developer.android.com/about/versions/14/behavior-changes-all#non-dismissable-notifications)を参照してください。
</Accordion>

<Accordion title="Next ボタンをクリックしてもバックアップの自動コピーが機能しないのはなぜですか？">
  以下を確認してください。

  1. すべてのバリアントのすべてのバックアップが空であること。
  2. すべての必須フィールドが入力されていること。
  3. バックアップが入力されていないこと。
</Accordion>

<Accordion title="コンテンツをコピーした後にバックアップの自動コピーが機能しないのはなぜですか？">
  Copy Content を実行すると、iOS の Default Click Action Type（ドロップダウン）がコピーされます。これによりバックアップが空ではなくなるため、バックアップの自動コピーが行われなくなります。バックアップの自動コピーを有効にするには、iOS のバックアップで Default CTA type を削除してください。
</Accordion>

<Accordion title="カルーセルのスライドにエラーが表示されないのはなぜですか？">
  1. エラーは、ページを切り替えようとしたとき、またはテスト通知を実行しようとしたときに初めて表示されます。
  2. スライドのタブを開いたときにも、スライド内にエラーが表示されます。
</Accordion>

<Accordion title="エラーのあるカルーセルのスライドが開かないのはなぜですか？">
  1. カルーセルのスライドのエラーは、エラーのあるスライドの名前とともにトースターに表示されます。
  2. 現時点では、エラーのあるスライドのタブは自動的には開きません（実装上の技術的な課題があるためです）。
</Accordion>

<Accordion title="パーソナライズのフォールバックを追加するにはどうすればよいですか？">
  - テンプレートとバックアップの両方に、パーソナライズ用のインラインフォールバックがあります。
  - パーソナライズ属性を追加する際に、「**replace text**」オプションを選択すると、インラインフォールバックを追加できます。
  - フォールバックを追加するには、以下の Jinja テンプレートを使用します。

  #### フォールバックを使用したパーソナライズのサンプル:

  - 例: 名（first name）のユーザー属性
  - テンプレートのメッセージ: 'Hi John, Welcome to MoEngage. To proceed further, click here.'
  - フォールバックのメッセージ: 'Good Morning. To proceed further, click here.'

  サンプル

  ```python
  {% set firstName = {{UserAttribute['First Name']}} %}
  {% if firstName %}Hi {{ firstName }}, Welcome to MoEngage
  {% else %}Good Morning
  To proceed further, click here
  {% endif %}
  ```
</Accordion>

<Accordion title="テンプレートの Title と Summary フィールドに複数行を追加できない">
  Title と Summary は 1 行のみの入力です。
</Accordion>

<Accordion title="プログレスバーの時間に遅れが生じるのはなぜですか？">
  バッテリー最適化が実行されている可能性があり、これがプログレスバーの更新に問題を引き起こすことがあります。
</Accordion>

<Accordion title="画像の理想的なアスペクト比はどれくらいですか？">
  Android 12 での変更により、OEM ごとに UI の仕様が異なるため、Android デバイスでの画像の表示方法に違いが生じます。画像の見え方は、デバイスの幅やデバイスの OEM によって異なる場合があります。プッシュ通知の理想的なアスペクト比は以下のとおりです。

  ### 画像の理想的なアスペクト比

  #### Android の場合

  推奨されるアスペクト比はテンプレートによって異なり、同じテンプレート内でも通知にボタンが含まれるかどうかによって異なります。

  | テンプレート | ボタンあり | ボタンなし |
  | --- | --- | --- |
  | Basic notification | 2.9:1 | 2.8:1 |
  | Stylized basic notification | 2.8:1 | 2.1:1 |
  | Simple image carousel | 2.8:1 | 2.1:1 |
  | Image banner with text overlay | 1.4:1 | 1.3:1 |
  | Timer | 2.8:1 | 2.1:1 |
  | Timer with progress bar | 2.4:1 | 1.9:1 |

  画像は 25 KB 程度に抑えてください。サポートされているファイル形式は PNG、JPEG、JPG です。キャンペーンビルダーでも、設定中のテンプレートの推奨比率が画像フィールドの下のヘルプテキストに表示されます。

  画像が推奨比率に近い場合、トリミングは最小限になりますが、正確な表示はデバイスの幅や OEM によって異なります。

  <Tabs>
    <Tab title="Type A デバイス">
      Pixel、Xiaomi、Asus のスマートフォンは Type A デバイスに分類されます。
    </Tab>
    <Tab title="Type B デバイス">
      Samsung、OnePlus、Oppo、Vivo、Realme、およびその他のスマートフォンは Type B デバイスに分類されます。
    </Tab>
  </Tabs>

  どちらのデバイスタイプでもクリエイティブがトリミングされないようにするには、以下の「デバイス間で画像を正しく表示する」に関する FAQ で説明されている **Image scaling** オプションを使用してください。

  iOS の場合: 画像には 2:1（横向き）を使用することを推奨します。iOS は、画像のアスペクト比に合わせて通知領域を自動的にスケーリングします。
</Accordion>

<Accordion title="プッシュ通知の画像がトリミングされることなく、さまざまなデバイスで正しく表示されるようにするにはどうすればよいですか？">
  デバイスごとに複数の画像を作成することはできないため、MoEngage では、プッシュ通知がさまざまなデバイスで一貫して表示されるように、以下の画像スケーリングのアプローチを採用することを推奨しています。

  1. **クリエイティブをトリミングしたくない場合** 最も一般的な画面サイズの Device Type A に指定されたアスペクト比に従ってプッシュ通知を作成します。テンプレートの作成時に、**Image scaling** セクションで **Fit inside image container** を使用して、クリエイティブがトリミングされないようにします。水平方向または垂直方向に余白が表示される場合があります。 <img src="/images/moengage_95ccbc.png" alt="FitImageToContainer.png" />
  2. **クリエイティブの端（各辺から 10% の余白）に意味のあるコンテンツがない場合** テンプレートの作成時に、**Image scaling** セクションで **Fill image container** オプションを使用し、画像に余白を追加します。これにより、極端なケースで余白が多少トリミングされても、意味のあるコンテンツがトリミングされることはありません。 <img src="/images/moengage_1b292d.png" alt="FillImageContainer.png" />
</Accordion>
