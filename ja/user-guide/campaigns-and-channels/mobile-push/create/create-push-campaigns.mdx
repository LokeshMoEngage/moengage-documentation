プッシュキャンペーンを作成するには、次の手順を実行します。

<Info>
  システムで IP ホワイトリスト登録が必要な場合は、プッシュキャンペーンを設定する前に[こちら](/ja/user-guide/settings/account/security/ip-whitelisting-in-moengage)を参照してください。
</Info>

1. MoEngage Dashboard に移動し、左側のナビゲーションから **Engage** -\> **Campaigns** を選択します。
2. **All Campaigns** ページの右上にある <img alt="mceclip2.png" src="/images/moengage_c0c461.png" style={{ display:"inline-block" }} /> をクリックします。
3. 表示されたアウトバウンドチャネルから _Push_ を選択します。
4. 次のいずれかのキャンペーン配信タイプを選択します。
   - One Time
   - Periodic
   - Event Triggered
   - Business Event Triggered
   - Device Triggered
   - Location Triggered 配信タイプの詳細については、[配信タイプ](/ja/user-guide/campaigns-and-channels/getting-started/introduction/delivery-types-moengage-channels)を参照してください。

# プッシュキャンペーンの作成手順

プッシュキャンペーンの作成は、次の 3 つのステップで構成されます。

1. [ターゲットユーザー](#step-1-target-users): キャンペーンのターゲットオーディエンスを定義します
2. [コンテンツ](#step-2-define-content): 送信するプッシュ通知のコンテンツを定義します
3. [スケジュールとゴール](#step-3-scheduling-and-goals): キャンペーンの配信スケジュールとゴールを定義します

## ステップ 1: ターゲットユーザー

このセクションでは、キャンペーンのオーディエンスを定義します。キャンペーンの詳細、オーディエンスの上限、ターゲティングルール、プラットフォームの選択が含まれます。

### キャンペーンの詳細

キャンペーンの詳細セクションには、次のフィールドがあります。

|  |  |
| --- | --- |
| **Team** - 組織でチームが有効になっている場合は、ドロップダウンでチームを選択します。詳細については、[MoEngage のチーム](/ja/user-guide/settings/account/team-management/teams-in-moengage)を参照してください。 |  |
| **Campaign name** - キャンペーンを管理および識別するためのキャンペーン名を入力します。キャンペーン名は 5 文字以上で、上限は 256 文字です。 | <img alt="Push_CampaignDetails (1).png" src="/images/moengage_768da6.png" style={{ display:"inline-block" }} /> |
| **Campaign tags** - ドロップダウンリストからキャンペーンタグを選択します。最大 5 つのタグを選択できます。詳細については、[キャンペーンタグ](/ja/user-guide/campaigns-and-channels/getting-started/introduction/campaign-tags)を参照してください。 |  |

<Accordion title="イベントトリガー型キャンペーン">
  イベントトリガー型キャンペーンでは、さまざまなユーザーアクションイベントをトリガーとしてパーソナライズされた通知を送信できます。たとえば、カートに追加したものの購入していない商品についてユーザーにリマインドできます。

  <Info>
    ワークスペースで [_Portfolio_](/ja/user-guide/settings/account/portfolio/portfolio) が有効になっている場合、あるプロジェクト（ブランド）でのユーザーアクションを起点として、別のプロジェクト（ブランド）からメッセージを送信する高度なイベントトリガー型キャンペーンを作成できます。
  </Info>

  このようなキャンペーンの作成について詳しくは、[イベントトリガー型キャンペーンの作成](/ja/user-guide/campaigns-and-channels/getting-started/triggers/event/create-an-event-triggered-campaign)を参照してください。
</Accordion>

<Accordion title="ビジネスイベントトリガー型キャンペーン">
  |  |  |
  | --- | --- |
  | ビジネスイベントトリガー型キャンペーンでは、<br />_Select business event_ ドロップダウンを使用して、キャンペーンにマッピングするビジネスイベントを選択できます。<br />ドロップダウンには、MoEngage アカウントで作成されたすべてのビジネスイベントが含まれます。 | <img alt="BusinessEvent.png" src="/images/moengage_698fd3.png" style={{ display:"inline-block" }} /> |

  ビジネスイベントを選択すると、そのビジネスイベントに関連付けられたイベント属性をセグメンテーションフィルターで使用できるようになります。ビジネスイベント属性は、次のセグメンテーションフィルターで使用できます。

  - ユーザープロパティによるセグメント - ユーザープロパティをビジネスイベント属性にマッピングできます
  - ユーザー行動によるセグメント - ユーザーが実行したイベントの属性をビジネスイベント属性にマッピングできます
  - ユーザーアフィニティによるセグメント - ユーザーが実行したイベントの属性をビジネスイベント属性にマッピングできます

  <Info>
    - セグメンテーションを機能させるには、選択したユーザー属性またはイベント属性のデータ型がビジネスイベント属性のデータ型と一致している必要があります。
    - ビジネスイベントは（ビジネスイベントがトリガーされた値に基づく）動的セグメンテーションで実行されるようにモデル化されているため、ビジネスイベントトリガー型キャンペーンでは Show count が無効になっています。
  </Info>
</Accordion>

<Accordion title="位置情報トリガー型キャンペーン">
  <img alt="AddGeoFence.png" src="/images/moengage_0eb9de.png" style={{ display:"inline-block" }} /> をクリックします。表示される _Add Geofence_ ポップアップで、次の操作を行います。

  1. ジオフェンス名を追加します。
  2. ユーザーアクションのドロップダウンからトリガー条件を選択し、ジオフェンスへの進入/退出/滞在時にプッシュメッセージをトリガーします。次のオプションを使用できます。
     - _User enters the Geofence_ - ユーザーが定義された範囲に入ったときにメッセージがトリガーされます。
     - _User exits the Geofence_ - ユーザーが定義された範囲から出たときにメッセージがトリガーされます。
     - _Dwell based (user stays in Geofence)_ - ユーザーが定義された範囲に入り、X 分間その範囲内に滞在したときにメッセージがトリガーされます。**このタイプのトリガーは Android でのみサポートされていることに注意してください**。顧客が車でジオフェンスの近くを短時間通過するだけで多くのアラートを受け取る場合、滞在ベースのフェンスはこのようなスパムの削減に非常に効果的です。
  3. 場所を検索してジオフェンスを指定します。この場合、緯度と経度は自動入力されます。または、次の情報を指定してジオフェンスを指定することもできます。
     - _Latitude_
     - _Longitude_
     - _Radius (in meters)_ - ジオフェンスをトリガーするための適切な半径パラメーターを入力します。たとえば、ニューヨークの Foley Sq の周囲に 7 km のジオフェンスが設定されている場合、選択した条件（進入/退出/滞在）に基づいてプッシュ通知がトリガーされます。

       MoEngage では半径の最小値や最大値は強制されません。確実にトリガーされるよう、半径は 100～150 メートル以上に設定してください。
  4. **Done** をクリックしてジオフェンスを追加します。それぞれに個別のメッセージと場所を設定した複数のジオフェンスを追加できます。ジオフェンスを削除するには、ジオフェンスリストの "x" 記号をクリックします。

  <Info>
    位置情報トリガー型キャンペーンおよび API トリガー型キャンペーンでは、AB バリエーション/ロケールはサポートされていません。
  </Info>
</Accordion>

### ターゲットオーディエンス

このセクションには、キャンペーンのターゲットオーディエンスを選択するためのセグメンテーションフィルターが含まれています。次のオプションを使用できます。

<Tabs>
  <Tab title="すべてのユーザー">
    このフィルターオプションを使用すると、すべてのアプリユーザーにキャンペーンを送信できます。このオプションを使用する場合、複数のフィルターを追加することはできません。

    ![AllUsers\_Segmentation.png](/images/moengage_ef8dfc.png)
  </Tab>
  <Tab title="ユーザープロパティでフィルター">
    このフィルターオプションを使用すると、初回確認日時、最終確認日時、都市などのユーザープロパティに基づいてユーザーをターゲットにできます。User property タブを選択し、次の操作を行います。

    1. ドロップダウンで目的の属性を選択します。選択した属性に基づいてフィルターが有効になります。たとえば、数値の属性には 'is equal to'、'is not equal to'、'is between' などのフィルター条件があり、文字列の属性には別のフィルターがあります。
    2. フィルター値を指定して、目的のユーザーセグメントを作成します。

    詳細については、[セグメントの作成](/ja/user-guide/segment/create-segments/rule-based-filter-segments)を参照してください。

    ![UserProperty.png](/images/moengage_6372a3.png)
  </Tab>
  <Tab title="ユーザー行動でフィルター">
    このフィルターオプションを使用すると、アプリ/サイトの起動、商品の閲覧など、ユーザーの行動やイベントに基づいてユーザーをターゲットにできます。User Behavior を選択し、次の操作を行います。

    1. 実行条件と目的のユーザーアクティビティ（イベント）を選択します。
    2. イベントの実行頻度と期間を指定します。
    3. \+Attributes をクリックし、フィルター条件を指定したイベント属性を追加します。
    4. フィルター値を指定してルールを作成します。

    詳細については、[セグメントの作成](/ja/user-guide/segment/create-segments/rule-based-filter-segments)を参照してください。

    ![UserBehavior.png](/images/moengage_85a00f.png)
  </Tab>
  <Tab title="ユーザーアフィニティでフィルター">
    このフィルターオプションを使用すると、特定の属性値でアクションを実行したユーザーに基づいて作成されたユーザーグループをターゲットにできます。詳細については、User Affinity を参照してください。User Affinity を選択し、次の操作を行います。

    1. 目的のユーザーイベントまたは属性を選択します。
    2. 次の中からユーザーアフィニティパラメーターを選択します。
       - Predominantly フィルター条件を指定したアフィニティ属性を選択し、アフィニティ値を指定します
       - Minimum of フィルター条件を指定したアフィニティ属性を選択し、アフィニティ値を指定します
       - Most no. of times 上位または下位のユーザーの割合を入力するか、矢印を使用して指定します
       - Least no. of times
    3. 上位または下位のユーザーの割合を入力するか、矢印を使用して指定します。イベント実行の期間を入力するか、矢印を使用して指定します。
    4. Attribute ボタンをクリックして、フィルターに属性を追加します。

    ![UserAffinity.png](/images/moengage_028ccd.png)
  </Tab>
  <Tab title="カスタムセグメントでフィルター">
    このフィルターオプションを使用すると、利用可能なカスタムセグメントのリストからカスタムセグメントをターゲットオーディエンスとして選択できます。詳細については、[カスタムセグメント](/ja/user-guide/segment/create-segments/manage-segments)を参照してください。

    ![CustomSegment.png](/images/moengage_163392.png)
  </Tab>
</Tabs>

<Info>
  [_Portfolio_](/ja/user-guide/settings/account/portfolio/portfolio) 機能が有効になっている場合、ワークスペース内の異なるアプリやウェブサイト（プロジェクト）のユーザーデータと行動を組み合わせてユーザーセグメントを作成できます。詳細については、[マルチプロジェクト Portfolio でのセグメンテーション](/ja/user-guide/segment/advanced-concepts/segmentation-in-a-multi-project-portfolio)を参照してください。
</Info>

アカウントでチームが有効になっている場合、作成対象のチームに指定されたセグメンテーション条件が AND 条件でキャンペーンに追加されます。詳細については、[MoEngage のチーム](/ja/user-guide/settings/account/team-management/teams-in-moengage)を参照してください。

フィルター条件を選択した後、次の操作も行えます。

- このオプションを使用して、複数のユーザープロパティルール、ユーザーアクティビティルール、カスタムセグメントルールを作成・組み合わせ、複雑なユーザーセグメントを作成します。
  - _\+ Filter_ をクリックします。
  - _AND または OR_ をクリックします。
  - 属性またはイベントを選択し、フィルター条件を定義します。
- **Exclude Users** - _Exclude Users_ チェックボックスをオンにして、キャンペーンから除外するユーザーのフィルター条件を定義します。
- **Send campaign to the users opted out in preference management** - このオプションをオンにすると、プリファレンス管理でオプトアウトしたユーザーもキャンペーンの対象に含めます。詳細については、[プリファレンス管理](/ja/user-guide/campaigns-and-channels/mobile-push/getting-started-with-mobile-push/preference-management-for-push-notifications)を参照してください。
- **Reset Filters** - このオプションをクリックすると、セグメンテーションフィルターがリセットされます。
- **Show Count** - _Show Count_ をクリックすると、設定したセグメントに現在含まれているユーザーの総数が表示されます。

### コントロールグループ

このセクションには、キャンペーンのコントロールグループに関する情報が含まれています。コントロールグループのユーザーを除外するには、次の操作を行います。

- **Global control group** トグルを有効にすると、コントロールグループのユーザーがキャンペーンのターゲットセグメントから除外されます。
- **Campaign control group** を有効にすると、キャンペーン内の一定割合のユーザーがキャンペーンのターゲットセグメントから除外されます。トグルの下のボックスで、キャンペーンから除外するユーザーの割合を指定します。注: このオプションは、位置情報トリガー型およびデバイストリガー型キャンペーンでは使用できません。

## ステップ 2: コンテンツの定義

このセクションには、プッシュ通知のコンテンツを定義するために選択できるさまざまなテンプレートが含まれています。いずれかのテンプレートを選択し、[プッシュテンプレート](/ja/user-guide/campaigns-and-channels/mobile-push/create/push-templates)に記載されている手順に従ってください。

MoEngage では、プレビューに表示されるプッシュメッセージを確認してから Next をクリックし、キャンペーンのスケジュールとゴールを設定することを推奨しています。

<Info>
  **RTL 言語のサポート**: RTL 言語地域のユーザーをターゲットにする場合、通知は次のように表示されます。
  
  - **Android**（展開モードおよび折りたたみモード）: メッセージ全体を RTL 言語で記述し、デバイスの言語が RTL に設定されている場合、RTL で表示されます。絵文字や Unicode 文字を含むメッセージは LTR で表示されます。
  - **iOS 折りたたみモード**: メッセージ全体を RTL 言語で記述し、デバイスの言語が RTL に設定されている場合、RTL で表示されます。絵文字や Unicode 文字を含むメッセージは LTR で表示されます。
  - **iOS 展開モード**: メッセージやデバイスの言語に関係なく、常に LTR で表示されます。
  - その他のすべてのケースでは LTR で表示されます。
</Info>

<Accordion title="UTM パラメーターの追加">

  **イベントトリガー型キャンペーンはいつ送信されますか？**

  キャンペーンは次の場合にのみ送信されます。

  - この種類のトリガーの作成に使用されるイベントプロパティ/属性（flight\_time の例など）が有効な日時形式である場合。日時形式でない場合、文字列には[サポートされている形式](/ja/user-guide/campaigns-and-channels/mobile-push/create/create-push-campaigns)のいずれかのデータが含まれている必要があります。選択した属性にこれらのいずれかの形式のデータが含まれていない場合、キャンペーンはユーザーに送信されません。
  - 属性の日時の値が、トリガー条件が満たされた時刻よりも後である場合。
  - 属性の日時の値が、トリガー条件が満たされた時刻 \+ 30 日よりも前である場合。たとえば、トリガー条件が日付 D に満たされた場合、属性値が D\+30 未満のときにのみ通知が送信されます。
  - インテリジェント遅延最適化（**With Delay**）は、相対タイミングで送信されるキャンペーンでは機能しません。

### コンバージョンゴール

コンバージョンゴールを追加して、キャンペーンのビジネス指標を追跡できます。最大 5 つのコンバージョンゴールを追跡できます。任意のアプリイベントをコンバージョンゴールのアクティビティとして選択でき、複数のコンバージョンゴールを設定できます。最初のゴールはプライマリゴールとして扱われます。

たとえば、キャンペーンの送信後に iPhone を購入した顧客の数を追跡したいとします（イベント - 購入イベント、商品 - iPhone）。コンバージョンゴールの設定は、次の詳細を含む下の画像のようになります。

- **Goal Name** - _iPhonePurchase_
- **App Event you wish to track** - _Made Purchase_
- **Event Attribute/Property** - product は _イベント属性/プロパティ_ です
- **Value of Event Attribute/Property** - _iPhone_

![ConVErsionGoals.png](/images/moengage_301b43.png)

複数のコンバージョンゴールを使用すると、複数のビジネス指標を追跡したり、ユーザーアクションのファネルを可視化したりできます。たとえば、次のような内容を確認したい場合、複数のコンバージョンゴールで確認できます。

- 商品ページを閲覧したユーザーは何人か？
- そのうち、その商品をカートに追加したユーザーは何人か？
- そのうち、注文を完了したユーザーは何人か？

### 詳細設定

このセクションでは、次のオプションを使用できます。

|  |  |
| --- | --- |
| **Expiration Settings** - プッシュ通知の有効期限の値を指定できます。このセクションには、iOS および Android プラットフォームでプッシュ通知の送信を停止するタイミング（指定した期間の経過後）に関する情報が含まれています。 | <img alt="Expiration Settings.png" src="/images/moengage_b7c71f.png" style={{ display:"inline-block" }} /> |

プッシュの有効期限の値を設定するには、次のオプションを使用できます。

- **Expire notifications after** - このフィールドは、プッシュ通知サービスが未配信のメッセージを破棄するまでに、配信のためにメッセージを保存する期間を指定します。プッシュサービス（FCM/APNS）は、**Expire notifications after** の期間（分単位）が経過するまでメッセージの送信を再試行します。この期間が経過すると、配信の試行は停止します。デフォルト値は 36 時間で、Android および APNS のプッシュ通知に適用されます。
- **Remove notifications from inbox after** - MoEngage SDK の Notification Center（Inbox）機能を使用している場合、通知を Inbox から削除するまでの期間を指定できます。期間は日単位または時間単位で設定できます。デフォルトでは 30 日に設定されます。

<Info>
  MoEngage は、設定された **Expire Notifications After** の値を各配信パートナー（FCM、APNS、Web Push サービスなど）に送信します。ただし、これらのサービスがすべてのケースでこの値を遵守するとは限りません。一部のキャンペーンでは、FCM で約 0.1%～0.5% のユーザー、APNS で最大 0.1% のユーザーに対して、有効期限を過ぎてから通知が配信されたことがあります。
</Info>

|  |  |
| --- | --- |
| **Priority** — 時間的制約のある通知の場合にこのオプションを選択します。次のオプションを使用できます。<ul><li>**Android**:<ul><li>**Send at priority**: 通知を高優先度で送信するかどうかを指定します。<ul><li> オン: バッテリー最適化や低電力モードなどのデバイスの制限を回避して、通知を即時に配信します。</li><li>オフ: デバイスがアイドル状態や低電力モードのときなど、デバイスのリソースを節約する方法で通知を配信します。</li></ul></li></ul></li></ul> このチェックボックスにより、緊急の通知は迅速にユーザーに届き、緊急でない通知は省電力ポリシーに従います。<ul><li>**iOS**:<ul><li>**APNS Priority**: 通知の配信の優先度を指定し、ネットワークや電力の制約下で配信をどのように処理するかを APNS に伝えます。<ul><li>値 `10` は、通知を即時に配信し、必要に応じてデバイスをスリープから復帰させます。</li><li>値 `5` は、デバイスの電力を節約する方法で通知を配信します。</li><li>値 `1` は、デバイスをスリープから復帰させることなく、他のすべての要素よりも電力の節約を優先して通知を配信します。</li></ul></li><li>**Interruption Level**: 通知の重要度とタイミングを指定できます。詳細については、[iOS 15 の通知](/ja/user-guide/campaigns-and-channels/mobile-push/notification-features-and-behavior/notifications-in-ios-15)を参照してください。</li><li>**Relevance Score**: 通知の重要度を示す 0～1 の値を指定できます。詳細については、[iOS 15 の通知](/ja/user-guide/campaigns-and-channels/mobile-push/notification-features-and-behavior/notifications-in-ios-15)を参照してください。</li></ul></li></ul> | <img alt="Image 18-11-24 at 12.42 PM.jpeg" src="/images/moengage_aa041d.png" style={{ display:"inline-block" }} /> |

<Info>

  要件に応じて通知の優先度を設定することもできますが、特定のカテゴリの通知の配信を異なる優先度にする戦略的な必要性がない限り、即時配信を確実にするために値を '10'（デフォルト）のままにしておくことを推奨します。たとえば、トランザクション通知を配信する必要があり、プロモーション通知がトランザクション通知の配信を妨げていることが確認された場合、マーケターはプロモーションキャンペーンの優先度を下げて、トランザクション通知が配信される可能性を高めることができます。
</Info>

**Background Update Targeting**

ステップ 2 ですべてのプラットフォーム、ロケール、バリアントに対して Background Update テンプレートを選択した場合、ここに **Background Update Targeting** オプションが表示されます。<img alt="bg update delivery.png" src="/images/moengage_abde0e.png" />

- **Send campaign to opted out users (Background push notifications do not need explicit push permissions)**: このチェックボックスをオンにすると、プッシュ通知を手動でオプトアウトしたユーザーにもリーチできます。Background Update はサイレントで、明示的なプッシュ許可を必要としないため、アプリの状態管理やバックグラウンド同期のためにこれらのユーザーにも配信できます。
- オプトアウトしたユーザーは配信フェーズで動的に追加されるため、ステップ 1 で表示される "Target Audience" の数は、最終的な "Sent" の数よりも少なくなる場合があります。

詳細については、[プッシュテンプレート](/ja/user-guide/campaigns-and-channels/mobile-push/create/push-templates)を参照してください。

<Info>
  iOS の Background Update は低い APNS 優先度で送信されます。Apple のドキュメントによると、これらは "ベストエフォート" の配信であり、デバイスが "強制終了" 状態の場合、バッテリー残量が少ない場合、またはユーザーがデバイス設定で **Background App Refresh** を無効にしている場合は、破棄されることがあります。
</Info>
