ビジネスコミュニケーションにRCSを使用するには、次のチャートに示す公式の手順に従う必要があります。

![Flowchart.png](/images/moengage_36e183.png)

前提条件は以下のようにまとめられます。

- オンボーディングフォームを使用してMoEngageに[登録](/ja/user-guide/campaigns-and-channels/sms-mms-and-rcs/rcs/getting-started-with-rcs/prerequisites#registration)します。
- RCSメッセージを送信して[接続をテスト](/ja/user-guide/campaigns-and-channels/sms-mms-and-rcs/rcs/getting-started-with-rcs/prerequisites#test-the-connection)します。
- ローンチリクエストフォームを使用して[ローンチを検証](/ja/user-guide/campaigns-and-channels/sms-mms-and-rcs/rcs/getting-started-with-rcs/prerequisites#verification-and-launchn)します。

# 登録

登録プロセスは、アカウントマネージャーから共有されるオンボーディングフォームで、必要な情報をMoEngageに提供することから始まります。

<Info>
  要求される情報は通信事業者によって異なる場合があります。
</Info>

<img
  alt="会社RCSページ.png"
  src="/images/moengage_939632.png"
  style={{ width:"49%" }}
/>

| 情報 | 詳細 |
| --- | --- |
| **会社名** | RCSの会話で顧客に表示される会社名です。 |
| **受信者の国** | メッセージの送信先となる国です。 |
| **会社の説明** | RCSの会話で顧客に表示される会社の説明です。会社の説明のテキストは、白に対して最低4.5:1のコントラスト比が必要です。 |
| **ブランドカラーの16進数コード** | ブランドカラーの16進数コードです。たとえば、ブランドカラーが赤の場合、赤の16進数コードは#FF0000です。 |
| **顧客向け電話番号** | RCSの会話で顧客に表示される電話番号です。 |
| **顧客向けメールアドレス** | RCSの会話で顧客に表示されるメールアドレスです。 |
| **会社のWebサイト** | RCSの会話で顧客に表示される会社のWebアドレスです。 |
| **ロゴ画像** | ロゴ画像はブランドを表すものです。RCSの会話で顧客に表示されます。ロゴ画像が以下の仕様を満たしていることを確認してください。 <ul><li>画像サイズ: 224 x 224 px</li><li>形式: JPG/PNG</li><li>最大ファイルサイズ: 90 KB</li></ul> |
| **ヒーロー画像** | ヒーロー画像は、RCSの会話内のメッセージコンテンツを引き立てる、より大きく目立つ画像です。ヒーロー画像が以下の仕様を満たしていることを確認してください。 <ul><li>画像サイズ: 1440 x 448 px</li><li>形式: JPG/PNG</li><li>最大ファイルサイズ: 360 KB</li></ul> |
| **プライバシーポリシーURL** | プライバシーポリシーURLは、貴社のプライバシーポリシーにリンクし、貴社がユーザーのデータをどのように収集、使用、保護するかをユーザーに通知します。このURLはRCSの会話で顧客に表示されます。 |
| **利用規約URL** | _利用規約URL_は、貴社の利用規約にリンクし、サービスの利用に適用される法的な条件へのアクセスをユーザーに提供します。これはRCSの会話で顧客に表示されます。 |
| **テストフェーズ用の携帯電話番号** | これらの携帯電話番号はテスト目的で追加されます。\+19999999999のように国番号を含める必要があります。 |
| **送信者の課金カテゴリ** | RCSメッセージの送信コストを決定するために使用される分類を指します。この分類は、送信されるメッセージの種類とその使用状況に基づいています。 <ul><li>**Conversational**: 一定期間内の複数のA2P（Application to Person）およびP2A（Person to Application）メッセージで構成される会話に対する課金です。送信者が双方向のメッセージ交換を伴う複雑なユーザーインタラクションを行う場合は、このオプションを選択します。</li><li>**Single message**: リッチカードを含むメッセージなど、リッチなRBM（RCS Business Messaging）コンテンツを含む単一メッセージに対する課金です。送信者が主にリッチメッセージを送信し、返信をほとんど想定しない場合は、このオプションを選択します。</li><li>**Basic message**: 最大160文字のシンプルなテキストメッセージに対する課金です。送信者がSMSからRBMにアップグレードしており、返信をほとんど想定しない場合は、このオプションを選択します。一般的に、エージェントは最大160文字のプレーンテキストメッセージを送信することが想定されています。ただし、エージェントに制限はなく、そのようにプログラムされていればよりリッチなコンテンツを送信でき、それに応じて課金されます。</li></ul> **注意**: Single messageおよびBasic messageのカテゴリでは、Conversationalの課金イベントが発生することはありません。通信事業者は、配信されるコンテンツに基づいて、各メッセージにBasic messageまたはSingle messageの料金を課金します。このプロセスにより、明確でわかりやすい課金体系が確保されます。 |

RCSサービスプロバイダーは、RCSテクノロジープロバイダー（MNOなど）に公式の登録リクエストを提出します。登録プロセスには通常2～3営業日かかります。登録が完了すると、RCSテクノロジープロバイダーから通知されます。その後、接続をテストできます。

# 接続のテスト

以下の方法で接続をテストできます。

- RCSサービスプロバイダーのダッシュボードを使用してテキストメッセージを送信します。
- 許可リストに登録されたテスト用携帯電話番号を使用して、MoEngageでRCSキャンペーンを作成します。

# 検証とローンチ

アカウントマネージャーから共有される該当のローンチリクエストフォームに、以下の情報を入力します。

<Info>
  要求される情報は通信事業者によって異なる場合があります。
</Info>

| 情報 | 詳細 |
| --- | --- |
| **ブランディング** | ブランドの親会社の正式名称とWebサイトが含まれます。 |
| **ブランドの担当窓口** | RCSを通じたブランドのコミュニケーションの管理と代表を担当する、指定された個人またはチームの氏名、役職、メールアドレスです。 |

RCSサービスプロバイダーは、モバイルネットワーク事業者（MNO）に送信者の検証を依頼します。一部のMNOでは、サービスを利用するために追加のチェックを完了する必要があります。詳細については、RCSサービスプロバイダーのアカウントマネージャーにお問い合わせください。

ローンチが承認されると、追加のテストや承認なしで、RCSメッセージとキャンペーンを無制限に送信できます。連絡先をテスターとして招待したり、番号をセーフリストに登録したりする必要はありません。
