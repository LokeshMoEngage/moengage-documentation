DLT 規制に準拠するには、SMS 設定にいくつかの変更を加える必要があります。これにより、現在および今後の SMS キャンペーンが中断されることはありません。詳細については、[SMS DLT 規制と登録プロセス](/ja/user-guide/campaigns-and-channels/sms-mms-and-rcs/compliance-and-deliverability/messaging-regulations-for-india)を参照してください。

<Info>
  - DLT 規制はインドでのみ適用されるため、これらの変更はインドの携帯電話番号に SMS を送信する場合にのみ適用されます。
  - 規制プロセスでは、すべての通信事業者でエンティティ ID、送信者 ID、テンプレート ID のスクラビングが必要です。
  - すべてのコンテンツテンプレートが通信事業者の DLT ポータルにアップロードされていることを確認してください。
</Info>

この記事では、DLT 規制によって影響を受ける領域と、それに対して必要な対応について説明します。

## SMS プロバイダーで DLT 固有の詳細を更新する

DLT プラットフォームのスクラビング要件に従い、通信事業者は、すべてのメッセージ送信で以下の情報を受け取った場合にのみメッセージを受け付けて配信します。

- Principal Entity ID
- Sender ID
- Template ID

SMS プロバイダー Gupshup および Kaleyra で従う手順を以下に示します。

<Tabs>
  <Tab title="Gupshup">
    1. アカウントのログイン情報と OTP を使用して [Gupshup ポータル](https://enterprise.smsgupshup.com/)にログインします。
    2. DLT Template モジュールに移動します。Single Template と Upload Template List の 2 つのタブがあります。
    3. Single Template セクションで以下を入力し、_SUBMIT_ をクリックします。
       - Template Name
       - Template Id (URN)
       - Transactional (yes/no)
       - DLT Message Type
       - Message Type
       - Business Category
       - Mask
       - Template content.
    4. Upload template list セクションで、上記と同じ詳細を入力します。これは一括アップロードのオプションで、多数のテンプレートを同時にアップロードできます。
  </Tab>
  <Tab title="Kaleyra (Solution Infini)">
    Kaleyra は新しいサービス「[DLT AI](https://messaging.kaleyra.com/support/solutions/folders/3000018909)」をリリースしました。これにより、一切の変更を加えずにメッセージ送信プロセスを継続できます。必要な作業は以下のとおりです。

     1. Entity ID と Sender ID を送信します。詳細については、[Kaleyra での Entity ID と Sender ID の送信](https://support.kaleyra.com/support/solutions/articles/3000102533-principle-entity-id-addition-%E2%80%93-kaleyra-platform)を参照してください。
     2. Template ID を送信します。詳細については、[Kaleyra テンプレート](https://support.kaleyra.com/support/solutions/articles/3000102535-template-addition-kaleyra-platform)を参照してください。
  </Tab>
</Tabs>

Kaleyra のプラットフォームで Entity ID と Template ID を追加すると、これらの詳細が自動的にマッピングされ、リクエストが通信事業者に送信されます。

<Info>
  - プロモーション SMS とトランザクション SMS の両方で上記の手順を完了していることを確認してください。
  - Custom Connectors を使用して SMS を送信している場合は、SMS プロバイダーに問い合わせて、DLT フィールド (Entity ID、Sender ID、Template ID) の渡し方を確認してください。
</Info>

## MoEngage ダッシュボードで設定を更新する

SMS Gupshup または Kaleyra を統合プロバイダーとして使用している場合は、MoEngage ダッシュボードで Sender ID を更新してください。トランザクション SMS とプロモーション SMS の両方について、すべての送信者の Sender ID フィールドに、DLT プラットフォームで登録および承認された Header ID を入力します。これにより、SMS キャンペーンが影響を受けないようにできます。

## 承認済みテンプレートに従って SMS を設定する

テンプレートのスクラビングガイドラインに従い、SMS コンテンツは承認済みテンプレートに準拠させる必要があります。SMS が承認済みテンプレートのいずれとも一致しない場合、SMS は拒否されます。

承認済みテンプレートの _#var#_ パラメーターで、動的な値やパーソナライズされた値を渡すことができます。各 _#var#_ には 30 文字の制限があります。_#var#_ を組み合わせて使用することで、より多くの文字数に対応できます。必要に応じてテンプレートを設定し、承認を取得してください。
