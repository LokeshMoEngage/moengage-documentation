Web Personalization は、ユーザーがサイトにアクセスしたときにパーソナライズされたデータを配信することで、Web サイトのコンテンツを個々のユーザーに合わせてカスタマイズするのに役立ちます。これにより、各ユーザーに最も関連性の高いエクスペリエンスを表示できます。

Web Personalization の一般的なユースケースは以下のとおりです。

- ユーザーの行動に基づいてホームページのバナーをパーソナライズする。
- ユーザーの所在地に基づいて、ローカライズされた Web サイトコンテンツを表示する。
- 新しいページレイアウトをテストして、パフォーマンスを向上させる要素を確認する。

## Web Personalization の利用開始

Web Personalization を実装するには、以下の要件を満たしていることを確認してください。

1. セルフハンドル型キャンペーンを設定する前に、MoEngage の Web SDK を連携していることを確認します。詳細については、[Web SDK の連携](/ja/developer-guide/web-sdk/web-sdk-integration/basic-integration/web-sdk-integration)を参照してください。
2. CSM または MoEngage サポートチームに連絡して、MoEngage アカウントで MoEngage Web Personalization を有効にします。
3. パーソナライズの失敗、API の失敗、または MoEngage サーバーからのコンテンツ取得の遅延が発生した場合に表示する、デフォルトコンテンツとフォールバックコンテンツを処理していることを確認します。
4. セルフハンドル型キャンペーンでは、MoEngage がパーソナライズされたデータを Web サイトに配信することを理解してください。その後、Web サイトがこのデータを処理し、表示を管理します。
5. データが Web サイトに表示された後、*Impression* イベントと *Click* イベントを MoEngage に送信するように Web サイトを設定します。これにより、MoEngage はキャンペーンのパフォーマンス統計を計算できます。詳細については、[Personalize API エクスペリエンスのイベントトラッキング](/ja/developer-guide/personalize-sdk/sdk-integration/personalize-api-experience-events-tracking)を参照してください。

## TAG\_NAME について

MoEngage ダッシュボードで作成されたすべての Web Personalization キャンペーンは、Web パーソナライズキャンペーン作成ジャーニーの[ステップ 2: キャンペーンデータ](/ja/user-guide/campaigns-and-channels/web-personalization/create/create-a-web-personalization-campaign)で説明されているように、**Campaign Tag** に関連付けられています。この TAG\_NAME は、MoEngage Web SDK が利用可能なキャンペーンの中から、パーソナライズされたコンテンツを取得する正確なキャンペーンを選択するのに役立ちます。

*Tag\_Name* は、パーソナライズされたデータを取得する関数のパラメーターです。この関数が呼び出されると、MoEngage SDK はパーソナライズされたデータを Web サイトに配信します。データを受信した後、Web サイトはこのデータを使用してアクションを実行する必要があります。
