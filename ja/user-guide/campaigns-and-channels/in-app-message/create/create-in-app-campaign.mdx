In-App キャンペーンを作成するには、次の手順に従います。

1. MoEngage ダッシュボードのサイドバーで **Engage** にカーソルを合わせます。**Engage** メニューが表示されます。
2. **\+ New Campaign** をクリックします。New Campaign ダイアログボックスが表示されます。**Engage** メニューの **All Campaigns** をクリックし、All campaigns ページで **\+ Create campaign** をクリックすることもできます。 <img src="/images/moengage_ceb916.png" alt="+ New Campaign オプションがハイライトされた Engage メニュー" />
3. **Inbound** の下にある **In-app** をクリックします。In-App キャンペーンの作成ページが表示されます。 <img src="/images/moengage_617e13.png" alt="Inbound の下の In-app オプションがハイライトされた New Campaign ダイアログボックス" />

# In-App メッセージキャンペーンの作成

In-App メッセージキャンペーンを作成するには、次の手順に従います。

1. [ユーザーのターゲティング](#step-1-target-users): キャンペーンのオーディエンスを定義します。
2. [コンテンツ](#step-2-content): メッセージのコンテンツをデザインします。
3. [スケジュールとゴール](#step-3-schedule-and-goals): 配信スケジュールを設定し、キャンペーンのパフォーマンスをトラッキングします。

## Step 1: Target Users

### キャンペーンの詳細

**Campaign Details** セクションには次の項目があります。

![details.png](/images/moengage_048d33.png)

- **Campaign name**: キャンペーンを簡単に識別・管理できるように名前を入力します。キャンペーン名は 5～256 文字である必要があります。
- **Campaign tags**: ドロップダウンリストから最大 5 つのタグを選択します。タグを使用すると、キャンペーンを整理・フィルタリングできます。詳細については、[Campaign Tags](/ja/user-guide/campaigns-and-channels/getting-started/introduction/campaign-tags) を参照してください。

### プラットフォームの選択

**Target platforms** セクションで、In-App メッセージを表示するプラットフォームを選択します。

![platforms.png](/images/moengage_1dd469.png)

<Info>
  [Portfolio](/ja/user-guide/settings/account/portfolio/portfolio) が有効になっている場合は、**Select Project** ドロップダウンからターゲットプロジェクトを選択して、キャンペーンを配信するウェブサイトを指定できます。詳細については、[Portfolio for In-App Campaigns](/ja/user-guide/campaigns-and-channels/in-app-message/getting-started-with-in-app-message/portfolio-for-in-app-campaigns) を参照してください。
</Info>

## トリガー条件

このセクションでは、In-App メッセージがユーザーに対してトリガーされるタイミングを定義します。

<Tabs>
  <Tab title="セッション開始時">
    **On session start** を選択すると、ユーザーのアプリセッションが開始されるとすぐに In-App メッセージが表示されます。アプリセッションは、ユーザーがアプリを最初に操作したときに開始されます。ユーザーがログアウトした場合、別のトラフィックソースから流入した場合、または定義された非アクティブ期間（デフォルトは 30 分）を超えて操作がない場合に、セッションは終了します。

    ![On session start が選択された Trigger criteria カード。](/images/on-session-start.png)

    **Select trigger time** で、キャンペーンの公開後すぐにメッセージを送信するには **Immediately** を、指定した時間の経過後にメッセージを送信するには **After Delay** を選択します。

    <Info>
      - In-App メッセージがスプラッシュ画面に表示されないように、必ず遅延を追加してください。
      - **After Delay** オプションでは、最大 1 日（86400 秒）、最小 1 秒の遅延を設定できます。
      - **After Delay** オプションは、次の SDK で利用できます。
        - Android SDK バージョン 6.9.0 以降
        - iOS SDK 4.11.1 以降
        - React Native SDK 8.6.0 以降
        - Cordova SDK 8.4.0 以降
        - Capacitor SDK 3.1.0 以降
      - このトリガー条件は、次の SDK で利用できます。
        - Android SDK バージョン 9.0.0 以降
        - iOS SDK バージョン 6.06.0 以降
      - このトリガー条件は、現在ネイティブの Android および iOS でのみ利用できます。ハイブリッドはサポートされていません。
    </Info>
  </Tab>
  <Tab title="画面読み込み時">
    **On screen load** を選択すると、特定の画面またはアプリコンテキストで In-App メッセージが表示されます。

    ![On screen load が選択された Trigger criteria カード。](/images/on-screen-load-selected.png)

    **Select screen/In app context** では、次のオプションを選択できます。

    ![Screenshot 2025-03-03 at 4.15.36 PM.png](/images/moengage_2aa553.png)

    - **Any screen (Earlier on app open)**: アプリが開かれるとすぐに、_showInApp()_ または _showNudge()_ が明示的に呼び出されている任意の画面にメッセージが表示されます。最初に開かれた画面にこれらのメソッドが存在しない場合、ユーザーがこれらのメソッドが呼び出される画面に移動するまでメッセージは表示されません。たとえば、アプリに 10 個の画面があり、そのうち 5 個の画面にメソッドを追加した場合、メソッドが追加されたすべての画面にメッセージが表示されます。メソッドが存在するすべての画面にメッセージが表示されないようにするには、キャンペーンに適切な配信コントロールを追加してください。配信コントロールの詳細については、[こちら](#delivery-controls)を参照してください。
    - **Specific screens**: **Specific screens** を選択した後、選択したプラットフォームに基づいて画面またはアプリコンテキストを設定します。In-App メッセージには、画面、アプリコンテキスト、またはその両方を設定できます。
      - **Screen**: アプリケーションには、ログイン、ホーム、商品、チェックアウト画面など、複数の画面が含まれる場合があります。**Android** タブと **iOS** タブで、In-App キャンペーンを表示する場所を選択します。**Screen is any of** リストから画面を選択します。最大 5 つの画面を選択できます。これは OR 条件のため、選択した画面のいずれかにメッセージが表示されます。
      - **App context**: コンテキストとは、メッセージを表示できる画面のセクションまたは一部です。たとえば、ポッドキャスト画面には _For you_ と _All episodes_ の 2 つのコンテキストを設定できます。目的のアプリコンテキストに In-App キャンペーンを表示するには、**App context is any of** フィールドにコンテキスト名を追加します。これは OR 条件のため、いずれかのアプリコンテキストにメッセージが表示されます。最大 5 つのアプリコンテキストを選択できます。コンテキストの詳細については、[Android](/ja/developer-guide/android-sdk/in-app-messages/in-app-nativ) および [iOS](/ja/developer-guide/ios-sdk/in-app-messages/in-app-nativ) を参照してください。

    ![In-App メッセージの特定の画面とアプリコンテキストを選択しています。](/images/on-screen-load.gif)

    **Select trigger time** で、キャンペーンの公開後すぐにメッセージを送信するには **Immediately** を、指定した遅延後にメッセージを送信するには **After Delay** を選択します。

    <Info>
      - In-App メッセージを表示するには、画面に _showInApp()_ または _showNudge()_ メソッドを追加する必要があります。詳細については、[Display In-App](/ja/developer-guide/android-sdk/in-app-messages/in-app-nativ) を参照してください。
      - **After Delay** オプションでは、最大 1 日（86400 秒）、最小 1 秒の遅延を設定できます。
      - **After Delay** オプションは、In-App Android SDK バージョン 6.9.0 以降および In-App iOS 4.11.1 以降でのみ利用できます。
      - 旧トリガー条件 **On app open** を使用している既存のキャンペーンは、**On specific screen** トリガーの **Any screen** に移行されます。
      - 画面の取得動作:
        - **Android の場合**: MoEngage は MoEngage SDK を通じて、選択された画面をアプリから自動的に取得します。
        - **iOS の場合**: In-App メッセージを表示する画面名を入力する必要があります。
      - このトリガー条件は、次の SDK で利用できます。
        - Android SDK バージョン 9.0.0 以降
        - iOS SDK バージョン 6.06.0 以降
      - このトリガー条件は、現在ネイティブの Android および iOS でのみ利用できます。ハイブリッドプラットフォームはサポートされていません。
    </Info>
  </Tab>
  <Tab title="カスタムイベント発生時">
    **On custom event** を選択すると、ユーザーが特定のカスタムイベントを実行したときに In-App メッセージが表示されます。

    ![On custom event が選択された Trigger criteria カード。](/images/on-custom-event-selected.png)

    #### **IF user**

    このセクションでは、In-App キャンペーンのイベント条件を選択します。ユーザーがこのイベントを実行すると、MoEngage は In-App キャンペーンを送信します。複数のイベントと属性を追加できます。

    1. **Select an event** リストからイベントを選択します。
    2. In-App Android SDK バージョン 8.1.0 および In-App iOS SDK バージョン 5.0.1.1 以降では、**\+ Trigger** をクリックして、イベント内に複数の OR 条件を追加できます。たとえば、モバイルで In-App を 1 回以上クリックしたユーザーに In-App メッセージを表示できます。

    ![+ Trigger を使用して OR 条件が追加されたイベントトリガー。](/images/on-custom-event-or-condition.png)

    カスタムイベントをさらに絞り込むこともできます。

    1. **\+ Attributes** をクリックして、フィルターに属性を追加します。
    2. **Select attribute** ドロップダウンリストから属性を選択し、選択した属性の論理ドロップダウンを選択します。
    3. さらに属性を追加するには:
    4. **\+ Attribute** をクリックします。
    5. **AND** または **OR** をクリックします。
    6. **Select attribute** リストから属性を選択し、選択した属性の論理ドロップダウンを選択します。

    たとえば、イベント _User installs the app_ を選択した場合、属性 _App Version_ を追加して、アプリの特定のバージョンをインストールしたユーザーをフィルタリングできます。

    ![](/images/moengage_b8d968.png)

    #### **AND then**

    **AND then** 機能を使用すると、さらにカスタマイズを追加できます。**\+ Trigger** オプションに加えて、**\+ Filter** ボタンを使用すると、複数のイベントをつなげることができます。

    たとえば、_In-App Clicked Android_ イベントを選択し、**AND then** オプションを使用して _Added to Cart_ イベントを追加できます。

    これにより、モバイルデバイスで In-App キャンペーンを 1 回以上クリックし、かつその後カートに商品を 1 回以上追加したユーザーに In-App キャンペーンが表示されます。

    ![+ Filter を使用して AND then 条件で組み合わされた 2 つのイベント。](/images/on-custom-event-and-condition.png)

    **Filter** 条件のイベントが評価されるまでの待機時間を定義することもできます。この制限を 15 分に設定すると、ユーザーは最初のトリガーイベントを実行してから 15 分以内に **Filter** イベントを実行する必要があります。この例では、最初のイベントは _In-App Clicked Android_ です。ここでは、最大 24 時間、最小 1 分の遅延を設定できます。

    ![3.png](/images/moengage_85d71a.png)

    **\+ Filter** を再度クリックすると、トリガー条件に別のイベントを追加できます。_AND_ または _OR_ を選択するオプションが表示されます。_AND_ を選択して 2 つのフィルター条件を組み合わせるか、_OR_ を使用して、制限時間内にいずれかのイベントを実行したユーザーをフィルタリングします。

    ![](/images/moengage_bf15cc.png)

    #### **THEN**

    **THEN** セクションの **Trigger the message** で、メッセージを表示するタイミングを定義するオプションを選択します。利用可能なオプションは次のとおりです。

    - **Immediately**: トリガー条件が満たされた直後にメッセージが表示されます。
    - **After Delay**: 定義した遅延後にメッセージが表示されます。

    ![5.png](/images/moengage_544cc5.png)

    **Trigger criteria summary**: このセクションには、選択したイベントと属性に基づくトリガーの概要が表示され、トリガー条件を理解しやすくなります。

    ![Screenshot 2025-03-03 at 4.45.50 PM.png](/images/moengage_6156e6.png)

    <Info>
      - **Filter** で同じイベントを選択し、かつ **Then** オプションを使用しないでください。エラーメッセージが表示され、キャンペーンは実行されません。
      - **AND then** オプションは、In-App Android SDK バージョン 8.1.0 以降および In-App iOS 5.01.1 以降でのみ利用できます。
      - _After Delay_ を選択した場合、最大 1 日（86400 秒）、最小 1 秒の遅延を設定できます。
      - _After Delay_ オプションは、In-App Android SDK バージョン 6.9.0 以降および In-App iOS 4.11.1 以降でのみ利用できます。
      - Data API またはその他のサーバーサイドソースから受信したイベントは、カスタムイベントのトリガーアクションとしてサポートされていません。
    </Info>
  </Tab>
  <Tab title="プッシュクリック時">
    **On push click** を選択すると、この In-App キャンペーンをプッシュキャンペーンにリンクできます。ユーザーが接続されたプッシュ通知をクリックすると、ターゲット画面に In-App メッセージが表示されます。

    ![On push click トリガーカードが選択され、その下に Select Push Campaign と Select trigger time オプションが表示されている画面。](/images/on-push-click-1.png)

    このトリガーを設定するには:

    1. **Trigger criteria** で **On push click** を選択します。
    2. **Select Push Campaign** で、最初のドロップダウンから **Campaign name** または **Campaign ID** を選択し、キャンペーンリストからリンクするプッシュキャンペーンを選択します。**Search to select** を使用して、名前または ID でキャンペーンを検索できます。リストには公開済みのプッシュキャンペーンのみが表示されます。
    3. **Select trigger time** で、次のいずれかを選択します。
       - **Immediately**: ユーザーがプッシュをクリックしてアプリが開くとすぐに In-App メッセージが表示されます。
       - **After Delay**: 設定した遅延（たとえば 3 秒後）の後に In-App メッセージが表示されます。遅延を使用すると、メッセージが表示される前にディープリンク先の画面の読み込みを完了させることができます。

    ![Campaign name と Campaign ID のフィルターオプションが表示された Select Push Campaign ドロップダウン。](/images/on-push-click-2.png)

    このトリガーを選択すると、**Select Target Audience** セクションは **All Users** に固定されます。実際のオーディエンスは、リンクされたプッシュキャンペーンを受信してクリックしたユーザーのセットです。

    **ユーザーの体験:**

    1. ユーザーがプッシュ通知、またはその中に設定されたアクションボタンをクリックします。
    2. アプリは、プッシュキャンペーンで指定されたディープリンクまたは画面（たとえば支払い画面）を開きます。
    3. MoEngage は、そのプッシュキャンペーンにリンクされた In-App キャンペーンがあるかどうかを確認します。一致するものが見つかった場合、その画面の上に In-App メッセージが表示されます。一致するものが見つからない場合、In-App メッセージは表示されず、ユーザーはディープリンク先の画面にとどまります。

    <Info>
      **サポートされているプッシュキャンペーンの種類**

      | プッシュキャンペーンの種類 | サポート |
      | --- | --- |
      | One Time | はい — プッシュを特定の時刻にスケジュールしてください |
      | Event-Triggered | はい |
      | Device-Triggered | はい |
      | Location-Triggered | はい |
      | Periodic | いいえ |

      One Time プッシュキャンペーンの場合は、できるだけ早く送信するのではなく、特定の時刻にプッシュをスケジュールしてください。Periodic プッシュキャンペーンは、各インスタンスが内部的に個別のキャンペーンとして作成されるため、キャンペーンリストには表示されません。

      **サポートされているプッシュクリックアクション**

      リンクされた In-App メッセージは、プッシュクリックアクションが **Deep link** または **Navigate to screen** の場合にのみ表示されます。これは、デフォルトの通知クリックとアクションボタンの両方に適用されます。**Rich landing** は、In-App メッセージを重ねて表示できないウェブビューを開くため、サポートされていません。

      **サポートされているプラットフォーム**: Android および iOS。Web プッシュはサポートされていません。

      **利用可能なバージョン**: Android Bill of Materials (BOM) SDK バージョン 2.3.0 以降および iOS SDK バージョン 10.14.0 以降で利用できます。
    </Info>

    <Warning>
      リンクされた In-App メッセージは、次の場合には表示されません。

      - プッシュクリックアクションが **Rich landing**、または Deep link や Navigate to screen 以外のアクションである場合。この場合、MoEngage は[配信ファネル](/ja/user-guide/campaigns-and-channels/in-app-message/analyze/analyze-in-app-campaigns)にエラーを記録します。
      - ディープリンクが、アプリ内の画面ではなく、ブラウザーなどの別のアプリを開く場合。
      - ディープリンクまたは画面が、ブロックされた画面に解決される場合。
      - プッシュがセルフハンドル通知を使用している場合。
      - プッシュキャンペーンが Periodic である場合、または Flow 内のノードとして作成された場合。リンクできるのは、**Engage** \> **Campaigns** \> **Push** から作成されたスタンドアロンのプッシュキャンペーンのみです。
    </Warning>
  </Tab>
</Tabs>

## ターゲットオーディエンスの選択

このセクションには、キャンペーンのターゲットオーディエンスを選択するためのセグメンテーションフィルターが含まれています。

<Tabs>
  <Tab title="すべてのユーザー">
    このフィルターオプションを選択すると、すべてのアプリユーザーにキャンペーンを送信します。このオプションを使用する場合、複数のフィルターを追加することはできません。

    ![6.png](/images/moengage_a7af66.png)
  </Tab>
  <Tab title="ユーザープロパティでフィルタリング">
    このフィルターオプションを選択すると、初回表示日時、最終表示日時、都市などのプロパティに基づいてユーザーをターゲティングできます。**User property** タブをクリックし、次の手順に従います。

    1. ドロップダウンリストから目的の属性を選択します。これにより、選択した属性に基づくフィルターが有効になります。たとえば、数値属性には 'is equal to'、'is not equal to'、'is between' などのフィルター条件があり、文字列属性には異なるフィルターがあります。
    2. フィルター値を入力して、目的のユーザーセグメントを作成します。
    3. **\+ Nested Filter** をクリックしてフィルターを追加し、ネストされた AND または OR 条件を作成します（任意）。

    詳細については、[Create Segments](/ja/user-guide/segment/create-segments/rule-based-filter-segments) を参照してください。

    ![UserProperty.png](/images/moengage_97cc86.png)
  </Tab>
  <Tab title="ユーザー行動でフィルタリング">
    このフィルターオプションを選択すると、アプリ/サイトの起動や商品の閲覧など、ユーザーの行動やイベントに基づいてユーザーをターゲティングできます。**User Behavior** をクリックし、次の手順に従います。

    1. 実行条件と目的のユーザーアクティビティ（イベント）を選択します。
    2. イベントの頻度とイベント実行の期間を入力します。
    3. **\+ Attributes** をクリックし、フィルター条件付きのイベント属性を追加します。
    4. フィルター値を入力してルールを作成します。
    5. **\+ Aggregation** ボタンを使用して集計機能を追加します。詳細については、[Aggregation Operations](/ja/user-guide/segment/advanced-concepts/aggregation-operations) を参照してください。
    6. **\+ Nested Filter** をクリックしてフィルターを追加し、ネストされた AND または OR 条件を作成します（任意）。

## キャンペーン適格性の再評価

デフォルトでは、セグメントのメンバーシップは、ユーザーがアプリを開いたときの最初のキャンペーン呼び出し時に評価されます。セッション中に発生した属性の変更は、次回のアプリ起動まで反映されません。**Re-evaluate campaign eligibility before displaying** トグルを有効にすると、SDK はキャンペーンのトリガーをインターセプトして、バックエンドとのライブチェックを実行します。ユーザー属性が変更されている場合（たとえば、Free から Paid ステータスへの移行）、SDK は古いキャンペーンを破棄し、ユーザーの更新された状態に関連するコンテンツを取得します。再評価は、一度に最大 5 つの In-App キャンペーンで有効にできます。

<Info>
  **情報**

  **利用可能な条件と範囲**

  - **SDK バージョン**: セグメントの再評価は、In-app Android SDK バージョン 9.7.0 および In-app IOS SDK バージョン 7.04.0 以降でサポートされています。
  - **サポートされているセグメント**: この機能は、User Attribute ベースのセグメントと Real-Time Segment Evaluation (RTSE) セグメントでのみ利用できます。
  - **除外されるセグメント**: リアルタイムの変更が適用されないセグメントタイプ（たとえば、静的セグメント）では、このオプションは非表示になります。
  - **制限**: このオプションは最大 5 つのキャンペーンで利用できます。
</Info>

**実行ロジック**

有効にすると、実行ロジックは次のようになります。

1. **トリガーの検出**: ユーザーがトリガー条件に一致するアクションを実行します。
2. **バックエンドでの検証**: SDK が新しい評価のためにバックエンドリクエストを開始します。
3. **適格性チェック**: バックエンドがユーザーの現在の属性を評価します。ユーザーが適格である場合はキャンペーンが表示され、適格でない場合はキャンペーンが破棄されて失敗が記録されます。
4. **キャンペーンの更新**: キャンペーンが破棄された場合、SDK は新しいキャンペーン呼び出しを実行して、更新されたセグメントに関連するキャンペーンを取得します。
5. **キャンペーンの表示**: 新しい適格なキャンペーンが、同じセッション内の次のトリガー時にユーザーに表示されます。

**ユーザージャーニーの例**

| ステップ | アクション | ロジック | 結果 |
| --- | --- | --- | --- |
| 1 | ユーザーがアプリを開きます。 | SDK がキャンペーン呼び出しを実行します。ユーザーは "Free" として識別されます。 | キャンペーン A（Free ユーザー向け）がキャッシュされます。 |
| 2 | ユーザーがプランをアップグレードします。 | 属性が Plan: Free から Plan: Paid に変わります。 | SDK が属性の変更を検出します。 |
| 3 | ユーザーがトリガーアクションを実行します。 | **Re-evaluate campaign eligibility before displaying** トグルがオンになっています。SDK がバックエンドを呼び出します。 | 検証のためにキャンペーンの表示が一時停止されます。 |
| 4 | 評価が行われます。 | バックエンドがユーザーを "Paid" として識別します。 | キャンペーン A が破棄され、失敗が記録されます。 |
| 5 | 表示。 | SDK が "Paid" ステータスのキャンペーンを取得します。 | 次のトリガーポイントでキャンペーン B（Paid）が表示されます。 |

_注: この機能を無効にすると、ユーザーがアップグレードした後も、アプリが再起動されるまで SDK はキャンペーン A（Free）を表示し続けます。また、後続のキャンペーンで再評価が有効になっていない場合、SDK はそれらの特定のキャンペーンに対してリアルタイムチェックを実行しません。_

## セッション内属性

セッション内属性を使用すると、現在のアプリセッション内でのアクションに基づいてユーザーをグループ化し、ターゲティングできます。たとえば、セッション内属性を使用して、初めてアプリにアクセスした新規ユーザーにのみオンボーディングフローを表示できます。この方法により、これらのユーザーは最初のセッション中にすぐにカスタマイズされた体験を得ることができます。

セッション内属性を追加するには:

1. **\+ In-session attributes** ボタンをクリックし、リストから必要な属性を選択します。 <img src="/images/moengage_e00742.png" alt="Screenshot 2025-01-21 at 2.47.47 PM.png" />
2. **And**/**Or** を使用して、複数のセッション内属性を組み合わせます。 <img src="/images/moengage_efe554.png" alt="Screenshot 2025-01-21 at 2.46.44 PM.png" />
3. セッション内のアクティビティに基づいてユーザーを除外するには、**Exclude Users** チェックボックスを選択します。

In-App キャンペーンでは、次のセッション内属性を使用できます。

- **Query Parameter**: この属性は、Uniform Resource Locator (URL) のクエリパラメーターに基づいてユーザーをセグメント化します。通常、ユーザーはソーシャルメディアプラットフォーム上の広告をクリックして、パーソナライズされた URL にアクセスします。
  - UTM パラメーターを使用すると、ユーザーを URL に誘導したソースやキャンペーンに基づいてユーザーをセグメント化できます。
  - _utm\_source_ などの UTM パラメーターは、ユーザーをウェブサイトに誘導しているキャンペーンを識別します。UTM パラメーターとカスタムパラメーターを使用して、ユーザーをセグメント化し、体験をパーソナライズできます。
- **User Type**: この属性は、ユーザーが新規かリピーターかに基づいてユーザーをセグメント化します。SDK は、各ユーザーのユーザー詳細（_unique\_id_）をアプリストレージに保存します。関連するユーザー詳細が SDK のデータストレージに存在する場合、ユーザーは _Returning User_ と見なされます。それ以外の場合、ユーザーは _New_ と見なされます。ユーザーがアプリのキャッシュをクリアした場合、そのユーザーは新規と見なされます。
  - 注: 2 人のユーザー（User 1 と User 2）が同じデバイスを使用し、User 1 の後に User 2 がログインした場合、User 2 はリピーターと見なされます。
- **Day of the Week**: この属性は、ユーザーがアプリにアクセスした曜日に基づいてユーザーをセグメント化します。
- **Time of the Day**: この属性は、ユーザーがアプリにアクセスした時間帯に基づいてユーザーをセグメント化します。リストにある 1 時間単位のスロットから選択できます。
- **GeoLocation**: この属性は、ユーザーがアプリにアクセスしたときの地理的位置に基づいてユーザーをセグメント化します。ユーザーが所在する国、州/地域、都市を選択するか、特定の国を除外できます。

### コンテンツのパーソナライズ

'@' 記号を使用してユーザー属性、ユーザーイベント、商品セット、Content API、コンテンツブロックを挿入することで、In-App キャンペーンのコンテンツをパーソナライズできます。これにより、ユーザーごとに動的で関連性の高いメッセージを配信できます。

詳細については、次を参照してください。

- [MoEngage Templating Language (JINJA)](/ja/user-guide/campaigns-and-channels/getting-started/message-personalization/jinja-templating-language)
- [Derived Events & Attributes](/ja/user-guide/data/event-data/derived-events-and-attributes)
- [Content APIs](/ja/user-guide/campaigns-and-channels/getting-started/campaign-content/content-apis)
- [Content Block](/ja/user-guide/content/content-blocks/content-blocks)
- [Auxiliary Data](/ja/user-guide/data/imports/auxiliary-data)

次の操作を行います。

1. キャンペーン作成のステップ 2 で、テキストボックスまたは画像プロパティの URL をクリックします。
2. **@** と入力してコンテンツをパーソナライズします。
3. **Data personalization** または **Content Block** のいずれかをクリックします。
4. **Data personalization** タブをクリックし、ドロップダウンから次のいずれかを選択します。
   1. **User Attributes**
   2. パーソナライズが機能しない場合のフォールバックオプションとして、次のいずれかを選択します。
      - **No Fallback**: パーソナライズに失敗した場合、代替コンテンツは提供されません。
      - **Do not send In-App**: パーソナライズに失敗した場合、In-App メッセージは送信されません。
      - **Replace Text**: パーソナライズに失敗した場合に使用するテキストを入力または貼り付けます。
   3. **Product Sets**
   4. **Content API**: Content API パラメーターの値を変更します。
5. **Content Block** をクリックします。
   1. 挿入するコンテンツブロックを選択します。
   2. **Insert only the content of the content block** をクリックします。
6. **Done** をクリックします。

  - Unique ID
  - Email ID

### Conversion Goals

キャンペーンのビジネス指標をトラッキングするために、最大 5 つのコンバージョンゴールを追加できます。任意のアプリイベントをコンバージョンゴールのアクティビティとして選択できます。最初のゴールはプライマリゴールとして扱われます。

たとえば、キャンペーンの送信後に iPhone を購入した顧客の数（Event: Purchase event、Product: iPhone）をトラッキングする場合、コンバージョンゴールの設定は次の画像のようになります。

![ConVErsionGoals.png](/images/moengage_9b7d41.png)

複数のコンバージョンゴールを使用すると、複数のビジネス指標をトラッキングしたり、ユーザーアクションのファネルを可視化したりできます。たとえば、複数のコンバージョンゴールを使用して次を確認できます。

- 商品ページを閲覧したユーザーは何人か。
- その商品をカートに追加したユーザーは何人か。
- 注文を完了したユーザーは何人か。

### キャンペーンの優先度

In-App キャンペーンの優先度を **Critical**、**High**、**Medium**、**Normal**、**Low** のいずれかに設定します。

**On push click** トリガーを使用するキャンペーンには、追加の **Critical - Functional** 優先度があります。Critical - Functional は Critical を含む他のすべての優先度よりも上位にランク付けされるため、リンクされた In-App メッセージは他のすべてのキャンペーンよりも優先して表示されます。On push click キャンペーンでは、優先度は自動的に Critical - Functional に設定され、変更できません。

### Delivery Controls

In-App キャンペーンでは、次のオプションを選択できます。

- **Limit the maximum number of times a user can see messages from this campaign to**: メッセージを表示する回数を入力して、キャンペーンの頻度をコントロールします。**注**: フリークエンシーキャップはユーザーレベルではなく、デバイスレベルで機能します。つまり、ユーザーが 2 台のデバイスに同時にログオンしている場合、頻度の設定が 1 に設定されていても、両方のデバイスでキャンペーンを受信します。
- **Add a minimum delay between two messages of this campaign**: 2 つのメッセージ間に最小遅延を追加して、ユーザーに In-App メッセージを表示する頻度とタイミングをコントロールします。この設定は Nudge テンプレートでは無効です。
- **Ignore frequency capping**: この In-App キャンペーンでフリークエンシーキャップの制限を無視するには、このトグルを有効にします。詳細については、[Frequency Capping](/ja/user-guide/settings/channels/delivery-controls/frequency-capping) を参照してください。**注**: フリークエンシーキャップは、In-App Android SDK バージョン 9.8.0 および In-App iOS SDK バージョン 7.04.0 以降でサポートされています。
- **Count for frequency capping**: In-App メッセージを全体のフリークエンシーキャップに含めて、ユーザーに配信されたメッセージの総数をモニタリングする場合は、このトグルを有効にします。 <img src="/images/moengage_1e5562.png" alt="Screenshot 2025-10-22 at 12.17.37 PM.png" />
- **Ignore global minimum delay**: この特定のキャンペーンについて、グローバル最小遅延の設定を有効または無効にします。
- **Auto Dismiss message after**: このオプションは、指定した期間（秒単位）の経過後に In-App メッセージを閉じます。指定した時間が経過すると、ユーザーが何も操作しなくても In-App メッセージは閉じられます。

<Note>
  **On push click** キャンペーンでは、ユーザーがプッシュをクリックしたときにリンクされた In-App メッセージが常に表示されるように、MoEngage が配信コントロールを自動的に設定します。表示の最大回数、メッセージ間の最小遅延、**Ignore frequency capping**、**Ignore global minimum delay**、**Count for the frequency capping** は無効になっており、変更できません。設定可能なのは **Auto dismiss message after** のみです。
</Note>

<Accordion title="2 つのキャンペーン間の遅延">
  複数の In-App キャンペーンがある場合は、異なるキャンペーンのメッセージ間に最小遅延を設定して、表示タイミングをずらすことができます。**Settings** \> **Channels** \> **Delivery controls** に移動します。

  **注**: この最小遅延は、異なるキャンペーンのメッセージと同じキャンペーンのメッセージの両方に適用されます。

  ここでは、異なるキャンペーンの 2 つの In-App メッセージ間の最小遅延（分単位）を設定できます。この設定により、ユーザーが時刻 T にキャンペーン 1 のメッセージを表示し、T\+15 より前に別のメッセージが送信された場合、そのメッセージは表示されません。

</Accordion>
