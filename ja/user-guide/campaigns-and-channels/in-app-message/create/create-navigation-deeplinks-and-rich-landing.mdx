# アプリ内メッセージのナビゲーションアクションでユーザーを誘導する

アプリ内メッセージは、ユーザーのエンゲージメントを高め、アプリ内でユーザーを誘導するための強力なツールです。MoEngage では、アプリ内メッセージのウィジェットに追加できる 3 種類のナビゲーションアクション（**Navigate to Screen**、**DeepLink**、**Rich Landing**）を提供しています。これらのアクションにより、ユーザーをアプリ内の特定の場所や外部コンテンツへ誘導し、ユーザージャーニーの向上と機能の利用促進を図ることができます。

この記事では、アプリ内メッセージでこれらのナビゲーションアクションを設定する方法と、各方法の目的について説明します。

## アプリ内ナビゲーションアクションを設定する

<Tip>
  In-App キャンペーン作成のステップ 2 にいることを確認してください。詳細については、[In-App キャンペーンの作成](/ja/user-guide/campaigns-and-channels/in-app-message/create/create-in-app-campaign)を参照してください。
</Tip>

In-App キャンペーンでナビゲーションアクションを設定するには、次の手順に従います。

1. **Content** セクションでテンプレートを選択した後、ナビゲーションアクションを追加するウィジェットを選択します。
2. **Actions** セクションまでスクロールし、**\+ Actions** をクリックします。
   ![action.png](/images/moengage_919f24.png)
3. ドロップダウンリストから **Navigation** を選択します。
   ![click navigation.png](/images/moengage_6249b5.png)
4. ナビゲーションアクションとして、次の 3 つのラジオボタンのいずれかを選択します。
   - **Navigate to screen**
   - **DeepLink**
   - **Rich Landing**
5. 遷移先の画面を選択するか、遷移先の URL を入力します。
   ![urls.gif](/images/moengage_a4b9c4.png)
6. **Next** をクリックします。

## ナビゲーションオプションについて

<Tabs>
  <Tab title="Navigate to Screen">
    このアクションは、ユーザーが設定されたウィジェットをタップしたときに、アプリ内の特定の画面へユーザーを遷移させます。ユーザーをアプリ内にとどめ、さまざまなセクションや機能の間をシームレスに誘導するよう設計されています。

    - **機能:** 現在のアプリ内の指定された画面を開きます。
    - **使用するタイミング:** オンボーディングフローでのユーザー誘導、新機能への誘導、特定の商品カテゴリーのプロモーション、アプリから離れずにコンテンツを閲覧してもらいたい場合などに使用します。
    - **設定方法:** MoEngage プラットフォームのドロップダウンリストから遷移先の画面を選択します。このオプションを使用するには、アプリの画面が MoEngage で定義されている必要があります。

    ![navigate to screen.gif](/images/moengage_ec2a51.png)
  </Tab>
  <Tab title="Deep Link">
    ディープリンクを使用すると、アプリ内の特定のコンテンツや画面、別のアプリ、または外部 Web サイトへユーザーを誘導できます。"Navigate to Screen" アクションとは異なり、ディープリンクでは外部アプリケーションや Web コンテンツを開くことができ、より幅広いリダイレクトが可能です。

    - **機能:** アプリ内の特定の画面、別のアプリ、または外部 URL を開きます。
    - **使用するタイミング:** アプリをインストールしていないユーザーをアプリストアへリダイレクトする、EC サイトの特定の商品ページへ誘導する、キャンペーンからソーシャルメディアアプリを開く、といった場合に使用します。
    - **設定方法:** 入力ボックスに目的の URL またはディープリンクを入力します。ディープリンクを正しく機能させるには、開発チームによるアプリ内での特定の設定が必要です。

    ![deeplink.gif](/images/moengage_0d98e3.png)

    ### 開発者向けのディープリンク実装に関する考慮事項

    ディープリンクを実装するには、さまざまなプラットフォーム（Android、iOS、Flutter など）で正しく解決されるよう、アプリケーション内で特定の技術的な設定が必要です。デジタルマーケターは開発チームと緊密に連携し、キャンペーン開始前にディープリンクが適切に設定・テストされていることを確認してください。

    ### ネイティブフレームワークでの DeepLink の処理

    ### Android

    1. DeepLink を作成し、マニフェストファイルに追加します。[Android](https://developer.android.com/guide/navigation/design/deep-link) のドキュメントを参照してください。
    2. リンクがマニフェストに追加されていることを確認してください。追加されていない場合、アプリの画面ではなくブラウザが開きます。
    3. 上記の手順を完了した後、キャンペーン作成時に入力ボックスに DeepLink を追加します。

    ### iOS

    1. Info.plist ファイル内のビルド設定に URL スキーム（URL 全体ではなく）を追加します。
    2. 上記の手順を完了した後、キャンペーン作成時に入力ボックスに DeepLink を追加します。

    ## ハイブリッドフレームワーク（Flutter など）での DeepLink の処理

    プッシュ通知とは異なり、ハイブリッドフレームワークでは MoEngage SDK はデフォルトでアプリ内のリダイレクトを処理しません。Rich Landing ページを除き、アプリ内クリックのコールバックメソッドを実装する必要があります。

    1. ルート/アプリウィジェットにアプリ内クリックのコールバックメソッドを実装します。
    2. コールバックを登録した後、moengage\_plugin.initialise() メソッドを呼び出します。
    3. これらのコールバック内で、DeepLink または画面ベースのリダイレクトを処理します。

    詳細なガイダンスについては、コールバックに関する詳細なドキュメントを参照してください。

    これらの手順に従うことで、MoEngage ダッシュボードでさまざまなナビゲーションアクションを効果的に設定・管理し、スムーズで魅力的なユーザー体験を実現できます。

    <Info>
    ネイティブ（Android、iOS）およびハイブリッドフレームワーク（Flutter など）でディープリンクを処理するために必要な詳細な実装手順とコールバックメソッドについては、[In-App NATIV に関する MoEngage 開発者ドキュメント](/ja/developer-guide/react-native-sdk/in-app-messages/inapp-nativ)を参照してください。
    </Info>
  </Tab>
  <Tab title="Rich Landing">
    Rich Landing ページは、アプリの Web ビュー内に Web コンテンツを直接表示します。このアクションにより、ユーザーはアプリ環境にとどまったまま Web ページを閲覧でき、シームレスで統合されたユーザー体験を提供できます。

    - **機能:** 指定された HTTPS URL をアプリ内の Web ビューで開きます。
    - **使用するタイミング:** ユーザーをアプリの外へ誘導せずに、商品詳細ページの表示、アンケートフォームの表示、プロモーションコンテンツの提示、ブログ記事の共有などを行う場合に使用します。
    - **設定方法:** 表示したい Web ページの完全な HTTPS URL を入力します。

    ![richlanding.gif](/images/moengage_d619f6.png)

    <Info>
    Rich Landing ページでは HTTPS URL のみがサポートされています。HTTP URL は読み込まれません。
    </Info>
  </Tab>
</Tabs>

## Rich Landing とディープリンクの比較

次の表は、Rich Landing ページとディープリンクの主な違いを示しています。

| 項目 | Rich Landing | Deep Link |
| --- | --- | --- |
| コンテンツの表示 | アプリの Web ビュー内 | アプリ内または外部（ブラウザ、他のアプリ） |
| ユーザー体験 | ユーザーをアプリ内にとどめる | ユーザーをアプリの外へ誘導できる |
| 主なユースケース | アプリ内で Web コンテンツをシームレスに表示（商品詳細、アンケートなど） | アプリ内の特定の画面、外部 Web サイト、または他のアプリへの誘導（アプリストアへのリダイレクト、特定のコンテンツなど） |
| 技術要件 | HTTPS URL が必要 | 開発者によるアプリ側での URL スキームとインテントフィルターの設定が必要 |
| メリット | ユーザー維持率の向上、Web コンテンツへのシームレスな遷移 | 汎用性が高く、アプリや Web を横断して幅広くリーチできる |
| 例 | アプリ内の商品詳細ページ、アンケートフォーム、プロモーションコンテンツ、ブログ記事 | アプリの特定のセクションへのリダイレクト、外部 Web サイトを開く、アプリストアへの誘導 |

これらのナビゲーションアクションを効果的に使用することで、MoEngage ダッシュボード内で多様なユーザー体験を設定・管理し、スムーズで魅力的なユーザージャーニーを実現できます。
