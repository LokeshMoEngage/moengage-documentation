# 概要

[Portfolio](/ja/user-guide/settings/account/portfolio/portfolio) 機能は、MoEngage 内のすべてのプロジェクトを一元化し、顧客の統合ビューを提供します。これにより、複数のアプリケーションにわたるアプリ内キャンペーンのセグメント化、パーソナライズ、展開、分析の方法が強化されます。

この記事では、Portfolio 機能が次の主要な領域に与える影響について説明します。

- 特定のプロジェクトとプラットフォームのターゲティング
- プロジェクト横断のセグメンテーション
- パーソナライゼーション
- テストキャンペーン
- キャンペーン分析とユーザープロフィール

これらの概念を説明するために、*Project Alpha* と *Project Beta* という 2 つの異なるブランドを持つ企業のキャンペーンを例に取り上げます。目標は、プライマリアプリ（*Project Alpha*）のロイヤルカスタマーに対して、プレミアムブランド（*Project Beta*）をクロスプロモーションすることです。

<Tip>
- アプリ内キャンペーンを作成する前に、必要なチャネル設定がすべて完了していることを確認してください。
- Portfolio 機能を活用するには、アカウントに少なくとも 1 つのプロジェクトを追加する必要があります。詳細については、[こちら](/ja/user-guide/settings/account/portfolio/portfolio)を参照してください。
- ポートフォリオに複数のプロジェクトが含まれている場合、キャンペーン作成ページに **Project** ドロップダウンリストが表示され、プロジェクトごとに固有の設定を選択して構成できます。
</Tip>

# 特定のプロジェクトとプラットフォームのターゲティング

Portfolio 機能を使用すると、各プロジェクト固有のコンテキストに合わせてメッセージやオファーを調整できます。この例での目標は、*Project Alpha* の価値の高い顧客に *Project Beta* のオファーを試してもらうことです。

1. キャンペーン作成の Target Users ステップで、**Target platforms** セクションを見つけます。
2. **Select** **Project** リストで、ターゲットプロジェクト（例: Project Alpha）を選択します。
3. iOS や Android などの Platforms チェックボックスを選択し、そのブランドのすべての対象デバイスに招待を送信します。 <img alt="inapp portfolio target.png" src="/images/moengage_c4d6b8.png" />

キャンペーン作成手順の詳細については、[アプリ内キャンペーンの作成](/ja/user-guide/campaigns-and-channels/in-app-message/create/create-in-app-campaign)ガイドを参照してください。

# プロジェクト横断のセグメンテーション

プロジェクト全体にわたるユーザーのジャーニー全体に基づいて、ユーザーをセグメント化できます。これは、効果的なクロスプロモーションやライフサイクルマーケティングに不可欠です。

**例**: *Project Alpha* の価値の高い顧客のうち、まだ *Project Beta* とエンゲージしていない顧客を見つけます。

**Target audience** セクションで、*Project Alpha* で購入を行い、まだ *Project Beta* のアプリを開いていないユーザーをターゲットにします。以下の手順に従って、このロジックを設定できます。

1. **Target audience** セクションで **Filter users by** を選択し、**User behavior** タブを選択します。
2. 最初のルールでは、ドロップダウンリストから Project A を選択し、条件「Has Executed Made Purchase」を設定します。 <img alt="inapp audience portfolio 1.png" src="/images/moengage_79d312.png" />
3. **+ Filter** をクリックして 2 つ目のルールを追加します。Project B を選択し、条件「Has NOT Executed App Opened」を設定します。 <img alt="inapp audience portfolio 2.png" src="/images/moengage_916d35.png" />

<Info>
- プッシュ通知とは異なり、アプリ内キャンペーンおよび OSM キャンペーンではプロジェクト横断のトリガーはサポートされていません。たとえば、*Project Beta* で発生した「Add to Cart」イベントに基づいて、*Project Alpha* でアプリ内メッセージをトリガーすることはできません。
- これらのチャネルでは、キャンペーンの送信用に選択したプロジェクトがトリガー条件に自動的に適用され、プロジェクト横断のトリガー選択は利用できません。
</Info>

# パーソナライゼーション

パーソナライゼーションでは、ターゲットとするプロジェクトに合わせてメッセージを調整し、関連性を確保します。特定のプロジェクト向けにキャンペーンを作成すると、MoEngage はユーザー属性リストを自動的にフィルタリングし、ターゲットプロジェクトの属性とグローバル属性のみを表示します。

例: *Project Alpha* の顧客に *Project Beta* をプロモーションするキャンペーンでは、パーソナライゼーションに *Project Alpha* のデータが使用されます。ユーザーが *Project Beta* で異なるプロフィール情報（異なる「First Name」や「Loyalty Status」など）を持っている場合でも、キャンペーンはユーザーが現在体験しているブランドのコンテキストを維持するために、*Project Alpha* の情報を正しく使用します。

1. キャンペーンの Content ステップで @ を入力すると、パーソナライゼーション属性のリストが開きます。
2. 利用可能な *Project Alpha* の属性またはグローバル属性から、属性（例: **First Name**）を選択します。

# テストキャンペーン

アプリ内のテストキャンペーンはコンテキスト固有であり、選択したプロジェクトの環境内でのみ実行されます。

- テストを開始すると、アプリ内メッセージは、キャンペーン設定で構成したプロジェクトに関連付けられたアプリとプラットフォーム（iOS/Android）でのみトリガーされます。
- この分離により、Project Alpha のテストが誤って Project Beta のアプリに表示されることはなく、ポートフォリオ全体でユーザー体験の整合性が保たれます。

# FAQ

<Accordion title="Basic App で初回購入を行ったばかりのユーザーに、Premium App で「Welcome」アプリ内メッセージを表示したいです。どうすればよいですか？">

MoEngage は現在、リアルタイムのプロジェクト横断トリガーをサポートしていません。つまり、App A のイベントによって App B でメッセージを即座に表示させることはできません。

回避策として、プロジェクト横断のセグメンテーションの使用をお勧めします。Target Audience セクションで、過去 1 時間以内に Project Basic で「First Purchase」を実行したユーザーを絞り込むセグメントを作成できます。これにより、ユーザーが次に Project Premium のアプリを起動したときに、そのキャンペーンが表示されます。

</Accordion>
<Accordion title="両方のアプリに同じユーザーがいる場合、そのユーザーの「In-app Impressions」は分析でまとめてカウントされますか？">

いいえ。Portfolio 機能は顧客の統合ビューを提供しますが、Campaign Analytics はプロジェクト固有です。クロスプロモーションを実施した場合、インプレッションとクリックはキャンペーンが展開されたプロジェクト内で追跡されます。これにより、どの「Host App」が「Target App」のコンバージョンを最も促進しているかを正確に測定できます。

</Accordion>
<Accordion title="プレミアムアプリの「Subscription Tier」属性を使ってベーシックアプリのメッセージをパーソナライズしようとしていますが、属性が見つかりません。なぜですか？">

データをクリーンかつブランド固有に保つため、パーソナライゼーションメニュー（@）には、選択したターゲットプロジェクトに属する属性のみが表示されます。Project Alpha のキャンペーンを作成する際に Project Beta のデータを使用する必要がある場合は、その属性を MoEngage の設定でグローバル属性として構成する必要があります。

</Accordion>
<Accordion title="ステージングアプリでテスト用のアプリ内メッセージを送信した場合、誤って本番アプリに表示される可能性はありますか？">

いいえ。アプリ内のテストキャンペーンは厳密にコンテキスト固有です。テストを開始すると、メッセージはキャンペーン設定で構成したプロジェクトに関連付けられたアプリとプラットフォーム（iOS/Android）内でのみトリガーされます。*Project Alpha* のテストが *Project Beta* のユーザー体験に干渉することはありません。

</Accordion>
