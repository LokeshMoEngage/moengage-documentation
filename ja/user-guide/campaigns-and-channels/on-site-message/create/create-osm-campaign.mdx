# OSM キャンペーンを作成する手順

OSM キャンペーンの作成は、次の 3 つのステップで構成されます。

1. [ターゲットユーザー](/ja/user-guide/campaigns-and-channels/on-site-message/create/create-osm-campaign#step-1-target-users): キャンペーンのターゲットオーディエンスを定義します
2. [コンテンツ](/ja/user-guide/campaigns-and-channels/on-site-message/create/create-osm-campaign#step-2-define-content): 送信するプッシュ通知のコンテンツを定義します
3. [スケジュールと目標](/ja/user-guide/campaigns-and-channels/on-site-message/create/create-osm-campaign#step-3-scheduling-and-goals): キャンペーンの配信スケジュールと目標を定義します

## ステップ 1: ターゲットユーザー

このセクションには以下が含まれます。

### **キャンペーンの詳細**

キャンペーンの詳細セクションには、次のフィールドがあります。

|  |  |
| --- | --- |
| <ul><li>**Campaign name** - キャンペーンを管理・識別するためのキャンペーン名を入力します。キャンペーン名は 5 文字以上である必要があり、上限は 256 文字です。</li><li>**Campaign tags** - ドロップダウンリストからキャンペーンタグを選択します。最大 5 つのタグを選択できます。詳細については、[キャンペーンタグ](/ja/user-guide/campaigns-and-channels/getting-started/introduction/campaign-tags)を参照してください。</li></ul> | <img alt="Campaign_Details_OSM.png" src="/images/moengage_1ac0a8.png" /> |

### **ターゲットプラットフォーム**

このセクションでは、キャンペーンのターゲットプラットフォームを選択できます。次のオプションを利用できます。

|  |  |
| --- | --- |
| <ul><li>**Web** - キャンペーンで Web プラットフォームをターゲットにする場合は Web を選択します。</li><li>**Mobile Web** - キャンペーンで Mobile Web プラットフォームをターゲットにする場合は Mobile Web を選択します。</li></ul> | <img alt="OSM_TargetPlatforms.png" src="/images/moengage_088cfb.png" /> |

### **トリガー条件**

#### **On Page Load**

ユーザーに対して Web サイトのページが読み込まれた時点でメッセージを表示したい場合は、このオプションを選択します。次のオプションを利用できます。

- **Immediately** - ユーザーに対してページが読み込まれるとすぐに OSM を表示します。
- **After Delay** - 指定した遅延時間の後に OSM を表示します。たとえば、遅延を 2 秒に指定した場合、ページの読み込みから 2 秒後に OSM が表示されます。
- **After Scroll** - ユーザーが Web サイトを約 x% スクロールした時点で OSM を表示します。スクロール率を 30 に指定した場合、ユーザーが Web サイトの 30% をスクロールした後に OSM が表示されます。

ユーザーがカスタムイベントを実行したときに On-site メッセージを表示できます。Trigger the message オプションを使用して、メッセージを即時または遅延後に送信できます。

#### IF user

**IF user** セクションでは、イベントを選択できます。IF 条件で単一のイベントを選択した場合、ユーザーがそのイベントを実行するとメッセージが送信されます。ただし、IF 条件に複数のイベントや属性を追加することもできます。

**IF user** セクションで、次の操作を行います。

1. **Select an Event** ドロップダウンからイベントを選択します。
2. イベントを絞り込むこともできます。その場合は次のようにします。
   - Attribute ボタンをクリックしてフィルターに属性を追加し、その属性の論理ドロップダウンを選択します。
   - さらに属性を追加するには、次の操作を行います。
     - **\+ Attribute** ボタンをクリックします
     - _AND_ または _OR_ をクリックします
     - Attribute ドロップダウンから該当する属性を選択し、選択した属性の論理ドロップダウンを選択します。

たとえば、_User installs the app_ イベントを選択した場合、_App Version_ という属性を追加して、特定のバージョンのアプリをインストールしたユーザーを絞り込むことができます。

<img
  src="/images/moengage_d42dd1.png"
  style={{ width:"88%" }}
/>

#### AND then

**And/ Then** 機能により、さらに細かくカスタマイズできるようになりました。**\+ Trigger** オプションに加えて、**\+** **Filter** ボタンを使用すると、複数のイベントをつなげることができます。

たとえば、_On-site Message Clicked_ イベントを選択し、\*\*AND then \*\*オプションを使用して _Added to Cart_ イベントを追加できます。

これにより、On-site メッセージキャンペーンを少なくとも 1 回クリックし、その後カートに商品を少なくとも 1 回追加したユーザーに On-site メッセージが表示されます。

<img
  src="/images/moengage_07485b.png"
  alt="multiple trigger attributes.png"
  style={{ width:"56%" }}
/>

\*\*Filter \*\*条件のイベントが評価されるまでの待機時間も定義できます。この制限を 15 分に設定すると、ユーザーは最初のトリガーイベントを実行してから 15 分以内に **Filter** イベントを実行する必要があります。この例では、最初のイベントは _On-site Message Clicked_ です。

- ここで設定できる最大遅延は 24 時間、最小遅延は 1 分です。

<img
  src="/images/moengage_3006b1.png"
  style={{ width:"66%" }}
/>

\+ Filter ボタンを再度クリックすると、トリガー条件に別のイベントを追加できます。_AND_ または _OR_ を選択できます。_AND_ を選択すると 2 つのフィルター条件を組み合わせることができ、_OR_ を使用すると制限時間内にいずれかのイベントを実行したユーザーを絞り込むことができます。

<img
  src="/images/moengage_26cb81.png"
  style={{ width:"59%" }}
/>

#### THEN

THEN セクションの Trigger the message で、メッセージを表示するタイミングを定義するオプションを選択します。利用可能なオプションは次のとおりです。

- **Immediately**: トリガー条件が特定された直後にメッセージが表示されます。
- **After Delay**: 定義した遅延時間の後にメッセージが表示されます。たとえば、遅延を 2 秒に指定した場合、ページの読み込みから 2 秒後に OSM が表示されます。 <img alt="and then.png" src="/images/moengage_a3d571.png" />

<Info>
  After Delay を選択した場合、最大 1 日 (86400 秒)、最小 1 秒の遅延を設定できます。
</Info>

**Trigger Criteria Summary**: Trigger Criteria Summary では、選択したイベントと属性に基づいてトリガーが要約され、トリガー条件を理解しやすくなります。

![](/images/moengage_7e079c.png)

#### **On Exit Intent**

ユーザーが Web サイトから離脱しようとしたときにメッセージをトリガーしたい場合は、このオプションを選択します。詳細については、[Exit Intent テクノロジー](/ja/user-guide/campaigns-and-channels/on-site-message/create/exit-intent-technology)を参照してください。

![OnExitIntent.png](/images/moengage_1f279b.png)

### **ページの選択**

このセクションでは、ユーザーにキャンペーンを表示する Web ページを選択できます。次のいずれかを選択できます。

- **All pages**: Web サイトのすべてのページにキャンペーンを表示します。
- **Specific pages**: Web サイトの特定のページにキャンペーンを表示します。URL ルールを定義して、キャンペーンを表示または非表示にするページを選択できます <img src="/images/moengage_80aa24.png" alt="Screenshot 2024-11-07 at 12.54.46 PM.png" />

URL パスを使用して特定のページでキャンペーンを表示または非表示にするには、次の手順に従います。

1. **Specific pages** をクリックします。 <img src="/images/moengage_d30ea8.png" alt="WhatsApp Image 2024-11-12 at 3.53.09 PM.jpeg" />
2. **If URL** で、次に示すように **Select Option** リストから任意の条件を選択します。 <img src="/images/moengage_c7f565.png" alt="WhatsApp Image 2024-11-09 at 3.55.02 PM.jpeg" /> 利用可能な条件は次の表のとおりです。
   | 条件 | 説明 |
   | --- | --- |
   | is | 条件で指定した特定の URL のいずれかでポップアップが表示されます。ポップアップを表示するには、URL が完全に一致する必要があります。 |
   | is not | 条件で指定した URL 以外の任意の URL でポップアップが表示されます。ポップアップを表示するには、URL が完全に一致していない必要があります。 |
   | contains | 条件で指定したテキストまたは文字列のいずれかを**含む**任意の URL でポップアップが表示されます。URL が完全に一致する必要はありませんが、指定したテキストの少なくとも 1 つを含む必要があります。 |
   | contains (all of) | 条件で指定したテキストまたは文字列を**すべて含む**任意の URL でポップアップが表示されます。URL が完全に一致する必要はありませんが、指定したテキストをすべて含む必要があります。 |
   | does not contain | 条件で指定したテキストまたは文字列のいずれも**含まない**任意の URL でポップアップが表示されます。ポップアップを表示するには、URL が指定したテキストをすべて除外している必要があります。 |
   | does not contain (all of) | 条件で指定したテキストまたは文字列を**すべては含まない**任意の URL でポップアップが表示されます。ポップアップを表示するには、URL が指定したテキストの少なくとも 1 つを除外している必要があります。 |
   | starts with | 条件で指定した特定のテキストまたは文字列で**始まる**任意の URL でポップアップが表示されます。ポップアップを表示するには、URL が指定したテキストで始まる必要があります。 |
   | ends with | 条件で指定した特定のテキストまたは文字列で**終わる**任意の URL でポップアップが表示されます。ポップアップを表示するには、URL が指定したテキストで終わる必要があります。 |
   | does not starts with | 条件で指定した特定のテキストまたは文字列で**始まらない**任意の URL でポップアップが表示されます。ポップアップを表示するには、URL が指定したテキストで始まっていない必要があります。 |
   | does not end with | 条件で指定した特定のテキストまたは文字列で**終わらない**任意の URL でポップアップが表示されます。ポップアップを表示するには、URL が指定したテキストで終わっていない必要があります。 |
3. 次に示すように、**Select Option** リストの隣のボックスに 1 つ以上の URL を入力します。 <img src="/images/moengage_bbda3c.png" alt="Screenshot 2024-11-14 at 1.36.28 PM.png" />
   <Info>
     **情報**
     - Enter キーを押すと、複数の URL やキーワードを手動で追加できます。
     - CSV から URL のリストをコピーして入力ボックスに貼り付けることもできます。
   </Info>
4. **\+ Filter** をクリックします。
5. **And** または **Or** 演算子を選択し、**Select Option** リストで条件を選択します。
6. **Select Option** リストの隣のボックスにキーワードを入力します。 <img src="/images/moengage_e6b1d1.png" alt="Screenshot 2024-11-14 at 1.33.11 PM.png" />
7. 複数のルールを追加するには、手順 4 ～ 6 を繰り返します。 <img src="/images/moengage_b7c108.png" alt="Screenshot 2024-11-14 at 1.39.42 PM.png" />
8. 特定のルールを削除するには、削除アイコン ( <img alt="delete icon.png" src="/images/moengage_f7d066.png" style={{ display: 'inline-block'}} /> ) をクリックします。
9. **Check page targeting** ボックスに URL を入力して、指定した URL が定義した条件を満たしているかを確認します。
10. **Check** をクリックします。 <img src="/images/moengage_f292ff.png" alt="Screenshot 2024-11-14 at 1.40.33 PM.png" />
    - 指定した URL が定義した条件を満たしている場合、次のように **Passed** 通知が表示されます <img src="/images/moengage_4f9385.png" alt="Screenshot 2024-11-14 at 1.32.30 PM.png" />
    - 指定した URL が定義した条件を満たしていない場合、次のように **Failed** 通知が表示されます。通知に記載されたエラーの指示に従ってください。 <img src="/images/moengage_931c2e.png" alt="Screenshot 2024-11-14 at 1.42.27 PM.png" />

#### In-Session 属性

In-session 属性を使用すると、Web サイトでの現在のセッション内のアクションに基づいてユーザーをグループ化し、ターゲットにできます。

たとえば、ユーザーがインドにいる場合、インド在住のユーザー向けに作成したパーソナライズされたポップアップを表示できます。これにより、同じセッション内ですぐにパーソナライズされた体験を提供できます。

In-session 属性を追加するには、**\+ In-session attributes** ボタンをクリックします。

![](/images/moengage_880186.png)

複数の In-session 属性を組み合わせることができます。また、セッション内のアクティビティに基づいてユーザーを除外することもできます。

![](/images/moengage_ecbac7.png)

In-app キャンペーンでは、次の In-session 属性を使用できます。

1. **Query Parameter**: URL 内のクエリパラメーターに基づいてユーザーをセグメント化できます。通常、ユーザーはソーシャルメディアプラットフォーム上の広告をクリックして、パーソナライズされた URL にアクセスします。
   - Source、Medium、Content、Campaign などの UTM パラメーターを使用して、ユーザーの訪問元や、この URL に到達したキャンペーンなどに基づいてユーザーをセグメント化できます。
   - utm\_source、utm\_campaign などの UTM パラメーターは、Web サイトにユーザーを誘導しているキャンペーンを特定するために使用されます。UTM パラメーターやカスタムパラメーターを使用して、ユーザーをセグメント化し、Web サイトの体験をパーソナライズできます。
2. **User Type**: 新規ユーザーかリピーターかに基づいてユーザーをセグメント化できます。Web SDK は、各ユーザーのユーザー詳細 (_unique\_id_) をブラウザストレージに保存します。これらの詳細がストレージに存在する場合、そのユーザーはリピーターです。存在しない場合、そのユーザーは新規ユーザーです。
   - したがって、ブラウザのキャッシュがクリアされると、そのユーザーは新規として扱われます。
   - **注**:
     - 2 人のユーザーが同じデバイスを使用し、ユーザー 1 の後にユーザー 2 がログインした場合、ユーザー 2 は _リピーター_ (_returning_ _user_) と見なされます
     - ユーザーがモバイルブラウザからログインし、その後デスクトップブラウザから再度ログインした場合、デスクトップからのログインは _新規ユーザー_ と見なされます。
3. **Day of the Week**: ユーザーが Web サイトを訪問した曜日に基づいてユーザーをセグメント化できます。
4. **Time of the Day**: ユーザーが Web サイトを訪問した時間帯に基づいてユーザーをセグメント化できます。ドロップダウンで、1 日のうちの任意の 1 時間枠を選択できます。
5. **Geolocation**: ユーザーが Web サイトを訪問した地理的位置に基づいてユーザーをセグメント化できます。ユーザーが所在する国、州/地域、都市を選択したり、特定の国を除外したりできます。
6. **Device Type**: ユーザーが Web サイトを訪問したデバイスに基づいてユーザーをセグメント化できます。Mobile、Desktop、Tablet のいずれか 1 つまたは組み合わせを含めたり除外したりできます。
7. **Operating System**: ユーザーが Web サイトを訪問したデバイスのオペレーティングシステムに基づいてユーザーをセグメント化できます。Android、iOS、Windows、Mac、Linux、その他のいずれか 1 つまたは組み合わせを含めたり除外したりできます。
8. **Browser Type**: ユーザーが Web サイトを訪問したブラウザに基づいてユーザーをセグメント化できます。Chrome、Safari、Firefox、Opera、その他のいずれか 1 つまたは組み合わせを含めたり除外したりできます。

### キャンペーンオーディエンス上限

### コンバージョン目標

コンバージョン目標を追加して、キャンペーンのビジネス指標を追跡できます。最大 5 つのコンバージョン目標を追跡できます。任意のアプリイベントをコンバージョン目標のアクティビティとして選択でき、複数のコンバージョン目標を設定できます。最初の目標はプライマリ目標として扱われます。

たとえば、キャンペーンの送信後に iPhone を購入した顧客の数を追跡したいとします (イベント - 購入イベント、商品 - iPhone)。コンバージョン目標の設定は、次の詳細を含む下の画像のようになります。

- **Goal Name** - _iPhonePurchase_
- **App Event you wish to track** - _Made Purchase_
- **Event Attribute/Property** - _product_ is _event attribute/property_
- **Value of Event Attribute/Property** - _iPhone_

![ConVErsionGoals.png](/images/moengage_04fdea.png)

複数のコンバージョン目標を使用すると、複数のビジネス指標を追跡したり、ユーザーアクションのファネルを可視化したりできます。たとえば、次の内容を確認したい場合は、複数のコンバージョン目標を使用して確認できます。

- 商品ページを閲覧したユーザーは何人か
- そのうち、その商品をカートに追加したユーザーは何人か
- そのうち、注文を完了したユーザーは何人か

  | **Set Attribution window** - アトリビューションウィンドウ (コンバージョン目標を特定のキャンペーンに帰属させるための、ユーザーがキャンペーンを受信した時点から計算される期間またはウィンドウ) を設定できます。デフォルトでは 36 時間に設定されています。上記の例では、これを 5 時間に設定したとします。 | <img alt="AttributionWindow.png" src="/images/moengage_a94a46.png" /> |
</Accordion>

### **キャンペーンの優先度と配信コントロール**

このセクションには、次のオプションが含まれています。

- **Campaign Priority** - 次のキャンペーン優先度のいずれかを設定します: Critical、High、Medium、Normal、Low。ユーザーが同時に 2 つのキャンペーンを表示できる場合、優先度の高いキャンペーンが表示されます。両方のキャンペーンの優先度が同じ場合は、最近作成されたキャンペーンが先に表示されます。
- **Global Delivery Control** - このセクションでは、On-site messaging チャネルに設定された _Ignore global minimum delay_ を適用するかどうかを指定できます。このトグルを有効にすると、On-site メッセージに設定された最小遅延の設定が無視されます。
  <Frame>
    ![FC Osm](/images/FC-osm.png)
  </Frame>
- **Local Delivery Controls** - このセクションには、このキャンペーンに関する配信コントロールを指定するためのオプションが含まれています。ここでは次のオプションを利用できます。
  - **Maximum times to show a message** - 同じキャンペーンの On-site メッセージを 1 人のユーザーに表示する最大回数を指定できます。これは、User Profile の **On-site Message Shown** イベントを使用して追跡されます。たとえば、キャンペーンの公開時には Maximum times to show a message がオフになっていて、後から 1 回に編集されたとします。キャンペーンの編集前にすでにメッセージが表示されていたユーザーが再度サイトを訪問した場合、そのユーザーの User Profile にはすでに **On-site Message Shown** が存在するため、メッセージは再度表示されません。
  - **Minimum delay between 2 messages on this campaign** - 同じキャンペーンからの 2 つの On-site メッセージ間の最小時間間隔を指定できます。
  - **Auto dismiss message after 'x' seconds** - On-site メッセージが URL から削除されるまでの時間を指定できます。 <img src="/images/moengage_f91d85.png" alt="Priority_and_Delivery_Controls.png" />

これでキャンペーンを送信する準備ができました。Publish をクリックし、表示されるダイアログボックスで確認してキャンペーンを作成します。

キャンペーンが正常に作成されると、Campaign Info ページが表示されます。

# よくある質問

## OSM エディターでカスタムフォントを使用するにはどうすればよいですか？

OSM エディターでカスタムフォントファイルを直接アップロードすることはできません。エディターの **Add New Font** オプションでは、Google Fonts または _Fonts_ タブで利用可能なフォントからのみ選択できます。独自のフォントを使用するには、次のいずれかの方法を使用します。

- **Context Hub でフォントを追加する。** Context Hub の **Brand → Visual system → Fonts** でフォントを追加します。そこで追加したフォントは、その後に公開される OSM キャンペーンで利用可能になります。以前に公開されたキャンペーンでは、作成時のフォントがそのまま使用されます。詳細については、[Context Hub](/ja/user-guide/settings/account/context-hub/context-hub) を参照してください。
- **エディターで CSS を使用してフォントを参照する。** 以下の手順で説明するように、フォントファイルを自分でホストし、埋め込み要素を使用して適用します。

CSS を使用してカスタムフォントを参照するには、次の手順に従います。

#### **1. フォントファイルをホストする**

カスタムフォントファイルが、安全なドメインまたは公開アクセス可能な URL でホストされていることを確認します。例: `https://yourdomain.com/fonts/yourfont.ttf`

デモ用として、次の Roboto フォントのリンクを使用できます: `https://fonts.gstatic.com/s/roboto/v30/KFOmCnqEu92Fr1Mu5mxKKTU1Kvnz.woff2`

URL をクリックするとダウンロードが開始され、フォントファイルが正しくホストされていることを確認できます。

#### **2. テンプレートを準備する**

OSM Pro でカスタマイズするテンプレートを選択します。

![select template.png](/images/moengage_20f40e.png)

#### **3. テキスト設定を変更する**

カスタムフォントを適用するテキスト要素をクリックします。

- 設定アイコンをクリックし、スタイルアイコンを選択します。 <img src="/images/moengage_dbaa71.png" alt="click on settings.png" />
- 「Advanced」タブに切り替えます。 <img src="/images/moengage_bdb919.png" alt="switch to advanced tab.png" />
- 「CSS Id」フィールドに、`text_id1` などの一意の識別子を入力します。 <img src="/images/moengage_e68c2f.png" alt="add identifier.png" />

識別子を追加したら、設定メニューを閉じます。

#### **4. 埋め込み要素を追加する**

テンプレートに埋め込み要素を挿入します。この埋め込み要素はユーザーには表示されず、テンプレート内のフォントスタイルを変更するためだけに使用します。

![embed element.png](/images/moengage_319050.png)

#### **5. カスタムフォントのコードを挿入する**

先ほど追加した埋め込み要素をクリックし、次の CSS を入力します。

HTML

```html wrap
<style type="text/css">
 @font-face {
  font-family: 'customfont';
  src: url('https://yourdomain.com/fonts/yourfont.ttf'); /* Your font URL */
 }
 #text_id1 p {
  font-family: 'customfont' !important;
 }
</style>
```

このコードはカスタムフォントをインポートし、ID が `text_id1.` の要素内の段落に適用します。

#### **6. その他の要素をカスタマイズする**

ボタンなど、他の要素のフォントを変更するには、次のようにします。

- 上記のテキスト要素と同様に、ボタンに一意の ID (たとえば `button_id1`) を割り当てます。
  <Frame>
    ![Change Button Identifier](/images/change-button-identifier.png)
  </Frame>
- ボタンの ID を含めるように CSS コードを変更します。

<CodeGroup>

```html HTML wrap
<style type="text/css">
@font-face {
font-family: 'customfont';
src: url('https://yourdomain.com/fonts/yourfont.ttf');
}
#text_id1 p, #button_id1 span {
font-family: 'customfont' !important;
}
</style>
```

</CodeGroup>

この CSS コードは、指定した URL から読み込まれる「customfont」という名前のカスタムフォントを定義し、`#text_id1` と `#button_id1` で識別される要素内のテキストに適用します。これにより、他のスタイルにかかわらずカスタムフォントが使用されます。

<Frame>
  ![Button Code](/images/button-code.png)
</Frame>

#### **7. プレビューして公開する**

CSS を追加した後、テンプレートをプレビューしてフォントが正しく表示されることを確認します。確認できたら、キャンペーンを公開できます。

![Updated template.png](/images/moengage_1f3a3b.png)
