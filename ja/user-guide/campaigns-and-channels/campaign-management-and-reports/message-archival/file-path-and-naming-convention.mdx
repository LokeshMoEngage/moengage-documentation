MoEngage では、メッセージデータをアーカイブするための主なオプションとして、S3 バケットへのエクスポートと SFTP サーバーへのエクスポートの 2 つを提供しています。各オプションには、それぞれ独自のディレクトリ構造とファイルの命名規則があります。以下の該当するタブを選択して、設定したアーカイブ方式の詳細を確認してください。

    ただし、MoEngage の S3 バケットでもお客様の S3 バケットでも、要件に応じてファイルの命名規則をカスタマイズできます。

    - ファイルパスまたはファイル名には、次のいずれかの属性を追加できます。
      | 属性 | 説明 |
      | --- | --- |
      | `{{cid}}` | MoEngage キャンペーン ID |
      | `{{channel}}` | チャネルタイプ |
      | `{{db_name}}` | ワークスペース名 |
      | `{{date}}` | アーカイブの日付 |
      | `{{id}}` | ID |
      | `{{moe_transaction_id}}` | MoEngage トランザクション ID |
      | `{{time}}` | アーカイブの時刻 |
      | `{{moe_event_id}}` | MoEngage イベント ID |
      | `{{alert_ID}}` | アラート ID は Inform 用です。Inform の場合、キャンペーン ID はありません。 |
    - ファイル名内の属性の順序は変更できます。たとえば、ワンタイム Email キャンペーンのファイルの命名規則を考えてみます。デフォルト: `MoeCampaignID_ID_epochtime_email.eml ` カスタマイズ後: `ID_MoeCampaignID_epochtime_email.eml` (ここでは、ID が MoeCampaignID の前に来ます)
  </Tab>
  <Tab title="SFTP サーバーへのアーカイブ">
    設定が完了すると、MoEngage はメッセージイベントデータをお客様のサーバーにエクスポートします。アーカイブプロセスでは、すべてのチャネル (Push、Email、SMS など) のメッセージが同じエクスポートファイルにまとめられます。

    #### サーバーのディレクトリパス

    MoEngage は、アーカイブファイルを SFTP サーバー上の特定のディレクトリパスにアップロードします。セットアップ時に、これらのアップロードのベースパスを設定できます。指定するパスは、スラッシュ (/) で終わる必要があります。ベースパスを指定しない場合、MoEngage はデフォルトの `/home/{username}/uploads/` を使用します。

    MoEngage は、ワークスペース名 (db\_name) と日付を自動的に追加して、最終的なディレクトリ構造 `your_configured_base_path/{db_name}/{YYYY-MM-DD}/` を作成します。

    カスタムパスを指定しない場合、MoEngage は次のデフォルト構造を使用します。

    `/home/{username}/uploads/{db_name}/{YYYY-MM-DD}/`

    - **/home/**{username}**/uploads/:** デフォルトのベースパス。
    - **username:** SFTP 接続のセットアップ時に指定したユーザー名。
    - **db\_name:** MoEngage ワークスペースの名前。
    - **YYYY-MM-DD:** エクスポートの日付。

    たとえば、デフォルトのパスを使用し、ユーザー名が `citi-test`、ワークスペース (db\_name) が `checkfcsgain` の場合、2025 年 7 月 15 日のファイルは `/home/citi-test/uploads/checkfcsgain/2025-07-15/` に配置されます。

    #### アーカイブファイルの名前と構造

    SFTP サーバーにアップロードされるファイルは、.zip アーカイブに圧縮されます。これらのアーカイブには一貫したパターンで名前が付けられ、データ量が多い場合は複数のパートに分割されることがあります。

    **ZIP ファイルの命名規則:** `[workspace_name]_[date]_[hour]_[chunk_number].zip`

    | コンポーネント | 説明 |
    | --- | --- |
    | `workspace_name` | MoEngage ワークスペースの名前 (例: `checkfcsgain`)。 |
    | `date` | YYYY-MM-DD 形式のエクスポートの日付。 |
    | `hour` | エクスポートが生成された時間帯 (00～23)。 |
    | `chunk_number` | 1 から始まる連番。1 時間あたりのデータの合計が 200 MB 未満の場合、チャンク番号は 1 になります。 |

    <Info>
      ファイルはチャンクに分割され、1 チャンクあたりの最大サイズは 200 MB です。特定の 1 時間のデータがこの上限を超える場合、複数の ZIP ファイルに分割されます。たとえば、2025 年 7 月 14 日の午前 6 時台のデータが 350 MB の場合、次の 2 つのファイルを受信します。

      - `checkfcsgain_2025-07-14_06_1.zip`
      - `checkfcsgain_2025-07-14_06_2.zip`

      個々のメッセージレコード (完全な JSON オブジェクト) が、2 つの異なるファイルにまたがって分割されることはありません。
    </Info>

    **アーカイブの中身: データファイル**

    各 .zip アーカイブには、複数の JSON ファイルが含まれています。個々の JSON ファイルは、次の命名規則とコンテンツ規則に従います。

    - **データファイル名:** MoEngage は、これらのファイルに内部システムでの命名を反映したシステム生成の名前を使用します。例: `sftp.bulk.upload+0+0000049701.json`。
    - **ファイルの内容と形式:** これらの各 JSON ファイルには、1 つ以上の完全な JSON オブジェクトが連続して含まれる場合があります。1 つのファイル内の個々の JSON オブジェクトの間に区切り文字はありません。ファイルを開くと、完全な JSON オブジェクトが次々と並んでいるのが確認できます。

    各 JSON オブジェクトは 1 つのアーカイブされたメッセージを表し、`"message_content"` キーで始まります。

    **アップロードのスケジュール**

    エクスポートを管理するために、MoEngage の関数が 1 時間ごとに実行されます。この関数は、最新のメッセージデータを収集して zip アーカイブに圧縮し、SFTP サーバーにアップロードします。
  </Tab>
