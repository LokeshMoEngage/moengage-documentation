**ナビゲーション**:

1. MoEngage のサイドバーメニューで、**Engage** アイコン <img alt="Screenshot 2025-06-04 at 4.32.53 PM.png" src="/images/moengage_79c979.png" style={{ display: 'inline-block'}} /> にカーソルを合わせます。**Engage** メニューが表示されます。
2. **All Campaigns** をクリックします。

3. _Select Channel_ ドロップダウンで _Connector_ を選択します。
4. 分析情報を確認したいコネクターキャンペーンをクリックします。

表示される画面では、次のセクションを利用できます。

1. **Campaign Details** - キャンペーンとそのステータスに関する情報が含まれます。詳細については、[キャンペーンの詳細](#campaign-details)を参照してください。
2. **Analytics** - キャンペーンで追跡されるさまざまな指標に関する情報が含まれ、次のセクションで構成されます。
   - - [キャンペーンパフォーマンス統計](#campaign-performance-stats)

3. **Info** - キャンペーンのターゲットセグメント、コンテンツ、プレビュー、配信スケジュールに関する情報が含まれます。詳細については、[キャンペーン情報](#campaign-info)を参照してください。

# キャンペーンの詳細

このセクションには、次の情報が含まれます。

- キャンペーンの種類
- キャンペーン ID
- キャンペーンの作成および更新の詳細
- チーム情報
- 承認者リスト/承認者/却下者(Campaign Approval Flow - CAF が有効な場合)
- キャンペーンのステータス - キャンペーンには次の状態があります: _Active_、_Expired_、_Not Sent_、_Paused_、_Scheduled_、_Sending_、_Sent_、_Stopped_。CAF が有効な場合は、キャンペーンのステータスとしてさらに Under\_Review\_ と _Rejected_ の 2 つの状態が追加されます。

**Campaign Details セクションで実行できるアクション**

| **アクション** | **説明** |
| --- | --- |
| Refresh | その時点でのキャンペーンの詳細でページを再読み込みします。 |
| Edit | キャンペーンを編集できます。 |
| Duplicate | キャンペーンを複製し、現在のキャンペーンのすべての詳細が入力された状態でキャンペーンエディターページを開きます。複製されたキャンペーンの名前には 'Duplicate -' が付加されます。 |
| Approve | CAF が有効な場合に、レビュー中のキャンペーンを承認できます。このアクションは、キャンペーンのレビュアーリストに追加されているユーザーのみが利用できます。詳細については、[キャンペーン承認ワークフロー](/ja/user-guide/settings/account/team-management/campaign-approval-workflow)を参照してください。 |
| Reject | CAF が有効な場合に、レビュー中のキャンペーンを却下できます。このアクションは、キャンペーンのレビュアーリストに追加されているユーザーのみが利用できます。詳細については、[キャンペーン承認ワークフロー](/ja/user-guide/settings/account/team-management/campaign-approval-workflow)を参照してください。 |
| Stop | キャンペーンが 'Sending' 状態のときに実行でき、キャンペーンを停止できます。 |

# キャンペーンの分析

分析セクションには、パフォーマンス統計と収益指標に関する情報が含まれます。

## キャンペーンパフォーマンス統計

キャンペーンパフォーマンスは、コネクターキャンペーンの効果を示します。

**統計セクションで実行できるアクション**

1. _数値ビュー_ または _パーセンテージビュー_ を選択して、統計を数値またはパーセンテージで表示します。
2. セクション上部の _ドロップダウンで Unique または Total_ を選択して、統計のユニーク数または合計数を表示します。
3. _指標のピン留め_ - 右上の _Pin metrics ドロップダウン_ を使用して、表示したい指標をピン留めできます。最大 5 つの指標をピン留めできます。選択したピン留め指標は Pinned Metrics セクションに表示されます。\_Show all metrics\_をクリックするとキャンペーンで追跡されているすべての指標が表示され、_Hide unpinned metrics_ をクリックするとキャンペーンのピン留めされた指標のみが表示されます。

![withoiut rectanghle campaign perfom stst.png](/images/moengage_cfd4bb.png)

次のキャンペーンパフォーマンス統計を利用できます。

1. **コンバージョン指標** - これらの指標は、キャンペーンに設定されたコンバージョンゴールに関連します。これらの指標が高いほど、キャンペーンの効果が高いことを示します。コネクターキャンペーンで追跡されるコンバージョン指標を以下の表に示します。
   | 指標 | 説明 |
   | --- | --- |
   | Converted Users | プライマリコンバージョンを完了したユニークユーザーの数を示します。Converted Users は以前は Conversions と呼ばれていました。この指標は、各キャンペーンからユーザーがコンバージョンした回数を表示します。繰り返しが 1 回のみのキャンペーンでは、Converted Users は[アトリビューションウィンドウ](/ja/user-guide/campaigns-and-channels/campaign-management-and-reports/conversion-and-attribution#attribution-window)内にプライマリコンバージョンゴールイベントを少なくとも 1 回達成したユニークユーザーを表します。アクティブなキャンペーンでは、Converted Users はアクティブなキャンペーンのインスタンスごとにコンバージョンしたユニークユーザーの数を表します。Converted Users の数が多いほど、キャンペーンがビジネスゴールの達成に効果的であることを示します。  <br />**例** <ol><li>ユーザーが X 日目に 1 つのキャンペーンインスタンスを受信し、Y 日目に別のインスタンスを受信して、両日にそれぞれ 1 回コンバージョンした場合、Converted Users は 2 としてカウントされます(以前のバージョンでは 1 としてカウントされていました)。</li><li>ユーザーが X 日目に 1 つのキャンペーンインスタンスを受信し、同じキャンペーンから 2 回コンバージョンした場合、Converted Users は 1 としてカウントされます。</li><li>ユーザーが X 日目に同じキャンペーンの 2 つのキャンペーンインスタンスを受信し、両方でコンバージョンした場合、Converted Users は 2 としてカウントされます。</li></ol> |
   | Event (Primary) | ユーザーが通知を受信した時点から[アトリビューションウィンドウ](/ja/user-guide/campaigns-and-channels/campaign-management-and-reports/conversion-and-attribution#attribution-window)(設定可能)内に発生したプライマリコンバージョンゴールイベントの合計数を示します。  Event Primary カードではアップリフトのパーセンテージも確認できます。詳細については、[キャンペーンのアップリフト](/ja/user-guide/campaigns-and-channels/getting-started/introduction/control-groups)を参照してください。**Event (Primary)** - アクティブなキャンペーンのコンバージョンは、すべてのキャンペーン通知から発生したコンバージョンイベントの数です。この指標は、最初のキャンペーン開始後のプライマリコンバージョンイベントの累計です。  **例**  ユーザーが商品購入のためのコネクターキャンペーンを受信したとします。ユーザーが 2 回購入した場合、コンバージョンイベントは 2 になります。 |
   | Conversion Rate(CVR) | コンバージョンイベントを実行したユーザーの割合をパーセンテージで示します。コンバージョン数はユニークとして追跡されます。コンバージョンイベントが多いほど、キャンペーンがビジネスゴールの達成に効果的であることを示します。  CVR = ((Unique conversions) / (Total sent)) \* 100 |
   | Revenue Metrics | プライマリゴールで有効になっている場合、キャンペーンには 3 つの収益指標があります。 <ul><li>**Total Campaign Revenue** は、キャンペーンに起因するコンバージョンイベント全体の合計注文金額です。</li><li>**Average Order value** = (Total Revenue/ Number of conversion events)</li><li>**Average Revenue per user** = (Total Revenue/ Number of unique conversions)</li></ul> <img src="/images/moengage_93c821.png" alt="ConnectorInfo_PerformanceStats.png" /> |

<Note>
  収益属性がオブジェクト配列内にある場合、MoEngage の計算結果が想定と一致しないことがあります。詳細については、[オブジェクト属性を使用した収益トラッキング](/ja/user-guide/campaigns-and-channels/campaign-management-and-reports/conversion-and-attribution#how-revenue-is-calculated-for-object-array-attributes)を参照してください。
</Note>

2. **配信指標** - コネクターキャンペーンで追跡される配信指標を以下の表に示します。
   | 指標 | 説明 |
   | --- | --- |
   | **Attempted** | キャンペーンの対象となり(フリークエンシーキャップに違反したユーザーを除外した後)、MoEngage がコネクターリクエストの送信を試行したユーザーの数を示します。 |
   | **Sent** | 正常に送信されたコネクターリクエストの合計数を表します。コネクターリクエストが送信されると、受信側サーバーはコネクターリクエストの処理結果を示すレスポンスコードを返します。Sent は、URL に送信されたリクエストが _200 OK_ ステータスを返したユーザーの数です。  **Sent rate** は (Sent/Attempted)\*100 で計算されます。 |
   | **Failed** | リクエスト URL からのレスポンスが 200 以外のステータスを返したユーザーの数と、コネクターリクエストで使用されるユーザー/イベント属性の値を MoEngage が見つけられなかったユーザーの数の合計を表します。  **Failure rate** は (Failed/Attempted)\*100 で計算されます。 |
3. 以下の表は、リクエスト URL からのレスポンスに応じて配信指標がどのようにマークされるかをまとめたものです。コネクターキャンペーンではリクエストは再試行されません。
   | レスポンスコード | Sent としてマーク | Failed としてマーク |
   | --- | --- | --- |
   | 200 | はい | いいえ |
   | その他 | いいえ | はい |

## コンバージョンゴールのパフォーマンス

このセクションは、キャンペーンに複数のコンバージョンゴールを設定した場合に表示されます。このセクションでは、マーケターがキャンペーンに設定したゴールのパフォーマンスを比較します。

**Total Conversions:** 各ゴールのすべてのゴールイベントを表示します。つまり、ユーザーが 2 回購入した場合は 2 回として表示されます。上記のセクションで説明したコンバージョンイベントに相当します。

**Unique Conversions:** ゴールは、キャンペーンインスタンスごとにコンバージョンしたユーザー全体でユニークです。上記のセクションで説明した Conversions 指標に相当します。

Conversion Goals パフォーマンスの表形式ビューで、アップリフトのパーセンテージを確認できます。詳細については、[キャンペーンのアップリフト](/ja/user-guide/campaigns-and-channels/getting-started/introduction/control-groups)を参照してください。

## キャンペーン配信

キャンペーン配信統計セクションは、配信ファネルと各ファネルステージで除外されたユーザーの数を把握するのに役立ちます。各配信ファネルステージについて、以下の表で説明します。

| ファネルステージ | 内容 |
| --- | --- |
| Users in segment | キャンペーンの対象となったセグメント内のユーザーの合計数を表します。 |
| Users after FC Removal | コネクターの FC 設定で定義されたフリークエンシーキャップを超えたリクエストを除外した後のユーザー数を表します。 |
| After Personalization Removal | パーソナライズに失敗したリクエストを除外した後のユーザー数を表します。 |
| Sent | リクエスト URL から 200 レスポンスを受け取ったコネクターリクエストの数を表します。 |

## エラーの内訳

このセクションでは、さまざまなキャンペーン配信の失敗とその理由について説明します。エラーは次のカテゴリに分類されます。

- **Failed to Send エラー** - リクエストが送信されなかった場合に発生するエラーで、次のいずれかの理由により発生する可能性があります。
  - キャンペーンのコントロールグループに含まれていたため除外されたユーザー
  - フリークエンシーキャップの上限違反によりキャンペーンから除外されたユーザー
  - リクエスト URL が 200 以外のレスポンスを返したユーザー
  - 定義されたローリングウィンドウ内で、キャンペーンの **Limit Message** 設定の上限にすでに達していたため除外されたユーザー。詳細については、[定期キャンペーンおよびトリガーキャンペーンのメッセージ制限](/ja/user-guide/settings/channels/delivery-controls/limit-messages-for-periodic-and-triggered-campaigns)を参照してください。
  - パーソナライズ属性が利用できなかったためキャンペーンから除外されたユーザー。パーソナライズエラーの **Name** 列にある **See breakdown** をクリックすると、パーソナライズに失敗したユーザーの数とその理由の詳細を確認できます。 <img src="/images/moengage_c0b513.png" alt="Personalization Failed.png" />
  
パーソナライズエラーは、次のカテゴリに分類できます。

| エラーカテゴリ | 説明 |
| --- | --- |
| User Attribute | パーソナライズで使用されるユーザー属性が、システムに存在しない(コピー&ペーストのミスなど)、または特定のユーザーに対して存在しないために利用できないことを示します。たとえば、パーソナライズで first\_name ユーザー属性を使用しており、あるユーザーにその属性がない場合、**User Attribute** エラーになります。 |
| Event Attribute | パーソナライズで使用される属性が、システムに存在しない(コピー&ペーストのミスなど)、または特定のユーザーに対して存在しないために利用できないことを示します。たとえば、パーソナライズで product\_name イベント属性を使用しており、あるユーザーにその属性がない場合、**Event Attribute** エラーになります。 |
| Campaign Attribute | パーソナライズで使用されるキャンペーン固有の情報が利用できないことを示します。たとえば、パーソナライズにキャンペーンタグを使用しており、キャンペーンタグ属性が欠落している場合、**Campaign Attribute** エラーになります。 |
| Undefined | パーソナライズで使用される属性の値を MoEngage が取得できない場合に発生するエラーを示します。たとえば、プロダクトセット内の特定の商品で画像属性が利用できない場合、**Undefined** エラーになります。 |
| Unknown | 上記のいずれのカテゴリにも該当しないエラーを示します。 |

<Info>
  **Failed to Send** の **Personalization Failed** カテゴリに表示される失敗数は、パーソナライズに失敗したユニークユーザーの数を示します。同じユーザーに対して複数の失敗が発生し、UI に表示される各失敗カテゴリでそれぞれカウントされる場合があるため、この数はパーソナライズ失敗分析 UI に表示されるカウントと異なることがあります。たとえば、あるユーザーでユーザー属性とイベント属性の両方の失敗が発生した場合、**分析** 画面では両方のセクションで失敗数としてカウントされますが、**Personalization Failed** セクションでは 1 としてカウントされます。

  ![Personalization Failure Analysis.png](/images/moengage_7efe08.png)
</Info>
