テストキャンペーンは、キャンペーン開始前の品質保証において重要なステップです。テストにより、メールのレイアウトを事前に検証し、さまざまなユーザーセグメントにおけるパーソナライゼーションの正確性を確認し、すべてのリンクとメディアをチェックできます。テストを実施することで、キャンペーンが意図したとおりに表示および機能することを確認でき、不具合のあるコンテンツをオーディエンス全体に配信してしまうリスクを軽減できます。

<Tip>
  先に進む前に、[メールキャンペーンの作成](/ja/user-guide/campaigns-and-channels/email/create/create-an-email-campaign)のジャーニーで、ステップ 1: **Target Users** とステップ 2: **Content** を完了していることを確認してください。
</Tip>

<Note>
  テストキャンペーンおよびプレビューキャンペーンでは、ユーザープロファイルのデータは変更されません。テストを送信しても、配信停止ステータス（`moe_unsubscribe`）やその他の到達可能性属性などのプロファイルフィールドは更新されません。これらのフィールドを更新するのはライブキャンペーンのみです。配信停止フロー（または同様のプロファイル更新）を検証するには、小規模な社内セグメントをターゲットにしたライブキャンペーンを実行してください。
</Note>

# テストキャンペーンの送信

テストキャンペーンを送信するには、以下のコンポーネントを使用して、ロケール、ターゲットユーザー、およびパーソナライゼーションに使用するデータを制御できます。

- [ロケールとバリエーション](/ja/user-guide/campaigns-and-channels/email/create/test-email-campaign#locale-and-variations)
- [Send via](/ja/user-guide/campaigns-and-channels/email/create/test-email-campaign#send-via)
- [ランダムユーザーでパーソナライズ](/ja/user-guide/campaigns-and-channels/email/create/test-email-campaign#personalize-with-a-random-user)
- [テストメール](/ja/user-guide/campaigns-and-channels/email/create/test-email-campaign#test-email)

## ロケールとバリエーション

メールキャンペーンに複数のロケールとバリエーションがある場合、**Test Campaign** セクションに **Locale and variations** ドロップダウンメニューが表示されます。

この **Locale and variations** ドロップダウンを使用して、テストしたい特定のロケールとバリエーションを選択し、**Send via** ドロップダウンで利用可能なオプションを使ってテストメールを送信できます。この機能により、複数のロケールバリエーションを同時にテストできます。

MoEngage は、テストに使用する識別子に基づいて、選択したロケールとバリエーションの組み合わせごとに個別のメールを送信します。たとえば、2 つのロケール（例: 英語とスペイン語）と 3 つのキャンペーンバリエーション（例: A、B、C）を選択した場合、MoEngage は選択した各ユーザーに 6 通の異なるテストメールを送信します。この一括送信機能により、ロケールの組み合わせごとに多数のテストユーザープロファイルを作成することなく、キャンペーンのすべてのバージョンを確認できます。
  ![Testcampaign1](/images/testcampaign1.png)


## Send Via

**Send via** ドロップダウンから以下のオプションを選択して、メールキャンペーンをテストできます。

  ![Testcampaign2](/images/testcampaign2.png)


- **Custom Segment**: 選択したカスタムセグメントから最大 50 人のユーザーにパーソナライズされたテストメールを送信できます。セグメントに 50 人を超えるユーザーが含まれている場合、MoEngage はランダムに選択された 50 人のユーザーにテストキャンペーンを送信します。
- **Email ID (Registered users)**: メール ID を入力することで、MoEngage に既存のユーザープロファイルを持つユーザー（登録済みユーザー）にパーソナライズされたテストメールを送信できます。
- **Email ID (Non-registered users)**: メール ID を入力することで、外部ユーザー（未登録ユーザー）にテストメールを送信できます。
- **Unique ID**: 一意の顧客 ID を入力することで、既存ユーザーにパーソナライズされたテストメールを送信できます。一意の ID を入力すると、関連付けられたユーザープロファイルが取得され、登録済みのメールアドレスにテストが送信されます。
- **Mobile Number**: 携帯電話番号を入力することで、既存ユーザーにパーソナライズされたテストメールを送信できます。携帯電話番号を入力すると、関連付けられたユーザープロファイルが取得され、登録済みのメールアドレスにテストが送信されます。
  <Info>
    [PII（個人を特定できる情報）トークン化送信](/ja/user-guide/data/privacy/personal-data-or-personally-identifiable-information-pii/pii-tokenized-sending)が有効になっている場合、登録済みユーザーに対する以下の識別方法は利用できません。
    - **Email ID (Registered users)**
    - **Mobile Number**
  </Info>

## ランダムユーザーでパーソナライズ

パーソナライゼーションにデフォルトのユーザープロファイルのデータを使用するには、**Personalize with arandom user** トグルをオンにします。特定のユーザーを選択するには、MoEngage の[パーソナライズドプレビュー](/ja/user-guide/campaigns-and-channels/getting-started/message-personalization/personalized-preview)機能を使用します。

  ![Testcampaign3](/images/testcampaign3.png)

<Info>
  - **Email ID (Non-registered users)** オプションを選択すると、MoEngage は自動的に **Personalize with a Random User** トグルをオンにします。これは、未登録ユーザーにはプロファイルがないため、パーソナライゼーションフィールドにサンプルデータを提供するためです。このトグルはオフにできますが、その場合パーソナライゼーションは解決されません（下表を参照）。
  - その他すべての **Send via** オプションでは、MoEngage は選択したユーザーの実際の属性を使用します。**Personalize with a Random User** トグルをオンにすると、デフォルトのサンプルプロファイルのデータが優先され、パーソナライゼーションにおいて選択したユーザーの実際の属性が上書きされます。
  - 透明性を確保するため、MoEngage はパーソナライゼーションにデータが使用されているデフォルトユーザーの識別子を表示します。
</Info>

### 各シナリオで解決されるパーソナライゼーション

テストメールで解決されるパーソナライゼーションの種類と、その解決に MoEngage が使用するデータは、**Personalize with a Random User** トグルの状態と選択した **Send via** オプションによって異なります。

| Personalize With A Random User トグル | Send Via | ユーザー属性のパーソナライゼーション | イベント属性のパーソナライゼーション | コンテンツブロック、Product Set、補助データ、または Content API\* | 使用されるデータ |
| --- | --- | --- | --- | --- | --- |
| OFF | Email ID (Non-registered users) | ❌ 解決されない | ❌ 解決されない | ❌ 解決されない | 該当なし |
| OFF | Custom Segment、Email ID (Registered users)、Unique ID、または Mobile Number | ✅ 解決される | ❌ 解決されない | ✅ 解決される | ターゲット/選択したユーザーの実際のプロファイルデータ |
| ON | すべての **Send via** オプション | ✅ 解決される | ✅ 解決される | ✅ 解決される | パーソナライズドプレビューのデフォルトサンプルユーザーのデータ |

\* コンテンツブロック、Product Set、補助データ、または Content API 自体にイベント属性の Jinja パーソナライゼーションが含まれていない場合にのみ解決されます。

<Note>
  ターゲット/選択したユーザーでテストする場合（トグル OFF）、イベント属性のパーソナライゼーションは解決されません。キャンペーンコンテンツにイベント属性のパーソナライゼーションが含まれている場合は、**Personalize with a Random User** をオンにしてください。
</Note>

関連情報: ここに表示されるサンプルデータがライブ送信時に解決される内容と一時的に異なる場合がある理由については、[メールのレンダリング: 動作とトラブルシューティング](/ja/user-guide/campaigns-and-channels/email/create/personalize-email-content#email-rendering-behavior-and-troubleshooting)を参照してください。

## テストメール

**Test** をクリックしてテストメールを送信します。テストメールの送信後、**View test results** をクリックして、生成されたテスト結果にアクセスします。

  ![Testcampaign4](/images/testcampaign4.png)


<Info>
  - テストキャンペーンでロケールとバリエーションの両方が選択されている場合、MoEngage は件名の先頭に角括弧で囲まれたプレフィックス \[TEST - `<Locale Name>` - `<Variation Name>`\] を自動的に付加します。
  - その他すべてのテストキャンペーンでも、プレフィックスには \[TEST\] インジケーターが含まれるため、ロケールバリエーションの選択有無にかかわらず、すべてのテストメールを簡単に識別できます。
  - UTM パラメータ付きのキャンペーン URL をテストして、適切な値が取得されることを確認できます。
  - 実行できるテストキャンペーンの数に 1 日あたりの上限はありません。
</Info>

### テスト結果

**Test results** ページには、送信を試みた各メールの詳細データを示す表が表示されます。送信の **Status**、送信された特定の **Locale-variation** の組み合わせ、および失敗に関する情報（**Failure reason** と推奨される **Corrective actions** を含む）が記載されます。

# 失敗シナリオ

以下の表は、メールキャンペーンで起こりうる失敗シナリオの概要を示しており、システムが報告する理由と、解決に必要な対応する技術的手順を詳しく説明しています。

| 失敗の理由 |説明  | 是正措置 |
| --- | --- | --- |
| **MoEngage suppression or User not found** | このエラーは、追加された識別子がワークスペース内の登録済みユーザープロファイルに含まれていない場合に発生します。 |  |
| このエラーは、Hard Bounce、Unsubscribe、Spam などのユーザー属性が True に設定されている場合や、ユーザーが選択したサブスクリプションカテゴリに登録していない場合にも発生することがあります。<br /><br /> 選択した識別子にテストメールを送信するには、これらの属性の値を False に更新してください。そのためには、<a href="/ja/user-guide/data/imports/manual-uploads" target="_blank" rel="noopener noreferrer">こちら</a>  に記載されている手順に従ってください。選択したサブスクリプションカテゴリが配信停止リストに含まれている場合は、<a href="/ja/user-guide/campaigns-and-channels/email/getting-started-with-email/handle-unsubscribes-in-emails" target="_blank" rel="noopener noreferrer">こちら</a>  に記載されている手順に従ってください。 | プロファイルが存在する場合は、Hard Bounce、Unsubscribe、Spam の値が False であること、およびユーザーが選択したサブスクリプションカテゴリに登録されていることを確認してください。 |  |
| メールがトランザクションメールの場合、Hard Bounce などのユーザー属性が True に設定されていると、このエラーが発生することがあります。 | 選択した識別子にテストメールを送信するには、Hard bounce 属性の値を False に更新してください。そのためには、<a href="/ja/user-guide/data/imports/manual-uploads" target="_blank" rel="noopener noreferrer">こちら</a>  に記載されている手順に従ってください。 |  |
| **Added invalid/inaccessible attachments** | このエラーは、指定された添付ファイルのリンクが公開アクセス可能でないために発生します。 | 公開アクセス可能な有効な添付ファイルのリンクを追加してください。アクセス可能かどうかを確認するには、URL をシークレットブラウザウィンドウに貼り付け、添付ファイルが正常に読み込まれることを確認します。 |
| **Added invalid template** | このエラーは、選択したカスタムテンプレートが無効または空であるために発生します。 | 既存の空でないカスタムテンプレートを選択してください。これを行うには、メールキャンペーン設定の <a href="/ja/user-guide/campaigns-and-channels/email/create/create-an-email-campaign#step-2-content" target="_blank" rel="noopener noreferrer">ステップ 2: Content</a>   で **Saved Templates** からテンプレートにアクセスし、テンプレートの内容を確認します。 |
| **Unable to resolve personalization** | このエラーは、コンテンツのパーソナライゼーションの問題、またはユーザープロファイル内のデータ不足により、MoEngage がパーソナライゼーションを解決できない場合に発生します。具体的には、選択したユーザープロファイルに、キャンペーン内のパーソナライゼーションフィールドに必要な属性値がない場合に発生します。 | テストメールに使用されるすべての種類のパーソナライゼーションに値があることを確認してください。 |
| **Added invalid HTML code** | このエラーは、コンテンツに無効または空の HTML が含まれている場合に発生します。 | チームでレビューするか、公開されている <a href="https://validator.w3.org/nu/#textarea" target="_blank" rel="noopener noreferrer">HTML 検証ツール</a>  を使用して HTML コンテンツを検証し、特定された問題を修正してください。 |
| **Entered email ID(s) are invalid** | このエラーは、入力された From アドレスまたは Reply-to メール ID が無効であるために発生します。 | 有効な From ID / Reply to メール ID を使用し、入力ミスを修正してください。 |
| **SMTP connection failure** | このエラーは、送信者設定の認証情報が正しくないために発生します。 | 送信者設定で使用されている認証情報を確認してください。有効な場合は、もう一度操作を試してください。 |
| **SMTP response failure** | このエラーは、送信者設定の認証情報が正しくないために発生します。 | 送信者設定で使用されている認証情報を確認してください。有効な場合は、もう一度操作を試してください。 |
| **Duplicate email ID** | このエラーは、選択したリストに同じメール ID を共有する複数のユーザープロファイルが含まれている場合に発生します。 | MoEngage は送信前に重複排除を行います。正確なテストを行うには、一意のメール ID を持つプロファイルを使用してください。 |
| **Email content failed to resolve to valid HTML code.** | このエラーは、\<html\> タグと \<body\> タグの両方が欠落している場合に発生します。 | メールが正しくレンダリングされるよう、コンテンツをこれらの標準タグで囲んでください。 |
| このエラーは、必須の \<html\> タグと \</html\> タグが欠落している場合に発生します。 | もう一度試す前に、コードの先頭と末尾に \<html\> と \</html\> を追加してください。 |  |
| このエラーは、\<body\> コンテナが欠落しているか空の場合に発生します。 | 実際のメールコンテンツを開始と終了の body タグで囲んでいることを確認してください。<br /><br />このエラーは、<a href="/ja/user-guide/campaigns-and-channels/email/create/add-view-in-browser-vib-link-to-emails" target="_blank" rel="noopener noreferrer">VIB（View in Browser）機能</a>   が有効になっている場合にのみ表示されます。 |  |
