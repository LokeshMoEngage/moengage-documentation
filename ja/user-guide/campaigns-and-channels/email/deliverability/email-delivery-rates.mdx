# 概要

メール配信率とは、送信したメール数に対する、受信サーバーに正常に受け入れられたメール数の比率です。

<Info>
  メール配信率は次のように計算されます。

  - メール配信率 = \[#配信済みメール/ #送信済みメール\]\*100
  - メール配信率 = \[(#送信済みメール - #バウンスしたメール)/ #送信済みメール\]\*100
</Info>

# メール配信率が低い理由

メール配信率の低下につながる要因は次のとおりです。

## ハードバウンス

ハードバウンスは恒久的な失敗であり、受信者のメールアドレスまたはドメインが存在しない場合に発生します。ハードバウンス率が高い場合は、メールリストの品質が悪く、多くの受信者が有効なメールアドレスを持っていないことを示しています。ハードバウンスは、次の理由でも発生する場合があります。

- **無許可のオーディエンス収集**：受信者からの適切な許可や同意なしにメールアドレスを収集し、メールリストを作成する行為を指します。
- **メールリストの衛生管理の欠如**：メールリストが定期的に管理されておらず、古いメールアドレスや無効なメールアドレスが含まれている可能性があることを指します。

<Info>
  MoEngage では、メールがハードバウンスした受信者は、今後のすべての配信から抑制されます。
</Info>

## ソフトバウンス

ソフトバウンスは一時的な失敗であり、後で解決できるメール配信の一時的な問題を示します。ソフトバウンス率が高い場合は、メールリストの品質が悪いこと、またはメール配信の手法が不適切であること、あるいはその両方を示しています。ソフトバウンスは、次の理由でも発生する場合があります。

- メールボックスの容量不足
- 受信者のドメインが利用できない、または到達できない
- IP またはドメインのブロック（コンテンツがスパムとしてフラグ付けされたためにメールがブロックされる）
- ドメインまたは IP のレピュテーションが低いことによるブロック

<Info>
  - バウンスエラーコードは、_Email soft bounced_ イベントの _reason_ という名前の属性で確認できます。特定のユーザーについては、**User Profile**\> **Activity info** タブでこの情報を確認できます。

  - メールベンダー（SendGrid、SES、SparkPost など）がバウンスの分類（ハードバウンスとソフトバウンス）を行います。MoEngage は内部でこの分類を行いません。
  - MoEngage では、メールがソフトバウンスした受信者は、今後の配信から抑制されません。
</Info>

## 遅延（Deferral）

メールの遅延（Deferral）とは、メールサーバーがメールの配信を一時的に遅らせることです。これは、メールサーバーがメールの配信を恒久的に拒否するドロップとは異なります。遅延は、メールが送信されたものの正常に配信できない、または失敗が発生した一時的な状態であり、配信が保留中の一時的な状態を示していると考えることができます。

遅延は、受信サーバーが次のようなメッセージで応答した場合に発生することがあります。

- サーバーがビジー状態
- IP のレート制限またはスロットリング

これにより、MoEngage はこれらのメールが正常に配信されるか、失敗（バウンス）としてマークされるまで、送信を再試行します。遅延が発生すると、メールは事前に設定された bounce-after 期間まで再試行され、その後、正常に配信されるか、バウンスとしてマークされます。bounce-after 期間は通常、Sendgrid では 72 時間、Amazon SES では 14 時間です。したがって、最初の配信試行から 72 時間経過してもメールがキューに残っている場合、そのメールはソフトバウンスとして分類されます。

<Info>
  1 つの送信イベントが複数の遅延につながる場合がありますが、1 つの遅延は 1 つの配信済みイベントまたはバウンスイベントにしかつながりません。
</Info>

## ラテラルバウンス

ラテラルバウンスは例外的なケースで、受信サーバーが最初はメールを受け入れ、後で拒否するものです。これは通常、受信サーバーの受信メール処理設定の誤りが原因で発生します。

# 配信率の向上

ハードバウンスとソフトバウンスは配信率が低くなる主な原因です。これらの数を減らすことで、配信率の向上につながります。

## ハードバウンスを減らす

ハードバウンスを減らすには、次の手順を実行します。

- **自動抑制メカニズムを確認する**：自動抑制メカニズムとは、メールサービスプロバイダー（ESP）が実装している、バウンスした受信者へのメール送信を自動的に抑制または停止するシステムまたはプロセスです。ハードバウンスの自動抑制メカニズムが想定どおりに機能していることを確認してください。
- **メールリストの収集ポイントを確認する**：新規顧客については、有効なメールアドレスが収集されるように、メールリストの収集ポイントを保護します。サインアップフォームでダブルオプトインや CAPTCHA を使用したり、入力ミスを防ぐために顧客にメールアドレスを再入力してもらったりできます。
- **エンゲージしていないユーザーを削除する**：一定期間（約 9 か月）アクティビティがない場合は、メールアドレスが有効かどうかにかかわらず、それらのユーザーを削除します。
- **データベースをクリーニングする**：長期間メールを送信していない場合や、オフラインでのサインアップがある場合は、サードパーティのサービスを使用してデータベースをクリーニングすると効果的です。
- **新規ユーザーにウェルカムキャンペーンを送信する**：適切に実行されたウェルカムキャンペーンは、新規購読者との強固な基盤の確立、信頼の構築、メールアドレスの検証、エンゲージメントの促進、リストの衛生管理の改善に役立ちます。これらの要因が総合的にハードバウンスの削減に貢献します。
- **リストの購入を控える**：購入したリストには、古いメールアドレス、無効なメールアドレス、または存在しないメールアドレスが含まれていることがよくあります。リストの購入を控え、代わりに許可ベースの正当な方法でメールリストを作成することで、メールアドレスが最新かつ有効であることを保証できます。これにより、ハードバウンスが発生する可能性が大幅に減少します。

## ソフトバウンスを減らす

ソフトバウンスを減らすには、次の手順を実行します。

- **[ハードバウンス](/ja/user-guide/campaigns-and-channels/email/deliverability/email-delivery-rates#hard-bounce)が少ないことを確認する**：ハードバウンスとソフトバウンスはそれぞれ独立していますが、ハードバウンスを効果的に管理することは、健全なメール配信インフラストラクチャの維持に貢献します。恒久的な配信失敗を最小限に抑えることで、メールの配信が成功しやすい条件が整い、ソフトバウンスの可能性が低下します。
- **ドメインと IP のレピュテーションが中程度以上であることを確認する**：良好なドメインと IP のレピュテーションを確立して維持することで、メールの配信が成功しやすい環境が整い、受信者の信頼が高まり、ソフトバウンスの可能性が低下します。ドメインレピュテーションを高めるためのヒントについては、[ドメインレピュテーションの問題と予防策](/ja/user-guide/campaigns-and-channels/email/deliverability/domain-reputation/issues-with-domain-reputation-and-preventive-measures)を参照してください。
- **IP ブロックがないか確認する**：IP ブロックが確認された場合は、問題を解決するための適切な措置を講じてください。IP ブロックが有効な間は、ブロックが解除されるまで、影響を受けるドメインの受信者を抑制することをお勧めします。
- **受信者を抑制する**：メールボックスが利用できない、または容量不足のために継続的にソフトバウンスする受信者を抑制することで、メール配信を最適化できます。これにより、アクティブで反応のある受信者をターゲットにでき、エンゲージメント率が向上し、ソフトバウンスが減少します。
- **メールコンテンツ（HTML）をテストする**：メールコンテンツを徹底的にテストし、スパムフィルターが作動しないようにすることで、メールがバウンスしたりスパムとしてマークされたりする可能性を減らすことができます。これにより、デリバラビリティの向上、エンゲージメントの増加、ソフトバウンスの減少につながります。

<Info>
  オーディエンスの品質と送信行動が良好であれば、一貫して 99% の配信率を達成できます。
</Info>

## 遅延を減らす

遅延を減らすには、次の手順を実行します。

- **新規送信者は、メールのウォームアップとランプアップを正しく行う**：これは、メールプロバイダーとの良好なレピュテーションを確立するための積極的なアプローチです。メールの送信量を徐々に増やし、責任ある送信方法を示すことで遅延の可能性を減らし、最終的にデリバラビリティとメールキャンペーンの成功を向上させます。
- **送信量の急増を避ける**：メールサーバーが短期間に異常に大量のメッセージを受信すると、一時的に過負荷になったり、リソースの制限が発生したりする場合があります。このような場合、サーバーは一部のメールの配信を遅延させることで対応する場合があります。したがって、既存の送信者は送信量の急増を避ける必要があります。
- **低い 1 分あたりのリクエスト数（RPM）を使用してワンタイムキャンペーンをスロットリングする**：低い RPM を設定すると、1 分あたりのメールリクエスト数が制限されます。これにより、サーバーがリクエストをより効果的に処理でき、遅延の可能性が低下します。ベストプラクティスについては、[こちら](/ja/user-guide/campaigns-and-channels/email/deliverability/best-practices/best-practices-regarding-request-per-minute-rpm)を参照してください。
- **大量送信のキャンペーンには [Best time to send (BTS)](/ja/user-guide/ai-and-intelligence/timing/best-time-to-send) 戦略を使用する：** BTS 戦略は、特に大量の送信を不定期に行う場合に役立ちます。タイムリーかつ正常なメール配信の可能性を高めることでメール配信を最適化し、遅延の可能性を減らします。
- **IP の数が十分であることを確認する**：特に地域ドメインの場合、メールの送信量を支える十分な数の IP を確保することで、メール配信の遅延を減らすことができます。
- **一時停止して少ない送信量で送信する**：一時停止してから、以前のメール開封者に少ない送信量で送信し、その後適切なランプアッププロセスを実施することで、メール配信の遅延を減らすことができます。

<Info>
  詳細については、[メール配信率に関する FAQ](/ja/user-guide/campaigns-and-channels/email/deliverability/email-deliverability-faqs/faq-regarding-email-delivery-rates) を参照してください。
</Info>
