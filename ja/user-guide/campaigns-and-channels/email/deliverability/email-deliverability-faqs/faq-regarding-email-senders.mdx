この記事では、メールコネクターとコネクター間のドメイン移行に関する最も一般的な質問にお答えします。

## 既存のメールプロバイダーがあります。MoEngage と連携できますか？

はい。SendGrid、Amazon SES、SparkPost、Mandrill、Netcore などのネイティブコネクターを使用しない場合、MoEngage ではカスタムコネクターのセットアップをサポートしています。詳細については、[Partner Guides](/ja/partner-guide/messaging-channels/email-providers/configure-amazon-ses) を参照してください。

MoEngage のネイティブコネクター以外のメールコネクターのアカウントをお持ちの場合は、App marketplace を通じて、コネクターの詳細をカスタムメールコネクターとして MoEngage で設定できます。詳細については、[Configure Custom Connector](/ja/user-guide/campaigns-and-channels/email/getting-started-with-email/configure-email-channel) を参照してください。

## MoEngage が管理するメールプロバイダーと独立したメールプロバイダーの違いは何ですか？

|  |  |  |
| --- | --- | --- |
| **基準** | **MoEngage プロバイダー** | **MoEngage で設定した独立した Sendgrid アカウント** |
| 到達率のサポート | MoEngage チームが以下をサポートします。<ol><li>メールのセットアップ</li><li>送信量の段階的な増加を含むメールのオンボーディング</li><li>監視、傾向と問題の特定、トラブルシューティング</li><li>監査レポートの提供（有料）</li><li>到達率に関する包括的なサポートの提供</li><li>MoEngage が割引された一括料金を提供するため、料金が安くなります。</li></ol> | プロセス全体を通じた手厚いサポートと到達率のサポートがないことを除けば、独自のプロバイダーを使用することによる大きな技術的デメリットはありません。  また、MoEngage チームがベンダーとの問題のトラブルシューティングと管理を行います。 |
| 共有 IP | いいえ。 | はい |
| ベンダーへのフルアクセス | いいえ。ただし、すべてのデータは MoEngage のワークプレイスにあるため、通常はフルアクセスは必要ありません。 | はい |

## 同じドメインと IP を MoEngage の Sendgrid に移行できますか？

はい。MoEngage はドメインを移行でき、移行したドメインは異なる ESP と並行して使用できます。Sendgrid の IP が専用 IP である場合は、それらも移行できます。詳細については、[SendGrid IP Migration](/ja/user-guide/campaigns-and-channels/email/getting-started-with-email/sendgrid-ip-migration) を参照してください。

## MoEngage コネクターからメールを送信する際に SMTP エラーが発生します。これはどういう意味ですか？

エラーコードにはエラーの説明が含まれています。問題の解決に役立つ正確な SMTP の説明をエクスポートするには、MoEngage のカスタマーサクセスマネージャー（CSM）またはサポートチームにお問い合わせください。一般的なエラーメッセージの一部を以下に示します。

| **エラーメッセージ** | **エラーの原因** | **解決方法** |
| --- | --- | --- |
| Email address not verified. | f\_rom address\_ または _from domain_ が検証されていない場合に発生します。 | メールプロバイダーでドメインを検証する（DNS レコードを生成して追加する）か、メールプロバイダーで _from address_ を検証する必要があります。 |
| SMTP service disconnected. | 送信サーバーとの SMTP 接続が正常に確立されていない場合に発生します。SMTP アカウントが削除された場合に起こる可能性があります。 | メール設定と、メールプロバイダーの関連するアカウントまたはサブアカウントを確認してください。 |
| SMTP account not activated. | Sendinblue の SMTP アカウントが有効化されていない場合、または有効化の期限が切れている場合に発生します。 | SendinBlue でアカウントを有効化してください。SendinBlue のサポートにお問い合わせください |
| Throttling failure: Maximum sending rate exceeded | Amazon SES で設定された送信レートを超える速度でメールを送信した場合に発生します。 | キャンペーンをスロットリングし、SES の送信制限を引き上げてください。 |
| Throttling failure: Daily message quota exceeded | SES で設定された 1 日の最大送信数を超えた場合に発生します。これは深夜 0 時にリセットされます。 | SES のメール送信クォータを引き上げてください。 |
| Message rejected: Sending paused for this account. For more information, please check the inbox of the email address associated with your AWS account. | アカウントが停止または一時停止されている場合に発生します。 | SES UI でこのエラーの原因を確認し、SES サポートに問い合わせてこのエラーを解決してください。 |
| Authentication failed: Basic authentication is not allowed with 2FA enabled. | Sendgrid アカウントで 2FA が有効になっており、事前に検証されたソースからのメールのみが受け付けられる場合に発生します。 | SendGrid で **Allow List** を無効にするか、カスタマーサクセスチームに連絡して NAT フローを有効にしてください。 |
| Invalid Sending Pool Name: IP Pool is not valid, or no available IPs are found in the pool. | ドメイン/送信者に関連付けられた IP プールが存在しないか、IP が含まれていない場合に発生します | SES の設定を確認し、IP/IP プールの割り当てが正しいことを確認してください。 |
