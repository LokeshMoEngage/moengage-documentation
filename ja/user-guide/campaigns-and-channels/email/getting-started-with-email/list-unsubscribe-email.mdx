配信停止は、メール購読者の管理において自然に発生するものです。ユーザーにとってわかりやすい配信停止プロセスを確保することは、ブランドにとって不可欠です。

すべてのプロモーションメールには法的にメール本文への配信停止リンクが必要ですが、ユーザーがこのオプションを見つけやすくする最も簡単な方法は、List-Unsubscribe を実装することです。この機能は [2024 年からコンプライアンス要件](https://www.moengage.com/blog/upcoming-gmail-yahoo-email-deliverability-changes/)となりました。

# List-Unsubscribe とは

List-Unsubscribe は、インターネットサービスプロバイダー（ISP）が提供するワンクリックの方法で、ユーザーがメールから直接配信停止できるようにするものです。このオプションはメールのヘッダーに埋め込まれます。メールボックスプロバイダーは、送信者のレピュテーション、メール送信量、ユーザーエンゲージメントに基づいて、このオプションを受信者に表示するかどうかを決定します。

ISP が提供するネイティブの配信停止オプションをクリックすると、次の 2 つの方法でユーザーを配信停止できます。

- **ワンクリック配信停止**（[RFC 8058](https://datatracker.ietf.org/doc/html/rfc8058)）\
  この方法では、Uniform Resource Identifier（URI）が呼び出され、メールヘッダーに指定された専用の MoEngage URL が直接トリガーされることで、ユーザーが自動的に配信停止されます。
- **Mail-to 配信停止**この方法では、ユーザーに代わって、メールヘッダー内に指定されたメールアドレスにメールが送信されます。これらのメールを解析し、リクエストから 48 時間以内にユーザーを配信停止する必要があります

## List-Unsubscribe を実装する理由

以前、List-Unsubscribe は到達率のベストプラクティスとされていました。しかし、2024 年 6 月以降、Gmail と Yahoo の両方が、[到達率に関するポリシー](https://www.moengage.com/blog/upcoming-gmail-yahoo-email-deliverability-changes/)においてすべての大量送信者に対する必須要件としています。

この必須プロセスに従うことで、ルールを遵守できるだけでなく、以下のメリットも得られます。

- スパム苦情率を最小限に抑える
- 関心のある購読者にのみメールを送信することで、エンゲージメントとパフォーマンスを最適化する
- メールリストを定期的にクリーンアップすることで、メールマーケティングのコストを削減できる可能性がある
- 購読者との関係を良い形で終える

# MoEngage 管理と自己管理の違い

MoEngage では、次の 2 つの方法でこれらのプラクティスを遵守できるよう支援します。

**MoEngage 管理:** このオプションでは、MoEngage の機能を使用して、MoEngage 内でユーザーのサブスクリプションステータスをシームレスに取得・更新できます。他のシステム（サードパーティツールや社内システム）を使用している場合は、この情報を MoEngage からそれらのシステムに転送できます。

**ブランド管理または自己管理**: このオプションでは、独自のシステムを使用してユーザーの配信停止を処理できます。一般的に、ブランドが自社側でユーザーの設定を管理したい場合に使用されます。この場合、ブランドはユーザーの配信停止を取得し、自社のシステムと MoEngage の両方を更新する必要があります。

## MoEngage での設定方法

要件に応じて、次の 2 つのオプションのいずれかを使用できます。

<Tabs>
  <Tab title="MoEngage 管理のアプローチで設定する">
    **MoEngage 管理**

    MoEngage は、メールヘッダーの HTTPS URL セクションに配信停止 URL を、mail-to セクションにメール ID をそれぞれ追加します。配信停止 URL によりユーザーはクリック 1 回で配信停止でき、メール ID により List-Unsubscribe の mail-to 方式でユーザーが配信停止されます。また、MoEngage はすべてのリクエストを処理し、ワークスペース内のユーザーの設定を更新します。

    MoEngage 管理のアプローチで List-Unsubscribe を設定するには:

    1. MoEngage ダッシュボードにログインします。
    2. **Settings** \> **Channels** \> **Email settings** \> **Sender Configuration** タブに移動します。
    3. メールコネクタをクリックします。
    4. 省略記号アイコンをクリックし、**Edit** をクリックします。
    5. **One-click unsubscribe** で **MoEngage Managed** をクリックします。 <img src="/images/moengage_e0b94d.png" alt="email sendgrid.gif" />

    ### 仕組み

    前述のとおり、MoEngage はプロモーションメールの送信時に、配信停止 URL とメール ID をメールヘッダーに追加します。ユーザーが受信トレイに表示される **Unsubscribe** をクリックすると、次のいずれかが実行されます。

    - ワンクリック方式: ユーザーが **Unsubscribe** をクリックして確認すると、リクエストが MoEngage API に直接送信されます。MoEngage は直ちにリクエストを処理し、ユーザーのプロファイルを更新します。
    - Mail-to 方式: ユーザーが **Unsubscribe** を選択して確認すると、ISP が MoEngage の受信トレイにメールを送信します。MoEngage はこのリクエストを処理し、48 時間以内にユーザーのプロファイルを更新します。

    ### 配信停止データを自社システムに渡す方法

    これらのユーザー設定の変更を社内システムまたはサードパーティシステムに渡したい場合は、次のいずれかを実行します。

    - イベントトリガー型のコネクタキャンペーンを設定します。_Email Unsubscribed event is triggered_ のときにトリガーされ、自社またはサードパーティシステムの API を呼び出して値を更新するように設定します。詳細については、[コネクタキャンペーンの作成](/ja/user-guide/campaigns-and-channels/connectors/create/create-a-connector-campaign)を参照してください。
    - MoEngage Streams を設定して、\_Email Unsubscribed\_event をエンドポイントに渡します。その後、このデータをさらに処理したり、他のシステムに転送したりできます。詳細については、[MoEngage Streams](https://www.moengage.com/docs/api/data/moengage-streams) を参照してください。
  </Tab>
  <Tab title="自己管理のアプローチで設定する">
    **自己管理** 自己管理では、配信停止 URL とメール ID を指定する必要があります。MoEngage はメールの送信時に、これらをメールヘッダーの HTTPS URL セクションと mail-to セクションに追加します。ただし、配信停止リクエストのその後の処理はお客様の責任となります。コンプライアンスを確保するには、48 時間以内に配信停止を処理する必要があります。また、MoEngage が今後のキャンペーンからこれらの配信停止ユーザーを自動的に除外できるよう、更新された設定を MoEngage に返す必要があります。

    自己管理のアプローチで List-Unsubscribe を設定するには:

    1. MoEngage ダッシュボードにログインします。
    2. **Settings** \> **Channels** \> **Email settings** \> **Sender Configuration** タブに移動します。
    3. メールコネクタをクリックします。
    4. 省略記号アイコンをクリックし、**Edit** をクリックします。
    5. **One-click unsubscribe** で **Self Managed** をクリックします。

    ![email sendgrid.gif](/images/moengage_e0b94d.png)

    次に、以下を指定する必要があります。

    1. **One-click unsubscribe URL:** クリック 1 回でユーザーを直接配信停止するリンクを指定します。配信停止するユーザーを識別して適切に処理できるよう、JINJA を使用してこの URL にパラメータを追加してください。また、このリンクがリダイレクトや、追加の入力や確認のためのランディングページを必要とせずに、ユーザーを直接配信停止することを確認してください。\
       追加した識別子に "@" などの特殊文字が含まれている場合は、標準の URL エンコードが適用されます。詳細については、[こちら](https://developers.google.com/maps/url-encoding#common-characters-that-need-encoding)を参照してください。\
        たとえば、指定したリンクが `https://www.abc.com/unsubscribe?emailAddress={{UserAttribute['Email (Standard)']|default('email')}} ` の場合、これに加えて Moengage からのパラメータがメールヘッダーの HTTPS セクションに追加され、次のようになります。\
        `https://www.abc.com/unsubscribe?emailAddress=bob@bob.com&qmoe=abc123` ここで、

    - [**_https://www.abc.com/unsubscribe?emailAddress_**](https://www.abc.com/unsubscribe?emailAddress) は One-click unsubscribe URL に入力した URL であり、**_emailAddress_** は設定を管理するためにユーザーを識別するパラメータです。
    - [**_bob@bob.com_**](mailto:bob@bob.com) は、パラメータの値として指定した Jinja の値です
    - _qmoe_ は、ユーザーとこのリクエストの発生元のキャンペーンを識別するために MoEngage が URL に付加するパラメータです。

    <Info>
      リンクと識別子にパラメータを追加する際は、必ずデフォルト値も含めてください。たとえば、値は次のようになります。
      `https://www.abc.com/unsubscribe?emailAddress=bob@bob.com&qmoe=abc123`
    </Info>

    2. **One-click unsubscribe email:** メールヘッダーの mail-to セクションに追加するメール ID を指定します。\
        メール ID を指定すると、識別用に **User Identifier** フィールドが表示されます。MoEngage は、ISP から送信されるメールの件名をカスタマイズし、この情報を Base64 で暗号化した形式で含めます。これにより、件名を解析してデコードし、配信停止する必要のあるユーザーを安全に識別できます。\
        **User identifier** の値は、ユーザーの識別方法によって異なります。使用できる値の例を以下に示します。これらは、MoEngage で使用されるテンプレート言語である Jinja を使用して追加する必要があります。
       | **User Identifier の例** | **JINJA 形式** |
       | --- | --- |
       | ID | &#123;&#123;UserAttribute['ID']\|default('ID')&#125;&#125;|
       | Email ID |&#123;&#123;UserAttribute['Email (Standard)'] \| default('email')&#125;&#125;  |

    <Info>
      - 保存するには、ユーザー識別子の入力時に必ずデフォルト値を追加する必要があります。
      - 場合によっては、ISP が件名で送信された情報を破損させることがあります。そのため、メールの "From ID" から常にメールアドレスを確認できるメールによる設定の識別がより適した方法です。
    </Info>

    ### 受信したリクエストの処理方法

    <Info>
      処理後、これらの配信停止を MoEngage に返すことが非常に重要です。これにより、この方法で配信停止したユーザーを送信前に除外し、MoEngage が今後のメールを送信しないようにできます。MoEngage を更新しない場合、MoEngage が設定の変更を認識していないため、これらのユーザーに引き続きメールが届く可能性があります。
    </Info>

    ユーザーが List-Unsubscribe 方式で配信停止した場合は、常に以下を実行する必要があります。

    - **ISP がワンクリック URL を通じてリクエストを処理した場合:**

     1. 追加したパラメータを使用して、配信停止するユーザーを識別します。上記の例では、\_emailAddress\_parameter を使用してユーザーを識別し、処理できます。
     2. qmoe パラメータを渡して以下のパブリック API を実行し、MoEngage がユーザーのサブスクリプションステータスを更新できるようにします。
       ```text
       https://api-0x.moengage.com/v1/emailunsubscribe?qmoe=
       ```
         - API エンドポイント URL の 'X' は MoEngage のデータセンター（DC）を指します。MoEngage は各お客様を異なる DC でホストしています。こちらの DC と API エンドポイントのマッピングを参照して DC 番号（X の値）を確認し、URL の 'X' の値を置き換えてください。
         - _\<qmoe\_parameter\>_ は、前述のとおり、ユーザーとキャンペーンを識別するために MoEngage が URL に付加するパラメータです。上記の例では、_qmoe\_parameter_ は _abc123._ です。
    - **ISP が Mail-to 方式を通じてリクエストを処理した場合:**
     1. 指定した受信トレイに ISP から送信されたメールの件名を解析してユーザーを識別し、管理しているリストから配信停止します。件名の例は以下のとおりです。

     ```text wrap
     Unsubscribe | cattr:YzlhZjVkYzUtYWRkMi00MTZkLTg4OTQtNWNlZmRkYTJjNDYw-WTRv4uSIgrZTVV5fJSvAZkS2smalAXvg8qX_0qz3AXdXNRHz.AwCwAo2OsppN0DGt2qd0R4qSg-5YLB5qTvuHp.2EIBfDrKmDauXjQXySNcGHo0w__OdsmU2_LAzK1aAynsczTVn.yuaRa.4MGgjQ-lq_KXmK.l7mgq17UL1WOZsjqPOJGzcrHTW3iZYOXt2O5Ikgwk9CJgO0Hg7Z8ZO3OewvzeED8BFN4fuAwyvkCV7yPQtHTMZ_coK_Yu42TPeysvhhgr0yFlLvrXIMsEolDk64xtNx8Ie76YcE
     ```
    - 上記の件名を解析し、**_cattr:_** と**_最初のハイフン_**の間にあるサブテキストを見つける必要があります。この例では、`YzlhZjVkYzUtYWRkMi00MTZkLTg4OTQtNWNlZmRkYTJjNDYw` がそのサブテキストです。
    - 次に、これを Base64 方式でデコードして、配信停止する必要のあるユーザーを特定します。

    2. MoEngage がユーザーのサブスクリプションステータスを更新できるよう、メールを受信トレイ `unsubscribe-DC0X@moengage.com` に転送します。

    - ここで、メール ID の 'X' は MoEngage のデータセンター（DC）を指します。MoEngage は各お客様を異なる DC でホストしています。[こちら](/ja/user-guide/data/key-concepts/data-centers-in-moengage)の DC と API エンドポイントのマッピングを参照して DC 番号（X の値）を確認し、URL の 'X' の値を置き換えてください。
    - 受信トレイで受信したメールの自動転送を設定すると、より簡単に行えます。設定方法については、以下を参照してください。
      - [Yahoo](https://help.yahoo.com/kb/SLN29133.html?guccounter=1)
      - [Microsoft](https://learn.microsoft.com/en-us/microsoft-365/admin/email/configure-email-forwarding?view=o365-worldwide)
      - Gmail
  </Tab>
</Tabs>

# この方法で配信停止したユーザーの確認方法

ユーザーから配信停止のリクエストを受信するたびに、MoEngage は属性 **_source_** が **_List Unsubscribe_** の **_Email Unsubscribed_** イベントを発生させます。これは MoEngage 管理と自己管理の両方のアプローチに適用されます。ただし、自己管理のアプローチの場合は、上記の手順が正しく実行されていることを確認してください。

<Accordion title="現時点で送信しているメールがこの義務に準拠しているかどうかを確認するにはどうすればよいですか？">
  準拠しているかどうかを確認するには、Gmail の受信トレイで、送信したメールについて以下を実行します。

  1. メールで Show Original を選択します。新しいタブが開き、メールとそのヘッダーの未加工バージョンが表示されます。
  2. "List-Unsubscribe" を検索します。
  3. メールの未加工バージョンのヘッダー内にこのキーワードが見つかれば、準拠しています。

  また、メールが以下の画像のように表示される場合も準拠しています。

<Accordion title="ワンクリック配信停止の入力欄に入力する URL は HTTPS タイプである必要がありますか？">

</Accordion>

<Accordion title="入力する URL を、ユーザーが配信停止できるランディングページの URL にすることはできますか？">

<Accordion title="準拠していれば、メール本文から配信停止リンクを削除できますか？">

</Accordion>

</Accordion>
