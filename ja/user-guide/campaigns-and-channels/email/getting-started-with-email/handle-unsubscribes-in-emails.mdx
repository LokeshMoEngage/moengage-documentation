# 概要

メールを使用するマーケターは、良好なドメインレピュテーションを維持し、規制を遵守するために、非トランザクションメールに _Unsubscribe_ リンクを設ける必要があります。配信停止したユーザーには、同様の性質の今後のコミュニケーションを送信しないようにする必要があります。

<Note>
  テストキャンペーンとプレビューキャンペーンでは、ユーザープロファイルデータは変更されません。テスト送信を行っても、プロファイルの配信停止ステータス（`moe_unsubscribe`）やその他のリーチャビリティ属性は更新されません。これらのフィールドを更新するのはライブキャンペーンのみです。配信停止フローを検証するには、小規模な社内セグメントを対象にライブキャンペーンを実行してください。
</Note>

MoEngage プラットフォームは、以下の種類のサブスクリプション管理を提供することで、マーケターが上記のルールを遵守できるよう支援します。

- [グローバル配信停止](/ja/user-guide/campaigns-and-channels/email/getting-started-with-email/handle-unsubscribes-in-emails#global-unsubscribe)
- [List-Unsubscribe](/ja/user-guide/campaigns-and-channels/email/getting-started-with-email/handle-unsubscribes-in-emails#list-unsubscribe)
- [サブスクリプションカテゴリ](/ja/user-guide/campaigns-and-channels/email/getting-started-with-email/handle-unsubscribes-in-emails#subscription-categories)

# 配信停止と抑制の違い

配信停止はユーザーのアクションです。ユーザーが配信停止をクリックすると、MoEngage はそのプロファイルの標準の配信停止属性を `True` に設定します。抑制（Suppression）は、非トランザクションキャンペーンがユーザーに届かないようにするプラットフォーム側の結果であり、配信停止は抑制をトリガーする条件の 1 つにすぎません。

抑制をトリガーする条件、ブランドによる抑制の管理方法、MoEngage がネイティブの抑制リストを保持しない理由など、詳しい比較については、Suppression Updates ページの[配信停止と抑制の違い](/ja/user-guide/campaigns-and-channels/email/getting-started-with-email/suppression-updates#unsubscribe-vs-suppression)を参照してください。

# MoEngage メールにおけるサブスクリプション管理の種類

## グローバル配信停止

グローバル配信停止を使用すると、ユーザーはブランドまたはビジネスからのすべての非トランザクションメールの配信を停止できます。ユーザーがこのリンクをクリックすると、直接配信停止されるか、配信停止前に再確認を行うためのランディングページにリダイレクトされます。これはトランザクションメールや Inform 経由で送信されたメールには影響しません。これらのメールは、グローバル配信停止のステータスに関係なく引き続きユーザーに届きます。トランザクションを含むすべてのキャンペーンタイプをブロックする唯一のトリガーはバウンスです。

## List-Unsubscribe

List-Unsubscribe は、ISP が提供するワンクリックで配信停止できる方法です。メールヘッダーに含まれ、送信者のレピュテーション、送信量、エンゲージメントに応じて、メールボックスプロバイダーが受信者に表示するかどうかを決定します。以前はクライアントが従うことのできるベストプラクティスでしたが、2024 年以降は [Google と Yahoo](https://www.moengage.com/blog/upcoming-gmail-yahoo-email-deliverability-changes/) により、満たすべき必須のコンプライアンス要件となっています。

## サブスクリプションカテゴリ

サブスクリプションカテゴリを使用すると、ユーザーはコミュニケーションのカテゴリ単位で選択的に配信停止できます。たとえば、ニュースレター、製品アップデート、プロモーションのカテゴリでメールを送信しているとします。サブスクリプションカテゴリを使用すると、ユーザーは 1 つのページから、関心のあるカテゴリ・関心のないカテゴリを選択して購読または配信停止できます。

つまり、サブスクリプションカテゴリはサブスクリプション管理のオプションの方法ですが、他の 2 つはメールマーケティングにおけるすべての大量メール送信者に義務付けられています。サブスクリプションカテゴリの詳細については、[こちら](https://moengage-user-guide.mintlify.app/user-guide/campaigns-and-channels/email/getting-started-with-email/configure-subscription-categories#moengage-landing-page)をクリックしてください。

# MoEngage 管理とカスタム管理（自己管理）の違い

大まかに言うと、MoEngage ではマーケターが以下の方法でこれらを設定できます。

- **MoEngage 管理:** このオプションでは、MoEngage の機能をシームレスに使用して、MoEngage 上でユーザーのサブスクリプションを取得・更新できます。他のシステム（サードパーティツールや社内システム）がある場合は、この情報を MoEngage からそれらのシステムに転送できます。
- **自己管理、カスタム管理、またはなし:** このオプションでは、ブランド独自のユーザーサブスクリプション処理を呼び出すことができます。一般的に、ブランドが自社側でユーザーの設定を管理したい場合に使用されます。この場合、ブランドはユーザーのサブスクリプションを取得し、自社のシステムと MoEngage の両方を更新する必要があります。

  </Tab>

## サブスクリプションカテゴリ

MoEngage でサブスクリプションカテゴリを設定するには、以下の手順を実行します。

1. MoEngage ダッシュボードの左側のナビゲーションメニューで、**Settings** \> **Channel** \> **Email** に移動します。
2. Email ページで **Subscription management** タブを選択し、**Subscription categories** タブを選択します。
3. **Configure subscription categories** をクリックします。\
   MoEngage が標準で提供するランディングページを使用してサブスクリプションカテゴリを設定することも、独自のカスタムランディングページを使用して定義することもできます。詳細については、[こちら](/ja/user-guide/campaigns-and-channels/email/getting-started-with-email/configure-subscription-categories)をクリックしてください。

<Info>
  カスタムランディングページを使用している場合は、[こちら](https://www.moengage.com/docs/api/subscription-preferences/update-subscription-preferences)の API を使用して設定の変更を MoEngage に返すために必要な手順を実行してください。これにより、今後ユーザーが誤ったメールの対象となった場合に、MoEngage が必要な対応を行えます。
</Info>

# 提供されるサブスクリプションの種類に応じた MoEngage でのメール作成

## グローバル配信停止

前述のとおり、MoEngage Tracking または Sendgrid Tracking の場合、デフォルトのテキストが常にメールの末尾に追加されます。ただし、その位置はカスタマイズできます。

<Tabs>
  <Tab title="MoEngage 管理">
    - ドラッグアンドドロップエディターで、送信者設定で構成された、MoEngage を通じて配信停止をトラッキングする配信停止リンクを挿入するには、以下の手順を実行します。

    1. 配信停止リンクを挿入するテキストを選択します。
    2. テキストエディターで、**Special links** \> **Frequently used** \> **MoE Tracking Unsubscribe Link** をクリックします。

    ![Special links.gif](/images/moengage_bc282a.png)

    - **ドラッグアンドドロップエディターの使用中にカスタムの配信停止リンクを挿入するには、以下の手順を実行します。**
      1. エディターから HTML ブロックを必要な位置にドラッグアンドドロップします。
      2. 以下の HTML コードを追加します。
      ```html wrap
      <a data-msys-unsubscribe="1" href= "https://www.abc.com/unsubscribe">Unsubscribe here </a> 
      ```
      ここで、`https://www.abc.com/unsubscribe` には使用する配信停止 URL を追加する必要があります。

    <Info>
      - これを正しく機能させるには、href 属性に常にプロトコル（HTTP または HTTPS）を含める必要があります。
      - _Unsubscribe here_ のテキストは、サポートされている任意の言語の必要なテキストに置き換えることができます。
    </Info>

    <Warning>
      href はエンコードせずに貼り付けてください。リンクに MoEngage のパーソナライゼーショントークンが含まれている場合は、URL エンコードしないでください。URL エンコードすると `{{` 区切り文字が `%7B%7B` に、`$` が `%24` に置き換えられ、デコード時に Jinja が解析できない `{{$` シーケンスになります。キャンペーンを保存または送信すると、`Error in parsing jinja template format. Error unexpected char u'$' at ...` のようなエラーが発生する場合があります。トークンは、エディターに用意されているマージタグまたはトークンオプションを使用して挿入してください。詳細については、[Jinja テンプレート言語](/ja/user-guide/campaigns-and-channels/getting-started/message-personalization/jinja-templating-language#escaping)を参照してください。
    </Warning>

    **カスタム HTML エディター**

    以下の HTML コードを使用して、配信停止のテキストとリンクを任意の位置に配置します。

    ```html wrap
    <a data-msys-unsubscribe="1" href= "https://www.abc.com/unsubscribe">Unsubscribe here </a> 
    ```

    <Info>
      - さらに HTML 属性や CSS 値を追加して、見た目を整えることもできます。
      - また、リンクではなくテキストのみを変更したい場合は、同じコードに 1 つだけ小さな変更を加えます。
      - href には設定で指定した値を使用します。
    </Info>
  </Tab>
  <Tab title="Sendgrid トラッキング">
    **MoEngage 管理の Sendgrid アカウント**

    Sendgrid Tracking を使用している場合は、Sendgrid ダッシュボードで置換テキストを定義した後、そのテキストを使用できます。MoEngage 管理の Sendgrid アカウントを使用している場合、置換テキストは _\[unsubscribe\_here\]_ です。

    **カスタム管理の Sendgrid アカウント**

    独自の Sendgrid アカウントを使用している場合は、置換タグを設定できます。設定するには、以下の手順を実行します。

    1. **Sendgrid** \> **Settings** \> **Tracking** \> **Suppression Tracking** に移動します。
    2. 任意の置換タグを追加します。

    これで、メール内の任意の場所にリンクを挿入し、その値として置換タグを入力することで追加できます。

    <Info>
      - Sendgrid は置換タグが見つかったすべての箇所をリンクに置き換えるため、定義する置換タグには注意してください。
      - 置換タグは大文字と小文字が区別されます。
    </Info>
  </Tab>
  <Tab title="なしまたはカスタムトラッキング">
    前述のとおり、作成者またはマーケターが配信停止リンクを追加する必要があります。メール内の任意の場所にリンクを挿入することで追加できます。
  </Tab>
</Tabs>

## List-Unsubscribe

アプローチの種類（MoEngage 管理または自己管理）に関係なく、MoEngage はすべての非トランザクションメールのメールヘッダーに必要な情報を常に自動的に追加します。そのため、キャンペーンの作成時にカスタマイズや手動入力を行う必要はありません。

## サブスクリプションカテゴリ

### デフォルトのリンク位置

使用するランディングページの種類に関係なく、MoEngage はデフォルトで以下のテキストを使用してメールの末尾にリンクを配置します。

_Update your email preferences here to choose the category of emails you wish to receive._

送信されるメールでは、上記テキストの _here_ にランディングページのリンクがハイパーリンクとして設定されます。

### リンク位置のカスタマイズ

以下の手順を使用して、ランディングページのリンクの位置をいつでもカスタマイズできます。

<Tabs>
  <Tab title="ドラッグアンドドロップエディター ">
    ドラッグアンドドロップエディターでサブスクリプションカテゴリのランディングページのリンクを挿入するには、以下の手順を実行します。

    1. ランディングページのリンクを挿入するテキストを選択します。
    2. テキストエディターで、**Special links** \> **Frequently used** \> **Preference Management** をクリックします。

    ![email preferences link..gif](/images/moengage_5f0516.png)
  </Tab>
  <Tab title="カスタム HTML エディター">
    以下の HTML コードを使用して、配信停止のテキストとリンクを任意の位置に配置します。

    ```html wrap
    <a data-msys-managepref=”1” href= “https://api-0X.moengage.com">Manage your preference here</a>
    ```

    ここで、URL の _X_ は MoEngage のデータセンター（DC）を指します。MoEngage は各お客様を異なる DC でホストしています。[こちら](/ja/user-guide/data/key-concepts/data-centers-in-moengage)の DC と API エンドポイントのマッピングを参照して DC 番号（_X_ の値）を確認し、URL の _X_ の値を置き換えてください。
  </Tab>
</Tabs>

### グローバル配信停止リンクではなくサブスクリプションカテゴリのリンクを表示する

デフォルトでは、MoEngage は常にグローバル配信停止リンクと設定管理リンクの両方をメールの末尾に追加します。上記で定義した HTML コードを使用して、両方のリンクを任意の位置に配置できます。

ただし、グローバル配信停止リンクを非表示にしてカテゴリへのリンクのみを表示したい場合は、以下の方法で実現できます。

<Tabs>

    ここで、URL の _X_ は MoEngage のデータセンター（DC）を指します。MoEngage は各お客様を異なる DC でホストしています。[こちら](/ja/user-guide/data/key-concepts/data-centers-in-moengage)の DC と API エンドポイントのマッピングを参照して DC 番号（X の値）を確認し、URL の 'X' の値を置き換えてください。
  </Tab>
  <Tab title="カスタム HTML エディター">
    以下の HTML コードを使用して、配信停止のテキストとリンクを任意の位置に配置します。

    ```html wrap

    <div style="display: none;"><a data-msys-unsubscribe=”1” href= “https://api-0X.moengage.com">Manage your preference here</a></div>
    ```

    ここで、URL の _X_ は MoEngage のデータセンター（DC）を指します。MoEngage は各お客様を異なる DC でホストしています。[こちら](/ja/user-guide/data/key-concepts/data-centers-in-moengage)の DC と API エンドポイントのマッピングを参照して DC 番号（X の値）を確認し、URL の 'X' の値を置き換えてください。
  </Tab>
</Tabs>

# 配信停止の分析

## グローバル配信停止または List-Unsubscribe

ユーザーがメールに追加されたリンク（グローバル配信停止リンク）または ISP が提供するオプション（List-Unsubscribe オプション）を通じて配信停止すると、配信停止のトラッキングが _None_ でない場合、または[こちら](/ja/user-guide/campaigns-and-channels/email/getting-started-with-email/list-unsubscribe-email#how-to-configure-this-in-moengage)に記載されているとおりに List-Unsubscribe の処理を正しく設定している場合に、MoEngage は _Email Unsubscribed_ イベントをトリガーします。

## サブスクリプションカテゴリ

ユーザーが MoEngage から送信されたメールを通じて設定を変更すると、MoEngage システムは、キャンペーン、メールの件名、配信停止されたカテゴリなどの情報を含む _Email Subscription Category Updated_ イベントをトリガーします。

上記のイベントを通じて、配信停止または設定を変更しているユーザーを分析できます。また、これらのイベントを使用して、サブスクリプションを変更したユーザーを検索し、ターゲットにすることもできます。

<Info>
  これは、MoEngage 管理のランディングページ、およびカスタムランディングページを使用していても[こちら](https://www.moengage.com/docs/api/subscription-preferences/update-subscription-preferences)に記載されているとおりに情報を MoEngage に返しているワークスペースに適用されます。
</Info>

# サブスクリプションステータスの更新

## MoEngage からサードパーティシステムへの配信停止の更新

### 全体レベルでの配信停止

配信停止が _List-Unsubscribe_ と _Global Unsubscribe_ リンクのどちらで行われた場合でも、以下の手順を実行してステータスを渡すことができます。

1. _Email Unsubscribed_ イベントの発生時にトリガーされ、サードパーティシステムのエンドポイントに API コールを行うイベントトリガー型のコネクタキャンペーンを作成します。コネクタキャンペーンの作成の詳細については、[こちら](/ja/user-guide/campaigns-and-channels/connectors/create/create-a-connector-campaign)を参照してください。または
2. MoEngage Streams を使用して、_Email Unsubscribed_ イベントを自社のシステムに渡すことができます。MoEngage Streams の詳細については、[こちら](https://www.moengage.com/docs/api/data/moengage-streams)をクリックしてください。

### 設定の変更

新しい設定値を渡すには、以下の手順を実行します。

1. _Email Subscription Category Updated_ イベントの発生時にトリガーされ、サードパーティシステムのエンドポイントに API コールを行ってユーザーが配信停止したカテゴリを伝えるイベントトリガー型のコネクタキャンペーンを作成します。コネクタキャンペーンの作成の詳細については、[こちら](/ja/user-guide/campaigns-and-channels/connectors/create/create-a-connector-campaign)を参照してください。または
2. MoEngage Streams を使用して、_Email Subscription Category Updated_ イベントを自社のシステムに渡すことができます。MoEngage Streams の詳細については、[こちら](https://www.moengage.com/docs/api/data/moengage-streams)をクリックしてください。

### 設定の変更

#### カスタムランディングページを使用して MoEngage から送信されたキャンペーンによる設定の更新:

カスタムランディングページを使用していて、ユーザーの設定を MoEngage に反映したい場合は、以下の手順を実行します。

1. URL を解析して user\_id と cid パラメータを見つけます。
2. [こちら](https://www.moengage.com/docs/api/subscription-preferences/update-subscription-preferences)に記載されている API を呼び出します。
3. API の実行時に、保存した user\_id と cid をパラメータとして渡します。

たとえば、カスタムランディングページへのリンクが [_https://www.abc.com/managepreference_](https://www.abc.com/managepreference) の場合、ユーザーがメールからこれをクリックすると、リンクは以下のようになります。


ここで、解析して user\_id を見つけることができます。この場合は以下のとおりです。

```text wrap
7XvJW2dj3iS.rYAt4pg5ASBQtaqAMFDw9e89vZCXx_RFfN3eL0wBG008oI6cpncOQV6ESg
```

cid は以下のとおりです。

#### サードパーティシステムから MoEngage への設定の更新:

<Tabs>
  <Tab title="API によるアプローチ">
    サードパーティシステムから MoEngage にユーザーの設定を更新するには、以下の手順を実行します。

    1. サブスクリプションカテゴリを更新する [API](https://www.moengage.com/docs/api/subscription-preferences/update-subscription-preferences) を呼び出します。

      API を使用してユーザーの設定を更新する際、MoEngage でアーカイブまたは無効化されているカテゴリの値を受信した場合、そのカテゴリの設定は更新されません。
    </Info>

    CSV アップロードを使用してユーザーのサブスクリプションカテゴリをアップロードするには、以下の手順を実行します。

    1. MoEngage ダッシュボードの左側のナビゲーションメニューで **Segment** をクリックし、**User Imports** をクリックします。
    2. User Imports ページで、右上の **Import users** をクリックします。 <img src="/images/moengage_be4392.png" />
    3. **Import name** ボックスに、インポートの一意の名前を入力します。
    4. **Select user type** で **Registered users** を選択します。
    5. **Select file** で **upload from the computer** をクリックして CSV ファイルをアップロードします。CSV ファイルをアップロードする際は、以下の点に従ってください。アップロードする CSV ファイルでは:
       1. 1 つの列を ID 用に確保します。これらは顧客を一意に識別するために使用する顧客 ID です。たとえば、顧客のメール ID などです。

    ![](/images/moengage_23a756.png)

    14. ユーザーインポートは、_Successful_ の同期ステータスとともに User Imports ページに一覧表示されます。

  </Tab>

## MoEngage および送信者でのユーザーの再購読

以前に MoEngage プラットフォームと Sendgrid プラットフォームで配信停止したユーザーを、両方で同時に再購読させたい場合があります。MoEngage Resubscribe API は、MoEngage 上のユーザーの配信停止フラグを "false" にリセットし、SendGrid を呼び出して（配信停止したユーザーに関連付けられた）メールアドレスを抑制リストから削除します。

これを行うには、以下の手順を実行します。

1. 再購読させるメール ID のリストをまとめます。
2. [こちら](https://www.moengage.com/docs/api/resubscribe/bulk-resubscribe-users)に記載されているとおりに MoEngage Resubscribe API を呼び出します。
3. _update\_esp=true_ を設定し、メール ID のリストを _recipients key_ に _array_ として渡します。

<Warning>
  MoEngage またはメール送信者でユーザーを再購読させても、抑制条件が解除されるだけで、同意が回復するわけではありません。再購読したユーザーへの送信を再開する前に、Suppression Updates ページの[コンプライアンスに関する注意事項](/ja/user-guide/campaigns-and-channels/email/getting-started-with-email/suppression-updates#unsubscribe-vs-suppression)を参照してください。
</Warning>

# よくある質問

<Accordion title="配信停止リンクをクリックした後にユーザーが遷移するランディングページをカスタマイズできますか？">
  はい、配信停止リンクをクリックした後にユーザーが遷移するランディングページはカスタマイズできます。このオプションは **Sender Configuration** で利用できます。ユーザーが配信停止リンクをクリックすると、配信停止された後にこのランディングページに移動し、配信停止の理由を確認できます。
</Accordion>

<Accordion title="特に PII トークン化が有効になっている場合、送信者と MoEngage はどのように連携して、配信停止やメール送信を可能にするカスタム ID にどのメール ID が関連付けられているかを把握するのですか？">
  この連携には以下のステップが含まれます。

  - MoEngage はコンテンツ API を呼び出し、メール ID の代わりに MoEngage に保存されているトークンを渡します。
  - レスポンスとして、クライアントシステムがメール ID を返します。
  - MoEngage はペイロードを生成し、送信者にリクエストを送信します。
  - この送信リクエストを記録するために、メール ID は暗号化されて保存されます。生のメール ID が MoEngage に保存されることはありません。
</Accordion>
