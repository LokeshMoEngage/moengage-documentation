この記事では、メール設定の各タブについて説明し、メールチャネルを設定する手順を解説します。メール設定にアクセスするには、以下の手順に従ってください。

1. **MoEngage Dashboard** にログインします。
2. 左側のパネルで **Settings** に移動します。
3. **Channels** の下にある **Email** をクリックします。
4. メール設定ページには、次のタブがあります。
   - [Overview](/ja/user-guide/campaigns-and-channels/email/getting-started-with-email/configure-email-channel#overview-tab)
   - [Sender Configuration](/ja/user-guide/campaigns-and-channels/email/getting-started-with-email/configure-email-channel#sender-configuration-tab)
   - [General Settings](/ja/user-guide/campaigns-and-channels/email/getting-started-with-email/configure-email-channel#general-settings-tab)
   - [Subscription Management](/ja/user-guide/campaigns-and-channels/email/getting-started-with-email/configure-email-channel#subscription-management-tab)
   - [PII Tokenization](/ja/user-guide/campaigns-and-channels/email/getting-started-with-email/configure-email-channel#pii-tokenization)
   - [Dynamic Sender Routing](/ja/user-guide/campaigns-and-channels/email/getting-started-with-email/configure-email-channel#dynamic-sender-routing)

<Note>
  **前提条件**

  [Portfolio](/ja/user-guide/settings/account/portfolio/portfolio) が有効なワークスペースでは、メール設定を行う前に、MoEngage Portfolio に少なくとも 1 つのプロジェクトを追加する必要があります。プロジェクトの追加について詳しくは、[Portfolio](/ja/user-guide/settings/account/portfolio/portfolio#add-project) を参照してください。
</Note>

<Info>
  [Portfolio](/ja/user-guide/settings/account/portfolio/portfolio) が有効なワークスペースで、ポートフォリオに複数のプロジェクトがある場合、メール設定ページの上部にドロップダウンリストが表示されます。ドロップダウンリストから設定するプロジェクトを選択すると、関連するすべての設定が自動的に読み込まれます。プロジェクトが 1 つだけのポートフォリオでは、すべての設定がそのプロジェクトに追加されます。

  メール設定の Dynamic Sender Routing は、プロジェクト固有の設定をサポートしていません。
</Info>

### Custom Connector の設定

MoEngage は、メールキャンペーンを送信するために任意の SMTP コネクタと統合できます。コネクタを設定し、[配信停止の仕組み](/ja/user-guide/campaigns-and-channels/email/getting-started-with-email/handle-unsubscribes-in-emails)をセットアップする必要があります。また、SMTP コネクタが必要な形式(この記事の後半で説明)でバウンスと苦情の詳細を送信できる場合は、オプションでそれらを追跡することもできます。

#### Custom SMTP 設定の構成

- **Sender Name:** 送信者の名前を入力します。
- **SMTP Host Name:** 使用している SMTP コネクタサービスの IP アドレスまたはサーバー名
- **SMTP Port:** 接続先となるコネクタサービスの SMTP ポート番号です。一部のホスティング会社が設定しているレート制限を回避するため、ポート 25 ではなくポート 587 を使用することをお勧めします。
- **SMTP Protocol:** コネクタがサポートするプロトコルプレフィックス(SSL/TLS)を選択できます。
- **SMTP Authentication:** SMTP コネクタが接続の確立に認証を必要とする場合は、ここで **ON** を選択します。次に、ユーザー名とパスワードに SMTP 認証情報を入力します。<img src="/images/moengage_9da22d.png" alt="Screenshot 2024-07-02 at 7.03.22 PM.png" />

#### Custom Unsubscribe 設定の構成

- **MoEngage Tracking** は、MoEngage の配信停止ページの URL をメールのフッターとして追加します - "If you'd like to unsubscribe and stop receiving these emails click here"。<br />デフォルトでは、MoEngage は顧客を標準のランディングページにリダイレクトします。そこで利用できるオプションは再購読のみです。配信停止の理由を収集するなどの目的で顧客をカスタムのランディングページに誘導したい場合は、以下に示すように、Unsubscribe Page URL に独自のランディングページへのリンクを設定できます。<br />[https://api-0X.moengage.com/v1/emailresubscribe](https://api-01.moengage.com/v1/emailresubscribe?_gl=1*1xg8h4k*_ga*MTA1OTk1Mzg0MS4xNzIwNDE4MzEw*_ga_161P72P6V0*MTcyMDU4NzE3MS40LjEuMTcyMDYwNDQ5Mi4wLjAuMA..)
- MoEngage は顧客ごとに異なるデータセンターでホストしています。データセンター番号(X の値)は、データセンターと API エンドポイントの対応表を[こちら](/ja/user-guide/data/key-concepts/data-centers-in-moengage)で確認してください。
- **None** を選択すると、MoEngage はメールキャンペーンに配信停止リンクを含めません。この場合、メールコンテンツの作成時に配信停止リンクを含める責任はお客様にあります。プロモーションキャンペーンで配信停止リンクを含めない場合、スパムと判定される可能性が高くなります。<img src="/images/moengage_7a090a.png" alt="none.png" />

詳しくは、[メールでの配信停止の処理](/ja/user-guide/campaigns-and-channels/email/getting-started-with-email/handle-unsubscribes-in-emails)を参照してください。

#### List Unsubscribe Email の設定

- **MoEngage Managed** オプションを選択すると、MoEngage はすべての非トランザクションメールのヘッダーに独自の mail-to および https URL を含めます。<img alt="配信停止設定.png" src="/images/moengage_fea7ec.png" />
- **Self Managed** オプションを選択した場合は、**One-click unsubscribe URL** と **List unsubscribe email** を入力します。MoEngage はこれらをすべての非トランザクションメールのヘッダーの mail-to および https URL に含めます。<img src="/images/moengage_83e1f0.png" alt="Screenshot 2024-07-03 at 10.58.54 AM.png" /> 詳しくは、[List-Unsubscribe Email](/ja/user-guide/campaigns-and-channels/email/getting-started-with-email/list-unsubscribe-email) を参照してください。

#### Custom Bounce and Complaint 設定の構成

- **Bounce & Complaints Tracking:** この URL は ESP のダッシュボードで設定する必要があります。ESP は配信、バウンス、スパム苦情などのイベントをこの URL に送信し、MoEngage はそれを取り込んで対応するキャンペーンの統計を更新します。MoEngage は、**Bounces & Complaint Tracking (Callback URL)** フィールドに記載された URL への POST 呼び出しで、以下の形式でこの情報を受け取ります。<img src="/images/moengage_baa47f.png" alt="バウンス.png" />
- 以下のようにコールバック URL を追加します: [https://api-0X.moengage.com/v1/](https://api-01.moengage.com/v1/emailresubscribe)[emailbounceendpoint/`<>`](https://api-0X.moengage.com/v1/emailbounceendpoint/`<>`) MoEngage は顧客ごとに異なるデータセンターでホストしています。データセンター番号(X の値)は、データセンターと API エンドポイントの対応表を[こちら](/ja/user-guide/data/key-concepts/data-centers-in-moengage)で確認してください。

<Info>
  このコールバックには Campaign ID が含まれないため、Custom SMTP Connector の場合、MoEngage はキャンペーン分析にバウンスと苦情の詳細を表示しません。
</Info>

この API は POST リクエストのみをサポートしています。

```json JSON
[
{
"event": "hard_bounce",
"data": [
  {
   "email":"abc@moengage.com"
  },
  {
   "email":"bcd@moengage.com"
  }
 ]
}
]
```

| JSON パラメータ | データ型 | 必須 | 説明 |
| --- | --- | --- | --- |
| event | String | はい | このフィールドは配信コールバックイベントを示します。サポートされる値: <ul><li>hard\_bounce</li><li>soft\_bounce</li><li>spam</li></ul> <br />**注**: このフィールドは大文字と小文字を区別します。リクエストで値を渡す際は、例と同じ大文字/小文字を使用してください。 |
| data | Array | はい | このフィールドにはユーザーのデータが含まれます。ここでのデータはユーザーのメール ID です。 |

これでコネクタの設定は完了です。**Save** ボタンをクリックして、これらの設定(認証情報などを含む)をテストし保存できます。その後、**General Settings** で **Custom SMTP** をデフォルトのコネクタとして選択できます。

## General Settings タブ

新しいメールキャンペーンを作成する際は、**General Settings** の設定がデフォルトとして使用されます。

### デフォルト送信者の設定

デフォルトに設定されている送信者(MoEngage の送信者または MoEngage 以外の送信者のいずれか)は、**Set a** **Default Sender** フィールドの下に表示されます。
   <img src="/images/set_a_default_sender.png" alt="set_a_default_sender.png" />
### ユーザーのメールアドレスを保存するユーザー属性

**User attribute that stores user's email address** フィールドに **Email (Standard).** を追加します。これはメール属性に対する MoEngage の標準属性名で、名前は MoEngage が提供し、値はクライアントが提供します。
   - 正しいコネクタ設定で標準属性から Email を選択すると、このメールアドレスに対してグローバルなオプトアウトが追跡されます。
       <img src="/images/user_attribute_that_stores_email_address.png" alt="user_attribute_that_stores_email_address.png" />

### 同じメールアドレスを持つユーザーのサブスクリプションを更新する
 
 1 人の人物が、同じワークスペース内に複数のユーザープロファイルを持つ場合があります。これは通常、データが異なるチャネルから、または異なるタイミングで取り込まれた場合に発生し、同じメールアドレスを共有しているにもかかわらず別々のプロファイルが作成されます。

これはキャンペーンの配信には影響しません。MoEngage の送信フローはメールアドレスで受信者を重複排除するため、複数のプロファイルを持つ人物でも、特定のキャンペーンを受け取るのは 1 通のみです。

 ただし、これはコンプライアンスに影響します。配信停止、バウンス、苦情のステータスなどの属性は個々のプロファイルレベルで管理され、プロファイル間で共有されません。ある人物が配信を停止した際に、その人物のプロファイルの 1 つだけが対象となっていた場合、そのプロファイルのみが配信停止としてマークされます。その人物の残りのプロファイルは今後のキャンペーンの対象のままとなり、配信停止後にその人物がメールを受け取るという、コンプライアンスに違反する結果になる可能性があります。この設定はそのギャップに対処します。
        <img src="/images/update_subscription_for_users.png" alt="update_subscription_for_users.png" />
 - **有効な場合:** 配信停止など、ユーザーに対するサブスクリプション関連の更新があると、MoEngage はワークスペース内で同じメールアドレスを持つ他のすべてのプロファイルを特定し、それぞれに同じ更新を適用します。
 - **無効な場合:**
  - 一意の ID が指定されている場合、MoEngage はその一意の ID に一致する単一のプロファイルのみを更新します。
  - メール ID が指定されている場合、MoEngage はメールでユーザーを検索しようとします。ただし、複数のプロファイルが同じメールアドレスを共有している場合、一意の識別子がないためリクエストは失敗し、そのエントリは **Unprocessed** としてマークされます。
 詳しくは、[Suppression Updates](/ja/user-guide/campaigns-and-channels/email/getting-started-with-email/suppression-updates) を参照してください。
### 開封トラッキングの同意

メールの開封トラッキングピクセルは、メール本文に埋め込まれた 1 ピクセルの透明な画像です。受信者がメールを開くと、メールクライアントがバックグラウンドでこの画像を読み込み、開封が MoEngage に報告されます。これが開封率トラッキングの仕組みです。

規制当局が開封トラッキングに受信者の同意を求めている国では、MoEngage は受信者が明示的に同意した場合にのみピクセルを追加し、受信者がいつでも簡単にオプトアウトできる方法を提供します。

**Open tracking consent** 設定を使用すると、トラッキングピクセルを受け取る受信者を制御でき、残りのオーディエンスのトラッキングは変更されません。この設定は、開封トラッキングの同意が必要な地域(例: フランス/イタリア)の受信者にメールを送信する場合にのみ関係するため、デフォルトでは無効になっています。オーディエンスに該当しない場合は、有効にする必要はありません。

<img src="/images/open_tracking_consent.png" alt="open_tracking_consent.png" />

- **Enabled**: このトグルをオンにすると、受信者の同意と以下の設定フィールドに基づいて、メールに開封トラッキングピクセルを含めるか除外するかを決定します。オフ(デフォルト)の場合、同意チェックは適用されず、通常どおりすべての受信者に開封トラッキングピクセルが含まれます。
    - **Country attribute**: 各受信者の国を保存するユーザー属性を選択します。**string** 属性のみがサポートされ、複数の値を保存する属性は使用できません。国の照合は完全一致で、大文字と小文字は区別されません。そのため、属性値が **Regulated countries** で設定した国名と正確に一致するようにしてください(例: "FR" ではなく "France")。
    - **Regulated countries**: 開封トラッキングの同意が必要な国を選択します。
      <Info>
        - 特定の国の代わりに **Any** を選択できます。**Any** を選択すると、他の国を併せて追加することはできません。MoEngage は実際の国に関係なくすべての受信者の同意属性を確認し、受信者が明示的にオプトインしていない限り開封トラッキングピクセルは含まれず、同意リンクは常に含まれます。
        - 他の国が選択されている場合、**Any** は選択できません。
        - 受信者の国データが設定された規制対象国と一致しないシナリオには、次の 2 つがあります。
          - 国属性に値があるが、どの規制対象国とも一致しない場合。たとえば、受信者の国属性が "India" に設定されており、規制対象国のリストにフランスとイタリアが含まれている場合、この受信者は規制の対象外となるため、トラッキングピクセルはメールに含まれます。
          - 受信者の国属性がまったく設定されていない場合は、**For recipients with no country data** 設定が適用され、常にトラッキングピクセルを含めるか、受信者の同意値に基づいて含める/除外するかを選択できます。
      </Info>
      <Warning>
        オーディエンスの国属性は、常に設定され正確な状態に保ってください。MoEngage は提供された値に基づいてトラッキングを判断します。このデータが欠落している、古い、または不正確な場合、同意したユーザーをトラッキングできず、エンゲージメントデータを把握できなくなる可能性があります。
      </Warning>
    - **For recipients with no country data:** 国属性が設定されていない受信者に対するトラッキングピクセルの扱いを選択します。次の 2 つのオプションがあります。
      - **Always include tracking pixel**: MoEngage は、このようなすべてのユーザーに対して常に開封トラッキングピクセルを含めます。
      - **Use consent attribute:** 受信者の開封トラッキング同意属性に基づいて、トラッキングピクセルを含めるか除外するかが決まります。この属性には次の 2 つの値があります。
          - True: トラッキングピクセルがメールに含まれ、通常どおりプロファイルに対して開封が追跡されます。
          - False または値なし: その受信者のメールにはトラッキングピクセルが含まれません。
          この属性がトラッキングをどのように制御するかについて詳しくは、[同意属性と開封トラッキングピクセル](/ja/user-guide/campaigns-and-channels/email/getting-started-with-email/consent-attribute-and-open-tracking-pixel)を参照してください。

   </Info>

### オプトイン管理
   オプトイン管理は、メールによるコミュニケーションを送信するためのユーザーの許可を取得・管理するプロセスです。メールを送信するための同意を得ることと、それらのメールの受信に関するユーザーの選択を処理することが含まれます。詳しくは、[オプトイン管理](/ja/user-guide/campaigns-and-channels/email/getting-started-with-email/opt-in-management)を参照してください。\
   **Single opt-in** と **Double opt-in (Recommended)** は、オプトイン管理の 2 つのアプローチであり、異なるレベルのユーザー同意を表します。
   - **Single Opt-in**: デフォルトでは、MoEngage の新しいユーザープロファイルはすべてシングルオプトイン方式で作成されます。詳しくは、[シングルオプトイン](/ja/user-guide/campaigns-and-channels/email/getting-started-with-email/opt-in-management#single-opt-in)を参照してください。
   - **Double Opt-in (Recommended)**: すべての新しいユーザープロファイルは、最初はオプトアウトの状態です。これらのユーザーは、同意を求めるメールで確認を行った後にのみダブルオプトインとみなされます。このプロセスは既存のユーザーには影響しないことに注意してください。\
     MoEngage ワークスペースでダブルオプトインの運用を開始するには、**Double opt-in (Recommended)** をクリックして **Save** をクリックします。詳しくは、[ダブルオプトイン](/ja/user-guide/campaigns-and-channels/email/getting-started-with-email/opt-in-management#double-opt-in)を参照してください。\
     ダブルオプトイン方式に移行する際は、ワークスペースで Inform と Landing Page のどちらが有効になっているかに基づいて、手順を実施してください。これらの手順について詳しくは、[MoEngage でのダブルオプトインの設定](/ja/user-guide/campaigns-and-channels/email/getting-started-with-email/opt-in-management#double-opt-in-in-moengage)を参照してください。<img src="/images/moengage_9a40f9.png" alt="Screenshot 2025-04-02 at 4.43.20 PM.png" />

### Suppression Updates

   Suppression Updates は、グローバルなメールサブスクリプションリストを管理してバウンス、配信停止、苦情を制御し、コンプライアンスと送信者レピュテーションを確保します。詳しくは、[Suppression Updates](/ja/user-guide/campaigns-and-channels/email/getting-started-with-email/suppression-updates) を参照してください。サブスクリプション更新用の CSV ファイルをアップロードするには、次の手順を実行します。

      <Frame>
        ![Suppressionmanagement1](/images/suppressionmanagement1.png)
      </Frame>
   4. **Update subscriptions** ページで、**Subscription update file** をアップロードします。
      <Frame>
        ![Screenshot2026 01 19at1 45 46PM](/images/Screenshot2026-01-19at1.45.46PM.png)
      </Frame>
   5. **Submit** をクリックします。送信後、ファイルが処理されるとメール通知が届き、ダウンロードアイコンがアクティブになります。**注**: ファイルは 7 日間ダウンロード可能で、その後削除されます。
   6. 送信後、アップロードされたファイルは、下の画像のように **Update history** セクションに一覧表示されます。
      <Frame>
        ![Subscriptionmanagement Updateslistview(1)](/images/SubscriptionmanagementUpdateslistview\(1\).png)
      </Frame>
      **Update History**
      - アップロードされたファイルには、次のステータスがあります。
        - **Successful**: このステータスは、MoEngage がアップロードされたファイル内のすべてのレコードをエラーなく正常に処理したことを示します。
        - **Partially successful**: ファイルは受け付けられましたが、その中の特定の行を処理できませんでした。これは次の場合に発生します。
          - 個々のレコードが検証に失敗した場合。
          - 重複エントリなどのロジックにより、レコードが Unprocessed(スキップ)としてマークされた場合。**注**: これらのレコードの具体的なエラー詳細を確認するには、処理済みファイルをダウンロードする必要があります。
        - **Failed**: このステータスは、MoEngage がファイル自体を処理できなかったこと(例: 不正な形式やファイルレベルのエラーによるもの)を示します。レコードは処理されていません。
      - ファイルの **Status** は、次の検証ロジックに基づいて表示されます。
        - CSV ファイルに重複エントリが含まれている場合、MoEngage は最後のエントリのみを処理し、すべての重複をスキップします。この場合、**Update history** セクションには **Partially Successful** のステータスが表示され、スキップされたエントリは処理済み CSV ファイルで **Unprocessed** としてマークされます。
        - _Unsubscribe_、_Spam_、_Bounce_ のエントリがユーザーのプロファイルの現在の値と一致する場合、MoEngage はそのエントリの処理をスキップします。**Update History** セクションには **Partially Successful** のステータスが表示され、これらのエントリは処理済み CSV ファイルで Unprocessed としてマークされます。
        - **メールに基づく配信停止(有効)**: MoEngage はメールアドレスを一意の識別子として扱います。アップロードで MoE ID と Email ID のどちらが使用されたかに関係なく、指定されたメールに関連付けられているすべてのユーザープロファイルを更新します。
        - **メールに基づく配信停止(無効)**: システムは特定のユーザープロファイルを一意の識別子として扱います。
          - MoEngage ID が指定されている場合: システムはその一意の ID に一致する単一のプロファイルのみを更新します。
          - メール ID が指定されている場合: システムはメールでユーザーを検索しようとします。ただし、複数のプロファイルが同じメールアドレスを共有している場合、一意の識別子がないためリクエストは失敗し、そのエントリは **Unprocessed** としてマークされます。

## 配信コールバック

キャンペーン分析ページで配信統計を表示するには、以下の定義に従ってコールバックを送信する必要があります。

これはカスタム SMTP コネクタには適用されません

- MoE-API は Settings ダッシュボードに表示されます。この API は POST リクエストのみをサポートしています。
- エンドポイントには認証の仕組みはありません。
- API リクエストの推奨タイムアウトは 5 秒です。
- _user\_id_ は、Email Sending API ペイロードの _custom\_args_ パラメータから取得する必要があります。
- event では各ケースを渡すことができます。値は大文字と小文字を区別することに注意してください。

以下はそのサンプルペイロードです。

```json JSON
[
 {
  "event": "hard_bounce",
  "cid": "MOE_CampaignID",
  "data":[
      {
       "email":"encrypted_email_id1",
       "user_id":"MOE_USER_ID"
     },
     {
       "email":"encrypted_email_id2",
       "user_id":"MOE_USER_ID"
     }
   ]
  }
]
```

| JSON パラメータ | データ型 | 必須 | 説明 |
| --- | --- | --- | --- |
| event | String | はい | このフィールドは配信コールバックイベントを示します。サポートされる値: <ul><li>delivered</li><li>hard\_bounce</li><li>soft\_bounce</li><li>spam   <br />**注**: このフィールドは大文字と小文字を区別します。リクエストで値を渡す際は、例と同じ大文字/小文字を使用してください。</li></ul> |
| cid | String | はい | このフィールドは、MoEngage でキャンペーンを識別するために使用される一意の識別子を示します。 |
| data | JSON Object | はい | このフィールドにはユーザーのデータが含まれます。詳しくは、[Data JSON Object](/ja/user-guide/campaigns-and-channels/email/getting-started-with-email/configure-email-channel#data-json-object) を参照してください。 |

#### Data JSON Object

data JSON オブジェクトには、次の内容が含まれます。

| JSON パラメータ | データ型 | 必須 | 説明 |
| --- | --- | --- | --- |
| email | String | はい | このフィールドはユーザーのメール ID を示します。 |
| user\_id | String | はい | このフィールドは、MoEngage でユーザーを識別するために使用される一意の識別子を示します。 |
