# 概要

マーケターにとって、適切なオプトイン管理はオーディエンスとの信頼関係を築き、規制を遵守するうえで非常に重要です。オプトイン管理とは、主にメールを通じたコミュニケーションについて、ユーザーの同意を取得し管理するための取り組みを指します。これには次の 2 つの重要なアクションが含まれます。

- メールコミュニケーションについてユーザーから明示的な同意を取得する。
- 受信者が受け取るメールコミュニケーションを自身で管理できるようにする。

効果的かつ規制に準拠したメールマーケティングを行うには、これらのオプトインの取り組みを理解することが不可欠です。これらの原則を実践できるよう、MoEngage では次のオプトイン方式を提供しています。

- [シングルオプトイン](/ja/user-guide/campaigns-and-channels/email/getting-started-with-email/opt-in-management#single-opt-in)
- [ダブルオプトイン](/ja/user-guide/campaigns-and-channels/email/getting-started-with-email/opt-in-management#double-opt-in)

# シングルオプトイン

シングルオプトインは、ユーザーがメールアドレスを入力した直後（通常はウェブサイトのサインアップ時）にコミュニケーションの受信登録が完了するメール購読方式です。この方式では、サインアップ時にメールアドレスを入力したことをもって、ユーザーがコミュニケーションの受信に暗黙的に同意したものとみなします。

デフォルトでは、ダッシュボードでユーザープロファイルが作成されるたびに、MoEngage はシングルオプトイン方式を適用します。MoEngage は、メール ID を提供したユーザーはメールを受信する資格があるものとみなします。この方式は、即時の同意を前提として、サインアップのしやすさを優先します。

この方式は、インドを含む東南アジア地域で一般的に使用されています。一方、ヨーロッパの規制では、トランザクションメールを例外として、マーケティングコミュニケーションには明示的な確認が求められることがよくあります。

<Info>
  - シングルオプトインは、同意があるという前提で動作します。
  - シングルオプトインはシンプルですが、エンゲージメントの低い購読者や、誤って入力されたメールアドレスが含まれることがあります。
  - 一部の地域の規制では、より質の高いエンゲージメントを目指し、[ダブルオプトイン](/ja/user-guide/campaigns-and-channels/email/getting-started-with-email/opt-in-management#double-opt-in)の重要性が強調されています。
</Info>

# ダブルオプトイン

ダブルオプトインは、サインアップ時に最初にメールアドレスを入力した後、ユーザーが購読を確認するための追加ステップを行う必要がある購読方式です。通常は、入力したアドレスに送信されたメール内の確認リンクをクリックします。この確認が完了して初めて、ユーザーはプロモーションメールの受信登録が完了します。この方式は、追加の確認ステップによって購読者の検証とエンゲージメントを優先します。

ダブルオプトインには次のようなメリットがあります。

- **より質の高いメールリスト**: ダブルオプトインにより、購読者が本当に関心を持っていることを確認できるため、エンゲージメントの高いユーザーのリストが得られます。これにより、開封率、クリック率、およびキャンペーン全体のパフォーマンスが向上する可能性があります。
- **スパム報告の削減**: 明示的な確認を求めることで、ユーザーがメールをスパムとしてマークする可能性が大幅に低下します。これにより送信者のレピュテーションが保護され、メールの到達率が向上します。
- **到達率の向上**: メールプロバイダーは、ダブルオプトインを正当なメール運用の証とみなします。これにより到達率が向上し、メールが意図した受信者の受信トレイに確実に届くようになります。
- **メールアドレスの正確性の向上**: ダブルオプトインにより、収集したメールアドレスが有効で正しく入力されていることを確認できます。これにより、入力ミスや偽のアドレスによるバウンス率が低下します。
- **送信者レピュテーションの向上**: 関心を確認済みのエンゲージメントの高い購読者にメールを送信することで、メールプロバイダーからの送信者レピュテーションが向上します。良好な送信者レピュテーションは、メールの到達率にとって非常に重要です。

## MoEngage のダブルオプトイン

ユーザープロファイルが作成されるたびに、MoEngage は **Email** **Opt-in Status** 属性を使用して、ユーザーがダブルオプトインの確認を行ったかどうかを追跡します。この属性には次の値があります。

- **Optin pending**: ユーザーがまだメールコミュニケーションの受信に同意していないことを示します。また、Email Opt-in Status 属性を持たない MoEngage のユーザープロファイルは、値が _Optin pending_ のユーザーとして扱われます。
- **Double opted in**: ユーザーがメールコミュニケーションの受信に明示的に同意したことを示します。
- **Opted out**: ユーザーがメールコミュニケーションの受信を購読解除したことを示します。

### Email Opt-in Status の更新方法

ダブルオプトインを有効にしても、既存または新規のユーザープロファイルに対して **Email Opt-in Status** 属性が自動的に作成または入力されることは**ありません**。この属性は、MoEngage がそのユーザーについて明示的なオプトインステータスの更新を受信した場合にのみ作成・更新されます。更新は、[Opt-in Management API](https://www.moengage.com/docs/api/opt-in-management/update-user-email-opt-in-preferences)、同意を求めるメールへのユーザーの操作、CSV インポート、ユーザープロファイルでの購読関連の更新など、サポートされているいずれかの方法で行われます。

つまり、ダブルオプトインを有効にした後、まだオプトインステータスの更新を受け取っていないユーザープロファイルを確認すると、**Email Opt-in Status** 属性はプロファイルに表示されません。

<Info>
  **Email Opt-in Status** 属性を持たないユーザープロファイルは、値が *Optin pending* のユーザーと同様に扱われます。
</Info>

### Email Opt-in Status がメール配信に与える影響

メールを送信する前に、システムは **Email Opt-in Status** ユーザー属性を確認し、ユーザーがメールを受信する資格があるかどうかを判断します。

* ユーザーにこの属性が存在し、その値がユーザーのオプトイン済みを示している（つまり値が *Double opted in* である）場合、メールが送信されます。
* 属性が存在しない場合、または他の値（*Optin pending* や *Opted out* など）である場合、ユーザーはメールを受信しません。

<Info>
  この確認は、メールキャンペーンで **Send only to double-opted-in users** トグルが有効になっている場合に適用されます。詳細については、[ダブルオプトインを使用したエンゲージメントとリーチのバランス](/ja/user-guide/campaigns-and-channels/email/getting-started-with-email/opt-in-management#balance-engagement-and-reachability-using-double-opt-in)を参照してください。
</Info>

次のシナリオでは、ユーザーの操作がオプトインステータスにどのように影響するかを説明します。

### シナリオ 1: ダブルオプトイン導入後に新規ユーザーがサインアップした場合

John がウェブサイトにサインアップしました。サインアップ時に次の処理が行われます。

- MoEngage がワークスペースに John のプロファイルを作成します。
- MoEngage が John のオプトインステータスを _Optin pending_ に設定します。
- John に同意を求めるメールを送信し、設定を尋ねます。

その後、John は次の行動をとる可能性があります。

- **同意を求めるメールに応答しない**: John は同意していないため、John の **Email Opt-in Status** は _Optin pending_ のままです。
- **同意を求めるメールを操作する**: John は確認リンクをクリックし、同意を提供するとともに購読カテゴリの設定を選択します。MoEngage は John の **Email Opt-in Status** を _Double opted in_ に変更します。
- **同意後に設定を変更する**: MoEngage は設定を適宜更新し、**Email Opt-in Status** は _Double opted in_ のままです。
- **メールの購読を解除する**: John の **Email Opt-in Status** は _Opted out_ に変更されます。

### シナリオ 2: ダブルオプトイン導入前にサインアップした既存ユーザーの場合

David はウェブサイトの既存ユーザーです。ウェブサイトがダブルオプトインを導入する前から存在していました。このようなユーザーの場合:

- David はまだ設定を共有していないため、MoEngage は David のオプトインステータスを _Optin pending_ に設定します。
- John に同意を求めるメールを送信し、設定を尋ねます。
- David は、以前に公開されたキャンペーン設定に基づいて、他のプロモーションメールを受信できます。

その後、David は次の行動をとる可能性があります。

- **同意を求めるメールに応答しない**: David は同意していないため、David の **Email Opt-in Status** は _Optin pending_ のままです。
- **同意を求めるメールを操作する**: David は確認リンクをクリックし、同意を提供するとともに購読カテゴリの設定を選択します。MoEngage は David の **Email Opt-in Status** を _Double opted in_ に変更します。
- **設定を変更する:**
  - **同意後**: David は同意を提供した後に設定を変更します。MoEngage は購読カテゴリの設定を適宜更新し、**Email Opt-in Status** は _Double opted in_ のままです。
  - **古いメールを操作する**: David は古いメールを操作して設定を変更します。MoEngage は購読カテゴリの設定を適宜更新し、**Email Opt-in Status** は _Optin pending_ から _Double opted in_ に変更されます。
- **メールの購読を解除する:**
  - **同意後**: David は同意を提供した後にメールの購読を解除しました。David の **Email Opt-in Status** は _Double opted in_ から _Opted out_ に変更されます。
  - **古いメールを操作する**: David は古いメールを操作してメールの購読を解除します。MoEngage は David の購読を解除し、**Email Opt-in Status** は _Optin pending_ から _Opted out_ に変更されます。

<Info>
  メールやランディングページを通じてオプトインステータスが変更されるたびに、これらすべてのアクションを追跡するために _Email Opt-in Status Updated_ という名前のイベントがトリガーされます。
</Info>

# MoEngage でダブルオプトインを設定する

ダブルオプトイン方式には、[メール設定](/ja/user-guide/campaigns-and-channels/email/getting-started-with-email/configure-email-channel)の **Subscription Management** \> **Opt-in Management** タブからアクセスできます。

ダブルオプトイン方式に移行するには、ワークスペースで Inform または Landing Page が有効になっているかどうかに応じて、次の手順を実施してください。

    - MoEngage の Track User Data API をトリガーしてオプトインステータスを更新します。詳細については、[Track User](https://www.moengage.com/docs/api/user/track-user) を参照してください。

      <Warning>
        **Email Opt-in Status に Track User API を使用する場合の重要な考慮事項:**

        Track User API は、ユーザー属性を作成または更新するために設計された汎用 API です。1 回の呼び出しで複数の属性を更新できるため、読みやすい名前を想定しており、**Email Opt-in Status** などの特定の属性に対して厳密な検証を行いません。そのため、この API は有効なオプトインステータスではない値もエラーを返さずに受け入れる場合があり、予期しない動作につながる可能性があります。

        Track User API を使用して Email Opt-in Status を更新する場合は、値をプレーンテキストのフロントエンド名として渡してください。
        * `Optin pending`
        * `Double opted in`
        * `Opted out`

        これらの値では大文字と小文字は区別されません。

        **推奨される代替手段:** **Email Opt-in Status** の更新、特に新規ユーザーの場合は、代わりに [Opt-in Management API](https://www.moengage.com/docs/api/opt-in-management/update-user-email-opt-in-preferences) を使用してください。この API はオプトイン設定の管理専用に構築されており、渡された値の検証を行い、バックエンドで定義された次の値のみを受け入れます: `DOUBLE_OPTED_IN`、`OPTED_OUT`、`OPT_IN_PENDING`。それ以外の値が渡された場合、データは破棄されます。
      </Warning>

# ダブルオプトインを使用したエンゲージメントとリーチのバランス

ダブルオプトイン方式では、主に高い関心を示した購読者とエンゲージできますが、この方法によってリストの購読者総数が大幅に減少する可能性があることを認識しておくことが重要です。購読者の質と量のこのトレードオフは、重要な検討事項です。

複数の地域で事業を展開するブランドの場合、ダブルオプトインを導入するかどうかを地域レベルで戦略的に決定できます。この柔軟性は、メールマーケティングのベストプラクティスや同意に関する法的要件が地域によって大きく異なる可能性があることを考慮したものです。

MoEngage の[ダブルオプトイン](/ja/user-guide/campaigns-and-channels/email/getting-started-with-email/configure-email-channel#subscription-management-tab)オプションを使用すると、メールキャンペーンの作成時に、これらの地域的な考慮事項に基づいて **Send only to double-opted-in users** トグルを有効または無効にできます。これにより、メールリスト管理を状況に合わせて調整できます。詳細については、[こちら](/ja/user-guide/campaigns-and-channels/email/create/create-an-email-campaign)を参照してください。

# よくある質問

<Accordion title="オプトイン設定を変更すると、既存のアクティブなメールキャンペーンにはどのような影響がありますか？">
  - ワークスペースがダブルオプトイン方式に移行した場合、既存のアクティブなキャンペーンはすべて、_Email Opt-in Status_ ユーザー属性の値を考慮せずに、ターゲットオーディエンスに含まれるリーチ可能なユーザーへの送信を継続します。一方、新たに作成されるプロモーションメールキャンペーンでは、デフォルトで **Email Opt-in Status** ユーザー属性の値が考慮されます。これは作成者の判断でキャンペーンレベルで変更できます。
  - ワークスペースがダブルオプトイン方式からシングルオプトイン方式に移行した場合、アクティブなプロモーションメールキャンペーンはすべて、ユーザーのリーチ可能ステータスを判断する際に **Email Opt-in Status** ユーザー属性の値を無視するようになります。
</Accordion>

<Accordion title="同じメール ID を持つプロファイルが複数ある場合はどうなりますか？オプトインステータスはそのようなすべてのプロファイルに引き継がれますか？">
  デフォルトでは、はい、引き継がれます。ユーザー A と B が同じメール ID を持ち、A から同意を得た場合、A と B の両方がダブルオプトイン済みとしてマークされます。ただし、この動作はいつでも制御できます。制御するには、MoEngage チームにお問い合わせください。
</Accordion>

<Accordion title='「ユーザーマージ」の場合、オプトインステータスの値はどうなりますか？'>
  ユーザーマージとは、MoEngage が匿名プロファイルを識別済みプロファイルにマージするプロセスです。そのため、常にマージされたプロファイルの値が保持されます。
</Accordion>

<Accordion title="複数のユーザー属性でメール ID を追跡している場合、Email Opt-in Management API で値を渡すと、MoEngage はオプトイン値を更新するユーザーをどのように特定しますか？">
  メールの General Settings で指定されたユーザー属性を使用して、API で指定されたメールを値として持つユーザーが検索されます。API にカスタマー ID が指定されている場合、MoEngage はそれを使用してユーザーを検索します。
</Accordion>

<Accordion title="必要に応じて、オプトインステータスが更新されたユーザーをセグメント化するにはどうすればよいですか？">
  - [Email Opt-in Management API](https://www.moengage.com/docs/api/opt-in-management/update-user-email-opt-in-preferences)、[Resubscribe API](https://www.moengage.com/docs/api/resubscribe/bulk-resubscribe-users#bulk-resubscribe-users)、[Update Subscription Preference API](https://www.moengage.com/docs/api/subscription-preferences/update-subscription-preferences)、またはエンドユーザーの操作によってユーザーのオプトインステータスが更新されるたびに、MoEngage は必要な情報を含む _Email Optin Status Updated_ というイベントを発生させます。\
    **注**: このイベントの保持期間は、MoEngage で追跡される他のイベントと同じです。より長期間保存したい場合は、Streams または MoEngage が提供するその他のエクスポートオプションを使用して、自社側で保存してください。[詳細](/ja/user-guide/data/exports)はこちらをクリックしてください。
</Accordion>

<Accordion title="PII 暗号化またはトークン化を使用している場合、オプトインステータスを更新するにはどうすればよいですか？">
  - メールに PII Tokenization を使用している場合は、[Email Opt-in Management API](https://www.moengage.com/docs/api/opt-in-management/update-user-email-opt-in-preferences) を呼び出す際に必ずユーザー ID を渡してください。MoEngage はこのユーザー ID を使用してユーザーを特定し、オプトインステータスを更新します。この場合、MoEngage はメール ID を保存しないため、メール ID を渡しても効果はありません。
  - PII Encryption を使用してメールを送信している場合は、ユーザー ID または復号化されたメール ID のいずれかを必ず渡してください。MoEngage はこの情報を使用して、関連するユーザーを特定してオプトインステータスを更新するか、そのメール ID を持つすべてのユーザーのオプトインステータスを更新します。
</Accordion>

<Accordion title="ダブルオプトインを有効にした後、ユーザープロファイルに Email Opt-in Status 属性が表示されないのはなぜですか？">
  ダブルオプトインを有効にしても、既存または新規のすべてのユーザープロファイルに対して **Email Opt-in Status** 属性が自動的に作成されることはありません。この属性は、[Opt-in Management API](https://www.moengage.com/docs/api/opt-in-management/update-user-email-opt-in-preferences)、同意を求めるメールへのユーザーの操作、CSV インポート、その他の購読関連の更新などを通じて、そのユーザーについて明示的なオプトインステータスの更新を受信した場合にのみ作成されます。この属性を持たないユーザープロファイルは、値が *Optin pending* のユーザーと同様に扱われます。
</Accordion>

<Accordion title="Email Opt-in Status の更新にはどの API を使用すればよいですか？">
  **Email Opt-in Status** の更新、特に新規ユーザーの場合は、[Opt-in Management API](https://www.moengage.com/docs/api/opt-in-management/update-user-email-opt-in-preferences) を使用することをお勧めします。この API は渡された値の検証を行い、バックエンドで定義された次の値のみを受け入れます: `DOUBLE_OPTED_IN`、`OPTED_OUT`、`OPT_IN_PENDING`。それ以外の値が渡された場合、データは破棄されます。

  [Track User API](https://www.moengage.com/docs/api/user/track-user) でも **Email Opt-in Status** 属性を更新できますが、この API は汎用的な属性更新用に設計されており、オプトインステータスの値に対して厳密な検証を行いません。Track User API を使用する場合は、値を読みやすい名前（*Optin pending*、*Double opted in*、*Opted out*）として渡してください。
</Accordion>

<Accordion title="Email Opt-in Status の有効な値は何ですか？また、API によってどのように異なりますか？">
  有効な値は、使用する API によって異なります。

  * **Opt-in Management API**（バックエンドで定義された値）: `DOUBLE_OPTED_IN`、`OPTED_OUT`、`OPT_IN_PENDING`。この API は値を検証し、無効な値を含むデータを破棄します。
  * **Track User API / CSV インポート**（読みやすい名前）: `Optin pending`、`Double opted in`、`Opted out`。これらの値では大文字と小文字は区別されません。

  どちらの値のセットも、同じオプトインステータスに対応しています。呼び出す API に適した形式を使用してください。
</Accordion>
