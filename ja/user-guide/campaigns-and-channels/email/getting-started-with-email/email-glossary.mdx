# AMP メール

Accelerated Mobile Pages (AMP) は、一貫して高速に読み込まれるコンテンツページを構築するためのフレームワークを提供することで、モバイルウェブをより良くすることを目指すオープンソースプロジェクトです。

AMP メールを使用すると、送信者はメールに AMP コンポーネントを含めることができ、受信者はメールページを離れることなく購入取引などのアクションを実行できます。

# BIMI

Brand Indicators for Message Identification ([BIMI](https://bimigroup.org/)) は、DMARC を基盤として構築された技術で、ブランドが受信トレイに商標ロゴを表示するのに役立ちます。Gmail と Yahoo は、BIMI が有効な送信者に青いチェックマークを表示します。これにより、受信者の信頼を築くことができます。

# バウンス

バウンスとは配信の失敗のことです。メールが受信者のサーバーに受け入れられなかった場合、それをバウンスと呼びます。バウンスには、ソフトバウンス (一時的なもので、次回の送信で配信される可能性がある) とハードバウンス (永続的なもの: ユーザーが存在しない) の 2 種類があります。

# 一括メール

大規模なグループの一部として一括で送信されるメールを、一括メールと呼びます。

# 一括メール送信者

メールを一括で送信する、つまり大量のメールを送信する送信者を一括送信者と呼びます。Google は、1 日あたり 5,000 通を超えるメールを送信する送信者を[一括送信者](https://support.google.com/a/answer/14229414#zippy=%2Cwhat-is-a-bulk-sender)と定義しています。

# 1 日あたりのピーク送信量

1 日に送信する最大量を指します。これは通常、オンボーディング/ウォームアップ・ランプアップ段階にある新規送信者に適用されます。

そのため、ランプアップ期間中または完了後に送信する最大量と考えることができます。ピークシーズンの送信量はここには含まれません。

# 専用 IP

1 つのドメインまたはブランドのメール送信専用に予約された IP を、専用 IP と呼びます。

# DKIM

Domain Keys Identified Email ([DKIM](https://dkim.org/)) は、メールが改ざんされているかどうかを検出するために設計されたメール認証方式です。DKIM はメッセージに新しいドメイン名識別子を付加し、暗号技術を使用してその存在の正当性を検証します。

# DMARC

Domain-based Message Authentication Reporting & Conformance ([DMARC](https://dmarc.org/)) は、SPF と [DKIM](#dkim) を基盤として構築されたメール認証およびレポートポリシーです。DMARC は、DKIM および SPF のチェックに失敗したメールをどのように処理するかを ISP に指示します。厳格な DMARC ポリシーにより、スパマーがお客様になりすますことを防止できます。DMARC では 3 つのポリシーを設定できます。

- p=none [受信サーバーが DMARC に失敗したメールを独自の判断で処理できることを意味します]
- p=quarantine [DMARC に失敗したメールをスパム/迷惑メールフォルダーに送信することを意味します]
- p-reject [DMARC に失敗したメールを拒否する、つまり完全にブロックすることを意味します]

厳格な DMARC「p=reject; sp=reject; pct=100」により、スパマーがお客様になりすますことを防止できます。

# ドメイン

メールが *MyBrand `<xyz@anything.mybrand.com>`* から送信される場合、From ドメインは *anything.mybrand.com* となり、これは実質的に *mybrand.com* のサブドメインです。  
この例では、**From name** は *MyBrand*、**From domain** は *anything.mybrand.com*、**From address** は *xyz@anything.mybrand.com** です。*

# ドメインレピュテーション

受信サーバーが、そのドメインから送信されるメールの評価に基づいて各ドメインに割り当てる値です。レピュテーションが高い (良い) ほど、以降のメールが受信トレイに届く可能性が高まります。レピュテーションが低いと、メールがスパムに振り分けられる可能性が高くなります。ドメインレピュテーションは、受信者および受信サーバーのフィルターがお客様のメールをどのように認識しているかの結果です。

# メールの遅延 (Deferred)

メールが送信された後の一時的な状態です。配信が試行されたものの、配信されなかった、または失敗した状態を指します。受信サーバーが、サーバーがビジー状態である、または IP がレート制限/スロットリングされていると応答し、後で再試行する場合です。この場合、システムはメールが配信されるか失敗 (バウンス) するまで再試行します。

メールの遅延はメールの最終状態ではありません。事前に設定されたバウンスまでの期間内に、後続の再試行によって配信されるかバウンスされます。バウンスまでの期間は、Sendgrid の場合は通常 72 時間です。つまり、最初の配信試行から 72 時間経過してもメールがキューに残っている場合、ソフトバウンスとしてマークされます。

# メールの到達率

メールの到達率とは、受信者の受信トレイに届いたメールの割合を示す指標です。受信サーバーはメールを受信トレイに送信したかスパムに送信したかを共有しないため、メールの到達率を算出する方法はありません。到達率の代替指標には、ドメインおよび IP のレピュテーション、キャンペーンのパフォーマンス指標 (配信、開封、クリック、苦情、配信停止)、受信トレイ到達率などがあります。

# メールのサンセット

メールのサンセットとは、エンゲージメントのないメールアドレスを抑制するプロセスです。受信トレイへの到達状況が良好であるにもかかわらず一定期間 (たとえば 6 か月以上) エンゲージメントがない場合、ユーザーがメールボックスを放棄した、メールボックスがスパムトラップである、ユーザーがブランドとのやり取りを望まなくなった、などの理由が考えられます。そのため、メールのサンセットはメールリストをクリーンに保つために使用されます。

# メールの抑制

ターゲットユーザーであるにもかかわらず、メールの受信対象から除外されるユーザーのリストです。通常、これらはお客様のコミュニケーションの配信を停止したユーザー、メールをスパムとして報告したユーザー、またはメールアドレスが存在しないユーザーです。ソフトバウンスが繰り返されるアドレスも送信対象から除外し、抑制する必要があります。

# フィードバックループ

フィードバックループ (FBL) または苦情フィードバックループは、Yahoo、Microsoft、Gmail などのインターネットサービスプロバイダー (ISP) が提供するサービスです。通常、メールサービスプロバイダー (ESP) が、管理しているドメインと IP の FBL 登録を管理します。登録が完了すると、ISP は受信者からの苦情を指定されたフィードバックアドレスに転送します。この特定のフィードバックアドレスは、FBL の登録プロセス中に追加して検証する必要があります。

<Info>
Google は FBL の一部としてユーザーの詳細を共有しません。送信時にメールに Feedback ID ヘッダーが含まれている場合、Google Postmaster ツールで確認できるのはスパム苦情の割合のみです。
</Info>

フィードバックループは一般的な用語です。Yahoo では Complaint feedback loop、Microsoft では JMRP (Junk Mail Reporting Program) と呼ばれています。

# SNDS のフィルター結果

フィルター結果とは、その IP から送信されたすべてのメッセージに適用されたスパムフィルタリングの集計です。個々の受信者のフィルターや行動履歴にも依存するため、必ずしも受信トレイと迷惑メールの割合を意味するわけではありませんが、それに近い値になります。

- 赤: メールの 90% 超がスパムと判定された
- 黄: メールの 10%～90% がスパムと判定された
- 緑: メールの 10% 未満がスパムと判定された

# フォルダー振り分け

Gmail には複数のタブ [メイン、ソーシャル、プロモーション、フォーラム] があり、Microsoft には 2 つのタブ [優先と その他] があります。また、Apple は 2024 年末までにタブを導入すると最近発表しました。

フォルダー振り分けは、受信トレイ到達率と同様に、各タブに送信されたメールの指標です。受信トレイ到達率と同様に絶対数で算出することはできず、Inbox Monster、eDataSource、Everest (Validity) などのサードパーティプロバイダーを通じて取得できます。

# 送信元メールアドレス

メールが *MyBrand `<xyz@anything.mybrand.com>`* から送信される場合、送信元メールアドレスは *xyz@anything.mybrand.com* です。

# 送信者名

メールが *MyBrand `<xyz@anything.mybrand.com>`* から送信される場合、送信者名は *MyBrand* です。

# Google アノテーション

[メールアノテーション](https://developers.google.com/gmail/promotab/overview)は、Gmail アプリのプロモーションタブにのみ関連します。

メールにアノテーションを付けると、Gmail ユーザーは受信トレイから直接プロモーションを確認できます。ユーザーはプロモーションタブでアノテーション付きのテキストや画像をクリックすると、メールを開かずにプロモーションの詳細を確認できます。

# ハードバウンス

バウンスが永続的な場合、ハードバウンスと呼ばれます。通常、受信者のドメインが存在しないか永久に無効化されている場合、または受信者のメールアドレスが存在しないか永久に無効化されている場合に発生します。後でユーザーのメール ID が変更された場合、Hard Bounce の値は false にリセットされます。

# 受信トレイ到達率

受信トレイ到達率とは、受信者の受信トレイに届いた可能性が高いメールの割合です。受信サーバーはこの情報を直接共有しないため、正確に判断する方法はありません。ただし、eDataSource、Inbox Monster、Validity、EmailConsul、Kickbox などのサードパーティツールは、シードテストの結果に基づいておおよその受信トレイ到達率を提供しています。

# IP アドレス

IP アドレスは、メールの送信元となるメールサーバーの識別子です。これらはオンボーディング時に ESP のアカウントに割り当てられます。

# IP レピュテーション

ISP が、その IP から送信されるメールの評価に基づいて各 IP に割り当てる値です。レピュテーションが高い (良い) ほど、メールが受信トレイに届く可能性が高まります。レピュテーションが低いと、メールがスパムに振り分けられる可能性が非常に高くなります。IP レピュテーションは、受信者および受信サーバーのフィルターがお客様のメールをどのように認識しているかの結果です。

# ネームスペースマイニング

ネームスペースマイニングとは、メールアドレスにメールを送信する (または送信を試みる) ことなく、そのアドレスが存在するかどうかを検証する行為です。この手法は、スパム、フィッシングメール、マルウェアを送信するための有効なメールアドレスのリストを生成する目的で、悪意のある送信者によく使用されます。

例: 一般的な名前のさまざまな組み合わせでサーバーに問い合わせ、有効なメールアドレスを特定する: *johndoe@hotmail.com*、*johndeooo@hotmail.com*、*junedoe@hotmail.com*、*jonnydoe@hotmail.com* など。

ネームスペースマイニングのようなパターンにより、メールがブロックされる場合があります。ネームスペースマイニングに関与していない場合は、受信者のサーバーを攻撃するためにハッカーによってお客様のサーバーが侵害されていないかを確認してください。

Microsoft SNDS では、行われた接続リクエスト (RCPT コマンド) と実際に送信されたメール (Message recipients) を比較して表示します。この 2 つの間に大きな差がある場合は、IP が侵害されている可能性があります。あるいは、IP のレート制限により何度も再試行が発生していることが原因の場合もあります。ただし、Microsoft によってネームスペースマイニング行為と誤認され、ブロックされる可能性があります。

# フィッシング

信頼できる組織の偽のコピーを餌として提示し、個人情報を盗もうとする行為をフィッシングと呼びます。スパマーは送信者のアドレスを偽造し、信頼できるブランドになりすまして、最終的な受信者をだまし機密情報を開示させます。

銀行、オンライン決済サービス、ソーシャルメディアアカウントは、フィッシングの一般的な標的です。これらの詐欺は、メールをはじめさまざまな経路で拡散されます。

# プレウォームド IP

レピュテーションが割り当てられており、すでに大量送信に向けてウォームアップされている IP を、プレウォームド IP と呼びます。メールキャンペーンの用語では、プレウォームドとは IP ウォーミング作業を行う必要がないことを意味します。

# プリスティンスパムトラップ

プリスティンスパムトラップは、ユーザー収集方法が不適切または安全でないスパマーや送信者を捕捉するために特別に作成されたハニーポットアドレスです。これらのメールアドレスはどこにも登録されることなくウェブ上に放置されているため、リストをスクレイピングする人は誰でもこれらのユーザーを取得してしまいます。

# 商品カルーセル

[商品カルーセル](https://developers.google.com/gmail/promotab/overview#product-carousel)は、プロモーションの複数の画像プレビューを表示します。Gmail モバイルアプリのプロモーションフォルダー向けのアノテーションの拡張版です。

# プロモーションメール

プロモーションメールは通常、新着商品、特典、セールなどについて顧客に知らせるために送信されます。プロモーションメールの目的は、製品やサービスの認知度を高め、顧客のエンゲージメントとリテンションを図り、最終的に収益を生み出すことです。

# リサイクルスパムトラップ

リサイクルスパムトラップとは、かつては有効で実在の人物が所有し、複数のウェブサイトに登録していた可能性もあるアドレスですが、一定期間非アクティブとなった後に受信サーバーがハードバウンスの応答を返すようになり、ハードバウンスの応答を継続的に返した後、送信者のリストの品質を監視するために受信サーバーがスパムトラップに転用したものです。リサイクルトラップに継続的にヒットする送信者は、リスト管理のベストプラクティスに従っていないとみなされます。

# 送信者認証

送信者認証とは、メールの真正性、つまりメールの送信者が名乗っている本人であること、IP がその送信者のメールを送信することを許可されていること、送信中にメールメッセージが改ざんされていないことを検証するための一連の技術です。

# 共有 IP

共通の IP を使用して複数のドメインのメールを送信する場合、それを共有 IP と呼びます。

# SNDS

Microsoft の Smart Network Data Services (SNDS) は、Google Postmaster ツールが Gmail に関連するレピュテーション情報を共有するのと同様に、Microsoft における IP レピュテーションに関するインサイトを提供します。

# スノーシュースパム

スノーシュースパムとは、メールをさまざまなドメインや IP に分散させることでスパムフィルターを回避する手法です。少量の送信者に対してはコンプライアンス要件が緩やかであるのと同様に、スパムフィルターも少量の送信に対しては比較的感度が低くなっています。スノーシュー手法はこの抜け穴を利用しています。

# ソフトバウンス

バウンスが一時的な場合、ソフトバウンスと呼ばれます。通常、受信者のメールボックスが満杯の場合、受信者のメールサーバーがビジー状態の場合、送信者の IP がブロックされている場合、受信サーバーに一時的に到達できない場合などに発生します。

# スパムメール

スパムは一般的に、未承諾の一括メール (Unsolicited Bulk E-mail: UBE) と理解されています。ただし、不要なメールはすべてスパムとみなすことができます。

# スパムレポート/スパム苦情/ユーザー苦情

受信トレイでメールを受け取った後、そのメールをスパムとしてマークしたユーザーを示します。Gmail の場合、この情報は Google Postmaster ツールで確認できます。従来のフィードバックループをサポートしているその他のメールボックスプロバイダーの場合、この情報はキャンペーン分析で確認できます。

# スパムトラップ

スパムトラップとは、メール送信者のリスト管理方法を評価するためにメールボックスプロバイダーが作成または転用したハニーポットアドレスです。スパムトラップのアドレスは有効であるため、メールは配信されます。しかし、メールに対してエンゲージメントが発生することはありません。

# Spamhaus

[Spamhaus](https://www.spamhaus.org/who-is-spamhaus/) は、IP およびドメインのレピュテーションに関する信頼できる機関です。Spamhaus は最大のブロックリストです。Spamhaus のブロックリストに掲載された IP やドメインは、配信率が非常に低く、ソフトバウンスが非常に多くなる傾向があります。Gmail、Yahoo、Microsoft、Comcast などの主要なメールボックスプロバイダーはすべて、ドメイン/IP のレピュテーションを判断する際に Spamhaus のデータを参照しています。

# SPF

Sender Policy Framework ([SPF](https://en.wikipedia.org/wiki/Sender_Policy_Framework)) は、メールの送信元 IP がその (mailed-by) ドメインからメールを送信することを許可されているかどうかを検証するのに役立つメール認証方式です。

# トランザクションメール

トランザクションメールは通常、ユーザーによって、またはユーザーのアカウントでアクションが実行されたときに送信されます。たとえば、購入、サブスクリプション、アカウントアクティビティ、ワンタイムパスワード、請求書、配送や請求の情報などに関するメールです。

# 未承諾メール

明示的にオプトインしていないユーザーにメールが送信された場合、そのメールは未承諾メールと呼ばれます。

# 配信停止によるドロップ

これはメールベンダーによる抑制の場合に関連します。メールアドレスがメールベンダー (SendGrid) の抑制リストに存在し、MoEngage からそれらのユーザーにメールが送信された場合、そのメールは Unsubscribe drop としてドロップされます。

# ウェブスクレイピングまたはメールスクレイピング

メールスクレイピングとは、ウェブサイト、ソーシャルメディアプラットフォーム、ローカルの HTML ドキュメントなど、ウェブからメールアドレスを収集する手法です。このプロセスを自動化してユーザーを収集できるさまざまなツールが存在します。

この方法で収集されたユーザーは、メールの受信に明示的に同意していません。これは到達率およびユーザー収集のベストプラクティスに反します。また、GDPR や CASL などのポリシーにも違反します。

# メールサービスプロバイダー (ESP)

クライアントに代わってメールキャンペーンを送信および管理するための技術を提供するプラットフォームまたは企業です。

# メールウォームアップ / IP ウォーミング

新しい IP アドレスまたはドメインから送信するメールの量を徐々に増やしていく重要なプロセスです。これにより、メールボックスプロバイダーとの間で良好な送信レピュテーションを確立します。

# リストハイジーン

無効、非アクティブ、またはエンゲージメントのない購読者を削除することで、メールリストを定期的に維持・クリーニングする取り組みです。このプロセスは、到達率の向上とバウンスの削減に不可欠です。

# レンダリング性

さまざまなメールクライアント (Gmail、Outlook、Apple Mail など) やデバイスの種類 (デスクトップ、モバイル) で、メールが正しく一貫して表示される能力です。
