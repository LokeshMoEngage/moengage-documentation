## 概要

[Portfolio](/ja/user-guide/settings/account/portfolio/portfolio) 機能を使用すると、単一の MoEngage ワークスペース内で複数のブランドやアプリケーションを個別のプロジェクトとして管理できます。これにより、プロジェクト固有のコンプライアンスと設定を維持しながら、プロジェクト横断のデータを活用してセグメント化、パーソナライズを行い、ターゲットを絞ったメールキャンペーンを展開できます。

この記事では、Portfolio 機能が次の主要な領域にどのように影響するかを説明します。

- [ターゲットユーザーとパーソナライゼーション](#target-users-and-personalization)
  - [特定のプロジェクトをターゲットにする](#target-specific-projects)
  - [プロジェクト横断のセグメンテーション](#cross-project-segmentation)
  - [プロジェクト横断のトリガー型キャンペーン](#cross-project-triggered-campaigns)
  - [パーソナライゼーション](#personalization)
- [メールキャンペーンのコンテンツ](#email-campaign-content)
- [Portfolio レベルとプロジェクトレベルのリーチ可能性](#portfolio-and-project-level-reachability)

これらの概念を説明するために、Project A と Project B という 2 つの異なるブランドを持つ企業のキャンペーンを例に考えます。このキャンペーンの目的は、スタンダードアプリ（Project A）のロイヤルカスタマーに対して、プレミアムブランド（Project B）をクロスプロモーションすることです。

<Note>
  **前提条件**

  - Portfolio が有効なワークスペースでメールキャンペーンを作成するには、アカウントに少なくとも 1 つのプロジェクトを追加する必要があります。プロジェクトの追加の詳細については、[Portfolio](/ja/user-guide/settings/account/portfolio/portfolio) を参照してください。
  - [メール設定](/ja/user-guide/campaigns-and-channels/email/getting-started-with-email/configure-email-channel)ページでは、プロジェクト固有の設定がサポートされています。Portfolio に複数のプロジェクトが含まれている場合、これらの設定ページに **Project** ドロップダウンリストが表示され、プロジェクトごとに固有の設定を選択して構成できます。次のメール設定がプロジェクト固有の設定をサポートしています。
    - Overview
    - Sender Configuration
    - General Settings
    - Subscription Management
    - Font Management
    - PII Tokenization
    **注**: メール設定の Dynamic Sender Routing は、プロジェクト固有の設定をサポートしていません。
</Note>

## ターゲットユーザーとパーソナライゼーション

Portfolio 機能は、メールキャンペーンの **Target Users and Personalization** セクション内の次の領域に影響します。

- 特定のプロジェクトをターゲットにする
- プロジェクト横断のセグメンテーション
- プロジェクト横断のトリガー型キャンペーン
- パーソナライゼーション

<Info>
  MoEngage は、キャンペーン作成時にプロジェクト固有のメール設定を動的に読み込みます。確実にデプロイできるよう、MoEngage はメール設定を取得できない場合にキャンペーンの作成を防止します。エラーメッセージが表示された場合は、数分待ってから再試行してください。問題が解決しない場合は、サポートチケットを登録してサポートを依頼してください。
</Info>

### 特定のプロジェクトをターゲットにする

新しいメールキャンペーンを作成すると、ワークフローを効率化するために、MoEngage プラットフォームは最後に操作したプロジェクトを自動的にデフォルトとして設定します。キャンペーンを特定のプロジェクトにリンクすると、システムはそのプロジェクトのメール設定（コネクター、「From」アドレス、購読カテゴリなど）を自動的に読み込みます。

次の例では、Project A の顧客に新しいオファーを宣伝するメールを送信することを目的としています。

1. キャンペーン作成の [Step 1: Target users](/ja/user-guide/campaigns-and-channels/email/create/create-an-email-campaign) で、プロジェクト選択ドロップダウンを見つけます。
2. ターゲットプロジェクト（例: **Project A**）を選択します。MoEngage は、プロジェクト固有のすべてのメール設定を直ちに読み込みます。

<Frame>
  ![Target Users ステップのプロジェクト選択ドロップダウン](/images/targetspecificproject.png)
</Frame>

### プロジェクト横断のセグメンテーション

1 つのプロジェクト内での行動だけでなく、すべてのプロジェクトにわたるユーザーの完全なジャーニーに基づいてユーザーをセグメント化できます。たとえば、Project A のキャンペーンを作成している場合でも、Project B でユーザーが行ったアクションに基づいてユーザーをターゲットにし、絞り込むことができます。

**シナリオ:** Project A（メインアプリ）で積極的に買い物をしているユーザーのうち、Project B で購入していないユーザーにのみ、Project B（プレミアムブランド）の初回割引を送信することを目的とします。

**設定方法:**

1. **Target audience** セクションで **Filter users by** を選択し、**User behavior** タブをクリックします。
2. 最初のルールでは、プロジェクトのドロップダウンリストを使用して **Project A** を選択します。条件を、**last 3 days** にイベント _Added to Cart_ を **Has executed** に設定します。

<Frame>
  ![Added to Cart イベントを使用した Project A のユーザー行動フィルタールール](/images/userbehavioremail.png)
</Frame>

3. **\+ Filter** をクリックして 2 つ目のルールを追加します。ドロップダウンリストから **Project B** を選択し、条件を、**last 3 days** にイベント _Order Placed_ を **Has not executed** に設定します。

<Frame>
  ![複数のフィルタールールを使用したプロジェクト横断のセグメンテーション](/images/crossprojseg.png)
</Frame>

これらのルールでターゲットオーディエンスを設定することで、MoEngage はクロスプロモーションメールを Project A のアクティブな購買者にのみ送信し、Project B で既に購入したユーザーを除外します。

### プロジェクト横断のトリガー型キャンペーン

イベントトリガー型およびビジネスイベントトリガー型のメールキャンペーンでは、あるプロジェクトでの顧客の行動を使用して、別のプロジェクトのメールキャンペーンをトリガーできます。これにより、ブランドポートフォリオ全体でユーザーのアクションにリアルタイムで反応する、自動化されたクロスプロモーション戦略を作成できます。

**シナリオ:** 購買意欲の高いユーザーにプレミアムブランド（Project B）を紹介することを目的とします。スタンダードブランド（Project A）でユーザーが購入を完了するか、カートに商品を追加して高い購買意欲を示したときに、プレミアムブランドからラグジュアリーコレクションを紹介するメールを即座にトリガーしたいとします。

**設定方法:** Project B 内で自動化キャンペーンを構築し、ユーザーの Project A での操作に基づいてトリガーを定義します。

1. **Select condition** セクションで、**If user performs** が選択されていることを確認します。
2. 最初のルールでは、**Primary trigger event(s)** ボックスで、プロジェクトのドロップダウンリストから **Project A** を選択します。条件を、イベント _Purchased_ を **Has Executed** に設定します。

<Frame>
  ![Purchased イベントを使用して Project A に設定したプライマリトリガーイベント](/images/crossprojecttriggered1.png)
</Frame>

3. **\+ Add alternate trigger event** をクリックして 2 つ目のルールを追加し、条件を、イベント _Added to Cart_ を **Has Executed** に設定します。

<Frame>
  ![Added to Cart イベントを使用して設定した代替トリガーイベント](/images/crossprojecttriggered2.png)
</Frame>

これらのトリガーを使用して Project B でキャンペーンを設定することで、ユーザーが Project A で購入を完了するか、カートに商品を追加するたびに、MoEngage はクロスプロモーションメールを自動的に送信します。

詳細については、[イベントトリガー型キャンペーンを作成する](/ja/user-guide/campaigns-and-channels/getting-started/triggers/event/create-an-event-triggered-campaign)を参照してください。

### パーソナライゼーション

パーソナライゼーションでは、送信者のプロジェクト固有のコンテキストに合わせてメッセージを調整し、データの整合性とブランドの関連性を確保します。あるブランドのコンテキストのデータが別のブランドで使用されないよう、MoEngage は**送信元プロジェクト**に基づいて使用可能な属性をフィルタリングします。

Project B から、Project A を操作したユーザーをターゲットにキャンペーンを送信する場合、システムは配信されるメッセージのコンテキストを重視します。

- **ターゲット属性リスト**: キャンペーンの Content ステップでは、**グローバルユーザー属性**と **Project B 固有のカスタム属性**を含むフィルタリングされたリストが表示されます。
- **データの分離**: Project A にのみ存在するカスタム属性は非表示になります。これにより、メッセージでは顧客が現在メールを受け取っているブランドに関連する属性のみが使用されます。
- **一貫性**: 属性の範囲を送信元プロジェクトに限定することで、パーソナライズされたタグ（ロイヤルティティアやブランド固有の設定など）が、提供するブランド体験に対して正確に保たれます。

詳細については、[メールコンテンツをパーソナライズする](/ja/user-guide/campaigns-and-channels/email/create/personalize-email-content)を参照してください。

## メールキャンペーンのコンテンツ

メールキャンペーン作成の Step 2: Content では、次の領域がプロジェクトレベルで管理されます。

- メールコネクター
- From メールアドレス
- カスタムフォント
- テストキャンペーン

次の領域はグローバルレベルで管理されます。

- テンプレートマネージャー
- コンテンツブロック
- コンバージョン目標
- UTM トラッキング
- ロケール
- 添付ファイル

## Portfolio レベルとプロジェクトレベルのリーチ可能性

単一のワークスペース内でマルチブランドのポートフォリオを管理する場合、組織はユーザーのリーチ可能性情報（バウンス、購読解除、スパム報告など）をどのように維持するかを柔軟に決定できる必要があります。

ワークスペースでマルチブランドのポートフォリオが有効になっている場合、各ユーザーの購読ステータスはプロジェクトごとに個別に追跡されます。この設定が有効な場合、グローバルな BUC（Bounce、Unsubscribe、Complaint）属性は評価されません。これにより、ユーザーがあるブランドのコミュニケーション設定を更新しても、ポートフォリオ内の別のブランドの購読ステータスに意図せず影響することはありません。

キャンペーンを作成すると、システムは選択したプロジェクトに固有のユーザーのリーチ可能性ステータスを自動的に確認します。

<Warning>
  プロジェクトレベルのメールが有効になる前に、ワークスペースで _Portfolio_ 機能を使用してメールキャンペーンを実行していた場合、それらの既存キャンペーンを編集または複製することはできません。プロジェクトレベルのリーチ可能性とプロジェクトレベルのメール設定は、既存のキャンペーンを編集するか新しいキャンペーンを作成した時点で有効になるため、既存キャンペーンの設定が無効になる可能性があります。代わりに、該当するプロジェクトで新しいメールキャンペーンを作成してください。
</Warning>

**シナリオ:** 親会社が、MoEngage ワークスペース内で Project A（衣料品小売アプリ）と Project B（食料品配達アプリ）という 2 つの異なるブランドを管理しています。1 人のユーザーが両方のアプリに登録して使用しています。

- このユーザーは衣料品に関するプロモーションメールが不要になったため、Project A の購読を解除します。
- ただし、食料品の週次割引コードは引き続き受け取りたいため、Project B の購読は継続します。

**結果:** このユーザーが Project A で作成された新しいメールキャンペーンのターゲットオーディエンスに該当する場合、MoEngage はこのユーザーをリーチ不可と判断し、メッセージを抑制します。同じユーザーが Project B で作成されたメールキャンペーンのオーディエンスに該当する場合は、完全にリーチ可能な状態のままで、メールを受信します。

# よくある質問

<Accordion title="キャンペーンの作成時にプロジェクト固有のメール設定の読み込みに失敗した場合はどうなりますか？">
  確実にデプロイできるよう、MoEngage はキャンペーンの作成を防止します。エラーメッセージが表示された場合は、数分待ってから再試行してください。問題が解決しない場合は、MoEngage サポートチームにお問い合わせください。
</Accordion>

<Accordion title="別のプロジェクトで行った行動に基づいて、あるプロジェクトのユーザーをターゲットにできますか？">
  はい。プロジェクト横断のセグメンテーションを使用すると、ブランドポートフォリオ全体にわたるユーザーの完全なジャーニーに基づいてユーザーをフィルタリングできます。たとえば、最近 Project A でカートに商品を追加したユーザーをターゲットにしつつ、Project B で既に注文したユーザーを除外できます。
</Accordion>

<Accordion title="あるプロジェクトでのアクションによって、別のプロジェクトからメールをトリガーできますか？">
  はい。プロジェクト横断のトリガー型キャンペーンを使用すると、あるプロジェクトでの顧客の行動を使用して、別のプロジェクトのメールをリアルタイムでトリガーできます。たとえば、スタンダードブランド（Project A）でユーザーが商品を購入すると、プレミアムブランド（Project B）からウェルカムメールを即座にトリガーできます。
</Accordion>

<Accordion title="プロジェクト横断のメールをパーソナライズする際に、任意のプロジェクトのカスタム属性を使用できますか？">
  いいえ。データの整合性を確保するため、MoEngage はデータの分離を行います。コンテンツ作成ステップでは、システムが送信元プロジェクトに基づいて使用可能な属性をフィルタリングします。表示されるのはグローバルユーザー属性と送信元プロジェクト固有のカスタム属性のみで、他のプロジェクトのカスタム属性は非表示になります。
</Accordion>
