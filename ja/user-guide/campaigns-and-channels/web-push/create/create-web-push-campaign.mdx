# Web Push キャンペーンを作成する手順

Web Push キャンペーンの作成は、次の 3 つのステップで構成されます。

1. [ターゲットユーザー](#step-1-target-users): キャンペーンのターゲットオーディエンスを定義します
2. [コンテンツ](#step-2-define-content): 送信するプッシュ通知のコンテンツを定義します
3. [スケジュールと目標](#step-3-scheduling-and-goals): キャンペーンの配信スケジュールと目標を定義します

## ステップ 1: ターゲットユーザー

このセクションには次の内容が含まれます。

### キャンペーンの詳細

キャンペーンの詳細セクションには、次のフィールドがあります。

|  |  |
| --- | --- |
| **Team** - 組織でチームが有効になっている場合は、ドロップダウンでチームを選択します。詳細については、[MoEngage のチーム](/ja/user-guide/settings/account/team-management/teams-in-moengage)を参照してください。 |  |
| **Campaign name** - キャンペーンを管理および識別するためのキャンペーン名を入力します。キャンペーン名は 5 文字以上で、上限は 256 文字です。 | <img alt="Push_CampaignDetails (1).png" src="/images/moengage_686d1c.png" style={{ display: 'inline-block'}} /> |
| **Campaign tags** - ドロップダウンリストからキャンペーンタグを選択します。最大 5 つのタグを選択できます。詳細については、[キャンペーンタグ](/ja/user-guide/campaigns-and-channels/getting-started/introduction/campaign-tags)を参照してください。 |  |

<Accordion title="Event Triggered キャンペーン">
  Event Triggered キャンペーンを使用すると、さまざまなユーザーアクションイベントをトリガーとして、パーソナライズされた通知を送信できます。たとえば、カートに追加したものの購入していない商品についてユーザーにリマインドできます。

  このようなキャンペーンの作成方法の詳細については、[Event Triggered キャンペーンの作成](/ja/user-guide/campaigns-and-channels/getting-started/triggers/event/create-an-event-triggered-campaign)を参照してください。
</Accordion>

<Accordion title="Business Event Triggered キャンペーン">
  |  |  |
  | --- | --- |
  | Business Event Triggered キャンペーンでは、_Select business event_ ドロップダウンを使用して、キャンペーンにマッピングするビジネスイベントを選択できます。ドロップダウンには、MoEngage アカウントで作成されたすべてのビジネスイベントが含まれます。 | <img alt="BusinessEvent.png" src="/images/moengage_7c29b1.png" /> |

  ビジネスイベントを選択すると、そのビジネスイベントに関連付けられたイベント属性がセグメンテーションフィルターで利用可能になります。ビジネスイベント属性は、次のセグメンテーションフィルターで利用できます。

  - ユーザープロパティによるセグメント - ユーザープロパティをビジネスイベント属性にマッピングできます
  - ユーザー行動によるセグメント - ユーザーが実行したイベントの属性をビジネスイベント属性にマッピングできます
  - ユーザーアフィニティによるセグメント - ユーザーが実行したイベントの属性をビジネスイベント属性にマッピングできます

  <Info>
    - セグメンテーションを機能させるには、選択したユーザー属性またはイベント属性のデータ型が、ビジネスイベント属性のデータ型と一致している必要があります。
    - ビジネスイベントは動的セグメンテーション（ビジネスイベントがトリガーされた際の値に基づく）で実行されるように設計されているため、Business Event Triggered キャンペーンでは Show count が無効になります。
  </Info>
</Accordion>

### ターゲットオーディエンス

このセクションには、キャンペーンのターゲットオーディエンスを選択するためのセグメンテーションフィルターが含まれます。次のオプションを使用できます。

<Tabs>
  <Tab title="すべてのユーザー ">
    このフィルターオプションを使用すると、すべてのアプリユーザーにキャンペーンを送信できます。このオプションを使用する場合、複数のフィルターを追加することはできません。

    ![AllUsers\_Segmentation.png](/images/moengage_026a58.png)
  </Tab>
  <Tab title="ユーザープロパティでフィルター ">
    このフィルターオプションを使用すると、初回訪問日時、最終訪問日時、都市などのユーザープロパティに基づいてユーザーをターゲットにできます。User property タブを選択し、次の操作を行います。

    1. ドロップダウンで目的の属性を選択します。選択した属性に基づいてフィルターが有効になります。たとえば、数値の属性には「is equal to」、「is not equal to」、「is between」などのフィルター条件があり、文字列の属性には別のフィルターがあります。
    2. 目的のユーザーセグメントを作成するためのフィルター値を指定します。

    詳細については、[セグメントの作成](/ja/user-guide/segment/create-segments/rule-based-filter-segments)を参照してください。

    ![UserProperty.png](/images/moengage_79723f.png)
  </Tab>
  <Tab title="ユーザー行動でフィルター">
    このフィルターオプションを使用すると、アプリ/サイトの起動、商品の閲覧など、ユーザーの行動やイベントに基づいてユーザーをターゲットにできます。User Behavior を選択し、次の操作を行います。

    1. 実行条件と目的のユーザーアクティビティ（イベント）を選択します。
    2. イベントの実行頻度と期間を指定します。
    3. \+Attributes をクリックし、フィルター条件を指定したイベント属性を追加します。
    4. ルールを作成するためのフィルター値を指定します。

    詳細については、[セグメントの作成](/ja/user-guide/segment/create-segments/rule-based-filter-segments)を参照してください。

    ![UserBehavior.png](/images/moengage_c190c2.png)
  </Tab>
  <Tab title="ユーザーアフィニティでフィルター ">
    このフィルターオプションを使用すると、特定の属性値でアクションを実行したユーザーに基づいて作成されたユーザーグループをターゲットにできます。詳細については、User Affinity を参照してください。User Affinity を選択し、次の操作を行います。

    1. 目的のユーザーイベントまたは属性を選択します。
    2. 次の中からユーザーアフィニティパラメーターを選択します。

    - Predominantly 
      フィルター条件を指定してアフィニティ属性を選択し、アフィニティ値を指定します
    - Minimum of 
      フィルター条件を指定してアフィニティ属性を選択し、アフィニティ値を指定します
    - Most no. of times 
      入力するか矢印を使用して、上位または下位のユーザーの割合を指定します
    - Least no. of times

    3. 入力するか矢印を使用して、上位または下位のユーザーの割合を指定します。入力するか矢印を使用して、イベント実行の期間を指定します。
    4. Attribute ボタンをクリックして、フィルターに属性を追加します。

    ![UserAffinity.png](/images/moengage_32befe.png)
  </Tab>
  <Tab title="カスタムセグメントでフィルター">
    このフィルターオプションを使用すると、利用可能なカスタムセグメントのリストからターゲットオーディエンスとしてカスタムセグメントを選択できます。詳細については、[カスタムセグメント](/ja/user-guide/segment/create-segments/manage-segments)を参照してください。

    ![CustomSegment.png](/images/moengage_512db2.png)
  </Tab>
</Tabs>

<Info>
  [_Portfolio_](/ja/user-guide/settings/account/portfolio/portfolio) 機能が有効になっている場合、ワークスペース内の異なるアプリやウェブサイト（プロジェクト）のユーザーデータと行動を組み合わせてユーザーセグメントを作成できます。詳細については、[マルチプロジェクト Portfolio でのセグメンテーション](/ja/user-guide/segment/advanced-concepts/segmentation-in-a-multi-project-portfolio)を参照してください。
</Info>

アカウントでチームが有効になっている場合、作成対象のチームに指定されたセグメンテーション条件が AND 条件でキャンペーンに追加されます。詳細については、[MoEngage のチーム](/ja/user-guide/settings/account/team-management/teams-in-moengage)を参照してください。

フィルター条件を選択した後、次の操作も行えます。

- このオプションを使用して、複数のユーザープロパティルール、ユーザーアクティビティルール、カスタムセグメントルールを作成・組み合わせ、複雑なユーザーセグメントを作成します。
  - _\+ Filter_ をクリックします。
  - _AND または OR_ をクリックします。
  - 属性またはイベントを選択し、フィルター条件を定義します。
- **Exclude Users** - _Exclude Users_ チェックボックスをオンにして、キャンペーンから除外するユーザーのフィルター条件を定義します。
- **Send campaign to the users opted out in preference management** - このオプションをオンにすると、プリファレンス管理でオプトアウトしたユーザーをキャンペーンの対象に含めます。詳細については、[プリファレンス管理](/ja/user-guide/campaigns-and-channels/mobile-push/getting-started-with-mobile-push/preference-management-for-push-notifications)を参照してください。
- **Reset Filters** - このオプションをクリックすると、セグメンテーションフィルターがリセットされます。
- **Show Count** - _Show Count_ をクリックすると、設定したセグメントに現在含まれているユーザーの総数が表示されます。

![OtherFilterOptions.png](/images/moengage_cf8602.png)

### ターゲットプラットフォーム

このセクションでは、キャンペーンのターゲットプラットフォームを選択できます。次のオプションを使用できます。

1. **Android**
2. **iOS**
3. **Web**

Web Push キャンペーンを実行するには、**Web** オプションを選択します。

**注**: **Create New Campaign** ページで Device Triggered または Location Triggered キャンペーンを選択した場合、Web Push キャンペーンは実行できません。

### **コントロールグループ**

このセクションには、キャンペーンのコントロールグループに関する情報が含まれます。コントロールグループのユーザーを除外するには、次の操作を行います。

|  |  |
| --- | --- |
| <ul><li>Global control group トグルを有効にすると、コントロールグループのユーザーをキャンペーンのターゲットセグメントから除外します。</li><li>Campaign control group を有効にすると、キャンペーン内の一定割合のユーザーをキャンペーンのターゲットセグメントから除外します。トグルの下のボックスに、キャンペーンから除外するユーザーの割合を指定します。</li><li>コントロールグループの詳細については、[コントロールグループ](/ja/user-guide/campaigns-and-channels/getting-started/introduction/control-groups)を参照してください。</li></ul> | <img alt="ControlGroup.png" src="/images/moengage_c5b1d3.png" style={{ display: 'inline-block'}} /> |

**Next** をクリックするか、**Create Campaign** ナビゲーション上部のタブを使用してステップ 2 に進みます。

## ステップ 2: コンテンツの定義

このセクションには、キャンペーンのコンテンツを定義するためのさまざまなフィールドがあります。Web プッシュ通知に表示するメッセージを作成できます。メッセージのプレビューは画面の右半分に表示されます。

Web Push キャンペーンの各構成要素は次のとおりです。

<img
  src="/images/moengage_1f2167.png"
  style={{ width:"56%" }}
/>

<Accordion title="基本情報">
  1. **Message Title**: キャンペーンのタイトルを入力します。
  2. **Message**: キャンペーンに表示するコンテンツを入力します。
  3. **Redirect URL**: ユーザーが Web Push 通知をクリックした後にリダイレクトされる URL を入力します。
  4. **Auto Dismiss Notification**: 8 秒後に通知を自動的に閉じるオプションがあります。このオプションを有効にしない場合、ユーザーが通知を操作する（削除または開く）まで通知が表示され続けます。
  5. **Image**: 通知のメッセージの下に添付される画像です。コンピューターから画像をアップロードするか、画像の URL を入力できます。

  <img
    src="/images/moengage_854767.png"
    style={{ width:"55%" }}
  />
</Accordion>

<Accordion title="ボタン">
  ボタンを使用すると、メッセージに最大 3 つの Call to Action を追加できます。ボタンを追加するには、次の手順に従います。

  1. **\+ Action button** をクリックします。
  2. **Title**: ボタンにタイトルを付けます。ボタンを使用してユーザーをカートに移動させる場合は、ボタン名を「Check Out」にできます。
  3. **Icon**（任意）: ボタンにアイコンを追加します。MoEngage では、コンピューターから画像をアップロードできます。
  4. **URL**: ユーザーがボタンをクリックした後にリダイレクトされる URL を入力します。

  プッシュメッセージには最大 2 つのアクションボタンを追加できます。Web Push 通知自体は、ブラウザーによってデフォルトでアクションボタンとして扱われます。

  <img
    src="/images/moengage_1e550b.png"
    alt="Screenshot 2022-09-20 at 12.59.39 PM.png"
    style={{ width:"65%" }}
  />
</Accordion>

<Accordion title="詳細設定">
  **Icon Image**: プッシュメッセージに表示されるアイコンです。デフォルトのアイコン（Web Push 設定にあるもの）を選択するか、新しい画像をアップロードできます。

  <img
    src="/images/moengage_a04e18.png"
    style={{ width:"62%" }}
  />
</Accordion>

MoEngage では、プレビューに表示される Web Push メッセージを確認してから、Next をクリックしてキャンペーンのスケジュールと目標を設定することを推奨しています。

<Info>
  **See in web browser** ボタンをクリックすると、Web Push 通知を確認できます。お使いのブラウザーとデバイスで Web Push 通知のプレビューが開きます。他のブラウザーやデバイスで通知がどのように表示されるかを確認するには、[こちらのページ](/ja/user-guide/campaigns-and-channels/web-push/getting-started-with-web-push/configure-web-push-settings)を参照してください。
</Info>

<Accordion title="テストキャンペーン（任意）">
  テストキャンペーンを使用すると、テストデバイスでキャンペーンをプレビューし、通知が意図したとおりに伝わるかを確認できます。

  次のいずれかのオプションを選択し、テストユーザーに対して選択した属性の値を指定することで、作成したキャンペーンをテストできます。

  - Unique ID
  - Email ID
  - Mobile Number
  - Google Advertising identifier
  - iOS Identifier for advertising
  - Device Push Token
  - Custom Segment

  <img
    src="/images/moengage_b9b680.png"
    alt="TestCampaign (1).png"
    style={{ width:"81%" }}
  />

  Business Event Triggered キャンペーンの場合、以下に示すように、イベントをトリガーする属性の入力を求められます。セグメンテーションでビジネスイベント属性をユーザー属性またはイベント属性にマッピングしている場合は、キャンペーンのテスト時にこれらの値を渡す必要があります。値が渡されない場合、テストキャンペーンは失敗します。
</Accordion>

## ステップ 3: スケジュールと目標

このセクションには次の内容が含まれます。

- [配信スケジュール](#delivery-schedule) - キャンペーンをユーザーに配信するタイミングと配信の周期を選択します。
- [コンバージョン目標](#conversion-goals) - キャンペーンで追跡するコンバージョン目標と収益指標を選択します。
- [配信コントロール](#delivery-controls) - スロットリング、フリークエンシーキャップ、通知の有効期限設定などの高度な配信コントロールオプションを選択します。

### 配信スケジュール

<Accordion title="One Time">
  <Tabs>
    <Tab title="できるだけ早く">
      ターゲットユーザーにキャンペーンを即時送信します。

      ![OneTime\_SendASAP.png](/images/moengage_97f5cb.png)
    </Tab>
    <Tab title="特定の日時">
      指定した時刻、タイムゾーン、または予測された時刻にキャンペーンを送信します。

      次のいずれかを選択します。

      | フィールド | 説明 |
      | --- | --- |

### コンバージョン目標

コンバージョン目標を追加して、キャンペーンのビジネス指標を追跡できます。最大 5 つのコンバージョン目標を追跡できます。任意のアプリイベントをコンバージョン目標のアクティビティとして選択でき、複数のコンバージョン目標を設定できます。最初の目標がプライマリ目標として扱われます。

たとえば、キャンペーン送信後に iPhone を購入した顧客の数を追跡したいとします（イベント - 購入イベント、商品 - iPhone）。その場合、コンバージョン目標の設定は、次の詳細を含む下の画像のようになります。

- **Goal Name** - _iPhonePurchase_
- **App Event you wish to track** - _Made Purchase_
- **Event Attribute/Property**\*- product\* が _イベント属性/プロパティ_ です
- **Value of Event Attribute/Property** - _iPhone_

![ConVErsionGoals.png](/images/moengage_985966.png)

複数のコンバージョン目標を使用すると、複数のビジネス指標を追跡したり、ユーザーアクションのファネルを可視化したりできます。たとえば、次の内容を確認したい場合は、複数のコンバージョン目標を使用できます。

- 商品ページを閲覧したユーザーは何人か？
- そのうち、その商品をカートに追加したユーザーは何人か？
- そのうち、注文に成功したユーザーは何人か？

    | <ul><li>**Ignore frequency capping** - このトグルを有効にすると、フリークエンシーキャップの設定を無視します。詳細については、[フリークエンシーキャップ](/ja/user-guide/settings/channels/delivery-controls/frequency-capping)を参照してください。</li><li>**Ignore global minimum delay** - このトグルを有効にすると、プッシュ通知に設定された最小遅延の設定を無視します。</li><li>**Request Limit** - 最大スループットは 1 分あたり 25 万リクエストです。複数のキャンペーンが並行して実行されている場合、すべてのキャンペーンのスループットをサポートできず、キャンペーンが遅延する可能性があります。</li></ul> | <img src="/images/moengage_8893d5.png" style={{ display: 'inline-block'}} /> |
