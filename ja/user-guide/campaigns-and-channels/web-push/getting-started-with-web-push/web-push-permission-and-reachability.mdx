# 概要 - プッシュ許可

プッシュ通知の許可は、アプリがユーザーのデバイス上で取得するアプリレベルの許可です。この許可は、ユーザーの通知トレイにプッシュ通知を表示するために必要です。この許可がオフになっている場合、送信した通知はユーザーに表示されず、バックグラウンドでアプリにサイレントに配信されます。

# プッシュ許可の仕組み

Web プッシュの許可は、ブラウザとデバイスのオペレーティングシステム (OS) に依存します。ほとんどのブラウザの動作には、いくつかの共通点があります:

- デフォルトでは、ユーザーが許可するまで、ウェブサイトは通知を送信できません。
- ユーザーは次のいずれかの方法でウェブサイトに許可を与える必要があります:  
  - ブラウザが表示するダイアログボックスで許可を承認する
  - ブラウザの通知設定でそのウェブサイトの許可を有効にする
- ユーザーが許可した場合、アプリはユーザーに通知を送信できます。
- ユーザーが許可しなかった場合、アプリはユーザーに通知を送信できません。
- ダイアログボックスの動作はブラウザによって異なります。

| ブラウザ | 「Allow」(または同等のアクション)をクリックした場合の動作 | 「Block」(または同等のアクション)をクリックした場合の動作 | ダイアログボックスを無視した場合の動作 |
| --- | --- | --- | --- |
| Chrome, Opera | ウェブサイトに許可が付与され、通知を送信できます。 | ウェブサイトへの許可が拒否され、通知を送信できません。  また、ウェブサイトはダイアログボックスで再度許可を求めることもできません。 | ウェブサイトへの許可が拒否され、通知を送信できません。  ウェブサイトはダイアログボックスで再度許可を求めることができます。 |
| Safari, Edge, Firefox | ウェブサイトに許可が付与され、通知を送信できるようになります。 | ウェブサイトへの許可が拒否され、通知を送信できません。  また、ウェブサイトはダイアログボックスで再度許可を求めることもできません。 | ウェブサイトへの許可が拒否され、通知を送信できません。  また、ウェブサイトはダイアログボックスで再度許可を求めることもできません。 |

# ブラウザの許可と OS レベルの通知設定の違い

Web プッシュの許可はブラウザレベルで機能します。ブラウザが通知を表示するかどうかは、オペレーティングシステムが別途制御します。この 2 つの設定は互いに独立しています。

ユーザーがブラウザで Web プッシュの許可を付与したものの、オペレーティングシステムレベルでそのブラウザの通知をオフにしている場合、次のようになります:

- ブラウザは通知を受信して表示しようとします。オペレーティングシステムは画面上への表示を抑制します。
- MoEngage は *Notification Received Web* イベントをトラッキングします。このイベントは、画面上への表示ではなく、ブラウザレベルでの受信を反映します。
- ブラウザのサブスクリプションは有効なままであるため、MoEngage はそのユーザーを Web プッシュの購読済みかつリーチ可能なユーザーとしてカウントします。

これは想定どおりの動作です。Web プッシュの配信を分析する際は、*Notification Received Web* を、ユーザーが画面上で目にする通知の数ではなく、ブラウザレベルでの受信の指標として解釈してください。

# プッシュ許可のトラッキング

2024 年 9 月 9 日以降、*Reachability Push Web* 属性からユーザーのプッシュ許可をトラッキングできるようになります。

## ユーザーレベルでのプッシュ許可ステータスのトラッキング

この属性には次の値があります:

| 値 | 説明 |
| --- | --- |
| 201 - Reachable and opted in | 有効なプッシュトークンを持ち、少なくとも 1 つのブラウザからオプトインしているすべてのユーザーに適用されます。 |
| 202 - Not reachable due to opt-out | 有効なプッシュトークンを持っていたすべてのブラウザからオプトアウトしたすべてのユーザーに適用されます。 |
| 200 - Reachable and opt-in status unknown | トラッキングの変更がリリースされた後にまだウェブサイトを開いておらず、有効なプッシュトークンを持つすべてのユーザーに適用されます。 |

<Info>
- Android や iOS とは異なり、Web プッシュ通知では、ユーザーがブラウザにプッシュ通知の送信を許可した場合にのみプッシュトークンが生成されます。
- ステータスが '202—Not reachable due to opt-out' のユーザーは、最初にオプトインした後、有効なプッシュトークンを保持したままオプトアウトしたデバイスを持っています。
- 新しい Web デバイスのリーチャビリティステータスは、デフォルトで '404—Any user who is not reachable due to Push ID not found' です。
</Info>

MoEngage ダッシュボードで **Segment** \> **Create Segment** に移動し、セグメンテーションクエリを使用して *Reachability Push Web* 属性をクエリすることで、これらの各ユーザーの数を個別に取得できます。

## プッシュ許可の変更のトラッキング

Web Push のリーチャビリティに関するイベントは次のとおりです:

| 名前 | 説明 | プラットフォーム |
| --- | --- | --- |
| Subscribed to Push | ユーザーがプッシュ通知を購読したときにトラッキングされます。 | Web |
| Unsubscribed to Push | ユーザーがプッシュ通知の購読を直接解除したときにトラッキングされます。 | Web |

## プッシュ許可の傾向を経時的にトラッキングする

MoEngage の Reachability Dashboard には、プッシュ通知の受信にオプトインしたすべてのユーザーと、オプトインしていないユーザーのリーチャビリティの傾向が表示されます。Reachability Dashboard には、**Dashboards** \> **Reachability** に移動してアクセスできます。

## オプトインの方法

このセクションでは、Web Push のオプトイン情報を構成できます。オプトインとは、ウェブページ上でユーザーからプッシュ許可を求める方法を指します。詳細については、[Web Push 設定の構成](/ja/user-guide/campaigns-and-channels/web-push/getting-started-with-web-push/configure-web-push-settings)を参照してください。
