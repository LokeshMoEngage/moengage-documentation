## 目的

Web プッシュ購読者ベースを他のプラットフォームから MoEngage に移行し、MoEngage で作成したキャンペーンでこれらのユーザーをターゲットにします。

## 実施する手順

1. MoEngage SDK をウェブサイトに連携します。SDK の連携手順については、[連携ドキュメント](/ja/developer-guide/web-sdk/web-sdk-integration/basic-integration/web-sdk-integration)を参照してください。
2. 以前のベンダーのプラットフォームで「All Users」をターゲットとするキャンペーンを作成し、ユーザーをウェブサイトにリダイレクトします。この手順の目的は、MoEngage プラットフォームで作成したキャンペーンの WebPush 通知を表示するために必要な MoEngage Service Worker を、ユーザーのデバイスに登録することです。既存ユーザーの大部分が MoEngage に登録されるまで、ユーザーのターゲティングを続けてください。Web プッシュ購読者数は、MoEngage の主要指標ページで確認できます。
3. ユーザーがすでにウェブサイトからの Web プッシュ通知の受信を購読している場合、オプトイン権限はユーザーに表示されません。バックエンドでは、次の処理が行われます。\
   i) MoEngage Service Worker の登録\
   ii) このユーザーのプッシュトークンの生成\
   iii) ブラウザーの種類、ブラウザーのバージョンなどのデバイス情報の取得
4. これで、ユーザーは MoEngage Dashboard で作成したキャンペーンからプッシュ通知を受信できるようになります。

# よくある質問

**Q: MoEngage SDK の連携後、購読ユーザーがウェブサイトにアクセスしない場合はどうなりますか？ Web Push キャンペーンでリーチできますか？**

A: MoEngage SDK の連携後にユーザーがウェブサイトにアクセスしない場合、MoEngage のサービスワーカーはユーザーのデバイスに登録されません。以前のサービスワーカー（以前のベンダーのもの）は異なるペイロード構造に従っている可能性があり、MoEngage のペイロード構造をサポートしていない可能性があるため、ユーザーは Web プッシュ通知を受信できません。通知がユーザーに表示された場合でも、この場合 MoEngage はインプレッションを追跡できません。
