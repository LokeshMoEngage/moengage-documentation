# 概要

_Dynamic Content Personalization_ は、パーソナライズされたメッセージの作成方法を一新し、1 つのマスターキャンペーンから多数のユニークな体験を提供できるようにします。直感的なノーコードのインターフェイスを使用して、複雑な `if-else` ロジックを瞬時に構築できます。

_Dynamic Content Personalization_ 機能では、次のことができます。

- プロモーションバナーを切り替える
- コールトゥアクションを変更する
- オーディエンスセグメントごとに異なる製品レコメンデーションを表示する

_Dynamic Content Personalization_ では、指定した条件を満たさないユーザー向けに明確なフォールバックコンテンツを定義することもできます。このロジックブロック全体は、管理しやすい「[チップ](/ja/user-guide/campaigns-and-channels/getting-started/message-personalization/dynamic-content-personalization#chip-actions)」にカプセル化され、保存してキャンペーンやテンプレート全体で再利用できるため、一貫性を確保し、貴重な時間を節約できます。

この機能は、キャンペーン（Push、SMS、Email、In-App、WhatsApp）、Flows、Content Blocks など、複数のモジュールで利用できます。

<Info>
  アクティブまたは一時停止中のキャンペーンにある既存のパーソナライゼーションは影響を受けません。これらの既存のキャンペーンを編集すると、エディターは新しい UI ベースのエクスペリエンスに切り替わります。
</Info>

# ユースケース

_Dynamic Content Personalization_ 機能は、一般的なマーケティング課題に対応する 3 つのコアモジュール（視覚的なロジックのための Conditional UI、再利用のための Chip Actions、高度な制御のための Custom Jinja Editor）を統合することで、複雑なコードを必要とせずに、さまざまな高度なデータドリブンのマーケティングシナリオを実現します。

- **小売および eコマース**: ユーザーのロイヤルティティアに基づいてユニークなプロモーションオファーを表示したり、カートに残された特定のアイテムでカート放棄のリマインダーをパーソナライズしたり、ユーザーの名前で挨拶する条件付きのウェルカムメッセージを作成したりできます。
- **旅行およびホスピタリティ**: ユーザーのステータスに基づいて「チェックイン」メッセージまたは「アップグレード」オファーを表示する動的なフライトリマインダーを送信したり、情報が利用できない場合のフォールバックとして「TBA」を使用して出発ゲート番号を表示したりできます。
- **金融サービス**: ユーザーの関心（旅行か商品かなど）に基づいてクレジットカードの特典情報をカスタマイズしたり、ユーザーの口座残高が一定のしきい値に達したときに特定の投資商品をおすすめしたりできます。
- **メディアおよびエンターテインメント:** ユーザーの年齢と視聴の好みに基づいて、1 つのキャンペーン内で異なるテレビ番組や映画を宣伝し、コンテンツが常に適切で関連性の高いものになるようにできます。

# Dynamic Content Builder を使用する

このセクションでは、Dynamic Content Builder を使用してパーソナライゼーションを追加および管理するワークフローについて説明します。エディターには 3 つのコアモジュールがあります。

- [Conditional](/ja/user-guide/campaigns-and-channels/getting-started/message-personalization/dynamic-content-personalization#conditional)
- [Chip Actions](/ja/user-guide/campaigns-and-channels/getting-started/message-personalization/dynamic-content-personalization#chip-actions)
- [Custom Jinja Editor](/ja/user-guide/campaigns-and-channels/getting-started/message-personalization/dynamic-content-personalization#custom-jinja-editor)

## Conditional

Conditional は、コードを書かずにパーソナライゼーションロジックを構築するための主要な視覚的ツールです。構文を手動で記述する代わりに、ドロップダウンメニューからオプションを選択して、複雑な `if-else` ロジックブロックを作成できます。

1. パーソナライズ可能なフィールドに移動し、**@** 記号を入力して **Personalization Editor** を開きます。
2. **Conditional** タブを選択します。
3. 識別しやすくするために、ロジックブロックに「Welcome Greeting Block」などの **Display name** を入力することをお勧めします。
4. **`Define the primary IF Condition Block.`** このブロックでは、特定の演算子の階層を使用してメインの条件を構築します。
   1. **最初の条件を構築する:** ドロップダウンメニューを使用して、_User Attribute_ などの属性ソース、`First Name` などの特定の属性、`is not empty` などの演算子、および比較する値を選択します。
   2. **グループ内に条件を追加する:** **\+ Add condition** をクリックして、同じグループ内に別のルールを追加します。ドロップダウンが表示され、これらのルールを **AND** または **OR** 演算子で接続できます。
   3. **複数の条件グループを接続する:** **\+ Add Group condition** をクリックして、別のルールグループを作成します。これらのグループを接続する演算子は、グループ内で使用される演算子によって決まります。
      - グループ内の条件を **OR** で接続する場合、別々のグループを接続する演算子は **AND** である必要があります。これにより、`(A OR B) AND (C OR D)` のようなロジックが作成されます。
      - 逆に、グループ内の条件を **AND** で接続する場合、別々のグループを接続する演算子は **OR** である必要があります。これにより、`(A AND B) OR (C AND D)` のようなロジックが作成されます。

        ![IFBlock.png](/images/moengage_990abe.png)
1. **`Configure the Then Block.`** `Then` テキストボックスに、`IF` 条件を満たすユーザーに表示されるコンテンツを入力します。このフィールドはさらなるパーソナライゼーションもサポートしており、`@` を入力して別の動的な値やネストされた条件ブロックを挿入できます。

   ![IFThen.png](/images/moengage_00e8e0.png)
2. （オプション）**`Add Else If Conditions.`** メインの `IF` ブロックの下にある **\+ Add condition** をクリックして、`Else If` ブロックを追加します。このアクションにより、最初の条件が満たされない場合に別の条件セットを確認できます。
   1. `Else If` ブロックに複数の条件やグループ条件を追加して、ロジックのチェーンを作成できます。
   2. **Else If** ブロックの **Then** ブロックを設定できます。

      ![ELSEIFTHENBLOCK.png](/images/moengage_4aabd2.png)
3. **最終フォールバックを設定する。** 下部にある **Else use fallback option as** ドロップダウンリストを使用して、前述の条件のいずれも満たさないユーザーに対するデフォルトの動作を定義します。オプションは次のとおりです。
   - **No Fallback:** 条件を満たさないユーザーには値を送信しません。
   - **Do not send:** 条件を満たさないユーザーへのメッセージ全体を中止します。
   - **Fallback:** デフォルトのコンテンツを入力できるテキストボックスを表示します。このフィールドもパーソナライズできます。

     ![falluback.png](/images/moengage_ef6da1.png)
5. **Done** をクリックしてロジックを保存し、チップとしてメッセージに挿入します。

<Info>
  _Conditional_ モジュールは、Location および Object データ型を除くすべてのデータ型で条件の作成をサポートしています。
</Info>

### シナリオ: パーソナライズされた初回購入オファーによる高度なオンボーディング

**目標:** 新規ユーザーに挨拶するだけでなく、高度にターゲットを絞ったオファーで初回購入を促す、1 つの強力なウェルカムメッセージを送信したいと考えています。オファーは、ユーザーのプロファイルデータと予測価値に基づいて変える必要があります。

- - セグメントごとに複数のキャンペーンを作成する代わりに、**Conditional UI** を開き、ブロックに「Tiered Onboarding Offer」などの **Display name** を入力します。
  - **OR** を使用して最初の条件グループを構築し、名前で呼びかけられるユーザーを特定します:\
    `IF` (`User Attribute` `First Name` `is not empty`) `OR` (`User Attribute` `Last Name` `exists`)
  - 次に、**\+ Add Group condition** をクリックし、**AND** 演算子で接続して高価値のサブセグメントをターゲットにします。2 番目の条件グループを構築します:\
    `AND` (`User Attribute` `Predicted LTV` `is greater than` `80`)
  - この高価値セグメントの **Then** ブロックに、プレミアムオファーを追加します:「Hi `{{user.properties.first_name}}`, as a VIP, here's 25% off your first order!」

    ![IFFFFFF.png](/images/moengage_c68068.png)
  - 次に、**\+ Add condition** をクリックして **Else If** ブロックを作成し、名前はあるものの高価値セグメントに含まれないユーザーをターゲットにして、標準の割引を提供します:「Hi `{{user.properties.first_name}}`, welcome! Here's 10% off your first order.」

    ![ELSEIFFFF.png](/images/moengage_1da7f2.png)
  - 最後に、メインの **Else use fallback option as** を **Fallback** に設定し、その他すべての匿名ユーザー向けの一般的なオファーを入力します:「Get free shipping on your first order!」
  - **結果:** 3 つの異なるキャンペーンのように機能する、1 つの洗練されたオンボーディングメッセージを作成でき、複数のユーザー属性に基づいて挨拶とオファーの両方を動的にパーソナライズできます。

    ![RESULTTTTT.gif](/images/moengage_f66f60.png)

## Chip Actions

_Dynamic Content builder_ で作成したすべてのパーソナライゼーションは、管理しやすい「チップ」に変換されます。チップの省略記号ボタンをクリックすると **Actions for chip** メニューが表示されます。このメニューは **Email**（カスタム HTML エディター内）と **Push** で使用できます。

<img
  alt="chipactionmenu.png"
  src="/images/moengage_c3ef22.png"
  style={{ width:"54%" }}
/>

- **Copy chip**: チップのロジックの正確で再利用可能なコピーを作成します。コピーした新しいチップに加えた編集は、元のチップには影響しません。コピーしたチップは、次のようなサポートされている場所に貼り付けることができます。
  - Content blocks
  - Push キャンペーン
  - Email キャンペーンのカスタム HTML エディター\
    サポートされていないエディターやチャネルにチップを貼り付けようとすると、エラーになります。

    ![copychiperror.png](/images/moengage_9c72ec.png)
- **Copy Jinja code:** チップの基になる Jinja コードをコピーします。コピーしたコードは Custom Jinja Editor で貼り付けたり変更したりできます。
- **Edit in code editor**: 高度な変更を行うために、チップのロジックを Custom Jinja Editor で直接開きます。コードエディターでチップを編集すると、チップはカスタム Jinja ブロックに永続的に変換されます。この操作の後は、_Conditional_ モジュールを使用してチップを編集できなくなります。
- **Rename**: キャンペーン内で識別しやすくするために、パーソナライゼーションチップに一意の名前を割り当てることができます。

## Custom Jinja Editor

高度なユースケースや特定のフォーマットが必要な場合は、パーソナライゼーションコードを直接記述または編集できます。このエディターは、Jinja 構文に精通したユーザーに完全な制御を提供します。

- **エディターへのアクセス:** Custom Jinja Editor には 2 つの方法でアクセスできます。
  - Personalization Editor 内の **Custom Jinja** タブを選択します。
  - 既存のチップをクリックし、**Actions for chip** メニューから **Edit in code editor** を選択します。
- **構文の検証:** **Done** をクリックすると、構文の自動検証チェックが実行されます。コードを直接編集すると構文エラーが発生する可能性があるため、このプロセスは不可欠です。
  - 構文エラーが検出されると、MoEngage はチップの保存を阻止し、エラーメッセージを表示します。デバッグを容易にするために、メッセージには最初に検出されたエラーの行番号が示されます。

    ![customjinjasingleerror.gif](/images/moengage_c72c57.png)
  - コードに複数のエラーが含まれている場合は、順番に解決する必要があります。バリデーターは、以前に特定されたエラーが修正され、再度保存を試みた後にのみ、次のエラーを報告します。

    ![customjinjamultipleerror.gif](/images/moengage_0f6c23.png)

# 機能サポートマトリックス

次の表は、MoEngage 内のさまざまなチャネルと機能において、_Dynamic Content builder_ のコアモジュールがどこでサポートされているかを示しています。

| チャネル / モジュール | Conditional | Chip Actions | Custom Jinja Editor |
| --- | --- | --- | --- |
| **Email** | ✅ | ✅\* | ✅ |
| **Push** | ✅ | ✅ | ✅ |
| **SMS** | ✅ | ❌ | ✅ |
| **WhatsApp** | ✅ | ❌ | ✅ |
| **In-App** | ✅ | ❌ | ✅ |
| **OSM** | ✅ | ❌ | ✅ |
| **Inform** | ✅ | ❌ | ❌ |
| **Flows** | チャネル固有のノード（例: Flow 内の Email ノードや Push ノード）内でサポートされています。 | | |
| **Content Blocks** | ✅ | ✅\* | ✅ |
| **Template Management** | Email および OSM テンプレートでサポートされています。 | | |

_\* Chip Actions は、次の特定のエディターで使用できます:_

- _Email の場合: カスタム HTML エディターのみ。_
- _Content Blocks の場合: プレーンテキストエディターのみ。_

# よくある質問（FAQ）

<Accordion title="ユーザーが複数のルールに一致した場合はどうなりますか？">
  ルールは上から下へ順番に評価されます。ユーザーには一致した**最初の**ルールのコンテンツが表示され、そのルールセットの評価は停止します。
</Accordion>

<Accordion title="ユーザー属性、イベント属性、プロダクトセットを組み合わせて条件を作成できますか？">
  はい。**\+ Add Group condition** ボタンと **AND** 演算子を使用すると、1 つの条件ブロック内で異なる属性ソースを組み合わせることができます。これにより、特定のユーザー属性とプロダクトセット属性を同時に確認するなど、高度なロジックを作成できます。
</Accordion>

<Accordion title="Jinja を直接記述する場合とどう違いますか？">
  Dynamic Content Builder は、スピードと正確性を重視して設計されています。Jinja を手動で記述することも引き続き可能ですが、UI ビルダーを使用すると一般的な構文エラーを防ぎ、複雑なロジックを読みやすくし、マーケターがコーディングの専門家でなくてもパーソナライゼーションを作成できます。ほとんどの条件ロジックでは、この方法をお勧めします。
</Accordion>

<Accordion title="追加できる条件の数に制限はありますか？">
  いいえ、1 つの条件ビルダー内で追加できる `if-else` 条件の数に制限はありません。
</Accordion>

<Accordion title="エディターを使用してリンクや画像 URL をパーソナライズできますか？">
  はい。Dynamic Content Builder は、URL や画像ソースのフィールドなど、パーソナライゼーションをサポートするすべてのテキストフィールドで使用できます。これにより、ユーザー属性に基づいてディープリンクを動的に変更したり、異なる画像を表示したりできます。
</Accordion>
