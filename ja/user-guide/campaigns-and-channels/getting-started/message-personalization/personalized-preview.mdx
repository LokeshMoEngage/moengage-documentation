# 概要

_Personalization Preview_ 機能を使用すると、ターゲットオーディエンスのニーズに合わせてコンテンツを効果的に最適化できます。パーソナライズされたコンテンツがエンドユーザーにどのように表示されるかを視覚的に確認できます。プレビューにより、Jinja コードのエラーを特定し、文字単位での正確なエラー通知を受け取り、問題を修正して成果を高めることができます。

# パーソナライズプレビューをサポートするチャネル

パーソナライズプレビューを使用すると、ユーザーの 1 人を対象として、キャンペーンのパーソナライズされたメッセージをプレビューできます。

| チャネル             | パーソナライズのサポート |
| ------------------- | ------------------------- |
| Push                | はい                       |
| Email               | はい                       |
| SMS                 | はい                       |
| RCS                 | はい                       |
| MMS                 | はい                       |
| In-app Messaging    | はい                       |
| On-site Messaging   | はい                       |
| Cards               | いいえ                        |
| Connector           | いいえ                        |
| WhatsApp            | はい                       |
| Facebook Audience   | 該当なし                        |
| Google Ads Audience | 該当なし                        |

# パーソナライズプレビューでサポートされるパーソナライズの種類

パーソナライズプレビューは、ユーザー属性、イベント属性、Recommendations、Content API など、すべての種類のパーソナライズでサポートされています。

| パーソナライズの種類     | サポート |
| ------------------------ | ---------- |
| ユーザー属性           | はい        |
| イベント属性          | はい        |
| 商品セット             | はい        |
| Content API              | はい        |
| コンテンツブロック            | はい        |
| 補助データ           | はい        |
| キャンペーン属性       | はい        |
| ビジネスイベント属性 | はい        |
| クーポン                   | はい        |

# パーソナライズされたキャンペーンコンテンツをプレビューする

このセクションでは、キャンペーン内のパーソナライズされたコンテンツをプレビューする方法について説明します。

## Push、SMS、WhatsApp、In-app メッセージ、On-site メッセージ

1. キャンペーン作成プロセスのステップ 2 に移動します。

   ![CreatePushCampaign.png](/images/moengage_990af8.png)
2. **Preview type** で **Personalized** をクリックします。MoEngage がユーザーをランダムに選択し、そのユーザー向けのパーソナライズプレビューを表示します。
3. 編集アイコンを使用して、デフォルトのユーザーを変更します。

   <img
     alt="Screenshot_2021-08-31_at_12.03.43_PM.png"
     src="/images/moengage_652e30.png"
     style={{ width:"61%" }}
   />
4. **Select user by** リストと **User identifier value** リストを使用して、プレビューに使用するユーザーを選択します。

   <Frame>
     ![プレビューに使用](/images/use-for-preview.png)
   </Frame>
5. **Fetch user data** をクリックします。

   MoEngage は、キャンペーンで使用されているすべての属性を読み込みます。該当する場合は、フォールバックが属性の横に表示されます。
   - **ユーザー属性とイベント属性**: これらの値はユーザーデータから直接取得されます。属性値を変更したり、フォールバック値と実際の値を切り替えたりできます。\
     すべての値を選択したら、**Refresh**/**Update preview** をクリックして、選択した値でプレビューを表示します。

     <Tabs>
       <Tab title="旧 UI">
         ![image (3).png](/images/moengage_641ee8.png)
       </Tab>
       <Tab title="新 UI">
         ![SMSPREVIEW.png](/images/moengage_5f15fd.png)
       </Tab>
     </Tabs>
     <Note>
       お使いのアカウントで **Update Preview** を有効にするには、MoEngage のカスタマーサクセスマネージャー (CSM) またはサポートチームにお問い合わせください。
     </Note>
   - **商品セット**: これらの値は商品データから直接取得されますが、JSON として表示されます。要件に応じて JSON オブジェクトを変更し、**Refresh**/**Update preview** をクリックします。
   - **Content API**: MoEngage は、設定された API を使用してこれらの値を取得します。ここで JSON オブジェクト内の値をプレビュー用に変更できます。

     ![PersonalizedPreview.png](/images/moengage_879360.png)

     エンドポイントに到達できない場合は、空のレスポンスが表示されます。これにより、プレビュー用の一時的なデータを作成できます。
6. ユーザーを選択してプレビューしたら、スライドアウトを閉じてキャンペーンの変更を続行できます。選択したユーザーの詳細は、今後のプレビューのために保存されます。

# パーソナライズプレビューの出力を編集する

パーソナライズプレビューの出力を変更して、コンテンツをキャンペーンの目標やオーディエンスの好みにより適合させ、プレビューがマーケティングの意図を正確に反映するようにできます。

パーソナライズプレビューの出力を編集するには、次の手順を実行します。

1. **Personalized preview** ページで、パーソナライズ入力の横にあるテキストボックスをクリックし、データを入力します。商品セットリストを展開して編集アイコンをクリックすることで、商品セットを編集することもできます。出力を編集したら、**Refresh**/**Update preview** をクリックして更新します。

   <Note>
     お使いのアカウントで **Update Preview** を有効にするには、MoEngage のカスタマーサクセスマネージャー (CSM) またはサポートチームにお問い合わせください。
   </Note>
   <Tabs>
     <Tab title="旧 UI">
       ![edittttprevieww.gif](/images/moengage_a4d14f.png)
     </Tab>
     <Tab title="新 UI">
       ![EMAILpreview.png](/images/moengage_55e4a8.png)
     </Tab>
   </Tabs>
2. **Use sample data from the personalized preview for the test** トグルをオンにすると、更新されたパーソナライズプレビューの出力でキャンペーンをテストし、ローンチ前にパフォーマンスと効果を評価できます。

# エラー検出

<Note>
  これは早期アクセス機能です。お使いのアカウントで有効にするには、MoEngage のカスタマーサクセスマネージャー (CSM) またはサポートチームにお問い合わせください。
</Note>

パーソナライズに問題がある場合、プレビューペインにエラーの内訳が表示されます。

- メッセージに、壊れたユーザー属性やイベント属性など複数の問題がある場合は、すべて同時に表示されます。
- メッセージに商品セット/Content API/コンテンツブロック/AUX データに起因する問題がある場合は、最初に検出されたエラーカテゴリーが UI に表示されます。
- 各エラーには、エラーカテゴリー (発生源を特定するため) と説明 (解決方法を説明するため) が含まれます。

## エラーカテゴリーと説明

プレビューアーは、エラーを主要なグループに分類します。以下の表は、特定のカテゴリーがどのように報告されるかを、発生する可能性のあるエラーメッセージの例とともに示しています。

| エラーグループ                                                                             | 対象カテゴリー               | 説明と例                                                                                                                                                                    |
| --------------------------------------------------------------------------------------- | ------------------------------ | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| **個別カテゴリー**  <br />定義された機能に固有の属性またはリソース。 | ユーザー属性                | **エラーラベル:** "User attribute" **例:** `LastSeen is missing`                                                                                                                       |
|                                                                                         | イベント属性               | **エラーラベル:** "Event" または "Event attribute" **例 1:** `No event found for event name : MOE_WHATSAPP_DELIVERED in the last 15 days` **例 2:** `admin.admininvalid is missing` |
|                                                                                         | ビジネスイベント                | **エラーラベル:** "Business event attribute" **例:** `testInavlid is missing`                                                                                                          |

## カスタム Jinja エラーメッセージ

`MOE_NOT_SEND` タグを使用すると、テンプレート内でカスタム検証ロジックを定義できます。これにより、特定のビジネス条件やデータ要件が満たされない場合にメッセージが送信されないようにできます。これらのカスタムエラーは、テスト中は **Preview Pane** に、ローンチ後は **Analytics Error Breakdown** に表示されます。

### 例 1: 単一属性の検証

この例では、特定のイベントプロパティを検証します。属性が存在しない場合、MoEngage はプレビューをブロックし、定義されたエラーメッセージを表示します。

<CodeGroup>

```text Jinja wrap
{% if not EventAttribute['invalidEventAttribute'] %} {% MOE_NOT_SEND("invalidEventAttribute is missing") %} {% endif %}
```

</CodeGroup>

**プレビュー結果:** Preview Pane に、ブロッキングエラー "There are errors that are preventing the preview to load." が表示されます。**User attribute** セクションには、次の具体的なエラーが一覧表示されます: `1. First Seen not found for the u...: Custom error message provided by client.`

### ![2026-02-05_10-53-13.png](/images/moengage_d0ca03.png)

### 例 2: 集約検証 (複数のエラー)

複数の属性を同時に検証するには、`elif` チェーンではなく独立した `if` ステートメントを使用します。これにより、Preview Pane がすべての検証失敗を 1 つのリストに集約するため、欠落している複数のデータポイントを一度にデバッグできます。

<CodeGroup>

```text Jinja wrap
{% if not EventAttribute['Core_Observability.invalidAttribute'] %} {% MOE_NOT_SEND("Core_Observability.invalidAttribute is missing") %} {% endif %}
{% if not UserAttribute['invalidAttribute'] %} {% MOE_NOT_SEND("invalidAttribute is missing") %} {% endif %}
{% if not UserAttribute['invalidAttribute2'] %} {% MOE_NOT_SEND("invalidAttribute2 is missing") %} {% endif %}
```

</CodeGroup>

**プレビュー結果:** ユーザーに複数の属性が欠落している場合、Preview Pane はエラーをカテゴリー別に整理します。たとえば、このシナリオでは次のようになります。

- **Event attribute**
  - 1. Core_Observability.invalidAttribute is missing
- **User attribute**
  - 1. invalidAttribute is missing
  - 2. invalidAttribute2 is missing

<img
  src="/images/moengage_242c2b.png"
  alt="multipleerror.png"
  style={{ width:"84%" }}
/>

### 検証シナリオ

**シナリオ 1: すべてのデータが存在する場合**

- **入力:** 選択したユーザーに `Core_Observability`、`invalidAttribute`、`invalidAttribute2` の値があります。
- **結果:** メッセージは正常に表示されます。エラーペインは空のままです。

**シナリオ 2: 一部のデータが欠落している場合**

- **入力:** 選択したユーザーに `invalidAttribute2` が欠落していますが、その他の属性は存在します。
- **結果:** プレビューはブロックされます。
- **エラー出力:** ペインの **User attribute** カテゴリーに、次の 1 つのエラーが表示されます: `1. invalidAttribute2 is missing`。

# プレビューを確定する

1. 右側のペインでエラーを確認します。
2. Jinja コードを編集するか、サンプル属性値を変更します。
3. **Refresh**/**Update Preview** をクリックして、修正されたコンテンツを確認します。
4. **Use sample data from the personalized preview for the test** トグルをオンにすると、デバッグ済みのデータを使用してデバイスにテストを送信できます。

# FAQ

<Accordion title="プレビューペインで行った変更は、実際のユーザーのデータに影響しますか？">
  いいえ。Personalized Preview で属性やデータに加えた変更は一時的なものであり、プレビューの表示のみに使用されます。MoEngage 内の実際のユーザープロファイルが上書きされたり、保存されたりすることはありません。
</Accordion>

<Accordion title='"Refresh" ではなく "Update Preview" ボタンを表示するにはどうすればよいですか？'>
  **Update Preview** ボタンは、カスタマーサクセスマネージャー (CSM) によって有効化された場合にのみ表示されます。従来のインターフェースを使用している場合は、**Refresh** アクションが表示されます。
</Accordion>

<Accordion title="Content API エンドポイントに到達できない場合はどうなりますか？">
  エンドポイントに到達できない場合は、空のレスポンスが表示されます。プレビューウィンドウに一時的な JSON データを手動で入力して、キャンペーンをテストできます。
</Accordion>

<Accordion title="欠落している属性のエラーメッセージをカスタマイズできますか？">
  はい。MOE_NOT_SEND タグを使用して、カスタム検証ロジックを定義できます。これにより、特定の条件が満たされない場合にメッセージが送信されないようにし、プレビューペインにカスタムエラーメッセージを表示できます。
</Accordion>

<Accordion title="コードのエラーを修正しましたが、エラーリストが消えません。不具合ですか？">
  プレビューは入力中にリアルタイムで更新されません。テンプレート内の複数のエラーを修正した後、**Update Preview** (または **Refresh**) をクリックして検証を再実行する必要があります。これにより、エラーリストがクリアされる前に、すべての修正が一度に検証されます。
</Accordion>
