# 概要

ビジネスイベントトリガーキャンペーンは、システム内で特定のビジネスイベントが発生したときに顧客にメッセージを送信します。これらのキャンペーンを作成して使用するには、次の主な手順に従います。

1. API を使用して MoEngage で[ビジネスイベントを作成します](/ja/user-guide/campaigns-and-channels/getting-started/triggers/business-event/business-event-triggered-campaigns#create-the-business-event)。
2. このイベントを使用する[ビジネスイベントトリガーキャンペーンを作成します](/ja/user-guide/campaigns-and-channels/getting-started/triggers/business-event/business-event-triggered-campaigns#create-a-business-event-triggered-campaign)。
3. [ビジネスイベントをトリガーします](/ja/user-guide/campaigns-and-channels/getting-started/triggers/business-event/business-event-triggered-campaigns#trigger-the-business-event)。

ビジネスイベントトリガーキャンペーンは、次のようなシナリオで活用できます。

- OTT プラットフォームが新しいシリーズをリリースし、類似のコンテンツを視聴しているユーザーに通知したい場合。
- 商品が再入荷し、以前にその商品を閲覧したユーザーに知らせる必要がある場合。
- フライトや列車が遅延し、チケットを購入したユーザーにこの情報を伝える必要がある場合。

## ビジネスイベントを作成する

[Create Business Event API](https://www.moengage.com/docs/api/business-events/create-business-event) を使用して、NewSeriesAlert などのビジネスイベントを作成します。これは通常、イベントとその属性を定義するための 1 回限りの設定です。サンプルペイロードを以下に示します。

<CodeGroup>

```json Sample Payload wrap
--data '{
"event_name": "NewSeriesAlert",
"event_attributes": [
{
"attribute_name": "season",
"attribute_data_type": "string"
},
{
"attribute_name": "episodes",
"attribute_data_type": "int"
},
{
"attribute_name": "cast",
"attribute_data_type": "array"
},
{
"attribute_name": "genre",
"attribute_data_type": "string"
}
],
"created_by": "john.doe@example.com"
}'
```

</CodeGroup>

ビジネスイベントを作成したら、キャンペーンの作成に進むことができます。

## ビジネスイベントトリガーキャンペーンを作成する

<Note>
  1 つのビジネスイベントで開始できるキャンペーントリガーは、スライディングウィンドウで測定して、5 分間に最大 10 回、1 時間に最大 50 回です。制限を超えたトリガーでも `200` レスポンスが返されますが、キャンペーンは送信されずに停止状態で作成されます。ビジネスイベントのすべての制限については、[トリガーのレート制限](/ja/user-guide/campaigns-and-channels/getting-started/triggers/business-event/overview-business-events#trigger-rate-limits)を参照してください。
</Note>

<Tabs>

    1. MoEngage ダッシュボードの左側のナビゲーションメニューで **Engage** をクリックし、**Campaigns** をクリックします。
    2. All campaigns ページで、**\+** **Create campaign** をクリックします。
    3. **Outbound** で **Push** をクリックし、**Business Event Triggered** をクリックします。
    4. キャンペーン作成ページで、チーム (アカウントでチームが設定されている場合)、キャンペーン名、タグを追加します。
    5. **Select Business Event** ドロップダウンリストで、**BackInStock** イベントをクリックします。

         <img

         />
       </Frame>
    6. **Target audience** セクションで、ユーザー属性またはイベント属性をビジネスイベントの属性と動的に照合します。これにより、1 つのキャンペーンを多数のビジネスイベントに使用できます。

       たとえば、再入荷のビジネスイベントの場合、ユーザーが在庫切れの商品を閲覧していれば、その商品の 1 つ以上の属性 (商品 ID、商品名、アイテムコード、商品 URL、商品画像、ブランド、カテゴリーなど) をビジネスイベントの属性にマッピングできます。再入荷した任意の商品についてビジネスイベントがトリガーされると、このキャンペーンが実行されます。
       - **User Property**: ユーザープロパティまたはユーザー属性をイベント属性と照合します。ユーザープロパティに商品 ID が保存されている場合は、再入荷商品の商品 ID を含むビジネスイベント属性と照合できます。

         <Frame>
           ![User Property Push](/images/UserProperty_Push.png)
         </Frame>
         **注**: Array 属性の場合、ビジネスイベントのセグメンテーションでは次の演算子がサポートされています: _exists、does not exist、(any of) in the following、(all of) in the following、not in the following。_
       - **User Behavior**: 過去 25 日間に在庫切れ商品を閲覧したオーディエンスをターゲットにします。Business Event Attributes を使用して、ユーザーが閲覧した商品の属性と、再入荷した商品の属性を照合します。以下の例は、ユーザーが閲覧した商品の商品名、ブランド、アイテムコードを、再入荷した商品と照合する方法を示しています。

         <Frame>
           ![Push User Behavior(1)](/images/Push_Userbehavior\(1\).png)
         </Frame>
       - **User Affinity**: 以前に特定の商品に対して親和性を示したユーザーに商品をレコメンドします。以下の例では、過去 3 日間にその商品を閲覧したユーザーに再入荷商品が表示されます。

         <Frame>
           ![Push User Affinity](/images/Push_Useraffinity.png)
         </Frame>
    7. キャンペーンのプラットフォームとコントロールグループ (任意) を追加し、次のステップに進みます。
    8. Push キャンペーンのコンテンツを作成し、配信スケジュールを追加します。メッセージ、タイトル、サマリーをビジネスイベントの属性でパーソナライズできます。詳細については、[パーソナライズ](/ja/user-guide/campaigns-and-channels/getting-started/message-personalization/overview#event-attributes)を参照してください。
    9. キャンペーン作成のステップ 3 で、次の操作を行います。
       1. キャンペーンの **Start date** と **End date**、および配信のタイムゾーンを選択します。
       2. 必要に応じてコンバージョンゴールを追加します。
       3. 配信コントロールを追加して、フリークエンシーキャップを無視し、デフォルトのスロットリング制限を上書きします。
    1. キャンペーンを公開します。このキャンペーンは、ビジネスイベントがトリガーされたときに顧客にメッセージを送信します。

    </Note>

<Info>
  - セグメンテーションは動的であるため、キャンペーンまたはフローの作成時に到達可能なユーザー数を確認することはできません。この数は、キャンペーンまたはフローをトリガーするビジネスイベントに基づいて、実行時に計算されます。たとえば、コメディを好むユーザーをターゲットにして今後公開されるコメディシリーズについて知らせたい場合、キャンペーンに定義された動的セグメントの条件を満たす、コメディを視聴した、またはコメディを好むユーザーのみが Email を受信します。
  - セグメンテーションが機能するには、セグメンテーションで使用するイベント属性またはユーザープロパティのデータ型が、ビジネスイベントの属性のデータ型と一致している必要があります。属性が一致しない場合、セグメンテーションは実行されず、キャンペーンはユーザーに送信されません。
  - **All Users** セグメンテーションオプションを使用して、システム内のすべてのユーザーにビジネスイベントトリガーのキャンペーンまたはフローを送信することもできます。
  - ビジネスイベントのセグメンテーションフィルターでは、最大 60 日間の情報を参照できます。
</Info>

## ビジネスイベントをトリガーする

ビジネスイベントを設定し、それを使用するキャンペーンを作成したら、[Trigger Business Event API](https://www.moengage.com/docs/api/business-events/trigger-business-event) を使用してビジネスイベントをトリガーします。このアクションにより、キャンペーンが開始され、ターゲットユーザーにメッセージが送信されます。サンプルペイロードを以下に示します。

<CodeGroup>

```json Sample Payload wrap
--data '{
"event_name": "NewSeriesAlert",
"event_attributes": {
"season": "Season 1",
"episodes": 12,
"cast": ["John Doe", "Jane Doe"],
"genre": "Comedy"
},
"triggered_by": "john.doe@example.com"
}
```

</CodeGroup>
