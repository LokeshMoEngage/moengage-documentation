# はじめに

MoEngage の *Business Events* を使用すると、マーケターはユーザーのアクションではなくビジネスアクションに基づくイベントを作成し、これらのイベントが発生したときにキャンペーンを実行できます。

## イベントトリガーキャンペーンとビジネスイベントトリガーキャンペーンの比較

イベントトリガーキャンペーンとビジネスイベントトリガーキャンペーンは、どちらもイベントが発生したときに開始されます。ただし、次の違いがあります。

- イベントトリガーキャンペーンは、顧客による Web ページの閲覧 (*Web Page Viewed*) などのユーザーアクションによってトリガーされます。
- ビジネスイベントキャンペーンは、ブランドによる商品の再入荷など、ビジネス側で行われたアクションによってトリガーされます。

ビジネスイベントを使用すると、企業はこうした社内のビジネスアクションに基づくイベントを MoEngage 内で作成できます。

<Info>
ビジネスイベントは、Push、SMS & RCS、Email のチャネルでサポートされています。
</Info>

ビジネスイベントからは、キャンペーンと Flows の両方をトリガーできます。ビジネスイベントトリガーのフローを構築するには、[ビジネスイベントトリガーキャンペーン](/ja/user-guide/campaigns-and-channels/getting-started/triggers/business-event/business-event-triggered-campaigns)を参照してください。

## 手動でのキャンペーン作成の課題

毎日数千の商品が在庫切れになり、再入荷される e コマースブランドを考えてみましょう。10 個の商品が再入荷し、通知を希望した顧客に知らせたい場合、マーケターは通常、商品ごとに次の作業を行います。

1. 再入荷した商品ごとにセグメントを作成します。これには、商品の **Product ID** を、再入荷した商品の **Product ID** とマッピングする作業が含まれます。
2. 再入荷した商品ごとにキャンペーンコンテンツをパーソナライズします。
3. キャンペーンを公開します。

商品が再入荷するたびに新しいキャンペーンを作成するには多くの手作業が必要となり、エラーや機会損失につながる可能性があります。

MoEngage のビジネスイベントは、こうした手作業とオーバーヘッドを削減します。上記のすべてを 1 つのキャンペーンで実行できます。

## ビジネスイベントの仕組み

ビジネスイベントを使用して再入荷キャンペーンを実行するには、次の手順を実行します。

1. *BackInStock* という名前のビジネスイベントを作成します。**Product ID** や **Product Name** などのイベント属性を含めます。各商品の Product ID は一意です。
2. ユーザーのセグメントを作成します。再入荷キャンペーンでは、商品を閲覧したユーザー、または "notify me" オプションをクリックしたユーザーに通知します。商品を閲覧したユーザーについては、MoEngage が *ViewedProduct* イベントをトラッキングし、商品の **Product ID** がイベント属性として利用できます。在庫切れの商品を閲覧したユーザーに通知する動的セグメントを作成するには、**Product ID** イベント属性をビジネスイベントの **Product ID** 属性と動的にマッピングするようにセグメントを設定します。
3. ビジネスイベントトリガーキャンペーンを作成し、*BackInStock* イベントに関連付けます。
4. 商品が再入荷したときに BackInStock イベントをトリガーします。

この設定により、商品が再入荷するたびにキャンペーンが自動的に実行されます。マーケターは複数のキャンペーンを作成する必要はありません。多数の異なるキャンペーンを実行する代わりに、1 つのキャンペーンを設定するだけで、商品の再入荷時に自動的に実行されます。

# メリット

ユーザーのアクションだけでなくビジネスロジックに基づいてキャンペーンを自動化することで、この機能により、受動的なエンゲージメントから能動的なエンゲージメントへと移行できます。ビジネスイベントが主な課題にどのように対処するかを以下に示します。

- **手間をかけずに正確にターゲティング**: 適切なユーザーを適切なビジネスイベントに自動的に照合する動的セグメンテーションを活用できます。たとえば、ビジネスイベントの ProductID をユーザーがウィッシュリストに追加した商品の ProductID と照合するルールを一度作成するだけで、商品やアラートごとに手動でセグメントを作成し続ける必要がなくなります。これにより、運用上のオーバーヘッドなしで、キャンペーンを常にタイムリーかつ関連性の高いものにできます。
- **ハイパーパーソナライズの自動化:** `Product Name`、`Image URL`、`Ticket Price` などの属性をビジネスイベントからキャンペーンコンテンツに直接動的に取り込むことで、コンテキストに完全に合致したメッセージを配信できます。
- **かつてない規模の実現**: 数十、さらには数千もの手動の単発キャンペーンを、1 つのインテリジェントな自動化された親キャンペーンに置き換えられます。たとえば、1 つの "Back-in-Stock" キャンペーンでカタログ内のすべての再入荷商品を処理できるため、商品ごとに新しいキャンペーンを構築するという運用上の悪夢から解放され、コア戦略の最適化に集中できます。
- **統合された分析で重要な指標を測定**: 戦略のパフォーマンスを明確かつ包括的に把握できます。数百もの断片化されたキャンペーンレポートのデータを統合しようとする代わりに、"Price Drop Alerts" などのユースケースの全体的なビジネスインパクトを、単一の統合ダッシュボードからトラッキングできます。これにより、ROI の証明、アプローチの最適化、経営陣への有意義な結果の報告が容易になります。

# ユースケース

### e コマース

- 以前は入手できなかった商品が再入荷したときに、再入荷キャンペーンを送信します。
- 価格が下がったときにビジネスイベントトリガーを作成し、これらのトリガーに基づいてキャンペーンを作成することで、値下げアラートを自動化します。

### Over-the-Top プラットフォーム (OTT)

- お気に入りの Web シリーズの新しいエピソードやシーズンのリリースについて知らせることで、顧客のエンゲージメントを高めます。
- さまざまなアウトバウンドチャネルでキャンペーンを作成し、今週または今月に公開予定の映画や Web シリーズについてユーザーに通知することで、コンテンツをプロモーションします。
- 特定のジャンルを好むユーザーに新しい OTT シリーズのアラートを送信することで、類似のコンテンツをレコメンドします。たとえば、新しい犯罪捜査ドラマが公開された場合は、犯罪捜査ドラマの視聴を好むユーザーにアラートを送信します。

### 旅行・ホスピタリティ業界

- 航空会社の旅行者にフライトの遅延や欠航の情報を伝えます。
- 以前に閲覧したフライトチケットの値下げアラートを送信します。

### ユーザー生成コンテンツ

- ユーザーがフォローしているブロガーや人物がオンラインになったとき、またはライブセッションを開催しているときに更新情報を送信します。
- お気に入りのチャネルに新しい動画や投稿がアップロードされたときに更新情報を送信します。
- 以前に類似のコンテンツに関心を示したユーザーに、トレンドのコンテンツをレコメンドします。

# 制限とサポートされる属性

ビジネスイベントを設定する際は、次の点に注意してください。

- **ワークスペースあたりのビジネスイベント数**: ワークスペースごとに最大 50 個のビジネスイベントを作成できます。
- **サポートされる属性のデータ型**: イベント属性は、integer、float、string、date、array のデータ型をサポートしています。
- **重複排除なし**: MoEngage はビジネスイベントの重複排除を行いません。同じビジネスイベントを何度でもトリガーでき、各トリガーは独立して実行されます。同じビジネスイベントを繰り返しトリガーすることは、サポートされているユースケースです。

API の詳細については、[Business Events API (V5) リファレンス](/ja/api/business-events/business-events-v5/business-events-v5-overview)を参照してください。ビジネスイベントの作成、または既存の統合については、[Business Events API (Legacy) リファレンス](/ja/api/business-events/business-events-legacy/business-events-overview)を参照してください。

## トリガーのレート制限

レート制限は、ビジネスイベント自体をトリガーした回数ではなく、ビジネスイベントが開始した**キャンペーンとフローのトリガー**の数をカウントします。複数のキャンペーンやフローに関連付けられたビジネスイベントは、それぞれに対して 1 つのトリガーを生成し、各トリガーはそれぞれの制限にカウントされます。

| ビジネスイベントが実行する対象 | 制限 |
| --- | --- |
| キャンペーン | 5 分あたり 10 トリガー、1 時間あたり 50 トリガー、1 日あたり 200 トリガー |
| フロー | 1 時間あたり 3 トリガー、1 日あたり 10 トリガー |

MoEngage は、これらの制限を固定の時計の期間ではなく、**スライディングウィンドウ**で測定します。ウィンドウは常に現在の時点から、制限に応じて直前の 5 分間、1 時間、または 1 日を遡って参照します。そのため、古いトリガーがウィンドウから外れるにつれて、容量が徐々に回復します。1 時間あたりの制限は、毎正時にリセットされるわけではありません。

### 制限を超えた場合の動作

制限を超えたトリガーでも `200` レスポンスが返されます。MoEngage はダッシュボード上でキャンペーンを停止状態で作成し、送信しません。送信されるはずのメッセージが送信されなかった場合は、キャンペーンリストを確認してください。

<Note>
  `200` レスポンスは、トリガーが受信されたことを確認するものであり、キャンペーンが送信されたことを確認するものではありません。スロットリングされたトリガーも `200` を返します。配信を確認するには、レスポンスコードに頼るのではなく、キャンペーンの状態を確認してください。
</Note>

### 例: キャンペーンとフローに関連付けられた 1 つのビジネスイベント

`BackInStock` ビジネスイベントが 2 つのキャンペーンと 1 つのフローに関連付けられているとします。そのビジネスイベントを 1 回トリガーすると、次のトリガーが生成されます。

- 2 つのキャンペーントリガー (各キャンペーンに 1 つずつ)。
- 1 つのフロートリガー。

1 時間以内に `BackInStock` を 25 回トリガーすると、キャンペーンには 50 のトリガーが蓄積され、1 時間あたり 50 というキャンペーンの制限に達します。フローには 25 のトリガーが蓄積されるため、3 回目のトリガーの後に 1 時間あたり 3 という制限を超えます。

量だけでなく間隔も重要です。25 回のトリガーが短時間に集中した場合、キャンペーンは 5 回目のビジネスイベントトリガーの後に 5 分あたり 10 トリガーの制限に達し、1 時間あたりの制限が適用されるよりもずっと前に制限がかかります。ウィンドウはスライドするため、容量は固定のリセット時刻ではなく、最も古いトリガーがウィンドウから外れるにつれて解放されます。

## ビジネスイベントトリガーキャンペーンの配信タイミング

ビジネスイベントトリガーキャンペーンは、One-time キャンペーンと同じ配信 SLA に従います。

## ビジネスイベントトリガーのフローへの投入タイミング

ビジネスイベントトリガーのフローはユーザーを一括で投入し、1 回の実行で数百万人のユーザーを処理できます。この規模のため、ビジネスイベントがトリガーされてからユーザーがフローに入るまで最大 60 分かかる場合があります。時間に敏感なコミュニケーションを計画する際は、この点を考慮してください。
