# データのパーソナライゼーション

MoEngage では、ランディングページ向けの強力なパーソナライゼーションオプションを提供しています。@ を使用して、ランディングページのコンテンツや画像をパーソナライズできます。これらのパーソナライゼーション方法を組み合わせることで、ターゲットを絞った効果の高いランディングページを作成できます。User Attributes、User Events、Product Sets、Content APIs、Content Blocks を使用してコンテンツをパーソナライズできます。

ランディングページをパーソナライズするには、次の手順を実行します。

1. テンプレートを選択した後、テキストボックスまたは画像プロパティの URL をクリックします。
2. テキストエリア内の任意の場所に @ を入力して、属性を追加します。  
    <img alt="2024-12-17_15-10-00 (1).gif" src="/images/moengage_48556e.png" /> 同様に、ボタンをクリックして画像をパーソナライズできます。  
    <img alt="2024-12-17_15-21-06 (1).gif" src="/images/moengage_8508b1.png" />
3. **Landing Page Personalization** ウィンドウが表示されます。

**Data personalization** タブで、次の種類から属性を 1 つ選択します。

- User Attributes
- Product Sets
- Content API（Content API のパラメーターの値を変更します）

**Content Block** タブで:

1. リストからコンテンツブロックを選択します。
2. **Insert only the content of the content block** トグルをオンにします。これにより、コンテンツがコンテンツブロックから切り離され、今後の更新はページに反映されなくなります。
3. 属性またはコンテンツブロックを選択した後、テキストエリアで Jinja コードを編集できます。
4. 変更を編集したら、**Done** をクリックします。

フィールドのパーソナライゼーションをクリックすると、再度編集できます。パーソナライゼーションのためにリストから別の属性を選択しないでください。選択すると、テキストボックス内の Jinja コード全体が置き換えられます。

<img alt="2024-12-17_15-23-35 (1).gif" src="/images/moengage_216474.png" />

### フォールバックの選択

パーソナライゼーションの代替（フォールバック）として、次のいずれかを選択できます。

- **No fallback**: このオプションでは、パーソナライゼーションが機能しない場合に代替が表示されません。
- **Replace text**: パーソナライゼーションが機能しない場合に使用するテキストを入力または貼り付けます。

<Info>
カスタム属性が MoEngage の標準属性と同じ名前にならないようにしてください。同じ名前のカスタム属性と標準属性をパーソナライゼーションに使用すると、誤ったパーソナライゼーションになる可能性があります。
</Info>

# 動的テキスト置換

動的テキスト置換（Dynamic Text Replacement）を使用すると、URL クエリパラメーターに基づいてランディングページ上のテキスト要素を自動的に変更できます。この機能を使用すると、ランディングページ内の特定のテキスト要素（見出し、ボタンのテキスト、段落など）を動的に置き換えることができます。これにより、ユーザーがページにアクセスした状況に合わせた、高度にパーソナライズされたコンテンツを作成できます。

### ユースケース

- 広告キャンペーンの UTM パラメーターで言及されている特定のプロモーションを表示する（例: utm\_campaign=summer\_sale または utm\_campaign=winter\_sale）。解決はパラメーターの値に基づいて行われます。
- クエリパラメーターに基づいて地域固有の情報を表示する（例: region=asia）。
- トラフィックソースに基づいて挨拶やオファーをパーソナライズする（例: source=facebook）。

動的テキスト置換を設定するには、次の手順を実行します。

1. ランディングページテンプレートを選択した後、目的のテキストエリアに @ を入力します。**Landing Page Personalization** ウィンドウが表示されます。
2. **Dynamic text replacement** タブをクリックします。  
    <img alt="2025-04-22_11-25-09 (1).gif" src="/images/moengage_bdd851.png" />
3. UTM Parameter リストから、既存のクエリパラメーター名を選択します。必要なパラメーターがリストにない場合は、以下に示すように、パラメーター名（例: offer）を入力して新しく作成できます。  
    <img alt="2025-04-22_11-27-56 (1).gif" src="/images/moengage_8073f8.png" />
4. **Choose Fallback** セクションでは、指定した UTM パラメーターがページ URL に存在しない場合や値がない場合に表示する内容を決定できます。

   1. **Replace with user attribute (Optional)**: 特定のユーザー属性の値にフォールバックするには、リストから目的のユーザー属性を選択します。
   2. **Replace tex**t: 静的なテキスト文字列にフォールバックするには、**Fallback text** ボックスに目的のフォールバックテキストを入力します。<img alt="2025-04-22_11-32-03 (1).gif" src="/images/moengage_c2ab73.png" />
5. **Done** をクリックします。

作成したクエリパラメーターは、**URL and settings** セクションに表示されます。

<img alt="Screenshot 2025-04-22 at 11.44.21 AM.png" src="/images/moengage_64dd85.png" />

ランディングページが公開されると、クエリパラメーターがランディングページの URL に追加されます。1 つのランディングページ内に複数のパラメーター（例: \{location}、\{product} など）を定義でき、それぞれが動的に置き換えられます。

# パーソナライゼーションの仕組み

ランディングページをパーソナライズすることで、リアルタイムでつながりのある体験を作成できます。これらのパーソナライズされたランディングページを、E-mail、OSM、In-App メッセージなどの他のキャンペーンと統合し、ユーザーを誘導できます。

パーソナライズされた要素を含むランディングページを公開したら、そのページの URL を他のチャネルで使用できます。URL は、ドメイン名、ランディングページのパス、およびユーザー属性を含む *moe\_aid* で始まるクエリパラメーターで構成されます。  
  
たとえば、次のランディングページ URL の場合  
*https://landing-pages.mnge.co/Journey/example?moe_aid=`{{UserAttribute['aid']}}`*

- *landing-pages.mnge.co* はドメイン名です
- */Journey/example* はランディングページのパスです
- *moe\_aid=`{{UserAttribute['aid']}}`* はクエリパラメーターです

On-site メッセージキャンペーンを使用して、顧客をパーソナライズされたランディングページに誘導したい場合を考えてみましょう。これを行うには、OSM キャンペーンで URL を使用します。ユーザーがクリックすると、システムはクエリパラメーター *`{{UserAttribute['aid']}}`* を暗号化された形式のそのユーザーの ID に置き換えます。MoEngage のランディングページはこの ID を復号して、パーソナライズされたコンテンツを表示します。ユーザー属性の解決に失敗した場合は、フォールバックテキストが表示されます。

<Info>
正常に解決されるように、この URL は MoEngage のキャンペーンチャネル内でのみ使用してください。
</Info>
