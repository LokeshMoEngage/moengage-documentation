# 概要

MoEngage では、アカウント管理者がチームメンバーに対して (ダッシュボードコンポーネントへの) さまざまなレベルのアクセス権限を付与できるよう、ロールベースのアクセス制御を提供しています。

アクセスロールは、**Settings** \> **Account** \> **Team management** \> **Roles** に移動して確認できます。

# アクセスロールの種類

MoEngage では、MoEngage UI の権限を管理するために 2 種類のアクセスロールを提供しています。

- [デフォルトロール](/ja/user-guide/settings/account/team-management/access-roles#default-roles): すべてのアカウントで利用できる、固定の権限セットを持つ事前定義済みのロールです。これらのロールは変更できません。
- [カスタムロール](/ja/user-guide/settings/account/team-management/access-roles#custom-roles): 組織の要件に基づいて特定の権限セットを設定できる、ユーザー定義のロールです。

## デフォルトロール {#default-roles}

これらは固定の権限を持つデフォルトロールで、すべてのアカウントで利用できます。これらのロールは編集できません。MoEngage では、次のデフォルトロールを提供しています。

### Admin

ワークスペースを作成したユーザーには、デフォルトで Admin ロールが割り当てられます。このロールはアカウントに対するすべての権限を持ちます。

- キャンペーンの作成
- アカウント設定の変更
- チームメンバーの招待

Admin は、他のユーザーを Admin、Manager、Marketer などとして招待できます。新しい Teams を作成、編集、削除できるのは Admin のみです。

チーム管理の詳細については、[Teams in MoEngage](/ja/user-guide/settings/account/team-management/teams-in-moengage) を参照してください。

### Manager

ライブユーザー向けのマーケティングキャンペーンを実行し、アカウントとすべての設定を管理するユーザーです。このメンバーは、Teams の作成/編集/削除権限を除き、Admin と同様にダッシュボードのすべての権限を持ちます。1 つのアカウントに複数の Manager を設定できます。Manager は、Manager 以下のロールにチームメンバーを招待できます。

### Marketer

ライブユーザー向けのキャンペーンを作成するユーザーで、セグメンテーションにはアクセスできますが、請求情報にはアクセスできません。キャンペーン承認フローを使用している場合、Marketer のキャンペーンは Manager または Admin の承認を受けた場合にのみ公開されます。詳細については、[Campaign Approval Flow](/ja/user-guide/settings/account/team-management/campaign-approval-workflow) を参照してください。

### Developer

アプリ/Web を MoEngage と統合するユーザーです。このメンバーは TEST 環境ではすべての機能にアクセス/テストできますが、LIVE 環境ではアクセスが制限されます。アクセスの詳細は次のとおりです。

- 請求の詳細を表示できず、アカウントに追加できるのは Developer のみです
- Admin/Manager のチームメンバーが作成したキャンペーンを表示できません
- Push FC と DND の設定を変更できません

<Warning>
**Developer ロールのキャンペーンはテストユーザーにのみ配信されます**

ライブアプリでは、Developer ロールのユーザーが作成したキャンペーンは、選択したセグメントの全員ではなく、テストユーザーまたはテストデバイスとしてマークされたユーザーにのみ MoEngage から配信されます。この制限により、開発者がテストを行う間も本番環境のオーディエンスが保護されます。

キャンペーンのオーディエンスは、選択したセグメントとテストユーザーの共通部分になります。セグメントにテストユーザーが含まれていない場合、セグメント自体はユーザーを返しても、キャンペーンの受信者は 0 人になります。この場合もセグメンテーションは想定どおりに機能し、テストユーザーの制限を反映した正確な数を返します。
</Warning>

セグメント全体に配信するには、次のいずれかのオプションを選択します。

- ライブユーザーに公開できるロール (Admin、Manager、Marketer) を持つユーザーに、キャンペーンの作成、または既存キャンペーンの複製と送信を依頼します。
- Developer アカウントからキャンペーンを送信する前に、配信対象のユーザーをテストユーザーとしてマークします。
- Developer によるテストが目的の場合は、テストアプリからキャンペーンを送信します。

キャンペーンが [キャンペーン承認ワークフロー](/ja/user-guide/settings/account/team-management/campaign-approval-workflow) を経る場合、承認者が承認前にキャンペーンを編集すると、承認者自身のロールがキャンペーンに引き継がれ、キャンペーンのターゲットも変わります。詳細については、[How an Approver's Edit Changes Campaign Targeting](/ja/user-guide/settings/account/team-management/campaign-approval-workflow#how-an-approvers-edit-changes-campaign-targeting) を参照してください。

## カスタムロール {#custom-roles}

カスタムロールを使用すると、必要な権限セットを持つ新しいロールを作成できます。既存のロールを複製し、必要に応じて権限セットを割り当てることもできます。

<Info>
    ロールを作成/更新できるのは Admin のみです。
</Info>

### 新しいロールを作成する手順

1. **Settings \> Account \> Team management \> Roles** に移動します。 <img src="/images/moengage_5b43b3.png" alt="Roles_RevampedUI.png" />
2. ヘッダーの右上にある **Create role** をクリックします。 <img alt="Screenshot 2022-05-17 at 8.55.49 AM.png" src="/images/moengage_7d55e6.png" />
3. ロール名と説明を入力します。既存のロールから権限セットをコピーすることも、一から作成することもできます。 <img alt="Screenshot 2022-05-17 at 8.58.02 AM.png" src="/images/moengage_ca1ce8.png" />
4. **Create** をクリックします。
5. 要件に応じて権限のチェックを付けたり外したりできます。変更は自動的に保存されます。
