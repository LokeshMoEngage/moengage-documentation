# 概要

<Note>
  これは有料のアドオン機能です。アカウントで有効にするには、MoEngage のカスタマーサクセスマネージャー (CSM) またはサポートチームにお問い合わせください。
</Note>

_Portfolio_ 機能を使用すると、単一の統合された MoEngage ワークスペース内で、複数のアプリケーション (アプリ) やウェブサイトを個別の **Projects** として管理できます。この機能は、複数のデジタルプロパティ (たとえば、異なるブランドや複数の国での事業) を管理し、ユーザーデータとマーケティング活動を統合したいエンタープライズ向けに設計されています。すべてのアプリとウェブサイトを 1 つのワークスペースに集約することで、顧客の統合ビューを作成し、分析、セグメンテーション、エンゲージメントのための強力な機能を活用できます。

# ユースケース

Portfolio 構成を採用することで、マーケターはいくつかの重要なビジネス課題を解決できます。

- **統合された顧客ビュー**: すべてのアプリとウェブサイトのユーザーデータを、ユーザーごとに単一の包括的なプロファイルに統合し、カスタマージャーニー全体を把握できます。
- **クロスブランドセグメンテーション**: 異なるプロジェクトにまたがるユーザー行動に基づいて、強力なオーディエンスセグメントを構築できます。たとえば、複数のサブブランドでアクティブな顧客を特定し、ブランドをまたいだエンゲージメントに報いる単一のロイヤルティキャンペーンを送信できます。
- **クロスプロジェクトトリガーキャンペーン**: あるブランドでユーザーがカートを放棄したときに、別のブランドから類似商品を提案するキャンペーンをトリガーできます。たとえば、ある製品ラインの購入者に別の製品ラインの補完的なオファーをターゲティングしたり (クロスセル)、ユーザーがあるアプリでは非アクティブになったものの別のアプリではアクティブなままである場合に再アクティブ化オファーをトリガーしたり (解約防止) できます。
- **一元化されたキャンペーン管理**: 単一のダッシュボードから任意のプロジェクトに Push Notification キャンペーンを管理・配信し、運用を効率化できます。
- **包括的な分析**: すべてのデジタルプロパティにわたるユーザーエンゲージメント、コンバージョン、キャンペーンパフォーマンスを Portfolio レベルで把握できます。
- **ユーザーコミュニケーションの制御**: ブランド Portfolio 全体でユーザーへのコミュニケーション頻度 (Frequency Capping) と Do Not Disturb (DND) 時間を管理し、メッセージ疲れを防止できます。たとえば、最も適切なアプリから最も関連性の高い速報プッシュを 1 件だけ送信し、重複した通知を避けることができます。

# Portfolio の管理

**Project** は、Portfolio 内の単一のアプリまたはウェブサイトです。ワークスペースでは約 20 件のプロジェクトをサポートできます。

## プロジェクトの追加

1. MoEngage UI の左側のナビゲーションメニューで、**Settings** \> **Account** \> **Portfolio** をクリックします。 <img src="/images/moengage_7bd2a0.png" alt="portfolio1.gif" />
2. **Portfolio** ページで、**\+ Add Project** をクリックします。 <img src="/images/moengage_bd96b5.png" alt="portfolio2.png" />
3. **Add a new Project** ウィンドウで、次の値を入力します。
   | フィールド | 説明 |
   | --- | --- |
   | Project Name | 新しいプロジェクトの名前を指定します。必須です。プロジェクト名は最大 25 文字の英数字で、先頭は英字である必要があります。スペースや特殊文字は使用できません。 |
   | Project Icon | プロジェクトを表すアイコンを指定します。任意です。MoEngage 上で正しく表示されるように、最小解像度 72x72 ピクセルの画像をアップロードしてください。サポートされているファイル形式は次のとおりです。 <ul><li>PNG</li><li>GIF</li><li>WebP</li><li>ICO</li><li>CUR</li><li>BMP</li></ul> |
   | Type of Business | 設定するプロジェクトのビジネスモデルを指定します。必須です。利用可能なオプションは次のとおりです。 <ul><li>Offline / Storefront</li><li>Online</li></ul> |
   | Platform(s) | 設定するプロジェクトのプラットフォームを指定します。必須で、**Type of Business** フィールドの値が _Online_ に設定されている場合にのみ表示されます。サポートされているプラットフォームは次のとおりです。 <ul><li>Android</li><li>iOS</li><li>Web <br /></li></ul> **注**: 初期のプラットフォーム選択は、表示と初期設定のためのものです。プロジェクトがそのプラットフォームに固定されるわけではなく、後から他のプラットフォームを追加して設定できます。 |
4. **Save** をクリックします。\
   **Portfolio** ページにプロジェクトの詳細が表示されます。 <img src="/images/moengage_4333c6.png" alt="snnnnaaaappp.png" />

## プロジェクトの分析

**Portfolio** ページでは、設定されたすべてのプロジェクトの包括的な概要が表示され、プロジェクト関連情報を詳細に分析できます。次の詳細を確認できます。

![ProjectIDimg.png](/images/moengage_e07cb7.png)

- **Project Icon**: このプロジェクトに関連付けられたアイコンを示します。カスタムアイコンがアップロードされていない場合は、デフォルトのアイコンが表示されます。
- **Project Name**: このプロジェクトに割り当てられた一意の名前を示します。
- **Project ID**: プロジェクトに対して自動生成される一意の ID を示し、受信データの振り分けに使用されます。
- **Platform(s)**: プロジェクトの対象プラットフォーム (たとえば、iOS、Web、Android) を示します。
- **Last Updated By**: プロジェクトを最後に変更した日付とユーザーを表示します。プロジェクトの変更権限は、アプリ設定レベルに基づきます。詳細については、[Permission Levels](/ja/user-guide/settings/account/team-management/access-roles) を参照してください。
- **Created By**: プロジェクトを最初に作成したユーザーと作成日を示します。

## プロジェクトの編集

プロジェクトを編集するには、次の手順を実行します。

1. **Portfolio** ページに移動し、該当するプロジェクトの行を検索します。
2. 対象のエントリの省略記号 ( <Icon icon="ellipsis-stroke-vertical" /> ) アイコンをクリックし、**Edit** をクリックします。
3. **Add a New Project** ウィンドウで、必要な変更を行います。
4. **Save** をクリックします。

![Edit Project.gif](/images/moengage_297a2c.png)

<Info>
  - プロジェクトの変更に関する注意点は次のとおりです。
    - **Project Icon** はいつでも編集できます。
    - 新しいプラットフォームは追加できますが、既存のプラットフォームは削除できません。
  - データの整合性を確保するため、プロジェクトのアーカイブと削除は MoEngage サポートチームが対応します。詳しいサポートが必要な場合は、MoEngage のカスタマーサクセスマネージャー (CSM) またはサポートチームにお問い合わせください。
</Info>

# Portfolio の影響

_Portfolio_ 機能により、MoEngage の主要な領域での操作方法が変わります。

## データとユーザープロファイル

Portfolio 機能はデータとユーザープロファイルを一元化し、プロジェクトレベルと Portfolio レベルの両方で属性とイベントを管理できるようにします。この機能は、MoEngage でのデータの取り込みと管理に次のような影響を与えます。

- **Portfolio 固有およびプロジェクト固有の属性**: MoEngage では、カスタムおよび標準のユーザー属性とイベントをプロジェクトレベルで追跡できます。
  - 名、姓、携帯電話番号などの基本情報を含む標準属性は、Portfolio レベルの標準属性として追跡されます。
  - カスタムユーザー属性は、プロジェクトレベルと Portfolio レベルの両方で追跡できます。
  - 標準イベントとカスタムイベントは、プロジェクトレベルで追跡されます。\
    プロジェクトレベルと Portfolio レベルで追跡されるユーザー属性については、[Derived User Attributes Behaviour](/ja/user-guide/data/key-concepts/portfolio-data-ingestion-and-management#user-profile) を参照してください。
- **ユーザープロファイルビュー**: 複数のプロジェクトに存在するユーザーの場合、プロファイルページにドロップダウンメニューが表示され、各プロジェクトにおける属性とアクティビティを確認できます。
- **データ管理**: Data Management セクションでは、一意のイベントとユーザー属性の Portfolio レベルの概要が表示されます。これにより、プロジェクト間でデータを管理できます。Portfolio 全体でのデフォルトの上限は、一意のイベント 1024 件、一意のユーザー属性 1024 件です。
- **データの取り込み**: Data API と SDK を使用して Portfolio にデータを取り込むことができます。

詳細については、[Portfolio: Data Ingestion and Management](/ja/user-guide/data/key-concepts/portfolio-data-ingestion-and-management#data-ingestion) を参照してください。

## セグメンテーション

セグメンテーションツールを使用すると、複数のプロジェクトにまたがるルールを構築できます。異なるアプリやウェブサイトでの行動を組み合わせて、クロスターゲティング用の非常に具体的なオーディエンスを作成できます。

- **クロスプロジェクトルール**: セグメントを構築する際、各ルールに _Project_ ドロップダウンリストが表示され、あるプロジェクトでの行動と別のプロジェクトでの属性に基づいてユーザーをフィルタリングできます。
- **Portfolio レベルのフィルタリング**: ユーザーイベントについては、_Portfolio_ を選択すると、いずれかのプロジェクトでアクション (_Purchase_ など) を実行したユーザーを検索でき、広範な "OR" 条件を作成できます。
- **到達可能性の計算**: セグメントビルダーに表示される到達可能数は **グローバル** な数 (少なくとも 1 つのプロジェクトで到達可能なユーザー) であることを理解しておくことが重要です。そのセグメントをキャンペーンで使用すると、数は **プロジェクト固有** になり、キャンペーンの送信先である単一のプロジェクトで到達可能なユーザーのみが表示されます。

詳細については、[Segmentation in a Multi-Project Portfolio](/ja/user-guide/segment/advanced-concepts/segmentation-in-a-multi-project-portfolio#overview) を参照してください。

## Email 設定

Portfolio 機能は設定を一元化し、次の機能を通じてブランドの一貫性があり文脈に即した Email キャンペーンを実現します。

- **プロジェクト固有の設定**: Project ドロップダウンリストを使用して、Portfolio 内の各プロジェクトに固有の設定を選択して適用します。これにより、Overview、Sender Configuration、General Settings、Subscription Management、Font Management、PII Tokenization の設定をプロジェクトごとに独立して維持できます。
- **文脈に応じたパーソナライゼーション**: キャンペーン作成時に利用可能なユーザー属性が自動的にフィルタリングされ、送信元プロジェクトに関連するデータのみが表示されるため、ブランドの一貫性を維持できます。
- **プロジェクトレベルの到達可能性**: 各ユーザーの Email 購読ステータスはプロジェクトごとに個別に追跡されるため、ユーザーはあるプロジェクトでは到達可能で、別のプロジェクトでは到達不可能な場合があります。

<Warning>
  プロジェクトレベルの Email が有効になる前に、ワークスペースで _Portfolio_ 機能を使用して Email キャンペーンを実行していた場合、それらの既存キャンペーンを編集または複製することはできません。プロジェクトレベルの到達可能性とプロジェクトレベルの Email 設定は、既存のキャンペーンを編集するか新しいキャンペーンを作成した時点で有効になり、既存キャンペーンの設定が無効になる可能性があります。代わりに、該当するプロジェクトで新しい Email キャンペーンを作成してください。
</Warning>

詳細については、[Portfolio for Email Campaigns](/ja/user-guide/campaigns-and-channels/email/getting-started-with-email/portfolio-for-email-campaigns#overview) を参照してください。

## Push 設定

Portfolio 機能は主要な設定を一元化し、次の機能を通じて Push キャンペーンが常にブランドの一貫性を保ち、文脈に即したものになるようにします。

- **プロジェクト固有の設定**: Portfolio 内の各プロジェクトに、Mobile App Push、Web Push、Push Previews の固有の設定を個別に適用できます。
- **文脈に応じたパーソナライゼーション**: キャンペーン作成時に利用可能なユーザー属性が自動的にフィルタリングされ、送信元プロジェクトに関連するデータのみが表示されるため、ブランドの一貫性を維持できます。

詳細については、[Portfolio for Push Campaigns](/ja/user-guide/campaigns-and-channels/mobile-push/getting-started-with-mobile-push/portfolio-for-push-campaigns#overview) を参照してください。

## In-app Messaging 設定

Portfolio 機能は設定を一元化し、次の機能を通じて、ブランドの一貫性を維持しながら In-app キャンペーンが正しいアプリケーションのコンテキストで配信されるようにします。

- **プロジェクト固有の配信**: 作成時に特定のプロジェクトとプラットフォーム (iOS/Android) を選択することで、キャンペーンをホストするモバイルアプリケーションを制御できます。
- **文脈に応じたパーソナライゼーション**: ユーザー属性が自動的にフィルタリングされ、対象プロジェクトに関連するものまたはグローバルデータのみが表示されるため、ブランドの整合性を維持できます。

詳細については、[Portfolio for In-app Campaigns](/ja/user-guide/campaigns-and-channels/in-app-message/getting-started-with-in-app-message/portfolio-for-in-app-campaigns#overview) を参照してください。

## On-site Messaging 設定

Portfolio 機能は設定を一元化し、次の機能を通じて Web オーバーレイがドメインに正確で文脈に即したものになるようにします。

- **プロジェクト固有のターゲティング**: キャンペーンごとに特定のプロジェクトと Web プラットフォームを選択することで、OSM キャンペーンが正しいウェブサイトにのみ表示されるようにします。
- **文脈に応じたパーソナライゼーション**: パーソナライゼーションリストが自動的にフィルタリングされ、送信元プロジェクトの属性とグローバル属性のみが表示されるため、ブランド間のデータ漏洩を防止できます。

詳細については、[Portfolio for OSM Campaigns](/ja/user-guide/campaigns-and-channels/on-site-message/getting-started-with-on-site-message/portfolio-for-on-site-messaging#overview) を参照してください。

## キャンペーン

Portfolio 機能は複数のプロジェクトにまたがる顧客データを統合し、次の主要な機能を通じてキャンペーンのセグメント化、パーソナライズ、分析の方法を強化します。

<Info>
  _Portfolio_ 機能は、Push API で作成されたキャンペーンではサポートされていません。動的条件を使用する Flows もサポートされていません。
</Info>

- **プロジェクト固有のターゲティング**: キャンペーンを送信するプロジェクトを制御し、すべてのブランディングとディープリンクがその特定のブランドにとって文脈上正しいものになるようにします。これは Push、Email、In-app、OSM チャネルでサポートされています。
- **クロスプロジェクトセグメンテーション**: 関連付けられた任意のプロジェクトのユーザー行動と属性を組み合わせたルールを構築し、正確なオーディエンスを作成できます。
- **クロスプロジェクトトリガーキャンペーン**: あるプロジェクトでのユーザーのリアルタイムのアクションに基づいて別のプロジェクトからキャンペーンをトリガーし、自動化されたクロスプロモーション戦略を実現できます。これは In-app および OSM チャネルには適用されません。
- **個別のプロジェクト分析**: 固有の到達可能性属性を使用して、プロジェクトごとにプッシュ通知のオプトイン率を個別に分析・比較できます。これは Push チャネルでのみサポートされています。
- **集約された到達可能性**: すべてのプロジェクトにおけるステータスに基づいて、ユーザーの全体的な到達可能性を判断します。少なくとも 1 つのプロジェクトからの通知にオプトインしている場合、そのユーザーは到達可能と見なされます。

_Portfolio_ 機能のチャネル別サポートマトリックスの詳細については、[Supported Features by Channel](/ja/user-guide/settings/account/portfolio/portfolio#supported-features-by-channel) を参照してください。

## Global Frequency Capping

_Portfolio_ 機能を使用すると、ブランド Portfolio 全体でコミュニケーション頻度を管理できます。すべてのプロジェクトからユーザーが受信するコミュニケーションの総数を制限する _Global Frequency Capping_ を設定することで、メッセージ疲れを防止します。

- Portfolio レベルでマスターの頻度上限を設定できます。この上限はユーザーごとに適用され、ワークスペース内のすべてのプロジェクトから送信されるコミュニケーションの総数に適用されます。\
  たとえば、グローバル上限が 5 件に設定されている場合、3 つの異なるプロジェクトに属するユーザーが受信するコミュニケーションは、3 つのブランドを合わせて最大 5 件になります。
- グローバル上限が全体のボリュームを制御する一方で、_タグベースの頻度上限_ を使用すると、より詳細なプロジェクト固有の制御が可能です。\
  たとえば、特定のプロジェクトからのメッセージを 3 件に制限するには、次のようにします。
  - その特定のプロジェクトで実行されるすべてのキャンペーンに一意のタグを追加します。
  - その特定のタグが付いたコミュニケーションを 3 件に制限する頻度上限ルールを設定します。

詳細については、[Frequency Capping](/ja/user-guide/settings/channels/delivery-controls/frequency-capping#overview) を参照してください。

# チャネル別のサポート機能

到達可能性やクロスプロジェクトトリガーなど、Portfolio の主要機能の利用可否はコミュニケーションチャネルによって異なります。次の表に、各チャネルでサポートされている機能を示します。\
**_\*Not Supported: これらのチャネルでは、ワークスペース上で Portfolio のユーザーインターフェイス要素を利用できません。_**

| チャネル | 到達可能性レベル | クロスプロジェクトセグメンテーション | クロスプロジェクトイベントトリガー |
| --- | --- | --- | --- |
| **Push** | Project | Supported | Supported |
| **Email** | Project | Supported | Supported |
| **SMS & RCS** | Portfolio | Supported | Supported |
| **WhatsApp** | Portfolio | Supported | Supported |
| **In-App Messaging** | Not Applicable | Supported | Not Applicable |
| **On-site Messaging** | Not Applicable | Supported | Not Applicable |
| **Cards** | Not Applicable | Supported | \*Not Supported |
| **Connectors** | Not Applicable | Supported | Supported |
| **Facebook Audience** | Not Applicable | \*Not Supported | \*Not Supported |
| **Google Ads Audience** | Not Applicable | \*Not Supported | \*Not Supported |
| **Inform** | \*Not Supported | \*Not Supported | \*Not Supported |
| **Flows** | Not Applicable | \*Not Supported | \*Not Supported |

<Info>
  - **プロジェクトレベルの到達可能性**: ユーザーのオプトインステータスは、プロジェクトごとに個別に追跡されます。
  - **Portfolio レベルの到達可能性**: ユーザーのオプトインステータスは、Portfolio 内のすべてのプロジェクトに適用されます。プロジェクト固有のオプトインステータスはありません。
  - **Not Applicable**: これらのチャネルには、Push や Email と同じ意味でのオプトイン到達可能性の概念がありません。
  - **\*Not Supported**: ダッシュボードでは、これらのチャネルに対して Portfolio の UI 要素が提供されません。
    - クロスプロジェクトセグメンテーションを使用するには、次のいずれかを行います。
      - カスタムセグメントを使用して、プロジェクトをまたいでキャンペーンをターゲティングします。
      - プロジェクトレベルのユーザー属性を使用してセグメントを作成します。イベントベースのセグメンテーションの場合は、_project name_ イベント属性を選択し、値としてプロジェクト名を指定します。
    - _project name_ イベント属性を選択し、値としてプロジェクト名を指定することで、クロスプロジェクトイベントトリガーを使用できます。
</Info>

<Note>
  _Portfolio_ 機能は Web Personalization チャネルをサポートしていないため、上記の表には記載されていません。
</Note>

# FAQ

<Accordion title="同じ人が私の 2 つのアプリを使用している場合、MoEngage はその人を 1 人の統合ユーザーとして扱いますか?">
  はい。Portfolio 機能の主な目的は、すべてのアプリとウェブサイト (Projects) のデータを **ユーザーごとに単一の包括的なプロファイル** に統合し、ブランドをまたいだジャーニー全体の統合ビューを提供することです。
</Accordion>

<Accordion title="ユーザーの詳細やアクション (属性とイベント) は、異なるプロジェクト間でどのように扱われますか?">
  "First Name" や "Mobile Number" などの標準的な詳細は、**Portfolio レベル** で追跡されます (ユーザーごとに 1 つの値)。カスタム属性は、Portfolio レベルまたはプロジェクトレベルのいずれかで設定できます。ただし、すべてのユーザーアクション (イベント) は **プロジェクトレベル** で追跡されるため、どのアプリまたはウェブサイトでアクションが発生したかを常に把握できます。
</Accordion>

<Accordion title="複数のプロジェクトのデータを使用して強力なセグメントを作成しました。キャンペーンで使用しようとしたときにオーディエンスサイズが減少したのはなぜですか?">
  これは想定どおりの動作です。セグメントビルダーには、条件を満たし、少なくとも 1 つのプロジェクトで到達可能なユーザーの **グローバル数** が表示されます。そのセグメントを特定のプロジェクトのキャンペーンで使用すると、数は **プロジェクト固有** になり、その特定のプロジェクトで到達可能なユーザーのみが表示されます。
</Accordion>

<Accordion title="Portfolio を設定する際に注意すべき制限や、後から変更できない選択はありますか?">
  はい。知っておくべき重要な点が 2 つあります。

  - 1 つのワークスペースでサポートできるプロジェクトは約 **20 件** です。
  - プロジェクトにプラットフォーム (iOS や Android など) を追加した場合、その選択は永続的です。追加した後に **プラットフォームを削除することはできません**。
</Accordion>

<Accordion title="不要になったプロジェクトを削除するにはどうすればよいですか?">
  ダッシュボードからプロジェクトを自分で削除またはアーカイブすることはできません。データの整合性を確保するため、MoEngage のカスタマーサクセスマネージャー (CSM) またはサポートチームにお問い合わせください。
</Accordion>
