MoEngage Inform は、複数のチャネルにわたる統合メッセージングインフラストラクチャを提供し、トランザクションアラートの構築と管理を容易にします。

# トランザクションアラート

ブランドが顧客に送信する、時間的制約のあるトランザクションコンテンツはすべてトランザクションアラートです。トランザクションアラートの例を以下に示します。

- 注文/予約/購入の確認と関連する更新
- 発送/配達の確認と該当する更新
- 不正防止のためのセキュリティおよびアカウントアラート
- パスワードのリセット
- OTP（ワンタイムパスワード）/ 認証コード
- ユーザーの招待と共有
- 以前のトランザクションに関連するユーザーの未操作

# 従来のトランザクションメッセージング構造

通知は、マルチチャネルのトランザクションメッセージング構造を使用して、複数のチャネルで同時に送信されます。このような構造を実装するには、次のことが必要です。

1. 複数のチャネル用の API を構築する
2. すべてのチャネルとベンダーにわたってこれらの API を保守する
3. ベンダー契約を管理する

## 従来の構造 - 欠点

現在のトランザクションメッセージングインフラストラクチャには、以下の欠点があります。

- 必要な開発者リソースの不足 - わずかな変更を行う場合でも、エンジニアリングリソースに大きく依存する
- アラート（メッセージ）のパフォーマンスに関する可視性の欠如 - アラート、コンテンツテンプレート、配信パートナーを管理する一元化されたダッシュボードがない
- コンテンツに対する制御の欠如 - エンジニアリングリソースを待つ必要があるため、プロダクト、コンテンツ、マーケティングの各チームがコンテンツやアラートロジックを制御できる範囲が限られる

# MoEngage Inform

MoEngage Inform を使用すると、ブランドは One API を通じて、チャネルをまたいでトランザクションアラートを構築および管理できます。迅速に構築と反復を行い、容易にスケールできます。

## メリット

MoEngage Inform を使用すると、ブランドはコードを変更またはデプロイすることなく、単一のダッシュボードを利用できます。以下のことに役立ちます。

- 複数のチャネルでパーソナライズされたトランザクションメッセージを送信する
- 新しいチャネルを追加する
- 数分でテンプレートを構築および編集する
- メッセージングベンダーをシームレスに切り替える
- エンドツーエンドのログを使用してリアルタイムで簡単にデバッグする
- プロダクト、グロース、マーケティングの各チームと連携してアラートを分析および最適化する

# 制限と動作

Inform は、ほとんどのシナリオで基盤となるチャネル（SMS、WhatsApp、Email、または Push）の配信動作を継承します。このセクションでは、Inform 固有の動作と制限について説明します。

## インプレッショントラッキング

Inform アラートのインプレッショントラッキングは、標準の Push キャンペーンと同じように機能します。Inform 固有の実装や動作はありません。 

詳細については、[**Push Analytics and Info**](/ja/user-guide/campaigns-and-channels/mobile-push/analyze/push-analytics-and-info) を参照してください。

## フォールバックの動作

Inform は、以下のフォールバックメカニズムをサポートしています。

- **Sender fallback**: ユーザーまたは API の属性に基づいて送信者を自動的に選択します。設定された条件がいずれも満たされない場合、Inform は設定済みのフォールバック送信者を使用します。詳細については、[**Dynamic Sender Routing**](/ja/user-guide/inform/advanced-concepts/dynamic-sender-routing) を参照してください。
- **Channel fallback (on sender failure)**: ペイロードエラー、ベンダーからの 4xx または 5xx レスポンス、またはベンダーによる拒否により、デフォルトチャネルでベンダーへの送信に失敗した場合、Inform はアラートを設定済みの第 1 および第 2 のフォールバックチャネルにルーティングします。これは、アラート作成時に **Set Channel Sending Order** でアラートごとに設定できます。詳細については、[**Channel Sending Order**](/ja/user-guide/inform/create/create-alert#alert-details) を参照してください。
- **Channel fallback (on delivery failure)**: デフォルトチャネルがアラートを受け付けたものの、設定可能な待機時間枠（1～60 分）内に配信されなかった場合、Inform は設定済みのフォールバックチャネルで配信を再試行します。これは、**Set Channel Sending Order** でアラートごとに設定できます。詳細については、[**Channel Sending Order**](/ja/user-guide/inform/create/create-alert#alert-details) を参照してください。
- **Template fallback**: 設定されたテンプレート選択条件が満たされない場合に、アラートをフォールバックテンプレートにルーティングします。詳細については、[**Dynamic Template Selector**](/ja/user-guide/inform/advanced-concepts/dynamic-template-selector) を参照してください。

## 件名とコンテンツの制限

Inform では、基盤となるチャネルによって適用される制限以外に、コンテンツや件名に関する追加の制限はありません。

使用しているチャネルについて記載されている制限に従ってください。たとえば、WhatsApp テンプレートでは本文に 1,024 文字の制限が適用されます。詳細については、[Common Errors in WhatsApp Campaigns](/ja/user-guide/campaigns-and-channels/whatsapp/troubleshooting-and-faqs-whatsapp/common-errors-in-whatsapp-campaigns) を参照してください。

## スループット（RPM）

Inform のスループットは契約によって決まります。デフォルトでは、Inform は 1 分あたり 10,000 リクエスト（RPM）をサポートしています。

- スループットの制限はチャネルに依存しません。つまり、SMS、WhatsApp、Email、Push のいずれでアラートを送信する場合でも、同じ RPM が適用されます。 
- 1 つの Inform API リクエストが複数のチャネルを対象とする場合、設定された各チャネルに個別のメッセージが生成されますが、API リクエストとしては 1 件とカウントされます。 

スループットの制限を変更するには、MoEngage のカスタマーサクセスマネージャー（CSM）またはサポートチームにお問い合わせください。

## IP ホワイトリスト

Inform では、IP ホワイトリストはデフォルトで有効になっていません。組織で MoEngage の IP アドレスを許可リストに追加する必要がある場合は、MoEngage のカスタマーサクセスマネージャー（CSM）またはサポートチームに連絡して、ワークスペースの IP ホワイトリストをリクエストしてください。
