これらは、アラートで受信したリクエストごとに生成されるログです。Alert Logsには次の機能があります。

- **可用性**: システムがリクエストを処理するとすぐに、ログが利用可能になります。
- **並べ替え**: ログはリクエストを受信した時刻順に並べ替えられます。
- **リアルタイム更新**: セクションの右上にあるRefreshボタンをクリックすると、ログをリアルタイムで更新できます。

# アラートログを検索する

Alert Logsは、リクエストのステータス、チャネルレベルのフィルター、およびリクエストID、トランザクションID、受信者IDなどの一意の識別子に基づいてアラートのパフォーマンスを分析する手段です。次の条件を使用してログを検索できます。

## リクエストIDまたはトランザクションIDで検索する

リクエストIDは、MoEngageが受信したリクエストに付与される一意の識別子です。トランザクションIDは、ユーザーにアラートが送信される対象のトランザクションを識別する一意の識別子です。トランザクションIDはお客様が生成および管理し、リクエストとともにMoEngageに渡します。\
リクエストIDまたはトランザクションIDで検索するオプションを使用すると、Alert Logsで特定のリクエストまたはトランザクションのログを検索し、ダッシュボードでそのステータスを確認できます。

## 重複リクエスト

トランザクションIDを使用して検索することで、重複リクエストを検索できます。5分以内に、以前に成功したリクエストまたは処理中のリクエストと同じトランザクションIDを含むリクエストは、重複とみなされます。\
注: リクエストが重複とみなされるには、リクエストIDとトランザクションIDが完全に一致する必要があります。部分一致では機能しません。

## チャネルで検索する

このオプションを使用すると、選択したチャネル（SMSおよび/またはEmail）に基づいてリクエストをフィルタリングし、リクエストまたは配信のステータスを使用してリクエストを分析できます。

## リクエストのステータスで検索する

このオプションを使用すると、ステータスに基づいてリクエストをフィルタリングできます。ステータスで使用できるフィルターオプションは次のとおりです。

| リクエストのステータス | 説明 |
| --- | --- |
| **Request Failed** | このオプションでは、次のいずれかの理由でアラートの処理に失敗したすべてのリクエストが表示されます。 <ul><li>アラートIDが正しくない</li><li>ペイロード情報が正しくない</li><li>トランザクションIDが無効である</li><li>ペイロードに必須フィールドがない</li><li>レート制限が設定されたRPMを超えた</li><li>非アクティブな（一時停止または削除された）アラートのアラートIDである</li></ul> |
| **Request Dropped** | このオプションでは、アラートで破棄されたすべてのリクエストが表示されます。リクエストは、アラートが一時停止されている場合、トランザクションが処理中の場合、重複リクエストを受信した場合、またはMoEngage Informの処理時間が1時間を超えた場合に破棄されます。 |
| **Request Processing** | このオプションでは、アラートで現在処理中のすべてのリクエストが表示されます。ベンダーへの送信を試行中のリクエストは、現在処理中のリクエストとなります。 |
| **Delivery Successful** | このオプションでは、正常に配信されたすべてのリクエストが表示されます。 |
| **Delivery Pending** | このオプションでは、まだ配信されていないすべてのリクエストが表示されます。これらは、MoEngageによって処理され、さらに処理するためにベンダーに送信されたメッセージです。 |
| **Delivery Failed** | このオプションでは、まだ配信されていないすべてのリクエストが表示されます。これらは、MoEngageによって処理され、さらに処理するためにベンダーに送信されたメッセージです。 |
| **Delivery Info NA** | このオプションでは、配信情報が利用できないすべてのリクエストが表示されます。 |

## 指定した期間内で検索する

このオプションを使用すると、指定した日付の範囲内でリクエストをフィルタリングできます。

## 受信者IDで検索する

このオプションを使用すると、受信者ID（プッシュ通知の場合はPush Token、Eメールの場合はEmail ID、SMSの場合は携帯電話番号）に基づいてリクエストをフィルタリングできます。

## Time to Sendで検索する

このオプションを使用すると、MoEngageがメッセージの送信に要した時間に基づいてリクエストをフィルタリングできます。このフィルターでは、最小および最大の配信時間を秒単位で指定できます。

# リクエストの詳細

ログセクションの各行には、アラートで受信したリクエストに関する情報が含まれます。ログ内の各リクエストでは、次の情報を確認できます。

| リクエストの詳細 | 説明 |
| --- | --- |
| **Received Time** | MoEngageがAPI呼び出し経由でリクエストを受信した時刻です。 |
| **Request ID** | このAPI呼び出しに対してMoEngageが生成した一意の識別子です。MoEngageは、受信したすべてのAPI呼び出しに対して、一意の識別子としてRequest IDを提供します。 |
| **Channel** | リクエストが処理されたチャネルです（例: SMSまたはEmail）。チャネルの横にある送信者アイコンは、[Dynamic Sender Routing](/ja/user-guide/inform/advanced-concepts/dynamic-sender-routing)のロジックによって、アラートの送信にどの送信者が自動的に選択されたかを示します。  <br />**Push** チャネルの場合、**Message type for iOS** が **Live Activity Only** または **Live Activity with Push Fallback** であれば、ログページにはStart、Update、EndなどのLive Activity固有のステータスが表示されます。これらのインジケーターは、プッシュ通知の詳細を表示するときにログエントリに表示されます。  <br />Live Activityは、次の3つの段階で構成されます。<br /> <ul><li>**Start**: 初めて通知を開始します。</li><li>**Update**: アクティビティ中に送信される中間ステップまたはデータの更新を表します。</li><li>**End**: トランザクションの完了を示す最後の呼び出しです。  <img alt="Screenshot 2026-01-09 at 12.59.05 PM.png" src="/images/moengage_6cf805.png" /></li></ul> 詳細については、[Transactional Live Activites](/ja/user-guide/campaigns-and-channels/mobile-push/notification-features-and-behavior/transactional-live-activities)を参照してください。 |
| **Status** | リクエストのステータスを示します。リクエストで考えられるステータスの詳細については、[リクエストのステータス](/ja/user-guide/inform/analyze/alert-logs#search-by-request-status)を参照してください。 |
| **Failure Reason** | MoEngageがリクエストを処理できなかった場合、またはベンダー側で失敗が発生した場合に、失敗の理由を示します。 |
| **Recipient ID** | メッセージの配信先となるチャネルの宛先識別子です。たとえば、プッシュ通知の場合はPush Token、Eメールの場合はEmail ID、SMSの場合は携帯電話番号です。 |
| **Transaction ID** | トランザクションごとにお客様が渡す必要がある識別子です。Transaction IDの横にあるフォールバックアイコン <img alt="Screenshot 2025-08-06 at 5.12.06 PM.png" src="/images/moengage_0861af.png" /> は、プライマリチャネルでの送信または配信に失敗した後、フォールバックチャネルを使用してアラートの送信が試行されたことを示します。 |
| **Delivery Time** | この時間は、リクエストの処理時間、EメールまたはSMSプロバイダーがユーザーにリクエストを送信するのに要した時間、およびプロバイダーが配信情報をシステムに報告するまでの時間の合計として計算されます。 |

各リクエストでは、次の情報を確認できます。

- **Delivery info:** Delivery Infoセクションには、リクエストを受信した日時、指定したチャネルでメッセージがベンダーに送信された日時、および配信時間に関する詳細が含まれます。アラートが複数のチャネルで順次送信されるように設定されている場合は、次の情報を確認できます。
  - _Attempted via First Backup - `<channelname>`_
  - Request received from Primary Channel - `<channel name>`
  - Attempted via _Second Backup - `<channelname>`_
  - _Request received from First Backup_ - `<channel name>` たとえば、プライマリチャネルまたはデフォルトチャネルがPush、1つ目のフォールバックがSMS、2つ目のフォールバックがEmailで、PushとSMSの両方でリクエストが失敗し、Emailチャネルを使用して送信された場合、これらのリクエストのDelivery Infoは以下の画像のように表示されます。 <img alt="test alert logs -old.png" src="/images/moengage_d3f1d2.png" />
- **Request:** Requestタブには、ログが表示されている特定のチャネルのリクエストペイロードが含まれます。
- **Response:** Responseタブには、MoEngageが生成したリクエストへのレスポンスが含まれます。
