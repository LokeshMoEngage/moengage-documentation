# アラートの設定

アラートを設定するには、次の手順を実行します。

1. [Alert Details](#alert-details): アラートを説明する詳細を追加します
2. [Content](#create-content): 選択したすべてのチャネルのメッセージをデザインします
3. [Publish](#publish): アラートをテストして公開します

## Alert Details

**Alert Details** セクションでは、以下のフィールドを使用してアラートの詳細を定義します。

1. **Specify an Alert Name**: このフィールドはアラートを識別するために使用され、必須です。最小 5 文字、最大 256 文字まで入力できます。
2. **Reference ID**: このフィールドは、お客様の参照名を使用してアラートを識別するために使用され、Alert ID の代わりにアラートを識別する手段として使用できます。このフィールドは必須ではなく、最小 5 文字、最大 256 文字まで入力できます。
3. **Describe the alert in the Alert Description**: このフィールドは、アラートの目的を説明するために使用されます。
   - **Tags**事前定義されたタグを選択するか、新しいタグを追加してアラートを識別します。このドロップダウンには、アラートにコンテキストを追加できるタグが含まれています。これらのタグは、トランザクション OTP、注文確認など、アラートの目的を説明できます。追加したタグを使用すると、All Alerts セクションでアラートをフィルタリングできます。詳細については、[Tags](/ja/user-guide/campaigns-and-channels/getting-started/introduction/campaign-tags) を参照してください。
   - **Teams**このフィールドは、Teams のリストからこのアラートに関連付けるチームを選択するために使用されます。組織で「Teams」が有効になっている場合、アラート作成時にこのフィールドが有効になります。詳細については、[Teams in MoEngage](/ja/user-guide/settings/account/team-management/teams-in-moengage) を参照してください。
4. **Configure relevant channels**
   <Info>
   アラートを作成する前に、チャネルを設定する必要があります。これらのチャネルの設定については、[SMS Settings、](/ja/user-guide/campaigns-and-channels/sms-mms-and-rcs/sms/getting-started-with-sms/configure-an-sms-sender) [Email Settings、](/ja/user-guide/campaigns-and-channels/email/getting-started-with-email/configure-email-channel)  [Push Settings](/ja/user-guide/campaigns-and-channels/mobile-push/getting-started-with-mobile-push/configure-mobile-push)、および [WhatsApp settings](/ja/user-guide/campaigns-and-channels/whatsapp/getting-started-with-whatsapp/configure-whatsapp) を参照してください。
   </Info>
   アラートを送信するチャネルを選択します。選択したチャネルのコンテンツは、アラート作成の次のステップ（コンテンツ作成）で定義できます。アラートを作成するには、少なくとも 1 つのチャネルを選択する必要があります。複数のチャネルを選択した場合は、それらすべてのコンテンツを定義する必要があります。  
    <img alt="Screenshot 2026-01-13 at 5.25.25 PM.png" src="/images/moengage_1f312f.png" />   
   - **SMS**:  このオプションを使用すると、SMS アラートを送信できます。
   - **Email**: このオプションを使用すると、メールアラートを送信できます。
   - **Push**: このオプションを使用すると、プッシュアラートを送信できます。以下の **Target Platforms for Push** を利用できます。
     - **Android:** このオプションを使用すると、標準の Android プッシュアラートを送信できます。
     - **iOS:** このオプションを使用すると、iOS アラートを送信できます。以下の **Message type****- iOS** オプションがサポートされています。
       - **Push Notification:** このオプションを使用すると、標準の iOS プッシュ通知を送信できます。一般的なお知らせ、マーケティングオファー、またはユーザーのロック画面でリアルタイムかつ持続的な更新を必要としないアラートに使用します。
       - **Live Activity Only:** このオプションを使用すると、標準プッシュのフォールバックなしで、リアルタイムの Live Activity のみで iOS ユーザーとエンゲージできます。インタラクティブ性の高い、その場の体験に最適です。
       - **Live Activity with Push Fallback:** このオプションを使用すると、iOS で Live Activity を優先できます。メッセージが確実にユーザーに届くよう、標準の iOS プッシュ通知がバックアップとして送信されます。
     - **Web:** このオプションを使用すると、標準の Web アラートを送信できます。
   - **WhatsApp:** このオプションを使用すると、WhatsApp アラートを送信できます。
5. **Set Channel Sending Order(Channel Fallback)**

   アラート作成で複数のチャネルを選択した場合、アラートを並列で送信するか順次送信するかを設定できます。複数のチャネルを選択した場合、以下のチャネル送信順序オプションを利用できます。

   1. **In parallel**: 2 つのチャネルに限り、アラートを並列で送信できます。
   2. **In sequence (on Sender Failure)**: デフォルトチャネルでの送信に失敗した場合に使用する、デフォルト、第 1、および第 2 のフォールバックチャネルを指定できます。チャネルフォールバックは、以下の場合に使用されます。
      1. - デフォルトまたは第 1 フォールバックチャネルのリクエストペイロードにエラーがある場合。たとえば、チャネルのリクエストペイロードに受信者の詳細またはパーソナライゼーション属性が存在しない場合
         - 特定のチャネルのベンダーに送信したリクエストが 4xx または 5xx エラーを返した場合。たとえば、認証情報が無効な場合はベンダーから 401 エラーが返され、配信を試行しているチャネルの *failed-to-send* エラーと見なされます。
         - チャネルのリクエストがベンダーによって拒否された場合も、MoEngage はフォールバックチャネルを使用してアラートを送信します。たとえば、ベンダーアカウントのクレジット上限に達している場合、ベンダーはアラート送信のリクエストを拒否することがあります。このような場合、MoEngage は設定されたフォールバックを使用してアラートを送信します。

      たとえば、デフォルトチャネルが Push、第 1 フォールバックが WhatsApp、第 2 フォールバックが SMS で、顧客にアラートを送信するとします。Push の送信に失敗した場合（ユーザーが有効なプッシュトークンを持っていない場合など）、WhatsApp チャネルを使用してアラートの送信が試行されます。WhatsApp チャネルでの送信に問題がある場合は、次に SMS チャネルが試行されます。  
       <img alt="2026-01-13_17-12-42.gif" src="/images/moengage_82844a.png" />
   3. **In sequence (on Delivery Failure)**: デフォルトチャネルがアラートの配信に失敗した場合に使用する、デフォルトチャネルとフォールバックチャネルを指定できます。Delivery fallback 設定を使用して、チャネルを切り替えるまでの待機時間枠を設定できます。Try successful delivery for \_ before making a new attempt フィールドに、1 分から 60 分までの値を入力します。デフォルトチャネルがアラートの配信に失敗した場合、待機時間の経過後に、システムはフォールバックチャネルを使用してアラートの配信を再試行します。

      たとえば、デフォルトチャネルが SMS、フォールバックチャネルが Email で、待機時間枠が 5 分であるとします。SMS の配信に失敗した場合、5 分後に Email チャネルを使用してアラートの送信が試行されます。  
       <img alt="WI 3.gif" src="/images/moengage_c4a25f.png" />

- ## Create Content

  このセクションでは、送信するアラートのコンテンツを定義します。

  SMS Content Email Content  Push Notification Content  WhatsApp Content

  以下のオプションを使用して、SMS キャンペーンのコンテンツを作成できます。

  1. すべてのフィールドに必要な詳細を入力する空白のテンプレート。
  2. [SMS Template APIs](https://developers.moengage.com/hc/en-us/articles/14579504140052-Overview) を使用して MoEngage にアップロードされたテンプレートのデータが事前入力されるカスタムテンプレート。

  ### 空白のテンプレートを使用したコンテンツの作成

  空白のテンプレートを選択し、以下の手順に従って SMS キャンペーンのコンテンツを作成します。

  アラートの SMS コンテンツ作成セクションでは、以下のフィールドを利用できます。

  1. **SMS Sender**

     SMS Sender ドロップダウンを使用して、SMS アラートの送信に使用する SMS コネクタ（サービスプロバイダー）を選択します。このドロップダウンには、設定済みの SMS コネクタ（サービスプロバイダー）のリストが表示されます。  
     [Dynamic Sender Routing](/ja/user-guide/inform/advanced-concepts/dynamic-sender-routing) を設定している場合は、ドロップダウンから作成済みの Conditions を選択できます。選択すると、選択した条件で使用される送信者のリストが表示されます。  
      <img alt="SMS SENDER.png" src="/images/moengage_28eef2.png" />
  2. **Template ID**

     選択した SMS コネクタ（サービスプロバイダー）が DLT 規制（インド地域）の対象となる場合、このフィールドは必須です。  
     詳細については、[DLT regulations](/ja/user-guide/campaigns-and-channels/sms-mms-and-rcs/compliance-and-deliverability/messaging-regulations-for-india) を参照してください。
  3. **Message**

     このフィールドには、ユーザーに送信されるメッセージが含まれます。メッセージエディターの右側にある **Text personalization** をクリックして、メッセージをパーソナライズできます。詳細については、[Personalize your Alert](/ja/user-guide/inform/create/personalize-alert) を参照してください。
  4. **Shorten URL and Track URL**

     このセクションには、メッセージ本文に含まれる URL が表示されます。選択した URL は、MoE ドメイン（`<to add MoE domain>`）を使用して短縮され、ユーザーに送信されます。

     <Info>
     クリックトラッキングは、Shorten & Track URL が有効になっている URL でのみ有効になります。
     </Info>

  ### カスタムテンプレートを使用したコンテンツの作成

  このセクションでアップロード済みのテンプレートのいずれかを選択し、そのテンプレートを使用してアラートを送信できます。詳細については、[SMS Custom Templates.](https://developers.moengage.com/hc/en-us/articles/14579504140052-Overview) を参照してください。

  ### ロケールの追加

  アラートをさまざまな言語にローカライズするには、コンテンツ作成ステップの右上隅にある *+Locale* をクリックします。新しいロケールを追加するか、既存のロケールをキャンペーンに追加するかを選択できます。デフォルトロケールの既存コンテンツをコピーするか、追加したロケール用にまったく新しいメッセージを作成できます。詳細については、[Localize campaign message](/ja/user-guide/campaigns-and-channels/getting-started/campaign-content/localize-campaign-messages) を参照してください。

  SMS コンテンツをテストするには、`<country code>` `<Mobile number>` の形式で携帯電話番号を入力します。たとえば、受信者の携帯電話番号は +14083636XX または 1408363XX のような形式にする必要があります。

  アラートの Email コンテンツ作成セクションでは、以下のオプションを利用できます。いずれかのオプションを選択して、メールアラートのコンテンツを作成します。

  ### Drag and Drop Editor

  Drag and Drop エディターを使用すると、MoEngage の構築済みテンプレートを使用してアラート用のメールテンプレートを作成できます。テンプレートはニーズに合わせてカスタマイズできます。

  ### Custom HTML Editor

  Custom HTML Editor を使用すると、HTML を使用してメールテンプレートを作成できます。HTML コンテンツを入力または貼り付けるか、HTML ファイル（Zip ファイル）をアップロードしてエディターで編集できます。

  ### My Saved Templates

  Saved Templates セクションでは、保存済みテンプレートのいずれかを読み込み、ニーズに合わせて編集できます。これらのテンプレートオプションのいずれかを選択すると、次の画面で送信者の詳細と添付ファイルの詳細を入力し、メッセージコンテンツを編集または追加できます。

  ### 送信者の詳細

  このセクションには、以下のフィールドが含まれます。

  - **Subject**: メールアラートのタイトルを入力します。受信者がアラートの目的を一目で理解できるよう、アラートの内容を明確かつ簡潔に要約する必要があります。
  - **Email Connector**: Email Connector ドロップダウンを使用して、メールアラートの送信に使用するメールコネクタ（サービスプロバイダー）を選択します。このドロップダウンには、設定済みのメールコネクタ（サービスプロバイダー）のリストが表示されます。  
    [Dynamic Sender Routing](/ja/user-guide/inform/advanced-concepts/dynamic-sender-routing) を設定している場合は、ドロップダウンから作成済みの Conditions を選択できます。選択すると、選択した条件で使用される送信者（コネクタ）のリストが表示されます。  
     <img alt="Screenshot 2025-08-13 at 10.43.36 AM.png" src="/images/moengage_b14646.png" />
  - **Sender Name**: 送信者の名前を入力します。この名前は、メールの送信者として受信者に表示されます。
  - **From email address:** アラートの送信元となるメールアドレスです。受信者には送信者としてこのアドレスが表示されます。
  - **Reply to email address:** 受信者からの返信を受け取るメールアドレスです。
  - **Cc**: *Carbon Copy* の略です。ここに 1 つ以上のメールアドレスを入力して、主な宛先ではない受信者にアラートのコピーを送信できます。
  - **Bcc**: *Blind Carbon Copy* の略です。ここに 1 つ以上のメールアドレスを入力して、アラートの非表示のコピーを送信できます。「To」および「Cc」フィールドの受信者は、「Bcc」フィールドに誰が含まれているかを確認できません。

  このセクションのフィールドは、**Cc** と **Bcc** を除きすべて必須です。

  ### 添付ファイルの詳細

  Attachments タブ（Sender Details タブの隣にあります）をクリックし、以下のいずれかのオプションを使用して、メールアラートに添付ファイルを追加できます。

  - **Upload file** - このオプションでは、**Upload file** オプションを使用してローカルドライブからファイルをアップロードできます。ファイルをドラッグ＆ドロップするか、**Upload from computer** オプションをクリックしてコンピューターからファイルを参照してアップロードします。
  - **Attach via API** - このオプションでは、API ペイロードでメールの添付ファイルを送信できます。添付ファイルを追加するには、次の手順を実行します。  
    - **Add Personalised Attachment Key(s)** フィールドを使用して、ペイロードで添付ファイル情報が渡されるフィールド名（添付ファイルキー）を追加します。
    - API でパーソナライゼーション用の変数を渡すのと同様に、添付ファイルキーを `{{}}` で囲みます。たとえば、`{{sample_attachment_key}}` です。
    - **Attach.** をクリックします。添付ファイルが正常に追加されると、UI に **Attachment Key added successfully** メッセージが表示されます。
    - 添付ファイルキーは、ペイロードの **personalized\_attachments** オブジェクトに追加されます。Inform API にリクエストを送信する際は、アラート作成時に指定した添付ファイルキーを使用して、このオブジェクトで添付ファイルの詳細を渡す必要があります。

    <Info>
    - 添付ファイルの合計サイズは 4 MB 未満である必要があります。
    - 最大 5 つのファイルを添付できます。
    </Info>

  必要な詳細を入力し、以下の Template editor セクションに移動してメールコンテンツを編集します。  
  エディターの右上隅にある Text personalization ボタンを使用して、メールをパーソナライズできます。詳細については、[Personalize your Alert](/ja/user-guide/inform/create/personalize-alert) を参照してください。

  ### メールへの CC と BCC の追加

  カーボンコピー（CC）とブラインドカーボンコピー（BCC）は、選択したターゲットセグメントに含まれない受信者にメールのコピーを送るために使用されます。この機能を有効にすると、CC/BCC の受信者は、主な受信者（**To** フィールド）が受け取るメールアラートとまったく同じコピーを受け取ります。

  **Cc**、**Bcc**、またはその両方をクリックして、アラートに CC または BCC のメール受信者を追加します。以下で説明するように、静的アドレスまたはパーソナライズされたメールアドレスを追加できます。

  - 静的な CC または BCC アドレスを追加する - すべてのメールアラートに同じ CC/BCC 受信者のセットが設定されます。
  - パーソナライズされた Cc/Bcc アドレスを追加する - CC/BCC のメールアドレスはパーソナライズされた属性から取得されます。

  CC/BCC をパーソナライズするには、**Text personalization** ボタンをクリックします。詳細については、[Personalize Alert](/ja/user-guide/inform/create/personalize-alert) を参照してください。

  ### メールアラートコンテンツのテスト

    ## Publish
  - 公開前にアラートをテストして、API との連携が正常に機能しているかを確認し、ユーザーが受信する実際の SMS とメールを確認できます。詳細については、[Test Your Alert](/ja/user-guide/inform/create/test-alert) を参照してください。
  - アラートを公開するには、**Publish.** をクリックします。これによりアラートが公開され、アラートを一意に識別するために使用できる Alert ID が生成されます。入力した Reference ID を使用してアラートを識別することもできます。
  - Alert-Info ページに移動し、リクエストの詳細とメッセージのプレビューを確認できます。Analytics セクションと Logs セクションに切り替えることもできます。
  - アラートが公開されたので、[Inform Service API](https://developers.moengage.com/hc/en-us/articles/10699624590868-Inform-API) を使用してユーザーにアラートを送信できます。
    <Info>
    アラートでは、どのチャネルでも以下のチェックは実行されません: Delivery Controls（Frequency Capping と Do Not Disturb）、Unsubscribe（メールのみ）、Complaints（メールのみ）、Bounces（メールのみ）、Opt-in preference（SMS のみ）。
    </Info>
