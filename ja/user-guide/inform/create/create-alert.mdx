# アラートの設定

アラートは次の手順で作成できます。

- [ステップ 1: アラートの詳細](/ja/user-guide/inform/create/create-alert#alert-details): アラートを説明する詳細を追加します。
- [ステップ 2: コンテンツ](/ja/user-guide/inform/create/create-alert#create-content): 選択したすべてのチャネルのメッセージをデザインします。
- [ステップ 3: 公開](/ja/user-guide/inform/create/create-alert#publish): アラートをテストして公開します。

## アラートの詳細

**Alert Details** セクションでは、次のフィールドを使用してアラートの詳細を定義します。

1. **Specify an Alert Name**: このフィールドはアラートを識別するために使用され、必須です。5 文字以上 256 文字以下で入力できます。
2. **Reference ID**: このフィールドは、独自の参照名でアラートを識別するために使用され、Alert ID の代わりにアラートを識別する手段として利用できます。このフィールドは必須ではなく、5 文字以上 256 文字以下で入力できます。
3. **Describe the alert in the Alert Description**: このフィールドは、アラートの目的を説明するために使用します。
   - **Tags:** 定義済みのタグを選択するか、新しいタグを追加してアラートを識別します。このドロップダウンには、アラートにコンテキストを付加できるタグが含まれています。これらのタグは、トランザクション OTP や注文確認など、アラートの目的を表すことができます。タグを追加すると、All Alerts セクションでアラートを絞り込めるようになります。詳細については、[Tags](/ja/user-guide/campaigns-and-channels/getting-started/introduction/campaign-tags) を参照してください。
   - **Teams:** このフィールドは、Teams のリストからこのアラートに関連付けるチームを選択するために使用します。組織で「Teams」が有効になっている場合、アラート作成時にこのフィールドが有効になります。詳細については、[Teams in MoEngage](/ja/user-guide/settings/account/team-management/teams-in-moengage) を参照してください。
   - **Use rule set**: このチェックボックスを選択すると、このアラートで Dynamic Template Selector が有効になります。有効にすると、静的な単一テンプレートの配信が条件付きルーティングのフレームワークに置き換わります。複雑なトランザクションのバリエーションごとに個別のアラートを管理する代わりに、このオプションを選択することで、事前に設定した Rule Set をリンクできます。MoEngage は受信したランタイム API またはユーザー属性を評価し、各受信者に適切なコンテキストのメッセージバリアントを動的に配信します。詳細については、[Dynamic Template Selector](/ja/user-guide/inform/advanced-concepts/dynamic-template-selector) を参照してください。
4. **Configure relevant channels**
   <Info>
     チャネルはアラートを作成する前に設定しておく必要があります。これらのチャネルの設定については、[SMS 設定](/ja/user-guide/campaigns-and-channels/sms-mms-and-rcs/sms/getting-started-with-sms/configure-an-sms-sender)、[メール設定](/ja/user-guide/campaigns-and-channels/email/getting-started-with-email/configure-email-channel)、[プッシュ設定](/ja/user-guide/campaigns-and-channels/mobile-push/getting-started-with-mobile-push/configure-mobile-push)、[WhatsApp 設定](/ja/user-guide/campaigns-and-channels/whatsapp/getting-started-with-whatsapp/configure-whatsapp)を参照してください。
   </Info>
   アラートを送信するチャネルを選択し、アラート作成の次のステップ(コンテンツ作成)で、選択したチャネルのコンテンツを定義します。アラートを作成するには、少なくとも 1 つのチャネルを選択する必要があります。複数のチャネルを選択した場合は、それぞれのコンテンツを定義する必要があります。 <img src="/images/moengage_8d31b0.png" alt="Screenshot 2026-01-13 at 5.25.25 PM.png" />
   - **SMS**: このオプションでは、SMS アラートを送信できます。
   - **Email**: このオプションでは、メールアラートを送信できます。
   - **Push**: このオプションでは、プッシュアラートを送信できます。次の **Target Platforms for Push** を利用できます。
     - **Android:** このオプションでは、標準の Android プッシュアラートを送信できます。
     - **iOS:** このオプションでは、iOS アラートを送信できます。次の **Message type** **- iOS** オプションがサポートされています。
       - **Push Notification:** このオプションでは、標準の iOS プッシュ通知を送信できます。一般的なお知らせ、マーケティングオファー、またはユーザーのロック画面でのリアルタイムかつ持続的な更新を必要としないアラートに使用します。
       - **Live Activity Only:** このオプションでは、標準のプッシュフォールバックなしで、リアルタイムの Live Activity のみを使用して iOS ユーザーにエンゲージできます。インタラクティブ性の高い、その瞬間の体験に最適です。
       - **Live Activity with Push Fallback:** このオプションでは、iOS で Live Activity を優先できます。メッセージが確実にユーザーに届くよう、標準の iOS プッシュ通知がバックアップとして送信されます。
     - **Web:** このオプションでは、標準の Web アラートを送信できます。
   - **WhatsApp:** このオプションでは、WhatsApp アラートを送信できます。
5. **Ignore DND settings**: [Do Not Disturb (DND)](/ja/user-guide/settings/channels/delivery-controls/do-not-disturb) の設定は、特定の静かな時間帯(深夜など)に緊急性の低い通知の送信を防ぐために MoEngage ワークスペースで管理されるパラメーターです。しかし、MoEngage Inform で生成されるトランザクション更新は、多くの場合、時間的制約があり重要です。**Ignore DND settings** セクションを使用すると、チャネルごとにワークスペースの静かな時間帯の設定を上書きできます。
6. **Set Channel Sending Order(Channel Fallback)** アラート作成で複数のチャネルを選択した場合、アラートを並列で送信するか順次送信するかを設定できます。複数のチャネルを選択した場合、次のチャネル送信順序オプションを利用できます。
   1. **In parallel**: 並列でアラートを送信できるのは 2 つのチャネルのみです。
   2. **In sequence (on Sender Failure)**: デフォルトチャネルでの送信に失敗した場合に使用する、デフォルト、第 1、第 2 のフォールバックチャネルを指定できます。チャネルフォールバックは、次のような場合に使用されます。
      - デフォルトまたは第 1 フォールバックチャネルのリクエストペイロードにエラーがある場合。たとえば、チャネルのリクエストペイロードに受信者の詳細やパーソナライゼーション属性が含まれていない場合です。
      - 特定のチャネルのベンダーにリクエストを送信した際に、4xx または 5xx エラーが返された場合。たとえば、認証情報が無効な場合はベンダーから 401 エラーが返され、配信を試みているチャネルの _failed-to-send_ エラーと見なされます。
      - チャネルへのリクエストがベンダーに拒否された場合も、MoEngage はフォールバックチャネルを使用してアラートを送信します。たとえば、ベンダーアカウントのクレジット上限に達している場合、ベンダーはアラートの送信リクエストを拒否することがあります。このような場合、MoEngage は設定されたフォールバックを使用してアラートを送信します。たとえば、デフォルトチャネルが Push、第 1 フォールバックが WhatsApp、第 2 フォールバックが SMS で、顧客にアラートを送信するとします。Push の送信に失敗した場合(ユーザーに有効なプッシュトークンがない場合など)、WhatsApp チャネルでアラートの送信が試行されます。WhatsApp チャネルでの送信に問題がある場合は、次に SMS チャネルが試行されます。 <img src="/images/moengage_691442.png" alt="2026-01-13_17-12-42.gif" />
   3. **In sequence (on Delivery Failure)**: デフォルトチャネルでアラートの配信に失敗した場合に使用する、デフォルトチャネルとフォールバックチャネルを指定できます。配信フォールバックの設定を使用して、チャネルを切り替える前の待機時間を設定できます。Try successful delivery for \_ before making a new attempt フィールドに、1 分から 60 分の値を入力します。デフォルトチャネルでアラートの配信に失敗した場合、待機時間の経過後に、システムはフォールバックチャネルを使用してアラートの配信を再試行します。たとえば、デフォルトチャネルが SMS、フォールバックチャネルが Email、待機時間が 5 分であるとします。SMS の配信に失敗した場合、5 分後に Email チャネルでアラートの送信が試行されます。 <img src="/images/moengage_725160.png" alt="WI 3.gif" />

## コンテンツの作成

このセクションでは、送信するアラートのコンテンツを定義します。

<Tabs>
  <Tab title="SMS コンテンツ">
    SMS キャンペーンのコンテンツは、次のオプションを使用して作成できます。

    1. すべてのフィールドに必要な詳細を入力する空のテンプレート。
    2. [SMS Template APIs](/ja/api/sms-templates/sms-templates-overview) を使用して MoEngage にアップロードされたテンプレートのデータがあらかじめ入力されるカスタムテンプレート。

    ### 空のテンプレートを使用したコンテンツの作成

    空のテンプレートを選択し、次の手順に従って SMS キャンペーンのコンテンツを作成します。

    アラートの SMS コンテンツ作成セクションでは、次のフィールドを利用できます。

    1. **SMS Sender** SMS Sender ドロップダウンを使用して、SMS アラートの送信に使用する SMS コネクタ(サービスプロバイダー)を選択します。このドロップダウンには、設定済みの SMS コネクタ(サービスプロバイダー)のリストが表示されます。[Dynamic Sender Routing](/ja/user-guide/inform/advanced-concepts/dynamic-sender-routing) を設定している場合は、作成した Conditions をドロップダウンから選択できます。選択すると、選択した条件で使用される送信者のリストが表示されます。 <img src="/images/moengage_e8d028.png" alt="SMS SENDER.png" />
    2. **Template ID** 選択した SMS コネクタ(サービスプロバイダー)が DLT 規制(インド地域)の対象である場合、このフィールドは必須です。詳細については、[DLT 規制](/ja/user-guide/campaigns-and-channels/sms-mms-and-rcs/compliance-and-deliverability/messaging-regulations-for-india)を参照してください。
    3. **Message** このフィールドには、ユーザーに送信されるメッセージが含まれます。メッセージエディターの右側にある **Text personalization** をクリックすると、メッセージをパーソナライズできます。詳細については、[アラートのパーソナライズ](/ja/user-guide/inform/create/personalize-alert)を参照してください。
    4. **Shorten URL and Track URL** このセクションには、メッセージ本文に含まれる URL が表示されます。選択した URL は、MoE ドメイン(`<to add MoE domain>`)を使用して短縮され、ユーザーに送信されます。
       <Info>
         クリックトラッキングは、Shorten & Track URL が有効になっている URL でのみ有効になります。
       </Info>

    ### カスタムテンプレートを使用したコンテンツの作成

    このセクションでアップロード済みのテンプレートを 1 つ選択し、それを使用してアラートを送信できます。詳細については、[SMS カスタムテンプレート](/ja/api/sms-templates/sms-templates-overview)を参照してください。

    ### ロケールの追加

    アラートをさまざまな言語にローカライズするには、コンテンツ作成ステップの右上にある _\+Locale_ をクリックします。新しいロケールを追加するか、既存のロケールをキャンペーンに追加するかを選択できます。デフォルトロケールから既存のコンテンツをコピーするか、追加したロケール用にまったく新しいメッセージを作成できます。詳細については、[キャンペーンメッセージのローカライズ](/ja/user-guide/campaigns-and-channels/getting-started/campaign-content/localize-campaign-messages)を参照してください。

    SMS コンテンツをテストするには、`<country code>` `<Mobile number>` の形式で携帯電話番号を入力します。たとえば、受信者の携帯電話番号は \+14083636XX や 1408363XX のような形式になります。

  <Tab title="メールコンテンツ">
    アラートのメールコンテンツ作成セクションでは、次のオプションを利用できます。いずれかのオプションを選択して、メールアラートのコンテンツを作成します。

    ### ドラッグ&ドロップエディター

    ドラッグ&ドロップエディターでは、MoEngage の構築済みテンプレートを使用してアラート用のメールテンプレートを作成できます。テンプレートはニーズに合わせてカスタマイズできます。

    ### カスタム HTML エディター

    カスタム HTML エディターでは、HTML を使用してメールテンプレートを作成できます。HTML コンテンツを入力または貼り付けるか、HTML ファイル(Zip ファイル)をアップロードしてエディターで編集できます。

    ### My Saved Templates

    Saved Templates セクションでは、保存済みのテンプレートを読み込み、ニーズに合わせて編集できます。いずれかのテンプレートオプションを選択すると、次の画面で送信者の詳細と添付ファイルの詳細を入力し、メッセージコンテンツを編集または追加できます。

    ### 送信者の詳細

    このセクションには、次のフィールドがあります。

    - **Subject**: メールアラートのタイトルを入力します。受信者がアラートの目的を一目で理解できるよう、アラートの内容を明確かつ簡潔に要約する必要があります。
    - **Email Connector**: Email Connector ドロップダウンを使用して、メールアラートの送信に使用するメールコネクタ(サービスプロバイダー)を選択します。このドロップダウンには、設定済みのメールコネクタ(サービスプロバイダー)のリストが表示されます。[Dynamic Sender Routing](/ja/user-guide/inform/advanced-concepts/dynamic-sender-routing) を設定している場合は、作成した Conditions をドロップダウンから選択できます。選択すると、選択した条件で使用される送信者(コネクタ)のリストが表示されます。 <img src="/images/moengage_bac6e4.png" alt="Screenshot 2025-08-13 at 10.43.36 AM.png" />
    - **Sender Name**: 送信者の名前を指定します。この名前は、メールの送信者として受信者に表示されます。
    - **From email address:** アラートの送信元となるメールアドレスです。受信者には、このアドレスが送信者として表示されます。
    - **Reply to email address:** 受信者からの返信を受け取るメールアドレスです。
    - **Cc**: _Carbon Copy_ の略です。1 つ以上のメールアドレスを入力して、主な宛先ではない受信者にアラートのコピーを送信できます。
    - **Bcc**: _Blind Carbon Copy_ の略です。1 つ以上のメールアドレスを入力して、アラートの非表示のコピーを送信できます。"To" および "Cc" フィールドの受信者は、"Bcc" フィールドに誰が含まれているかを確認できません。

    このセクションのフィールドは、**Cc** と **Bcc** を除いてすべて必須です。

    ### 添付ファイルの詳細

    メールアラートに添付ファイルを追加するには、Attachments タブ(Sender Details タブの隣にあります)をクリックし、次のいずれかのオプションを使用して添付ファイルを追加します。

    - **Upload file** - このオプションでは、**Upload file** オプションを使用してローカルドライブからファイルをアップロードできます。ファイルをドラッグ&ドロップするか、**Upload from computer** オプションをクリックしてコンピューター上のファイルを参照し、アップロードします。
    - **Attach via API** - このオプションでは、API ペイロードでメールの添付ファイルを送信できます。添付ファイルを追加するには、次の手順に従います。
      - **Add Personalised Attachment Key(s)** フィールドを使用して、ペイロードで添付ファイル情報を渡すフィールド名(添付ファイルキー)を追加します。
      - API でパーソナライゼーション用の変数を渡す場合と同様に、添付ファイルキーを `{{}}` で囲みます。たとえば、`{{sample_attachment_key}}` のようにします。
      - **Attach** をクリックします。添付ファイルが正常に追加されると、UI に **Attachment Key added successfully** メッセージが表示されます。
      - 添付ファイルキーは、ペイロードの **personalized\_attachments** オブジェクトに追加されます。Inform API にリクエストを送信する際は、アラート作成時に指定した添付ファイルキーとともに、このオブジェクトで添付ファイルの詳細を渡す必要があります。

    <Info>
      - 添付ファイルの合計サイズは 4 MB 未満である必要があります。
      - 添付できるファイルは最大 5 つです。
    </Info>

    必要な詳細を入力したら、以下のテンプレートエディターセクションに移動してメールコンテンツを編集します。エディターの右上にある Text personalization ボタンを使用して、メールをパーソナライズできます。詳細については、[アラートのパーソナライズ](/ja/user-guide/inform/create/personalize-alert)を参照してください。

    ### メールへの CC と BCC の追加

    カーボンコピー(CC)とブラインドカーボンコピー(BCC)は、選択したターゲットセグメントに含まれない受信者にメールのコピーを送信するために使用します。この機能を有効にすると、CC/BCC の受信者は、主な受信者(**To** フィールド)が受け取るメールアラートとまったく同じコピーを受け取ります。

    **Cc**、**Bcc**、またはその両方をクリックして、アラートに CC または BCC のメール受信者を追加します。以下で説明するように、静的なアドレスまたはパーソナライズされたメールアドレスを追加できます。

    - 静的な CC または BCC アドレスを追加する - すべてのメールアラートに同じ CC/BCC 受信者が設定されます。
    - パーソナライズされた Cc/Bcc アドレスを追加する - CC/BCC のメールアドレスはパーソナライズされた属性から取得されます。

    CC/BCC をパーソナライズするには、**Text personalization** ボタンをクリックします。詳細については、[アラートのパーソナライズ](/ja/user-guide/inform/create/personalize-alert)を参照してください。

## 公開

公開する前にアラートをテストして、API との連携が正しく機能しているかを確認し、ユーザーが実際に受け取る SMS やメールを表示できます。詳細については、[アラートのテスト](/ja/user-guide/inform/create/test-alert)を参照してください。

アラートを公開するには、**Publish** をクリックします。これによりアラートが公開され、アラートを一意に識別するために使用できる Alert ID が生成されます。入力した Reference ID を使用してアラートを識別することもできます。

その後、Alert-Info ページに移動し、リクエストの詳細やメッセージのプレビューを確認できます。Analytics セクションや Logs セクションに切り替えることもできます。

アラートが公開されたので、[Inform Service API](https://www.moengage.com/docs/api/transactional-alerts/send-transactional-alert) を使用してユーザーにアラートを送信できます。

<Info>
  次のチェックは、どのチャネルのアラートに対しても実行されません: Delivery Controls(Frequency Capping および Do Not Disturb)、Unsubscribe(メールのみ)、Complaints(メールのみ)、Bounces(メールのみ)、Opt-in preference(SMS のみ)。
</Info>
