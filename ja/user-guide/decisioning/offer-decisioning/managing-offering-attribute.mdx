title: "Offering Attributesの管理"

Offering Attributesは、一度定義してオファリングに添付できる再利用可能なスコアリングパラメーターです。クリック率や手動ランクだけでなく、各オファーをより豊かで多次元的に把握できるようにディシジョンエンジンを支援し、すべての顧客に対して常に最も関連性が高く戦略的に重要なオファリングを提示できるようにします。\
Offering Attributesは、Custom Formulaランキング戦略の構成要素と考えてください。顧客が複数のオファリングの対象となる場合、エンジンは定義した属性を使用して各オファリングの加重スコアを計算し、それに応じてランク付けします。

# Offering Attributesで解決できること

静的なオファリング優先度スコアに基づくOffering priorityランキングは、オファーの数が少なく、ビジネス目標が週ごとに変わらない場合に信頼性があります。これは、ターゲットセグメント内のユーザーに表示されるオファリングを変えずに維持する必要がある場合に特に役立ちます。

Merlin AIベースの最適化は、クリックとコンバージョンから学習し、ユーザーから最も良い反応を得ているオファリングを提示します。次のような場合に役立ちます。

- オファリングの発見 — ユーザーの共感を呼ぶものをユーザー自身に見つけてもらう
- オファー間に強い「ビジネス上の」優先順位がない
- 意味のあるシグナルを迅速に生成できる十分なトラフィックがある

Offering Attributesを使用したCustom formulaを使用すると、戦略的に重要であり、かつ個々のユーザーに関連性の高いオファリングに対して、単一のランキングスコアを生成できます。

**サンプルのユースケースを以下に示します。**

<u>ユースケース1</u>

コンバージョン率2%のプレミアムアクセサリーが、CVR 12%の\$15のスマートフォンケースに常にランキングで負けています。手動ランクは役立ちますが、新しいアクセサリーが発売されるとすぐに機能しなくなります。\
**<u>Custom formulaを使用する場合</u>**: プレミアムSKUのオファリングに高い"Margin Score"(固定値、90)を割り当て、スマートフォンケースのオファリングに低い"Margin score"(40)を割り当てます。Custom formulaで"Margin score"属性に40%の重みを割り当てます。個々のオファリングの優先度スコアに手を加えることなく、プレミアムアクセサリーのオファリングの競争力が維持されます。

<u>ユースケース2</u>

純粋なエンゲージメント戦略はリテンションの関連性ではなく全体のクリック率に対して最適化するため、解約の可能性が高いとフラグが付けられた顧客に、依然として新規顧客向けのプロモーションが配信されています。\
**<u>Custom formulaを使用する場合</u>**<u>:</u> ユーザーのプロファイルにリンクされた"Churn Propensity"動的値属性を割り当てます。リテンション重視としてタグ付けされたオファリングは、リスクの高いユーザーに対して自動的にブーストされます。

# Offering Attributesの種類

Offering Attributesには2つの種類があります。違いを理解することで、スコアリング数式の各次元にどちらを使用するかを判断できます。

## Fixed value

Fixed value属性は、オファリング自体について意味のある情報を捉える、ユーザーが定義したオプションのリストです。作成者はオファリングを作成または編集する際に、それを最もよく表すオプションを選択します。

重要な特徴は、スコアがターゲットユーザーではなくオファリングによって決まることです。そのオファリングの対象となるすべてのユーザーに、ランキング数式で同じスコアが適用されます。そのため、誰が表示しているかに関係なく、オファリングの戦略的またはビジネスレベルの重み(利益率、キャンペーンの優先度、製品カテゴリーの重要度など)を表現したい場合には、Fixed Value属性が適したツールとなります。

**例**:

銀行は、ある四半期にはローン残高の拡大に注力し、次の四半期には保険の普及率の向上に注力する場合があります。

"Business Objective"属性を作成し、"Grow loan book"、"Increase insurance penetration"、"Cross-sell investments"の3つのオプションを設定します。

個々のオファリングごとに、"Business Objective"属性を選択し、適切なオプションを選択してスコアを割り当てます。

各四半期の初めにDecision Policyでこの属性の重みを変更すると、適切なオファリングが自動的に優先されます。オファリングレベルの編集は必要ありません。

## Dynamic value

Dynamic value属性は、オファリングの作成時にスコアが固定されないスコアリングパラメーターで、ディシジョニングの時点で個々の顧客ごとに新たに計算されます。エンジンはMoEngage内のその顧客のリアルタイムプロファイルを参照し、事前に設定した特定のユーザー属性を確認して、その結果に基づいてスコアを付与します。

重要な特徴は、同じオファリングでも顧客ごとに異なるスコアを受け取る可能性があることです。そのため、関連性がオファリングの内容だけでなく顧客が誰であるかに依存する場合には、Dynamic Value属性が適したツールとなります。

**オファリングの値とユーザープロファイル属性のマッチング**

Dynamic Value属性を定義する際は、1つ以上のユーザープロファイル属性にマッピングし、各マッピングにスコアを割り当てます。ディシジョニング時に、エンジンはそれらのユーザー属性を順番に確認し、最初に一致したもののスコアを付与します。

上記の例では、手動の介入なしに、同じ電子機器のオファリングがUser CよりもUser Aに対して上位にランク付けされています。マーケターはオファリングを一度作成するだけで、エンジンがすべての個人に対してランキングを自動的にパーソナライズします。\
 

|  | **Fixed value** | **Dynamic value** |
| :-- | :-- | :-- |
| **スコアを設定するのは誰か** | オファリングの作成時に作成者が設定 | ディシジョニング時に評価される、MoEngage内の顧客のライブプロファイル |
| **スコアはユーザーごとに異なるか** | いいえ - オファリングの対象となるすべてのユーザーに同じスコア | はい - 各ユーザーが自身のプロファイル値に基づいたスコアを受け取る |
| **何を捉えるか** | オファリング自体の戦略的またはビジネスレベルの重要度 | この特定のユーザーにとって、現時点でオファリングがどの程度関連性があるか |
| **オプションの定義方法** | Adminが名前付きオプションのドロップダウンを作成 | Adminがユーザープロファイル属性をスコアにマッピング — 属性が一致するごとに異なるスコアを返す |
| **ユーザープロファイル値に依存するか** | いいえ — スコアは作成者が手動で設定 | はい — ディシジョニング時にユーザープロファイル属性がMoEngageで利用可能である必要がある |
| **併用するタイミング** | 同じCustom Formulaで両方を使用して、ビジネス上の優先度と個々の関連性のバランスを取ります — 例えば、ビジネス目標40%(固定)\+ カテゴリーアフィニティ30%(動的)\+ パフォーマンス30%。 |  |

# 次のステップ

Offering Attributesについて理解したら、次のことができます。

- 1つ以上のOffering Attributesを作成します。詳細については、[Create Offering attribute](/ja/user-guide/decisioning/offer-decisioning/create-offering-attribute)を参照してください。
- オファリングの作成時にそれらをオファリングに割り当てます。詳細については、[Create Offerings](/ja/user-guide/decisioning/offer-decisioning/create-offerings)を参照してください。
- Decision Policy内のCustom Formulaランキング戦略でそれらを使用します。詳細については、[Custom Formula Ranking Strategy](/ja/user-guide/decisioning/offer-decisioning/custom-formula-ranking-strategy)を参照してください。
