<Accordion title="オファリングとDecision Policyの違いは何ですか?">
  オファリングは、コンテンツと適格性ルールを含む単一のプロモーション単位を表します。一方、Decision Policyは、同じ表示面またはユーザーに対して複数のオファリングが適格な場合に、それらをどのように優先順位付けし、選択し、表示するかを決定します。
</Accordion>

<Accordion title="オファリングを複数のキャンペーンや場所で再利用できますか?">
  はい、オファリングはさまざまなキャンペーンや表示面で再利用できます。一貫したメッセージを届けるために、適格性ルールがターゲットオーディエンスに適用される限り、1つのオファリングを複数の場所(例: ホームページのバナー、アプリのプッシュ通知)にリンクできます。
</Accordion>

<Accordion title="パーソナライゼーションテンプレートとは何ですか?">
  テンプレートは、オファリングのコンテンツをデザインするための再利用可能なビジュアルレイアウトです。アプリやWebサイト上でのオファリングの最終的な見た目を視覚化し、ブランドの一貫性を確保するのに役立ちます。
</Accordion>

<Accordion title="各オファリングのコンテンツをカスタマイズできますか?">
  はい。テンプレートはレイアウトを提供しますが、各オファリングのコンテンツは完全にカスタマイズできます。これには、キャンペーンの目標に合わせたテキスト、画像、リンク、書式設定が含まれます。
</Accordion>

<Accordion title="オファリングの対象となる顧客をどのように定義しますか?">
  適格性ルールを使用すると、次の条件に基づいて特定のユーザーをターゲットにできます。

  - ユーザー属性
  - ユーザー行動
  - ユーザーアフィニティ
  - カスタムセグメント\
    これらのルールは、オファリングの作成時にEligibilityセクションで設定します。
</Accordion>

<Accordion title="1つのオファリングに複数の適格性ルールを含めることはできますか?">
  はい、AND/ORロジックを使用して複数の適格性ルールを組み合わせることができます。例えば、特定の州に住んでいて、かつ(AND)過去30日以内に購入したユーザーをターゲットにできます。
</Accordion>

<Accordion title="オファリングの優先度の値とは何ですか?また、どのように機能しますか?">
  優先度の値は、同じ表示面またはユーザーに対して複数のオファリングが適格な場合に、オファリングの重要度を決定します。優先度の高いオファリングが先に表示されます。例えば、優先度10のオファリングは、優先度5のオファリングより先に表示されます。
</Accordion>

<Accordion title="表示キャッピングはどのように機能しますか?">
  表示キャッピングは、オファリングがユーザーに表示される頻度を制御します。

  - ユーザーごとの上限: 個々のユーザーがオファリングを表示する回数を制限します。
  - 全体の上限: オファリングのターゲットセグメント内のすべてのユーザーにおける合計表示回数を制限します。
</Accordion>

<Accordion title="Capping Reset Frequencyはどのように機能しますか?">
  **Capping Reset Frequency** 設定は、各オファリングの表示上限がリセットされるタイミングを制御します。これは、ユーザーごとの上限と全体の上限の両方に適用されます。Daily、Weekly、Monthlyの3つのリセット間隔をサポートしています。これらの上限のリセットスケジュールは次のとおりです(時刻はすべてUTC)。

  - Daily: 毎日午前12:30までにリセットされます。
  - Weekly: 毎週日曜日の午前12:30までにリセットされます。
  - Monthly: 毎月1日の午前12:30までにリセットされます。
</Accordion>

<Accordion title="オファリングにタグを割り当てることはできますか?">
  はい、オファリングを整理しやすくするためにタグを割り当てることができます。例えば、シーズン、キャンペーン名、カテゴリーでプロモーションにタグを付けることができます。これらのタグにより、Decision Policyでの動的なグループ化も可能になります。
</Accordion>

<Accordion title="オファリングの適格性ルールに一致するユーザーがいない場合はどうなりますか?">
  オファリングの適格性ルールに一致するユーザーがいない場合、そのオファリングは表示されません。フォールバックコンテンツを確実に表示するには、関連するDecision Policyでフォールバックオファリングを設定して、その不足を補うことができます。
</Accordion>

<Accordion title="オファリングでパーソナライズされたコンテンツ(例: ユーザー名)を使用できますか?">
  いいえ、オファリングでのパーソナライズされたコンテンツのサポートは現在有効になっていません。
</Accordion>

<Accordion title="オファリングに動画やGIFなどのリッチメディアを含めることはできますか?">
  現在、オファリングのコンテンツプレビューでは画像とテキストを表示できますが、動画やGIFのサポートは実装によって異なります。
</Accordion>

<Accordion title="オファリングの異なるバージョンをA/Bテストできますか?">
  はい。1つのオファリング内に、オファリングコンテンツのバリエーションを最大5つ作成できます。オファリングの作成時に、Step 2で ***+A/B Test*** CTAをクリックします。
</Accordion>

<Accordion title="オファリングではどのような分析を利用できますか?">
  MoEngageは、各オファリングについて次のような詳細な分析を提供します。

  - インプレッション数(オファリングを表示したユーザー)。
  - クリック数(オファリングにエンゲージしたユーザー)。
  - コンバージョンイベント数(コンバージョンイベントを実行したユーザー)。
  - ユーザーあたりの収益(コンバージョン目標に収益属性が選択されている場合)。
  - 平均注文額(コンバージョン目標に収益属性が選択されている場合)。

   MoEngageは、上記の指標について各バリエーションの詳細な分析を提供します。
</Accordion>

<Accordion title="個々のオファリングのエンゲージメントをどのように追跡できますか?">
  APIレスポンス内のoffering\_contextキーを使用してエンゲージメントを追跡できます。これにはインプレッションとクリックの指標が含まれ、MoEngageの分析システムを通じてレポートできます。
</Accordion>

<Accordion title="作成後にオファリングを一時停止または削除できますか?">
  いいえ、一時停止や削除はできません。代わりに、オファリングをアーカイブして、Decision Policyに含まれないようにすることができます。
</Accordion>

<Accordion title="誤ったオファリングを公開してしまった場合はどうすればよいですか?">
  誤ったオファリングを公開した場合は、そのオファリングをアーカイブしてください。これにより、アーカイブした時点以降、そのオファリングがDecision Policyで使用されなくなります。
</Accordion>

<Accordion title="作成できるオファリングの数に制限はありますか?">
  同時に保持できるアクティブなオファリングの数に、プラットフォームによる制限はありません。
</Accordion>

<Accordion title="アクティブなDecision Policyの数に制限はありますか?">
  いいえ。同時にアクティブにできるDecision Policyの数に、プラットフォームによる制限はありません。
</Accordion>

<Accordion title="オファリングの稼働後に編集できますか?">
  はい、アクティブなオファリングは編集できます。ただし、オファリングの稼働後は、新しいバリエーションの追加、既存のバリエーションの配分の変更、新しいコンバージョン目標の導入はできません。その他の設定はすべて編集可能です。
</Accordion>

<Accordion title="オファリングの稼働後にフリクエンシーキャッピングを編集できますか?">
  はい。全体の上限(セグメント全体)とユーザーごとの上限は、いつでも更新できます。ただし、システムがこれらの変更をどのように適用するかは、上限値を調整するか、時間の周期(ケイデンス)を調整するかによって異なります。
  - ***ケース1: 初めて上限を追加する場合***
    - アクティブなオファリングに以前キャッピングの上限がなかった場合、追加した新しい上限は、変更を公開すると ***すぐに*** 有効になります。
  - ***ケース2: 既存の上限を更新する場合***
    - すでに有効な上限を変更する場合、動作は具体的に何を変更するかによって異なります。
    - ***シナリオA: 上限値を変更する場合(ケイデンスは同じ)***
      - 同じ期間(例: Weekly)のまま数値を更新する場合(例: 5から10)、システムはオファリングがすでに表示された ***現在のカウントを保持*** します。
      - ***上限を引き上げる場合***: 新しい上限に達するまで、オファリングは引き続き表示されます。
        - *例: 上限を週5回から10回に引き上げました。すでに2回表示したユーザーは、今週さらに8回表示できます。*
      - ***上限を引き下げる場合***: ユーザーがすでに新しい上限を超えている場合、次の期間(日/週/月)が始まるまでオファリングは表示されなくなります。
        - *例: 上限を週5回から2回に引き下げました。すでに3回表示したユーザーは、新しい週が始まるまで再び表示されません。*
    - ***シナリオB: ケイデンスを変更する場合(期間の変更)***
      - ケイデンスを変更する場合(例: WeeklyからDaily、MonthlyからWeeklyへの切り替えなど)、システムはすべてのユーザーの ***頻度カウンターを0にリセット*** します。
        - 新しいルールと上限は、変更した時点から「白紙の状態」で適用されます。
        - *例: 上限を週5回から1日5回に変更しました。ユーザーがその週の初めにオファリングを3回表示していても、カウンターは0にリセットされるため、その日に5回表示できます。*
</Accordion>

<Accordion title="オファリングが表示上限に達するとどうなりますか?">
  オファリングが設定された表示上限(例: 合計インプレッション数またはユーザーベースの上限)に達すると、ユーザーが適格性の基準に一致していても、それ以降は表示されなくなります。
</Accordion>

# Offering Attributes

<Accordion title="既存のOffering PriorityまたはMerlin AI戦略でOffering Attributesを使用できますか?">
  いいえ。Offering Attributesは、Custom Formulaランキング戦略でのみ使用されます。Offering PriorityおよびMerlin AI戦略は独自のランキングロジックを使用し、属性スコアは組み込みません。
</Accordion>

<Accordion title="Custom Formulaを使用するDecision Policyに含まれるオファリングに属性を割り当てない場合はどうなりますか?">
  数式で使用される特定の属性の値がオファリングにない場合、その属性のスコアは0として扱われます。オファリングは引き続きランキングに表示されますが、その属性に割り当てられた重みの恩恵を受けません。
</Accordion>

<Accordion title="属性名またはオプション値を編集すると、稼働中のオファリングとDecision Policyはどうなりますか?">
  属性名とオプション値の変更は、現在稼働中のものを含め、関連するすべてのオファリングとDecision Policyに即座に反映されます。MoEngageは、このような変更を確定する前に警告を表示するため、影響を評価できます。
</Accordion>

<Accordion title="作成後に属性をFixed ValueからDynamic Valueに切り替えることはできますか?">
  その属性がまだどのオファリングやDecision Policyでも使用されていない場合に限り可能です。関連付けられると、タイプはロックされます。タイプを変更する必要がある場合は、正しいタイプで新しい属性を作成し、それに応じてオファリングとポリシーを更新してください。
</Accordion>

<Accordion title="Offering Attributesを作成・管理できるのは誰ですか?">
  Adminロールを持つユーザーのみです。Authorは、オファリングの作成時または編集時に属性をオファリングに割り当てることはできますが、属性の定義を作成、変更、削除することはできません。
</Accordion>

<Accordion title='Settingsに"Offer Decisioning"セクションが表示されません。どうすればよいですか?'>
  この機能はアカウントレベルの機能フラグによって制御されています。セクションが表示されない場合、またはAccount Managerに連絡するよう求めるメッセージが表示される場合は、MoEngageのAccount Managerまたはサポートチームに連絡して、アカウントでこの機能を有効にしてもらってください。
</Accordion>

<Accordion title="作成できる属性の数に制限はありますか?">
  はい。現在の上限は、アカウントあたり50個の一意のOffering Attributesです。
</Accordion>

<Accordion title="同じユーザープロファイル属性を複数のDynamic Value Offering Attributesで使用できますか?">
  はい。ユーザープロファイル属性は、複数のOffering Attributesで参照できます。ただし、1つのDynamic Value Offering Attribute内では、同じユーザー属性をマッピングリストに複数回含めることはできません。
</Accordion>
