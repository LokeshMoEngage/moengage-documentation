先月、10%割引を提供するキャンペーンを成功裏に実施したとします。今度は、高価値でロイヤルティの高い顧客を優遇するために、より大きな割引を提供するキャンペーンを実施したいと考えていますが、対象は前回のキャンペーンに反応した顧客のみです。たとえば、先月の支出額がその前の月と比べて20%増加した顧客のみをターゲティングしたいとします。このような顧客をどのようにセグメント化すればよいでしょうか?

グロースチームがユーザーを効果的にターゲティングするには、高度なセグメンテーション機能が必要です。集計を使用すると、集計演算子を活用してセグメンテーションクエリをより深くすることができます。集計演算子を使用して実行できるユースケースの例を以下に示します。

1. 過去30日間に1000ドル以上を支出したユーザーをフィルタリングする
2. フルーツカテゴリで200ドル以上購入したユーザーをフィルタリングする
3. ファッションカテゴリの支出を10%増加/減少させたユーザーをフィルタリングする
4. 注文あたりの平均支出額が先週と比べて15%増加したユーザーをフィルタリングする

集計を使用すると、グロースチームは合計、平均、最小、最大、中央値などの演算を使用して[イベント属性](/ja/user-guide/data/event-data/derived-events-and-attributes)を集計できます。イベント属性に対する集計演算子を[数値フィルター](/ja/user-guide/segment/advanced-concepts/filters-in-segmentation)と組み合わせることで、高度なクエリを作成し、より深い顧客セグメントを抽出できます。

# 集計演算子

| 集計演算子 | 説明 |
| --- | --- |
| Sum | ユーザーについて、選択した期間内のフィルタリングされたイベント全体における選択した属性値の合計です。 |
| Average | ユーザーについて、選択した期間内のフィルタリングされたイベント全体における選択した属性値の平均です。 |
| Minimum | ユーザーについて、選択した期間内のフィルタリングされたイベント全体における選択した属性値の最小値です。 |
| Maximum | ユーザーについて、選択した期間内のフィルタリングされたイベント全体における選択した属性値の最大値です。 |
| Median | ユーザーについて、選択した期間内のフィルタリングされたイベント全体における選択した属性値の中央値です。 |
| Change | ユーザーについて、選択した期間の間でのフィルタリングされたイベント全体における集計属性値の絶対的な変化です。 プライマリ期間は、選択したイベントに関連付けられた期間です。ベース期間は、集計演算子に関連付けられた期間です。 Change = プライマリ期間の集計値 - ベース期間の集計値 |
| Percentage Change | ユーザーについて、選択した期間の間でのフィルタリングされたイベント全体における集計属性値の相対的な変化です。 Percentage Change = (プライマリ期間の集計値 - ベース期間の集計値)\*100/ ベース期間の集計値 |

<Info>
- 集計は、該当する場合、30日/4週間/720時間/1か月の期間にわたって適用できます。これらの上限は変更可能です。変更をご希望の場合は、担当のCSMにお問い合わせください。
- ChangeとPercentage Changeは、どちらも負の値になる場合があります。
- Previous Period: 前の期間とは、プライマリ期間の直前にある同じ長さの期間です。これが集計のベース期間になります。現在が2022年5月18日午後5時15分であると仮定します。'last 3 days' のプライマリ期間が2022年5月15日～2022年5月18日の場合、ベース期間は2022年5月12日～2022年5月14日になります。
- Date Range: ユーザーについて、フィルタリングされたイベント全体で属性値を集計するために使用できる日付範囲です。選択した日付範囲が集計のベース期間になります。
</Info>

# 注意事項

1. sum、min、max、average、medianは数値関数であるため、集計は数値属性でのみ使用できます。
2. 集計は、セグメンテーションのUser Behaviorセクションでのみ使用できます。
3. イベントの保持期間と集計:
   - 集計の前の期間は、イベントの保持期間を超えることはできません。
   - 'Date range' で使用できる日付は、イベントの保持期間および集計ウィンドウを超えることはありません。
4. 中央値は、選択した属性値のおおよその50パーセンタイルです。
5. ユーザーについて、フィルタリングされたイベントがプライマリ期間には存在するもののベース期間には存在しない場合、そのユーザーはChangeとPercentage Changeのどちらにもカウントされません。たとえば、ベース期間にはユーザーの購入イベントがないものの、プライマリ期間には存在する場合、そのユーザーはChangeおよびPercentage Changeの集計の計算対象になりません。
6. ChangeとPercentage Changeは、次の日付フィルターでは使用できません: Before、After、In the last N hours/weeks/months**、** last week、this week、last month、this month。
