# 概要

リアルタイムセグメント評価（RTSE）を使用すると、ユーザーが重要なアクションを実行した瞬間に、そのユーザーの属性、行動、関心に基づいてオーディエンスにエンゲージできます。これにより、タイムリーで関連性の高いキャンペーンを送信し、ユーザーの行動に応じたレコメンデーションをその場で提供する能力が向上します。

これは、設定されたスケジュールで更新される定期セグメントとは対照的です。定期セグメントは幅広いオーディエンス分析に強力ですが、RTSE は即時のアクションベースのマーケティング向けに設計されています。

# リアルタイムセグメント評価の仕組み

RTSE の仕組みを理解すると、その強みが明確になります。このプロセスは即時に行われるように設計されています。

- **ユーザーアクション:** ユーザーがアプリまたはウェブサイトでトリガーイベントを実行します（例: カートに商品を追加する、特定の商品を閲覧する、サインアップを完了する）。
- **リアルタイム評価:** MoEngage は、この新しいアクションとユーザーの最近の行動に基づいて、このユーザーがキャンペーンのオーディエンス条件を満たすかどうかを即座に確認します。
- **キャンペーンのトリガー:** ユーザーが条件を満たす場合、キャンペーンが即座にトリガーされます。

これにより、ユーザーのアクションから数時間後、機会が過ぎ去ってしまった後ではなく、最も関連性の高い瞬間にメッセージが配信されます。

<Note>
  1 つのワークスペースで同時に使用できるアクティブなリアルタイムセグメントは最大 **10 個** で、1 日に登録できる新しいリアルタイムセグメントは最大 **10 個** です。アクティブセグメントの上限を超えると、リアルタイムセグメントを使用する新しいキャンペーンまたはフローの開始に失敗します。これらの上限を引き上げるには、サポートにお問い合わせください。
</Note>

## 定期更新の間隔

セグメントがリアルタイムで評価されない場合、MoEngage はスケジュールに従ってセグメントを更新します。間隔はキャンペーンタイプによって異なります。

| キャンペーンタイプ | おおよその更新間隔 |
| --- | --- |
| Smart Trigger キャンペーンおよび Flows | 3 時間 |
| インバウンドチャネル（In-App、On-Site Messaging、Cards） | 6 時間 |

更新と更新の間は、最後の更新時点のセグメントメンバーシップが適用されます。これはエントリーと除外の両方に影響します。条件を満たし始めたユーザーは次の更新までターゲットにされず、キャンペーンを送信されたばかりのユーザーでも、次の更新前にトリガーイベントを実行すると再度キャンペーンを受信する可能性があります。詳細については、[イベントトリガーキャンペーンの作成](/ja/user-guide/campaigns-and-channels/getting-started/triggers/event/create-an-event-triggered-campaign)および[イベントトリガーフロー](/ja/user-guide/flows-cross-channel-messaging/faqs/event-triggered-flows)を参照してください。

## RTSE のメリット

- **リテンション率の向上**: リアルタイムセグメンテーションにより、企業は行動、嗜好、過去のインタラクションに基づいて特定の顧客グループをターゲットにできます。このパーソナライズされたアプローチとリアルタイムセグメンテーションを組み合わせることで、エンゲージメントとユーザーリテンションを高めることができます。
- **タイムリーさ**: リアルタイムセグメンテーションにより、ユーザーがウェブサイトを閲覧しているとき、カートに商品を追加したとき、マイルストーンに到達したときなど、適切なタイミングでターゲットキャンペーンを送信できます。このタイムリーさにより、ユーザーの注意を引き、アクションを促す可能性が高まります。
- **関連性**: ユーザーをリアルタイムでセグメント化することで、送信するキャンペーンが個人の現在の関心やニーズに合ったものになります。この関連性によりユーザーエクスペリエンスが向上し、キャンペーンが受信者の心に響きやすくなります。
- **コンバージョン率の向上**: リアルタイムセグメンテーションにより、関連性が高くタイムリーなオファーでユーザーをターゲットにでき、コンバージョンの可能性が高まります。カスタマージャーニーの重要な瞬間にユーザーにリーチすることで、コンバージョン率を高め、収益の成長を促進できます。

# RTSE を使用したキャンペーンの作成

イベントトリガーキャンペーンで RTSE を活用すると、顧客のアクションに基づいてリアルタイムでパーソナライズされたメッセージを送信できます。たとえば、ユーザーがアプリケーションを最新バージョンに更新した場合、新しい機能をすぐに伝えることができます。

次の手順を実行します。

1. MoEngage ダッシュボードの左側のナビゲーションで、**\+ Create new** \> **Campaign** をクリックします。
2. [RTSE をサポートするチャネル](#channels-that-support-rtse)のいずれかを選択し、配信タイプとして **Event triggered** を選択します。詳細については、[イベントトリガーキャンペーンの作成](/ja/user-guide/campaigns-and-channels/getting-started/triggers/event/create-an-event-triggered-campaign)を参照してください。
3. **IF user performs** セクションで、_App update_ などのトリガーイベントを選択します。これが評価を開始する主要なアクションです。
4. **THEN trigger the message** セクションで **Immediately** を選択すると、ユーザーのアクションから数秒以内にキャンペーンが送信されます。

![メッセージを即時にトリガー](/images/moengage_ae2241.png)

5. **Select audience** セクションで **Filter users by** を選択し、**User property** または **User behavior** タブでセグメンテーション条件を追加します。

<Info>
  選択したセグメンテーション条件が RTSE でサポートされている場合、UI に直接確認メッセージが表示されます。

  _"Campaign segments will be evaluated in real-time on the latest data."_

  このメッセージが表示されない場合、キャンペーンは定期的なスケジュールで更新される定期セグメンテーションを使用します。間隔については、[定期更新の間隔](#periodic-refresh-intervals)を参照してください。
</Info>

# FAQ

<Accordion title="キャンペーンが RTSE を使用しているかどうかを確認するにはどうすればよいですか？">
  キャンペーンの作成中に、セグメンテーションフィルターがリアルタイム評価の対象である場合、UI に次のメッセージが表示されます: "Campaign segments will be evaluated in real-time based on the latest data." このインジケーターは作成プロセス中にのみ表示され、メインのキャンペーンダッシュボードには表示されないことに注意してください。
</Accordion>

<Accordion title="RTSE がイベントトリガーキャンペーンに最も適しているのはなぜですか？">
  RTSE は、ユーザーのアクションが発生した時点で反応するように設計されています。その主な価値は、ユーザーが重要なイベント（「トリガー」）を実行した正確な瞬間に、そのユーザーがセグメントの対象となるかどうかを評価できることにあります。そのため、タイムリーさとコンテキストが成功の鍵となるイベントトリガーキャンペーンに最適です。即時のアクションではなく過去のデータに基づいて幅広いオーディエンスをターゲットにするその他のキャンペーンタイプには、定期セグメンテーションの方が適しています。
</Accordion>

<Accordion title="RTSE キャンペーンの「Reachable Users」の数はどのように解釈すればよいですか？">
  **Show count** をクリックすると、その時点で条件を満たしているユーザー数のスナップショットが表示されます。ただし、RTSE の真の強みは、トリガーイベントを実行した各ユーザーに対して評価がリアルタイムで行われることです。つまり、現時点では条件を満たしていないユーザーでも、1 時間後にアクションを実行して条件を満たせば、キャンペーンにエントリーします。この数は参考になる推定値ですが、実際のオーディエンスはリアルタイムで決定されます。
</Accordion>

<Info>
  サンプルユーザーリストには、連絡先情報が重複するエントリー（例: 同じメール ID）が表示される場合があります。MoEngage はキャンペーン送信時に自動的に重複を排除し、各ユニークユーザーがメッセージを 1 回だけ受信するようにします。
</Info>
