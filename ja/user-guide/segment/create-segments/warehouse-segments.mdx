ウェアハウスセグメントを使用すると、データウェアハウスのデータを MoEngage にコピーしたり移動したりする手間をかけずに、そのデータに基づいて MoEngage でセグメントを作成できます。

たとえば、独自のロジックで算出したエンゲージメントスコアに基づいて、ロイヤルな買い物客に限定割引を提供したいとします。このデータはデータウェアハウスにのみ保存されており、そこからしかアクセスできません。ウェアハウスセグメントを使用すると、ウェアハウスのデータに直接アクセスして MoEngage でオーディエンスを作成し、数回のクリックで MoEngage からキャンペーンを送信できます。

データはウェアハウス内にとどまるため、同期の遅延なくデータにアクセスでき、データは自社のセキュリティおよびコンプライアンスの範囲内に保持されます。

# 設定方法

<Steps>
  <Step title="データウェアハウスを接続する">
    MoEngage に読み取りアクセス権を付与し、接続を設定します。手順はウェアハウスによって異なります。以下のどちらの方法でも必要です。

    [データウェアハウスを接続する](/ja/user-guide/segment/create-segments/warehouse-segments/connect-your-warehouse)
  </Step>
  <Step title="オーディエンスの定義方法を選択する">
    SQL クエリを記述するか、ドロップダウンフィルターからセグメントを作成します。以下の比較を参照してください。
  </Step>
  <Step title="ウェアハウスのスキーマをマッピングする（フィルターのみ）">
    フィルタービルダーを使用するには、**Settings** でウェアハウスのテーブルを MoEngage のユーザー、イベント、属性にマッピングします。

    [ウェアハウススキーマ](/ja/user-guide/data/warehouse-schemas)
  </Step>
</Steps>

# ウェアハウスセグメントを定義する 2 つの方法

どちらの方法もウェアハウスに対して実行され、キャンペーンでターゲットにできるカスタムセグメントを作成します。

| | [SQL タブ](/ja/user-guide/segment/create-segments/warehouse-segments/create-using-sql) | [Filter タブ](/ja/user-guide/segment/create-segments/warehouse-segments/create-using-filters) |
| --- | --- | --- |
| おすすめのケース | SQL の記述に慣れている場合 | SQL を記述したくない場合 |
| オーディエンスの定義方法 | 自分で記述する SQL クエリ | マッピングされた属性とイベントに対するドロップダウンフィルター |
| 必要な設定 | ウェアハウスの接続 | ウェアハウスの接続に加え、[ウェアハウススキーマ](/ja/user-guide/data/warehouse-schemas)でのテーブルのマッピング |
| ウェアハウス | BigQuery、Snowflake、Databricks、Redshift | BigQuery、Databricks |
| 集計とカスタム SQL ロジック | 利用可能 | 利用不可 |
| セグメントタイプ | Warehouse - SQL | Warehouse - filter |

日常的なオーディエンスの作成にはフィルターを使用します。フィルタービルダーで対応できない集計や変換がロジックに必要な場合は、SQL を使用します。
