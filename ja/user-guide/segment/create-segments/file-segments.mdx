グロースチームは、ユーザーおよびユーザーデータに対して独自の分析を行うことがよくあります。分析後、グロースチームはこれらのユーザーをキャンペーンで使用したり、さらに分析を行ったりしたいと考えます。

これらのユーザーは MoEngage にアップロードして、ファイルセグメントとして使用できます。ファイルセグメントはユーザーのリストです。ファイルセグメントは、MoEngage のキャンペーンや Analytics で使用できます。

ファイルセグメントを使用すると、自社で行ったユーザー分析によって特定したユーザーセグメントを柔軟に作成し、ターゲットにできます。一意のユーザーを識別するユーザー属性のいずれかを含むユーザーリストをインポートすると、これらのユーザーのカスタムセグメントが作成されます。

# ファイルセグメントの作成

ステップ 1:

MoEngage Dashboard \> Segment \> All Segments \> \+Segment \> File Segment に移動します

![File\_segment\_1.gif](/images/moengage_f964bb.png)

ステップ 2:

1. カスタムセグメントの名前と説明を入力します。

   <Note>
   名前 `All Users` は MoEngage によって予約されているため、カスタムセグメント名として使用できません。また、名前には `:` `|` `*` `?` `\` `<` `>` `=` `$` `"` の文字を含めることはできず、ピリオド (.) で始めることはできず、空白のみで構成することはできず、200 文字を超えることはできません。無効な名前または予約名を持つファイルセグメントは拒否され、カスタムセグメントのドロップダウンに表示されないか、ユーザー数が 0 と表示されます。これは、API または外部連携を通じて作成されたファイルセグメントにも適用されます。
   </Note>

2. ユーザーリストを含むファイルを選択します。CSV をアップロードするか、その URL を指定できます。
3. リストで使用しているユーザー属性を選択します。たとえば、ユーザーの Driving ID のリストがある場合は、ユーザー属性のドロップダウンから Driving ID を選択します。
4. カスタムセグメントが作成されたときに MoEngage が通知するメール ID を 1 つ以上入力します。

**注:** メールを受信した後にセグメントが表示されない場合は、ページを更新して検索してください。

![File\_segment\_3.gif](/images/moengage_42d23e.png)

<Warning>
  ユーザー属性の値は、単一のユーザーを一意に識別する必要があります。属性値が複数のユーザーを識別する場合（例: 値が「London」の city 属性には多くのユーザーが該当する可能性があります）、これらの複数のユーザーが単一の属性にマッピングされてセグメントの一部となり、他のユーザーがセグメントに含まれることを妨げる可能性があります。

  たとえば、5 つのメールをアップロードし、最初のメールが 3 人のユーザー（A、B、C）に一致し、残りの 4 つのメールがそれぞれ 1 人のユーザー（D、E、F、G）に一致したとします。この場合、システムはランダムに 5 人のユーザーを選択してファイルセグメントに追加します。

  システムは 2,000 個の属性値ごとのバッチで処理を行い、各バッチで最大 2,000 人のユーザーをファイルセグメントに追加します。ユーザー属性の値が少ない場合でも、より多くのユーザーがファイルセグメントに追加される可能性があります。たとえば、1500 個のユーザー属性値が 2500 人のユーザーに該当する場合、システムはこの 2500 人のうち 2000 人をランダムにファイルセグメントに追加します。

  ファイルセグメントに含める前に、すべてのユーザーが MoEngage にインポートされていることを確認してください。正常にマッピングできるのは既存のプロファイルのみです。

  30 日以上アーカイブされたファイルセグメントでは、ユーザーが完全に削除されます。このデータは削除後に復元できません。
</Warning>

## ファイルの要件

アップロードする前に、ファイルが次の要件を満たしていることを確認してください。

- ファイルは、ユーザー属性を含む単一の列を持つ CSV 形式である必要があります。
- ファイルサイズは 64 MB を超えてはなりません。
- ファイルに重複する値、空の行、空の列を含めてはなりません。

ファイル内の値には文字の制限はなく、ユーザー属性の値にはどのような文字も使用できます。文字の制限はファイルセグメント名にのみ適用され、ファイルの内容には適用されません。ただし、先頭または末尾のスペース、二重引用符で囲まれた値、UTF-8 以外の文字があると、値がユーザーと一致しなくなり、最終的なユーザー数が減少する可能性があります。

[サンプル CSV ファイルをダウンロードします。](https://app-cdn.moengage.com/assets/Sample_GAIDs.csv)

## URL の要件

ファイルを直接アップロードする代わりに URL を指定する場合は、次の条件を満たす必要があります。

- URL は公開アクセス可能である必要があります。プライベートな URL や期限切れの URL は MoEngage がダウンロードできず、ユーザー数 0 のセグメントになります。
- ファイルがプライベートエンドポイントの背後でホストされている場合は、関連する MoEngage の IP アドレスをホワイトリストに登録してアクセスを許可します。ホワイトリストに登録する IP アドレスのリストについては、MoEngage の CSM またはサポートチームにお問い合わせください。
- URL のファイルは、CSV の直接アップロードと同じ形式の要件を満たす必要があります。
- URL で指定するファイルは最大 300 MB まで可能です（直接アップロードの上限は 64 MB）。

## カスタムセグメントの利用可能性

MoEngage システムはファイルセグメントのリクエストを受信するとすぐに、カスタムセグメントを作成します。カスタムセグメントの作成後、システムはユーザーを処理し、それらのユーザーをカスタムセグメントに追加します。\
そのため、カスタムセグメントはファイルの処理中も、ファイルの処理に失敗した場合も **利用可能** です。ファイルセグメントが処理されると、そのステータス（完了または失敗）がメールで通知されます。

ファイルのアップロード/処理に失敗した場合は、同じカスタムセグメント名を使用してファイルを再度アップロードできます。システムは、指定されたカスタムセグメントに新しいユーザーを追加します。この機能により、既存のファイルカスタムセグメントに新しいユーザーを追加することもできます。

## ファイルセグメント処理のステータスと警告

完全に処理される前にファイルセグメントを使用することで発生する問題を防ぐために、MoEngage は UI に警告を表示します。これらの警告により、セグメントがまだ処理中かどうか、およびいつ使用するのが望ましいかを把握できます。

![スクリーンショット 2025-05-19 午後 3.16.56.png](/images/moengage_803c22.png)

<Info>
  これらの警告は次のページに表示されます。

  - Create segment ページ
  - すべてのキャンペーン作成ページの **Target audience** セクション
  - 分析ページの **Target audience** セクション
</Info>

### セグメント使用時の警告

別のセグメントの作成、キャンペーンのターゲティング、または分析で使用するために、まだ処理中のファイルセグメントを選択すると、警告メッセージが表示されます。警告は次の条件に基づいて表示されます。

- **選択した単一のセグメントが処理中の場合**: "Users are being updated in this segment - `<Custom Segment name>`. We suggest that you wait until the confirmation email is received to use this segment in a campaign. Keep an eye here for the latest update."
- **別のセグメントにネストされたセグメントが処理中の場合**: "Users are being updated in these segments - `<Custom Segment 1, Custom Segment 2, Custom Segment 3 names>`. These segments are nested in the parent segment chosen. We suggest that you wait until the confirmation email is received to use the segment in a campaign. Keep an eye here for the latest update."

最新のステータスを確認するには、ページを更新するか、セグメントを再度選択します。キュー内の最後のファイルが正常に処理されると、この警告は表示されなくなります。

### セグメント詳細ページの警告

現在更新中の（つまり、ファイルのアップロードがまだ処理中の）カスタムセグメントの詳細ページに移動すると、次のような警告メッセージが表示されます: "Users are being updated in this segment - `<CS name linked>`. We suggest that you wait until the confirmation email is received to use this segment in a campaign. Keep an eye here for the latest update."

セグメントの最新のステータスを確認するには、ページを更新します。ファイルの処理が正常に完了すると、この警告は表示されなくなります。

## ユーザーの利用可能性

ファイルセグメントには、MoEngage に存在するユーザーのみを含めることができます。MoEngage システムに存在しないユーザーをアップロードした場合、そのユーザーは処理されず、ファイルセグメントの一部になることはできません。

新しいユーザーを MoEngage にアップロードし、それらのユーザーのファイルセグメントを作成するには、[ユーザーのインポート](/ja/user-guide/data/imports/manual-uploads)を参照してください。

ファイルセグメントを介してアップロードされるユーザーの総数は、1 日あたり 200 万人に制限されています。\
（この上限はカスタマイズ可能です。上限を引き上げるには、サポートにお問い合わせください。）

1 つのファイルセグメントには最大 500 万人のユーザーを含めることができます。File Segment API を使用してファイルセグメントを作成または更新する場合、1 つのワークスペースで実行できる操作は 1 時間あたり最大 10 回、1 日あたり最大 100 回（24 時間のローリングウィンドウで計算）です。これらの上限を超えるリクエストは 429 レスポンスで拒否されます。

# ファイルセグメントの編集

既存のファイルセグメントは、MoEngage ダッシュボードから編集できます。MoEngage ダッシュボードでは、ファイルセグメントに対して次のアクションを実行できます。

1. ユーザーの追加: 既存のファイルセグメントに新しいユーザーリストを追加できます。
2. ユーザーの削除: 既存のファイルセグメントからユーザーリストを削除できます。
3. ユーザーの置換: 既存のファイルセグメント内のユーザーリストを置き換えることができます。

ステップ 1:

Segment \> All Segments ページから、編集するファイルセグメントに移動します。

ステップ 2:

Actions タブで、More Actions の縦の三点リーダーをクリックし、Edit オプションを選択します。

ステップ 3:

1. ファイルセグメントに対して実行する編集アクションを、Add users、Remove users、Replace users の中から選択します。
2. 追加、削除、または置換するユーザーリストを含むファイルを選択します。CSV をアップロードするか、その URL を指定できます。
3. リストで使用しているユーザー属性を選択します。たとえば、ユーザーの Driving ID のリストがある場合は、ユーザー属性のドロップダウンから Driving ID を選択します。
4. カスタムセグメントが処理されたときに MoEngage が通知するメール ID を 1 つ以上入力します。

![File\_segment\_4.gif](/images/moengage_8aedda.png)

ファイルセグメントのすべての機能（セグメントの作成、ファイルセグメントからのユーザーの削除と置換）には、[File Segment API](/ja/api/file-segments/create-file-segment) を使用してアクセスすることもできます。

# ファイルセグメントのアーカイブ/アーカイブ解除

ファイルセグメントは MoEngage ダッシュボードからアーカイブできます。

1. 過去 60 日間に実行されていない（クエリが実行されていない）ファイルセグメントは、自動的にアーカイブされます。
2. 継続的なコホートやファイルの同期は実行としてカウントされないため、定期的に同期している外部からインポートされたファイルセグメントでも自動的にアーカイブされる可能性があります。アクティブな状態を維持するには、ダッシュボードから手動で実行するか、セグメンテーションフィルターで使用します。
3. 外部からインポートされたファイルセグメント（例: Amplitude やその他の外部ツールから）は、ダッシュボードからアーカイブまたはアーカイブ解除することはできません。アーカイブを解除するには、[Unarchive Segment API](/ja/api/manage-segments/unarchive-segment) を使用します。
4. アーカイブされたファイルカスタムセグメントのすべてのユーザーは、アーカイブから 30 日後に削除されます。そのため、アーカイブから 30 日後には、アーカイブされたカスタムセグメントのユーザー数は 0 になります。

<Warning>
  アーカイブされたセグメントは、180 日を過ぎると表示されなくなります。
</Warning>

# FAQ

<Accordion title="MoEngage のファイルセグメントとアップロードしたファイルでユーザー数が異なるのはなぜですか？">
  ### 問題

  アップロードしたファイルと MoEngage のファイルカスタムセグメントの間で、ユーザー数に不一致があります。

  ### 説明

  このような違いが生じる考えられる理由は次のとおりです。

  - ユーザー数が 0
    - **誤った属性の指定:** ファイルセグメントのアップロード時に選択した属性が、ファイルで指定された値と一致していません。たとえば、選択した属性が _age_（double データ型）であるのに、ファイルに _name_（string データ型）の値が含まれている場合、MoEngage に一致するユーザーが存在せず、ユーザー数が 0 になります。
    - **ファイルをダウンロードできない:** 指定されたファイルの URL がプライベートまたは期限切れの場合、MoEngage はファイルをダウンロードできず、カスタムセグメントにユーザーが追加されないため、ユーザー数が 0 になります。
    - **不適切な CSV の内容:** 値の先頭または末尾のスペース、スペースのみの行、UTF-8 以外の文字、二重引用符で囲まれた値、カンマで終わる値などの問題があると、ユーザー数が 0 になる可能性があります。
    - **ファイル処理の遅延:** ファイルをアップロードした後、ユーザーはすぐにはカスタムセグメントに追加されません。処理時間はファイル内の値の数に応じて長くなります。アップロード直後にカスタムセグメントをクエリすると、ユーザー数が 0 になる場合があります。
  - ユーザー数が少ない
    - **MoEngage のユーザーが少ない:** ファイルに記載された値が MoEngage の値と一致しない場合、それらは考慮されず、ユーザー数が少なくなります。
    - **不適切な CSV の内容:** ユーザー数が 0 の場合と同様に、CSV の内容に問題があると、ユーザー数が少なくなる可能性があります。
    - **ファイルのアップロードがまだ処理中:** ファイルのアップロード直後に、ユーザー数 0 のカスタムセグメントが作成されます。その後、ファイルの処理中にユーザーが追加されます。処理中にセグメントをクエリすると、ユーザー数が少なく表示される場合があります。
  - ユーザー数が多い
    - **属性値が複数のユーザーに一致する:** ファイルで指定された値が MoEngage の複数のユーザーに一致する場合、一致したすべてのユーザーがカスタムセグメントに追加され、ユーザー数が多くなります。

  詳細については、[ファイルセグメント](/ja/user-guide/segment/create-segments/file-segments)をお読みください。
</Accordion>

<Accordion title="ファイルセグメントへの CSV アップロードが失敗するのはなぜですか？">
  ### 問題

  ファイルセグメントで CSV ファイルをアップロードする際に、次のエラーメッセージが表示されます。

  There seems to be an error. We are working to fix this.

  ### 解決策

  次の手順を実行します。

  1. **ファイル形式を確認する**:
     - ファイルが CSV 形式であることを確認します。
  2. **ファイルサイズを確認する**:
     - ファイルサイズが 64 MB を超えていないことを確認します。ファイルが許容上限を超えている場合は、アップロードする前にサイズを縮小します。
  3. **一意の識別子の列を確認する**:
     - ファイルに、セグメントの一意の識別子として指定された列が 1 つだけ含まれていることを確認します。
     - 一意の識別子（UID）を使用することを推奨します。
  4. **空の行と不要なデータを削除する**:
     - ファイルの末尾に空の行がないか確認します。
     - 問題の原因となる可能性のある不要な値や重複する値を削除します。
  5. **レコードの値を属性のデータ型に合わせる**:
     - レコードの値が指定されたデータ型と一致していることを確認します。
  6. **有効なファイルセグメント名を使用する**:
     - 文字の制限はファイルセグメント名に適用され、ファイル内の値には適用されません。名前に `:` `|` `*` `?` `\` `<` `>` `=` `$` `"` の文字が含まれていないこと、ピリオド (`.`) で始まっていないこと、空または空白のみでないこと、200 文字を超えていないことを確認します。

  詳細については、[ファイルセグメント](/ja/user-guide/segment/create-segments/file-segments)をお読みください。
</Accordion>
