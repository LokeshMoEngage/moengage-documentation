## 問題

キャンペーンが、セグメントクエリを実行するとユーザーを返すセグメントをターゲットにしているにもかかわらず、キャンペーンの受信者が 0 人になります。セグメンテーションは正常に完了し、正確な件数として 0 を返します。

## 手順

Developer ロールを持つユーザーが本番アプリでキャンペーンを作成したかどうかを確認します。

本番アプリでは、MoEngage は [Developer ロール](/ja/user-guide/settings/account/team-management/access-roles#developer)で作成されたキャンペーンの対象を、テストユーザーまたはテストデバイスとしてマークされたユーザーに制限します。キャンペーンのオーディエンスは選択したセグメントとテストユーザーの共通部分になるため、テストユーザーを含まないセグメントでは受信者が 0 人になります。セグメンテーションのデバッグ出力では、この制限はクエリに追加された `moe_test_device = true` フィルターとして表示されます。

確認するには、キャンペーンを開き、作成したユーザーのロールを確認します。

セグメント全体にリーチするには、次のいずれかのオプションを選択します。

- 本番ユーザーに公開できるロール（Admin、Manager、Marketer）を持つユーザーに、キャンペーンの作成、またはキャンペーンの複製と送信を依頼します。
- Developer アカウントからキャンペーンを送信する前に、リーチしたいユーザーをテストユーザーとしてマークします。
- Developer によるテストが目的の場合は、テストアプリからキャンペーンを送信します。

キャンペーンで[キャンペーン承認ワークフロー](/ja/user-guide/settings/account/team-management/campaign-approval-workflow)を使用している場合、承認者が承認前にキャンペーンを編集すると、承認者自身のロールがキャンペーンに引き継がれるため、キャンペーンのターゲットも変わります。

## 例

カスタムセグメントは 146 人のユーザーを返しますが、そのセグメントに基づいて作成されたキャンペーンの受信者は 0 人です。Developer ロールを持つユーザーが本番アプリでキャンペーンを作成したため、テストデバイスの制限が適用されます。セグメントにはテストユーザーが含まれていないため、共通部分は空になります。Marketer アカウントからキャンペーンを複製して送信すると、146 人のユーザー全員にリーチします。
