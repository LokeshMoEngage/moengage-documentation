## 問題

特定の日に *App/Site Opened* などのイベントを実行したユーザー数が、データウェアハウスと MoEngage ダッシュボードで異なります。

## 説明

次の理由により、わずかな差異が生じる場合があります。

- データウェアハウスのエクスポートでは *event\_time*（イベントが発生した時刻）が使用されますが、MoEngage の Analytics と Segmentation ではサーバー時刻（MoEngage サーバーでイベントを受信した時刻）が使用されます。
- イベントがエクスポートされる際には、関連するユーザープロファイル（ユーザー ID と属性）もエクスポートされます。イベントがエクスポート対象として選択された直後にプロファイルのマージ、削除、または更新が発生した場合、これらの変更はエクスポートされたイベントには反映されません。ただし、新しいイベントには更新されたプロファイル属性が含まれます。
- MoEngage ダッシュボードのレポートはアプリのタイムゾーンで表示されますが、MoEngage の Automated Data Exports は UTC タイムゾーンで実行されます。お客様側でレポートを生成する際は、この違いを考慮してください。

<Info>
MoEngage Analytics はユニークユーザーに基づいて動作しますが、エクスポートにはエクスポートされたすべてのイベントの生データが含まれます。詳細については、[データエクスポートのボリュームを分析する](/ja/user-guide/data/exports/events/analyze-the-volume-of-data-exports)を参照してください。
</Info>

差異が 10% を超える場合は、データ損失やその他のエラーがないか調査する必要があります。

<Info>
MoEngage は、テーブルにイベントを直接転送する宛先として、複数のデータウェアハウスをサポートしています。サポートされているデータウェアハウスは次のとおりです。

- Amazon Redshift
- Google BigQuery（GCS 経由）
- Snowflake

MoEngage は、バケットに JSON ファイルとしてイベントを転送する宛先として、複数のクラウドストレージもサポートしています。サポートされているクラウドストレージは次のとおりです。

- Amazon S3
- Google Cloud Storages
- SFTP
</Info>
