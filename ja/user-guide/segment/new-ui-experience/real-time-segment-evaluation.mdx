# 概要

リアルタイムセグメント評価（RTSE）を使用すると、ユーザーが主要なアクションを実行した瞬間に、その属性、行動、興味に基づいてオーディエンスとエンゲージできます。ユーザーの行動が発生したタイミングで、適切なキャンペーンを送信し、それに基づくレコメンデーションを提供する能力が向上します。

これは、設定されたスケジュールで更新される定期的なセグメントとは対照的です。定期的なセグメントは幅広いオーディエンス分析に効果的ですが、RTSE は即時のアクションベースのマーケティング向けに設計されています。

# リアルタイムセグメント評価の仕組み

RTSE の仕組みを理解すると、その強みが明確になります。このプロセスは即時に実行されるように設計されています。

- **ユーザーのアクション:** ユーザーがアプリまたはウェブサイトでトリガーイベントを実行します（たとえば、カートに商品を追加する、特定の商品を閲覧する、サインアップを完了するなど）。
- **リアルタイム評価:** MoEngage は、この新しいアクションと最近の行動に基づいて、このユーザーがキャンペーンのオーディエンス条件を満たすかどうかを即座に確認します。
- **キャンペーンのトリガー:** ユーザーが条件を満たす場合、キャンペーンが即座にトリガーされます。

これにより、ユーザーのアクションから数時間後、機会が過ぎてしまった後ではなく、最も関連性の高い瞬間にメッセージが配信されます。

<Note>
  ワークスペースでは、一度に最大 **10 個のアクティブなリアルタイムセグメント**を保持でき、**1 日あたり最大 10 個の新しいリアルタイムセグメント**を登録できます。アクティブセグメントの上限を超えると、リアルタイムセグメントを使用する新しいキャンペーンや Flows を開始できません。これらの上限を引き上げるには、サポートにお問い合わせください。
</Note>

## 定期更新の間隔

セグメントがリアルタイムで評価されない場合、MoEngage はスケジュールに従ってセグメントを更新します。間隔はキャンペーンタイプによって異なります。

| キャンペーンタイプ | おおよその更新間隔 |
| --- | --- |
| Smart Trigger キャンペーンと Flows | 3 時間 |
| インバウンドチャネル（In-App、On-Site Messaging、Cards） | 6 時間 |

更新と更新の間は、最後の更新時点のセグメントメンバーシップが適用されます。これはエントリーと除外の両方に影響します。条件を満たし始めたユーザーは次の更新までターゲットにならず、キャンペーンを送信されたばかりのユーザーでも、次の更新前にトリガーイベントを実行すると再度キャンペーンを受信する可能性があります。詳細については、[Create an Event-Triggered Campaign](/ja/user-guide/campaigns-and-channels/getting-started/triggers/event/create-an-event-triggered-campaign) と [Event Triggered Flows](/ja/user-guide/flows-cross-channel-messaging/faqs/event-triggered-flows) を参照してください。

## RTSE のメリット

- **リテンション率の向上**: リアルタイムセグメンテーションにより、企業は行動、好み、過去のインタラクションに基づいて特定の顧客グループをターゲットにできます。このパーソナライズされたアプローチとリアルタイムセグメンテーションを組み合わせることで、エンゲージメントとユーザーリテンションを高めることができます。
- **タイミング**: リアルタイムセグメンテーションにより、ユーザーがウェブサイトを閲覧しているとき、カートに商品を追加しているとき、マイルストーンに到達したときなど、適切なタイミングでターゲットを絞ったキャンペーンを送信できます。このタイミングの良さにより、ユーザーの注意を引き、アクションを促す可能性が高まります。
- **関連性**: ユーザーをリアルタイムでセグメント化することで、送信するキャンペーンが個人の現在の興味やニーズに関連したものになります。この関連性によりユーザー体験が向上し、キャンペーンが受信者の心に響きやすくなります。
- **コンバージョン率の向上**: リアルタイムセグメンテーションにより、関連性が高くタイムリーなオファーでユーザーをターゲットにでき、コンバージョンの可能性が高まります。カスタマージャーニーの重要な瞬間にユーザーにリーチすることで、コンバージョン率を高め、収益の成長を促進できます。

## RTSE をサポートするチャネル

- Push
- Email
- SMS
- WhatsApp
- Flows
- On-site Messaging
- In-app Messaging
- Web Personalization

| 業界 | ユースケース | 説明 |
| --- | --- | --- |
| Eコマース | カート放棄の回復 | RTSE を使用すると、カートに商品を追加したものの購入を完了していないユーザーを特定できます。パーソナライズされたリマインダーやオファーを送信して、チェックアウトを促すことができます。 |
| フラッシュセールの通知 | RTSE では、期間限定セールの対象商品に関心を示したユーザーをターゲットにできます。セールの開始と同時に、プッシュ通知やメールを即座に送信できます。 |
| 旅行・ホスピタリティ | 直前予約のお得なプラン | RTSE では、特定の目的地を検索しているユーザーを特定し、特別な直前予約プランを提供して稼働率を高めることができます。 |
| 予約のマイルストーン | 頻繁に旅行を予約する旅行者が特定のマイルストーン（たとえば 5 回目の予約）に到達した場合、RTSE を使用して「サンキュー」キャンペーンを実施し、次回の予約での割引やアップグレードを提供できます。 |
| 小売・クイックコマース | 店舗購入後のフォローアップ | ユーザーが店舗で大きな購入を行った場合（ロイヤルティプログラムを通じてトラッキング）、RTSE でイベントをトリガーして、お手入れガイド、関連アクセサリーのプロモーション、または満足度調査を送信できます。 |
| 注文のマイルストーン | 特定の回数（たとえば 10 回目）の注文を行ったユーザーがリアルタイムセグメントに追加され、次回の注文で使える割引や無料アイテムで感謝を伝えるキャンペーンがトリガーされます。 |
| エンターテインメント | コンテンツのレコメンデーション | OTT プラットフォームでは、リアルタイムの視聴習慣に基づいて視聴者をセグメント化し、新しいエピソードや映画を即座にレコメンドできます。 |
| 銀行・金融サービス | 高額取引のアラート | 一定のしきい値を超える取引を行ったユーザーはリアルタイムでセグメント化され、取引を確認するためのメールトリガーキャンペーンを受信します。 |

# RTSE キャンペーンの作成

[イベントトリガーキャンペーンを作成](/ja/user-guide/campaigns-and-channels/getting-started/triggers/event/create-an-event-triggered-campaign)して、リアルタイムのアクションに基づくパーソナライズされたレコメンデーションで顧客をターゲットにできます。たとえば、ユーザーがアプリケーションを最新バージョンに更新した場合、最新バージョンでの改善点や機能についてユーザーに伝えることができます。

RTSE キャンペーンを作成するには、次の手順を実行します。

1. MoEngage のサイドバーメニューで、**Engage** メニュー項目 <img alt="Screenshot 2025-06-04 at 4.32.53 PM.png"  src="/images/moengage_e94ed7.png"  /> にカーソルを合わせます。**Engage** メニューが表示されます。
2. **+ New Campaign** をクリックします。  
    <img alt="1.png"  src="/images/moengage_05668c.png"  />   
   **Engage** メニューで **All Campaigns** をクリックし、All campaigns ページで **+ Create campaign** をクリックすることもできます。
3. **New Campaign** ダイアログボックスで、[RTSE がサポートするチャネル](/ja/user-guide/segment/advanced-concepts/real-time-segment-evaluation)のいずれかを選択し、**Event triggered** をクリックします。詳細については、[こちら](/ja/user-guide/campaigns-and-channels/getting-started/triggers/event/create-an-event-triggered-campaign)を参照してください。  
    <img alt="Screenshot 2025-06-17 at 12.56.24 PM.png"  src="/images/moengage_6e299d.png"  />
4. キャンペーンの詳細を入力します。
5. **IF user** **performs** セクションで、**Has Executed** リストの *App update* をクリックします。これがプライマリフィルター条件です。
6. **THEN trigger the message** セクションで **Immediately** を選択すると、30〜60 秒以内にキャンペーンが送信されます。 <img alt="ScreenRecording2025-03-12at5.23.14PM-ezgif.com-video-to-gif-converter.gif" src="/images/moengage_5d012c.png" />
7. **Select audience** セクションで **Filter users by** を選択し、**User behavior** タブをクリックします。
8. **User behavior** セクションで、ドロップダウンリストを使用して次の条件を適用します。  
   *Has executed App update at least 1* time *in the last 3 days*.

<Info>
選択したセグメンテーション条件が RTSE でサポートされている場合、UI に直接次の確認メッセージが表示されます。

*"Campaign segments will be evaluated in real-time on the latest data."*

このメッセージが表示されない場合、キャンペーンでは定期的なスケジュールで更新される定期セグメンテーションが使用されます。間隔については、[定期更新の間隔](#periodic-refresh-intervals)を参照してください。
</Info>

# よくある質問

<Accordion title="キャンペーンで RTSE が使用されているかどうかを確認するにはどうすればよいですか？">

キャンペーンの作成中に、セグメンテーションフィルターがリアルタイム評価の対象である場合、UI に次のメッセージが表示されます: "Campaign segments will be evaluated in real-time based on the latest data."

</Accordion>
<Accordion title="RTSE がイベントトリガーキャンペーンに最も適しているのはなぜですか？">

RTSE は、ユーザーのアクションが発生した時点で反応するように設計されています。その中核となる価値は、ユーザーが主要なイベント（「トリガー」）を実行したまさにその瞬間に、セグメントに対するユーザーの適格性を評価できる点にあります。そのため、タイミングとコンテキストが成功に不可欠なイベントトリガーキャンペーンに最適です。即時のアクションではなく過去のデータに基づいて幅広いオーディエンスをターゲットにするその他のキャンペーンタイプには、定期セグメンテーションの方が適しています。

</Accordion>
<Accordion title="RTSE キャンペーンの「Reachable Users」の数はどのように解釈すればよいですか？">

**Show count** をクリックすると、その時点で条件を満たしているユーザー数のスナップショットが表示されます。しかし、RTSE の真の強みは、トリガーイベントを実行した各ユーザーに対して評価がライブで行われる点にあります。つまり、現在条件を満たしていないユーザーでも、アクションを実行した 1 時間後には条件を満たし、キャンペーンに参加する可能性があります。この数は参考になる推定値ですが、実際のオーディエンスはリアルタイムで決定されます。

<Info>
サンプルユーザーリストには、重複する連絡先情報（たとえば同じメール ID）を持つエントリーが表示される場合があります。MoEngage はキャンペーンの送信時に自動的に重複を排除し、各ユニークユーザーがメッセージを 1 回だけ受信するようにします。
</Info>

</Accordion>
