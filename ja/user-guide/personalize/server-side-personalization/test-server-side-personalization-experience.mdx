API 統合が正しく設定されていることを確認するために、エクスペリエンスの公開後にテストすることを MoEngage は推奨しています。

<img alt="Test serverside SS.png" src="/images/moengage_658393.png" />

## 認証ヘッダーの作成

Personalize API の記事の [Authentication](https://www.moengage.com/docs/api/personalize-experience/personalize-overview) セクションで説明されているとおり、Workspace ID と API Secret を使用して HTTP 認証ヘッダーを生成します。

## リクエストのコピー

ダッシュボードの Test Experience セクションから、サポートされている任意の言語のサンプルリクエストをクリップボードへのコピーアイコンを使用してコピーし、外部コンソールでテストすることもできます。

## Workspace ID のコピー

リクエストヘッダー **MOE-APPKEY** には、MoEngage アカウントの Workspace ID の値を含める必要があります。

## 属性

リクエストでは、次の属性を渡す必要があります。

| リクエストフィールド | 必須 | 説明 |
| --- | --- | --- |
| app\_id | はい | MoEngage アカウントの Workspace ID です。Workspace ID は MoEngage ワークスペースを一意に識別します。 |
| Authorization | はい | 認証のために渡す必要がある、Base64 でエンコードされた認証ヘッダー（WorkspaceID: APISECRET）です。 |
| user\_id | いいえ | このフィールドはブランド側で提供され、リクエストに貼り付ける必要があります。このフィールドは Client ID であり、パーソナライズされたコンテンツを表示するユーザーを識別します。これは、イベントをユーザーにマッピングするために不可欠です。  無効な User ID または存在しない User ID が共有され、API リクエストに有効な受信者の詳細が含まれている場合、有効な受信者の詳細を持つ新しいユーザープロファイルが作成されます。  リクエストに **user\_id** が含まれていない場合でも、***visitor\_id*** フィールドの値を考慮してリクエストは処理されます。リクエストに ***visitor\_id*** フィールドの値が含まれていない場合、イベントは MoEngage のどのユーザーにも記録されません。 |
| visitor\_id | いいえ | このフィールドは MoEngage SDK によって提供され、ユーザーに関連付けられた一意の ID がない場合にリクエストに貼り付ける必要があります。これは一般的に、過去に Web サイトを訪問したものの、Web サイトでログインまたはアカウントを作成していないユーザーに使用されます。  一意の ID の値は、こちらで説明されているとおりに取得できます |
| experience\_key | はい | このフィールドは、MoEngage Personalize を使用して作成された各サーバーサイドエクスペリエンスを一意に識別するために使用されます。1 つのリクエストで複数の値を渡し、各エクスペリエンスに定義されたパーソナライズされたコンテンツをレスポンスで受け取ることができます。 |
| platform | いいえ | このフィールドは、訪問者がブランドとのエンゲージメントに使用したプラットフォームを識別します。使用できる値 - web、mweb、android、ios |
| DAY\_OF\_THE\_WEEK | いいえ | このフィールドには、セッション内属性ベースのエクスペリエンスを評価するための曜日を含める必要があります。使用できる値 - Sunday、Monday、Tuesday、Wednesday、Thursday、Friday、Saturday |
| TIME\_OF\_THE\_DAY | いいえ | このフィールドには、セッション内属性ベースのエクスペリエンスを評価するための時間帯を含める必要があります。使用できる値 - 00、01、02、03、04、05、06、07、…、23。00 は午前 0 時から午前 1 時までの期間、01 は午前 1 時から午前 2 時までの期間を表し、以降も同様です。例: 午後 7 時から午後 11 時までの時間帯の場合、このフィールドの入力は "**19,20,21,22"** になります |
| USER\_IP\_ADDRESS | いいえ | このフィールドには、位置情報ベースのエクスペリエンスを評価するためのユーザーの IP アドレスを含める必要があります。 |
| USER\_AGENT | いいえ | このフィールドには、USER-AGENT HTTP ヘッダーを含める必要があります。これは、Device Type などのセッション内属性に基づいてパーソナライズされたコンテンツを配信するために不可欠です。 |

### パーソナライズされたコンテンツを取得するためのユーザー識別

API は、リクエストで共有されたユーザー ID 情報を処理し、以下に示すように、コミュニケーションを送信する必要があるユーザーを識別します。

<img alt="Server-side.png" src="/images/moengage_73ed9e.png" />

必要な情報をすべてリクエストに追加したら、外部コンソールからリクエストを送信します。

## Postman でのリクエストのテスト

Postman でテストするには、次の操作を行います。

1. **copy & open Postman** アイコンをクリックして cURL をコピーし、Postman にインポートします。

   - Authorization セクションを使用して認証の詳細を追加します。ユーザー名として Workspace ID を、パスワードとして API Key を追加します。
   - インポートした cURL にはペイロードの詳細が含まれています。エクスペリエンスキーをコピーして、該当するフィールドで更新します。認証ヘッダーとその他の属性を追加します。
   - Postman で Send をクリックします。これにより、Fetch Personalize API にリクエストが送信されます。

レスポンス、エラーコード、サンプルレスポンスについては、[Fetch API Response](https://www.moengage.com/docs/api/experiences/fetch-experience) を参照してください。
