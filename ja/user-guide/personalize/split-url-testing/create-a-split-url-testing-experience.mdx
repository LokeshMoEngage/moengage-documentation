**Split URL testing**は、Webサイト最適化のための体系的なアプローチを提供します。それぞれ異なるURLを持つ複数のバージョンのWebページを作成することで、バリエーションを体系的にテストし、どれが最も高い成果をもたらすかを判断できます。

## ユースケース

- Webページのパーソナライゼーションエクスペリエンスを別バージョンでテストする
- 特定のカテゴリのユーザーに地域固有のエクスペリエンスを提供する
- ユーザーの関心に基づいて特定の商品ページをレコメンドする
- 商品発売時にVIP顧客へ先行アクセスを提供する
- VIP顧客向けにカスタマイズされたエクスペリエンスやオファーを提供する

# Split URL Testingを作成する手順

パーソナライズされたエクスペリエンスを作成するには、次のいずれかを行います。

1. **Create New** -\> **Experience** -\> **Web** に移動します。または
2. **Personalize** -\> **All Experiences** に移動し、画面右上の **\+ Experience** をクリックします。

新しい **Split URL Testing Experience** の作成は、次の3つのステップで構成されます。

1. **Target Users**: Webエクスペリエンスの対象オーディエンスを指定します。
2. **Content**: 選択したユーザー向けのバリエーションとパーソナライズされたコンテンツを指定します。
3. **Schedule and goals**: エクスペリエンスの配信スケジュール、コンバージョン目標、配信コントロールを指定します。

# ステップ1: Target Users

このセクションには以下が含まれます。

### エクスペリエンスの詳細

- **Experience name**: エクスペリエンスを管理・識別するための名前を入力します。エクスペリエンス名は5文字以上256文字以下である必要があります。
- **Experience tags:** ドロップダウンリストからエクスペリエンスタグを選択します。タグを使用すると、エクスペリエンスにコンテキストを追加できます。たとえば、プラットフォームやアプリへのユーザーのオンボーディング用に作成したエクスペリエンスに、'onboarding' というタグを追加できます。詳細については、[Tags](/ja/user-guide/campaigns-and-channels/getting-started/introduction/campaign-tags)を参照してください。

## ターゲットオーディエンス

**\+Add Audience** を選択して、エクスペリエンスの対象ユーザーセグメントを定義します。

<Accordion title="ターゲットオーディエンスの定義">
  エクスペリエンスには複数のオーディエンス(最大10個)を追加できます。たとえば、スキンケア製品を販売するブランドの場合を考えてみましょう。マーケターが次のオーディエンスセグメントを作成すると、各セグメントに合わせてWebサイトをパーソナライズできます。

  - スキンケア製品の割引オファーをクリックしたユーザー - マーケターは、スキンケア製品のオファーや割引が主にページに表示されるようWebサイトをパーソナライズできます。

  1. ドロップダウンに表示される追加済みのオーディエンスのいずれかを選択して、既存のオーディエンスを追加します。一番下の行にある _Select_ をクリックして、オーディエンスをエクスペリエンスに追加します。

         1. 実行条件と目的のユーザーアクティビティ(イベント)を選択します
         2. イベントの頻度とイベント実行の期間を指定します
         3. フィルター条件付きのイベント属性を追加します
         4. フィルター値を指定してルールを作成します。詳細については、[Create Segments](/ja/user-guide/segment/create-segments/rule-based-filter-segments)を参照してください。

     | Query Parameter | URLのクエリパラメーターに基づいてユーザーをセグメント化できます。通常、ユーザーはソーシャルメディアプラットフォームの広告をクリックして、パーソナライズされたURLにアクセスします。Source、Medium、Content、CampaignなどのUTMパラメーターを使用して、訪問元のソースや、このURLにアクセスしたきっかけのキャンペーンなどに基づいてユーザーをセグメント化できます。utm\_source、utm\_campaignなどのUTMパラメーターは、ユーザーをWebサイトに誘導しているキャンペーンを識別するために使用されます。UTMパラメーターやカスタムパラメーターを使用して、ユーザーをセグメント化し、Webサイトのエクスペリエンスをパーソナライズできます。 |

# ステップ2: Content

このステップでは、バリエーションを作成し、ユーザーを異なるURLに振り分けることができます。

1. バリエーション間でユーザートラフィックを手動で割り当てる
2. MoEngageのMerlin AIを使用して、バリエーション間でトラフィックを自動で割り当てる

## ユーザートラフィックを手動で割り当てる

| フィールド | 説明 |
| --- | --- |
| Variation | デフォルトで次の2つのオプションがあります。 <br />1. Default Variation <br />2. | フィールド | 説明 |
| --- | --- |

# ステップ3: Schedule and Goals

このステップでは、エクスペリエンスのスケジュール条件を設定します。エクスペリエンスの開始日時と終了日時を設定できます。

![DeliverySchedule.png](/images/moengage_e1833d.png)

**Conversion Goals**

エクスペリエンスのビジネス指標を追跡するために、コンバージョン目標を追加できます。最大5つのコンバージョン目標を追跡できます。任意のアプリイベントをコンバージョン目標のアクティビティとして選択でき、複数のコンバージョン目標を設定できます。最初の目標がプライマリ目標として扱われます。

複数のコンバージョン目標を使用すると、複数のビジネス指標を追跡したり、ユーザーアクションのファネルを可視化したりできます。たとえば、次の内容を確認したい場合、複数のコンバージョン目標を使用して確認できます。

1. 商品ページを閲覧したユーザーは何人か?
2. そのうち何人がその商品をカートに追加したか?
3. そのうち何人が注文を完了したか?

**Tracking Revenue Performance**

MoEngageでは、キャンペーンの収益を非常に簡単に追跡できます。キャンペーンの収益とROIを確認できます。たとえば、コミュニケーションを送信した後に商品がどれだけの収益を上げたか、という疑問に答えることができます。

コンバージョン目標を設定する際に、'Revenue Performance' トグルを有効にすることで、収益を追跡する目標を選択できます。以下の例では、**\_orderSuccessful \_**イベントの収益を追跡するために、'Revenue performance' トグルを有効にする必要があります。

アトリビューションウィンドウ、つまりユーザーがキャンペーンを受信した時点から計算される、コンバージョン目標を特定のキャンペーンに帰属させる期間を設定することもできます。デフォルトでは36時間に設定されています。上記の例では、5時間に設定したとします。

**Delivery Controls**

このオプションでは、エクスペリエンスに優先度を割り当てることができます。Low、Medium、High、Criticalのエクスペリエンス優先度を割り当てることができます。**1つのURLに複数のエクスペリエンスが作成されている場合、優先度の高いエクスペリエンスがユーザーに表示されます。**

画面右下の **Publish** をクリックして、エクスペリエンスを公開します。
