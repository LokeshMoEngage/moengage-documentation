**Split URL testing** は、Web サイト最適化のための体系的なアプローチを提供します。それぞれ異なる URL を持つ複数のバージョンの Web ページを作成することで、バリエーションを体系的にテストし、どのバージョンが最良の結果をもたらすかを判断できます。

## ユースケース

- Web ページのパーソナライゼーションエクスペリエンスを別のバージョンでテストする
- 特定のカテゴリのユーザーに地域固有のエクスペリエンスを提供する
- ユーザーの興味に基づいて特定の商品ページをおすすめする
- 製品発売時に VIP 顧客に早期アクセスを提供する
- VIP 顧客にカスタマイズされたエクスペリエンスとオファーを提供する。

# Split URL Testing の作成

Split URL Testing エクスペリエンスを作成するには、次の手順を実行します。

1. MoEngage のサイドバーメニューで、Personalize メニュー項目 <img alt="Screenshot 2025-06-13 at 2.31.12 PM.png"  src="/images/moengage_3430b4.png"  /> にカーソルを合わせます。**Personalize** メニューが表示されます。
2. **+ New Experience** をクリックします。  
    <img alt="123.png"   src="/images/moengage_afae13.png"   />   
   **New Experience** ダイアログボックスが表示されます。  
    <img alt="Screenshot 2025-06-05 at 10.20.46 AM.png"   src="/images/moengage_cc276b.png"   />   
   **Personalize** メニューで **All Experiences** をクリックし、All Experiences ページで **+ Experience** をクリックすることもできます。**New Experience** ダイアログボックスが表示されます。
3. **Split URL Testing** をクリックします。  
    <img alt="Split URL testing.png"  src="/images/moengage_5ddd23.png"  />

新しい **Split URL Testing エクスペリエンス**の作成は、次の 3 つのステップで構成されます。

1. **Target Users**: Web エクスペリエンスのオーディエンスを指定します。
2. **Content**: 選択したユーザー向けのバリエーションとパーソナライズされたコンテンツを指定します。
3. **Schedule and goals**: エクスペリエンスの配信スケジュール、コンバージョン目標、配信コントロールを指定します。

# ステップ 1: Target Users

このセクションには次の項目が含まれます。

### エクスペリエンスの詳細

- **Experience name**: エクスペリエンスを管理および識別するための名前を入力します。エクスペリエンス名は 5 文字以上 256 文字以下である必要があります。
- **Experience tags:**  ドロップダウンリストからエクスペリエンスタグを選択します。タグを使用すると、エクスペリエンスにコンテキストを追加できます。たとえば、プラットフォームやアプリへのユーザーのオンボーディング用に作成したエクスペリエンスには、「onboarding」というタグを追加できます。詳細については、[Tags](/ja/user-guide/campaigns-and-channels/getting-started/introduction/campaign-tags) を参照してください。

## ターゲットオーディエンス

**+Add Audience** を選択して、エクスペリエンスのターゲットユーザーセグメントを定義します。

<Accordion title="ターゲットオーディエンスの定義">

エクスペリエンスには複数のオーディエンス（最大 10 個）を追加できます。たとえば、スキンケア製品を販売するブランドの場合を考えてみましょう。マーケターが次のオーディエンスセグメントを作成すると、各セグメントに合わせて Web サイトをパーソナライズできます。

- 香水を閲覧した、または香水に興味を示したユーザー - マーケターは、新着商品、割引、今後のセール、お客様の声、有名人のレビューなどに言及しながら、ページ上で主に香水が表示されるように Web サイトをパーソナライズできます。
- スキンケア製品の割引オファーをクリックしたユーザー - マーケターは、ページ上で主にスキンケア製品のオファーや割引が表示されるように Web サイトをパーソナライズできます。
- 天然由来のスキンケア製品に興味を示したユーザー - マーケターは、ページ上で主に天然由来かつクルエルティフリーの製品が表示されるように Web サイトをパーソナライズできます。

+*Add Audience* をクリックすると、エクスペリエンスのターゲットオーディエンスを指定するためのさまざまなオプションが表示されます。次の操作を行えます。

1. ドロップダウンに表示される既存のオーディエンスのいずれかを選択して、既存のオーディエンスを追加します。最下行の *Select* をクリックして、オーディエンスをエクスペリエンスに追加します。
2. 既存のオーディエンスを複製して編集します。ドロップダウンでオーディエンスを選択し、右下隅の *Duplicate and Edit* をクリックして詳細を変更します。
3. *+ New Audience* をクリックして、新しいオーディエンスを追加します。

New Audience ポップアップでは、次のフィールドを指定できます。

1. **Audience Name** - オーディエンスを識別する一意の名前。
2. **Segmentation criteria** - オーディエンスを定義するためのセグメンテーションフィルター。

   このセクションでは、ターゲットユーザーを選択するための条件を追加できます。たとえば、カートに商品を追加したものの購入を完了していないユーザーや、過去「x」日間に通知を受け取っていない、またはアプリを開いていないユーザーなどを追加/削除したい場合に使用します。

   All Users User Property User Behavior User Affinity Custom Segment

   アプリのすべてのユーザーにキャンペーンを送信できます。このオプションを使用する場合、複数のフィルターを追加することはできません。

   初回確認日時、最終確認日時、都市などのユーザープロパティに基づいてユーザーをターゲットにできます。

   User Properties を選択し、次の操作を行います。

   1. 目的のユーザープロパティとフィルター条件を選択します。
   2. フィルター値を指定してルールを作成します。

   詳細については、[Create Segments](/ja/user-guide/segment/create-segments/rule-based-filter-segments) を参照してください。

   アプリ/サイトの起動、商品の閲覧など、ユーザーの行動やイベントに基づいてユーザーをターゲットにできます。

   User Behavior を選択し、次の操作を行います。

   1. 実行条件と目的のユーザーアクティビティ（イベント）を選択します
   2. イベントの頻度とイベント実行の期間を指定します
   3. フィルター条件付きのイベント属性を追加します
   4. フィルター値を指定してルールを作成します。

   詳細については、[Create Segments](/ja/user-guide/segment/create-segments/rule-based-filter-segments) を参照してください。

   Affinity Segments は、特定の属性値でアクションを実行したユーザーに基づいて作成されるユーザーグループです。

   詳細については、[User Affinity](/ja/user-guide/segment/create-segments/affinity-segments) を参照してください。

   User Affinity を選択し、次の操作を行います。

   1. 目的のユーザーイベントまたは属性を選択します。
   2. 次の中からユーザーアフィニティパラメーターを選択します
      - Predominantly: フィルター条件付きのアフィニティ属性を選択し、アフィニティ値を指定します。
      - Minimum of: フィルター条件付きのアフィニティ属性を選択し、アフィニティ値を指定します。
      - Most number of times: 入力するか矢印を使用して、ユーザーの上位または下位のパーセンテージを指定します
      - Least number of times: 入力するか矢印を使用して、ユーザーの上位または下位のパーセンテージを指定します
   3. 入力するか矢印を使用して、イベント実行の期間を指定します。
   4. Attribute ボタンをクリックして、フィルターに属性を追加します。

   Custom Segment セクションを選択し、目的のカスタムセグメントを選択してルールを作成します。

   詳細については、[Custom Segments](/ja/user-guide/segment/create-segments/manage-segments) を参照してください。
3. **In-session attributes** - 特定の条件に基づいて Web サイト訪問者をグループ化できます。次のセッション内属性を追加できます。

   | フィールド | 説明 |
   | --- | --- |
   | Query Parameter | このフィールドでは、URL 内のクエリパラメーターに基づいてユーザーをセグメント化できます。通常、ユーザーはソーシャルメディアプラットフォーム上の広告をクリックして、パーソナライズされた URL にアクセスします。Source、Medium、Content、Campaign などの UTM パラメーターを使用して、訪問元のソースや、この URL にアクセスする元となったキャンペーンなどに基づいてユーザーをセグメント化できます。utm\_source、utm\_campaign などの UTM パラメーターは、Web サイトにユーザーを誘導しているキャンペーンを識別するために使用されます。UTM パラメーターとカスタムパラメーターを使用して、ユーザーをセグメント化し、Web サイトのエクスペリエンスをパーソナライズできます。 |
   | User Type | このフィールドでは、ユーザーが新規ユーザーかリピーターかに基づいてユーザーをセグメント化できます。  **注**:  1. 1. 2 人のユーザーが同じデバイスを使用しており、ユーザー 1 の後にユーザー 2 がログインした場合、ユーザー 2 は*リピーター* *ユーザー*と見なされます    2. ユーザーがモバイルブラウザからログインした後、デスクトップブラウザから再度ログインした場合、デスクトップからのログインは*新規ユーザー*と見なされます。 |
   | Day of the week | このフィールドでは、ユーザーが Web サイトを訪問した曜日に基づいてユーザーをセグメント化できます。 |
   | Time of the day | このフィールドでは、ユーザーが Web サイトを訪問した時間帯に基づいてユーザーをセグメント化できます。ドロップダウンで利用可能な 1 日のうちの任意の 1 時間枠から選択できます。 |
   | Geolocation | このフィールドでは、ユーザーが Web サイトを訪問した地理的位置に基づいてユーザーをセグメント化できます。ユーザーが所在する国、州/地域、都市を選択するか、特定の国を除外できます。 |
   | Device Type | このフィールドでは、ユーザーが Web サイトの訪問に使用したデバイスに基づいてユーザーをセグメント化できます。Mobile、Desktop、Tablet のいずれか 1 つまたは組み合わせを含めたり除外したりできます。 |
   | Operating System | このフィールドでは、ユーザーが Web サイトの訪問に使用したデバイスのオペレーティングシステムに基づいてユーザーをセグメント化できます。Android、iOS、Windows、Mac、Linux、Others のいずれか 1 つまたは組み合わせを含めたり除外したりできます。 |
   | Browser Type | このフィールドでは、ユーザーが Web サイトの訪問に使用したブラウザに基づいてユーザーをセグメント化できます。Chrome、Safari、Firefox、Opera、Others のいずれか 1 つまたは組み合わせを含めたり除外したりできます。 |
4. **Exclude Users** - *Exclude Users* をクリックし、*Select attribute* ドロップダウンでセッション内属性を指定することで、特定のセッション内属性を持つユーザーを除外できます。
5. **In-session behavior** - 進行中の現在のセッション内でのアクションに基づいて、Web サイト訪問者をグループ化してターゲットにできます。たとえば、ユーザーが特定の衣料品ブランドやジーンズなどの特定のアパレルを閲覧した場合、この情報を使用して同じセッション内の他の Web ページをパーソナライズし、同じブランドの他のアイテムのおすすめバナーや類似商品を表示できます。これにより、ユーザーの次回の訪問を待たずに、同じセッション内ですぐにパーソナライズされたエクスペリエンスを提供できます。
6. ユーザーのセッション内行動を使用してパーソナライズするには、*+In-session Behavior* をクリックし、イベント条件 *Has Executed/Has Not Executed* を追加して、*Select an event dropdown* でイベントを選択します。**注**: セッション内行動のターゲティングでは、選択したユーザーアクションの直近 10 件のインスタンスのみが考慮されます。
7. Save for later use チェックボックスはデフォルトでオンになっています。これにより、追加したオーディエンスが保存され、他のエクスペリエンスで使用できるようになります。
8. 画面右下隅の *Add* をクリックして、オーディエンスを追加します。 <img alt="AddAudience.gif" src="/images/moengage_b391c1.png" />

### コントロールグループ

*Global control group* を切り替えて、グローバルコントロールグループ内のユーザーをエクスペリエンスから除外します。詳細については、[Control Groups.](/ja/user-guide/campaigns-and-channels/getting-started/introduction/control-groups) を参照してください。

この情報を入力したら、**Next** をクリックします。ポップアップが開きます。

このステップでは、MoEngage の WYSIWYG エディターを使用して Web ページをパーソナライズします。[エディターの機能の詳細については、こちらの記事を参照してください。](/ja/user-guide/personalize/client-side-personalization/personalize-editor-capabilities)

# ステップ 2: Content

このステップでは、バリエーションを作成し、ユーザーを異なる URL に振り分けることができます

1. バリエーション間でユーザートラフィックを手動で割り当てる
2. MoEngage の Merlin AI を使用して、バリエーション間でトラフィックを自動的に割り当てる

# ステップ 3: Schedule and Goals

このステップでは、エクスペリエンスのスケジュール条件を設定します。エクスペリエンスの開始日時と終了日時を設定できます。

<img alt="DeliverySchedule.png" src="/images/moengage_d31b3a.png" />

**コンバージョン目標**

コンバージョン目標を追加して、エクスペリエンスのビジネス指標を追跡できます。最大 5 つのコンバージョン目標を追跡できます。任意のアプリイベントをコンバージョン目標のアクティビティとして選択でき、複数のコンバージョン目標を設定できます。最初の目標がプライマリ目標として扱われます。

複数のコンバージョン目標を使用すると、複数のビジネス指標を追跡したり、ユーザーアクションのファネルを可視化したりできます。たとえば、次の項目を確認したい場合は、複数のコンバージョン目標を使用して確認できます。

1. 商品ページを閲覧したユーザーは何人か？
2. そのうち何人がその商品をカートに追加したか？
3. そのうち何人が注文を完了したか？

**収益パフォーマンスの追跡**

MoEngage を使用すると、キャンペーンの収益を非常に簡単に追跡できます。キャンペーンの収益と ROI を確認できます。たとえば、コミュニケーションを送信した後に商品がどれだけの収益を上げたかという質問に答えることができます。

コンバージョン目標を設定する際に、「Revenue Performance」トグルを有効にすることで、収益を追跡する目標を選択できます。以下の例では、***orderSuccessful*** イベントの収益を追跡するために、「Revenue performance」トグルを有効にする必要があります。

<img alt="ordersuccessful.png" src="/images/moengage_5778fa.png" />

収益の追跡はオプションであり、必須ではありません。Revenue performance トグルを無効にすると、収益の追跡を無効にできます。目標を選択した後、注文の合計金額を取得する数値属性を選択できます。以下の例では、***cartValue*** に注文の合計金額が含まれています。金額を報告する通貨を選択することもできます。

<img alt="Trackrevenue.png" src="/images/moengage_d8ed93.png" />

**アトリビューションウィンドウの設定**

アトリビューションウィンドウ、つまりコンバージョン目標を特定のキャンペーンに帰属させる期間（ユーザーがキャンペーンを受信した時点から計算）を設定することもできます。デフォルトでは 36 時間に設定されています。上記の例では、5 時間に設定したとします。

<img alt="AttributionWindow.png" src="/images/moengage_79dba5.png" />

**配信コントロール**

このオプションでは、エクスペリエンスに優先度を割り当てることができます。エクスペリエンスの優先度として、Low、Medium、High、Critical を割り当てられます。**1 つの URL に複数のエクスペリエンスが作成されている場合、優先度の高いエクスペリエンスがユーザーに表示されます。**

画面右下隅の **Publish** をクリックして、エクスペリエンスを公開します。

以前は *Sherpa AI* と呼ばれていたすべての MoEngage AI 製品は、現在 *Merlin AI* と呼ばれています。
