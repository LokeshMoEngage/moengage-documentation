# 概要 🚀

_(連携の中核となる価値を説明してください。MoEngage キャンペーンに動的コンテンツを取り込む方法、または MoEngage のデータを使用して外部のサイト/アプリでの体験を調整する方法によって、マーケターがパーソナライズされたユーザー体験をどのように作成できるかを説明してください。)_

MoEngage と **\[Partner Name\]** の連携により、MoEngage キャンペーン内でユーザーに動的な 1 対 1 のパーソナライズされたコンテンツを配信できます。商品のレコメンデーション、パーソナライズされた画像、動的なオファーなどのリアルタイムのコンテンツを **\[Partner Name\]** から取得することで、エンゲージメントとコンバージョンを大幅に向上させることができます。

さらに、この連携では MoEngage のユーザーデータとイベントデータを **\[Partner Name\]** に送信できるため、ユーザーのクロスチャネルの行動に基づいて、Web サイト、アプリ、その他のチャネルでの体験をパーソナライズできます。

### 方法 A: MoEngage Content API を使用する

_(商品レコメンデーション用の JSON データなど、構造化された API レスポンスにはこの方法を使用してください。)_

#### ステップ 1: \[Partner Name\] から API 認証情報を取得する

1. _(ユーザーがダッシュボードのどこで API エンドポイント URL、API キー、その他の必要な認証情報を確認できるかについて、明確な手順を提供してください。スクリーンショットを使用してください。)_
2. **API URL** : `https://api.your-platform.com/recommendations`
3. **認証** : `Authorization: Bearer <YOUR_API_KEY>`

#### ステップ 2: MoEngage で Content API を設定する

1. MoEngage UI の左側のナビゲーションメニューで、**Settings** \> **Content API** に移動し、**\+ Add content API** をクリックします。
2. ステップ 1 で取得した API エンドポイント URL を入力します。MoEngage のパーソナライズ構文を使用して、URL を動的にすることができます: `https://api.partner.com/content?user_id={{UserAttribute['ID']}}`
3. **Headers** に認証キーを追加します。
4. 保存して API をテストします。テストが成功すると、受信が想定されるデータのサンプルが表示されます。

#### ステップ 2: MoEngage キャンペーンに URL を埋め込む

#### ステップ 1: \[Partner Name\] からデータ送信先の認証情報を取得する

1. _(データ配信に必要な認証情報をユーザーが取得する方法を説明してください。S3 の場合は、S3 バケットの URL、Access Key、Secret Key が含まれます。Webhook の場合は、エンドポイント URL と必要な認証トークンになります。)_

3. 送信するユーザーイベント (例: `Campaign Clicked`、`Product Viewed`) とユーザー属性を選択して、エクスポートを設定します。

## 問題

**問題の例:** パーソナライズされたコンテンツがテストメールに表示されない。

- **API リクエストを確認する**: Content API 設定の「Test」機能を使用して、MoEngage がサーバーから有効な `200 OK` レスポンスを受信していることを確認してください。レスポンス本文を確認し、想定どおりのデータが含まれていることを確認してください。
- **Jinja 構文を確認する**: API レスポンスの解析に使用する Jinja コードが正しいことを確認してください。よくある間違いは、JSON レスポンスに存在しないキーを参照することです。
- **ユーザーデータを確認する**: 送信先のテストユーザープロファイルに、API 呼び出しで使用する属性の値があることを確認してください (例: URL で `{{UserAttribute['ID']}}` を使用している場合は、テストユーザーに User ID があることを確認してください)。
