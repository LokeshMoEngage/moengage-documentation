# 概要 🚀

_(連携の中核となる機能を説明してください。マーケターが MoEngage のセグメンテーションとキャンペーントリガーを使用して貴社プラットフォームの API にデータを送信し、音声通話の発信、はがきの郵送、カレンダーイベントの作成などのアクションを開始する方法を説明してください。)_

MoEngage と **\[Partner Name\]** の連携により、MoEngage の Connector Campaigns を使用して、当社のプラットフォーム上でリアルタイムの自動アクションをトリガーできます。MoEngage から **\[Partner Name\]** の API にユーザーデータとイベントデータを送信することで、マーケターは統合されたカスタマージャーニーの一環として、音声、ダイレクトメール、カレンダーイベントなどの追加チャネルでキャンペーンをシームレスに展開できます。

これにより、ユーザーの行動に基づいて独自性が高くインパクトのあるチャネルでユーザーにエンゲージでき、従来のデジタルメッセージを超えてマーケティングオートメーションを拡張できます。

## ステップ 2: MoEngage で Connector Campaign を設定する

1. MoEngage UI の左側のナビゲーションメニューで、**Create Campaign** \> **Connectors** \> **Custom** に移動します。
2. 配信タイプ (イベントトリガー、スケジュールなど) を選択し、キャンペーン作成の 2 番目のステップ (「Webhook」) に進みます。
3. 貴社プラットフォームへの API 呼び出しを設定します。

| フィールド | 設定手順 | 例 |
| :-- | :-- | :-- |
| **Webhook URL** | API エンドポイントを入力します。エンドポイントで必要な場合は、`{{...}}` 構文を使用して URL に動的データ (User ID や Account Code など) を含めます。 | `https://api.partner.com/v1/send-voice-call` |
| **Method** | 適切な HTTP メソッドを選択します。 | `POST` |
| **Headers** | 認証とコンテンツタイプに必要なヘッダーを追加します。_(正確なヘッダーキーを記載し、特に Basic 認証の場合は値の形式を説明してください。)_ | **Key:**`Authorization`<br />**Value:**`Basic <ENCODED_KEY>`<br />**Key:**`Content-Type`<br />**Value:**`application/json` |
| **Body** | **Raw** を選択し、API に必要な完全な JSON ペイロードを指定します。MoEngage のパーソナライズ構文 (`{{UserAttribute['...']}}` または `{{EventAttribute['...']}}`) を使用して、動的なユーザーデータやイベントデータを送信します。**_重要_**_: 主要なユースケースについて、コメントを十分に付けた実践的な JSON の例を提供してください。)_ | 以下のペイロードの例を参照してください。 |

### JSON ペイロードの例

MoEngage のパーソナライズ構文 (`{{UserAttribute['...']}}`) を使用して動的データを送信します。

```json wrap
{
// The mobile number of the user to call
 "to": "{{UserAttribute['Mobile Number']}}",
// The Caller ID configured in your Partner account
 "from": "18005551234",
// The message to be read out, personalized with user's name
 "message": "Hello {{UserAttribute['First Name']}}, this is a reminder for your appointment tomorrow.",
// Unique identifier for the transaction
 "transaction_id": "{{EventAttribute['appointment_id']}}"
}
```

4. テスト機能を使用してエンドポイントにサンプルリクエストを送信し、設定を確認します。テストが成功すると、200 OK レスポンスが返されます。
5. 検証が完了したら、コネクターキャンペーンを公開できます。

## 問題

**問題の例:** Connector のテストが 401 Unauthorized エラーで失敗する。

- **認証ヘッダーを確認する**: `Authorization` ヘッダーの形式が正しいことを再確認してください。Basic 認証を使用している場合は、キーとシークレットが結合され、正しく Base64 エンコードされていることを確認してください。API Key と Secret が正しく、有効期限が切れていないことを確認してください。
