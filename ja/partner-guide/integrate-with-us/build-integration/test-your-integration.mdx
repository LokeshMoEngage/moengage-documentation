## テストの基本原則

具体的なシナリオに入る前に、次の指針を念頭に置いてください。

  * **顧客を第一に考える:** エンドユーザーの視点でテストします。設定プロセスは直感的ですか? 手順はわかりやすいですか? 顧客が連携をすばやく簡単に設定して使用できる必要があります。
  * **テスト環境と本番環境の両方をサポートする:** MoEngage のワークスペースは「Test」モードと「Live」モードで設定できます。連携は両方の環境で正しく機能する必要があります。サンドボックスアカウントでは両方の環境にアクセスできるため、本番の顧客データに影響を与えることなくワークフロー全体を検証できます。
  * **複数のデータセンターとの互換性を確保する:** MoEngage は、グローバルな顧客基盤にサービスを提供するために複数のデータセンターで運用されています。地域を問わずすべての共通顧客に対して連携が正しく機能するように、すべてのデータセンターに対して連携をテストすることが重要です。
  * **回復力を目指す:** 連携は予期しない問題を適切に処理できる必要があります。潜在的な障害を事前にテストし、顧客のワークフローが中断されないようにします。



## テストシナリオのベストプラクティス

包括的なテスト計画は、理想的なシナリオだけでなく、それ以外のケースもカバーします。次のフローを中心にテストを構成することをお勧めします。

### 1\. ハッピーパステスト

通常の想定どおりの条件下で連携をテストし、コア機能が設計どおりに動作することを確認します。

  * **認証**と接続設定が**成功すること**。
  * 正しいデータ形式で**データの同期** (ユーザー、イベント、セグメント) が**成功すること**。
  * **Connected Apps** の場合、キャンペーンが正常に実行され、`200 OK` の API レスポンスに基づいて「Sent」ステータスが正しくレポートされること。
  * MoEngage Streams または S3 エクスポートからデータが正しく受信されること。



### 2\. エラー処理

一般的なエラーや障害を意図的にテストし、連携がそれらを適切に処理してユーザーにわかりやすいフィードバックを提供することを確認します。

  * **無効な認証情報:** ユーザーが誤った API キー、トークン、またはパスワードを入力した場合はどうなりますか? エラーメッセージはわかりやすく役に立つものですか?
  * **API の障害:** API のタイムアウト、サーバーエラー (5xx)、またはクライアントエラー (4xx) をシミュレートします。連携は適切な場合に再試行しますか? 障害は正しくログに記録されますか?
  * **不正なデータ:** 誤った形式のデータや必須フィールドが欠落したデータを送信します。システムはわかりやすいエラーとともにデータを拒否しますか? それとも何も通知せずに失敗しますか?
  * **Connected Apps** の場合、API エラーによってキャンペーンが失敗したとき、MoEngage のキャンペーン統計情報に「Failed」ステータスが正しくレポートされますか?



### 3\. エッジケーステスト

連携にとって難しい可能性のある、通常とは異なるシナリオや極端なシナリオをテストします。

  * **空の値または Null 値:** 必須ではないフィールドの空文字列や null 値を、連携はどのように処理しますか?
  * **特殊文字とさまざまな言語:** 特殊文字や英語以外のテキストを含むユーザーデータや入力を、連携は正しく処理しますか?
  * **大量のデータ:** 多数のユーザーやイベントを使用してテストし、パフォーマンスのボトルネックや API のレート制限を確認します。



## Connected Apps に関する具体的なガイダンス

Connected Apps フレームワークを使用して構築した連携では、エンドツーエンドのキャンペーンフロー全体をテストすることが不可欠です。

  1. **接続設定を見直す:** App Marketplace のすべての入力フィールドがわかりやすく、適切な検証が行われ、想定どおりに機能することを確認します。
  2. **キャンペーンの作成をテストする:** Connected Channel を使用してキャンペーンを作成します。キャンペーンレベルのすべての入力フィールドが正しく表示されることを確認します。
  3. **開始して確認する:** テストキャンペーンを開始し、MoEngage のキャンペーン統計情報 (「Sent」、「Failed」) がお客様側からの API レスポンスを正確に反映していることを入念に確認します。
