## はじめに

MoEngage のテクノロジーパートナーの1つである Apsalar を使用すると、インストール獲得データをトラッキングして、MoEngage でのマーケティングオートメーションキャンペーンを強化できます。

## 対象範囲

MoEngage でインストールの Publisher Name と Campaign Name を使用します。

## 連携

<Info>
  **前提条件**

  - 有効な Apsalar (Singular) アカウントがあることを確認してください。
  - MoEngage ダッシュボードの **Settings** セクションへのアクセス権があることを確認してください。
</Info>

## 手順

Apsalar を MoEngage と連携するには、以下の手順に従います。

### ステップ 1: MoEngage のアトリビューショントラッキング用アプリキーを取得する

MoEngage ダッシュボードにログインし、次の手順に従います。

1. **Settings** \> **Analytics** \> **Acquisition tracking** に移動します。
2. **Acquisition Tracking** をオンにし、ドロップダウンから **Apsalar** を選択します。これにより **App Key** が生成されます。 <img src="/images/partner_22025651174804.png" alt="Apsalar が選択され App Key が生成された Acquisition Tracking 設定" />
3. **Save** をクリックします。
4. **App Key** をコピーします。これは Apsalar で MoEngage を設定する際に必要です。

### ステップ 2: Apsalar ダッシュボードで設定を行う

Apsalar ダッシュボードで設定を行うには、[Apsalar (Singular) のパートナー設定ドキュメント](https://support.singular.net/hc/en-us/articles/360053018851-How-to-Configure-Partner-Settings-and-Postbacks#Configuration_Steps)の手順に従います。

Apsalar ダッシュボードで次のフィールドを入力します。

| フィールド | 説明 |
| --- | --- |
| **MoEngage Data Center** | サインアップした MoEngage データセンターに応じて、`DC-01`、`DC-02`、`DC-03` のいずれかを選択します。MoEngage データセンターの確認方法の詳細については、[Data Centers in MoEngage](https://www.moengage.com/docs/user-guide/data/key-concepts/data-centers-in-moengage) を参照してください。 |
| **MoEngage Workspace ID** (旧 App ID) | MoEngage ダッシュボードで **Settings** \> **Account** \> **General settings** \> **Workspace ID (earlier app id)** に移動して、Workspace ID を取得します。 |
| **MoEngage App Key** | MoEngage ダッシュボードで **Settings** \> **Account** \> **APIs** \> **API keys** に移動して、App Key を取得します。 |

## MoEngage で獲得データを使用する方法

MoEngage が Apsalar からデータを受信し始めたら、次の方法でこのデータを活用できます。

### ユーザー属性

MoEngage は次のユーザー属性をトラッキングします。

| 属性 | 説明 |
| --- | --- |
| `Publisher name` | キャンペーンのパブリッシャー名。 |
| `datetime` | インストールのタイムスタンプ。 |
| `fb_campaign_name` | インストールにつながった Facebook キャンペーンの名前。 |
| `fb_campaign_id` | インストールにつながった Facebook キャンペーンの ID。 |
| `fb_ad_name` | Facebook 広告の名前。 |
| `fb_ad_id` | Facebook 広告の ID。 |
| `twtr_campaign_name` | インストールにつながった Twitter キャンペーンの名前。 |
| `twtr_campaign_id` | インストールにつながった Twitter キャンペーンの ID。 |

![MoEngage に表示される Apsalar からトラッキングされたユーザー属性](/images/partner_11445338176404.png)

### さまざまなパブリッシャーのパフォーマンスを分析する

Branch 連携は、MoEngage でアプリインストールキャンペーンとソースの効果を分析するのに役立ちます。ユーザーイベント、コンバージョンゴール、アンインストールなど、MoEngage ですでにトラッキングしているデータを活用して、実施しているさまざまなアプリインストールキャンペーンのパフォーマンスを比較したり、さまざまなパブリッシャーからのインストールの相対的なパフォーマンスを分析したりして、マーケティング費用を最適化できます。

このデータを分析するには、[MoEngage の獲得ダッシュボード](https://app.moengage.com/v3/#/acquisition)を表示します。

![パブリッシャー別にグループ化された獲得分析ダッシュボード](/images/partner_11445388548628.png)

MoEngage Analytics を使用している場合は、インストールの Publisher Name と Campaign Name の情報を活用してユーザーファネルを分析できます。

### さまざまなキャンペーンのパフォーマンスを分析する

連携が有効になった後、ダッシュボードのサイドバーで **Analyze** \> **Acquisitions** に移動して、獲得ダッシュボードで獲得データの分析を確認することもできます。

![キャンペーン別にグループ化された獲得分析ダッシュボード](/images/partner_11445435711252.png)

### オンボーディングキャンペーンの強化

MoEngage のユーザープロパティとして利用できるインストールの Publisher Name と Campaign Name を使用して、セグメントを作成し、MoEngage 経由で送信するプッシュ通知、アプリ内メッセージ、メール、SMS をパーソナライズできます。

インストールアトリビューションデータにより、ユーザーがアプリをインストールした時点で、ライフサイクルにおいてどのように進んでいく可能性があるかについてのインサイトが得られます。これは非常に有用な情報であり、リテンションの向上、最初のコンバージョンまでの時間の短縮、ユーザーあたりの LTV の向上により、オンボーディングキャンペーンのパフォーマンスを高めるのに役立ちます。

| パブリッシャーのカテゴリ | ユースケース |
| --- | --- |
| ユーザーあたりの平均セッション数が少ないパブリッシャー | ユーザーがアプリをインストールした時点から定期的にプッシュ通知を送信し、ユーザーあたりの平均セッション数を増やします。 |
| 平均 LTV が高いパブリッシャー | これらは潜在的なプレミアムユーザーです。キャンペーン戦略を実施して、プレミアムユーザーのセグメントへと育成します。 |
| アンインストール率が高いパブリッシャー | インストール直後に離脱する傾向が高いユーザーを特定し、初回購入のインセンティブを提供します。これにより離脱率を低減できます。 |
