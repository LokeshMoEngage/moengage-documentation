# SDK のインストール

Segment は SPM によるインストールのみをサポートしているため、MoEngage は Swift Package Manager を使用した場合にのみ Twilio Segment 経由で統合できます。

## Swift Package Manager を使用したインストール

統合するには、次の GitHub URL を使用し、ブランチを master に、またはバージョンを 1.0.0 以上に設定します。[https://github.com/moengage/MoEngage-Segment-Swift](https://github.com/moengage/MoEngage-Segment-Swift)

# Twilio Segment SDK のセットアップ

AppDelegate に移動し、Twilio Segment SDK をセットアップします。

<CodeGroup>

```swift Swift wrap
import Segment_MoEngage
...
func application(_ application: UIApplication, didFinishLaunchingWithOptions launchOptions: [UIApplication.LaunchOptionsKey: Any]?) -> Bool {
...
   let sdkConfig = MoEngageSDKConfig(appId: "YOUR Workspace ID", dataCenter: .data_center_01)
   MoEngageInitializer.initializeDefaultInstance(sdkConfig: sdkConfig)
...
}
```

</CodeGroup>

Analytics-Swift ライブラリのセットアップの直後で `analytics.add(plugin: ...)` を呼び出し、プラグインのインスタンスを Analytics タイムラインに追加します。

<CodeGroup>

```swift Swift wrap
import Segment_MoEngage
...
func application(_ application: UIApplication, didFinishLaunchingWithOptions launchOptions: [UIApplication.LaunchOptionsKey: Any]?) -> Bool {
...
   let analytics = Analytics(configuration: Configuration(writeKey: "")
                    .flushAt(3)
                    .trackApplicationLifecycleEvents(true))
   analytics.add(plugin: MoEngageDestination())
...
}
```

</CodeGroup>

<Warning>
  `MoEngageSDKConfig` の `dataCenter` パラメーター（上記では `.data_center_01`）を使用して、MoEngage アカウントに対応する正しいデータセンター/リージョンを設定してください。詳細については、[ドキュメント](/ja/developer-guide/ios-sdk/sdk-integration/basic/data-center)を参照してください。
</Warning>

# MoEngage のセットアップ

MoEngage をセットアップするには、次の手順を実行します。

1. MoEngage Dashboard \> Settings \> General に移動します。
2. Workspace ID（旧 App ID）をコピーします。
3. Twilio **Segment ダッシュボード**に移動し、**Destinations** に進んで **MoEngage Integration** を選択します。
4. MoEngage Integration を有効にします。
5. APP ID を、ステップ 1 で取得した Workspace ID に更新します。
6. 変更を保存します。

# ユーザー属性のトラッキング

ユーザー属性とは、メールアドレス、ユーザー名、携帯電話番号、性別など、ユーザー固有の特性です。**identify** を使用すると、ユーザーとそのアクションを紐付け、ユーザーの特性を記録できます。これには、一意の User ID と、ユーザーについて把握している任意の traits が含まれます。

<CodeGroup>

```swift Swift wrap
Analytics.main.identify(userId: "a user's id", traits: ["email": "a user's email address"])
```

</CodeGroup>

詳細については、こちらの[リンク](https://segment.com/docs/sources/mobile/ios/#identify)を参照してください。

# イベントのトラッキング

イベントトラッキングは、アプリ内のユーザー行動をトラッキングするために使用します。**track** を使用すると、ユーザーが実行したアクションを記録できます。すべてのアクションは「イベント」をトリガーし、イベントには関連する属性を含めることもできます。

<CodeGroup>

```swift Swift wrap
Analytics.main.track(name: "Item Purchased", properties: ["item": "Sword of Heracles"])
```

</CodeGroup>

データのトラッキングに必要な作業は以上です。詳細については、こちらの[リンク](https://segment.com/docs/sources/mobile/ios/#track)を参照してください。

# ユーザーのリセット

_reset_ メソッドは、現在のユーザーに関する SDK の内部ストアをクリアします。これは、ユーザーが時間の経過とともに異なる ID でログイン/ログアウトできるアプリで役立ちます。

<CodeGroup>

```swift Swift
Analytics.main.reset()
```

</CodeGroup>

詳細については、こちらの[リンク](https://segment.com/docs/sources/mobile/ios/#reset)を参照してください。

# プッシュ通知

プッシュ通知は、ユーザーのエンゲージメントを維持し、アプリに関する情報を届けるための優れた方法です。アプリにプッシュ通知を実装する際には、次のオプションがあります。

## MoEngage によるプッシュ実装

Twilio Segment SDK は現在、iOS10 で Apple によって導入された [UserNotifications](https://developer.apple.com/documentation/usernotifications) フレームワークをサポートしていないため、こちらが推奨される実装方法です。MoEngage SDK を使用してモバイルアプリにプッシュ通知を実装するには、次のリンクを参照してください: [**プッシュ通知**](https://www.moengage.com/docs/developer-guide/ios-sdk/push/basic/push-notifications)

<Warning>
  Twilio Segment による SDK の初期化に遅延があるため、[**AppDelegate Swizzling**](https://www.moengage.com/docs/developer-guide/ios-sdk/push/basic/ios-push-integration-tutorial#choose-a-notification-registration-method) は Twilio Segment 統合では確実に動作しません。そのため、プッシュ関連のすべてのコールバックで MoEngage SDK のメソッドを必ず呼び出してください。
</Warning>

## Twilio Segment によるプッシュ実装

<Warning>
  この方法では、通知のクリックによってアプリケーションが起動された場合に、MoEngage SDK が通知を処理できないことが確認されています。これは、この特定のシナリオで Twilio Segment SDK が MoEngage SDK にペイロードを提供しないためです。そのため、プッシュ関連のコールバックで MoEngage SDK のメソッドを直接呼び出す最初の方法を使用することを強く推奨します。
</Warning>

1. こちらの[リンク](https://segment.com/docs/libraries/ios/#how-do-i-use-push-notifications-)の手順に従って、Twilio Segment SDK を使用してプッシュを登録します。
2. アプリケーションの application:didReceiveRemoteNotification: メソッドに次のコードを追加します。
   <CodeGroup>
   ```swift Swift
   Analytics.main.receivedRemoteNotification(userInfo: userInfo)
   ```
   </CodeGroup>
3. アプリに application:didReceiveRemoteNotification:fetchCompletionHandler: を統合している場合は、そのメソッドに次のコードを追加します。
   <CodeGroup>
   ```swift Swift
   Analytics.main.receivedRemoteNotification(userInfo: userInfo)
   ```
   </CodeGroup>
4. handleActionWithIdentifier:forRemoteNotification: を実装している場合は、そのメソッドに次のコードを追加します。
   <CodeGroup>
   ```swift Swift
   Analytics.main.handleAction(identifier: identifier, userInfo: userInfo)
   ```
   </CodeGroup>

# インストール/アップデートの区別:

アプリがすでに App Store で公開されている状態で MoEngage を統合する場合があるため、アプリのアップデートが実際の UPDATE なのか INSTALL なのかを把握する必要があります。これらを区別するには、以下のいずれかのメソッドを使用します。

<CodeGroup>

```swift Swift
//For new Install call following
MoEngageSDKAnalytics.sharedInstance.appStatus(.install)
 
//For an app update call following
MoEngageSDKAnalytics.sharedInstance.appStatus(.update)
```

</CodeGroup>

詳細については、次の[リンク](https://www.moengage.com/docs/developer-guide/ios-sdk/data-tracking/basic/install-update-differentiation)を参照してください。

# InApp Native

アプリ内メッセージングは、ユーザーのセグメントに送信できるカスタムビューで、カスタムメッセージの表示、新しいオファーの提供、特定のページへの誘導などに使用できます。アプリ内メッセージングの詳細とアプリケーションへの実装方法については、次のリンクを参照してください: [InApp NATIV](https://www.moengage.com/docs/developer-guide/ios-sdk/in-app-messages/in-app-nativ)

<Info>
  Twilio **Segment for iOS** の使用方法の詳細については、Twilio Segment が提供する[開発者ドキュメント](https://segment.com/docs/sources/mobile/ios/)を参照してください。
</Info>
