# はじめに

[RudderStack](https://rudderstack.com/) は、顧客のイベントデータを収集し、任意のデータウェアハウスや MoEngage などの多数の分析プロバイダーにルーティングするための、開発者向けのオープンソース顧客データプラットフォームです。

RudderStack で MoEngage をソースとして使用すると、チームのマーケティングとエンゲージメントの取り組みを強化できます。MoEngage Streams を活用して、ユーザーのエンゲージメントイベントとアクティビティイベントを RudderStack に自動的に転送できます。これにより、これらのイベントを宛先やウェアハウスに転送できるようになります。

# 連携

<Info>
  - MoEngage と RudderStack のログイン認証情報。
  - RudderStack へのエクスポートには、アドオンである MoEngage Streams を使用します。アカウントで有効にするには、MoEngage の担当 CSM(カスタマーサクセスマネージャー)にお問い合わせください。
</Info>

## ステップ 1: RudderStack で新しい MoEngage ソースを追加する

RudderStack ダッシュボードで MoEngage ソースを設定するには、次の手順に従います。

1. [RudderStack ダッシュボード](https://app.rudderstack.com/)に移動し、**Add Source** をクリックします。**Event Streams** ソースのリストから **MoEngage** を選択します。
2. ソースに名前を付け、**Continue** をクリックします。
3. これで MoEngage ソースが設定されました。**Settings** タブに移動し、**Webhook URL** を控えておきます。この Webhook URL は MoEngage の App Marketplace で入力する必要があります。

![moengage-rudderstack-webhook-url.png](/images/partner_12718169699092.png)

## ステップ 2: MoEngage で接続の詳細を入力する

![moengage-app-marketplace.png](/images/partner_12718169705236.png)

1. MoEngage ソースの Webhook URL を取得したら、MoEngage Dashboard \>\> App Marketplace \>\> RudderStack を検索 \>\> に移動し、Add Integration をクリックします。
2. 接続に名前を付け、Webhook URL を入力してから、RudderStack に転送するイベントを選択します。
3. **Connect** をクリックして詳細を保存します。

## MoEngage のイベントプロパティ

次の表は、上記のイベントに含まれるプロパティの一覧です。

| 名前 | 説明 |
| --- | --- |
| App Version | このイベントが追跡されたモバイルアプリケーションのバージョン。App Version はすべてのイベントで追跡されます。 |
| SDK Version | このイベントが追跡された MoEngage SDK のバージョン。SDK Version はすべてのイベントで追跡されます。 |
| Platform | このイベントが追跡された OS 名(例: Android、iOS、Web)。Platform はすべてのイベントで追跡されます。 |
| Campaign Id | このイベントに関連付けられたキャンペーンの ID。 |
| Campaign Name | メッセージが属していたキャンペーンの名前を表します。 |
| Campaign Type | メッセージが属していたキャンペーンのタイプを表します。 |
| Readable Campaign Id | メッセージが属していたキャンペーンの ID を表します。 |
| Parent Campaign id | 定期キャンペーンが実行されたときに追跡されます。子インスタンスが定期的に再実行される親の定期キャンペーンのキャンペーン ID を表します。 |
| Parent Flow Id | ジャーニーキャンペーンが実行されたときに追跡されます。親ジャーニーキャンペーンの Flow ID を表します。 |
| Parent Flow Name | ジャーニーキャンペーンが実行されたときに追跡されます。親ジャーニーキャンペーンのフロー名を表します。 |
| Locale Id | Localization を使用してキャンペーンが送信されたときに追跡されます。メッセージロケールの ID を表します。 |
| Locale Name | Localization を使用してキャンペーンが送信されたときに追跡されます。メッセージロケールの名前を表します。 |
| Variation Id | A/B テストを使用してキャンペーンが送信されたときに追跡されます。メッセージバリエーションの ID を表します。 |
| URL | アプリ内キャンペーンで表示フィルターが選択されたときに追跡されます。 |
| timestamp | イベント実行時のユーザーの時刻。エポック時間で表されます。 |
| First Session | MoEngage Web SDK で追跡されるすべてのイベントに対して生成されます。ユーザーの最初のセッションの場合にのみ値が True になります。 |

| Exit Reason | ユーザーがフローから離脱したときに追跡されます。これは 'User Exited Flow' イベントの属性として追跡されます。 |

RudderStack に転送できる属性については、MoEngage の [Derived Events & Attributes](https://moengage-user-guide.mintlify.app/user-guide/data/event-data/derived-events-and-attributes) を参照してください。

# よくある質問

  <Accordion title="データの受信はいつ開始されますか?">
    通常、アカウントで自動データエクスポートが設定され、データが表示され始めるまでに最大 30 分かかります。
  </Accordion>

  <Accordion title="後から追加のイベントをエクスポートできますか?">
    はい。後から新しいイベントをエクスポートする必要がある場合は、App Marketplace でいつでも設定を編集して、新しいイベントをエクスポートに追加できます。
  </Accordion>
