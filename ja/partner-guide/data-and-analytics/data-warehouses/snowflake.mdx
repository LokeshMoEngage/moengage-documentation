## はじめに

[Snowflake](https://docs.snowflake.com/en/user-guide-getting-started) は、大量の構造化データおよび半構造化データを、高いスケーラビリティと効率性をもって保存、分析、処理できるデータプラットフォームです。独自のアーキテクチャにより、Snowflake を使用すると、組織はデータを統合し、迅速な分析を行い、すべてのユーザーがアクセスできる価値あるデータドリブンなインサイトを得ることができます。

## MoEngage × Snowflake

MoEngage × Snowflake 連携を使用すると、Snowflake インスタンスと MoEngage アプリの間に直接接続を設定し、定期的にデータを同期できます。同期を定期的に実行するスケジュールを定義でき、同期の頻度は最短で1時間ごと、最長で月に1回まで設定できます。同期が実行されると、MoEngage はデータウェアハウスインスタンスに直接接続し、指定されたテーブルからすべての新しいデータを取得して、MoEngage ダッシュボード上の対応するデータを更新します。

### メリット

#### 連携にかかる時間の短縮

- MoEngage は Snowflake と直接連携するため、適切な ETL ツールを探す必要がなくなります。
- 長く複雑な ETL パイプラインは、実際のデータフローなしで MoEngage がデータに直接アクセスできる1回限りの連携設定に置き換えられます。
- これにより、技術チームへの依存が大幅に軽減されます。

#### より高速なデータ処理

- Snowflake インフラストラクチャの能力により、膨大な量のデータをほぼリアルタイムで保存、処理、クエリできます。
- 元のスキーマの変更は、MoEngage 側で設定を変更することなく即座に反映されます。これは従来の ETL パイプラインに比べて大きな利点です。
- ETL ツールや外部クラウドプロバイダーが不要なため、インポートのコストは従来のデータパイプラインよりも大幅に低くなります。

### 連携のユースケース

- Snowflake からリアルタイムのオーディエンスを同期する
- Snowflake アカウントのユーザーデータを使用して、MoEngage のユーザーを最新の状態に保つ。
- Snowflake アカウントから MoEngage にイベントデータを直接インポートする。
- MoEngage にユーザーをインポートし、カスタムセグメントを使用してリターゲティングする。

## 連携

<Info>
  **前提条件**

  新しいユーザー、スキーマ、またはテーブルを作成するための十分な権限を持つ Snowflake アカウントがあることを確認してください。
</Info>

### 新しい Snowflake 接続を設定する

Snowflake からインポートまたはエクスポートするには、まず MoEngage を Snowflake データウェアハウスに接続する必要があります。新しい Snowflake 接続を作成するには、次の手順を実行します。

1. MoEngage ダッシュボードで、App Marketplace に移動します。
2. "Snowflake" を検索します。 <img src="/images/partner_18716690092052.png" alt="App Marketplace で Snowflake を検索" />
3. **Integrate** タブに移動し、**\+ Add Connection** をクリックします。
4. Snowflake データウェアハウスの詳細を入力します。 <img src="/images/partner_23948983262100.png" alt="Snowflake 接続フォーム" />
   | フィールド | 説明 | 例 |
   | --- | --- | --- |
   | Connection Name | この接続に識別しやすい名前を付けます。 | My Snowflake Prod |
   | Snowflake Account Identifier | Snowflake アカウントのアカウント識別子です。 <ul><li>常に Snowflake URL の先頭にあります (`https://ACCOUNT_IDENTIFIER.snowflakecomputing.com`)。</li><li>形式は Snowflake アカウントの作成時期によって異なる場合があります。詳細については、[Snowflake のドキュメントを参照してください](https://docs.snowflake.com/en/user-guide/admin-account-identifier.html)。</li></ul> Snowsight を使用している場合は、左側のナビゲーションの下部にあるアカウント名をクリックします。インポート元のアカウントを選択し、"コピー" アイコンをクリックして Account Identifier をコピーします。最新情報については、[Snowflake のドキュメント](https://docs.snowflake.com/en/user-guide/admin-account-identifier#finding-the-organization-and-account-name-for-an-account)を参照してください。<br /><img src="/images/snowflake.png" alt="Snowflake" title="Snowflake" /> | 形式は次のとおりです: `ACCOUNT_IDENTIFIER.snowflakecomputing.com` |
   | Warehouse | MoEngage がクエリの実行に使用するウェアハウスの名前です。 | COMPUTE\_WAREHOUSE |
   | Database | MoEngage がテーブルの読み取りに使用するデータベースです。スキーマはインポート/エクスポートの設定時に選択できます。 | MY\_DEMO\_DB |
   | Username | 読み取りアクセス権を持つ既存のデータベースユーザー名を使用するか、MoEngage 用に新しいユーザー名を作成します。 | — |
   | Authentication Method | MoEngage は次の2つの方法で Snowflake インスタンスに接続できます。 <ol><li>**Password** - 上記で入力したデータベースユーザー (ユーザー名) のパスワードを入力してください。</li><li>**Key** - MoEngage はキーペア認証方式を使用して Snowflake インスタンスに接続できます。</li></ol> | — |
   | Role | このロールは、MoEngage からクエリを実行する際に使用されます。**Test connection** をクリックして詳細をテストするか、直接 **Save connection** をクリックして続行できます。 | — |
   | <img src="/images/partner_18323283260564.png" alt="Snowflake アカウント識別子の例" /> |  |  |
   | キーペア認証の場合: |  |  |
   1. 認証方式として **Key** を選択します。
   2. **Generate Key** をクリックすると、MoEngage に公開鍵が表示されます。この公開鍵をデータベースユーザーに追加する必要があります。設定するには、[Snowflake のヘルプドキュメント](https://docs.snowflake.com/en/user-guide/key-pair-auth#assign-the-public-key-to-a-snowflake-user)に記載されている手順に従ってください。 <img src="/images/partner_23949032071828.png" alt="キー生成 UI" />
   3. このキーをデータベースユーザーに追加したら、**Test connection** をクリックします。MoEngage が認証情報の検証を試みます。MoEngage はキーのローテーションもサポートしています。IT ポリシーでキーのローテーションが必要な場合は、次の手順で実行できます。
   4. **App Marketplace** \> **Snowflake** \> **Integrate** に移動し、接続を編集します。
   5. 新しいキーを生成するアイコンをクリックします。 <img src="/images/partner_23949032074388.png" alt="新しいキーの生成アイコン" />
   6. 確認画面が表示されます。手順をよくお読みください。新しく生成したキーで接続を保存すると、MoEngage は以前のキーを使用しなくなります。ローテーションを正しく機能させるには、新しいキーがデータベースユーザーに2つ目の RSA キーとして関連付けられていることを確認する必要があります (キーのローテーションに関する Snowflake のヘルプドキュメントを参照してください)。接続の保存後に新しいキーが関連付けられていない場合、インポートとエクスポートが中断される可能性があります。 <img src="/images/partner_23948983277332.png" alt="キーローテーションの確認" />
   7. 新しいキーが生成されて表示されます。この時点で、[Snowflake のヘルプドキュメント](https://docs.snowflake.com/en/user-guide/key-pair-auth#configuring-key-pair-rotation)に記載されている手順に従って、この新しいキーをコピーし、Snowflake データベースユーザーに追加のキーとして関連付けることを強くお勧めします。新しいキーを関連付けたら、ローテーションを完了するために接続のテストを成功させる必要があります。
   8. 新しいキーの生成後、編集フォームを閉じた場合や **Connect** をクリックしなかった場合は、古い (既存の) キーが引き続き以前と同様に使用され、新しく生成されたキーはシステムから削除されます。
5. Snowflake 接続を設定すると、それを使用して MoEngage でさまざまなインポートとエクスポートを設定できます。

Snowflake インスタンスがパブリックではなく AWS 上にある場合は、MoEngage の AWS アカウントとの間で [AWS Private Link](https://docs.snowflake.com/en/user-guide/admin-security-privatelink) を設定することをお勧めします。詳細については、アカウントマネージャーにお問い合わせください。

### Snowflake を使用した Warehouse Segments

Snowflake は Warehouse Segments で利用できるようになりました。詳細については、[Warehouse Segments](/ja/user-guide/segment/create-segments/warehouse-segments) を参照してください。

### Snowflake から MoEngage にユーザーとイベントをインポートする

アカウントで MoEngage × Snowflake のインポートを設定するには、[Snowflake インポートガイド](/ja/user-guide/data/imports/setting-up-a-data-warehouse-import)をお読みください。

### MoEngage から Snowflake へのイベントのエクスポート

MoEngage から Snowflake のテーブルにイベントをエクスポートできます。エクスポートには、ワークスペースで Streams アドオンが有効になっている必要があります。エクスポートを設定するには、[Snowflake エクスポートガイド](/ja/user-guide/data/exports/events/data-warehouse/snowflake-exports)を参照してください。
