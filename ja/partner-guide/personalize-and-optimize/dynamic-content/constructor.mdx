## はじめに

[Constructor](https://constructor.com/) は、AI と機械学習を活用して、E コマースおよび小売の Web サイト向けにパーソナライズされた検索、レコメンデーション、閲覧体験を提供する検索および商品発見プラットフォームです。

## MoEngage × Constructor

MoEngage と Constructor の統合により、Constructor の Offsite Product Discovery を使用して、パーソナライズされた商品レコメンデーションを動的に生成し、MoEngage キャンペーンで配信できます。

## ユースケース

- **カート放棄および注文後のフォローアップ:** ユーザーの行動やカートの内容に基づいて動的な商品レコメンデーションを生成し、パーソナライズされたカート放棄リマインダーや注文後の提案を送信します。
- **カート放棄商品の類似商品レコメンデーション:** ユーザーのカートに残された商品に類似した商品を提案し、エンゲージメントを維持しながら代替品を提示します。
- **最近閲覧した商品のリマインダー:** ユーザーが最近閲覧したもののまだ購入していない商品を通知し、購入の完了を促します。
- **プロモーションキャンペーン:** シーズンセールや特別オファー向けに、ユーザーの好みに合わせて厳選した商品レコメンデーションを含むパーソナライズされたプロモーションメッセージを配信します。
- **見た目が類似した商品の提案:** ユーザーが最近閲覧した商品と見た目が似ている商品をレコメンドし、好みに合いそうな関連商品の発見を支援します。

## 統合

<Info>
  **前提条件**

  Offsite Discovery サービスが有効になっている Constructor アカウントへのアクセス権。
</Info>

Constructor のオンボーディングチームと協力して、統合プロセスを完了してください。パーソナライズされた商品レコメンデーションを有効にするため、Web サイトやその他の関連データソースからの行動データが利用可能であることを確認してください。

Constructor のオンボーディングチームは、MoEngage キャンペーンで使用するために必要な HTML スニペットの設定も支援します。

### Constructor の Offsite Discovery API URL を取得する

Constructor の Offsite Discovery API URL を使用して、商品画像をレンダリングし、ユーザーを適切な商品詳細ページに誘導できます。

HTML スニペットのサンプル:

<CodeGroup>

```html HTML wrap
<a href="[https://offsite-discovery.cnstrc.com/v1/product/url?position=](https://offsite-discovery.cnstrc.com/v1/product/url?position=)[position]&ui=[ui]&pod_id=[pod_id]&key=[key]&style_id=[style_id]&campaign_id=[campaign_id]" target="_blank">
  <img
    src="[https://offsite-discovery.cnstrc.com/v1/product/image?position=](https://offsite-discovery.cnstrc.com/v1/product/image?position=)[position]&ui=[ui]&pod_id=[pod_id]&key=[key]&style_id=[style_id]&campaign_id=[campaign_id]"
    width="200"
    border="0"
    alt="Shop Now"
  />
</a>
```

</CodeGroup>

| パラメーター | タイプ | 説明 |
| --- | --- | --- |
| `position` | 必須 | 提案リスト内での特定のレコメンド商品の順位を指します（例: `position = 2`）。 |
| `ui` | 必須 | ユーザーの識別子を表し、レコメンド結果のパーソナライズに不可欠です。ui パラメーターには、MoEngage と Constructor の間で共通の識別子を設定してください。省略した場合、Constructor はユーザー固有のレコメンデーションではなく一般的なレコメンデーションを返します。 |
| `pod_id` | 必須 | レコメンデーションの戦略とサーチャンダイジングルールを含む pod の識別子です（例: ベストセラー戦略の pod は、パーソナライズされたベストセラーを生成します）。 |
| `key` | 必須 | この顧客の Constructor インデックスキーです。 |
| `style_id` | 必須 | 商品カードに表示する画像を決定します。たとえば、style\_id が異なると、それぞれ異なる商品カード画像が表示されます。 |
| `campaign_id` | 必須 | メールキャンペーンの一意の ID |
| `item_id` | 任意 | シードアイテムを表します。代替品、補完品、バンドルなど、アイテム間ベースの戦略に必要です。たとえば、メール内の最初のアイテムがシードアイテムとなり、以降のアイテムが代替品となります。 |
| `num_results` | 任意 | メールに追加する商品の数です。デフォルトは 10 で、最大 100 まで指定できます。たとえば、`num_results = 3` の場合、3 つのレコメンデーションが追加されます |

HTML スニペットを取得したら、MoEngage キャンペーンに直接挿入できます。
