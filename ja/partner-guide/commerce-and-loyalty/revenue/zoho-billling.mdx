[Zoho Billing](https://www.zoho.com/billing/) は、成長企業向けのエンドツーエンドの請求ソリューションです。多様な料金モデルの導入、ユーザーの管理、支払いの回収、意思決定に役立つレポートの作成に使用できます。

## MoEngage × Zoho Billing

MoEngage と Zoho Billing を連携すると、サブスクリプションと支払いのデータを MoEngage アカウントに同期できます。その後、請求イベントに基づいてコミュニケーションを自動化し、サブスクリプションの詳細でキャンペーンをパーソナライズできます。

## ユースケース

Zoho Billing を MoEngage と連携すると、次のユースケースに対応できます。

- **パーソナライズされたコミュニケーションの送信** : サブスクリプションのステータス、支払い履歴、今後の更新などの Zoho Billing のデータを使用して、MoEngage からターゲットを絞ったパーソナライズされたメッセージを送信します。たとえば、特定のユーザーセグメントに更新のリマインダー、支払い失敗の通知、アップグレードのオファーを送信できます。
- **自動化されたライフサイクルキャンペーン** : Zoho Billing の請求イベントによってトリガーされる自動化されたユーザージャーニーを MoEngage で作成します。これらのイベントを使用して、新規購読者のオンボーディング、解約したユーザーの再エンゲージ、長期ユーザーへの特別なプロモーションの送信を自動的に行えます。

# 連携

<Info>
  連携を設定するには、次のものが必要です。

  - Zoho Billing のアクティブなアカウント。
  - Zoho Billing アカウントで Webhook を作成および管理する権限。
</Info>

## ステップ 1: MoEngage エンドポイントを取得する

連携専用のエンドポイントを取得するには、MoEngage サポートチームにお問い合わせください。リクエストでは、MoEngage とパートナープラットフォーム間でユーザープロファイルを紐付けるために使用する共通識別子を指定する必要があります。

たとえば、共通識別子はユーザーのメール ID や電話番号です。

## ステップ 2: Zoho Billing で Webhook を設定する

Zoho Billing で Webhook を設定するには、次の手順を実行します。

1. Zoho Billing ダッシュボードで、**Settings** \> **Automation** \> **Workflow Actions** に移動します。
2. **Webhooks** タブをクリックします。
3. 右上にある **\+** **New Webhook** をクリックします。 <img src="/images/partner_39487110682644.png" /> 右上にある **\+ New Webhook** をクリックします。 
4. Webhook のわかりやすい名前を入力します（例: MoEngage Subscription Updates）。
5. Webhook をトリガーするモジュールを選択します（例: Subscriptions または Invoices）。
6. MoEngage に更新を送信する特定のイベントを選択します。 

<Info>
  Subscriptions などの特定のモジュールでは、Zoho Billing は _Immediate Events_ と _Scheduled Events_ の両方を提供しています。連携のニーズに最も適したイベントタイプを選択してください。
</Info>

7. Webhook の設定セクションで、次の詳細を入力します。

| フィールド | 説明 |
| --- | --- |
| **Action** | メソッドが **POST** に設定されていることを確認します。次に、サポートチームから提供された MoEngage エンドポイント URL を入力します。 |
| Headers | 次のカスタムヘッダーを追加します: <ul><li>**Content-Type**: application/json</li><li>**Authorization**: Basic トークンを取得するには、オンラインの [Basic Auth Header Generator ツール](https://www.debugbear.com/basic-auth-header-generator)を使用します。Workspace ID をユーザー名、Data API Key をパスワードとして入力する必要があります。API トークンは、MoEngage ダッシュボードの Settings \>\> APIs にあります。Basic 認証トークンとして次の値を貼り付けます: <br />`Basic Qk5CR1NNNUR4eHh4eHhWQ1hSRFJEWTdSOlFsWHVoTHVaeHh4eHh4QWQrQnBYUEotNw==`<br />**注**: 余分なスペースを含めずにトークンを完全にコピーしてください。</li></ul> |
| Authorization Type | Authorization Type として **Self Authorization** を選択する必要があります。 |
| Body | Body セクションでは、次のいずれかを行う必要があります。<br /><br />• MoEngage の特定の標準フィールドのみを更新する場合は、**Default Payload** を選択します。<br />• カスタムペイロードを実装する場合は、JSON 形式で **Raw** を選択します。その後、Webhook の設定支援を受けるために、サンプルのペイロード構造をサポートチームと共有します。 |

8. **Save** をクリックします。

<Info>
  - Webhook の保存に失敗する場合や、想定どおりにトリガーされない場合は、入力したすべての値、特に MoEngage エンドポイント URL と認証トークンを再確認してください。
  - 認証トークンの先頭や末尾にスペースがないことを確認してください。
</Info>

Webhook を保存した後、Zoho Billing でテストイベントをトリガーします（選択したモジュールに応じて、新しいサブスクリプションの作成や既存の請求書の更新など）。データの取り込みの確認についてサポートが必要な場合は、MoEngage の[サポートチーム](/ja/user-guide/contact-support/raise-a-support-ticket-through-moengage-dashboard)にお問い合わせください。

### Zoho Billing から同期されるユーザー属性

デフォルトでは、Zoho Billing 連携は、キャンペーンのセグメント化とパーソナライズの機能を強化するために、次の主要なサブスクリプションおよび請求書のデータをユーザー属性として MoEngage に自動的に同期します。

#### サブスクリプションイベント

| 属性名 | 説明 |
| --- | --- |
| **Subscription plan name** | サブスクリプションプランの名前を表示します。多くの場合、請求書に表示されます。 |
| **Subscription plan code** | ユーザーのサブスクリプションプランを識別する一意のコードです。 |
| **Subscription status** | サブスクリプションの現在のステータスです（例: live、trial、canceled）。 |
| **Subscription number** | ユーザーのサブスクリプションの一意の識別子です。 |

#### 請求書イベント

| 属性名 | 説明 |
| --- | --- |
| **Invoice number** | 請求書の一意の ID です（通常は INV で始まります）。 |
| **Invoice total** | すべてのクレジットが適用された後の、請求書の最終的な支払額です。 |
| **Invoice status** | 請求書の現在のステータスです（例: paid、sent、overdue、void）。 |
| **Invoice due date** | 支払い期限切れを避けるために請求書の支払いを行う必要がある期日です。 |
| **Invoice payment date** | 請求書の支払いが正常に完了した日付です。 |
| **Invoice balance** | 請求書の未払いの残額です。 |

## ステップ 3: MoEngage でターゲットキャンペーンを送信する

連携が有効になると、Zoho Billing のユーザー属性とイベントが MoEngage に表示されます。データに基づいてユーザーをセグメント化し、ターゲットを絞ったキャンペーンを送信できます。
