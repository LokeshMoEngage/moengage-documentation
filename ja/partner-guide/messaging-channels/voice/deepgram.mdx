[Deepgram](https://deepgram.com/) は、リアルタイムの音声テキスト変換、テキスト音声変換、会話型音声エージェントを提供する AI 音声プラットフォームです。MoEngage と Deepgram の統合により、MoEngage Flows から AI 駆動のアウトバウンド電話を直接トリガーできます。これにより、アプリやサイトでのユーザーイベントをきっかけに、独自の Deepgram ベースのサーバーが処理するリアルタイムの音声会話につなげることができます。

Outbound Voice Call を使用すると、MoEngage を介して自動化された電話での会話を開始できます。チェックアウトの放棄、取引の失敗、更新期限の接近、サポートの必要性など、特定のユーザーアクションが発生すると、MoEngage は専用サーバーにリクエストを送信します。サーバーは Deepgram 音声エージェントを使用して通話を実行し、対話型の会話を管理します。

## Outbound Voice Call × MoEngage

この統合により、MoEngage 内に電話通信や会話型 AI のインフラストラクチャを構築することなく、イベントトリガー型の音声アウトリーチを自動化できます。

この統合により、次のことが可能になります。

- Flow イベントが発生した瞬間に、アウトバウンドの AI 音声通話をトリガーします。
- キャンペーンで設定したコンテキスト（注文 ID、更新日、支払金額、またはエージェントのプロンプトに必要なその他のフィールド）を各通話とともに渡します。

## ユースケース

Deepgram と MoEngage を統合すると、次のユースケースに対応できます。

- **カート放棄のフォローアップ**: ユーザーがチェックアウトを放棄した際に、カートの内容に言及する通話をトリガーし、購入完了のサポートを提供します。
- **支払い失敗からの回復**: 定期支払いが失敗した際に、顧客に通知して支払い情報の更新を支援する通話をトリガーします。
- **更新とリテンション**: サブスクリプションの更新前に顧客にリマインドし、必要に応じてリテンション特典を提示する通話をトリガーします。
- **注文ステータスと問題解決**: 遅延や配達について顧客に通知し、注文ステータスに基づいて解決策を提示する通話をトリガーします。

## アーキテクチャと接続

次の表は、統合のアーキテクチャとコンポーネントを示しています。

| コンポーネント | 説明 |
| --- | --- |
| **MoEngage Flow** | 指定したユーザーイベントが発生したときに、Connected App アクションをトリガーします。 |
| **POST /make-call** | アウトバウンド通話を開始するために、MoEngage からカスタムサーバーに送信される API リクエストです。 |
| **Voice Agent integration server** | リクエストを認証し、電話通信プロバイダーを介して通話を発信するお客様のサーバーです。 |

## 前提条件

<Info>
  統合を設定するには、次のものを用意してください。

  - **パブリック HTTPS サーバー**: `/make-call` の仕様を実装した、公開アクセス可能なサーバー。
  - **認証シークレット**: サーバーが受信リクエストで検証するシークレット（Bearer トークンとして送信されます）。
  - **コンテキストオブジェクトキー**: サーバーが通話コンテキストを受け取る際に想定する JSON キー（例: `lead` や `context`）。
</Info>

<Note>
  MoEngage は、音声エージェント自体のいかなる部分もホスト、実行、運用しません。お客様が選択した音声スタック上に構築した独自のサーバーをご用意ください。
</Note>

## ステップ 1: 音声エージェントサーバーを構築してデプロイする

MoEngage からのリクエストを受信して処理するためのエンドポイント（例: `/make-call`）を持つサービスを構築してホストします。`/make-call` というパスは一例であり、実装では別のエンドポイント名を使用できます。カスタムサーバーは次のタスクを管理します。

1. **リクエストの認証**: 受信したエンドポイントシークレットを検証し、安全な接続を確保します。
2. **通話のオーケストレーション**: 任意の電話通信サービスプロバイダーを介してアウトバウンド接続を開始します。
3. **会話ロジック**: Deepgram AI エンジンを使用して、リアルタイムの対話型会話を実現します。

技術的な詳細については、[Deepgram のドキュメント](https://developers.deepgram.com/docs/outbound-telephony-agent#outbound-telephony-voice-agent)を参照してください。

## ステップ 2: MoEngage でアプリを接続する

サーバーをデプロイしたら、MoEngage で接続します。

1. MoEngage ダッシュボードで **App Marketplace** に移動します。
2. **Outbound Voice Call (Custom Server)** を検索し、**Connect** をクリックします。
3. **Connection details** で、次の詳細を入力します。

| フィールド | 必須 | 説明 |
| --- | --- | --- |
| Connection Name | はい | この接続を識別するための名前（例: Production Voice Agent）。 |
| Server URL | はい | デプロイしたサーバーのパブリックベース URL（例: `https://your-app.com`）。 |
| Endpoint Secret | はい | サーバーが受信リクエストで検証する Bearer シークレットキー。 |
| Context Key | はい | サーバーがコンテキストを受け取る際に想定する JSON キー（例: `lead`、`order`）。このキーは、キャンペーン設定時に Context Fields で追加したキーと値のペアをラップします。 |

4. **Connect** をクリックします。

<Note>
  接続の詳細への変更が反映されるまでに最大 15 分かかります。
</Note>

## ステップ 3: キャンペーンを設定する

1. [Connected App キャンペーンを作成](/ja/user-guide/campaigns-and-channels/connected-apps/create/create-a-connected-app-campaign)し、キャンペーン設定のステップ 2 で **Make Outbound Call** コネクターを選択します。
2. **Call Configuration** セクションで、E.164 形式の **Phone Number** を入力します。`@` を入力するとパーソナライズできます。
3. プロンプトに必要な **Context Fields** をキーと値のペアとして追加します（例: `order_id`）。

![電話番号フィールドと、キーと値のペアとして入力されたコンテキストフィールドを示す通話設定画面](/images/Deepgram2.png)

## ステップ 4: テストと検証

統合が想定どおりに動作することを確認するには、次の検証手順に従います。

1. キャンペーンからテスト送信をトリガーし、リクエストボディのコンテキストオブジェクトが、アプリ接続時に設定した Context Key のとおりのキーの下に表示されることを確認します。
2. サーバーログを確認し、認証と電話の発信が行われたことを確認します。Authorization ヘッダーが Endpoint Secret と一致する受信リクエストを探します。
3. 会話で、提供したコンテキストフィールドが正しく使用されたことを確認します。
