# API Key ダッシュボード

MoEngage の API Key ダッシュボードが、Data、Segmentation、Push API で複数のキーをサポートするようになり、アクセス制御もサポートされました。API キーは通常、認証または認可のメカニズムとして使用されます。API キーは、API リソースへのアクセス権を持つユーザーまたはアプリケーションに関連付けられた一意の識別子です。複数の API キーのサポートにより、次のユースケースに対応できます。

- 既存のキーを使用可能な状態のまま、新しいキーを生成できます。
- チームごとに異なるキーを使用できます。

詳細については、[API Key ダッシュボード](/ja/user-guide/settings/account/api-and-api-keys/api-key-dashboard)を参照してください。

# WhatsApp の新しいテンプレート

WhatsApp テンプレートが Gupshup と Karix でも利用できるようになりました。これらのテンプレートを使用すると、企業は事前定義されたパーソナライズされたメッセージを作成でき、コミュニケーションを効率化できます。MoEngage を使用して WhatsApp メッセージを送信し、WhatsApp によって(直接または WhatsApp サービスプロバイダー(BSP)経由で)承認済みのテンプレート、または MoEngage でホワイトリストに登録されたテンプレートを使用できます。

この機能により、ビジネスの効率を向上させ、自動通知を確立し、WhatsApp での顧客エンゲージメントを促進し、ブランドの信頼性を高めることができます。

詳細については、[WhatsApp テンプレート](/ja/user-guide/campaigns-and-channels/whatsapp/getting-started-with-whatsapp/whatsapp-templates)を参照してください。

# タグベースのフリークエンシーキャッピング

MoEngage は、配信タイプとタグに対するフリークエンシーキャッピング(FC)をサポートするようになり、ユーザーとのコミュニケーションを最適化し、効果的に制御できるようになりました。この機能強化により、特定のユーザーコホートがさまざまな種類のキャンペーンから受け取るコミュニケーションの数を制御できます。また、配信タイプを制御し、特定の配信タイプが FC の上限全体を超えないようにすることもできます。

**機能強化:**

- FC ダッシュボードで、チャネルごとに配信タイプに基づくフリークエンシーキャッピングを構成できます。
- 個々のチャネルに対して、タグベースの FC ルールを構成できます。
- すべてのタグおよび任意のタグに対してタグベースの FC ルールを構成し、クロスチャネルのコミュニケーションを制御できます。
- 最大3つのタグベースのルールを構成でき、ユースケースに応じて拡張できます。
- Flows と Push API に個別のフリークエンシーキャッピングを構成して、これらのチャネルからのコミュニケーションをより適切に制御できます。

詳細については、[フリークエンシーキャッピング](/ja/user-guide/settings/channels/delivery-controls/frequency-capping)を参照してください。

# Snowflake 向け Warehouse Segments の導入

Snowflake 内のデータをコピーしたり移動したりする手間なく、MoEngage から直接簡単にアクセスして活用できるようになりました。この機能により、ワークフローが簡素化され、オーディエンスとのタイムリーなエンゲージメントが可能になります。

**メリット:**

- Warehouse Segments により、MoEngage への複雑なデータ同期が不要になります。
- Warehouse Segments により、ウェアハウスのデータに即座にアクセスでき、データの利用可能性に関する遅延がなくなります。SQL 定義を MoEngage に保存し、キャンペーンの実行時にセグメントを処理することで、オーディエンスセグメントをその場で生成できます。
- データはウェアハウス内に安全に保持され、直接アクセスされるため、Warehouse Segments はデータセキュリティと規制遵守に関する懸念に対応します。
- Warehouse Segments を使用すると、マーケターは、データを利用可能にするための ETL パイプラインの構築や保守をエンジニアリングチームに頼ることなく、ウェアハウスのデータから直接オーディエンスセグメントを作成できます。
- Warehouse Segments により、定期的なデータ転送パイプラインを構築するための追加の ETL ツールが不要になるため、データ同期に関連するオーバーヘッドコストが削減され、それらの管理に必要なリソースも不要になります。

詳細については、[Warehouse Segments](/ja/user-guide/segment/create-segments/warehouse-segments#step-1-set-up-your-data-source)を参照してください。

# Push 向け Teams Management 2.0

Teams 2.0 で Push チャネルが利用できるようになりました。これにより、担当している顧客に固有の Push キャンペーンデータを表示し、アクセスできます。

**メリット:**

- 国やブランドなど、ターゲティング条件の定義に役立つ複数のユーザー属性に基づいてチームを作成できます。
- Push チャネルのセグメンテーションクエリにチームフィルターを付加することで、Push キャンペーンでターゲットにできるオーディエンスを制御できます。

詳細については、[Push 向け Teams Management 2.0](/ja/user-guide/settings/account/team-management/teams-20-in-moengage)を参照してください。

# Personalized Preview API の導入

この API を使用すると、任意のキャンペーンタイプのパーソナライズされたペイロードを取得できるようになりました。MoEngage は、アウトバウンドチャネルとインバウンドチャネルを含むすべてのチャネルをサポートしています。

**メリット:**

- キャンペーンコンテンツ内で使用されるパーソナライゼーションが正しく、正しくレンダリングされることを確認できます。
- API を通じてテンプレートを送信し、テンプレート内のパーソナライズされたコンテンツが正しくレンダリングされるかをテストできます。
- ユーザーが独自の製品を使用してキャンペーンを作成している場合、任意のデバイスでペイロードをレンダリングできます。
- この API は、あらゆる種類のパーソナライゼーションに対応しています。

詳細については、[Personalized Preview](https://www.moengage.com/docs/api/test-campaigns/personalized-preview)を参照してください。

# Stats API

Stats API を使用すると、リアルタイムで同期される詳細なキャンペーン統計を取得できます。この API はプラットフォームレベルでデータを取得し、すべての種類のキャンペーンのデータを提供します。

**メリット:**

- 期間またはキャンペーン ID のリストに基づいて、キャンペーンのパフォーマンス統計を取得できます。
- 配信ファネルとエラーの内訳を取得して、キャンペーンのパフォーマンスを一括で確認できます。
- 現在のフェーズにおけるすべてのロケールとすべてのバリエーションレベルの統計を取得できます。

詳細については、[Stats API](https://www.moengage.com/docs/api/stats/get-campaign-stats)を参照してください。

# Personalize でのカウントダウンタイマーの導入

パーソナライズされたエクスペリエンスの作成時に、ウィジェットとしてカウントダウンタイマーを追加できるようになりました。

**メリット:**

- カウントダウンタイマーウィジェットは、緊急性と期待感を演出し、プロモーションコードの有効期限、期間限定セール、今後の製品発売、イベントまでのカウントなど、時間的制約のある情報を伝えることで、顧客の即時のアクションとインタラクションを促します。
- エディター内で動的なカウントダウンタイマーを直接設定できるようになりました。このシンプルさにより時間を節約でき、マーケティング戦略を試す機会が増えます。
- 作業内容を即座にプレビューし、顧客やリードに緊急性を感じさせることで、キャンペーンの効果をさらに高めることができます。

詳細については、[カウントダウンタイマー](/ja/user-guide/personalize/client-side-personalization/personalize-editor-widgets/adding-widgets)を参照してください。

# Split URL テスト

MoEngage は、ユーザーの好みに基づいて Web 要素の最適なバージョンを予測できる Split URL テストを導入しました。これにより、ユーザーのアクションを促す魅力的なエクスペリエンスを作成できます。

**メリット:**

- Split URL テストを使用すると、継続的に変更を加えることができ、データに基づいた意思決定により、よりユーザーフレンドリーなエクスペリエンスを実現できます。
- ユーザーに対してより高いパフォーマンスを発揮するコンテンツのバージョンをテストすることで、オーディエンスの好みに合わせてサイトを調整でき、ユーザーエンゲージメントを高めることができます。
- ユーザーの好みを理解することで Web サイトを最適化でき、不適切なコンテンツによる直帰率を大幅に低減できます。
- Web サイトに最も効果的な要素を選択することで、より高いコンバージョン率を達成できます。
- Split URL テストを使用すると、サイト全体に実装する前に少数のユーザーグループで変更をテストできるため、潜在的な悪影響を軽減できます。

詳細については、[Split URL テスト](/ja/user-guide/personalize/split-url-testing/create-a-split-url-testing-experience)を参照してください。

# WYSIWYG エディターと Personalize API

MoEngage は、コンテンツパーソナライゼーションモデルに対応するため、WYSIWYG エディターと Personalize API の提供内容を強化しました。これにより、ユーザー属性、Content Block、または Content API を活用できる、洗練された Web ページコンテンツのパーソナライゼーション機能が実現します。この機能は、社内システムや、ロイヤルティエンジンを含むサードパーティのリソースからのデータを活用した、コンテンツの充実化とパーソナライゼーションに重点を置いています。

詳細については、[コンテンツのパーソナライゼーション](/ja/user-guide/personalize/client-side-personalization/personalize-editor-capabilities)を参照してください。

MoEngage は Device API を導入しました。この API を使用すると、MoEngage でデバイスとデバイスプロパティを追加または更新できます。詳細については、[Track Device](https://www.moengage.com/docs/api/device/track-device)を参照してください。

Analytics でチャートを並べ替えられるようになりました。並べ替えは、User Analysis、Behavior、Session and Source で利用できます。

詳細については、[並べ替え](/ja/user-guide/analyze/analytics/getting-started-with-analytics/overview#sorting-and-calculation)を参照してください。

# Personalize での RTSE のサポート

Personalize で Real-Time Segmentation Refresh(RTSE)のサポートを導入しました。これにより、ユーザーセグメントをリアルタイムで更新でき、同じセッション内でパーソナライズされたエクスペリエンスを即座に提供できます。

# Sherpa AI ベースの動的トラフィック配分

Sherpa AI ベースの、バリエーション間の動的なトラフィック配分を導入しました。バリエーション間のトラフィックを継続的に監視し、手動で配分する必要はなくなりました。代わりに、Sherpa AI が、選択した指標に従って、最もパフォーマンスの高いバリエーションへのトラフィックフローを最適化します。

詳細については、[Sherpa AI ベースの動的トラフィック配分](/ja/user-guide/personalize/client-side-personalization/client-side-personalization/create-client-side-personalization-experience#step-2-content)を参照してください。
