# Rich Communication Services (RCS)

MoEngage はネイティブの Rich Communication Services (RCS) をリリースしました。この機能により、標準的な SMS を超えて、ユーザーのネイティブメッセージングアプリ内でアプリのようなリッチなエクスペリエンスを直接作成できます。

RCS は、テキストメッセージをインタラクティブな会話に変えます。注目を集めてアクションを促す高品質の画像や動画を送信できます。

**主なメリット:**

- **リッチメディアでエンゲージメントを向上**: 鮮やかな高解像度の画像や動画を送信して、商品を紹介し、魅力的なブランドストーリーを伝えます。
- **インタラクティブなボタンでコンバージョンを向上**: タップ可能な提案やボタンを追加して、ユーザーがワンタップで返信、選択、Web ページへのアクセスを行えるようにします。
- **信頼性と明確さを構築**: 認証済みの送信者プロファイルでユーザーの信頼を獲得し、配信確認と既読確認から有益なインサイトを得ます。
- **最大限のリーチを確保**: デバイスが RCS に対応していないユーザーには自動的に SMS へフォールバックすることで、到達率を最大化します。

詳細については、[RCS の概要](/ja/user-guide/campaigns-and-channels/sms-mms-and-rcs/rcs/getting-started-with-rcs/introduction-to-rcs) を参照してください。

# 通知のグループ化

MoEngage は *Notification Grouping* 機能を導入しました。この機能により、グループキーを使用して関連するプッシュ通知をまとめてスタックできます。ユーザーは通知ドロワー内の 1 つの展開可能なスレッドで通知を確認できるため、通知の煩雑さが軽減され、コンテンツへのエンゲージメントが向上し、ユーザーエクスペリエンスが強化されます。

この機能を使用すると、次のことができます。

- ニュースアプリで更新情報をカテゴリ別にスタックする。
- 銀行アプリで取引通知をグループ化し、追跡しやすくする。
- e コマースアプリで注文の更新、プロモーション、オファーを整理する。

MoEngage は、次のプラットフォームでグループ化された通知をサポートしています。

- **Android**: SDK バージョン 14.00.00 以降が必要で、`ismultiplenotificationsindrawer` 設定を *true* に設定する必要があります。
- **iOS**: SDK バージョン 9.24.0 以降が必要で、グループ化の管理には `APNS thread ID` を使用します。

詳細については、[通知のグループ化](/ja/user-guide/campaigns-and-channels/mobile-push/notification-features-and-behavior/push-notification-grouping) を参照してください。

# 通知の更新

MoEngage は *Notification Update* 機能を導入しました。この機能により、同じ更新キーを持つ新しいプッシュ通知を送信することで、既存のプッシュ通知を置き換えることができます。これにより、ユーザーは最も関連性の高い情報のみを受け取ることができ、重複や煩雑さが軽減されます。

この機能を使用すると、次のことができます。

- **注文の追跡**: 注文 ID を更新キーとして使用し、配送状況を更新します。
- **関連性の高いオファーの表示**: 以前のプロモーションを上書きして、最も適したプロモーションのみを表示します。
- **ニュースアラートの精緻化**: 最初のアラートを検証済みの最新情報で置き換えます。

プラットフォームのサポート:

- **Android**: SDK バージョン 14.00.00 以降が必要です。
- **iOS**: SDK バージョン 9.24.0 以降が必要です。

詳細については、[通知の更新](/ja/user-guide/campaigns-and-channels/mobile-push/notification-features-and-behavior/push-notification-update) を参照してください。

# プッシュ通知での GIF のサポート

MoEngage はプッシュ通知で GIF をサポートするようになり、より魅力的で視覚的に躍動感のあるメッセージを作成できるようになりました。この機能は、展開時の Android 14 以降および iOS のプッシュ通知でサポートされています。

この機能を使用すると、次のことができます。

- 360 度ビューやデモ形式のビジュアルで商品をプロモーションする。
- インタラクティブなアニメーションで、放棄されたカートをユーザーにリマインドする。
- アニメーションアイコンでセキュリティメッセージを強調する。
- アニメーションによる荷物追跡で配送の進捗状況を表示する。

<Info>
- GIF は次の環境でサポートされています。
  - Android 14 以降で、MoEngage SDK バージョン 14.00.00 以降を使用している場合。
  - MoEngage SDK バージョン 9.24.0 以降を使用している iOS デバイス。
- サポートされていないバージョンやデバイスでは、フォールバック画像が表示されます。
</Info>

詳細については、[プッシュ通知での GIF のサポート](/ja/user-guide/campaigns-and-channels/mobile-push/notification-features-and-behavior/gifs-in-push-notifications) を参照してください。

# Landing Pages

MoEngage は Landing Pages にいくつかの新機能を導入しました。パフォーマンス分析とパーソナライゼーション機能を強化するよう設計されています。

## A/B テストと Cohorts

ランディングページで A/B テストが利用できるようになりました。これにより、ページのバリエーションを試したり、Cohorts を通じてリアルタイムのユーザーコンテキストに基づいたターゲットコンテンツを配信したりできます。

- **A/B テスト**: エディター内で直接、ランディングページのバージョンを最大 5 つ作成できます。これらのバリエーション間でトラフィックを分配し、どのデザインやコンテンツが最良の結果をもたらすかを判断します。
- **Cohorts**: クエリパラメーター、地理的位置、デバイス、時刻、ブラウザーなどのセッション内属性に基づいて、特定のユーザーセグメントを定義します。これらのセグメントに合わせたランディングページのコンテンツを自動的に配信し、より関連性の高いパーソナライズされたエクスペリエンスを作成します。

詳細については、[ランディングページの作成](/ja/user-guide/content/landing-pages/create/create-a-landing-page) を参照してください。

## ランディングページの分析

公開済みのランディングページでランディングページの分析が利用できるようになり、ページのパフォーマンスを明確に把握できます。ランディングページを公開した後 (または **Content** \> **Landing pages** から) このページにアクセスして、閲覧数、クリック数、CTR を追跡できます。分析ページでは、チャートや表を使用して、時間の経過に伴うユーザーエンゲージメントを把握できます。また、さまざまな A/B テストのバリアントやターゲットのコホート全体でパフォーマンスを分析し、最適化の機会を特定することもできます。

詳細については、[ランディングページの分析](/ja/user-guide/content/landing-pages/analyze/analyze-landing-pages) を参照してください。

## 動的テキスト置換

ランディングページで Dynamic Text Replacement が利用できるようになり、パーソナライゼーション機能がさらに強化されました。

URL クエリパラメーターに基づいて、ランディングページのテキスト要素を自動的にパーソナライズできます。ランディングページエディター内の任意のテキスト領域で @ 記号を使用して、動的置換を設定します。テキスト要素 (見出しや CTA など) を特定の URL クエリパラメーター (utm\_campaign、source、カスタムパラメーターなど) にリンクします。これにより、ユーザーがクリックした特定の広告キャンペーンや推定される所在地を反映するなど、ユーザーの流入経路に基づいてメッセージをカスタマイズできます。

詳細については、[ランディングページのパーソナライズ](/ja/user-guide/content/landing-pages/create/personalize-a-landing-page) を参照してください。

# アラートの送信先

MoEngage は *Alert Destination* 機能を導入しました。この機能により、Email に加えて Slack チャネルにもリアルタイムのアラートを直接送信できます。これにより、チームはコンテキストを切り替えることなく、普段使用しているツールでタイムリーに通知を受け取ることができます。

この機能を使用すると、次のことができます。

- Slack 経由で重要な最新情報を送信する。サポートされているアラートの種類は次のとおりです。
  - Campaign Stats
  - Flow Stats
  - Campaign Expiry
  - APNS Token Expiry
  - FB Token Expiry
- アラートの種類ごとに、Slack、Email、またはその両方を送信先として設定する。
- 名前や設定を編集したり、関連するアクティブなアラートとともに送信先を削除したりする。

この機能は早期アクセスで利用できます。有効にするには、MoEngage のカスタマーサクセスマネージャー (CSM) またはサポートチームにお問い合わせください。

# In-App Messaging のトリガー

MoEngage は、明確さ、使いやすさ、ターゲティングオプションを向上させるために、In-app messaging のトリガーを更新しました。

**主な変更点:**

- **新しい「On Session Start」トリガー**: このトリガーは、ユーザーのセッションの開始時にアプリ内メッセージを表示します。すべての画面で特定のメソッド呼び出しを必要とせずに、即座にエンゲージメントを図るのに最適です。
  - このトリガーは、ユーザーが新しいセッション (アプリを開いてから、アプリを閉じる、ログアウトする、またはタイムアウトするまで) を開始したときにメッセージを表示します。
  - このトリガーを使用するキャンペーンでは、**`showinapp()` メソッドの実装は不要です**。これにより、すべての画面に SDK メソッドを実装することなく、アプリ内キャンペーンを公開できます。
- **名称変更および強化された「On Screen Load」トリガー (旧「On Specific Screen」)**: このトリガーを使用すると、ユーザーが特定の画面またはアプリのコンテキストに移動したときにアプリ内メッセージを表示できます。複数の画面やコンテキストに対して柔軟なターゲティングが可能です。
  - **移行:** 以前の「**On App Open**」トリガーは、「**On Screen Load**」の下に「**Any Screen (Earlier on app open)**」として分類されるようになりました。
  - **複数画面のターゲティング:** 指定した最大 5 つの画面の *いずれか* にユーザーがアクセスした場合にキャンペーンが表示されるようにターゲティングできるようになりました (**OR** 条件を使用)。
  - **複数コンテキストのターゲティング:** 指定した最大 5 つのコンテキストの *いずれか* にユーザーがアクセスした場合にキャンペーンが表示されるようにターゲティングすることもできます (**OR** 条件を使用)。
  - **UI の改善:** 画面名の選択が「**On Screen Load**」トリガーの条件設定内に直接統合されました。

**SDK の更新要件:**

「On Session Start」トリガーの機能 (`showinapp()` が不要) を使用するには、SDK を更新する必要があります。

- **iOS in-app SDK バージョン:** 6.06.0
- **Android in-app SDK バージョン:** 9.0.0

詳細については、[アプリ内キャンペーンの作成](/ja/user-guide/campaigns-and-channels/in-app-message/create/create-in-app-campaign) を参照してください。

# Private ダッシュボードと Workspace ダッシュボード

MoEngage は Custom Dashboard 機能内に Private ダッシュボードと Workspace ダッシュボードを導入し、表示範囲とコラボレーションをより詳細に制御できるようにしました。このアップデートにより、さまざまなコラボレーションやセキュリティのニーズに合わせた柔軟なアクセス制御が可能になります。

この機能強化により、次の 2 つの方法でダッシュボードを作成できます。

- **Private ダッシュボード:** 機密データ、作成中のレポート、個人的な利用を想定して設計されています。デフォルトでは、これらのダッシュボードには所有者のみがアクセスでき、所有者は特定の個人に「View」または「Edit」アクセス権を付与できます。
- **Workspace ダッシュボード:** チーム全体での幅広い可視性と透明性を目的としています。ワークスペース内のすべてのメンバーには、デフォルトで「View」アクセス権が付与されます。ダッシュボードの所有者は、ワークスペース内の全員または特定のメンバーに編集権限を付与できます。

詳細については、[カスタムダッシュボード](/ja/user-guide/analyze/dashboards/custom-dashboards) を参照してください。

# Merlin AI Segment Assist

MoEngage は *Merlin AI Segment Assist* を導入しました。これは、高度にターゲティングされたオーディエンスセグメントの作成を簡素化する機能です。

自然言語のプロンプトを使用して目的のオーディエンスを定義できるようになり、Merlin AI がその説明を正確なセグメンテーションクエリに変換します。この進化により、イベントの分類体系の理解や複雑なフィルターの適用に伴う学習コストが削減され、より効率的にセグメントを構築して活用できます。

詳細については、[Merlin AI Segment Assist](/ja/user-guide/ai-and-intelligence/merlin-ai/merlin-ai-segment-assist) を参照してください。
