# Landing Pages の導入

ランディングページは、特定のキャンペーンやオーディエンス向けに設計された専用の Web ページです。閲覧を促す通常の Web ページとは異なり、これらのページは、購入の促進、リードの獲得、イベントへの登録など、1つの明確な目標に焦点を当てています。

詳細については、[Landing Pages](/ja/user-guide/content/landing-pages/create/create-a-landing-page)を参照してください。

# In-App キャンペーン向けのフォーム要素

*フォーム要素*機能を使用すると、リードの獲得、フィードバックの収集、ユーザーエンゲージメントの向上、アンケートの実施が可能です。ドラッグ&ドロップエディターを使用して、カスタマイズ可能なフォームを追加できます。テキスト、メール、日付などのフィールドをカスタマイズし、フォームの入力内容に基づいてユーザープロパティを更新できます。

この機能は In-App キャンペーンと On-site Messaging(OSM)キャンペーンで利用でき、SDK の更新は不要です。

詳細については、[In-App キャンペーンへのフォームの追加](/ja/user-guide/campaigns-and-channels/in-app-message/templates/drag-and-drop-editor/add-forms-to-your-in-app-campaign)および[フォーム入力](/ja/user-guide/campaigns-and-channels/in-app-message/analyze/analyze-in-app-campaigns#form-inputs)を参照してください。

# Behavior Analytics のカスタムアラートの改善

異常トレンドの画像がメールアラートに含まれるようになりました。アラート条件がトリガーされると、インタラクティブなトレンドの可視化をメールで直接受け取れるようになりました。

MoEngage は、アラート管理を簡素化する新しいアップデートも導入します。Alert management ページの **Analytics alerts** タブでアラート名をクリックすると、すべてのカスタムアラート条件としきい値にアクセスできるようになりました。

詳細については、[Analytics のアラート](/ja/user-guide/analyze/analytics/alerts-in-analytics)を参照してください。

# Reachability ダッシュボードの更新

MoEngage は、Reachability ダッシュボードに **iOS Reachability Trend** チャートと **Web Reachability Trend** チャートを導入しました。

これらのチャートを使用すると、Android に加えて、iOS および Web プラットフォームのユーザーのリーチャビリティ指標も追跡できるようになりました。

詳細については、次の記事を参照してください。

- [iOS のプッシュ許可とリーチャビリティ](/ja/user-guide/campaigns-and-channels/mobile-push/notification-features-and-behavior/ios-push-permission-and-reachability)
- [Web プッシュの許可とリーチャビリティ](/ja/user-guide/campaigns-and-channels/web-push/getting-started-with-web-push/web-push-permission-and-reachability)

# Data Management アラートの導入

MoEngage は、*Data Management アラート*を導入しました。これは、データ属性の使用状況、取り込まれたイベント量、追跡されたユーザー量に関連する特定の条件がトリガーされたときに、マーケターに通知するアラートです。これらは、MoEngage ワークスペースのデータ管理ダッシュボードと Alert management ページで利用できます。この機能は、次のユースケースに対応します。

- ワークスペースのデータトラッキングポリシーに準拠するため、イベント属性とユーザー属性の使用状況をプロアクティブに監視します。使用状況アラートを設定すると、イベント属性とユーザー属性の使用状況に基づいて通知されます。
- イベント量アラートを設定して、MoEngage とのデータ統合の構成を検証し、データの取り込みを確認します。

詳細については、[Data Management アラート](/ja/user-guide/settings/data-management/data-management-alerts)を参照してください。

MoEngage では、SFTP サーバーへの接続方法として、**Password** と **SSH Key Authentication** の2つを提供するようになりました。詳細については、[新しい SFTP 接続の構成](https://partners.moengage.com/hc/en-us/articles/26763225201172-SFTP#integration-0-1)を参照してください。

# キャンペーンプレビューの PII マスキング

*PII マスキング*機能は、キャンペーンプレビューで個人を特定できる情報(PII)のフィールドをマスキングすることで、組織が機密情報を保護できるよう支援します。これにより、プライバシー基準への準拠が確保され、ユーザー属性やイベント属性などの PII データがユーザーインターフェイス(UI)で露出するのを防ぎます。  
従来、PII マスキングはユーザープロファイルにのみ適用されていました。つまり、マスキングされた値はプロファイル内では非表示になりますが、パーソナライゼーションコンテンツでは引き続きアクセス可能でした。そのため、マスキングされた一部の値がユーザーインターフェイスにプレーンテキストで表示され、プライバシーが損なわれる可能性がありました。  
  
この機能により、次のことが可能になります。

- 顧客データのプライバシーを損なうことなく、コンテンツを検証し、パーソナライゼーションをテストできます。
- データ管理または Content API で指定された PII フィールドはマスキングされ(「XXXX」と表示)、PII 以外のフィールドは表示されたままになります。
- 不正な PII の露出を防ぐことで、キャンペーンテスト中のデータセキュリティを強化できます。

詳細については、次の記事を参照してください。

- [パーソナライズされたプレビューでの PII マスキング](/ja/user-guide/data/privacy/personal-data-or-personally-identifiable-information-pii/pii-masking-on-personalised-preview)
- [Content API](/ja/user-guide/campaigns-and-channels/getting-started/campaign-content/content-apis#step-1-configure-the-example-content-api)

# Integration Validation

*Integration Validation* 機能は、機能の実装を検証するためのダッシュボードインターフェイスを提供することで、MoEngage Android SDK の統合を簡素化します。

この機能により、開発者とマーケターは SDK の実装を独自にテストおよび検証でき、正確性を確保しながらサポートチームへの依存を減らすことができます。エラーを最小限に抑え、統合プロセスを効率化することで、シームレスなマーケティングコミュニケーションが可能になり、ユーザーエンゲージメントが向上します。

Integration Validation では、次のことができます。

- ダッシュボードから Android SDK の機能を直接テストできます。
- プッシュ通知に必要な重要な設定の欠落など、構成の問題を特定して解決できます。
- 実装の正確性を高め、より良い成果を得られます。

詳細については、[Integration Validation](/ja/user-guide/getting-started/integration-validation/android-native-integration-validation)を参照してください。

# iOS プッシュ通知の配信優先度

*iOS Push Notification Delivery Priority* 機能を使用すると、通知の配信設定を指定できます。この機能は、さまざまなネットワークや電力の制約下で通知の配信を最適化するのに役立ちます。

詳細については、MoEngage の[プッシュキャンペーンの作成](/ja/user-guide/campaigns-and-channels/mobile-push/create/create-push-campaigns)を参照してください。

# File Import Status API の導入

MoEngage は、インポートレベルとファイルレベルの両方で処理ステータスを取得する File Import Status API を導入しました。これにより、MoEngage ダッシュボードに移動することなく、インポートおよびインポート内のファイルのステータスをプロアクティブに追跡できます。

詳細については、[File Import Status](https://www.moengage.com/docs/api/file-import/import-details)を参照してください。
