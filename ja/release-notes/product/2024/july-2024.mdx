# Campaign API の導入

MoEngage は Campaign API を導入しました。Campaign API では、次のことができます。

- [キャンペーンの作成](https://www.moengage.com/docs/api/create-campaigns/create-campaign)(ワンタイム、定期、イベントトリガー、ビジネスイベントトリガー)
- [キャンペーンの更新](/ja/api/update-campaigns/update-campaign-v1-—-legacy)
- [キャンペーンの詳細の取得](https://www.moengage.com/docs/api/get-campaign-details/search-campaigns)(複数のフィルターを使用したキャンペーンの検索)
- [キャンペーンのステータスの変更](https://www.moengage.com/docs/api/update-campaigns/change-campaign-status)(キャンペーンのステータスの更新)
- [定期キャンペーンまたはトリガーキャンペーンのすべての子キャンペーンの取得](https://www.moengage.com/docs/api/get-campaign-details/get-child-campaigns)
- [キャンペーンのテスト](https://www.moengage.com/docs/api/test-campaigns/test-campaign)

現時点では、これはメールチャネルでのみサポートされています。詳細については、[Campaign API](https://www.moengage.com/docs/api/campaigns/campaigns-overview)を参照してください。

# My Studio の導入

MoEngage は、分析用フォルダーである My Studio を導入しました。

My Studio は安全で、本人のみがアクセスでき、クエリを保存できます。分析内容を手軽に保存し、ワンクリックでクエリを呼び出せるようになりました。

詳細については、[My Studio](/ja/user-guide/analyze/dashboards/my-studio)を参照してください。

# On-Site Messages のロケール

1つのキャンペーン内で、ロケールを使用して、さまざまな言語、地域、デバイスなどのオーディエンスをターゲットにできるようになりました。複雑な回避策や手間はもう必要ありません。

## 仕組み

カスタマイズされたメッセージを送信するには、API 呼び出しに目的のロケールを含めます。ユーザープロファイルを活用して、ロケールをインテリジェントに選択することもできます。

詳細については、[On-site Messages でのロケールの使用](/ja/user-guide/campaigns-and-channels/on-site-message/create/using-locales-in-on-site-messages)を参照してください。

# TV 向けの Cards

Self-handled Card キャンペーンを作成するプラットフォームとして、TV を選択できるようになりました。詳細については、[Card キャンペーンの作成](/ja/user-guide/campaigns-and-channels/cards/create/create-a-card-campaign)および[TV および OTT の統合](https://www.moengage.com/docs/developer-guide/tv-and-ott-integrations/getting-started/tv-and-ott-integrations)を参照してください。

<Note>
TV を Android、iOS、Web と一緒にプラットフォームとして選択することはできません。続行するには、TV のみを選択する必要があります。
</Note>

# イベントの命名規則

MoEngage は、アプリケーションでイベントを作成する際の推奨キーワード、ベストプラクティス、命名規則について、信頼できる唯一の情報源を提供します。

詳細については、[イベントの命名規則](/ja/user-guide/data/key-concepts/event-naming-conventions)を参照してください。

# メールのカスタムドメイン

MoEngage では、メッセージに標準の MoEngage ドメインではなく、カスタムドメインを構成できるようになりました。この機能により、SMS、WhatsApp、またはメールのメッセージ本文で送信される URL に、独自のカスタムドメインを使用できます。

詳細については、[カスタムドメインの構成](/ja/user-guide/settings/advanced-settings/configure-custom-domain-link-branding)を参照してください。

# メール設定の刷新

MoEngage は、MoEngage ダッシュボードのメール設定 UI を刷新しました。刷新された UI は、**Settings** \>  **Channels** \> **Email** で確認できます。

詳細については、[メールチャネルの構成](/ja/user-guide/campaigns-and-channels/email/getting-started-with-email/configure-email-channel)を参照してください。

# Alert Manager の強化

MoEngage は、顧客プランごとの Alert Manager の位置付けを変更しました。

- **Growth** プランの顧客は、MoEngage が標準で作成するシステムアラートのみを利用できます。システムアラートとは、基本的に MoEngage がクライアントにプロアクティブに送信したい情報のことです。
- **Enterprise** プランの顧客は、システムアラートとカスタムアラートの両方を利用できます。これらの顧客は、ビジネス上のしきい値に基づいてアラートを設定し、異常を監視できます。

Alert Management ダッシュボードの主な UI の変更点は次のとおりです。

- **Delivery channel** -\> **Send Alert On**
- **Alert type** -\> **Create Alerts On**
- **Alert the user when** -\> **Send alert when**

詳細については、[Alert Management](/ja/user-guide/settings/reports-and-alerts/alert-management/getting-started/overview-alert-management)および[アラートの作成](/ja/user-guide/settings/reports-and-alerts/alert-management/getting-started/create-an-alert)を参照してください。
