# WhatsApp テンプレート

WhatsApp テンプレートを使用すると、企業は事前定義されたパーソナライズされたメッセージを作成でき、コミュニケーションを効率化できます。MoEngage を使用して、事前承認済みまたはホワイトリストに登録されたテンプレートを使用した WhatsApp メッセージを、直接または WhatsApp サービスプロバイダー(BSP)経由で送信できるようになりました。この機能により、自動通知が可能になり、WhatsApp での顧客エンゲージメントが向上し、ブランドの信頼性が高まるため、ビジネスの効率が向上します。

WhatsApp テンプレートでは、次のことができます。

- 自動メッセージングによる顧客エンゲージメントの向上
- イベント、リマインダー、更新の通知の効率化
- 一貫性とスピードのための事前定義メッセージの活用

詳細については、[WhatsApp テンプレート](/ja/user-guide/campaigns-and-channels/whatsapp/getting-started-with-whatsapp/whatsapp-templates)を参照してください。

# iOS および Web のプッシュ許可とリーチャビリティの機能強化

iOS のプッシュ許可とリーチャビリティに、次の機能強化が加えられました。

- **仮のプッシュ通知の導入**: 通知をサイレントで送信でき、ユーザーは完全なプッシュ許可を付与するかどうかを決める前に、プッシュ通知の価値を体験できます。
- **オプトインステータスを含むようにリーチャビリティを変更**: *Reachability Push iOS* ユーザー属性が更新され、ユーザーのデバイスのオプトインステータスが反映されるようになりました。次の値を取ります。  
  - 201 - Reachable and opted in
  - 202 - Not reachable due to opt-out
  - 200 - Reachable an opt-in status unknown
- **ユーザーのオプトインステータスが変更されたときのイベントの変更**:  *Push Preference Changed iOS* イベントが廃止されるため、この動作は今後、イベント属性 *Platform = iOS* を持つ *Subscribed to Push* イベントおよび *Unsubscribed to Push* イベントによって追跡されます。  
  この変更は、2024年9月9日以降に SDK をアップグレードした iOS デバイス、および2024年10月1日以降にリリースされた Flutter SDK と React Native SDK に適用されます。

Web のプッシュ許可とリーチャビリティに、次の機能強化が加えられました。

- **オプトインステータスを含むようにリーチャビリティを変更**: *Reachability Push Web* ユーザー属性が更新され、ユーザーのデバイスのオプトインステータスが反映されるようになりました。次の値を取ります。  
  - 201 - Reachable and opted in
  - 202 - Not reachable due to opt-out
- **ユーザーのオプトインステータスが変更されたときのイベントの変更**:
  - *Subscribed to Web Push* イベントが廃止されるため、この動作は今後、イベント属性 *Platform = Web* を持つ *Subscribed to Push* イベントによって追跡されます。
  - *Unsubscribed to Web push* イベントが廃止されるため、この動作は今後、イベント属性 *Platform = Web* を持つ *Unsubscribed to Push* イベントによって追跡されます。

詳細については、[iOS のプッシュ許可とリーチャビリティ](/ja/user-guide/campaigns-and-channels/mobile-push/notification-features-and-behavior/ios-push-permission-and-reachability)および[Web プッシュの許可とリーチャビリティ](/ja/user-guide/campaigns-and-channels/web-push/getting-started-with-web-push/web-push-permission-and-reachability)を参照してください。

# In-App メッセージングのクリック分析の強化

今回のリリース以前は、ウィジェットのクリックを追跡するのは面倒なプロセスでした。セグメンテーションセクションに移動し、キャンペーン ID とウィジェット ID を使用して詳細なクエリを作成してから、セグメントを抽出してダウンロードするか、キャンペーンを作成する必要がありました。ユーザー行動分析やファネルの作成にも同じプロセスが必要で、ウィジェット ID を見つけるのが難しいこともよくありました。

この機能強化により、これらすべてのタスクをキャンペーン情報ページの **Click analysis** タブ内で直接処理できるようになりました。

# Analytics のテーブルでの並べ替え

以前は、カスタムの並べ替えを行うために外部ツールにデータをダウンロードする必要があり、手順が増えてワークフローが遅れていました。新しいプラットフォーム内の並べ替え機能により、この煩雑さが解消されます。  
並べ替え機能を使用すると、複数の列にわたってデータを昇順または降順で簡単に並べ替えることができます。

並べ替えは次の場所で利用できます。

- さまざまな分析カテゴリ: User、Behavior、Funnel、Session、Source のテーブル
- テーブルビューのカスタムダッシュボード

詳細については、[Analyze](/ja/user-guide/analyze/analytics/behavior/behavior-overview)を参照してください。

# OSM でのカスタムイベントの遅延

カスタムイベントの直後に On-site Messaging(OSM)をレンダリングする代わりに、配信に遅延を追加できるようになりました。この機能は、タイミングが重要でありながら即時のメッセージングが理想的でない場合に役立ちます。たとえば、ユーザーがフォームの送信(カスタムイベント)を完了したとき、OSM は数秒待ってからメッセージを表示できるため、ユーザーはワークフローを快適に完了できます。

この機能により、よりスムーズで妨げの少ないユーザーエクスペリエンスが実現し、エンドユーザーは中断されることなく現在のタスクを完了する時間を確保できます。

詳細については、[OSM Pro キャンペーンの作成](/ja/user-guide/campaigns-and-channels/on-site-message/create/create-osm-campaign)を参照してください。

# 30日を超えるユーザーアクティビティ

MoEngage では、アカウントのデータ保持期間全体にわたって、User Profile にユーザーアクティビティが表示されるようになりました。Activity Info には、過去30日または60日間(プランとデータセンターに基づく)にユーザーが実行したすべてのイベントとイベント属性が、イベントの実行時間順に表示されます。これにより、ユーザーのアクション履歴を明確に把握できます。

**Event Filters** セクションの期間に、アカウントのデータ保持期間までの日付が表示されるようになりました。過去30日を超えるイベントについては、最大7日間の期間を選択し、ユーザーについて確認したいイベントと属性を選択して、**Apply** をクリックすると結果が表示されます。

詳細については、[User Profile](/ja/user-guide/data/user-data/user-profile)を参照してください。
