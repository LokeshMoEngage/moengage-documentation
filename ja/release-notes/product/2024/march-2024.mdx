# インバウンドチャネル

## ドラッグ&ドロップエディター

MoEngage は、まったく新しいドラッグ&ドロップエディターを導入しました。フォントから画像、GIF まで、In-App キャンペーンのあらゆる要素をカスタマイズできます。MoEngage では、事前に用意されたテンプレートをカスタマイズして使用することも、新しいキャンペーンを一から作成することもできます。

## In-Session 属性

MoEngage では、OSM キャンペーンに In-Session 属性を追加できるようになりました。In-Session 属性を使用すると、Web サイト上でのユーザーのアクションに基づいてユーザーをグループ化し、ターゲットにできます。各ユーザーの現在のセッションに関連するキャンペーンを、その場で作成できます。

たとえば、ユーザーがインドにいる場合、インド在住のユーザー向けに作成したパーソナライズされたポップアップを表示できます。これにより、同じセッション内で即座にパーソナライズされたエクスペリエンスを提供できます。

詳細については、[In-Session 属性](/ja/user-guide/campaigns-and-channels/on-site-message/create/create-osm-campaign#in-session-attributes)を参照してください。

## マルチイベントトリガー

MoEngage では、OSM キャンペーンと In-App キャンペーンで、論理演算子を使用して複数のイベントを組み合わせられるようになりました。**Filters** ボタンが追加されたことで、_AND_ 演算子を使用して複数のイベントを組み合わせ、キャンペーンをトリガーできるようになりました。

たとえば、_In-app Clicked Android_ イベントを選択し、_AND_ 演算子を使用して _Added to Cart_ イベントを追加できます。これにより、In-App キャンペーンは、Android デバイスで In-App キャンペーンを少なくとも1回クリックし、その後カートにアイテムを少なくとも1回追加したユーザーにのみ表示されます。

詳細については、[トリガー条件](/ja/user-guide/campaigns-and-channels/in-app-message/create/create-in-app-campaign#trigger-criteria)を参照してください。

## リーチャビリティとオプトイントラッキングの変更

MoEngage は、リーチャビリティのトラッキングと、プッシュ通知を送信するための許可のトラッキングを改善しました。

### 変更内容

- リーチャビリティ
  - _Reachability Push iOS_ 属性を更新しました。この変更は、2024年4月17日以降にアップグレードされた新しい iOS SDK にのみ適用されます。古いデバイスは、アップグレードされるまで引き続き _200 - Reachable an opt-in status unknown_ のままとなります。
  - _Reachability Push Web_ 属性を更新しました。この変更はすべての Web デバイスに適用されます。_200 - Reachable an opt-in status unknown_ のデバイスは、2024年4月17日以降、代わりに _201 - Reachable and opted in_ と表示されます。
- プッシュ許可の変更のトラッキング
  - iOS
    - _Push Preference Changed iOS_ イベントを廃止しました。代わりに、この動作はイベント属性 Platform = "iOS" を持つ _Subscribed to Push_ および _Unsubscribed to Push_ によって追跡されます。
    - この変更は、2024年4月17日以降に SDK をアップグレードした iOS デバイスにのみ適用されます。
  - Web
    - _Subscribed to Web Push_ イベントを廃止しました。代わりに、この動作はイベント属性 Platform="Web" を持つ _Subscribed to Push_ によって追跡されます。
    - _Unsubscribed to Web push_ イベントを廃止しました。代わりに、この動作はイベント属性 Platform="Web" を持つ _Unsubscribed to Push_ によって追跡されます。
  - Android
    - _Subscribed to Push_ および _Unsubscribed to Push_ イベントは、Android デバイスでも標準イベントとして追跡されます。

### これらの変更によるメリット

今回のリリースにより、次のことが可能になります。

- プッシュ許可の変更の追跡
  - Android - Android デバイスのプッシュ許可の変更を追跡できます。
  - iOS および Web - トラッキングイベントの動作がすべてのプラットフォームで共通になり、これらのイベントの追跡方法が改善されました。
- プラットフォームごとのオプトイン内訳の取得
  - _Reachability Push iOS_ と _Reachability push web_ から、オプトインしたユーザーとオプトアウトしたユーザーの比率を確認できます。
- オプトインしたユーザーのみへの送信
  - iOS では、デバイスでプッシュ許可を承認したデバイスのみがプッシュ通知の対象となり、配信ファネルの精度が向上しました。

### 現在のキャンペーンへの影響

- Android - プッシュ通知の送信に変更はありません。
- iOS - ユーザーがオプトイン/オプトアウトとして追跡され始めると、時間の経過とともに全体の送信数が減少する場合があります。ただし、全体の配信数とインタラクションには影響はありません。
- Web - プッシュ通知の送信に変更はありません。
- ダッシュボードイベントの変更
  - 上記の変更で説明したイベントや属性を使用している場合、キャンペーンのセグメンテーションが影響を受ける可能性があります。今後のキャンペーン作成にこれらの変更を反映し、実行中の長期キャンペーンがあれば更新してください。
  - 上記のイベントや属性をセグメンテーション条件、トリガー条件、コンバージョン目標、またはパーソナライゼーション属性として使用しているすべてのアクティブなキャンペーンのリストを以下に示します。21のアカウントがこれらのイベントや属性をアクティブに使用していることが確認されています。影響を受ける顧客に確実に通知されるよう、関連するアカウントマネージャーをタグ付けしてください。

これらの変更は、2024年4月17日にすべての顧客に対して有効になります。iOS の場合、これらの変更は2024年4月17日以降に更新された新しい SDK バージョンのデバイスにのみ適用されます。

# アウトバウンドチャネル

## Template Groups の導入

### 既存の動作

顧客は、複数のロケールと複数のバリアントを持つメールキャンペーンを実行することがあります。これらのロケールとバリアントごとにカスタムテンプレートを個別にインポートすることはできますが、非常に手間と時間がかかり、エラーも発生しやすくなります。たとえば、20のロケールでそれぞれ2つのバリアントを持つキャンペーンを実行する場合、40の組み合わせのコンテンツを手動で追加する必要があります。これら40の組み合わせは、伝えるべきメッセージが同じであるため、互いに関連しています。このようなテンプレートは、まとめて作成され、まとめてキャンペーンで公開されるのが一般的です。

これまで、MoEngage に保存されたテンプレートには、ロケールやバリアントをテンプレートや他のテンプレートに関連付ける手段がありませんでした。また、メールテンプレート API(V2)にも、顧客がこの情報を MoEngage に送信する仕組みはありませんでした。

### 新しい動作

今回のリリースで、MoEngage は Template Groups を導入しました。Create Email Template API で `locale`、`variant`、`group_id` パラメータを渡すことで、テンプレートグループを作成できます。詳細については、[Create Email Template API](https://www.moengage.com/docs/api/email-templates/create-email-template-v2)を参照してください。

メールキャンペーンの作成時に、この機能を使用してテンプレートグループを MoEngage エコシステムにインポートし、マッピングされたテンプレートをまとめてレンダリングできます。Template Groups 機能を使用すると、すべてのロケールとバリアントの組み合わせに対してテンプレートを手動で追加する必要がないため、時間を節約できます。上記の40の組み合わせの例では、ワンクリックで関連するすべてのコンテンツを入力できます。詳細については、[メールコンテンツでのテンプレートグループのインポートと使用](/ja/user-guide/campaigns-and-channels/email/create/import-and-use-template-groups-in-email-content)を参照してください。

## メールキャンペーン向け Domain Reputation の導入

ドメインレピュテーションとは、インターネットサービスプロバイダー(ISP)やメールボックスプロバイダーから見たドメインの健全性のことです。これは、メールの到達率や受信トレイへの配置に影響を与える重要な要素です。

### 既存の動作

クライアントは、MoEngage ダッシュボード内でドメインの健全性を確認できませんでした。キャンペーンのパフォーマンスの低さがドメインレピュテーションの悪さに起因するかどうかを把握するには、Google Postmaster にログインしてドメインレピュテーションを確認するか、Email Deliverability Consultants(EDC)チームやカスタマーサポート(CS)チームに頼る必要がありました。

クライアントが低いレピュテーションのドメインでメールキャンペーンを実行し、キャンペーンのパフォーマンスに悪影響が出ることが多くありました。そのような場合、クライアントはキャンペーンのパフォーマンスが悪化した理由を知るために MoEngage に問い合わせていました。

### 新しい動作

MoEngage ダッシュボードで、ドメインレピュテーション情報を表示できるようになりました。この機能により、マーケターはメールキャンペーンのパフォーマンスをより深く理解し、EDC チームや CS チームへの依存を減らすことができます。詳細については、[Domain Reputation](/ja/user-guide/campaigns-and-channels/email/deliverability/domain-reputation/domain-reputation-in-moengage)を参照してください。

MoEngage ダッシュボードでは、検証済みのすべてのドメインについて、次の場所でドメインレピュテーションが表示されます。

- メール設定で「from email address」を追加するとき
- メールキャンペーンの作成中に「from email address」を選択するとき
- メールキャンペーンの All campaigns ページ
- キャンペーンのパフォーマンスとドメインレピュテーションを関連付けるための Campaign Analytics ページ

# Analytics

## User Analysis

MoEngage は、高度な分析手法である User Analysis を導入しました。ユーザー属性を分析することで、ユーザーの好みを包括的に理解し、その好みに基づいたターゲットキャンペーンを実行できます。

User Analysis で提供される分析タイプ:

- Total Count Analysis
- Unique Count Analysis
- Distribution Analysis
- Aggregation Analysis
- Email Domain Analysis

### Actionable Analytics

個別のチャート要素に基づいてセグメントを作成し、分析できます。たとえば、棒グラフの棒をクリックしてセグメントを作成できます。

Actionable Analytics でサポートされるアクションは、Segment Creation、Campaign Creation、Analysing Segment です。

### マップベースの分析

MoEngage は今回のリリースでコロプレスマップも導入し、初めてマップベースの分析を提供します。

詳細については、[User Analysis](/ja/user-guide/analyze/analytics/user-paths/user-path-analysis)を参照してください。

今回のリリースで、MoEngage はレコメンデーション結果をカスタマイズできるユーザーアクションフィルターを導入しました。この機能により、マーケターは選択したレコメンデーションモデルの結果にフィルター条件を適用できます。

# セグメンテーション

## 値の候補の機能強化

今回のリリースでは、値の候補のドロップダウンメニューに次の機能強化を行いました。

- **ドロップダウンメニューで選択できる値の上限を引き上げ**: 従来、ドロップダウンメニューでは300個の値を選択できました。今後は1000個の値を選択できます。
- **効率の向上**: 以前は、「in the following」条件を使用してドロップダウンからすべての値を選択した場合、値を1つずつ手動で選択解除する必要がありました。300個の値をすべて選択した後、それらすべてを手動で選択解除したり、ページを更新したりするのは困難でした。そこで、**Select All** ボタンと **Clear All** ボタンを導入します。
- **機能の拡張**: カンマ区切りの値を簡単に入力・選択できるよう、新しい **Freeform** カテゴリを導入します。これにより、ドロップダウンメニューの既存の **Newly Created** カテゴリに加えて **Freeform** カテゴリでも新しい値を作成・選択できるようになり、機能が2倍になりました。
- **重大なバグの修正**:
  - PII がマスキングされた属性に対して値の候補が提示されていました。
  - 値の部分一致により、検索ボックスに検索する値を貼り付けると、より多くの値が選択されていました。

詳細については、[値の候補](/ja/user-guide/segment/advanced-concepts/value-suggestions)を参照してください。

# Custom Connectors

## OAuth 2.0 による認可の構成

### 顧客の課題

- OAuth 2.0 を必要とする外部パートナーとのコネクタキャンペーンを実行できませんでした。
- クライアントのシステムが自社の認可サービスのいずれかから提供されたアクセストークンのみを受け入れる、クライアント固有の社内ユースケースでキャンペーンを実行できませんでした。

### 新機能

今回のリリースで、MoEngage では、アクセストークンを取得・更新する OAuth 2.0 認証サービスを構成できるようになりました。また、更新設定に基づき、アクセストークンの有効期限が切れる前にアクセストークンを更新するように構成することもできます。詳細については、[OAuth 2.0 による認可の構成](/ja/user-guide/settings/advanced-settings/authorization-configuration-with-oauth-20)を参照してください。

マーケターは、カスタムコネクタキャンペーンの作成時(ステップ2の Content)に、認証として OAuth 2.0 を使用できます。詳細については、[コネクタキャンペーンの作成](/ja/user-guide/campaigns-and-channels/connectors/create/create-a-connector-campaign)を参照してください。
