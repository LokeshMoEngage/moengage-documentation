# Object データ型

MoEngage では、文字列、数値、ブール値などの既存のデータ型の属性に加えて、Object データ型を使用してより詳細なクエリを実行し、カスタムユーザーセグメントを作成して、よりパーソナライズされたマーケティングキャンペーンを実施できます。

マーケターとして、ユーザーがカートに追加した特定のアイテムに基づいてユーザーをセグメント化したい場合があります。指定したアイテムを定義する属性が数多く存在する場合、それらを1つの Object にまとめてアイテムの識別に使用できます。たとえば、書籍「Atonement」をカートに追加したユーザーのリストを記録したいとします。この書籍は、次の Object を使用して定義できます。

<CodeGroup>

```json Sample Code
"book":{
"product_name" : "Atonement"
"price" : 100,
"sku" : "abc123"
}
```

</CodeGroup>

詳細については、[Object データ型のサポート](/ja/user-guide/data/key-concepts/support-for-object-data-type)および[セグメンテーションでの Object データ型](/ja/user-guide/segment/advanced-concepts/object-data-type-in-segmentation)を参照してください。

アプリケーションでこの機能を有効にするには、MoEngage のカスタマーサクセスマネージャーにお問い合わせください。

# Identity Resolution

_Identity Resolution_ 機能を使用すると、ブランドはさまざまなデータソースから取得した同一ユーザーの複数のプロファイルを統合できます。さまざまなソースに顧客 ID、メールアドレス、電話番号などの明確な ID 情報が含まれている場合、それらを組み合わせて統合された顧客プロファイルを構築できます。これにより、各ユーザーについて信頼できる唯一の情報源が維持され、アプリケーション上でのユーザーの行動をシームレスに追跡し、それに応じてビジネス戦略を調整できます。

詳細については、[ユーザー ID 管理](/ja/user-guide/data/user-data/unified-identity-identity-resolution)を参照してください。

# キャンペーンの移行

キャンペーンの移行により、よりスムーズで効率的なワークフローが実現し、ユーザーは戦略的な優先事項により多くの時間を充てられます。ワークスペース間でのキャンペーンの移動は、時間がかかる手作業であり、エラーが発生する可能性も高いものでした。この機能により、ワンクリックでキャンペーンを転送できるようになり、正確性が確保され、手作業が不要になります。

この機能は、移行プロセスを自動化することで本番キャンペーンの所要時間を短縮し、エラーの可能性を大幅に低減します。不足している要素を強調表示することでキャンペーンの送信失敗を最小限に抑え、ユーザーがより重要なタスクに集中できるようにします。

この機能では、次のことができます。

- あるワークスペースから別のワークスペースに複数のキャンペーンをコピーし、下書きとして保存できます。
- 同じデータクラスター(DC)内で、あるワークスペースから別のワークスペースにキャンペーンを移行できます。
- セグメンテーション属性、タグ、またはパーソナライゼーション属性(Content API、Content Block など)が不足している場合に、エラーメッセージを受け取れます。
- 下書きの新しい Imported 状態から、移行したキャンペーンに簡単にアクセスできます。
- Draft と Archived を除く任意のステータスのキャンペーンをインポートできます。

詳細については、[キャンペーンの移行](/ja/user-guide/campaigns-and-channels/campaign-management-and-reports/campaign-migration)を参照してください。

# Behavior Analytics のカスタムアラート

カスタムアラートを使用すると、導入のトレンドを監視したり、キャンペーンのパフォーマンスが円滑であることを確認したりできます。主要なイベントと属性にカスタムのしきい値を定義して、最も重要な指標を監視できます。トレンドがそれらのしきい値を超えると、メールでアラートを受け取れます。また、ユーザー登録の急増やエンゲージメントの低下についてチームに情報を共有することもできます。

**アラートはどこで設定できますか?**

Behavior Analysis の折れ線グラフ、棒グラフ、縦棒グラフでアラートを設定できます。

**サポートされているカスタムしきい値は何ですか?**

- 指標値を上回る、または下回る。
- 前の期間と比較して、指標値が % 単位で増加または減少する。
- 前の期間と比較して、指標値が # 単位で増加または減少する。

**アラートの頻度は?**

- 毎日、毎週、毎月。

詳細については、[Analytics のアラート](/ja/user-guide/analyze/analytics/alerts-in-analytics)を参照してください。

# カスタム属性を使用した Web ページのパーソナライズ

一連の手順や URL フィルター条件を経ることなく、適切な Web ページグループをターゲットにできるようになりました。カスタム属性を活用して、ユーザーが閲覧する Web ページの種類に基づいてユーザーエクスペリエンスを調整し、Web ページのデータを使用して個別のエクスペリエンスを提供できます。

カスタム属性で実現できるユースケースの例を以下に示します。

- ページタイプのターゲティングは、特定の商品ページを閲覧している顧客に特定のファッションアイテムを売り込みたいファッション小売業者に役立ちます。たとえば、ハンドバッグの商品ページを頻繁に訪れる顧客は、ハンドバッグのパーソナライズされたレコメンデーションを受け取ります。
- ページタイプのターゲティングにより、旅行代理店は顧客の閲覧習慣に合わせてコンテンツを調整できます。たとえば、顧客が家族旅行のパッケージを検索すると、子ども向けの追加特典や、家族旅行向けにカスタマイズされた旅行のアドバイスを受け取れます。
- オンライン書店は、顧客が訪れたジャンルや著者のページに基づいて、パーソナライズされた提案を提供できます。たとえば、ミステリーをテーマにした書籍を閲覧している顧客には、同じカテゴリの人気タイトルの提案が表示されます。

カスタム属性を設定するには、[カスタム属性](https://www.moengage.com/docs/developer-guide/personalize-sdk/sdk-integration/custom-attributes)を参照してください。

カスタム属性の使用方法については、[エクスペリエンスの作成](/ja/user-guide/personalize/client-side-personalization/client-side-personalization/create-client-side-personalization-experience)を参照してください。

# Cards のバナーカルーセル

MoEngage では、Android および iOS のネイティブアプリでバナーカルーセルを構築し、これらのバナーカルーセルを通じてアプリの訪問者に Self-Handled Cards を作成して配信できます。

詳細については、[アプリのホームページにカルーセルバナーを追加する方法](/ja/use-cases/cards/how-to-add-carousel-banners-on-app-home-page)を参照してください。
