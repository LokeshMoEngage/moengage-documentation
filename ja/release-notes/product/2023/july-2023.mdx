# Analytics の機能強化

1. Analytics のフィルターで、イベント属性に対する Geo point 演算子と Date time 演算子がサポートされるようになり、カスタムダッシュボードでチャート名を編集できるようになりました。
2. 古い指標とアクティブな指標を区別するため、すべてのアクティブな指標が点線で結ばれるようになりました。
3. すべての分析クエリが Athena 3 で実行されるようになりました。

# アウトバウンドチャネル

## グローバル配信制御設定

フリークエンシーキャップ (クロスチャネルおよびチャネル固有)、Do Not Disturb (DND)、キャンペーン間の最小遅延、スロットリングなど、すべての配信制御を 1 か所で設定できます。詳細については、[フリークエンシーキャップ](/ja/user-guide/settings/channels/delivery-controls/frequency-capping)、[DND](/ja/user-guide/settings/channels/delivery-controls/do-not-disturb)、[最小遅延](/ja/user-guide/settings/channels/delivery-controls/minimum-delay-between-campaigns)、[スロットリング](/ja/user-guide/settings/channels/delivery-controls/throttling)を参照してください。

## Email Analytics と Info の刷新

Email チャネルのキャンペーン分析と Info の UI が刷新されました。詳細については、[Email Analytics and Info](/ja/user-guide/campaigns-and-channels/email/analyze/email-analytics-and-info) を参照してください。

# セグメンテーションの機能強化

## 値の候補

セグメンテーションフィルターの値の候補が強化されました。

1. 値の候補では、イベントについては T-1 日後、ユーザー属性については T-2 日後にデータが利用可能になります。
2. データの保持期間は、最新の受信時刻から 60 日間に拡大されます。
3. 属性とデータ型の組み合わせごとに 5K 個の値がサポートされます。
4. サポートされるデータ型: STRING、DOUBLE、ARRAY\_STRING、ARRAY\_DOUBLE

## WhatsApp の到達可能性

セグメント化されたユーザー数と、実際に WhatsApp のコミュニケーションを受信するユーザー数は異なります。そのため、WhatsApp で到達可能なユーザー数を特定することは困難でした。この機能により、WhatsApp キャンペーンでターゲットにされたユーザーを特定できるようになりました。

## 監査ログ

カスタムセグメント、ファイルセグメント、ユーザーエクスポート、アウトバウンドセグメント同期で監査ログを利用できます。

# データ

API を介して行われた属性の更新と SDK を介して行われた属性の更新の間で競合が発生するため、Device API は非推奨になりました。また、この API はリアルタイムではない場合があり、データの不一致が生じる可能性があります。ユーザーのデバイスデータをシームレスにトラッキングするには、MoEngage SDK の使用をお勧めします。SDK は Push または InApp キャンペーンの送信に不可欠であり、デバイス属性をトラッキングするための包括的なソリューションを提供します。詳細については、[開発者向けドキュメント](https://www.moengage.com/docs/developer-guide/introduction)の各 SDK の Data Tracking セクションを参照してください。
