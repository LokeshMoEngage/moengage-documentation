## Analytics Agent

Analytics Agent は、分析に関する質問にわかりやすい英語で回答し、実際の答えを返す Custom Agent です。どのモジュールや分析タイプを開けばよいかを知っている必要はありません。知りたいことを質問するだけで、適切な分析を選択して実行し、確認した内容、オーディエンスと期間、主要な数値、そこから示唆されることをわかりやすい言葉でまとめて返します。このエージェントは次のように動作します。

- **適切な分析に自動的にルーティング**: 質問内容に基づいて、Behaviour、Funnel、Retention、Session & Source、User Analysis の中から選択します。
- **人とアクションを区別**: 「アプリを開いたユーザー数」と「アプリが開かれた回数」を区別し、すべての回答でその違いを明示します。
- **リテンションのコホートテーブルを返す**: リテンションに関する質問には、要約とともに日ごとのコホートテーブル (Day 0、Day 1、Day 2 など) が返されます。
- **機密データで分割しない**: メールアドレスや電話番号で内訳を出すよう依頼された場合は、その旨を伝え、代わりに安全な代替案を提示します。
- **推測せずに質問する**: リクエストが 2 つの異なる意味に解釈できる場合は、黙ってどちらかを選ぶのではなく、確認のための質問を 1 つします。

このエージェントは 5 つの Analytics モジュールすべてに対応し、Custom Agent フレームワーク上に構築されています。DC-01 から DC-04 および DC-101 で利用可能です。使用するには、**AI Agents \> Create from Scratch \> Analytics Agent** に移動します。現在、エージェントはテーブルとわかりやすい言葉による要約で回答します。チャート形式での出力は今後予定されています。

詳細については、[Custom Agents: 概要](/ja/user-guide/ai-and-intelligence/merlin-ai/custom-agents/custom-agents-overview) を参照してください。

## Message Archival の PGP 暗号化

Message Archival で、Key Management Service (KMS) 暗号化の代替として Pretty Good Privacy (PGP) 暗号化がサポートされるようになり、お客様所有の Amazon S3 バケットと SFTP サーバーの両方に暗号化が拡張されました。PGP 暗号化では次のことが可能です。

- **独自のキーの使用**: PGP 公開キーを MoEngage と共有すると、アーカイブされるすべてのメッセージが書き出される前にそのキーで暗号化されます。AWS 管理の KMS キーに依存することはありません。
- **SFTP のサポート**: PGP は、SFTP サーバーにアーカイブされるメッセージに対して MoEngage がサポートする最初の暗号化オプションです。SFTP は KMS がこれまで対応していなかった送信先です。
- **お客様所有の S3 バケットのサポート**: PGP はお客様所有の S3 バケットにアーカイブされるメッセージにも使用でき、KMS と PGP のいずれかを選択できます。MoEngage 所有の S3 バケットへのアーカイブはサポートされていません。
- **透過的なファイル処理**: 新たにアーカイブされるファイルには PGP のファイル拡張子が付き、既存のファイルパスと命名規則は設定どおりに維持されます。
- **キーの有効期限切れへの耐性**: PGP キーの有効期限が切れた場合や、S3 または SFTP の送信先への接続が切断された場合、MoEngage はメッセージを内部の再試行キューに最大 30 日間保持し、有効なキーまたは接続が復元されると送出します。

PGP 暗号化は、Email、SMS、Push、RCS でアーカイブされるメッセージで利用できます。PGP を有効にすると、切り替え前にアーカイブされたメッセージを含むすべてのアーカイブ済みメッセージに対して、ダッシュボードの **View sent message** オプションが機能しなくなります。これは、MoEngage がコンテンツを復号して表示できなくなるためです。暗号化の種類は Message Archival のセットアップ時に選択され、その後セルフサービスで変更することはできません。既存のアカウントを PGP に切り替える場合や、新しい設定で PGP をセットアップする場合は、CSM または MoEngage サポートチームにお問い合わせください。

詳細については、[メッセージの暗号化](/ja/user-guide/campaigns-and-channels/campaign-management-and-reports/message-archival/message-archival#message-encryption) を参照してください。

## 定期キャンペーンとトリガー型キャンペーンのメッセージ数の制限

定義した期間内に個々のユーザーが特定の定期キャンペーンまたはイベントトリガー型キャンペーンを受信する回数の上限を、カスタム属性や手動の追跡ロジックを使用せずに、Delivery Controls から直接設定できるようになりました。このコントロールには次の特長があります。

- **ユーザーごとの送信上限の設定**: キャンペーンごとに「[Y] 日/週/月/年 あたり [X] 件以下のメッセージ」を設定できます。最大 1 年の期間で最大 100 件のメッセージまで設定できます。
- **真のスライディングウィンドウを使用**: 上限は、固定のカレンダーによるリセットではなく、ユーザーが最後に正常に受信した時点からの直近の期間に基づいて、送信を試みるたびに再計算されます。
- **Push と Cards はプラットフォームごとにカウント**: Android、iOS、Web はそれぞれ個別に追跡されるため、1 つのプラットフォームで上限に達しても、他のプラットフォームでの送信はブロックされません。
- **Frequency Capping と併用可能**: これは独立したコントロールです。有効にしても Frequency Capping の動作は変わらず、その逆も同様です。
- **稼働中でも安全に編集可能**: アクティブなキャンペーンの回数や期間はいつでも更新できます。これにより新しいキャンペーンバージョンが作成され、処理中のユーザーのカウントダウンは新しい頻度に合わせて調整されます。
- **除外されたユーザーのレポート**: 上限に達したために除外されたユーザーは、キャンペーンの Error Breakdown の Failed to Send の下に、個別のカテゴリとして表示されます。

このコントロールは、Push、SMS、WhatsApp、Email、Connectors の定期キャンペーンとイベントトリガー型キャンペーンをサポートしています。Cards は定期キャンペーンのみでサポートされています。新規キャンペーンと既存キャンペーンの両方で機能し、トランザクションキャンペーンや Flows には適用されません。このコントロールはデフォルトでオフになっています。キャンペーン作成フローの Step 3 で、**Delivery Control \> Limit messages per user** から有効にします。この機能は Enterprise 料金プランのお客様がご利用いただけます。

詳細については、[定期キャンペーンとトリガー型キャンペーンのメッセージ数の制限](/ja/user-guide/settings/channels/delivery-controls/limit-messages-for-periodic-and-triggered-campaigns) を参照してください。

## Segmentation Assistant Custom Agent

Segmentation Assistant は、わかりやすい英語のリクエストを正確で確認済みのセグメントに変換する Custom Agent です。各ステップで実際のワークスペースデータに基づいて推論し、お客様の承認なしには何も作成しません。このエージェントには次の特長があります。

- **クエリ言語ではなくマーケターの言葉で話す**: オーディエンスの条件、前提、次のステップを、わかりやすい英語で一覧しやすい概要として返します。
- **アフィニティと行動を理解**: 「主にドキュメンタリーを見る」や「Nike へのアフィニティ」などの好みを表す表現を、1 回限りのイベントではなく行動パターンとして認識します。
- **既存のセグメントを再利用・拡張**: 既存のセグメントへの言及を認識し、そのロジックを取り込んで、新しい条件を重ねます。
- **名前の重複を回避**: 提案するセグメント名を既存の名前と照合し、すでに使用されている場合はわかりやすい代替案を提案します。
- **大文字と小文字を区別せずに照合**: 実際の属性値を確認し、正確な大文字・小文字の表記が確認できない場合は、デフォルトですべてのバリエーションに一致させ、その前提を明示します。
- **現実世界の単位を変換**: 値がどのように保存されているかを確認し、時間から秒、ドルからセントなど、正しく変換します。
- **保持期間のリスクを警告**: 参照した過去の期間がワークスペースのデータ保持設定の範囲外になる可能性がある場合に警告します。
- **矛盾や空のセグメントを検出**: 条件が同時に成立し得ない場合や、全員に一致してしまう場合は、処理を止めて確認します。
- **代替指標を提案**: 完全に一致するフィールドが存在しない場合は、データ内で最も近い実際の代替を提案し、使用前に確認します。
- **確定前にプレビュー**: 何かを作成する前に、ロールに応じて PII をマスクした状態で、チャネルごとのリーチ可能なオーディエンスを表示します。

このエージェントは DC-01 から DC-04 で利用可能で、DC-101 は今後予定されています。

詳細については、[Custom Agents: 概要](/ja/user-guide/ai-and-intelligence/merlin-ai/custom-agents/custom-agents-overview) を参照してください。

## Email の Bot Management

Email の Bot Management が強化され、**Settings \> Bot Management \> Email** という独自の場所に移動しました。ボット検出の拡大に伴い他のチャネルにも拡張できるよう設計された、チャネルに依存しない設定画面として再配置されています。このリリースでは次の機能が追加されました。

- **ボットによるクリックの検出**: セキュリティスキャナーによって事前にクリックされたリンクなど、ボットによるクリックを検出してフィルタリングします。これは以前は不可能でした。
- **ワークスペースレベルの IP と User Agent の設定**: MoEngage が管理するデフォルトに加えて、オーディエンスや業界に合わせた独自の IP および User Agent のブロックリストを設定できます。
- **MoEngage が管理するデフォルト**: 既知のボットの IP 範囲と User Agent パターンの厳選されたリストが初日から自動的に適用されます。セットアップは不要です。

検出は多層的に行われ、Apple MPP による開封 (SendGrid と NetCore)、IP と User Agent の照合、そして今四半期後半に追加予定の行動ヒューリスティックが含まれます。どのレイヤーも、単独でイベントをボットとして分類できます。配信停止リクエストは、きっかけとなったクリックがボットとして分類された場合でも、デフォルトで受け付けられます。この動作は設定で変更できます。

レポートでは、調整済みの指標を合計指標と並べて表示するか、完全に置き換えるかを選択でき、この設定は開封とクリックに一律に適用されます。すべての開封イベントとクリックイベントには、フィルタリング、セグメンテーション、分析に使用できる **Is Machine Open**/**Is Machine Event** および **Machine Event Reason** 属性が付与されます。有効にすると、MoEngage のデフォルトルールが初日から有効になり、開封とクリックの指標は実際の人間によるインタラクションを表すようになるため、低下する可能性があります。

詳細については、[メールの開封とクリックのボット検出](/ja/user-guide/settings/channels/bot-detection-settings/bot-detection-for-email-opens-and-clicks) を参照してください。

## 刷新された Data API

Data API を支えるバックエンドが刷新され、すべてのデータセンターで一般提供 (GA) となりました。P99 の応答時間が短縮され、信頼性が向上しています。内部の改善に加えて、お客様に関わる次の変更点にご注意ください。

- **レート制限の処理**: Data API のエンドポイントはすべてのレスポンスでレート制限ヘッダーを返すため、統合側で 429 エラーを待つことなく、残りの容量をリアルタイムで追跡できます。
- **データ損失の分析の迅速化**: すべての API レスポンスに、成功レスポンスの場合でもリクエスト ID が含まれるようになりました。これを使用して、MoEngage の内部ログから関連するペイロードをフィルタリングできます。
- **リクエストに応じた Get User API へのアクセス**: 機密性の高いユーザーデータのエクスポートのリスクを減らすため、ワークスペースで Get User API を有効にするには、サポートチケットを作成する必要があります。
- **Data API の IP ホワイトリスト**: より細かく制御するために、Data API にアクセスできる IP のホワイトリスト登録をオプトインで利用できます。
- **追加の日時サポート**: `YYYY-MM-DD` の日時形式がサポートされるようになりました。これには、米国 (NA) リージョンや、この形式をデフォルトで使用するパートナー統合も含まれます。
- **`update_existing_only` のサポート**: User API と Event API で、新しいユーザーを作成せずに既存のユーザーのみを更新できるようになりました。
- **非 ASCII 文字の取り込み**: Data API で、File インポートと同様に多言語の文字を取り込めるようになりました。

詳細については、[Data の概要](/ja/api/data/data-overview) を参照してください。IP による API アクセスの制限の詳細については、[MoEngage での IP ホワイトリスト](/ja/user-guide/settings/account/security/ip-whitelisting-in-moengage#ip-whitelisting-for-data-apis) を参照してください。

## Custom Agents のマルチエージェント連携

Custom Agents がマルチエージェント連携をサポートするようになりました。1 つのセッション内で、エージェントは他のエージェントにタスクを委任でき、サブエージェントは並行して実行でき、親エージェントが出力を統合します。これにより、単一目的のエージェントが組み合わせ可能な構成要素になります。マルチエージェント連携は DC-01 と DC-03 で利用可能で、他のデータセンターにも順次展開されます。

前回のアップデート以降、Custom Agents には次の機能も追加されました。

- **スケジュール設定と通知**: 日次および週次のトリガーと、タスク完了時のメール通知。
- **モデルティアの選択**: Agent Mode 設定 (Fast、Balanced、Pro)。デフォルトは Sonnet 5 です。
- **ワークスペースレベルのメモリ**: エージェントは、テナントおよびワークスペースのレベルでセッションをまたいでコンテキストを保持します。
- **新しい MoEngage のツールとアクション**: エージェントは、User Analytics、Flows、Custom Segments、Catalog discovery、Offerings、カスタムテンプレートとメールテンプレートに対してアクションを実行できます。

Custom Agents は DC-01 から DC-04 および DC-101 で利用可能です。

詳細については、[マルチエージェントワークフローの構築](/ja/user-guide/ai-and-intelligence/merlin-ai/custom-agents/build-multi-agent-workflows) を参照してください。
