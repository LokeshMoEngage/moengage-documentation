## In-App Messaging の新しいトリガー - On Push Click

MoEngage では、ユーザーがプッシュ通知をクリックしたときに、アプリ内メッセージを確実に表示できるようになりました。ユーザーがプッシュをクリックすると、MoEngage はユーザーが遷移した画面の上に、リンクされたアプリ内メッセージを表示します。これにより、プッシュで注意を引き、アプリ内メッセージでループを完結させることができます。以前は、プッシュのクリックからアプリ内メッセージを確実にトリガーする方法がありませんでした。Push to In-App を使用すると、プッシュがクリックされるたびにリンクされたメッセージが表示されます。オーディエンスはプッシュキャンペーンから引き継がれ、配信コントロールは自動的に設定されるため、プッシュがクリックされるたびにメッセージが表示されます。

注意事項:

- サポートされている SDK バージョンは、Android BOM SDK 2.3.0 以降、および iOS SDK Package バージョン 10.14.0 以降です。
- この機能は、プッシュキャンペーンの Deep Link および Navigate to Screen のクリックアクションで機能しますが、Rich Landing では機能しません。
- 定期プッシュキャンペーンはサポートされていません。

詳細については、[アプリ内キャンペーンの作成](/ja/user-guide/campaigns-and-channels/in-app-message/create/create-in-app-campaign) を参照してください。

## SMS 向け Merlin AI Campaign Insight Agent

Merlin AI Campaign Insight Agent が SMS に対応し、リリース時点で One-Time、Periodic、Event-Triggered の 3 つのキャンペーンタイプすべてをカバーしています。これは、既存の Push と Email のサポートに追加されるものです。SMS 向けに、エージェントは次の機能を追加します。

- **コネクターのパフォーマンスインサイト**: アカウントに設定されている SMS コネクターとルートを比較し、どれが配信を促進し、どれがパフォーマンスを低下させているかを示します。
- **急増と急減の分析**: SMS の量の突然の急増や急減について説明します。
- **トリガーの動作に関するインテリジェンス**: イベントトリガー型 SMS について、どのイベントが、どの頻度で、どのセグメントからトリガーされているかを示します。
- **イベントレベルの根本原因の診断**: トリガー型 SMS キャンペーンのパフォーマンスが低い場合に、問題がトリガー条件、オーディエンスの条件、タイミングウィンドウ、コネクターのルーティング、クリエイティブのどこにあるかを特定します。
- **トリガー頻度のベンチマーク**: イベントのトリガー率を過去のベースラインと比較します。

アカウントで Insight Agent がすでに有効になっている場合、このアップデートは自動的に展開されます。まだ有効になっていない場合は、MoEngage の CSM にアクセスをお問い合わせください。

## 認証フローの刷新

MoEngage は、プラットフォームから完全にロックアウトされることを防ぐため、刷新された認証フローを導入しました。SSO の取り消し、IdP の変更、アカウントのブロックなどにより最近使用したワークスペースでエラーが発生しても、すべてのワークスペースへのアクセスを失うことはなくなりました。

**主な更新内容**

- 新しい Login to a different workspace オプションをクリックして、認証前にワークスペースを選択できます。
- 2 段階認証の後、Select Workspace 画面で、承認されたワークスペース、環境タイプ (Live/Test)、ログイン方法を確認できます。
- アクセスできないワークスペースを回避し、利用可能なワークスペースにすぐにログインできるため、サポートチケットを作成する必要がなくなります。
- この統一されたログインフローは、Global Login Screen、DC 固有のログインページ、MCP、Mobile App の接続全体で利用できます。
- 既存の最終使用ワークスペースのフローと 2 段階認証の設定は、そのまま維持されます。

**セッション管理**
MoEngage は、Dashboard、MCP、Mobile のセッションを、それぞれ異なるタイムアウトで個別に管理します。MCP セッションは、30 日後、または 7 日間操作がない場合に期限切れになります。

**展開スケジュール**
このアップデートは、まず DC-03、DC-04、DC-06 に展開されます。残りのデータセンターと Global Login Screen にも間もなく展開されます。

詳細については、[MoEngage へのログイン](/ja/user-guide/getting-started/initial-setup/log-in-to-moengage#log-into-a-different-workspace) を参照してください。

## メール開封トラッキングの同意管理

MoEngage は、フランスの CNIL (2026 年 7 月 14 日施行) とイタリアの Garante (2026 年 10 月 28 日施行) の規制ガイダンスに沿って、メール開封トラッキングの同意を管理するネイティブな方法を提供するようになりました。これらの規制では、これらの国に所在する受信者に送信するメールに開封トラッキングピクセルを含める前に、個別の明示的な同意を取得することがブランドに求められます。この機能には次のものが含まれます。

- **開封トラッキングの同意トグルと国の選択**: Email General Settings から開封トラッキングの同意を有効にし、適用する国を選択します。設定した国以外の受信者は、通常どおりトラッキングされます。
- **受信者ごとの同意属性**: 新しいシステム属性 `moe_email_open_tracking_consent` は、各ユーザーの設定をメールのサブスクリプションステータスとは別に保存します。User Import、MoEngage SDK、または Server-to-Server Data API を通じて更新できます。
- **ピクセルの自動抑制**: 設定した国の同意していない受信者に対しては、送信済みのメールも含め、メールに開封トラッキングピクセルが含まれません。
- **メールフッターの同意管理リンク**: この機能を有効にすると、MoEngage はすべてのメールフッターに、配信停止リンクや Manage Preferences リンクとは別に、開封トラッキングの設定リンクを追加します。
- **同意の監査証跡**: 連絡先の開封トラッキングの同意に対するすべての変更は、新しい状態、以前の状態、タイムスタンプ、ソースとともにシステムイベントとして記録されます。
- **国データが欠落している場合のフォールバック設定**: 国の属性が入力されていない受信者をプラットフォームがどのように処理するかを設定します。

この機能はデフォルトでオフになっているため、設定して有効にするまで動作は変わりません。残りの開封データは同意した受信者からのみ得られるため、フランスやイタリアのオーディエンスが多いお客様では開封率が低下する可能性があります。同意していない受信者は開封イベントを生成しないため、Email Opened をトリガーまたはエントリー条件として使用している Flows は見直しが必要になる場合があります。

詳細については、[同意属性と開封トラッキングピクセル](/ja/user-guide/campaigns-and-channels/email/getting-started-with-email/consent-attribute-and-open-tracking-pixel) を参照してください。

## MoEngage Offering API

MoEngage Offering API が利用可能になり、プログラムで Offering を管理できるようになりました。

- **Create Offering**: ターゲットのセグメンテーション、カスタムスケジュール、コンテンツのバリエーションを使用して、新しい Offering を生成します。
- **Update Offering**: アクティブな Offering とスケジュール済みの Offering のターゲティングやスケジュールを更新します。
- **List Offerings**: レポートダッシュボードや自動化されたワークフロー向けに、ページ分割された Offering のリストを取得します。

これらの API は、MoEngage MCP サーバー内のツールとしても利用できます。単一の Offering を直接検索するための **Get Offering by ID** エンドポイントは今後予定されています。

詳細については、[Offerings API の概要](/ja/api/offerings/offerings-overview) を参照してください。

## パーソナライズされたリンクの SMS URL 短縮

MoEngage は、ユーザー属性、イベント属性、補助データなどのパーソナライゼーションパラメーターを使用して作成された SMS リンクの URL 短縮とクリックトラッキングをサポートするようになりました。以前は、URL 短縮とクリックトラッキングは `http://` または `www.` で始まる URL でのみ機能していたため、マーケターはパーソナライズされたリンクの回避策としてカスタム Jinja を使用する必要がありました。 

SMS キャンペーンビルダーで、パーソナライゼーションパラメーターを短縮リンクとして直接指定できるようになりました。MoEngage は生成される URL を自動的に構築、短縮、追跡するため、カスタム Jinja が不要になり、パーソナライズされた SMS リンクのクリックトラッキングが可能になります。

詳細については、[SMS キャンペーンの作成](/ja/user-guide/campaigns-and-channels/sms-mms-and-rcs/sms/create-an-sms-campaign#url-addition-and-shortening) を参照してください。

## API Firewall

API Firewall は MoEngage Data API に IP 許可リストを追加し、承認された IP アドレスにアクセスを制限することで、漏洩した認証情報だけではデータにアクセスできないようにします。API Firewall を使用すると、次のことができます。

- 承認されたサーバーの IP 許可リストを作成し、すべてのルールを先に追加してから、まとめて公開する。
- リストにない IP からのリクエストは、有効な API キーを持っている場合でも自動的に拒否する。
- ルールを単一の IPv4 または IPv6 アドレス、CIDR 範囲、または IPv4/IPv6 範囲として定義する。
- 各ルールを誰が、いつ、どの IP から変更したかを追跡し、過去 30 日間に各ルールから成功した Data API 呼び出しの数を確認する。

システムはフェイルオープンで動作するため、問題が発生した場合でも正当なトラフィックは引き続き流れます。API Firewall はサーバー間の Data API リクエストにのみ適用されるため、モバイルアプリや Web サイトからの SDK トラフィックは影響を受けません。API Firewall は現在、Data API を対象としています。

詳細については、[API Firewall](/ja/user-guide/settings/account/security/api-firewall) を参照してください。

## Amazon S3 のインポートとエクスポートの機能強化

MoEngage は Amazon S3 のインポートとエクスポートを更新しました。

- **App Marketplace での接続の詳細**: インポート設定ごとに認証情報を再入力する代わりに、**App Marketplace** \> **Amazon S3** で S3 の接続の詳細を一度設定するだけで済みます。これにより、大規模なチームでは、チームメンバー間で画面へのアクセス権限を分けることもできます。
- **S3 Cross-Account Role Assumption**: 静的なアクセスキーを共有する必要をなくす新しい認証方法で、インポートとエクスポートの両方に適用されます。
- **単一フォルダーへのエクスポート**: 日付ごとのネストされたフォルダーではなく、単一のフォルダーにファイルをエクスポートすることを選択でき、下流のデータパイプラインを簡素化できます。

このリリースには後方互換性があります。既存のインポートとエクスポートは引き続き実行され、アップデートが有効になると接続設定は自動的に App Marketplace に移行されます。 

**展開スケジュール**
この機能は DC-01 から DC-04 でリリースされています。

詳細については、[Amazon S3](/ja/partner-guide/data-and-analytics/cloud-storage/amazon-s3) を参照してください。

## 属性別のトレンドアイテム

Trending Items に Attribute Trend が追加されました。すべてのユーザーに同じグローバルなトレンドを表示するのではなく、カテゴリや地域などの特定の属性内でトレンドになっているものを表示します。カテゴリ、サブカテゴリ、場所、ブランドなど、任意のカタログ属性にトレンドをマッピングし、ユーザー全体で固定のトレンドにするカスタム値、またはユーザーごとにパーソナライズするユーザープロパティを使用してパーソナライズできます。アイテム属性とユーザーアクションのフィルターを使用して、結果を制御できます。

詳細については、[トレンドアイテム](/ja/user-guide/content/recommendations/advanced-recommendations/category-trending-items) を参照してください。

## 新しいコネクター、Connected Apps、動的コンテンツ

MoEngage は、新しいコネクター、アプリ、動的コンテンツの統合を追加しました。

- **Telegram のメディア、アクション、HTML のサポート**: インタラクティブな CTA とともに動画や写真を含め、メッセージの書式設定にネイティブ HTML を使用できます。[Telegram](/ja/partner-guide/messaging-channels/messaging-apps/telegram) を参照してください。
- **Reddit Ads Audience**: カスタムセグメントを同期して Reddit コミュニティをターゲティングし、類似オーディエンスを構築します。Connected Segments アドオンで利用できます。[Reddit Ads Audience](/ja/partner-guide/retargeting-and-audience-sync/audience-sync/reddit-ads-audience) を参照してください。
- **Truecaller**: 認証済みの発信者 ID、SMS、通話後のインタラクション画面を追加します。[Truecaller](/ja/partner-guide/retargeting-and-audience-sync/audience-sync/truecaller) を参照してください。
- **Deepgram AI Voice**: アウトリーチやアンケートなどの音声インタラクションを自動化して拡張します。Connected Channels アドオンで利用できます。[Deepgram](/ja/partner-guide/messaging-channels/voice/deepgram) を参照してください。
- **イベントとチケットの動的コンテンツ**: AXS、Oztix、Ticketek、Ticketmaster のリアルタイムのイベントデータとチケットデータを、送信時にキャンペーンに統合します。[Ticketmaster](/ja/partner-guide/personalize-and-optimize/dynamic-content/events-and-ticketing/ticketmaster) を参照してください。
- **Connected Apps の HTML サポートとキーと値のペア**: ネイティブ HTML と条件ロジックでメッセージを書式設定し、コンテンツのルーティングのために動的なデータ変数を渡します。[チャネルコネクター設定ファイルの作成](/ja/user-guide/campaigns-and-channels/connected-apps/getting-started-with-connected-apps/create-a-channel-connector-config-file#basic-info) を参照してください。

**展開スケジュール**
これらのアップデートは DC-01 から DC-04 で利用可能です。


## 6 つの新しいデータソース

MoEngage は、支払い、サブスクリプション、ロイヤルティ、e コマース、コンテキストデータからのリアルタイムのシグナルをキャンペーンに取り込む 6 つの新しいデータソースを追加しました。これらの統合は無料で接続できます。

- **Superwall**: リテンションキャンペーンやウィンバックキャンペーンのために、トライアルのアップグレード、メンバーシップの更新、解約を取得します。[Superwall](/ja/partner-guide/data-and-analytics/payments-and-subscriptions/superwall) を参照してください。
- **Razorpay**: 承認された支払い、完了した取引、放棄されたフローを追跡して、保留中のチェックアウトを回復します。[Razorpay](/ja/partner-guide/data-and-analytics/payments-and-subscriptions/razorpay) を参照してください。
- **NitroX**: アイテムへのエンゲージメント、カートの変更、完了した注文をストリーミングして、放棄の回復やクロスセルをトリガーします。[NitroX](/ja/partner-guide/commerce-and-loyalty/e-commerce/nitrox) を参照してください。
- **Xeno Loyalty**: ティアのアップグレード、ポイントの達成、商品の返品などのリアルタイムのロイヤルティアクションを送信します。[Xeno Loyalty](/ja/partner-guide/commerce-and-loyalty/loyalty/xeno-loyalty) を参照してください。
- **Xoxoday Loyalife**: ポイント残高、ティアのステータス、予測される利用期間などのロイヤルティ指標を同期します。[Xoxoday Loyalife](/ja/partner-guide/commerce-and-loyalty/loyalty/xoxoday-loyalife) を参照してください。
- **WooTag**: 地域の天気、試合のライブ速報、暗号資産のトレンド、交通状況などのコンテキストトリガーを使用します。[WooTag](/ja/partner-guide/personalize-and-optimize/contextual-location/wootag) を参照してください。

## 日次頻度での Computed Traits

Computed Traits を日次の更新頻度で利用できるようになりました。これはリクエストに応じて有効にできます。
