## MoEngage Go: MoEngage モバイルアプリ

MoEngage モバイルアプリ (MoEngage Go) は MoEngage Web ダッシュボードのコンパニオンアプリで、デスクを離れているときに完了する必要のあるタスクに焦点を当てています。スマートフォンから、キャンペーンのパフォーマンスの監視、実行中のキャンペーンの管理、レビュー待ちのキャンペーンの承認、重要なアラートへの対応を行うことができます。このアプリを使用すると、次のことができます。

- アクティブなキャンペーンとスケジュール済みのキャンペーンを表示する。
- レビュー待ちのアイテムを承認または却下する。
- 配信中の送信を一時停止または停止する。

サインインでは、Web アプリと同じロールと権限で SSO、Google、メールがサポートされています。キャンペーンの作成と編集のワークフローには完全なインターフェイスが必要なため、これらは引き続きデスクトップで行います。

MoEngage Go は、[iOS App Store](https://apps.apple.com/us/app/moengage-go/id6755712030?utm_source=help_docs&utm_medium=referral&utm_campaign=app_download) と [Android Play Store](https://play.google.com/store/apps/details?id=com.moengage.go&utm_source=help_docs&utm_medium=referral&utm_campaign=app_download) で利用できるようになりました。

詳細については、[MoEngage Go: 概要](/ja/user-guide/moengage-go/moengage-go-overview) を参照してください。

## Offer Decisioning の Decision Policy のシミュレーション

MoEngage は Offer Decisioning にシミュレーターを追加しました。これにより、Decision Policy を公開する前後にテストできます。特定の既知のユーザー、ランダムなユーザー、または匿名の訪問者を選択し、リアルタイムでポリシーを実行します。結果には、どの Offering がどの順序で選択されたか、どの Offering が対象ではあったが選択されなかったか、どの Offering がセグメントまたは上限のチェックで不合格になったかが表示されます。Custom Formula ランキング戦略の場合、結果には各 Offering のスコア計算が含まれます。デバイスタイプ、国や都市、言語などのセッション内属性をテストして、コンテキストのシグナルによって表示されるオファーがどのように変わるかを確認することもできます。

詳細については、[Decision Policy のシミュレーション](/ja/user-guide/decisioning/offer-decisioning/simulate-decision-policy) を参照してください。

## Funnels、Retention、Session & Source のカスタムアラート

MoEngage は、これまで Behavior 分析で利用可能だった Custom Alerts を、Funnels、Retention、Session & Source の分析タイプに拡張しました。

- Funnels では、任意の 2 つのステップ間でコンバージョンしたユーザー数に対してアラートを設定できます。
- Retention では、特定のリテンション日 (D7 や D30 など) を監視し、割合または値で増減したときに通知を受け取ることができます。
- Session & Source では、ソース全体のセッション数、直帰率、収益などの指標を追跡できます。

詳細については、[Analytics のアラート](/ja/user-guide/analyze/analytics/alerts-in-analytics) を参照してください。

## Analytics テーブルの AG Grid への移行

MoEngage は、Behavior、Funnels、Retention、Session & Source、User Analysis の分析テーブルを AG Grid に移行しました。更新されたテーブルでは、最小および最大の制限内で列のサイズを変更したり、任意の列を昇順または降順で並べ替えたり (3 回目のクリックでリセット)、すべての行と列を検索したりできます。列フィルターは、AND/OR 条件、複数列のフィルタリング、高度なクエリビルダーをサポートしています。

詳細については、[Analytics の概要](/ja/user-guide/analyze/analytics/getting-started-with-analytics/overview#tables) を参照してください。

## User Affinity の機能強化

MoEngage は Segments の User Affinity をアップグレードしました。User Affinity は Teams で機能するようになり、Teams は Analytics でも利用できるようになりました。アフィニティセグメントを構築する際に、イベント属性フィルター内でオブジェクトデータ型を使用でき、アップグレードされたフィルターにより、アフィニティベースのオーディエンスを定義する方法が増えました。

詳細については、[アフィニティセグメント](/ja/user-guide/segment/create-segments/affinity-segments) を参照してください。

## Flows Assist: 反復的な編集

Flows Assist で、同じセッション内で複数回のやり取りを通じてフローを改善できるようになりました。Flows Assist がフローを構築した後、分岐ロジック、遅延構造、その他の要素の変更を依頼すると、フローが更新されます。再生成するたびに新しいバージョン (V1、V2、V3 など) が作成され、以前のバージョンを選択してそこから続行したり、キャンバスに移動したりできます。この編集は、アクティブな Flows Assist セッションで構築中のフローにのみ適用されます。**Edit in Canvas** を選択するとセッションが終了し、Flows Assist は既存の下書きを編集できません。Target Audience は引き続きデフォルトで All Users になり、キャンペーンのステージはプレースホルダーのままで、コンテンツは生成されません。 

この機能は、DC-03 で Flows Assist MVP がすでに有効になっているお客様がご利用いただけます。

詳細については、[Merlin AI Flows Assist](/ja/user-guide/ai-and-intelligence/merlin-ai/merlin-ai-flows-assist) を参照してください。

## イベントトリガー型キャンペーン向け Campaign Insight Agent

Merlin AI Campaign Insights Agent は、既存の One-Time キャンペーンと Periodic キャンペーンのサポートに加えて、Email と Push のイベントトリガー型キャンペーンをサポートするようになりました。

イベントトリガー型キャンペーンについて、エージェントはトリガーファネル (トリガーとなるイベントからコンバージョンまで) に焦点を当てた専用のプロンプトセットを提供します。

- **パフォーマンスの要約**: イベントからコンバージョンまでのトリガーファネルのスナップショットで、うまくいった点、離脱が発生した箇所、次のステップを強調します
- **成功パターンの発見**: 過去のトリガー型キャンペーンを比較し、最良の結果をもたらした戦略を明らかにします
- **パフォーマンストレンドの分析**: 主要な指標における前週比の急増と急減を特定し、キャンペーンの推移を時系列で追跡できるようにします
- **トリガープレイブックの最適化**: コンバージョンを向上させるために、トリガーのタイミング、遅延、再エントリーの設定の改善を推奨します
- **配信失敗の診断**: トリガーファネル全体での離脱の根本原因を明らかにし、是正措置を提案します

**提供状況**: これは既存の早期アクセス機能である Campaign Insights Agent の一部です。アカウントですでに有効になっている場合は、イベントトリガー型のサポートも含まれます。まだ有効になっていない場合は、MoEngage の CSM またはサポートチームにお問い合わせください。

詳細については、[Campaign Insights Agent](/ja/user-guide/ai-and-intelligence/merlin-ai/campaign-insights-agent) を参照してください。

## フィードアップロードの刷新

MoEngage は、カタログフィードのアップロードを 2 ステップのワークフローに刷新しました。最初のステップでは、CSV、TSV、または XML ファイルをアップロードし、処理前にデータをプレビューします。2 番目のステップでは、システムがファイルの列をカタログ属性に自動的にマッピングし、そのマッピングを手動で調整できます。処理前に必須フィールドが確認され、大文字と小文字の不一致が処理され、保存されたマッピング設定は以降のアップロードで再利用されます。

詳細については、[カタログ](/ja/user-guide/content/recommendations/getting-started/catalogs#add-feeds-to-a-catalog) を参照してください。

## ワークスペースの分類

MoEngage は Workspace Classification をサポートするようになりました。ワークスペースを Production または Non-Production としてタグ付けし、段階的で自動化された機能リリースサイクルを実現できます。

この機能を使用すると、次のことができます。

- 新機能を Production 環境に展開する前に Non-Production ワークスペースにルーティングすることで、アップデートを安全にテストする。
- 展開サイクルの各段階で自動メール通知を受け取り、最新情報を把握する。
- 既存のワークスペースについては **Settings** \> **Account** \> **General Settings** から、新しいワークスペースについてはオンボーディング中に直接、分類を簡単に管理する。
- 分類されていないワークスペースには自動的に Non-Production がデフォルトで適用されるため、稼働中のキャンペーンを保護する。

<Info>
  この機能は、DC-03 の Enterprise プランのすべてのお客様に対して有効になっています。
</Info>

詳細については、[ワークスペースの設定](/ja/user-guide/settings/account/general-settings/workspace-settings) を参照してください。
