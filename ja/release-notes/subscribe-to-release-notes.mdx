RSS (Really Simple Syndication) はオープンスタンダードであるため、ほとんどのメールクライアント、ブラウザー、チームチャットツール、専用のフィードリーダーでこれらのフィードを閲覧できます。

<Note>
  MoEngage は、各 SDK のリリースノートごとに RSS フィードを公開しています。Product および Partner のリリースノートには、まだ RSS フィードがありません。これらの更新については、ドキュメントサイトの [Product](/ja/release-notes/product) および [Partners](/ja/release-notes/partners) のリリースノートをご確認ください。
</Note>

フィードを購読すると、ドキュメントサイトを手動で確認しなくても、新しい SDK バージョン、変更履歴、破壊的変更のお知らせを任意のリーダーで受け取ることができます。

## 利用可能なフィード

各 SDK のリリースノートページには、それぞれ独自のフィードがあります。使用している SDK のフィード URL をコピーしてください。

| --- | --- |
| Android | `https://www.moengage.com/docs/release-notes/sdks/android/rss.xml` |

| Web | `https://www.moengage.com/docs/release-notes/sdks/web/rss.xml` |
| React Native | `https://www.moengage.com/docs/release-notes/sdks/react-native/rss.xml` |
| Expo (React Native) | `https://www.moengage.com/docs/release-notes/sdks/expo-react-native/rss.xml` |
| Flutter | `https://www.moengage.com/docs/release-notes/sdks/flutter/rss.xml` |
| Cordova | `https://www.moengage.com/docs/release-notes/sdks/cordova/rss.xml` |
| Capacitor | `https://www.moengage.com/docs/release-notes/sdks/capacitor/rss.xml` |

## フィードを購読する

更新を受け取りたい場所に合った方法を選択してください。いずれの方法でも、上の表にある同じフィード URL を使用します。

<Tabs>
  <Tab title="Slack">
    Slack に組み込まれている RSS アプリを使用して、新しいリリースを Slack チャンネルに投稿します。チームで一緒に更新を追跡する場合に最適です。

    <Info>
      `/feed` コマンドを使用する前に、ワークスペースの管理者が [RSS アプリ](https://slack.com/apps/A0F81R7U7-rss) をインストールする必要があります。
    </Info>

    <Steps>
      <Step title="チャンネルを開く">
        リリースの更新を表示したいチャンネルに移動します。
      </Step>
      <Step title="フィードを購読する">
        URL を使用している SDK のフィード URL に置き換えて、次のメッセージを送信します。

        ```text wrap
        /feed subscribe https://www.moengage.com/docs/release-notes/sdks/android/rss.xml
        ```
      </Step>
    </Steps>

    購読の一覧を表示するには `/feed list` を、購読を解除するには `/feed remove [ID]` を使用します。コマンドの完全なリファレンスについては、Slack のガイド [Slack に RSS フィードを追加する](https://slack.com/help/articles/218688467-Add-RSS-feeds-to-Slack) を参照してください。
  </Tab>
  <Tab title="Microsoft Teams">
    Workflows (Power Automate) による自動化を使用して、新しいリリースを Teams チャンネルに投稿します。チームで一緒に更新を追跡する場合に最適です。

    <Info>
      Microsoft は、Teams 向けの従来の Office 365 RSS コネクターを廃止しました。代わりに、Power Automate を利用した **Workflows** アプリを使用してください。
    </Info>

    <Steps>
      <Step title="Workflows を開く">
        Teams で更新を受け取りたいチャンネルに移動し、その他のオプション (**...**) メニューを選択して、**Workflows** を選択します。
      </Step>
      <Step title="RSS テンプレートを選択する">
        **Post to a channel when a feed item is published** などの RSS テンプレートを検索して選択します。
      </Step>
      <Step title="フィード URL と投稿先を追加する">
        SDK のフィード URL を貼り付け、対象のチームとチャンネルを確認します。
      </Step>
      <Step title="ワークフローを保存する">
        ワークフローを保存します。新しいリリースが自動的にチャンネルに投稿されます。
      </Step>
    </Steps>
  </Tab>
  <Tab title="Microsoft Outlook">
    Outlook を使用して、各リリースを専用フォルダー内のメール形式のメッセージとして受け取ります。メールクライアントで更新を受け取りたい個人に最適です。

    <Steps>
      <Step title="RSS フィードを開く">
        左側のナビゲーションウィンドウで、**RSS Feeds** を右クリックします。
      </Step>
      <Step title="新しいフィードを追加する">
        **Add a New RSS Feed** を選択します。
      </Step>
      <Step title="フィード URL を貼り付ける">
        SDK のフィード URL を貼り付け、**Add** をクリックして **Yes** で確定します。
      </Step>
    </Steps>

    **RSS Feeds** の下に新しいフォルダーが表示され、各リリースのエントリーがメールメッセージのように表示されます。

    <Tip>
      フィードを右クリックして **Data File Properties** を選択すると、名前を変更できます (例: "MoEngage Android Release Notes")。チームと更新を共有するには、新しいエントリーを共有メールボックスに転送するルールを作成してください。
    </Tip>
  </Tab>
  <Tab title="ブラウザー拡張機能">
    Microsoft Edge や Google Chrome を含むほとんどの最新ブラウザーは、RSS フィードをネイティブに表示しません。代わりにフィードリーダーの拡張機能を使用してください。メール通知なしですばやくアクセスしたい場合に最適です。

    <Steps>
      <Step title="フィードリーダーをインストールする">
        Feedbro や RSS Feed Reader など、ブラウザーの拡張機能ストアから RSS 拡張機能を追加します。
      </Step>
      <Step title="新しいフィードを追加する">
        拡張機能を開き、フィードを追加または購読するオプションを選択します。
      </Step>
      <Step title="フィード URL を貼り付ける">
        SDK のフィード URL を貼り付けて保存します。新しいリリースが拡張機能に表示されます。
      </Step>
    </Steps>
  </Tab>
  <Tab title="自動メール">
    メールクライアントが RSS をサポートしていない場合は、[Zapier](https://zapier.com/apps/email/integrations/rss) などの自動化ツールを使用して、フィードが更新されたときにメールを受け取るようにします。任意の受信トレイや配信リストに更新を送信する場合に最適です。

    <Steps>
      <Step title="RSS からメールへの自動化を作成する">
        自動化ツールで、新しい RSS フィードアイテムをトリガーとするワークフローを作成します。
      </Step>
      <Step title="フィード URL を追加する">
        RSS ソースを SDK のフィード URL に設定します。
      </Step>
      <Step title="メールアクションを設定する">
        新しいリリースが公開されるたびに、選択した受信者にメールを送信するアクションを設定します。
      </Step>
    </Steps>
  </Tab>
</Tabs>

## フィードでできるその他のこと

フィードは機械可読であるため、[Zapier](https://zapier.com/apps/rss/integrations)、[Make](https://www.make.com/en/integrations/rss)、[Power Automate](https://make.powerautomate.com/) などの自動化ツールでフィードを監視し、新しいリリースをチームが作業しているあらゆる場所に振り分けることができます。一般的な活用例は次のとおりです。

- **フィルター付きアラート** — "breaking" や特定のモジュール名など、エントリーがキーワードに一致した場合にのみ通知します。
- **アップグレードの追跡** — 各リリースを Google Sheet、Airtable、または Notion のデータベースに記録し、確認済みの SDK バージョンを追跡します。
- **フィードの統合** — 使用している SDK のフィードをフィードリーダーで 1 つのストリームにまとめます。

### リリースごとにアップグレードタスクを作成する

新しい SDK リリースをすべて Jira または Linear の追跡タスクにすることで、アップグレードの見落としを防ぎます。

<Steps>
  <Step title="RSS トリガーを追加する">
    自動化ツールで、SDK のフィード URL の新しいアイテムをトリガーとするワークフローを作成します。
  </Step>
  <Step title="課題管理ツールのアクションを追加する">
    Jira または Linear で課題を作成するアクションを追加します。
  </Step>
  <Step title="リリースの詳細を課題にマッピングする">
    フィードアイテムのタイトルとリンクを使用して課題を入力します。たとえば、概要を `Review [SDK] release: {{title}}` に設定し、説明にリリースのリンクを追加します。
  </Step>
  <Step title="担当者とプロジェクトを設定する">
    SDK のアップグレードを担当するチームまたはプロジェクトに課題を割り当て、ワークフローを有効にします。
  </Step>
</Steps>
