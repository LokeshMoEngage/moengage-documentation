<Update label="23rd September 2026">
  <CardGroup cols={2}>
  <Card title="Android (Kotlin)">
    **プラグイン v4.3.0**

    - MoEngage Android SDK のバージョンを **15.03.00** に更新しました。[リリースノート](/ja/release-notes/sdks/android#23rd-september-2026)
    - MoEngage は、Jetpack Compose のユーザーインターフェースに Cards を直接埋め込む `cards-ui-compose` モジュールを導入しました。詳細は [Jetpack Compose での Cards](/ja/developer-guide/android-sdk/cards/cards-ui-compose) を参照してください。
    - Card のコンテンツがシステムによって強制的にダーク化されなくなりました。Cards は、ライトテーマとダークテーマの両方で、設定した色で表示されます。

    **破壊的変更**
    - MoEngage SDK によるプッシュトークンの登録はサポートされなくなりました。SDK は Firebase Installation ID を使用してデバイスをプッシュに登録するようになりました。アップグレードする前に、`com.google.firebase:firebase-messaging` を **25.1.2** 以上に更新し、アプリケーションのマニフェストファイルで Firebase Installation ID を有効にしてください。MoEngage SDK がトークンを登録しているアプリケーションで両方の手順を完了しない場合、プッシュの登録が停止し、通知を受信できなくなります。詳細は [Firebase Installation ID への移行](/ja/developer-guide/android-sdk/migration/migrating-to-firebase-installation-id) を参照してください。
  </Card>

    この日のリリースはありません。

  <Card title="iOS (Swift)">
    **プラグイン v3.2.0**

    - MoEngage-iOS-SDK を [11.2.0](/ja/release-notes/sdks/ios#16th-september-2026) に更新しました。
    - MoEngage フレームワークは、動的フレームワークとして埋め込まれる代わりに、ホストバイナリに静的にリンクされるようになりました。CocoaPods および Swift Package Manager による統合では変更は不要です。
    - Inbox の完了ブロックはメインスレッドで呼び出されるようになり、Inbox のエントリーはイミュータブルなスナップショットになりました。`isRead` や `clickedDate` などの既読状態の変更は、すでに保持しているエントリーオブジェクトを変更するのではなく、次回の取得時に反映されます。

    **破壊的変更**
    - SDK のデフォルトの **Dismiss** 通知アクションが通知カテゴリから削除されました。通知には、設定したアクションのみが表示されるようになりました。
    - Inbox API は Swift の並行処理モデルに準拠するようになりました。`presentInboxViewController`、`pushInboxViewController`、`getInboxViewController` はメインアクターにバインドされます。メインアクター外にある Swift の呼び出し箇所は更新が必要です。
    - `trackUserPushPreference` は非推奨になりました。この API は本リリースでは引き続き動作しますが、将来のメジャーバージョンで削除される予定です。
  </Card>
  </CardGroup>
</Update>

  <Card title="iOS (Swift)">
    **プラグイン v3.0.0**

    - MoEngage-iOS-SDK を [11.0.0](/ja/release-notes/sdks/ios#22nd-july-2026) に更新しました。

    **破壊的変更**
    - 基盤となる MoEngage iOS SDK は、パブリック API を使用する前に初期化を必須とするようになりました。すべてのビルド構成 (Debug、Release、TestFlight ビルド) において、順序どおりに呼び出されない場合は `fatalError` が発生します。
    - `MoEngageInAppActionType` と `MoEngageNudgePosition` は Swift の enum になりました。古い Objective-C スタイルのケース名を参照しているコードを更新してください。移行表については [iOS SDK リリースノート](/ja/release-notes/sdks/ios#22nd-july-2026) を参照してください。
    - 以前は `Void` を返していた API (例: `trackEvent`、`showInApp`、`setPushToken`、`initializeDefaultLiveInstance`) は、型付きのタスクオブジェクトを返すようになりました。直接呼び出しは変更なしでコンパイルされますが、明示的な `Void` 戻り値型を持つ Swift の関数参照の代入はコンパイルされなくなりました。
    - `presentCardsViewController`、`pushCardsViewController`、`getCardsViewController` に `@MainActor` アノテーションが付与されました。メインアクター以外のコンテキストからこれらを呼び出す Swift の呼び出し元は、メインアクターに切り替える必要があります。
    - `setUserAttribute`、`setDeviceAttribute`、および `MoEngageProperties` の属性 API では、Swift 6 言語モードまたは厳格な並行性チェックの下で、値が `Sendable` に準拠している必要があります。
  </Card>
  </CardGroup>
</Update>

    **プラグイン v4.0.0**

    - MoEngage Android SDK のバージョンを **15.00.00** に更新しました。[リリースノート](/ja/release-notes/sdks/android#7th-july-2026)

    **破壊的変更**
    - ビルドパフォーマンスと互換性を向上させるため、Android Gradle Plugin をバージョン 9.1.1 にアップグレードしました。
    - 最新の言語機能と安定性の向上を活用するため、Kotlin をバージョン 2.3.20 にアップグレードしました。
    - 最新の Android プラットフォームの機能に合わせて、Compile SDK と Target SDK を 36 にアップグレードしました。
    - 起動パフォーマンスを向上させるため、`DataCenter` の初期化を最適化しました。これにより Java の破壊的変更が発生し、`MoEngage.Builder` コンストラクターのシグネチャが更新されている点にご注意ください。詳細は [Android SDK リリースノート](/ja/release-notes/sdks/android#7th-july-2026) を参照してください。
    - SDK の初期化前に API が呼び出された場合、SDK は `IllegalStateException` をスローするようになりました。処理されない場合、ランタイムクラッシュが発生します。SDK API を呼び出す前に、必ず `MoEngage.initialiseDefaultInstance()` を呼び出してください。
