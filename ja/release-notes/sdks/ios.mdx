#### Core
<span style={{ backgroundColor: 'rgba(212, 56, 13, 0.1)', color: '#D4380D', border: '1px solid #FFCCC7', padding: '2px 10px', borderRadius: '12px', fontSize: '0.85em', fontWeight: 'bold' }}>破壊的変更</span>

* SDK のデフォルトの **Dismiss** 通知アクションが通知カテゴリから削除されました。通知には、設定したアクションのみが表示されるようになりました。アプリがこのボタンに依存している場合は、独自のカテゴリ定義に明示的に追加してください。
* `trackUserPushPreference` は非推奨になりました。この API は本リリースでは引き続き動作しますが、今後のメジャーバージョンで削除されます。

<span style={{ backgroundColor: 'rgba(212, 107, 8, 0.1)', color: '#D46B08', border: '1px solid #FFE58F', padding: '2px 10px', borderRadius: '12px', fontSize: '0.85em', fontWeight: 'bold' }}>修正</span>

* データ同期中にイベント識別子が重複する問題を修正しました。保留中の書き込みが完了する前にアプリが終了した場合、分析バッチ識別子が 2 つのイベントセットで再利用される可能性がありました。これは通常、アプリが強制終了された状態で通知の消去が処理された場合に発生していました。識別子はバッチの送信時に割り当てられるようになったため、各バッチは独自の識別子で 1 回だけ同期されます。

#### InApp
<span style={{ backgroundColor: 'rgba(0, 135, 103, 0.1)', color: '#008767', border: '1px solid #B5F5EC', padding: '2px 10px', borderRadius: '12px', fontSize: '0.85em', fontWeight: 'bold' }}>改善</span>

* **静的リンク:** InApp フレームワークは、動的フレームワークとして埋め込まれる代わりに、ホストバイナリに静的リンクされるようになりました。CocoaPods および Swift Package Manager での統合では変更は不要です。
* 手動の xcframework 統合では、次の 2 つの変更が必要です:
  * フレームワークを **Do Not Embed** に設定し、リリース zip から `MoEngageInApps.bundle` をアプリバンドルにコピーします。**Do Not Embed** ではフレームワークから何もコピーされないため、この手順を行わないと、プライバシーマニフェストなしでアプリが出荷されます。
  * **Other Linker Flags** に `-ObjC` を追加します。リンカーは、静的リンクされたモジュールのコードを、そのモジュールが定義するシンボルをアプリが参照している箇所でのみ取り込みます。

<span style={{ backgroundColor: 'rgba(212, 107, 8, 0.1)', color: '#D46B08', border: '1px solid #FFE58F', padding: '2px 10px', borderRadius: '12px', fontSize: '0.85em', fontWeight: 'bold' }}>修正</span>

* SDK 11.1.0 で発生した、Swift Package Manager 統合でモジュールが初期化されない問題を修正しました。静的リンクにより、SDK が名前で解決するクラスや拡張で宣言された `@objcMembers` メソッドなど、アプリのシンボルから直接参照されていないコードが除外されていました。モジュールは単一のオブジェクトファイルとしてビルドされるようになったため、その一部を参照するだけで全体がリンクされます。
* プロセスのライフサイクル内で SDK が複数回初期化された場合に、アプリ内統計トラッキングで発生する競合状態を修正しました。

#### Inbox
<span style={{ backgroundColor: 'rgba(212, 56, 13, 0.1)', color: '#D4380D', border: '1px solid #FFCCC7', padding: '2px 10px', borderRadius: '12px', fontSize: '0.85em', fontWeight: 'bold' }}>破壊的変更</span>

* Inbox API は Swift の並行処理モデルに従うようになりました。`presentInboxViewController`、`pushInboxViewController`、`getInboxViewController` はメインアクターにバインドされます。メインアクター外にある Swift の呼び出し箇所は更新が必要です。Objective-C の呼び出し元は影響を受けません。
* すべての Inbox の完了ブロックはメインスレッドで呼び出されるようになったため、完了ブロックから直接 UI を更新できます。
* `getInboxViewController` は常に完了ブロックを呼び出すようになり、指定された Workspace ID に SDK インスタンスが登録されていない場合は `nil` を渡します。
* Inbox のエントリはイミュータブルなスナップショットになりました。`isRead` や `clickedDate` などの既読状態の変更は、すでに保持しているエントリオブジェクトを変更するのではなく、次回の取得時に反映されます。エントリを既読にした後は、Inbox を再取得してください。

* **API 使用前の SDK 初期化の強制:** 初期化前に公開 API が呼び出された場合、SDK はすべてのビルド構成 (Debug、Release、TestFlight ビルド) で `fatalError` をトリガーするようになりました。これにより、誤った統合順序がサイレントに失敗するのではなく、すぐに表面化します。
* **公開 API が型付きタスクオブジェクトを返すように変更:** 以前は `Void` を返していた複数の API が、型付きタスクオブジェクトを返すようになりました。明示的な `Void` 戻り値型を持つ関数参照の代入はコンパイルできなくなりました。
* **Objective-C の列挙型を Swift に移行:** 公開 Objective-C 列挙型 `MoEngageInAppActionType` と `MoEngageNudgePosition` が Swift に移行されました (以下の移行表を参照してください)。

#### Core
<span style={{ backgroundColor: 'rgba(212, 56, 13, 0.1)', color: '#D4380D', border: '1px solid #FFCCC7', padding: '2px 10px', borderRadius: '12px', fontSize: '0.85em', fontWeight: 'bold' }}>破壊的変更</span>

* 以前は `Void` を返していた公開 API が型付きタスクオブジェクト (`MoEngageBaseTask` のサブクラス。例: `MoEngageTrackEventTask`、`MoEngageShowInAppTask`) を返すようになったため、`onSuccess` / `onFailure` または非同期の `result()` メソッドを通じて、呼び出しごとの成功または失敗を監視できます。変更されたモジュール: Core、InApp、Messaging。`@discardableResult` により無視された戻り値がカバーされるため、直接呼び出しと Objective-C の呼び出し元は変更なしでコンパイルできます。明示的な `Void` 戻り値型を持つ Swift の関数参照の代入はコンパイルできなくなりました。

  | API | 変更前 (コンパイル可能) | 変更後 (明示的なクロージャーが必要) |
  | :-- | :-- | :-- |
  | `trackEvent` (`MoEngageSDKAnalytics`) | `let trackFn: (String, MoEngageProperties?, String?) -> Void = MoEngageSDKAnalytics.sharedInstance.trackEvent` | `let trackFn: (String, MoEngageProperties?, String?) -> Void = { name, props, appID in`<br />`    _ = MoEngageSDKAnalytics.sharedInstance.trackEvent(name, withProperties: props, forAppID: appID)`<br />`}` |
  | `initializeDefaultLiveInstance` (`MoEngage`) | `let initFn: (MoEngageSDKConfig) -> Void = MoEngage.sharedInstance.initializeDefaultLiveInstance` | `let initFn: (MoEngageSDKConfig) -> Void = {`<br />`    _ = MoEngage.sharedInstance.initializeDefaultLiveInstance($0)`<br />`}` |

  直接呼び出しはそのまま変更不要です:

  ```swift
  // This continues to compile and behave exactly as before:
  ```
