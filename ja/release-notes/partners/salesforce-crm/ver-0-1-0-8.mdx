このリリースでは、堅牢な Custom Queue Framework、強化された例外ログ、改善された手動再試行機能、柔軟な設定が導入されています。また、UI の改善、レポートのサポート強化、およびいくつかの重要な修正も提供され、MoEngage との同期エクスペリエンスが効率化されます。

# 新機能

このバージョンで導入された新機能と改善点は次のとおりです。

### Custom Queue Framework (リアルタイム同期と履歴同期)

- 同期処理は専用の Sync Queue フレームワークを通じて実行されるようになり、マッピングされたオブジェクトのトリガーへの依存がなくなりました。
- 各同期は Sync Queue レコードでトラッキングされ、関連するすべての例外がトレーサビリティのために直接リンクされます。
- イベントの順序を維持するため、MoEngage との同期は FIFO ベースで行われます。
- 失敗時は最大 4 回まで自動的に再試行され、その後は無制限に手動で再試行できます。
- Flex Queue Limit と、満杯時の自動スケジュールにより、'Flex Queue full' エラーが解消されました。
- 制限が解除されるまで指数バックオフを使用する、インテリジェントな FUP (429) 再試行処理を行います。
- 同期レコードに最後の履歴同期のメタデータが含まれるようになり、可視性が向上しました。

### 例外処理の強化

- 例外に MoEngage API の詳細なレスポンスが記録されるようになりました。
- 例外は対応する Sync Queue レコードに直接リンクされます。
- デバッグを支援するため、再試行のたびに新しい例外エントリが記録されます。
- Salesforce に起因する既存の例外 (例: NullPointer) は、引き続きこれまでどおり記録されます。

### 同期ロジックの設定 (管理者が編集可能)

新しい Configuration カスタム設定により、管理者はコアとなる同期の動作を制御できます。次のレコードがデフォルトで作成されます。

| 設定名 | デフォルト値 | 説明 |
| :-- | :-- | :-- |
| Flex Queue Limit | 50 | バッチの実行を遅延させる前に組織で同時に実行できるジョブの最大数。 |
| Historic Sync Scheduler Time (min) | 5 | キューが満杯の場合に履歴同期を再試行するまでの遅延時間。 |
| Record Deletion Batch Size | 2000 | 古い成功レコードを削除する際のバッチサイズ。 |
| Record Deletion Interval (days) | 7 | 成功した Sync Queue レコードの保持期間。 |
| Sync Queue Batch Size | 20 | リアルタイム処理のバッチサイズ。 |
| Sync Queue Scheduler Time (min) | 5 | キューが満杯の場合にリアルタイム同期を再試行するまでの遅延時間。 |

管理者は、_Setup_ → _Custom Settings_ → _Configuration_ でこれらの値を変更できます。有効な値のみを使用するようにしてください。

### 手動再試行 (管理者のみ)

- MoEngage Admin 権限セットを持つユーザーが利用できます。
- 4 回の自動再試行がすべて終わった後、失敗した Sync Queue レコードに再試行オプションが表示されます。
- 再試行オプションは、次の場合に失敗した Sync Queue レコードに表示されます。
  - 4 回の自動再試行がすべて終わった後、または
  - 次のような再試行できないエラーが原因で同期が失敗した場合:
    - Account Suspended
    - Authentication Required
    - BlockedClient
    - MissingAttributeError
- 手動再試行は、リアルタイム同期 (即時再試行) と履歴同期 (スケジュールされたバッチ) の両方をサポートします。

### 項目レベルセキュリティ (FLS) のバイパス

- 同期時に、マッピングされたフィールドの FLS チェックがバイパスされるようになりました。
- MoEngage User/Admin 権限セットを持つユーザーは、マッピングされたすべてのフィールドへの項目レベルのアクセス権がなくてもレコードを同期できます。

### 成功したレコードの自動クリーンアップ

- Delete Processed Syncs という名前のジョブが毎日午前 1:00 に実行され、古い成功した同期と関連データを削除します。
- Record Deletion Interval (デフォルト: 7 日) によって制御されます。
- 権限関連の失敗を避けるため、管理者は自身のユーザーコンテキストでジョブを再スケジュールする必要があります (Setup → Scheduled Jobs)。

### UI の改善

- ライブステータスを取得するための Reload ボタンが Data Sync Field Mapping コンポーネントに追加されました。
- Sync ボタンのラベルは、最後の同期ステータスに基づいて動的に更新されます。
  - Sync, Sync Scheduled, Sync Processing, Sync Successful, Sync Partial Success, Sync Failed
- Sync ボタンをクリックすると、ライブトラッキングのために最新の Sync Queue レコードにリダイレクトされます。
- 新しい同期は、最後の同期ステータスが Successful、Failed、または Partial Success の場合にのみ開始できます。
- ツールチップに次の内容が表示されるようになりました。
  - "Run Historical Sync" (許可されている場合)
  - "Historical Sync Running" (進行中の場合)

### レポートの機能強化

- Sync Queue オブジェクトと Exceptions オブジェクトをレポートで使用できるようになりました。
- ユーザーは、同期アクティビティとエラー分析の両方についてカスタムレポートを作成できます。

## システムの動作の更新

- FLS のバイパスにより、マッピングされたすべてのフィールドへのアクセス権がないユーザーでもエラーが発生しなくなりました。
- クライアント側のバッチがマッピングされたオブジェクトのレコードを変更しても同期が失敗しなくなり、それらのレコードは\
  適切に処理されるようになりました。

## デプロイと管理者向けの注意事項

- インストール後のスクリプト:
  - Configuration レコードを作成します。
  - Delete Processed Syncs ジョブをスケジュールします (既に存在する場合は重複しません)。
- トリガーのデプロイとテストクラスは、Metadata API を介して管理されるようになりました。
