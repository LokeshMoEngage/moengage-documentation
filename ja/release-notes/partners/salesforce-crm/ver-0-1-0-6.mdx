このバージョンでは、バッチサイズオプションの拡大と同期メカニズムの内部ロジックの変更により、履歴同期が改善されています。

# 新機能

このバージョンで導入された新機能と改善点は次のとおりです。

### 履歴同期のバッチサイズオプションの強化

- 履歴同期機能に追加のバッチサイズオプションを導入しました。
- 新しいバッチサイズとして、1、5、10、15、20、25、50、75、100、125、150、175、200 のオプションを利用できるようになりました。

### MoEngage へのユーザー同期における `customer_id` フィールドの必須チェック

- 履歴同期とリアルタイム同期のロジックを更新し、customer\_id 属性のマッピングを検証するようにしました。
- **同期の動作** : `customer_id` にマッピングされた Salesforce フィールドが空の場合、そのレコードは MoEngage と同期されません。フィールドに値がある場合にのみ、レコードが MoEngage と同期されます。

### MoEngage へのイベント同期における customer\_id フィールドと action フィールドの必須チェック

- 履歴イベント同期とリアルタイムイベント同期の両方のロジックを強化し、`customer_id` と action のマッピングが存在するかを検証するようにしました。
- **同期の動作** : `customer_id` または action にマッピングされたフィールドが空の場合、そのレコードは MoEngage への同期のために送信されません。

<Info>
  以前に MoEngage と同期されたレコードで、必須の MoEngage 属性 (例: `customer_id` や action) にマッピングされた Salesforce フィールドの値が後でクリアされた (空になった) とします。その場合、そのレコードは MoEngage と同期されなくなります。\
  これにより、Salesforce と MoEngage の間でデータの不整合が生じる可能性があります。
</Info>
