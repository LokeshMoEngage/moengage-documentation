このリリースでは、システムの安定性が向上し、同期エラーが減少し、古いフィールドが整理されました。これらの機能強化に加え、UI の修正、よりスマートなエラー処理、レイアウトの更新により、管理者とユーザーの双方によりスムーズなエクスペリエンスを提供します。

# 新しい変更点と機能強化

## (フィールドの非推奨化) Sync オブジェクト

  * `Historical Sync?` チェックボックスフィールドは非推奨になりました。
  * **新規インストール**の場合、このフィールドは表示されません。
  * アップグレードされた組織では、このフィールドが引き続き表示される場合がありますが、安全に削除できます。Object  
Manager に通知が表示されます。

![](/images/partner_42483941052052.png)

## 新しいフィールドの追加

  * 名前: `Last Historic Sync Apex Batch Job Id`
  * タイプ: 数式フィールド
  * 値: 最後の履歴同期の 15 文字の Apex Batch Job ID。



このフィールドの値を使用して、履歴同期の進行状況をリアルタイムで監視できます。詳細については、[こちら](/ja/partner-guide/data-and-analytics/crm/salesforce-crm-native/sync-salesforce-objects-to-moengage)を参照してください。

## フィールドラベルの変更

  * `Last Historic Sync Batch Job Id` は `Last Historic Sync Batch Raw Job Id` という名前に変更されました。 
  * `Link to Last Historic Sync Queue Record` は `Last Historic Sync Queue Record` という名前に変更されました。



## Sync オブジェクト: ページレイアウトの更新

<Info>
ページレイアウトの変更は、パッケージのアップグレード時に自動的に適用されません。これらの更新を反映するには、お客様が "Sync Layout" を手動で更新する必要があります。
</Info>
### UI から次のフィールドを削除しました:

  1. `Last Historic Sync Batch Raw Job Id`
  2. `Last Historic Sync Queue ID`



### UI に次のフィールドを追加しました:

  1. `Last Historic Sync Apex Batch Job Id`
  2. `Last Historic Sync Queue Record`



# 問題の修正

## 履歴同期中の DML 例外

### 問題

レコードの customer_id が空の場合、MoEngage Events の同期が失敗していました。システムが  
次の DML エラーをスローしていました:  
`INVALID_OR_NULL_FOR_RESTRICTED_PICKLIST, Error Type: bad value for restricted picklist field: customer_id can not be empty`

### 修正内容

DML 例外の代わりに、このようなエントリに対して Failed Sync Queue レコードが作成されるようになり、同期の信頼性が向上しました。

## (UI の修正) "Sync Partial Success" ボタン

  * macOS の UI でボタンが 2 行に分かれて表示されていました。
  * **解決済み:** 1 行で正しく表示されるようになりました。



## 手動再試行: 未処理の例外

  * Salesforce プラットフォームの問題により、手動再試行中にエラーが発生していました。
  * **解決済み:** 手動再試行が完全に機能するようになりました。
