MoEngage は、共有プラットフォームをすべてのお客様にとって高速かつ信頼性の高い状態に保つため、REST API にレート制限を適用しています。特定のエンドポイントで別途記載がない限り（クライアント単位またはコンシューマー単位のものもあります）、制限は**ワークスペース単位**で適用され、制限を超えたリクエストは `HTTP 429 Too Many Requests` レスポンスで拒否されます。

以下の制限の多くはデフォルト値です。一部の制限は、正当な必要性に基づいてワークスペースごとに引き上げることができます。引き上げについては、MoEngage のカスタマーサクセスマネージャー（CSM）またはサポートチームにお問い合わせください。

<Note>
  レート制限とペイロードの上限は、それぞれ独立した制御です。リクエストがレート制限内であっても [ペイロードサイズ](#payload-size-limits) を超えると拒否される場合があり、その逆もあります。各エンドポイントのリファレンスページに記載されている制限が正式な値であり、以下の表はそれらをまとめたものです。
</Note>

## エンドポイント別のレート制限

エンドポイントは、API リファレンスのナビゲーションに合わせて製品領域ごとにグループ化されています。複数のエンドポイントが 1 つのプールを共有している場合、制限はそれらすべてにまたがって適用されます。

## ペイロードサイズの制限

ペイロードの上限は、レート制限とは独立して適用されます。上限を超えるリクエストは拒否されます。エンドポイントに応じて、通常は `HTTP 413`（ペイロードが大きすぎる）または `HTTP 400` が返されます。

| API / エンドポイント | 最大ペイロード |
| --- | --- |
| Track User (`/customer/{app_id}`) | 1 リクエストあたり 128 KB |
| Merge Users (`/customer/merge`) | 1 リクエストあたり 128 KB |
| Cohort sync (`/v1/integrations/cohortsync`) | 1 リクエストあたり 128 KB |
| GDPR / CCPA (`/opengdpr_requests/{appId}`) | 1 リクエストあたり 128 KB、1 ユーザーレコードあたり 100 KB |
| Custom Segments — File | 1 ファイルあたり 150 MB |
| Catalog API | 1 リクエストあたり 5 MB |
| Recommendations API | 1 リクエストあたり 1 MB |
| Live Activities (`/live-activity/broadcast/*`) | 1 リクエストあたり 5,120 バイト（iOS） |
| Email bulk resubscribe (`/emails/v1.0/bulk-resubscribe`) | 1 リクエストあたり 100 件の受信者アドレス |
