MoEngage Push API を使用すると、プッシュ通知をトリガーできます。高スループットのトランザクションおよびマーケティングのユースケース向けに設計されており、複雑なターゲティングロジックと、受信者ごとの高度なパーソナライズをサポートしています。

<Note>
  特定のユースケースに対応する API を選択してください。

  - **トランザクション:** システムによってトリガーされるイベント（OTP、ステータス更新など）には、Push API を使用します。
  - **非トランザクション:** マーケティング、プロモーション、ブロードキャストメッセージには、[Push Campaigns API](/ja/api/create-campaigns/create-campaign) の使用を強く推奨します。
</Note>

この API は次の用途に使用します。

- **セグメントをターゲティング:** すべてのユーザーまたは事前定義された特定のセグメントに通知を送信します。
- **個人をターゲティング:** Email、Mobile Number、Unique ID などの一意の属性を使用して、単一のユーザーにリーチします。
- **大規模なパーソナライズ:** Jinja テンプレートを使用して、ユーザー固有のデータを通知ペイロードに動的に挿入します。
- **すべてのプラットフォームにリーチ:** 1 回のリクエストで Android、iOS、Web に送信します。

[Push API (V5)](/ja/api/push/push-api) で通知を送信すると、キャンペーンが自動的に作成されます。事前にダッシュボードでキャンペーンを作成する必要はありません。

## API バージョン

| バージョン | エンドポイント | ステータス | 概要 |
| :--- | :--- | :--- | :--- |
| **V5** | [Push API (V5)](/ja/api/push/push-api) | サポート対象 | `POST https://api-{dc}.moengage.com/v5/push/notifications`。認証情報は `Authorization` ヘッダーで送信し、`targetAudience` に対応する `X-MOE-Query-Type` ヘッダーが必須です。リクエストフィールドは camelCase で、レスポンスは標準の HTTP ステータスコードとともに `{response_id, type, data}` エンベロープを使用します。 |
| **v2.1** | [Push API（v2.1、レガシー）](/ja/api/push/push-api-v2-1-legacy) | 2026 年 11 月 30 日以降は動作停止 | `POST https://pushapi-{dc}.moengage.com/v2.1/transaction/sendpush`。`appId` と `signature` を `X-MOE-APPKEY` ヘッダーと `X-MOE-PushAPI-Signature` ヘッダーとして送信し、さらに `targetAudience` に対応する `X-MOE-Query-Type` ヘッダーを送信します。 |
| **v2** | [Push API（v2、レガシー）](/ja/api/push/push-api-v2-legacy) | 2026 年 11 月 30 日以降は動作停止 | `POST https://pushapi-{dc}.moengage.com/transaction/sendpush`。元のバージョンで、`appId` と `signature` はリクエストボディのフィールドとして送信します。リクエストに応じてのみ利用可能です。 |

<Warning>
  **v2.1 および v2 エンドポイントは 2026 年 10 月 30 日をもって非推奨となり、2026 年 11 月 30 日以降は動作しなくなります。** これらのエンドポイントは今後保守されません。それまでに、すべての連携を [Push API (V5)](/ja/api/push/push-api) に移行してください。
</Warning>

## オーディエンスの種類

`targetAudience` は、通知の受信者と `campaignName` の扱いを決定します。対応する値を `X-MOE-Query-Type` ヘッダーで送信してください（大文字と小文字は区別されません）。

| `targetAudience` | `X-MOE-Query-Type` | キャンペーンの動作 | `campaignDelivery.type` |
| :--- | :--- | :--- | :--- |
| `User` | `user`、または `bulkUserRequest` が `true` の場合は `bulk users` | 同じ `campaignName` を渡す呼び出し間でキャンペーンが再利用されます。 | 常に即時送信されます。 |
| `Custom Segment` | `custom segment` | 呼び出しごとに新しいキャンペーンが作成されるため、`campaignName` は一意である必要があります。 | `soon`、`later`、または `periodic`。デフォルトは `soon` です。 |
| `All Users` | `all users` | 呼び出しごとに新しいキャンペーンが作成されるため、`campaignName` は一意である必要があります。 | `soon`、`later`、または `periodic`。デフォルトは `soon` です。 |

<Note>
  一部のワークスペースでは、`User` オーディエンスのみが有効になっています。そのようなワークスペースでは、`Custom Segment` または `All Users` をターゲットとするリクエストは `403` を返します。これらのオーディエンスに送信するには、カスタマーサクセスマネージャー（CSM）または MoEngage サポートにお問い合わせください。
</Note>

## よくある質問

<AccordionGroup>
  <Accordion title="Push API はサイレント通知をサポートしていますか？">
    はい、iOS ではサポートしています。`payload.IOS.contentAvailable` を `1` に設定すると、サイレントのバックグラウンド更新を送信できます。
  </Accordion>
  <Accordion title="HTML を使用して通知テキストをフォーマットできますか？">
    はい、ベーシックテンプレートは、サポートされているプラットフォームでテキストをフォーマットするための標準的な HTML タグをサポートしています。
  </Accordion>
  <Accordion title="特定のユーザーでパーソナライズが失敗した場合はどうなりますか？">
    プラットフォームのペイロード内に `fallback` オブジェクトを追加します。ユーザー属性が存在しないなどの理由でパーソナライズのロジックが失敗した場合、MoEngage は代わりにフォールバックコンテンツを送信します。
  </Accordion>
  <Accordion title="デバイストークンを直接使用してユーザーをターゲティングするにはどうすればよいですか？">
    `targetUserAttributes.attribute` を `PUSH_ID` に設定し、`targetUserAttributes.attributeValue` にデバイストークンを渡します。
  </Accordion>
  <Accordion title="request_id と response_id の違いは何ですか？">
    `request_id` は、リクエストボディで `requestId` として送信するトレース ID です。この値は `data.request_id` でそのまま返されます。`response_id` はレスポンス自体を識別します。MoEngage サポートに問い合わせる際は、`response_id` をお伝えください。
  </Accordion>
  <Accordion title="通知が受け付けられたことを示すステータスコードはどれですか？">
    `201` は、通知が送信のために受け付けられたことを意味します。それ以外のステータスコードはすべてエラーであり、理由は `error.code` と `error.message` に示されます。
  </Accordion>
  <Accordion title="RPM と時間の両方で配信をスロットリングできますか？">
    `advancedSettings.campaignThrottleRpm` と `advancedSettings.campaignThrottleTime` の両方を設定した場合は、`campaignThrottleRpm` が優先されます。ワークスペースの制限を超えるスロットル値を指定すると `422` が返されます。
  </Accordion>
  <Accordion title="Push API を使用するには IP ホワイトリストが必要ですか？">
    いいえ。任意ですが、承認済みのサーバーのみがワークスペースにアクセスできるように、MoEngage では設定を推奨しています。[IP ホワイトリスト](#ip-whitelisting) を参照してください。
  </Accordion>
</AccordionGroup>
