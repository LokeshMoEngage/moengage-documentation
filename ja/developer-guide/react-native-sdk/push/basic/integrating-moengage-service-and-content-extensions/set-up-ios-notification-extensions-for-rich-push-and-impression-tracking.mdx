このガイドの手順はすべて Xcode で実行します。作業を始める前に、Xcode で `ios/YourApp.xcworkspace` を開いて iOS プロジェクトを開いてください。

このガイドでは、MoEngage のサービス拡張機能とコンテンツ拡張機能を iOS アプリケーションに統合する方法について説明します。これらの拡張機能により、通知インプレッションのトラッキング、リッチメディア（画像、GIF、動画）のサポート、およびリッチプッシュ通知テンプレートの使用が可能になります。

## サービス拡張機能とコンテンツ拡張機能の統合

これらの拡張機能がない場合、MoEngage はプッシュインプレッションをトラッキングできず、[リッチメディア](https://www.moengage.com/docs/user-guide/campaigns-and-channels/mobile-push/notification-features-and-behavior/gifs-in-push-notifications)通知はプレーンテキストにフォールバックし、[リッチプッシュテンプレート](https://www.moengage.com/docs/user-guide/campaigns-and-channels/mobile-push/create/push-templates)はフォールバックテンプレートで表示されます。

| ユースケース | サービス拡張機能（ステップ 2） | コンテンツ拡張機能（ステップ 3） | MoEngageRichNotification（ステップ 4） | Integrator Tool のフラグ |
| :-- | :-- | :-- | :-- | :-- |
| プッシュインプレッションのトラッキング | ✅ 必須 | — | — | （デフォルト） |
| プッシュでのリッチメディア（画像、GIF、動画） | ✅ 必須 | — | ✅ 必須 | （デフォルト） |
| MoEngage リッチプッシュテンプレート（カルーセル） | ✅ 必須 | ✅ 必須 | ✅ 必須 | `--enable-push-notification-templates` |

### ステップ 2: サービス拡張機能の設定

サービス拡張機能は、通知インプレッションをトラッキングし、リッチメディアコンテンツをダウンロードします。

1. [App Identifier を作成します](https://developer.apple.com/help/account/identifiers/register-an-app-id): `[appBundleId].[serviceExtensionName].` の形式を使用します。
   1. `[appBundleId]` をアプリケーション固有のバンドル識別子に置き換えます。
   2. `[serviceExtensionName]` を任意の名前（デフォルトは _MoEngageNotificationService_）に置き換えます。例えば、アプリのバンドル識別子が `com.org.app` で、拡張機能の名前が `NotificationService` の場合、識別子は `com.org.app.NotificationService` になります。

<Info>
  既存の Notification Service Extension がある場合は、新しく作成せずにそれを再利用できます。[ステップ 5 の Run Script Phase](#step-5-integrate-the-extension-integrator-tool) を設定する際に、`--notification-service-extension-name` フラグでその名前を渡してください。ツールはカスタムコードを上書きすることなく、必要な MoEngage のロジックを挿入します。
</Info>

2. ステップ 1 で作成したサービス拡張機能の識別子を選択し、**Capabilities** タブを開いて [**App Groups**](https://developer.apple.com/help/account/identifiers/register-an-app-group) を追加します。`AppGroupName` キーと一致する名前を入力します。

### ステップ 3: コンテンツ拡張機能の設定（オプション）

コンテンツ拡張機能は、MoEngage のリッチプッシュ通知テンプレートを使用する場合にのみ必要です。

1. [App Identifier を作成します](https://developer.apple.com/help/account/identifiers/register-an-app-id): `[appBundleId].[contentExtensionName].` の形式を使用します。
   1. `[appBundleId]` をアプリケーション固有のバンドル識別子に置き換えます。
   2. `[contentExtensionName]` を任意の名前（デフォルトは _MoEngageNotificationContent_）に置き換えます。例えば、アプリのバンドル識別子が `com.org.app` で、拡張機能の名前が `NotificationContent` の場合、識別子は `com.org.app.NotificationContent` になります。
2. コンテンツ拡張機能の識別子を選択し、**Capabilities** タブを開いて [**App Groups**](https://developer.apple.com/help/account/identifiers/register-an-app-group) を追加します。`AppGroupName` キーと一致する名前を入力します。

### ステップ 4: MoEngageRichNotification の統合（オプション）

以下のいずれかのプッシュ通知機能をサポートする必要がある場合は、`MoEngageRichNotification` を統合します。

- **リッチメディア** — 通知バナーに画像、GIF、または動画を表示します
- **リッチプッシュテンプレート** — カルーセルなどのインタラクティブな通知レイアウトを表示します

<Info>
  ステップ 3 で説明したコンテンツ拡張機能を統合している場合、このステップは必須です。
</Info>

<Tabs>
  <Tab title="Swift Package Manager (SPM)">
    SPM を使用して `MoEngageRichNotification` をインストールするには、以下の手順を実行します。

    1. **File \> Add Package** に移動します。
    2. リポジトリ URL を入力します。
       - `https://github.com/moengage/apple-sdk.git`
    3. **master** ブランチまたは特定のバージョンを選択し、**Add Package** を選択します。
    4. パッケージのターゲットをアプリケーションに設定します。
  </Tab>
  <Tab title="CocoaPods">
    <Warning>
      **情報** CocoaPods は非推奨になる予定です。MoEngage では、すべての新規統合に Swift Package Manager を使用することを推奨しています。詳細については、[こちら](/ja/developer-guide/ios-sdk/sdk-integration/basic/sdk-integration)を参照してください。
    </Warning>

    1. アプリのターゲット内の `Podfile` に次の行を追加します。

    <Info>
      `react-native-moengage` パッケージは autolinking によってすでに `MoEngage-iOS-SDK` を取り込んでいるため、追加が必要なのは `RichNotification` サブスペックのみです。
    </Info>

    ```ruby lines wrap
    pod 'MoEngage-iOS-SDK/RichNotification'
    ```

    2. pod install を実行します。

    ```ruby lines wrap
     pod repo update
     pod install
    ```
  </Tab>
</Tabs>

### ステップ 5: 拡張機能 Integrator Tool の統合

ビルドプロセスにカスタムスクリプトを追加して、拡張機能の設定を自動化します。

1. Xcode でアプリケーションのターゲットを選択し、**Build Phases** に移動して **\+** をクリックし、**New Run Script Phase** を追加します。
<Frame>
     <img
       src="/images/newrunscriptphase.png"
       alt="New Run Script Phase"
       title="New Run Script Phase"
       className="mr-auto"
       style={{ width:"54%" }}
     />
</Frame>
2. **Input Files** セクションに次のパスを追加します。

- `$(BUILT_PRODUCTS_DIR)/$(INFOPLIST_PATH)`
- `$(INSTALL_DIR)/$(INFOPLIST_PATH)`

<Frame>
  <img
    src="/images/path-1.png"
    alt="パス 1"
    title="パス 1"
    style={{ width:"54%" }}
    className="mr-auto"
  />
</Frame>

3. 上の画像の **integrate\_extensions** を置き換えて、使用している依存関係マネージャーに対応するコマンドを入力します。

<Info>
  すでにスクリプトフェーズを追加して入力ファイルを設定している場合は、以下で説明するように実行コマンドを更新するだけで済みます。
</Info>

<Tabs>
  <Tab title="Swift Package Manager (SPM)">
    ```bash Swift Package Manager (SPM) lines wrap
    case "$ACTION" in
      install) SPM_ROOT="$OBJROOT/../../../../.." ;;   # xcodebuild archive
      *)       SPM_ROOT="$OBJROOT/../.." ;;            # build / run from Xcode
    esac
    "$SPM_ROOT/SourcePackages/artifacts/apple-sdk/moengage-extensions-integration/moengage-extensions-integration.artifactbundle/moengage-extensions-integration/bin/moengage-extensions-integration" $OPTIONS
    ```
  </Tab>
  <Tab title="CocoaPods">
    ```bash CocoaPods lines wrap
    ${PODS_ROOT}/MoEngageExtensionsIntegration/moengage-extensions-integration.artifactbundle/moengage-extensions-integration/bin/moengage-extensions-integration $OPTIONS
    ```
  </Tab>
</Tabs>

#### 使用可能なオプション

`$OPTIONS` を以下の 1 つ以上に置き換えます。

| オプション | 説明 |
| :-- | :-- |
| `--enable-push-notification-templates` | ステップ 3 のコンテンツ拡張機能を使用する場合に必須です。 |
| `--notification-service-extension-name $CUSTOM_SERVICE_EXTENSION_NAME` | サービス拡張機能のカスタム名を設定します。カスタムのサービス拡張機能の実装からこのツールに移行する場合に使用します。（デフォルト: `MoEngageNotificationService`） |
| `--notification-content-extension-name $CUSTOM_CONTENT_EXTENSION_NAME` | コンテンツ拡張機能のカスタム名を設定します。カスタムのコンテンツ拡張機能の実装からこのツールに移行する場合に使用します。（デフォルト: `MoEngageNotificationContent`） |

### コマンド例（SPM）

`NotificationService` という名前のサービス拡張機能と `NotificationContent` という名前のコンテンツ拡張機能を統合する場合、SPM の完全なコマンドは次のようになります。

```bash Swift Package Manager (SPM) lines wrap
case "$ACTION" in
  install) SPM_ROOT="$OBJROOT/../../../../.." ;;   # xcodebuild archive
  *)       SPM_ROOT="$OBJROOT/../.." ;;            # build / run from Xcode
esac
"$SPM_ROOT/SourcePackages/artifacts/apple-sdk/moengage-extensions-integration/moengage-extensions-integration.artifactbundle/moengage-extensions-integration/bin/moengage-extensions-integration" --enable-push-notification-templates --notification-service-extension-name NotificationService --notification-content-extension-name NotificationContent
```

4. **サンドボックスの無効化:** アプリケーションターゲットの **Build Settings** で、**USER\_SCRIPT\_SANDBOXING** を **No** に設定します。

## トラブルシューティングとよくある質問

<AccordionGroup>
  <Accordion title="Integrator Tool がエラーを返しました。どのように解決すればよいですか？">
    詳細な情報については、ビルドログを確認してください。

    <Frame>
      <img
        src="/images/errorlogs.png"
        alt="エラーログ"
        title="エラーログ"
        style={{ width:"79%" }}
        className="mr-auto"
      />
    </Frame>

    一般的な原因には次のようなものがあります。

    - **不正な統合:** セットアップが [サービス拡張機能とコンテンツ拡張機能の統合](/ja/developer-guide/ios-sdk/push/basic/ios-push-integration-tutorial)ガイドに従っていません。
    - **設定の欠落:** `Info.plist` に必要な MoEngage の設定オプションがありません。
    - **App Group の不一致:** `Info.plist` で指定した `AppGroupName` が、サービス拡張機能およびコンテンツ拡張機能のバンドル識別子の Capabilities、またはアプリケーションの Entitlements に含まれていません。
    - **環境の不一致:** プロビジョニングプロファイルが特定のビルド環境用に作成されていません（例: App Store ビルドの生成時に Development プロファイルを使用している）。
    - **カスタムディレクトリの問題:** プロビジョニングプロファイルがデフォルトの Xcode ディレクトリに保存されていません。[追加設定用のビルド設定](#troubleshooting-and-faqs)を使用してカスタムパスを渡してください。
    - **証明書の問題:** プロビジョニングプロファイルの生成時に、証明書の設定が欠落しているか誤っています。
    - **プロファイルの有効期限切れ:** プロビジョニングプロファイルの有効期限が切れています。プロファイルを再生成して再ダウンロードする必要があります。
  </Accordion>

  <Accordion title="サービス拡張機能とコンテンツ拡張機能の両方を統合する必要がありますか？">
    いいえ。サービス拡張機能は、通知インプレッションのトラッキングとリッチメディア（画像/GIF/動画）のダウンロードに必須です。コンテンツ拡張機能は、MoEngage のインタラクティブな _リッチプッシュテンプレート_（カルーセルやカスタムボタンレイアウトなど）を使用する場合にのみ必要です。
  </Accordion>

  <Accordion title="「App Group」の設定が必須なのはなぜですか？">
    iOS の拡張機能は、メインアプリケーションとは別のサンドボックスで実行されます。**App Group** は共有コンテナを作成し、メインアプリの MoEngage SDK が認証トークン、ユーザーデータ、ローカルストレージを拡張機能と共有できるようにします。これがないと、拡張機能はユーザーを検証したり、インプレッションを正しくトラッキングしたりできません。
  </Accordion>

  <Accordion title="Build Settings で「User Script Sandboxing」を無効にする必要があるのはなぜですか？">
    **Extension Integrator Tool** は、標準の Xcode サンドボックス外のシステムフォルダにあるプロジェクトのビルド成果物とプロビジョニングプロファイルにアクセスする必要があります。`ENABLE_USER_SCRIPT_SANDBOXING` が **Yes** に設定されていると、スクリプトがブロックされ、ビルドフェーズ中に「Permission Denied」エラーが発生します。
  </Accordion>

  <Accordion title="このツールで複数のビルド環境（Dev/Staging/Prod）を扱うにはどうすればよいですか？">
    追加のビルド設定を使用して、ローカルビルドと CI ビルドの両方で Integrator Tool に特定の設定入力を提供できます。

    - **`MOENGAGE_EXTENSION_PROFILES_SEARCH_PATHS`:** プロビジョニングプロファイルを検索する追加のフォルダを指定する場合に使用します。デフォルトでは、ツールは標準の Xcode ディレクトリを検索します。
      - `~/Library/Developer/Xcode/UserData/Provisioning Profiles`
      - `~/Library/MobileDevice/Provisioning Profiles` プロビジョニングプロファイルがこれらのフォルダにない場合は、このビルド設定で追加のパスを指定します。
    - **`MOENGAGE_NOTIFICATION_SERVICE_EXTENSION_PROFILE`:** Notification Service Extension のプロビジョニングプロファイルのファイル名を明示的に指定します。ツールはプロビジョニングプロファイルを検索する代わりに、このファイル名を使用します。プロファイルは上記のいずれかのフォルダに存在する必要があります。ツールが正しいプロビジョニングプロファイルを選択できない場合に、このオプションを使用してください。
    - **`MOENGAGE_NOTIFICATION_CONTENT_EXTENSION_PROFILE`:** Notification Content Extension のプロビジョニングプロファイルのファイル名を明示的に指定します。ツールはプロビジョニングプロファイルを検索する代わりに、このファイル名を使用します。プロファイルは上記のいずれかのフォルダに存在する必要があります。ツールが正しいプロビジョニングプロファイルを選択できない場合に、このオプションを使用してください。
  </Accordion>

  <Accordion title="通知でリッチメディアが表示されません。何が問題ですか？">
    これは通常、次の 3 つの技術的なギャップのいずれかに起因します。

    1. **App Group の不一致:** `Info.plist` の `AppGroupName` 文字列が Entitlements ファイルと完全に一致していることを確認してください。
    2. **ペイロードのタイムアウト:** iOS は拡張機能にメディアのダウンロード時間として約 30 秒を与えます。アセットが大きすぎる場合やネットワークが遅い場合は、失敗してプレーンテキストにフォールバックします。
  </Accordion>

  <Accordion title="このツールはカスタムの Derived Data パスや CI/CD で動作しますか？">
    はい。ステップ 5 のスニペットにある `case "$ACTION"` ブロックはすべてのビルドアクションに対応しているため、記載どおりに使用してください。

    CI 環境でカスタムの Derived Data またはビルドディレクトリを使用しており、パスの解決が失敗する場合は、代わりに `moengage-extensions-integration` バイナリへの絶対パスを指定してください。
  </Accordion>
</AccordionGroup>
