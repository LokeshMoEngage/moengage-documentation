# Manifest ベースの統合からの移行

SDK バージョン `9.0.00` では、Java/Kotlin コードを介して MoEngage SDK を統合する新しい方法を導入し、Manifest ファイルのメタデータを使用した統合を非推奨にしました。バージョン `10.0.00` 以降、Manifest のメタデータを使用する統合のサポートを削除します。コードベースの統合への移行の詳細については、[ドキュメント](https://www.moengage.com/docs/developer-guide/android-sdk/migration/moving-from-manifest-to-code-based-integration)を参照してください。

# 動作の変更

* セルフハンドルのアプリ内メッセージはメインスレッドで配信されます
* GCM のサポートを削除しました
* Baidu のサポートを削除しました
* SDK バージョン `10.0.00` より前は、アプリ内メッセージで GIF を表示するために SDK は Fresco に依存していました。SDK バージョン `10.0.00` 以降、SDK は GIF の表示に Glide を使用します。GIF を使用する場合は、アプリケーションに Glide を依存関係として追加してください。
* "nav\_provier"、"nav\_source" は、プッシュペイロードやディープリンクの URL に含まれなくなります。
* SDK の初期化時に送信者 ID が指定されている場合、`google-services.json` ファイルのデフォルトの送信者 ID の代わりに、その ID がトークン登録に使用されます。
* InApp コールバック - InApp コールバックリスナーは、インターフェースではなく具象クラスになりました。
* InstallReceiver は SDK から削除されました。マニフェストに `com.moe.pushlibrary.InstallReceiver` を追加している場合は削除してください。

# 10.0.00 で非推奨になった API

バージョン `10.0.00` では、パフォーマンスの向上と今後のより良いサポートのために、いくつかの API を非推奨にしました。以下は非推奨の API とその代替の一覧です。最新のメソッドに更新してください。

| 非推奨の API | 代替 API |
| --- | --- |
| MoEngage.Builder#setNotificationType(int) | MoEngage.Builder#enableMultipleNotificationInDrawer() |
| PayloadBuilder | Properties |
