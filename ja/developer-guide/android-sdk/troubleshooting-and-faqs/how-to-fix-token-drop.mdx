# トークンのドロップとは?

トークンのドロップとは、MoEngage プラットフォームがアプリケーションのすべてのユーザーのプッシュトークンを保持していない状況やケースを指します。  
たとえば、アプリケーションが毎日 100 人の新規ユーザーにインストールされているにもかかわらず、MoEngage プラットフォームには 60 人分のトークンしかない場合、これはトークンのドロップとみなされます。

# 修正が重要な理由

エンドユーザーにプッシュ通知を送信するにはプッシュトークンが必要であり、トークンがないとプッシュを送信できません。そのため、ユーザーのエンゲージメントを維持するには、トークンのドロップを修正することが非常に重要です。

# トークンのドロップが発生する理由

トークンのドロップは、さまざまな理由で発生する可能性があります。

* インターネット接続が不安定または接続がないため、Firebase SDK がトークンを生成しない。
* Play 開発者サービスのバージョンの不一致により、デバイス上の Play 開発者サービスのバージョンがアプリケーションで使用されている Firebase のバージョンと互換性がない。
* アプリケーションにトークンを MoEngage SDK に渡すかどうかを決定する内部チェックやフラグがあり、トークンの生成時にそのフラグが無効になっているため、トークンが MoEngage SDK に渡されない。
* 統合エラーにより、プッシュトークンが MoEngage SDK に渡されていない。

# 修正方法

* アプリ起動時にトークンが利用できない場合は、トークンの生成に成功するまでアプリケーションが定期的にトークンの生成を試行する再試行メカニズムを導入します。
* トークンを MoEngage SDK に渡す前にチェックを行っている場合は、アプリの初回起動時にトークンが渡されるように、そのチェックを削除するか、フラグをデフォルトで有効にしておきます。
* [プッシュトークンの登録と表示 (レガシー)](/ja/developer-guide/android-sdk/push/basic/push-token-registration-and-display-legacy) を再確認し、トークンを渡す実装が正しく行われているかを確認します。

# 再試行メカニズムに関する提案

アプリケーションは、アプリを起動するたびにプッシュトークンの生成を試行し、MoEngage SDK に渡すことをお勧めします。何らかの理由でアプリが Firebase API からトークンを取得できない場合は、成功するまで、またはアプリケーションがフォアグラウンドになるまで、定期的に登録を再試行する必要があります。

再試行メカニズムの設定方法の例として、こちらの[ライブラリ](https://github.com/umang91/fcm-client-lib)を参照できます。または、メカニズムを自分で設定する代わりに、このライブラリを使用することもできます。

<Info>
  * これは MoEngage の公式ライブラリではありません。このライブラリは MoEngage の開発者の 1 人によって作成されたものです。
  * MoEngage SDK には、トークンのドロップを減らすための再試行メカニズムがすでに組み込まれています。トークンのドロップを最小限 (通常は 2% 未満) に抑えるために、MoEngage SDK にトークンの登録を任せることをお勧めします。MoEngage SDK にプッシュトークンの管理を任せる方法の詳細については、[プッシュトークンの登録と表示 (レガシー)](/ja/developer-guide/android-sdk/push/basic/push-token-registration-and-display-legacy) を参照してください。
