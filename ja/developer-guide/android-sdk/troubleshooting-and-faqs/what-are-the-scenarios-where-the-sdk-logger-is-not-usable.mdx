---
title: "SDK ロガーが使用できないのはどのような場合ですか？"
description: "統合や UI の問題など、MoEngage SDK ロガーが役に立たないシナリオについて説明します。"
---

次のシナリオでは、SDK ロガーが正しく機能しない場合があります。

* **基本的な統合の問題**:
	+ **不適切な SDK 統合**: SDK が正しく統合されていない場合に発生します。
	+ **古い SDK バージョン**: SDK のバージョンが次より古い場合です。
		- Android SDK: Native 13.4.00
		- React Native: 10.3.00
		- Flutter: 9.0.0
		- Cordova: 9.0.0
		- Capacitor: 5.0.0
	+ **統合漏れ**: （要件どおりの）場所でプラグインが初期化されていない場合です。
* **データトラッキング**
* **プッシュ通知**:
	+ **表示または UI の問題**: プッシュ通知がデバイス上で正しくレンダリングされない場合です。
	+ **画像の読み込み失敗**: 例外やサポートされていない画像形式（例: WebP 画像ファイル形式）により、プッシュ通知に画像が表示されない場合です。
	+ **PushAmp のケース**: SDK ではなくシステムがプッシュ通知をレンダリングする状況です。
* **アプリ内メッセージ**:
	+ **表示の異常**: アプリ内メッセージまたはアプリ内ナッジが小さすぎたり大きすぎたりして、ダッシュボードの仕様と一致しない場合です。
	+ **動作の競合**: アプリ内メッセージがアプリの機能に干渉する場合です。
	+ **ハイブリッドアプリでのコンテキスト設定**: ネイティブ画面のみをトラッキングするため、ハイブリッドフレームワークでは画面トラッキングが行われません。
	+ **Self-Handled アプリ内メッセージ**: 正確な統計トラッキングを確保するために、呼び出しによる統合の検証が必要になる場合があります。開発者が、イベントや統計をトラッキングするために必要なメソッドを統合していない可能性があります。
* **カード**:
	+ **Self-Handled カード**: 統合上の見落としがある可能性があります。
