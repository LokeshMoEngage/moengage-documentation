FCM 認証は、Android デバイスにインストールされたアプリへのプッシュ通知の送信を有効にする方法の 1 つです。FCM 認証トークンは、Firebase サービスへのサーバーリクエストを承認するために使用されます。Android ユーザーにプッシュ通知を送信するには、認証トークンを生成して MoEngage ダッシュボードにアップロードする必要があります。

<Check>
  Firebase コンソールでアプリを作成済みであること。
</Check>

# Firebase サービスへのサーバーリクエストの承認

秘密鍵を使用して、Firebase サービスへのサーバーリクエストを承認できます。FCM の秘密鍵は、サービスアカウントを認証するために生成された秘密鍵の詳細を含むサービスアカウントの JSON ファイルです。

## 秘密鍵の生成手順

認証情報を使用して [Firebase コンソール](https://console.firebase.google.com/)にログインします。

1. プロジェクトを選択します。
2. 左上のペインで、**Project Overview** の横にある設定アイコンをクリックします。
3. **Project settings** を選択します。

   <Frame>
     ![FCM Step1](/images/FCM_Step1.png)
   </Frame>
4. **Project Settings** ページで、**Service accounts** タブに移動します。

   <Frame>
     ![Firebase Admin SDK](/images/FirebaseAdminSDK.png)
   </Frame>
5. **Generate new private key** をクリックします。JSON ファイルをダウンロードするだけなので、選択する言語は関係ありません。選択した言語は、FCM との通信を実装する場合のサンプルコードを提供するためのものです。MoEngage がこの処理をすでに行っているため、任意の言語を選択してキーを生成してください。
6. **Generate Key** をクリックして確定します。秘密鍵を含む JSON ファイルが生成されます。
7. JSON ファイルをダウンロードし、MoEngage ダッシュボードの **Settings** \> **Channel** \> **Push** \> **App Push** \> **Android** \> **FCM Authentication** \> **Private key file (Recommended)** でアップロードします。

   ![Mceclip4](/images/mceclip4.png)
8. JSON を設定したら、[Cloud コンソール](https://console.cloud.google.com/apis/library/fcm.googleapis.com)で FCM を有効にします。

   <Frame>
     ![Enable FCM](/images/EnableFCM.png)
   </Frame>

# 秘密鍵の設定による送信速度の変更

Firebase Cloud Messaging API には、デフォルトで 1 分あたり 600,000 リクエストのレート制限があります。詳細については、[こちら](https://firebase.google.com/support/faq#fcm-depr-rampup)を参照してください。アカウントがこの制限に達すると、FCM は以下のエラーで通知をドロップする場合があります。

| エラー                                                      | 説明                                                                                                                                                                                                                                                                                                                                 |
| ---------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| FCM Message rate exceeded   (Quotaexceededforquotametric…) | 送信速度が FCM アカウントのサービス容量を超えています。流入レートを制限するため、サービス容量を超えたリクエストは拒否されます。これは、複数のキャンペーンが同時に高速でトリガーされることが原因で発生します。キャンペーンの間隔を空けるか、キャンペーンの配信制御でリクエスト制限を下げることを検討してください。 |

<Info>
  FCM API のデフォルトのレート制限が 600,000 RPM に引き下げられたことに伴い、1 つのキャンペーンがプロジェクトの制限を超えないように、プッシュ通知の最大許容スロットル速度を 500,000 RPM に変更します。この変更は新規および既存のキャンペーンに適用されます。複数のキャンペーンが同時にトリガーされた場合は、引き続きドロップが発生する可能性があります。
</Info>

このようなエラーを減らすには、ユースケースに応じて以下のいずれかの方法を取ることができます。

- **キャンペーンの送信速度を下げる** 1 回限りのキャンペーンや定期キャンペーンで「FCM Message rate exceeded」が多く発生している場合、割り当てられたクォータを超えて送信容量を超過している可能性があります。クォータの超過を避けるため、キャンペーンの配信制御でリクエスト制限を下げることをお勧めします。\
  FCM のデフォルトのレート制限は 1 分あたり 600,000 リクエストであるため、イベントトリガー、ビジネスイベントトリガー、フロートリガーのキャンペーンなど、他の並行リクエストに対応できるよう、より低い制限（1 分あたり約 200,000 リクエスト）に設定することをお勧めします。
- **1 回限りのキャンペーンと定期キャンペーンの間隔を空ける**\
  1 回限りのキャンペーンや定期キャンペーンで「FCM Message rate exceeded」が多く発生している場合、同時に送信される複数のキャンペーンをスケジュールしているため、全体の送信速度が上がっている可能性があります。そのため、1 回限りのキャンペーンと定期キャンペーンの間隔を空けてください。
- **FCM にレート制限の引き上げをリクエストする** 現在の制限を確認するには、[Google Cloud コンソール](https://console.cloud.google.com/) \> APIs & Services \> Firebase Cloud Messaging API \> Quotas & System Limits に移動するか、直接 [FCM Quotas](https://console.cloud.google.com/apis/api/fcm.googleapis.com/quotas) に移動して、Send requests per minute の値を確認します。600,000 RPM を超えるレート制限の引き上げをリクエストするには、[Firebase サポートにお問い合わせください](https://firebase.google.com/support)。

# よくある質問

<Accordion title="このためにアプリの更新や SDK の変更は必要ですか？">
  MoEngage SDK は、FCM によるこれらの変更にすでに対応しています。秘密鍵による認証メカニズムに切り替える際に、MoEngage SDK を更新する必要はありません。\
  Server Key または Auth key は、MoEngage がお客様のアカウントに代わって FCM にリクエストを送信するための認証メカニズムです。これはアカウントレベルで機能し、エンドユーザーレベルやデバイスレベルでは機能しません。\
  Server key から秘密鍵に切り替えると、すべてのリクエストが Auth key メカニズムに移行され、エンドユーザーやデバイスへの影響はありません。
</Accordion>

<Accordion title="Server key から秘密鍵による認証メカニズムへの移行はいつまでに行う必要がありますか？">
  FCM XMPP および HTTP レガシー API を使用したメッセージ（アップストリームメッセージを含む）の送信は、2023 年 6 月 20 日に非推奨となり、**2024 年 6 月 21 日に削除されます**。Deprecation of Legacy HTTP API を参照してください。Firebase サービスに送信するすべてのリクエストには、できるだけ早く秘密鍵を使用することを強くお勧めします。
</Accordion>

<Accordion title="秘密鍵による認証メカニズムに移行しない場合はどうなりますか？">
  FCM の Server key メカニズムは 2024 年 6 月 21 日に非推奨となります。その後、FCM は Server key 認証メカニズムからのリクエストを引き続き受け付けても通知をデバイスに配信しないか、API リクエストを完全に拒否し始める可能性があります。どちらの場合も、**ユーザーは FCM 経由で通知を受信できなくなります**。
</Accordion>

<Accordion title="秘密鍵による認証メカニズムへの移行にはどのくらい時間がかかりますか？移行中にダウンタイムは発生しますか？">
  MoEngage ダッシュボードで設定を保存すると、アカウントは直ちに新しい API を使用して、実行中のキャンペーンを含む Android プッシュ通知を送信するように切り替わります。移行中にプッシュ通知の送信でドロップが発生することはありません。
</Accordion>

<Accordion title="秘密鍵による認証メカニズムのメリットは何ですか？">
  更新された FCM API では、HTTP v1 プロトコルの採用や、以前のバージョンの Server key 認証に代わる OAuth2 セキュリティモデルに基づく短期間有効なアクセストークンの実装など、いくつかの改善が導入されています。これらのトークンは使用期間を約 1 時間に制限することでセキュリティを強化し、トークンが漏洩した場合のリスクを最小限に抑えます。
</Accordion>

<Accordion title="秘密鍵による認証メカニズムへの移行にデメリットはありますか？">
  秘密鍵による認証メカニズムでは、Firebase Cloud Messaging API の一括送信メカニズムが廃止され、デフォルトで 1 分あたり 600,000 リクエストのレート制限があります。詳細については、[こちら](https://firebase.google.com/support/faq#fcm-depr-rampup)を参照してください。アカウントがこの制限に達すると、FCM は通知をドロップする場合があります。一括通知がサポートされなくなったため、1 回限りのキャンペーンや定期キャンペーンなどの一括キャンペーンでは、キャンペーンの送信速度が低下する可能性があります。\
  MoEngage では、1 つのキャンペーンがプロジェクトの制限を超えないように、プッシュ通知の最大許容スロットル速度を事前に 500,000 RPM に引き下げました。この変更は新規および既存のキャンペーンに適用されます。複数のキャンペーンが同時にトリガーされた場合は、引き続きドロップが発生する可能性があります。詳細については、[秘密鍵の設定による送信速度の変更](https://www.moengage.com/docs/developer-guide/android-sdk/push/basic/fcm-authentication#changes-in-sending-speed-with-private-key-configuration)を参照してください。
</Accordion>

<Accordion title="新しい認証方式と古い認証方式のどちらで配信されているかを確認するにはどうすればよいですか？">
  認証を秘密鍵に設定すると、変更は直ちに受け入れられ、以降のリクエストの送信に使用されます。
</Accordion>
