このページでは、MoEngage iOS SDK がアプリに与える 2 つの影響について説明します。ダウンロードサイズとインストールサイズに追加されるサイズと、アプリの起動に追加される時間です。

## アプリサイズへの影響

MoEngage は、SDK をサンプルアプリに統合し、各モジュール構成を App Store Connect にアップロードしてサイズへの影響を測定しました。結果は、アプリのダウンロードサイズである圧縮サイズと、インストールされたアプリがデバイス上で占有する容量である非圧縮サイズで示しています。

測定したバージョン:

*   [MoEngage-iOS-SDK](https://cocoapods.org/pods/MoEngage-iOS-SDK) - 9.14.0
*   [MoEngageRichNotification](https://cocoapods.org/pods/MoEngageRichNotification) - 7.13.0
*   [MoEngageInApp](https://cocoapods.org/pods/MoEngageInApp) - 4.13.0
*   [MoEngageCards](https://cocoapods.org/pods/MoEngageCards) - 4.13.0
*   [MoEngageGeofence](https://cocoapods.org/pods/MoEngageGeofence) - 5.13.0
*   [MoEngageInbox](https://cocoapods.org/pods/MoEngageInbox) - 2.13.0
*   [MoEngageRealTimeTrigger](https://cocoapods.org/pods/MoEngageRealTimeTrigger) - 2.13.0

<Info>
  **基準としての iPhone 12 Pro**

  App Store は各デバイスに必要なアーキテクチャのみをインストールするため、分析ではユニバーサルビルドを除外しています。以下の数値は、iOS 15.0 を搭載した iPhone 12 Pro を想定しています。
</Info>

## MoEngage SDK のサイズへの影響

サイズ分析は、MoEngage-iOS-SDK をダミーのサンプルアプリに統合した状態で実施しました。これらの数値は上記の SDK バージョンで測定したものであり、SDK 11.2.0 でのフレームワークのリンク方式の変更以前のものです。

| フレームワーク | バージョン | 圧縮サイズ | 非圧縮サイズ |
| :--- | :--- | :--- | :--- |
| ダミーのサンプルアプリ | NA | 36 KB | 125 KB |
| MoEngage-iOS-SDK | 9.14.0 | 849 KB | 2.5 MB |
| MoEngage-iOS-SDK + MoEngageInApp | 4.13.0 | 1.1 MB | 3.3 MB |
| MoEngage-iOS-SDK + MoEngageCards | 4.13.0 | 1.2 MB | 3.4 MB |
| MoEngage-iOS-SDK + MoEngageGeofence | 5.13.0 | 898 KB | 2.7 MB |
| MoEngage-iOS-SDK + MoEngageRichNotification | 7.13.0 | 933 KB | 2.8 MB |
| MoEngage-iOS-SDK + MoEngageInbox | 2.13.0 | 1.1 MB | 3.1 MB |
| MoEngage-iOS-SDK + MoEngageRealTimeTrigger | 2.13.0 | 1 MB | 3 MB |
| すべてのフレームワーク | 上記のとおり | 1.8 MB | 5.2 MB |

<Info>
  **MoEngage の全体的なサイズへの影響**

  *   圧縮サイズはアプリのダウンロードサイズです。非圧縮サイズは、デバイスにインストールされたアプリのサイズに相当します。
  *   [MoEngage-iOS-SDK](https://cocoapods.org/pods/MoEngage-iOS-SDK)（Core SDK）と、[MoEngageInApp](https://cocoapods.org/pods/MoEngageInApp)、[MoEngageCards](https://cocoapods.org/pods/MoEngageCards)、[MoEngageRichNotification](https://cocoapods.org/pods/MoEngageRichNotification)、[MoEngageGeofence](https://cocoapods.org/pods/MoEngageGeofence)、[MoEngageInbox](https://cocoapods.org/pods/MoEngageInbox)、[MoEngageRealTimeTrigger](https://cocoapods.org/pods/MoEngageRealTimeTrigger) モジュールを合わせた全体的なサイズへの影響は、圧縮サイズで 1.8 MB、アプリのインストールサイズ（非圧縮サイズ）で 5.2 MB です。
</Info>

## アプリ起動時間への影響

アプリに埋め込まれた動的リンクのフレームワークは、アプリの `main()` が実行される前にシステムによって読み込まれ、バインドされます。この処理は、そのセッションでアプリがフレームワークを呼び出すかどうかにかかわらず、コールドローンチのたびに発生します。アプリに埋め込むフレームワークが多いほど、この起動前のフェーズにかかる時間が長くなります。

SDK 11.2.0 以降、次のモジュールは個別の動的フレームワークとして埋め込まれるのではなく、アプリのバイナリに静的にリンクされるため、起動前の処理から除外されます。

*   `MoEngageSDK`
*   `MoEngageInApps`
*   `MoEngageCards`
*   `MoEngageInbox`
*   `MoEngageGeofence`
*   `MoEngageRealTimeTrigger`
*   `MoEngagePersonalization`
*   `MoEngageRecommendations`（SDK 11.3.0 から提供）

`MoEngageCore`、`MoEngageSecurity`、`MoEngageMessaging`、`MoEngageCampaignsCore`、`MoEngageRichNotification`、`MoEngageLiveActivity` は引き続き動的フレームワークです。Notification Service、Notification Content、Live Activity の各拡張機能もこれらのモジュールをリンクしており、拡張機能は独自のプロセスで実行されるため、アプリのバイナリにリンクされたコードを使用できません。

<Note>
  静的リンクには SDK 11.2.0 以降が必要です。詳細については、[iOS SDK リリースノート](/ja/release-notes/sdks/ios)を参照してください。
</Note>

### 測定された改善

iOS SDK が提供するすべてのモジュールを統合したサンプルアプリで、これらのモジュールが静的リンクに移行した後、MoEngage はコールドローンチ時間が 44.6% 短縮されたことを測定しました。

短縮の度合いは、統合するモジュールの組み合わせによって異なります。統合における変化を測定するには、アップグレードの前後で Xcode Organizer のアプリの **Launch Time** 指標を比較してください。

### 統合における変更

| 統合方法 | 必要な変更 |
| :--- | :--- |
| CocoaPods | なし。podspec がリンクの種類を設定します。 |
| Swift Package Manager | なし。パッケージマニフェストがリンクの種類を設定します。 |
| 手動（xcframework） | アプリのターゲットにフレームワークを追加し、静的フレームワークについて 3 つの手順を実行します。各静的フレームワークについて **Do Not Embed** を設定してリソースバンドルをコピーし、アプリのターゲットに `-ObjC` を 1 回追加します。[手動統合](/ja/developer-guide/ios-sdk/manual-integration/manual-integration)を参照してください。 |
