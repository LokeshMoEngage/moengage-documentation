## 概要

サポートされている任意のフレームワーク（CDN、NPM、GTM、SPA、AMP、Flutter、Shopify）向けに、次の 2 つの方法のいずれかを使用して Web SDK を統合できます。

- **スクリプトベースの初期化（推奨）:** フォームベースのインターフェイスを使用して、検証済みのコードスニペットを生成したり、モジュール固有の設定にアクセスしたりします。詳細については、[スクリプトベースの初期化（推奨）](#option-1-script-based-initialization-recommended)を参照してください。
- **手動統合:** SDK のパラメーターと初期化コードを手動で設定します。詳細については、[オプション 2: 手動統合](#option-2-manual-integration)を参照してください。

<Check>
  **Workspace ID（App ID）**と**データセンター**が必要です。これらの詳細は、ダッシュボードで `Settings > App > General` に移動して確認できます。
</Check>

## オプション 1: スクリプトベースの初期化（推奨）

信頼性が高く効率的なセットアップを実現するために、**スクリプトベースの初期化**方式を使用することをお勧めします。この方式では検証済みの JavaScript スニペットが生成されるため、構文エラーの可能性がなくなり、アプリケーションの種類に基づいて必要なフラグが自動的に含まれます。

<Check>
  - **ワークスペースの詳細:** **Workspace ID（App ID）**と**データセンター**（ダッシュボードの `Settings > App > General` で確認できます）を用意してください。
  - **Service Worker（Web Push の場合）:** Web Push を有効にする場合は、**ルートディレクトリ**に `serviceworker.js` という名前のファイルを作成します。
  - **ホワイトリスト登録（CSP）:** サイトでコンテンツセキュリティポリシーを使用している場合は、必要な MoEngage の URL をホワイトリストに登録します。詳細については、[こちら](/ja/developer-guide/web-sdk/web-sdk-integration/basic-integration/web-sdk-integration#whitelisting-urls)を参照してください。
</Check>

初期化スクリプトを生成するには、次の手順に従います。

1. [Web SDK 初期化 Web サイト](https://app-cdn.moengage.com/sdk/integration/config/index.html)に移動します。
2. アプリケーションの要件に基づいて値を設定します。各フィールドの詳細な説明については、以下の[設定パラメーター](#configuration-parameters)の表を参照してください。
3. フォームの下部にある **Generate Code** をクリックして、検証済みの JavaScript スニペットを作成します。
4. 生成されたコードを実装します。ツールに表示されたコードスニペットをコピーし、次のようにプロジェクトに貼り付けます。
   - **Service Worker を更新する（Web Push が有効な場合）:** 生成された `importScripts(...)` 行を `serviceworker.js` ファイルの先頭に追加します。
   - **HTML ファイルを変更する（Web Personalization が有効な場合）:** 生成された `<link>` タグと Personalization の `<script>` タグを、ルート HTML ファイルの `<head>` セクションの先頭に追加します。
   - **SDK を初期化する:**
     - **CDN** の場合: 初期化スクリプトを `<head>` タグに直接貼り付けます。
     - **NPM** の場合: `import` ステートメントと `Moengage.initialize({...})` ブロックをメインの JavaScript ファイルに貼り付けます。

<Info>
  **事後要件**

  統合後、ブラウザのデベロッパーツール（Network タブ）を開いてセットアップを検証します。ページを再読み込みし、リクエストが MoEngage のエンドポイント（例: `cdn.moengage.com` や `sdk-0X.moengage.com`）に正常に到達していることを確認します。
</Info>

### 一般的な設定シナリオ

開発やデバッグのニーズに合わせて、環境の選択とログの詳細度をそれぞれ個別に設定できます。

| 環境（`env`） | ログレベル（`logLevel`） | データの送信先     | コンソール出力                                            |
| ------------------- | ---------------------- | -------------------- | --------------------------------------------------------- |
| `'TEST'`            | `0`                    | テストダッシュボード       | クリーンなコンソール（SDK ログなし）。                              |
| `'TEST'`            | `1`                    | テストダッシュボード       | 重要なログとエラー（テストに推奨）。       |
| `'LIVE'`            | `0`                    | 本番ダッシュボード | 本番設定。ログは表示されません。                       |
| `'LIVE'`            | `1`                    | 本番ダッシュボード | トラブルシューティングのために本番環境で SDK のエラーログを有効にします。 |

## オプション 2: 手動統合

<Info>
- MoEngage の API は camelCase に移行しました。`app_id` や `project_id` などの初期化プロパティは、`appId` および `projectId` になりました。従来のプロパティも引き続き機能しますが、コンソールに非推奨の警告が記録されます。

- 以下の更新された CDN スニペットには、従来の（snake_case）メソッド名と最新の（camelCase）メソッド名の両方を登録する新しい配列 u=[...] が含まれています。これにより、SDK がページ上で完全に読み込まれる前に、どちらの構文でもネットワーク呼び出しを安全にキューに入れられるため、後方互換性が確保されます。

- セットアップに応じて、次のガイドラインに従ってください。

  - 新規統合: camelCase メソッドを使用して SDK を実装します。これにより、統合が最新の JavaScript 標準とネイティブに互換性を持つようになり、コンソールの警告を防ぐことができます。

  - CDN/NPM: Script タグが最新バージョンを取得する場合、SDK は従来の呼び出しを新しいロジックに自動的にマッピングします。ただし、camelCase へのリファクタリングを推奨します。

  - 固定バージョン: 重要: 新しい camelCase メソッドは、従来の SDK バージョンでは利用できません。ソースコード内の SDK バージョンを 2.71.00 以降に更新するまで、コードをリファクタリングしないでください。

詳細については、[こちら](https://www.moengage.com/docs/developer-guide/web-sdk/migration/standardizing-web-sdk-apis-for-cross-platform-consistency)を参照してください。 
</Info>

初期化パラメーターをコードベースで直接設定することで、SDK を手動で統合できます。以下のリストからプラットフォームまたはフレームワークを選択して、具体的な手動統合ガイドを確認してください。

- [CDN](#method-1-moengage-cdn)
- [NPM](#method-2-using-npm)
- [Google Tag Manager(GTM)](/ja/developer-guide/web-sdk/other-supported-web-sdk-integration/google-tag-manager-gtm-templates)
- [シングルページアプリ（SPA）のサポート](/ja/developer-guide/web-sdk/other-supported-web-sdk-integration/single-page-app-spa-support)
- [AMP Web Push の設定と統合](/ja/developer-guide/web-sdk/other-supported-web-sdk-integration/configure-and-integrate-amp-web-push)

- [Shopify アプリ](/ja/developer-guide/ecommerce-platforms/shopify/shopify-20)

手動統合を行う場合は、必ず次の設定手順を完了してください。

1. Web SDK のデータ収集に使用する MoEngage のデータセンターを指定します。
2. ホワイトリスト登録を有効にします。

<Info>
  これはすべての Web モジュールに必要な手順です。
</Info>

5. ワークスペースで _Portfolio_ が有効になっている場合は、`projectId` キーと、その値としてプロジェクトのプロジェクト ID を渡す必要があります。

#### SDK のアップグレード

コンテンツ配信ネットワークから MoEngage Web SDK を参照する場合、たとえば `https://cdn.moengage.com/release/{DC}/versions/{sdkVersion}/moe_webSdk.min.latest.js` で `sdkVersion = x` とすると（`sdkVersion = x` を使用して、メジャーリリースまでのバージョンのみを固定することが、デフォルトの推奨統合方法です）、ユーザーはサイトを更新したときに新機能とバグ修正を自動的に受け取ります。

ただし、メジャーな変更をリリースする場合は、破壊的変更によって統合に影響が及ばないように、MoEngage Web SDK を手動でアップグレードしていただく必要があります。

Web SDK のリリース履歴の全容については、[変更履歴](/ja/release-notes/sdks/web)で最新のリリース情報を確認できます。MoEngage Web SDK をアップグレードするには:

- 統合スクリプト内の `sdkVersion` の値を変更して、MoEngage ライブラリのバージョンを更新します。
- Web Push を統合している場合は、サイト上の Service Worker ファイル内の serviceworker CDN URL のバージョンを更新します。デフォルトでは、このファイルはサイトのルートディレクトリの `/serviceworker.js` にありますが、統合によっては場所がカスタマイズされている場合があります。`importScripts("https://cdn.moengage.com/release/{DC}/versions/[old-version-number]/serviceworker_cdn.min.latest.js");`
- Web Personalization を統合している場合は、Web Personalization スクリプト内のバージョンを更新します- `https://cdn.moengage.com/release/{DC}/versions/[old-version-number]/moe_webSdk_webp.min.latest.js?appId={workspace-id}`

<Warning>
  正しく機能させるには、これら 3 つの統合を同じバージョン番号で更新する必要があります。NPM を使用している場合は、package.json ファイルにある @moengage/web-sdk 依存関係のバージョン番号を使用してください。
</Warning>

### 方法 2: NPM を使用する

サイトで NPM または Yarn パッケージマネージャーを使用している場合は、[MoEngage NPM パッケージ](https://www.npmjs.com/package/@moengage/web-sdk)を依存関係として追加できます。

<CodeGroup>

```auto Add MoEngage NPM Package
npm install --save @moengage/web-sdk
# or, using yarn:
# yarn add @moengage/web-sdk
```

</CodeGroup>

インストールが完了したら、一般的な方法でライブラリを `import` または `require` できます。

<CodeGroup>

```javascript JavaScript wrap
import moengage from "@moengage/web-sdk";

// or, using `require`

const moengage = require("@moengage/web-sdk");
```

</CodeGroup>

次に、使用する前にすべてのページで設定を渡して初期化します。

<CodeGroup>

```javascript JavaScript wrap
moengage.initialize({
  appId: 'YOUR_WORKSPACE_ID',
  env: 'LIVE',
  logLevel: 0
});
```

</CodeGroup>

ここでは任意の設定を渡すことができます。例:

- ワークスペースで [_Portfolio_](https://www.moengage.com/docs/user-guide/settings/account/portfolio/portfolio) が有効になっている場合は、`projectId` キーを渡す必要があります。
- 特殊なプロジェクトの統合設定を変更したい場合は、次のスニペットのように渡します。

<CodeGroup>

```javascript JavaScript wrap
moengage.initialize({
  appId: 'YOUR_WORKSPACE_ID', 
  projectId: 'your_projectId',
  env: 'LIVE',
  logLevel: 0
});
```

</CodeGroup>

その後、次のスニペットのように、MoEngage SDK の任意のメソッドを使用できます。

<CodeGroup>

```javascript JavaScript wrap

```

</CodeGroup>

 

<Info>
  （パッケージマネージャーで指定されている @moengage/web-sdk のバージョンではなく）常に最新バージョンの Web SDK を使用したい場合は、設定で `useLatest` プロパティの値を `true` に設定して渡します。

  `moengage.initialize({appId: 'YOUR_WORKSPACE_ID', useLatest: true});`
</Info>

<Info>
  パッケージマネージャーで @moengage/web-sdk 依存関係のバージョンを変更することで、使用したい Web SDK のバージョンを使用できます。特定のバージョンまたはバージョン範囲の使用方法の詳細については、[こちら](https://docs.npmjs.com/cli/v10/configuring-npm/package-json#dependencies)を参照してください。
</Info>

- [https://app-cdn.moengage.com/](https://app-cdn.moengage.com)

- https://image-04.moengage.com/

**connect-src:**

- https://sdk-01.moengage.com/
- https://sdk-02.moengage.com/
- https://sdk-03.moengage.com/
- https://sdk-04.moengage.com/
- https://sdk-06.moengage.com/

**frame-src:**

- https://cdn.moengage.com/

**style-src:**

- https://cdn.moengage.com/
- [https://app-cdn.moengage.com/](https://app-cdn.moengage.com)
- https://fonts.bunny.net/

詳細については、[コンテンツセキュリティポリシー](https://developer.mozilla.org/en-US/docs/Web/HTTP/CSP)を参照してください。

## トラブルシューティング

### 環境で SDK をデバッグできません。

MoEngage SDK の初期化時に、`logLevel` が `1`（詳細な出力の場合は `2`）に設定されていることを確認してください。

### Live 環境で SDK のログを確認するにはどうすればよいですか？

MoEngage SDK の初期化時に、`logLevel` を 1 に設定します。

### TEST 環境と LIVE 環境の違いは何ですか？

MoEngage は、**TEST 環境**と呼ばれるステージング環境を提供しています。**LIVE 環境**には、本番 Web サイトからの実際のユーザー/顧客に関するデータが含まれます。

MoEngage Web SDK は、`env` パラメーターを使用してデータを正しくルーティングします。

- `env: 'TEST'`: データをテストダッシュボードにルーティングします。
- `env: 'LIVE'`: データを本番ダッシュボードにルーティングします。

選択した環境に関係なく、`logLevel` パラメーターを使用してログの詳細度を個別に制御できます。

### MoEngage Web SDK は、ネイティブブラウザ API にパッチを適用するアプリケーションをサポートしていますか？

はい。アプリケーションでネイティブブラウザ API にパッチを適用するフレームワークやライブラリ（Zone.js を使用する Angular アプリケーションなど）を使用している場合、SDK の一貫した動作を確保するために、MoEngage では Native Browser API Support を有効にすることを推奨しています。

セットアップ手順については、[Native Browser API Support](/ja/developer-guide/web-sdk/web-sdk-integration/optional-integration/native-browser-api-support) を参照してください。
