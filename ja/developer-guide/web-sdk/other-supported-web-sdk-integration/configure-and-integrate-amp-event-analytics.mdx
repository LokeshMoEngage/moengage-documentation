---

MoEngage AMP イベント分析プラグインは、ユーザー属性とイベントのトラッキング、およびサードパーティの JavaScript の実行に役立ちます。MoEngage AMP イベント分析プラグインは、ユーザー属性とイベントをトラッキングする際の、AMP ページと HTML ページの制限の違いに対処します。

MoEngage AMP イベント分析プラグインは、AMP 分析モジュールとは異なります。

<Warning>
  重要

  Web SDK v2.81.01 以降では、トリガーで `request` を `eventV2` に設定してください。従来の `event` リクエストは非推奨であり、今後のアップデートで削除される予定です。既存のトリガーを `eventV2` に移行してください。イベント名を `e` から `viewsInfo[].EVENT_ACTION` に、属性を `a` から `viewsInfo[].EVENT_ATTRS` に移動します。

  v2.81.01 未満の Web SDK バージョンでは、引き続き `event` を使用してください。
</Warning>

<Info>
  Web SDK をメジャーバージョン（`sdkVersion = "2"`）で参照している統合では、`eventV2` のサポートが自動的に適用されます。特定のリリースに固定している統合では、v2.81.01 以降が必要です。詳細については、[SDK のアップグレード](/ja/developer-guide/web-sdk/web-sdk-integration/basic-integration/web-sdk-integration#upgrading-the-sdk)を参照してください。
</Info>

AMP ページにイベントのトラッキングとユーザー属性のトラッキングを追加するには、次の手順に従います。

## AMP 分析スクリプトの追加

AMP 分析を使用してユーザー属性とイベントをトラッキングしたいすべての AMP ページで、.amp ファイルの `<head>` セクションにスクリプトを必ず含めてください。

<CodeGroup>

```HTML HTML lines wrap
<script async custom-element="amp-analytics" src="https://cdn.ampproject.org/v0/amp-analytics-0.1.js"></script>
```

</CodeGroup>

### HTML 内の任意の場所に追加

<CodeGroup>

```HTML HTML lines wrap
<amp-analytics type="moengage" id="moengage" >
<script type="application/json">
{
  "vars": {
    "appId": "YOUR_WORKSPACE_ID",
    "dataCenter": "sdk-01"
  }
}
</script>
</amp-analytics>
```

</CodeGroup>

<Info>
  注意

  YOUR_WORKSPACE_ID は、MoEngage ダッシュボード -\> Settings -\> App -\> General Settings にある実際の Workspace Id に必ず置き換えてください。

  dataCenter の詳細については、サポートチームにお問い合わせください。
</Info>

<Info>
  注意

  データをテスト環境にリダイレクトするには、appId に '\_DEBUG' を付加します。たとえば、appId が \
  YOUR_WORKSPACE_ID の場合、テスト環境では YOUR_WORKSPACE_ID_DEBUG になります。
</Info>

## ユーザーのトラッキング

上記の手順を実施すると、AMP ページにアクセスするすべてのユーザーが自動的にトラッキングされます。\
ただし、これらのユーザーはデフォルトで匿名ユーザーになります。\
ただし、以前に通常の HTML ページにアクセスし、Cookie を削除していない Web サイトのユーザーは、AMP ページでも同じユーザーとして扱われます。

## イベントのトラッキング

上記の手順を実施した場合、Page Viewed イベントはデフォルトでトラッキングされます。\
ただし、AMP フレームワークにはイベントのトラッキングに関する制限があるため、トラッキングできるのは `Page Viewed`、`Element Clicked`、`Page Scroll` など、一部の種類のイベントのみです。

<Info>
  MoEngage のベンダー構成では、すべてのリクエストに `identifiers` と `meta` が自動的に含まれます。これらをトリガーの構成に追加する必要はありません。カスタムの `identifiers` オブジェクトを追加するのは、リクエストを特定のログイン済みユーザーに関連付けるために、ログインイベントをトラッキングする場合のみです。
</Info>

イベントの一覧の詳細については、[AMP Analytics Examples](https://amp.dev/documentation/examples/components/amp-analytics/) を参照してください。

### 例 1: 要素のクリックイベント

次のように、id が `test` の HTML 要素がクリックされたときのクリックイベントをトラッキングできます。

<CodeGroup>

```HTML HTML lines wrap
<button id="test" data-vars-title="Example request title">
  Click here to generate an event
</button>

<amp-analytics type="moengage" id="moengage">
<script type="application/json">
{
  "vars": {
    "appId": "YOUR_WORKSPACE_ID",
    "dataCenter": "sdk-01"
  },
  "triggers": {
    "clickTrigger": {
      "on": "click",
      "selector": "#test",
      "request": "eventV2",
      "extraUrlParams": {
        "viewsCount": 1,
        "viewsInfo": [
          {
            "EVENT_ACTION": "amp example button click",
            "EVENT_ATTRS": {
              "title": "${title}"
            },
            "EVENT_G_TIME": "${timestamp}",
            "EVENT_L_TIME": "${timestamp}"
          }
        ]
      }
    }
  }
}
</script>
</amp-analytics>
```

</CodeGroup>

 

| パラメーター | 説明 |
| --------- | ----------- |
| `on` | イベントのタイプ |
| `selector` | 標準の CSS セレクター |
| `request` | 常に `eventV2` である必要があります |
| `viewsCount` | このリクエストに含まれるイベントの数。`viewsInfo` 内のオブジェクトの数に設定します。 |
| `viewsInfo` | イベントオブジェクトを含む配列。 |
| `viewsInfo[].EVENT_ACTION` | イベント名。この例では `"amp example button click"` です。 |
| `viewsInfo[].EVENT_ATTRS` | キーと値のペアで指定するイベント属性。ボタン要素の `data-vars-title` を使用して、変数 `title` を確認してください。 |
| `viewsInfo[].EVENT_G_TIME` | イベントのグローバル（UTC）タイムスタンプ。`${timestamp}` を使用します。 |
| `viewsInfo[].EVENT_L_TIME` | イベントのローカルタイムスタンプ。`${timestamp}` を使用します。 |

### 例 2: ページスクロールイベント

<CodeGroup>

```HTML HTML lines wrap
<amp-analytics type="moengage" id="moengage">
<script type="application/json">
{
  "vars": {
    "appId": "YOUR_WORKSPACE_ID",
    "dataCenter": "sdk-01"
  },
  "triggers": {
    "scrollPings": {
      "on": "scroll",
      "scrollSpec": {
        "verticalBoundaries": [25, 50, 90]
      },
      "request": "eventV2",
      "extraUrlParams": {
        "viewsCount": 1,
        "viewsInfo": [
          {
            "EVENT_ACTION": "PageScroll",
            "EVENT_ATTRS": {
              "scrolledUpto": "${scrollTop}"
            },
            "EVENT_G_TIME": "${timestamp}",
            "EVENT_L_TIME": "${timestamp}"
          }
        ]
      }
    }
  }
}
</script>
</amp-analytics>
```

</CodeGroup>

スクロールイベントには、`verticalBoundaries` と `horizontalBoundaries` を含む `scrollSpec` オブジェクトが必要です。スクロールイベントを発生させるには、2 つのプロパティのうち少なくとも 1 つが必要です。両方のプロパティの値は、スクロールイベントが生成される境界を含む数値の配列である必要があります。たとえば、上記のコードスニペットでは、ページが垂直方向に 25%、50%、90% スクロールされたときにスクロールイベントが発生します。ここで送信される属性は `scrolledUpto` で、ユーザーが上端からスクロールしたピクセル数を示す組み込み変数 `scrollTop` を保持します。

サポートされているすべての変数の一覧の詳細については、[Supported Variables](https://github.com/ampproject/amphtml/blob/main/docs/spec/amp-var-substitutions.md) を参照してください。

### 例 3: フォーム送信イベント

<CodeGroup>

```HTML HTML lines wrap
<form id="testForm" method="post" action-xhr="YOUR_SUBMIT_URL" target="YOUR_TARGET_VALUE">
   <input type="text" name="name" placeholder="Name..." required>
   <input type="submit" value="Subscribe">
</form>

<amp-analytics type="moengage" id="moengage">
<script type="application/json">
{
  "vars": {
    "appId": "YOUR_WORKSPACE_ID",
    "dataCenter": "sdk-01"
  },
  "triggers": {
    "formSubmit": {
      "on": "amp-form-submit",
      "request": "eventV2",
      "selector": "#testForm",
      "extraUrlParams": {
        "viewsCount": 1,
        "viewsInfo": [
          {
            "EVENT_ACTION": "FormSubmit",
            "EVENT_ATTRS": {
              "anyKey": "anyValue"
            },
            "EVENT_G_TIME": "${timestamp}",
            "EVENT_L_TIME": "${timestamp}"
          }
        ]
      }
    }
  }
}
</script>
</amp-analytics>
```

</CodeGroup>

上記の例では、フォームの id をセレクターの値 (**#testForm**) として設定しています。`viewsInfo` 内の `EVENT_ACTION` はイベント名で、`EVENT_ATTRS` にはこのイベントでトラッキングしたいキーと値が含まれます。

## ユーザー属性のトラッキング

<Warning>
  重要

  アカウントでユーザー属性が ID として設定されている場合は、このセクションで示すように単にユーザー属性としてトラッキングするのではなく、[ログイン](#tracking-user-login-and-logout)の一部としてトラッキングしてください。詳細については、[こちらのドキュメント](https://www.moengage.com/docs/user-guide/data/user-data/unified-identity-identity-resolution)を参照してください。
</Warning>

`EVENT_ACTION_USER_ATTRIBUTE` イベントを使用してユーザー属性をトラッキングできます。たとえば、Web サイトに次のボタンがあるとします。

<CodeGroup>

```HTML HTML lines
<button id="first-name" data-vars-first-name="someFirstName">  Click here to track first name</button>
```

</CodeGroup>

この場合、名 (ユーザーの名とみなします) を次のようにトラッキングします。

<CodeGroup>

```HTML HTML lines wrap
<amp-analytics type="moengage" id="moengage">
<script type="application/json">
{
  "vars": {
    "appId": "YOUR_WORKSPACE_ID",
    "dataCenter": "sdk-01"
  },
  "triggers": {
    "clickTrigger": {
      "on": "click",
      "selector": "#first-name",
      "request": "eventV2",
      "extraUrlParams": {
        "viewsCount": 1,
        "viewsInfo": [
          {
            "EVENT_ACTION": "EVENT_ACTION_USER_ATTRIBUTE",
            "EVENT_ATTRS": {
              "USER_ATTRIBUTE_USER_FIRST_NAME": "${firstName}"
            },
            "EVENT_G_TIME": "${timestamp}",
            "EVENT_L_TIME": "${timestamp}"
          }
        ]
      }
    }
  }
}
</script>
</amp-analytics>
```

</CodeGroup>

同様に、以下のボタンをクリックしたときにユーザーのメールアドレスをトラッキングするには、次のようにします。

<CodeGroup>

```HTML HTML lines
<button id="email" data-vars-email="someEmail">  Click here to track email</button>
```

</CodeGroup>

<CodeGroup>

```HTML HTML lines wrap
<amp-analytics type="moengage" id="moengage">
<script type="application/json">
{
  "vars": {
    "appId": "YOUR_WORKSPACE_ID",
    "dataCenter": "sdk-01"
  },
  "triggers": {
    "clickTrigger": {
      "on": "click",
      "selector": "#email",
      "request": "eventV2",
      "extraUrlParams": {
        "viewsCount": 1,
        "viewsInfo": [
          {
            "EVENT_ACTION": "EVENT_ACTION_USER_ATTRIBUTE",
            "EVENT_ATTRS": {
              "USER_ATTRIBUTE_USER_EMAIL": "${email}"
            },
            "EVENT_G_TIME": "${timestamp}",
            "EVENT_L_TIME": "${timestamp}"
          }
        ]
      }
    }
  }
}
</script>
</amp-analytics>
```

</CodeGroup>

同じ方法で、他の**事前定義済みのユーザー属性**もトラッキングできます。

<CodeGroup>

```HTML HTML lines wrap
<button id="btnId" data-vars-attribute-value="someValue">  Click here to track the user attribute</button>
```

</CodeGroup>

<CodeGroup>

```HTML HTML lines wrap
<amp-analytics type="moengage" id="moengage">
<script type="application/json">
{
  "vars": {
    "appId": "YOUR_WORKSPACE_ID",
    "dataCenter": "sdk-01"
  },
  "triggers": {
    "clickTrigger": {
      "on": "click",
      "selector": "#btnId",
      "request": "eventV2",
      "extraUrlParams": {
        "viewsCount": 1,
        "viewsInfo": [
          {
            "EVENT_ACTION": "EVENT_ACTION_USER_ATTRIBUTE",
            "EVENT_ATTRS": {
              "USER_ATTRIBUTE_NAME": "${attributeValue}"
            },
            "EVENT_G_TIME": "${timestamp}",
            "EVENT_L_TIME": "${timestamp}"
          }
        ]
      }
    }
  }
}
</script>
</amp-analytics>
```

</CodeGroup>

ここで、USER_ATTRIBUTE_NAME は次のいずれかに置き換える必要があります。

<CodeGroup>

```javascript JavaScript lines wrap
USER_ATTRIBUTE_USER_EMAIL //for user email - value needs to be string, eg: "dom@level5.com"
USER_ATTRIBUTE_USER_NAME //for user name - value needs to be string, eg: "Dominick (Dom) Cobb"
USER_ATTRIBUTE_USER_FIRST_NAME //for user first name - value needs to be string, eg: "Dominick"
USER_ATTRIBUTE_USER_LAST_NAME //for user last name - value needs to be string, eg: "Cobb"
USER_ATTRIBUTE_USER_MOBILE //for user mobile - value needs to be string, eg: "+12399999999"
USER_ATTRIBUTE_USER_GENDER //for user gender - value needs to be string, eg: "M"
USER_ATTRIBUTE_USER_BDAY //for user birthday - value needs to be in date format, eg: new Date(1980, 2, 31)
```

</CodeGroup>

**カスタムユーザー属性**をトラッキングするには、USER_ATTRIBUTE_NAME の代わりに独自のカスタム属性名を使用する必要があります。例:

<CodeGroup>

```HTML HTML lines wrap
<amp-analytics type="moengage" id="moengage">
<script type="application/json">
{
  "vars": {
    "appId": "YOUR_WORKSPACE_ID",
    "dataCenter": "sdk-01"
  },
  "triggers": {
    "clickTrigger": {
      "on": "click",
      "selector": "#btnId",
      "request": "eventV2",
      "extraUrlParams": {
        "viewsCount": 1,
        "viewsInfo": [
          {
            "EVENT_ACTION": "EVENT_ACTION_USER_ATTRIBUTE",
            "EVENT_ATTRS": {
              "colors": ["blue", "green", "red"]
            },
            "EVENT_G_TIME": "${timestamp}",
            "EVENT_L_TIME": "${timestamp}"
          }
        ]
      }
    }
  }
}
</script>
</amp-analytics>
```

</CodeGroup>

上記の例では、"colors" という名前のカスタム属性をトラッキングしています。この属性の値は配列 `["blue","green","red"]` です。

## ユーザーのログインとログアウトのトラッキング

[ユーザーをログインさせる以前の方法](/ja/developer-guide/web-sdk/other-supported-web-sdk-integration/user-login-in-amp-older-process)は変更されました。以下の方法は、MoEngage の User Identity Resolution 機能に従っています。[詳細はこちら](https://www.moengage.com/docs/user-guide/data/user-data/unified-identity-identity-resolution)。

Web サイトへの訪問中にユーザーのログインとログアウトが正しく実装され、ユーザーが認証されていることを確認してください。

<Warning>
  重要

  ユーザーのログインとログアウトが正しく処理されない場合、ユーザーデータが破損する可能性があります。詳細については、[こちらのセクション](https://www.moengage.com/docs/developer-guide/web-sdk/data-tracking/web-sdk-user-attributes-tracking#User-Login-and-Logout)を参照してください。
</Warning>

### ログインのトラッキング

<CodeGroup>

```HTML HTML lines wrap
<button id="login" data-vars-unique-id="someUniqueId" data-vars-user-email="emailValue@emailDomain.com">Click here to track user login</button>
```

</CodeGroup>

ここでは、ID "someUniqueId" と Email "[emailValue@emailDomain.com](mailto:emailValue@emailDomain.com)" をユーザーの ID としてトラッキングします。

<Warning>
  重要

  ID を設定する場合は、`identifiers` -\> `moe_user_id` と `identifiers` -\> `user_identities` の両方でその値を追加/更新してください。
</Warning>

<CodeGroup>

```html HTML lines wrap
<amp-analytics type="moengage" id="moengage">
<script type="application/json">
{
  "vars": {
    "appId": "YOUR_WORKSPACE_ID",
    "dataCenter": "sdk-01"
  },
  "triggers": {
    "clickTrigger": {
      "on": "click",
      "selector": "#login",
      "request": "eventV2",
      "extraUrlParams": {
        "identifiers": {
          "moe_user_id": "${uniqueId}",
          "user_identities": {
            "uid": "${uniqueId}",
            "u_em": "${userEmail}"
          }
        },
        "viewsCount": 1,
        "viewsInfo": [
          {
            "EVENT_ACTION": "EVENT_ACTION_USER_ATTRIBUTE",
            "EVENT_ATTRS": {},
            "EVENT_G_TIME": "${timestamp}",
            "EVENT_L_TIME": "${timestamp}"
          }
        ]
      }
    }
  }
}
</script>
</amp-analytics>
```

</CodeGroup>

ここで、`uid` は ID 属性、`u_em` は Email (Standard) 属性です。標準のユーザー属性を ID として設定する際に使用するキー名については、以下の表を参照してください。

| ユーザー属性名      | user_identities で使用するキー名 |
| ------------------------ | -------------------------------------- |
| ID                       | uid                                    |
| Email (Standard)         | u_em                                   |
| Gender                   | u_gd                                   |
| Birthday                 | u_bd                                   |
| Name                     | u_n                                    |
| First Name               | u_fn                                   |
| Last Name                | u_ln                                   |
| Mobile Number (Standard) | u_mb                                   |

たとえば、携帯電話番号のみでユーザーを識別したい場合は、次のようにします。

<CodeGroup>

```HTML HTML lines wrap
<button id="login" data-vars-user-mobile="7777777777">Click here to track user login</button>
```

</CodeGroup>

<CodeGroup>

```html HTML lines wrap
<amp-analytics type="moengage" id="moengage">
<script type="application/json">
{
  "vars": {
    "appId": "YOUR_WORKSPACE_ID",
    "dataCenter": "sdk-01"
  },
  "triggers": {
    "clickTrigger": {
      "on": "click",
      "selector": "#login",
      "request": "eventV2",
      "extraUrlParams": {
        "identifiers": {
          "user_identities": {
            "u_mb": "${userMobile}"
          }
        },
        "viewsCount": 1,
        "viewsInfo": [
          {
            "EVENT_ACTION": "EVENT_ACTION_USER_ATTRIBUTE",
            "EVENT_ATTRS": {},
            "EVENT_G_TIME": "${timestamp}",
            "EVENT_L_TIME": "${timestamp}"
          }
        ]
      }
    }
  }
}
</script>
</amp-analytics>
```

</CodeGroup>

<Info>
  注意

  Mobile と ID はユーザーの異なる 2 つの属性であるため、ここでは携帯電話番号の値を `identifiers` -\> `moe_user_id` で送信する必要はありません。ID を追加/更新する場合にのみ、ID の値を `moe_user_id` と `user_identities` の両方で送信する必要があります。
</Info>

<Warning>
  重要

  ログインをトラッキングした後は、ログアウトを実行するまで、以降のすべてのトリガーの `extraUrlParams` に `identifiers` オブジェクト（`moe_user_id` および/または `user_identities` を含む）を含めてください。ベンダー構成はデフォルトで `identifiers: {}`（空）を送信するため、ログイン後の各トリガーでユーザーの実際の ID で上書きする必要があります。そうしないと、MoEngage はダッシュボードでそれらのイベントをログイン済みユーザーに関連付けません。
</Warning>

たとえば、ユーザーに ID が設定された後にイベントをトラッキングしたい場合は、次のようにします。

<CodeGroup>

```html HTML wrap
<button id="title" data-vars-title="Example request title">Click here to generate an event</button>
```

</CodeGroup>

<CodeGroup>

```html HTML lines wrap
<amp-analytics type="moengage" id="moengage">
<script type="application/json">
{
  "vars": {
    "appId": "YOUR_WORKSPACE_ID",
    "dataCenter": "sdk-01"
  },
  "triggers": {
    "clickTrigger": {
      "on": "click",
      "selector": "#title",
      "request": "eventV2",
      "extraUrlParams": {
        "identifiers": {
          "moe_user_id": "someUniqueId",
          "user_identities": {
            "uid": "someUniqueId",
            "u_em": "emailValue@emailDomain.com"
          }
        },
        "viewsCount": 1,
        "viewsInfo": [
          {
            "EVENT_ACTION": "amp example button click",
            "EVENT_ATTRS": {
              "title": "${title}"
            },
            "EVENT_G_TIME": "${timestamp}",
            "EVENT_L_TIME": "${timestamp}"
          }
        ]
      }
    }
  }
}
</script>
</amp-analytics>
```

</CodeGroup>

### ID の更新のトラッキング

ID の値を更新する場合は、変更された ID を `identifiers` -\> `previous_identities` で送信します。

たとえば、最初に ID と Email をユーザーの ID として設定したとします。

<CodeGroup>

```HTML HTML lines wrap
<button id="login" data-vars-unique-id="someUniqueId" data-vars-user-email="emailValue@emailDomain.com">Click here to track user login</button>
```

</CodeGroup>

<CodeGroup>

```html HTML lines wrap
<amp-analytics type="moengage" id="moengage">
<script type="application/json">
{
  "vars": {
    "appId": "YOUR_WORKSPACE_ID",
    "dataCenter": "sdk-01"
  },
  "triggers": {
    "clickTrigger": {
      "on": "click",
      "selector": "#login",
```

  重要

</Warning>

## イベントのバッチ処理

複数のイベントを 1 つのトリガーの `viewsInfo` 配列内にまとめることで、1 回の HTTP リクエストで送信できます。`viewsCount` をイベントの数に設定し、各イベントオブジェクトを `viewsInfo` に追加します。このパターンは、常に同時に発生するイベントに使用します。たとえば、1 回のクリックで `Add To Cart` と `Product Clicked` の両方を 1 つのリクエストでトラッキングする場合です。

<Info>
  注

  この方法が機能するのは、構成時に両方のイベントを 1 つのトリガー内に記述するためです。AMP はトリガーを 1 回発火し、すべてのイベントをまとめて送信します。これは、自動的なトリガー間のバッチ処理（個別のトリガーの発火を 1 つのリクエストにまとめること）とは異なります。MoEngage はトリガー間のバッチ処理をサポートしていません。以下の注意事項を参照してください。
</Info>

<CodeGroup>

```HTML HTML lines wrap
<amp-analytics type="moengage" id="moengage">
<script type="application/json">
{
  "vars": {
    "appId": "YOUR_WORKSPACE_ID",
    "dataCenter": "sdk-01"
  },
  "triggers": {
    "addToCartBundle": {
      "on": "click",
      "selector": "#addToCart",
      "request": "eventV2",
      "extraUrlParams": {
        "viewsCount": 2,
        "viewsInfo": [
          {
            "EVENT_ACTION": "Add To Cart",
            "EVENT_ATTRS": {
              "productId": "${productId}",
              "price": "${price}"
            },
            "EVENT_G_TIME": "${timestamp}",
            "EVENT_L_TIME": "${timestamp}"
          },
          {
            "EVENT_ACTION": "Product Clicked",
            "EVENT_ATTRS": {
              "productId": "${productId}",
              "category": "${category}"
            },
            "EVENT_G_TIME": "${timestamp}",
            "EVENT_L_TIME": "${timestamp}"
          }
        ]
      }
    }
  }
}
</script>
</amp-analytics>
```

</CodeGroup>

この例では、`${productId}`、`${price}`、`${category}` は、クリックされた要素の `data-vars-product-id`、`data-vars-price`、`data-vars-category` 属性から解決されます。

MoEngage は次のリクエストボディを受け取ります。

```json JSON lines wrap
{
  "viewsCount": 2,
  "viewsInfo": [
    { "EVENT_ACTION": "Add To Cart", "EVENT_ATTRS": { "productId": "...", "price": "..." }, "EVENT_G_TIME": "...", "EVENT_L_TIME": "..." },
    { "EVENT_ACTION": "Product Clicked", "EVENT_ATTRS": { "productId": "...", "category": "..." }, "EVENT_G_TIME": "...", "EVENT_L_TIME": "..." }
  ],
  "identifiers": {},
  "meta": { "bid": "...", "request_time": "...", "integration_type": "AMP" }
}
```

<Warning>
  自動的なトリガー間のバッチ処理はサポートされていません

  AMP の組み込みの `batchInterval` は、個別のトリガーからの発火を収集し、発火ごとに 1 つのオブジェクトを含むトップレベルの JSON 配列としてまとめて送信します。MoEngage の `/v2/sdk/report` エンドポイントはトップレベルの配列のボディを受け付けず、単一の JSON オブジェクトを想定しています。リクエストが拒否されるため、`batchInterval` は使用しないでください。常に同時に発生するイベントには、代わりに上記の手動のマルチイベントトリガーパターンを使用してください。
</Warning>
