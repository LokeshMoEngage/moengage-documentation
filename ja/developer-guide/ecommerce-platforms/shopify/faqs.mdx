この記事では、MoEngage Shopify 統合のインストール、設定、使用に関するよくある質問（セットアップ、ID、データ同期、カタログ、イベントトラッキング）にお答えします。

## インストール

アカウント認証のトラブルシューティングについては、次の質問を確認してください。

<AccordionGroup>
  <Accordion title="認証時に API キーは機能しますか？">
    新しく生成された API キーが有効になるまでには、最大 10 分かかります。キーを生成してから 10 分待ってから、Shopify アプリの認証を再試行してください。エラーが解決しない場合は、キーの先頭や末尾にスペースが含まれておらず、キー全体がコピーされていることを確認してください。
  </Accordion>

  <Accordion title="Shopify アプリを再インストールした後、Webhook イベントが送信されないのはなぜですか？">
    Shopify パブリックアプリをアンインストールすると、MoEngage はデータと設定の削除をスケジュールします。この処理が完了するまでに最大 48 時間かかる場合があります。この期間内にアプリを再インストールすると、**Save Configuration** ボタンが無効のままになり、設定が停止した状態になるため、Webhook のサブスクリプションが再作成されず、イベントが送信されません。

    これを解決するには、削除が完了するまで待ってから再インストールするか、次の手順で設定をリセットしてください。

    1. すべてのイベントと属性のチェックを外します。
    2. **Save Configuration** をクリックします。
    3. すべてのイベントと属性に再度チェックを入れます。
    4. もう一度 **Save Configuration** をクリックします。
  </Accordion>
</AccordionGroup>

## ユーザー ID

ユーザープロファイルと識別子の管理については、次の質問を確認してください。

<AccordionGroup>
  <Accordion title="ユーザー識別子はどのように使用されますか？">
    ユーザー識別子は、MoEngage が各ユーザーを認識する方法を決定します。Shopify ID、メールアドレス、携帯電話番号など、最大 4 つの識別子を選択できます。同じユーザーが複数のデバイスからストアを訪問した場合、または Shopify の顧客レコードが更新された場合、いずれかの識別子の値が一致すれば、MoEngage はそのアクティビティを 1 つのプロファイルに統合します。
  </Accordion>

  <Accordion title="どのユーザー識別子を選択すればよいですか？">
    MoEngage は常に **Shopify ID** を選択し、デフォルトで **Email** と **Mobile number** を選択します。3 つすべてを維持することをお勧めします。選択には、**Email** または **Mobile number** の少なくとも一方を含める必要があります。

    すでに MoEngage を他のシステムと併用している場合は、それらのシステムで使用している識別子も考慮してください。サポートが必要な場合は、サポートチームまたはアカウントエグゼクティブにお問い合わせください。
  </Accordion>

  <Accordion title="ユーザー識別子として、携帯電話番号やメールアドレス以外の属性を使用できますか？">
    はい。Shopify ID、メールアドレス、携帯電話番号に加えて、タイプが単一行テキスト、URL、ID、整数、または小数の Shopify 顧客メタフィールドを使用するカスタムプロパティを選択できます。顧客ごとに値が異なるメタフィールドを選択してください。

    <Info>
      **セットアップ後は識別子が固定されます**

      設定を保存した後は、ユーザー識別子を変更できません。後で変更するには、サポートチームにお問い合わせください。プロファイルの統合は元に戻せません。
    </Info>
  </Accordion>

  <Accordion title="ユーザー識別子として、メールアドレスと携帯電話番号の両方を使用できますか？">
    はい。Shopify ID に加えて両方を選択でき、さらに識別子を 1 つ追加できます。
  </Accordion>

  <Accordion title="設定の保存がユーザー数のエラーで失敗するのはなぜですか？">
    MoEngage は、初めて設定を保存したときにワークスペースの Identity Resolution をセットアップします。Identity Resolution は、ユーザー数が 1,000 以下のワークスペースでのみセットアップできます。サポートチケットを作成し、サポートチームが解決した後に再度設定を保存してください。
  </Accordion>

  <Accordion title="既存のストアを複数の識別子に移行するにはどうすればよいですか？">
    複数の識別子が利用可能になる前に統合されたストアでは、セットアップ時に選択した識別子が引き続き使用されます。識別子を変更せずに、設定を再度保存して追加のユーザー属性や顧客メタフィールドを選択できます。Shopify ID やその他の識別子を追加する場合、またはワークスペースで Identity Resolution を有効にする場合は、サポートチームにお問い合わせください。詳細については、[既存のストア](/ja/developer-guide/ecommerce-platforms/shopify/shopify-20#existing-stores)を参照してください。
  </Accordion>

  <Accordion title="携帯電話番号を一意の識別子として設定する手順を教えてください。">
    携帯電話番号を識別子として選択する前に、Shopify ストアで次の変更を行う必要があります。

    - Shopify のチェックアウトフローでは、デフォルトで携帯電話番号を収集しません。インストール前に、ストアのチェックアウト設定からこれを有効にしてください。
    - デフォルトのユーザー登録およびログインフローでも携帯電話番号は収集されません。これらのタッチポイントでユーザーの携帯電話番号を取得するために、カスタムのログインおよび登録フローを実装してください。

    本番稼働前にこれらの変更を行わないと、携帯電話番号を提供していないユーザーに MoEngage が携帯電話番号の識別子を割り当てられないため、匿名プロファイルが大量に発生します。
  </Accordion>

  <Accordion title="配送先の携帯電話番号をユーザー識別子として使用できますか？">
    いいえ。MoEngage では、配送先の携帯電話番号を識別子として使用することはできません。配送先の携帯電話番号を識別子として使用すると、データの破損が発生します。1 人のユーザーが異なる配送先の携帯電話番号で複数の注文を行うことができ、それぞれが MoEngage で個別のプロファイルを作成するため、シングルカスタマービューが崩れ、アトリビューションエラーの原因となります。

    たとえば、ユーザー Bob が配送番号 SM1 で注文すると、MoEngage は SM1 で識別されるプロファイルを作成します。次に Bob が配送番号 SM2 で別の注文をすると、MoEngage は SM2 で識別される 2 つ目のプロファイルを作成します。Shopify では 2 件の注文を持つ 1 人のユーザーとして表示されますが、MoEngage ではそれぞれ 1 件の注文を持つ 2 人のユーザーとして表示されます。SM1 は「Add to Cart」の条件を満たしますが「Order Placed」の条件は満たさないため、カート放棄キャンペーンが誤って配信されます。

    **Mobile number** 属性には、顧客の Shopify アカウントの電話番号のみが入力され、住所の電話番号が使用されることはありません。
  </Accordion>

  <Accordion title="同じ携帯電話番号やメールアドレスに対して複数のプロファイルがあるのはなぜですか？">
    MoEngage は、いずれかのユーザー識別子の値が一致する場合にのみプロファイルを統合します。同じユーザーが複数のデバイスからストアを訪問しても、各タッチポイントでいずれの識別子も提供しない場合、MoEngage はそれらのセッションを統合できず、それぞれに個別のプロファイルを作成します。

    たとえば、メールアドレスが唯一の識別子であり、ユーザーが異なるデバイスから 2 件の注文を行い、どちらのチェックアウトでもメールアドレスを入力せずに携帯電話番号のみを使用した場合、MoEngage には同じ携帯電話番号を持つ 2 つの個別のプロファイルが表示されますが、統合をトリガーする一致する識別子はありません。このような重複を減らすには、識別子として **Email** と **Mobile number** の両方を選択してください。
  </Accordion>

  <Accordion title="電話番号を選択したのに、ユーザー ID としてメールアドレスが表示されるのはなぜですか？">
    これは、単一の識別子で統合されたストアに該当します。トラッキングイベントの発生時に、ユーザーの Shopify プロファイルに携帯電話番号が存在しない場合に発生します。MoEngage は選択された識別子を見つけられない場合、次に利用可能な識別子にフォールバックすることがあります。最も一般的な原因は、顧客が電話番号を入力せずにチェックアウトを完了することです。

    これを一貫して解決するには、カスタマーサクセスマネージャーに連絡するか、Identity Resolution の有効化を依頼するサポートチケットを作成してください。Identity Resolution を有効にすると、MoEngage は複数の識別子で同時にユーザーをトラッキングするため、このフォールバック動作を防止できます。
  </Accordion>

  <Accordion title="Cart Token を識別子とする匿名プロファイルが作成されるのはなぜですか？">
    ユーザーが識別データなしで（メールアドレスや電話番号がない状態で）カートに商品を追加すると、MoEngage はカート放棄イベントのデータを保持するために、Shopify のカートトークンを一時的な識別子として使用します。

    カートトークンのプロファイルが大量に表示される場合は、Identity Resolution が推奨される解決策です。有効にすると、ユーザーがメールアドレスまたは電話番号を提供した時点で、MoEngage はこれらの匿名プロファイルを識別済みプロファイルと統合できます。有効化を依頼するには、カスタマーサクセスマネージャーに連絡するか、サポートチケットを作成してください。
  </Accordion>
</AccordionGroup>

## [Identity Resolution](/ja/developer-guide/ecommerce-platforms/shopify/user-profile-management-with-shopify)

複数のソースからのユーザープロファイルを統合する方法については、次の質問を確認してください。

<AccordionGroup>
  <Accordion title="Identity Resolution とは何ですか？">
    Identity Resolution は、複数のソースからのユーザープロファイルを 1 つの統合プロファイルにリンクする MoEngage の機能です。有効にすると、MoEngage はすべてのタッチポイントで単一の値に依存するのではなく、複数の識別子（たとえばメールアドレスと携帯電話番号の両方）を使用して同じユーザーを認識できます。ワークスペースごとに最大 5 つの識別子を設定できます。

    Identity Resolution を使用しない場合、各ユーザーは単一の識別子でトラッキングされます。その識別子がない場合、MoEngage は個別の匿名プロファイルを作成します。Identity Resolution は、重複プロファイルを防止し、ゲストチェックアウトによる ID の欠落を解消し、ユーザーベース全体でキャンペーントリガーが正しく実行されるようにします。
  </Accordion>

  <Accordion title="Identity Resolution を有効にするにはどうすればよいですか？">
    新しい統合の場合、MoEngage アプリの設定を初めて保存したときに、選択したユーザー識別子を使用して、MoEngage がワークスペースの Identity Resolution をセットアップします。

    単一の識別子で統合されたストアの場合は、カスタマーサクセスマネージャーに連絡するか、サポートチケットを作成して有効化を依頼してください。有効化されたら、MoEngage ダッシュボードで **Settings** > **Data** > **Identity Resolution** に移動し、識別子と統合ルールを設定します。
  </Accordion>

  <Accordion title="プロファイルが統合された後に Identity Resolution を元に戻せますか？">
    いいえ。プロファイルの統合は元に戻せません。2 つのプロファイルが統合されると、分離することはできません。

    <Warning>
      **有効化する前に確認してください**

      Identity Resolution を有効にする前に、識別子の設定と統合ルールを慎重に確認してください。有効化の前に、サポートチームに統合レポートを依頼できます。このレポートには、すべてのユーザー統合アクションが記録されます。
    </Warning>
  </Accordion>
</AccordionGroup>

## [ユーザーと注文のバックフィル](/ja/developer-guide/ecommerce-platforms/shopify/user-data-sync)

ストアの過去データを同期する方法については、次の質問を確認してください。

<AccordionGroup>
  <Accordion title="どのようなデータを同期できますか？">
    過去データの同期では、次の 2 種類のデータを MoEngage に取り込みます。

    - ユーザープロファイル: 同期を実行した時点で Shopify ストアに存在するすべての登録ユーザー（ユーザーの作成日時は問いません）。
    - 注文データ: 選択した期間中に行われた注文。個別の **Shopify—Order Placed** イベントとして取り込まれます。各イベントには、Shopify の元の注文日がタイムスタンプとして付与されます。
  </Accordion>

  <Accordion title="データ同期が失敗しました。原因は何ですか？">
    一般的な原因は 2 つあります。

    - ユーザープロファイルに識別子が存在しない: 過去データの同期で携帯電話番号を識別子として使用しており、Shopify 上の既存のユーザープロファイルの一部に携帯電話番号がない場合、それらのユーザーとその注文データは自動的に同期できません。手動アップロードを手配するには、サポートチームにお問い合わせください。
    - イベント保持期間が同期期間より短い: MoEngage のイベント保持ポリシーが同期しようとしている期間より短い場合、同期は部分的なものになります。まず **Shopify—Order Placed** イベントの保持期間を延長してから、同期を再試行する必要があります。

    <Warning>
      **60 日を超えて同期する前にイベント保持期間を設定してください**

      同期を開始する前に、カスタマーサクセスマネージャーまたはサポートに連絡して、イベント保持期間を延長してください。これは、すでに実行された同期に遡って適用することはできません。
    </Warning>
  </Accordion>

  <Accordion title="同期にはどのくらいの時間がかかりますか？また、成功したことをどのように確認できますか？">
    過去 60 日間の標準的な同期は、通常 24 時間以内に完了します。2 年間の拡張同期には、最大 48 時間かかる場合があります。

    同期が正しく完了したことを確認するには、開始後少なくとも数時間待ってから、同期期間内に注文したことがわかっているユーザーのプロファイルを MoEngage で開きます。**Shopify—Order Placed** イベントが正しい元の注文日で表示されていることを確認してください。
  </Accordion>

  <Accordion title="同期を正常に実行するにはどうすればよいですか？">
    同期を実行する前に、次の 2 点を確認してください。

    - MoEngage アカウントに既存の重複データがないことを確認します。ユーザーデータとイベントデータがすでに存在する場合、同期によって重複が作成され、データの破損が発生します。
    - アプリのインストール日より前の期間を使用します。インストール後は、MoEngage が Webhook を介して新しい注文データを自動的にトラッキングするため、アカウントにすでに存在しているはずです。
  </Accordion>

  <Accordion title="イベント保持期間が同期期間より短い状態でデータ同期を実行するとどうなりますか？">
    ワークスペースのイベント保持期間より長い同期期間をリクエストした場合、MoEngage は保持期間内に含まれる注文のみを同期します。システムが Shopify から正常に取得した場合でも、MoEngage はその期間外の注文を保存しません。

    <Warning>
      **60 日を超えて同期する前にイベント保持期間を設定してください**

      同期を開始する前に、カスタマーサクセスマネージャーまたは MoEngage サポートチームに連絡して、イベント保持期間を延長してください。この変更は、すでに実行された同期に遡って適用することはできません。
    </Warning>
  </Accordion>
</AccordionGroup>

## [カタログ同期](/ja/developer-guide/ecommerce-platforms/shopify/sync-product-catalog)

商品カタログを同期する方法については、次の質問を確認してください。

<AccordionGroup>
  <Accordion title="カタログ同期はどのように機能しますか？">
    MoEngage は Shopify の商品カタログ全体を取得し、新しい MoEngage カタログに同期します。このカタログは、アプリ設定でカタログ同期を有効にすると自動的に作成されます。その後、このカタログは商品レコメンデーションブロック、メッセージ内の動的コンテンツ、セグメンテーションフィルターのデータソースとして利用できるようになります。

    <Info>
      **Basic Recommendations を有効にする**

      カタログ同期により商品データが MoEngage で利用可能になりますが、パーソナライズや商品レコメンデーションに使用するには、アカウントで Basic Recommendations を有効にする必要があります。
    </Info>
  </Accordion>

  <Accordion title="カタログはどのくらいの頻度で同期されますか？">
    最初の同期が完了した後、MoEngage はカタログをリアルタイムで最新の状態に保ちます。Shopify で行われた価格変更、フラッシュセール、在庫の更新は、スケジュールされた更新を待たずに MoEngage に反映されます。

    <Note>
      リアルタイムのカタログ同期はアーリーアクセスで提供されています。
    </Note>
  </Accordion>

  <Accordion title="どの商品がカタログに同期されますか？">
    MoEngage は、Shopify のステータスが **Active** の商品のみを同期します。商品のステータスが **Active** から他の値に変更されると、MoEngage はその商品をカタログから削除します。
  </Accordion>

  <Accordion title="どの商品詳細が同期されますか？">
    カタログのスキーマは、**Sync product catalog** タブでご自身で定義します。MoEngage は、Variation ID、Product ID、Link、Image Link、Vendor Name、SKU、Variation Title、Currency、Price、Quantity、Description、Created At、Updated At を含むデフォルトのマッピングを事前入力します。

    事前入力された属性のデータ型や Shopify のソースを変更したり、不要な属性を削除したり、Shopify のメタフィールドを含む独自の属性をマッピングしたりできます。詳細については、[商品カタログの同期](/ja/developer-guide/ecommerce-platforms/shopify/sync-product-catalog)を参照してください。
  </Accordion>

  <Accordion title="同期後にほとんどの商品が MoEngage に表示されないのはなぜですか？">
    一般的な原因は 3 つあります。

    - カタログフィールドのデータ型が商品間で一貫していない。たとえば、バリアント名フィールドが一部の商品では文字列、他の商品では数値の場合、MoEngage はフィールドの型が一致しない商品を拒否します。同期はエラーなしで完了しますが、それらの商品は通知なしに除外されます。
    - 商品が Shopify で **Active** になっていない。MoEngage は Active の商品のみを同期します。
    - 一意として指定した属性が、複数のアイテムで同じ値を持っている。MoEngage はそれらのアイテムを 1 つとして扱い、その識別子について最後に受信した値のみを保持するため、先のアイテムは表示されません。

    これを診断するには、MoEngage の商品総数と Shopify のアクティブな商品数を比較します。表示される商品が大幅に少ない場合は、Shopify の商品データで、データ型が混在しているフィールド（特にバリアント名、SKU、価格）を確認してください。不整合を修正し、同期を再度トリガーします。
  </Accordion>

  <Accordion title="カタログフィードをカスタマイズして属性を追加するにはどうすればよいですか？">
    最初の同期をリクエストする前に、**Sync product catalog** タブで属性を追加します。**Add custom attributes** で名前を入力し、データ型を選択して **Add attribute** をクリックし、Shopify のソースにマッピングします。Shopify のメタフィールドをソースとして使用できます。
  </Accordion>

  <Accordion title="最初のカタログ同期の後に何を変更できますか？">
    新しいカスタム属性はいつでも追加でき、MoEngage は次回の同期でそれらを含めます。

    テーブルにすでに存在する属性、そのデータ型、Shopify のソース、一意の識別子、カタログの通貨は、最初の同期が正常に完了すると固定されます。最初の同期をリクエストする前に、マッピングを確認してください。
  </Accordion>
</AccordionGroup>

## [イベントトラッキング](/ja/developer-guide/ecommerce-platforms/shopify/events-and-user-data-tracking)

自動イベントを監視する方法については、次の質問を確認してください。

<AccordionGroup>
  <Accordion title="自動イベントトラッキングはどのように機能しますか？">
    MoEngage は、すべてのストアで Shopify の標準イベントをすべて自動的にトラッキングします。イベントは、MoEngage Web SDK（Product Viewed や Add to Cart などのブラウザー側のアクション）と Shopify Webhook（Order Placed や Order Fulfilled などのサーバー側のシグナル）の組み合わせによってキャプチャされます。

    <Info>
      **キャンペーンで使用するイベントバージョン**

      Add to Cart や Checkout Started など、Web SDK と Shopify Webhook の両方でトラッキングされるイベントについては、セグメントの作成やキャンペーンのトリガーには常に Webhook バージョンを使用してください。Webhook イベントは Shopify のバックエンドから直接受信されるため、より信頼性の高いシグナルです。1 つのキャンペーンで同じイベントの両方のバージョンを使用すると、競合が発生します。
    </Info>
  </Accordion>

  <Accordion title="Order Placed の件数が Shopify と一致しないのはなぜですか？">
    不一致にはいくつかの原因があることが多いです。

    - **MoEngage の件数が少ない場合:** Shopify の Webhook 配信は保証されていません。Webhook リクエストが失われることがあります。
    - **MoEngage の件数が多い場合:** Shopify は同じ注文に対して重複した Webhook イベントを送信することがあります。MoEngage は重複排除を適用しますが、一部の重複がトラッキングされる場合があります。

    各プラットフォームは異なるカウント方法を使用しているため、他の分析ツールとの差異は想定されるものです。MoEngage データの信頼できる情報源は Shopify です。
  </Accordion>

  <Accordion title="Add to Cart の件数が Shopify と一致しないのはなぜですか？">
    Shopify は、Add to Cart をカートの作成につながったセッション数としてカウントします。MoEngage は、Add to Cart イベントが発火した回数をカウントし、これには 1 つのセッション内での複数回の追加が含まれます。キャンペーンのトリガーには MoEngage の件数を、コンバージョンファネルのベンチマークには Shopify の件数を使用してください。
  </Accordion>

  <Accordion title="Shopify イベントに Image URL がないのはなぜですか？">
    商品 URL と画像 URL は Shopify の Webhook ペイロードに含まれていないため、Shopify — Add to Cart、Shopify — Checkout Started、Shopify — Order Placed などの Webhook ベースのイベントには含まれません。

    キャンペーンのパーソナライズで商品画像や URL を使用するには、送信時にカタログによるエンリッチメントを使用します。商品カタログの同期を設定し、メッセージテンプレートでカタログ属性を参照してください。または、カスタム SDK イベントを使用してこれらの属性を直接トラッキングすることもできます。
  </Accordion>

  <Accordion title="一部のページで Product Viewed イベントと Add to cart イベントが発火しないのはなぜですか？">
    Web SDK ベースのイベントはすべて、Shopify のデフォルトテーマで自動的にトラッキングされます。ストアでカスタムテーマを使用している場合や、デフォルトテーマをカスタマイズしている場合、そのカスタマイズにより、それらのページやストアでデフォルトの Web SDK イベントの自動トラッキングが妨げられることがあります。これらのイベントをトラッキングするには追加のカスタムイベントトラッキングが必要です。または、引き続き Webhook ベースの代替イベントを使用することもできます。 
  </Accordion>

  <Accordion title="Shopify 顧客メタフィールドはイベントやユーザープロファイルでトラッキングされますか？">
    Shopify 顧客メタフィールドはユーザープロファイルに同期できます。MoEngage アプリの **Configuration** タブでカスタムユーザープロパティを追加し、その Shopify ソースとしてメタフィールドを選択します。入力したプロパティ名が、MoEngage ダッシュボードでのユーザー属性の名前になります。MoEngage は、Shopify で顧客が作成または更新されたときに値を更新します。

    顧客メタフィールドはイベント属性には表示されません。詳細については、[顧客メタフィールド](/ja/developer-guide/ecommerce-platforms/shopify/events-and-user-data-tracking#customer-metafields)を参照してください。
  </Accordion>

  <Accordion title="MoEngage の Shopify LTV が Shopify の値と異なるのはなぜですか？">
    MoEngage は、Shopify が顧客について報告する合計支出額を同期します。Shopify は、注文が全額返金されたときにこの値を更新します。一部返金は Shopify が合計を再計算するまで反映されず、テスト注文は含まれません。詳細については、[Shopify LTV](/ja/developer-guide/ecommerce-platforms/shopify/events-and-user-data-tracking#shopify-ltv) を参照してください。
  </Accordion>

  <Accordion title="イベントは自分のプロファイルに対してトラッキングされていますか？">
    チェックアウト前のイベントについては、ブラウザーに MoEngage の [Chrome プラグイン](https://chromewebstore.google.com/detail/moengage-sdk/dhggnkfnnoebbfofpimfehcklnekmbgi)を追加してから、イベントを再度実行します。プラグインでイベントがトラッキング済みと表示される場合は、トラッキングは機能しています。正しいユーザープロファイルを確認しているかどうかを確認してください。

    チェックアウトおよびチェックアウト後のイベントについては、注文 ID、メールアドレス、または携帯電話番号でイベント属性をフィルタリングして、イベントが別のプロファイルに対してトラッキングされていないかを確認します。
  </Accordion>

  <Accordion title="ストアでイベントがまったくトラッキングされないのはなぜですか？">
    まず、MoEngage Chrome プラグインを使用して、ストアで MoEngage SDK が読み込まれているかどうかを確認します。SDK が検出されない場合は、次の操作を行います。

    - Shopify 管理画面に移動し、MoEngage のアプリ埋め込み設定を開いて、アプリ埋め込みブロックの保存を解除してから再保存します。これにより SDK の挿入が再トリガーされます。
    - それでも SDK が読み込まれない場合は、ブラウザーのコンソールでページ上の JavaScript エラーを確認してください。

    SDK が正しく読み込まれているのにイベントが送信されない場合は、次の手順を実行します。

    1. MoEngage Shopify アプリでイベントトラッキングの設定を開きます。
    2. いくつかのイベントのチェックを外して保存し、その後すべてのイベントに再度チェックを入れて保存します。
    3. 5 分待ってから、ストアでイベントを実行します。
  </Accordion>
</AccordionGroup>

## 複数のストアを 1 つの MoEngage アカウントにリンクする

複数のストアフロントをリンクする際の設定と制限については、次の質問を確認してください。

<AccordionGroup>
  <Accordion title="1 つの MoEngage アカウントに複数の Shopify ストアを接続できますか？">
    はい、可能ですが、MoEngage ではこの方法を推奨していません。複数のストアをリンクする場合は、異なるストアのインストール時に同じ認証キーを使用して、同じ MoEngage アカウントにリンクします。

    続行する前に、次の影響を確認してください。

    - **Web Push**
      - 同じユーザーに対して、ストアごとに個別の Web プッシュ許可が求められます。
      - 複数のストアで Web プッシュをサブスクライブしたユーザーは、キャンペーンの対象が特定のストアに限定されていない場合、重複した通知を受け取ります。
    - **OSM（On-site Messaging）**
      - キャンペーンごとにターゲット URL を指定してください。指定しない場合、複数のストアを訪問するユーザーを含め、すべてのストアで同じキャンペーンが表示されます。
    - **データとプロファイル**
      - シングルカスタマービューを維持するために、すべてのストアで同じユーザー識別子を使用してください。ストアごとに異なる識別子を使用すると、同じユーザーに対して複数のプロファイルが作成されます。
    - **セグメンテーション**
      - セグメントを作成する際に各ストアのイベントを区別できるよう、イベント属性で URL またはストア ID のフィルターを使用して各ストアのイベントを識別してください。
  </Accordion>
</AccordionGroup>
