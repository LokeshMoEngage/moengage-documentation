<Accordion title="フォルダからのファイル取得でエラーが発生した場合はどうなりますか？">
  MoEngage は失敗したファイルを最大 30 回まで自動的に再試行し、それでも失敗した場合は恒久的に FAILED としてマークします。また、セットアップ時に通知のチェックボックスを選択すると、失敗時のメールアラートを設定することもできます。
</Accordion>

<Accordion title="ファイルが 'Applicable rate limit breached' で失敗しました。定期インポートで自動的に再処理されますか？">
  いいえ。ファイルが処理の再試行回数を使い切り、_Applicable rate limit breached_ ステータスで失敗した場合、MoEngage はそのファイルを単独で再実行できないため、定期スケジュールで自動的に再処理されることはありません。この再試行制限は、取り込みパイプラインが過負荷になるのを防ぐためのものです。影響を受けたファイルを再処理するには、ファイル名を変更してソースフォルダに再アップロードし、MoEngage が新しいファイルとして扱うようにしてください。レート制限に達する可能性を減らすには、多数のファイルを一度にスケジュールするのではなく、大きなバッチを分散させてください（[Limits](/ja/user-guide/data/imports/setting-up-a-file-import#limits) を参照）。
</Accordion>

<Accordion title="MoEngage は定期実行で新しいファイルをどのように取得しますか？">
  スケジュールされた各実行時に、MoEngage は設定されたフォルダパスを検索し、ファイル名のプレフィックスと日時形式の設定に基づいて新しいファイルを選択します。ファイルはフォルダの場所とファイル名の組み合わせで一意に識別されるため、各ファイルは 1 回だけ処理されます。
</Accordion>

<Accordion title="定期インポートで、以前に処理されたファイルが再度取得されることはありますか？">
  いいえ。すでに処理されたファイルは、ファイル名とフォルダの場所が同じである限り、再度処理されることはありません。同じファイルを別のフォルダに配置した場合は、その新しいフォルダ用に設定されたインポートによって再度処理されます。
</Accordion>

<Accordion title="1 つの CSV ファイルにユーザーデータとイベントデータの両方を含めることはできますか？">
  いいえ。ユーザーインポートとイベントインポートは別々のタスクとして設定してください。各ソースファイルには、ユーザー属性のみ、またはイベントレコードのみを含める必要があります。
</Accordion>

<Accordion title="NDJSON とは何ですか？また、なぜ必要なのですか？">
  NDJSON（Newline-Delimited JSON）とは、`.json` ファイルの各行が改行で区切られた完全な JSON オブジェクトである形式です。この形式により、MoEngage は大規模な JSON データセットを 1 行ずつ処理でき、スケーラブルで堅牢なインポートが可能になります。
</Accordion>

<Accordion title="圧縮ファイル（.gz、.zip など）はサポートされていますか？">
  いいえ。MoEngage は圧縮ファイルのインポートをサポートしていません。
</Accordion>

<Accordion title="既存のインポートのファイルタイプを変更すると、マッピングはどうなりますか？">
  ファイルタイプを変更すると、既存のプレビューが削除され、新しいファイルタイプで利用可能なファイルが再取得されます。プレビューするファイルを再度選択し、新しいファイルの構造に基づいてマッピングを再設定する必要があります。
</Accordion>
