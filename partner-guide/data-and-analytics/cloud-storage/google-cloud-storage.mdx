## Introduction

[Google Cloud Storage](https://cloud.google.com/storage) is an enterprise public cloud storage platform that can house large unstructured data sets.

## MoEngage × GCS

The MoEngage and GCS integration exports campaign interaction events to your Google Cloud Storage buckets. You can then import these files into BigQuery for further processing and analysis.

## Integration

<Info>
  **Prerequisites**

  - Ensure you have a Google Cloud Platform account with permission to create a new bucket and a service account.
  - Exporting data from MoEngage to Google Cloud Storage uses MoEngage Streams, which is a paid add-on. To check what's available for your plan, refer to [Plans and Pricing](https://www.moengage.com/plans-and-pricing/). To enable it for your account, contact your MoEngage Customer Success Manager (CSM) or the Support team.
</Info>

### Step 1: Create a dedicated service account for MoEngage

On your Google Cloud Platform console, go to the **IAM & Admin** console.

1. From the sidebar, open **Service Accounts**.
   ![Service Accounts home in the IAM & Admin console](/images/partner_12062501879700.png)
2. Click the **\+ Create Service Account** button.
3. Give this service account a name, and an optional description.
4. Click **Create and continue**.
   ![Creating a new service account in Google Cloud](/images/partner_12062703174548.png)
5. Add the role **Basic \> Browser** to this service account.
   ![Assigning the Basic \> Browser role to the service account](/images/partner_12062802345876.png)
6. Click **Continue**. Optionally, grant users access to this service account.
7. Click **Done**.
8. Open the service account from the list of service accounts.
9. Go to the **Keys** tab, click **Add Key**, and then select **Create new key**.
   ![Add Key option on the service account Keys tab](/images/partner_12062893736724.png)
10. Select the **Key Type** as **JSON**, and then click **Create**.
    ![Selecting JSON as the key type when creating a service account key](/images/partner_12062926508052.png)
11. Your new key is automatically downloaded in JSON format. Store this file safely. You will need to upload it later on the MoEngage dashboard.

<Tip>
  MoEngage recommends rotating your service account key regularly. To learn how to rotate it, see [Rotate Your Service Account Key](#rotate-your-service-account-key).
</Tip>

### Step 2: Grant this service account permissions to your bucket

1. On your service account details page, copy the email of your service account.
   ![Service account email on the details page](/images/partner_12063141549076.png)
2. Go to the **Cloud Storage** console, and open the bucket in which you want MoEngage to export the events.
3. Under the **Permissions** tab, click **Grant Access**.
   ![Grant Access option on the bucket Permissions tab](/images/partner_12063166880276.png)
4. Paste and select the service account email in the **New Principals** field.
5. Assign the role **Cloud Storage \> Storage Admin**.
   ![Assigning the Storage Admin role to the service account](/images/partner_12063216822036.png)
6. Click **Save**.

### Step 3: Enable APIs & Services in your GCP account

1. In your GCP console, go to **APIs & Services**, and then click **\+ Enable APIs and Services**.
   ![Enable APIs and Services option in GCP console](/images/partner_12063295895828.png)
2. Search for **Cloud Storage** and open the API details page.
3. Click **Enable** to enable it.
   ![Enabling the Cloud Storage API in GCP](/images/partner_12063394282388.png)

### Step 4: Enable IP Whitelisting

<DataTransferIpAllowlisting />

In Google Cloud, add a bucket IP filter that allows the MoEngage IPs. For the steps, see [Create IP filtering rules on a bucket](https://docs.cloud.google.com/storage/docs/create-ip-filter) in the Google Cloud documentation. Bucket IP filtering also blocks BigQuery from loading files from the bucket. If you load the exported files into BigQuery, use [VPC Service Controls](https://docs.cloud.google.com/vpc-service-controls/docs/overview) instead.

### Note on required permissions

To perform end-to-end testing, MoEngage requires a few additional permissions to be configured. If your IT policy does not allow for these permissions, you can skip them. However, you will not be able to test the connection from the App Marketplace. Skipping these optional permissions does not impact the actual data export in any way.

| Permission | Required | Description |
| --- | --- | --- |
| `storage.objects.create` | Yes | Allows the user to create objects (files) in a Google Cloud Storage bucket. MoEngage requires this permission to upload the export files to your bucket. |
| `storage.buckets.get` | Yes | Allows the user to view metadata for a Google Cloud Storage bucket. MoEngage requires this permission to check that the bucket exists before every upload and when you test the connection. |
| `resourcemanager.projects.getIamPolicy` | Optional | Allows the user to view the IAM policy for a project in Google Cloud Resource Manager. MoEngage uses this permission to test the connection and to turn a paused export back on. If you skip it, testing the connection fails with a `403` error, and you can't turn the export back on after MoEngage pauses it. |

Feel free to create a custom role that incorporates the mandatory permissions required by MoEngage along with any optional permissions cleared by your IT policy for testing.

### Rotate Your Service Account Key

MoEngage recommends rotating your service account key every 90 days or as per your IT policy. A service account can have multiple keys, so your current key keeps working while you switch to the new one.

1. In your Google Cloud console, go to **IAM & Admin** > **Service Accounts**, and open the service account that MoEngage uses.
2. Go to the **Keys** tab and note the ID and creation date of the current key, so that you can identify it later. Click **Add key**, and select **Create new key**. Select **JSON** as the key type and click **Create**. Google downloads the JSON key file to your computer. Store it securely, because Google does not show the private key again.
3. In your MoEngage dashboard, go to **App marketplace**, open **Google Cloud Storage**, and go to the **Integrate** tab. Edit the existing integration and upload the new service account credential JSON file.
4. Test the connection, and then save the integration. Testing the connection requires the `resourcemanager.projects.getIamPolicy` permission. For more information, see [Note on Required Permissions](#note-on-required-permissions).
5. After you confirm that your next scheduled export runs successfully, go to the **Keys** tab of the service account in the Google Cloud console and click **Delete** for the old key, using the ID you noted in step 2. Then delete the downloaded JSON file from your computer.

You can't restore a deleted key. If you want a reversible step first, disable the old key with the gcloud CLI, confirm that your exports keep running, and then delete it. For more information, see [Service account key rotation](https://docs.cloud.google.com/iam/docs/key-rotation) in the Google Cloud documentation.

<Warning>
  The rotation is not complete until you delete the old key in Google Cloud. Editing, disabling, or removing the integration in MoEngage does not revoke the key, and the old key keeps working until you delete it.
</Warning>

If you have more than one GCS integration, check which service account each one uses, and repeat these steps for each integration.
