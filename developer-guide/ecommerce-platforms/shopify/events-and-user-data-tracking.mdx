Events tracking and user data tracking allow you to send behavioral data from your Shopify store to MoEngage. After you track these events, you can use them to build segments, trigger campaigns, and personalize communication based on user actions on your store.

## Tracked Events

MoEngage tracks the following events for every store after you complete the integration. You do not need to select them. To review the events and their attributes, expand **User events** in the **Configuration** tab of the MoEngage app.

## Types of Events

Two sources generate events in the MoEngage Shopify integration:

- **Webhook**: Shopify generates these events and sends them directly to MoEngage via the Shopify webhook system. These represent server-side signals that the Shopify backend triggers, for example, when a user places an order or starts a checkout.
- **Web SDK:** The MoEngage JavaScript SDK running in the browser generates these events based on user behavior on your store frontend — for example, a product page view or a search action.

Both sources capture some events, such as Add to Cart and Checkout Started. This means that two separate event records can appear in MoEngage for the same user action, each with a different name and different attributes.

### Recommended Event Version for Campaigns and Segmentation

<Info>
  For any event that both Webhook and the Web SDK track, use the Webhook version when building segments or triggering campaigns.

  MoEngage receives webhook events directly from the Shopify backend; they are the more reliable signal for campaign logic. Web SDK events are useful for triggering on-site messages that must fire in real time within the browser session.

  If you use both versions of the same event in a single campaign or journey, you will cause conflicts and prevent a single consistent event-triggered flow from running.
</Info>

## Event Attribute Requirements

### Product URL and Image URL in Webhook Events

Webhook events do not include the product URL or image URL in their payloads. These attributes are present only when you capture the event by using the Web SDK.

**To obtain these attributes:** If you sync your product catalog to MoEngage, you can pull the product URL and image URL from the catalog at send time by using **Product set-based personalization**. For more information, refer to the [User Actions Model](/user-guide/content/recommendations/basic-recommendations/user-actions-model).

### Shopify Customer Metafields

Shopify customer metafields are custom data fields attached to the Shopify customer object. You can sync them to MoEngage user profiles as user attributes. For more information, refer to [Customer Metafields](#customer-metafields).

MoEngage does not include customer metafields in event attributes.

## Track Custom Events via Shopify Liquid

If you must track events beyond the MoEngage default set, for example, a wishlist action or a custom button click, you can add them using the MoEngage Web SDK in your Shopify theme's Liquid files.

<Note>
  **Before You Start**

  This procedure requires editing your Shopify theme files, which requires developer access. Check with your web team before you make changes.
</Note>

### Step 1: Identify the Correct Liquid File to Edit

Shopify themes use Liquid template files to render pages. To find the right file, perform the following steps:

1. Log in to your Shopify Admin.
2. Go to **Online Store** > **Themes**.
3. Locate the theme you want to edit and click the **Actions** (three dots) button.
4. Select **Edit code** from the drop-down menu.
5. Browse the `sections/` folder.

The file you edit depends on where the event should trigger:

- **Product page actions:** Edit `sections/product-template.liquid` or `sections/main-product.liquid`.
- **Collection page actions:** Edit the relevant collection section file.
- **All pages:** Edit `layout/theme.liquid`. Use this file sparingly.

### Step 2: Add the Track-Event Call

In the Liquid file, locate the HTML element the user interacts with. Add a JavaScript call to the MoEngage **track_event** method.

<CodeGroup>

```javascript No Attributes
Moengage.track_event("EVENT_NAME");
```

```javascript With Attributes
Moengage.track_event("EVENT_NAME", {
  "attribute_1": "value_1",
  "attribute_2": 2,
  "attribute_3": 3.4
});
```

```liquid Example: Wishlist
<button id="wishlist-btn" onclick="trackWishlistEvent()">Add to Wishlist</button>

<script>
  function trackWishlistEvent() {
    Moengage.track_event("Wishlist Added", {
      "Product ID": "{{ product.id }}",
      "Product Title": "{{ product.title }}",
      "Price": {{ product.selected_or_first_available_variant.price | divided_by: 100.0 }},
      "Product URL": "https://{{ shop.domain }}{{ product.url }}"
    });
  }
</script>
```

</CodeGroup>

### Step 3: Validate That the Event Fires

To validate that the event fires correctly, refer to the [Validate Integration](/developer-guide/ecommerce-platforms/shopify/validate-integration) documentation.

## Track Custom User Attributes

To sync Shopify customer metafields, select them in the **Configuration** tab of the MoEngage app. For more information, refer to [Customer Metafields](#customer-metafields).

To pass data that is not stored in a customer metafield, such as values available only in your theme, use the following methods.

### Liquid-Based Method

If the data is available in Shopify Liquid, for example, a metafield with storefront access enabled, you can read it in your theme. To find the correct file and add the code, perform the following steps:

1. Log in to your Shopify Admin.
2. Go to **Online Store** > **Themes**.
3. Locate the theme you want to edit and click the **Actions** (three dots) button.
4. Select **Edit code** from the drop-down menu.
5. Open `layout/theme.liquid`.
6. Inside the `<body>` tag, after you initialize the MoEngage SDK, add the following code:

```liquid
{% if customer %}
<script>
  Moengage.add_user_attribute("Loyalty Tier", "{{ customer.metafields.loyalty.tier.value }}");
  Moengage.add_user_attribute("Custom Attribute", "{{ customer.metafields.custom.attribute_name.value }}");
</script>
{% endif %}
```

Replace _loyalty_ and _tier_ with the actual namespace and key of your metafield. The `{% if customer %}` guard ensures the code only runs when a customer is logged in.

### Server-Side Method

If the data is stored outside Shopify customer metafields, for example, in a third-party app, perform a server-side integration:

1. In your backend, read the values you want to sync.
2. Call the MoEngage Data API to update the corresponding user attributes on the customer's profile.

## Profile Sync

MoEngage syncs user profiles from Shopify in near real time. When a customer is created or updated in Shopify, or when their tags, marketing consent, or purchase totals change, Shopify sends a webhook to MoEngage, and MoEngage updates the matching user profile.

MoEngage matches each update to a user profile by using the user identifiers you selected during integration. If no profile matches, MoEngage creates a new user profile. For example, a customer who signs up for an account or a newsletter in your store gets a MoEngage user profile even before they place an order.

<Note>
  The **Mobile number** attribute is populated from the phone number on the customer's Shopify account. The phone number in the customer's address is synced to the **Shipping Mobile Number** attribute and is never used to identify a user.
</Note>

## Tracked User Attributes

### Default User Properties

The **User properties** section of the **Configuration** tab lists the following user attributes by default. MoEngage syncs these attributes unless you remove them. You cannot remove **Shopify ID**, **Email**, or **Mobile number**.

| Property Name | Data Type | Description |
| --- | --- | --- |
| Shopify ID | Number | The user's customer ID in Shopify. |
| Email | String | The email address of the user. |
| Mobile number | String | The mobile number on the user's Shopify account. |
| First name | String | The first name of the user. |
| Last name | String | The last name of the user. |
| Shopify tags | Array | All tags on the Shopify customer. MoEngage adds and removes tags as they change in Shopify. |
| Shopify order count | Number | The total number of orders the user has placed. This value does not decrease when an order is cancelled or refunded. |
| Shopify last order ID | String | The ID of the user's most recent order. |
| Shopify last order name | String | The name of the user's most recent order, for example, `#1008`. |
| Shopify LTV | Number | The user's net lifetime spend in your store. For more information, refer to [Shopify LTV](#shopify-ltv). |
| Shopify zip code | String | The zip code of the user's default address. |
| Address line 1 (street) | String | The first line of the user's default address. |
| Address line 2 (apartment, suite) | String | The second line of the user's default address. |
| City | String | The city of the user's default address. |
| Province / state | String | The province or state of the user's default address. |
| Province code | String | The province or state code of the user's default address. |
| Country | String | The country of the user's default address. |
| Country code | String | The country code of the user's default address. |
| Shipping Mobile Number | String | The phone number in the user's default address. |

### Custom User Properties

To sync additional customer data, click **+ Custom property** in the **User properties** section, enter a property name, select a data type, and then select one of the following Shopify sources:

| Shopify Source | Description |
| --- | --- |
| Shopify verified email | Whether the user has verified their email address in Shopify. |
| Shopify customer since | The date and time the user's Shopify customer account was created. |
| Tax exempt | Whether the user is exempt from taxes in Shopify. |
| Tax exemptions | The tax exemption codes that apply to the user. |
| Shopify note | The note your team added to the customer in Shopify. |

### Customer Metafields

You can sync Shopify customer metafields as custom user properties. The Shopify source list includes the customer metafield definitions in your store, up to 250 definitions. The property name you enter is the name of the user attribute in the MoEngage dashboard.

MoEngage updates metafield values when a customer is created or updated in Shopify.

### Attributes That Are Not Synced

MoEngage does not sync the following Shopify customer data:

- Customer account state (enabled or disabled)
- The full address history of the customer. MoEngage syncs the default address only.
- The legacy **Accepts marketing** flag. Use the marketing consent attributes instead.
- The Multipass identifier

## Marketing Consent Mapping

MoEngage maps the Shopify marketing consent state of each channel to the MoEngage subscription attributes as follows:

| Shopify Consent State | Email (`moe_unsubscribe`) | Email (`moe_email_optin_status`) | SMS (`moe_sms_subscription`) | WhatsApp (`moe_wa_subscription`) |
| --- | --- | --- | --- | --- |
| Subscribed | `false` | `DOUBLE_OPTED_IN` | `OPTIN` | `true` |
| Pending | `false` | `OPT_IN_PENDING` | `OPT-IN PENDING` | Not updated |
| Unsubscribed | `true` | `OPTED_OUT` | `OPTOUT` | `false` |
| Not subscribed | `true` | Not updated | `EMPTY` | Not updated |
| Invalid | `true` | Not updated | Not applicable | Not applicable |
| Redacted | Not updated | Not updated | Not updated | Not updated |

MoEngage syncs the marketing consent of a channel only when its toggle is turned on in the **Sync user OPTIN** section of the **Configuration** tab: **Email subscription sync**, **SMS subscription sync**, or **WhatsApp subscription sync**.

## Shopify LTV

The **Shopify LTV** attribute holds the amount Shopify reports as the customer's total spend. It is calculated as the sum of order totals, including shipping, minus the value of returned items, across all orders that are not cancelled.

Keep the following in mind when you use this attribute:

- Shopify updates the value when an order is fully refunded. Partial refunds do not update it until Shopify recalculates the total, so the value can be higher than the actual net spend for some time.
- Test orders do not update this value.

## Configure User Properties

To add or remove the user properties that MoEngage syncs, perform the following steps:

1. Navigate to the **Configuration** tab in your Shopify app.
2. Expand **User properties**.
3. Remove the properties you do not need, or click **+ Custom property** to add one.
4. Click **Save configuration**.
